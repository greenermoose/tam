# Borrow small patterns, not big stacks

Across 29 surveyed projects and tools, the highest-value changes for `tam` are cheap metadata and build-time derivation rather than a new publishing platform: exact-name lookup, one-line descriptions, stable link IDs, reasoned freshness states and a generated index recur in man pages, tldr-pages and MkDocs Material ([man-pages(7), accessed 2026-11-26](https://man7.org/linux/man-pages/man7/man-pages.7.html); [tldr CLI specification, accessed 2026-11-26](https://raw.githubusercontent.com/tldr-pages/tldr/main/CLIENT-SPECIFICATION.md); [Material search plugin, accessed 2026-11-26](https://squidfunk.github.io/mkdocs-material/plugins/search/)). The second theme is that tutorials succeed when each step produces a visible, checkable result, which fits a command tool with a sandbox better than any surveyed system's quiz or forum ([Ubuntu tutorials guidelines, accessed 2026-11-26](https://ubuntu.com/tutorials/guidelines); [Diátaxis tutorials, accessed 2026-11-26](https://diataxis.fr/tutorials); [Bandit, accessed 2026-11-26](https://overthewire.org/wargames/bandit/)). These verdicts are research judgments, not approvals: `adopt`, `consider` and `reject` say what the evidence supports, and no change is scheduled, versioned or promised. Every required project has its own file; none was merged or omitted, and `lychee.md` was added because that project had direct source evidence in the platform notes. No code or expressive text was taken, so no upstream attribution files were changed. Evidence depth varies: Fedora, Debian wiki, elementary, LXQt and Docsy details are marked as snippets or starter notes, and those qualifiers must survive any later use.

## Exact names beat clever search

The man-page tradition makes the fast path deliberately boring: a canonical `NAME` line feeds a precomputed one-line index for `whatis`, exact name resolution comes before search, and `apropos` even reserves exit code 16 for "nothing found" ([whatis(1), accessed 2026-11-26](https://man7.org/linux/man-pages/man1/whatis.1.html); [apropos(1), accessed 2026-11-26](https://man7.org/linux/man-pages/man1/apropos.1.html)). tldr reaches the same place from the other direction, keying pages by command name and keeping roughly five examples per page with a deliberate hand-off to full manuals ([tldr CONTRIBUTING.md, accessed 2026-11-26](https://raw.githubusercontent.com/tldr-pages/tldr/main/CONTRIBUTING.md)). No primary source read here presents fuzzy or relevance-ranked search as the main discovery mechanism; `man -K` is explicitly brute-force over source and prone to false positives ([man(1), accessed 2026-11-26](https://man7.org/linux/man-pages/man1/man.1.html)). The practical consequence is to put a one-line summary and stable ID in page metadata, let an exact hit bypass ranking, and treat keyword or fielded lookup as a second tier; mandoc's macro-key queries show what fielded search could look like once options, files and cross-references are tagged ([mandoc apropos(1), accessed 2026-11-26](https://mandoc.bsd.lv/man/apropos.1.html)).

## A page should say where it fits and whether it is current

ArchWiki's fixed section grammar and status templates make both reader expectation and maintenance state explicit, and every status flag must carry a reason and appear in a maintenance view ([Help:Style, accessed 2026-11-26](https://wiki.archlinux.org/title/Help:Style); [Help:Template, accessed 2026-11-26](https://wiki.archlinux.org/title/Help:Template)). Debian's documentation project goes further by saying every document should be actively maintained, while Weblate's per-string states show the difference between a vague "outdated" and an actionable "source changed, needs rewriting" ([DDP, accessed 2026-11-26](https://www.debian.org/doc/ddp); [Weblate workflows, accessed 2026-11-26](https://docs.weblate.org/en/latest/workflows.html)). Dated prose is a liability: ArchWiki asks writers to link a bug report instead of writing "currently" or a version number, and Debian confines version-specific upgrade facts to release notes ([Help:Style, accessed 2026-11-26](https://wiki.archlinux.org/title/Help:Style); [Debian release notes, accessed 2026-11-26](https://www.debian.org/releases/stable/release-notes/about.en.html)). A banner alone is not enough, because Docusaurus's version banners and badges work only as part of a larger version model ([Docusaurus versioning, accessed 2026-11-26](https://docusaurus.io/docs/versioning)). The transferable design is reasoned status metadata in a generated index, visible on the page and aggregated into a maintenance list, with evidence links kept in records.

## Paths need outcomes, expected state and a failure branch

Ubuntu gives the most complete tutorial contract: every guide opens with a summary, "What you'll learn" and "What you'll need", runs 15–30 minutes with visible progress in 5–10 minute steps, offers code checkpoints for resuming, and ends with onward routes ([Ubuntu tutorials guidelines, accessed 2026-11-26](https://ubuntu.com/tutorials/guidelines)). Diátaxis adds the sharper rule that every step should show a comprehensible result and maintain a narrative of the expected, including exact output and likely failure signatures ([Diátaxis tutorials, accessed 2026-11-26](https://diataxis.fr/tutorials)). Bandit supplies the enforcement model: a level is finished when its observable goal is reached, and the beginner note offers recovery routes before answers ([Bandit, accessed 2026-11-26](https://overthewire.org/wargames/bandit/)). Fedora avoids triplication by factoring shared preparation into common pages and branching only where installation genuinely differs, while GNOME Help treats orientation and "Get more help" as distinct page types ([Fedora Getting Started, accessed 2026-11-26](https://docs.fedoraproject.org/en-US/fedora-user-docs/getting-started/); [GNOME Help, accessed 2026-11-26](https://help.gnome.org/users/gnome-help/stable/)). Ubuntu explicitly rejects separated exercises and answers, so the right shape for `tam` is a sandbox state check plus a "when stuck" branch, not a quiz UI ([Ubuntu tutorials guidelines, accessed 2026-11-26](https://ubuntu.com/tutorials/guidelines)).

## Generate navigation, indexes and reused text

MkDocs makes navigation an explicit manifest while still building pages left out of it, and Material derives its search index from the generated HTML sections rather than asking authors to maintain a second index ([MkDocs writing docs, accessed 2026-11-26](https://www.mkdocs.org/user-guide/writing-your-docs/); [Material search plugin, accessed 2026-11-26](https://squidfunk.github.io/mkdocs-material/plugins/search/)). Tokenisation, `search.boost` and `search.exclude` do more for result quality than a larger engine, which matters for names such as hyphenated commands and dotted identifiers ([Material search plugin, accessed 2026-11-26](https://squidfunk.github.io/mkdocs-material/plugins/search/)). Antora partials and Sphinx includes show how repeated definitions can be resolved during the build, with Antora warning about heading levels, ID collisions and attribute overrides ([Antora partials, accessed 2026-11-26](https://docs.antora.org/antora/latest/page/partials/); [Sphinx reST basics, accessed 2026-11-26](https://www.sphinx-doc.org/en/master/usage/restructuredtext/basics.html)). Local exact preview is normal in Fedora's docs-as-code workflow, tldr lints every pull request, and Lychee's feature model is a useful checklist for local link and anchor checks ([Fedora local editing, accessed 2026-11-26](https://docs.fedoraproject.org/en-US/fedora-docs/contributing/content/tools-edit-local-clone/); [tldr CONTRIBUTING.md, accessed 2026-11-26](https://raw.githubusercontent.com/tldr-pages/tldr/main/CONTRIBUTING.md); [Lychee, accessed 2026-11-26](https://github.com/lycheeverse/lychee)). One source, one build, several derived artefacts is the common architecture.

## Offline packaging is three hooks, not one viewer

Debian Policy treats documentation as installed, registered and optional: standard paths, compression, catalog updates through `install-info`, bulky material in separate doc packages, and a rule that programs must work when docs are absent ([Debian Policy §12, accessed 2026-11-26](https://www.debian.org/doc/debian-policy/ch-docs.html)). tldr takes the opposite packaging route, distributing a complete offline ZIP with explicit update commands, which avoids index staleness but needs an opt-in refresh ([tldr CLI specification, accessed 2026-11-26](https://raw.githubusercontent.com/tldr-pages/tldr/main/CLIENT-SPECIFICATION.md)). Material's offline plugin and generated index show that a static site can be shipped whole without a server ([Material search plugin, accessed 2026-11-26](https://squidfunk.github.io/mkdocs-material/plugins/search/)). At the cross-desktop level, the `help:` URI draft defines a document/page/anchor grammar and a language-coded XDG layout, while AppStream defines a help URL as a web link distinct from other metadata ([help URI draft, accessed 2026-11-26](https://www.freedesktop.org/wiki/Specifications/help-uri/); [AppStream metadata spec, accessed 2026-11-26](https://www.freedesktop.org/software/appstream/docs/chap-Metadata.html)). The three hooks to carry over are install into a discoverable place, register into a generated catalog, and tolerate a partial or missing corpus; no desktop help daemon is required.

## Navigation and accessibility need small, typed affordances

Info's best idea is not its key map but its link semantics: a last-position link, an up link, sibling links and a Directory node that reaches every manual, backed by validation of pointers and cross-references ([Info manual mirror, accessed 2026-11-26](https://web.mit.edu/gnu/doc/html/info.html)). Mallard's topic IDs, descriptions and typed guide links offer a lighter version of the same hierarchy, but its quickstart is deprecated and Yelp is described as unmaintained, so only the model is usable ([Mallard quickstart, accessed 2026-11-26](https://help.gnome.org/misc/tutorials/2013-12/mallard-quickstart.html)). KHelpCenter demonstrates local search over installed handbooks, while DocSearch's default theme is described as designed around colour and contrast ([KHelpCenter handbook, accessed 2026-11-26](https://docs.kde.org/stable5/en/kde-workspace/khelpcenter/index.html); [Docusaurus search, accessed 2026-11-26](https://docusaurus.io/docs/search)). No source read here establishes a dedicated breadcrumb component, formal glossary pane or audited terminal-pager accessibility practice, so those remain gaps rather than recommendations ([GNOME Help, accessed 2026-11-26](https://help.gnome.org/users/gnome-help/stable/)).

## Heavyweight stacks and open wikis do not fit

Hosted crawled search, Ask AI, Docusaurus version trees, a full Antora playbook, DocBook/DAPS profiling and DITA-class toolchains all solve scaling problems that a compact offline tool does not have ([DocSearch overview, accessed 2026-11-26](https://docsearch.algolia.com/docs/what-is-docsearch); [Docusaurus versioning, accessed 2026-11-26](https://docusaurus.io/docs/versioning); [Antora, accessed 2026-11-26](https://docs.antora.org/antora/latest/)). Open wiki editing depends on mass watchers and a tolerance for reverting incomprehensible edits, which is a poor trade for a corpus whose claims must stay traceable ([ArchWiki:Contributing, accessed 2026-11-26](https://wiki.archlinux.org/title/ArchWiki:Contributing)). Weblate's translation states are worth borrowing, but the platform and any per-language duplicate trees are not, especially since KDE declined a move to Weblate and tldr still tracks stale translations ([Weblate workflows, accessed 2026-11-26](https://docs.weblate.org/en/latest/workflows.html); [KDE Discuss, accessed 2026-11-26](https://discuss.kde.org/t/any-plans-to-move-to-weblate-for-translation/3415)). Unreviewed machine-generated text fails Weblate's own gateway rule, and GFDL invariant sections conflict with Debian's DFSG judgement ([Weblate workflows, accessed 2026-11-26](https://docs.weblate.org/en/latest/workflows.html); [Debian GR 2006 vote 001, accessed 2026-11-26](https://www.debian.org/vote/2006/vote_001)). Fedora wiki pages, Debian wiki pages, elementary, LXQt and Docsy evidence in these notes is snippet-heavy or starter-level; re-check before treating any detail as settled ([Fedora contributing, accessed 2026-11-26](https://docs.fedoraproject.org/be/fedora-docs/contributing/); [elementary help, accessed 2026-11-26](https://help.elementary.io/); [LXQt documentation, accessed 2026-11-26](https://lxqt.github.io/lxqt-documentation/)).

## Start with five concrete changes

**First**, add a canonical one-line description and stable ID to each page, then make an exact-name lookup bypass ranking and give "no match" a distinct exit status, following man and tldr ([man-pages(7), accessed 2026-11-26](https://man7.org/linux/man-pages/man7/man-pages.7.html); [tldr CLI specification, accessed 2026-11-26](https://raw.githubusercontent.com/tldr-pages/tldr/main/CLIENT-SPECIFICATION.md)). **Second**, derive the search index and navigation from rendered pages in the corpus build, with CLI-aware tokenisation, boost/exclude metadata and offline link-and-anchor checks ([Material search plugin, accessed 2026-11-26](https://squidfunk.github.io/mkdocs-material/plugins/search/); [Lychee, accessed 2026-11-26](https://github.com/lycheeverse/lychee)). **Third**, give each path an outcome, exact prerequisites and a rough time, attach expected sandbox state to every checkpoint, and add a failure branch that points to manuals, built-in help, search and community help ([Ubuntu tutorials guidelines, accessed 2026-11-26](https://ubuntu.com/tutorials/guidelines); [Bandit, accessed 2026-11-26](https://overthewire.org/wargames/bandit/)). **Fourth**, add reasoned status metadata with a maintenance view, and flag pages when an authority file changes, borrowing Arch's flag discipline and Weblate's "needs rewriting" state ([Help:Template, accessed 2026-11-26](https://wiki.archlinux.org/title/Help:Template); [Weblate workflows, accessed 2026-11-26](https://docs.weblate.org/en/latest/workflows.html)). **Fifth**, make end-to-end path walkthroughs and a short QA checklist part of acceptance, with a second reviewer for high-risk claims ([Docs QA Review Guidelines, accessed 2026-11-26](https://fedoraproject.org/wiki/Docs_QA_Review_Guidelines); [Diátaxis tutorials, accessed 2026-11-26](https://diataxis.fr/tutorials)). None of these is a change to shipped behaviour until the developer decides it.

## Conclusion

The surveyed systems converge on metadata and derivation rather than on bigger machinery: small typed fields, explicit navigation, reasoned status and generated indexes appear repeatedly across projects with very different communities. What none of them combines is a local command corpus, a sandbox that can verify expected state, and offline deep links; the most interesting `tam` ideas therefore sit in that gap and are designs, not copies. Because several source sets are snippet-only or explicitly historical, the next useful step is verification against the repository and the primary pages before any idea leaves this folder.

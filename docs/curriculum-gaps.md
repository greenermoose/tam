# Curriculum expansion after reorganization

These are gaps in teaching coverage, not implementation assignments. The
subject-library work reorganizes existing knowledge; it does not certify
research-level mastery. Existing skill mappings are coverage claims only.

| Subject | Missing capability | Prerequisites and affected paths |
| --- | --- | --- |
| Hardware foundations | Derive switching behavior from electrical and semiconductor models, with carefully explained mathematics | Arithmetic, units, algebra, probability; From atoms to bits and From gates to machine code |
| Networking | Explain IP addressing, routing, DNS, transport reliability, and packet inspection as a connected curriculum | Signals, bytes, processes; diagnosis and security paths |
| Cryptography | Work through modular arithmetic, probability, finite fields, security games, and lattice assumptions before encountering their advanced use | Junior-high mathematics to explicit mathematical foundations; Cryptography and quantum safety |
| Systems | Reason through virtual memory, scheduling, concurrency, persistence, and failure models with substantive worked cases | Processes, storage, architecture; How software runs and Rescue |
| Programming | Build fluency in C before advanced compilation, linking, and sanitizer analysis | Expressions, types, functions, pointers, lifetime; Systems programming in C11 |
| Research practice | Evaluate evidence, reproduce results, distinguish a model from its assumptions, and identify open questions | Domain-specific foundations and primary-source reading; all advanced paths |

Do not solve these gaps by adding more acronyms or declaring a short definition
an expert treatment. Each future lesson needs a clear capability, prerequisites,
primary sources, and an observable way to check understanding.

Emergency Disaster Recovery

Depth: beginner, intermediate, expert. Every level is shown below; follow one to
read only that depth.

When an application locks up, the graphical environment freezes, or a machine
fails to complete its boot sequence, a structured recovery escalation ladder
ensures you regain control calmly without risking data loss or filesystem
corruption.

Beginner: Dropping to a virtual console (TTY)

Summary: Escape a frozen Wayland desktop or unresponsive fullscreen window by
switching to an independent text virtual console.

Prerequisites: Basic command-line navigation ( The Shell and Streams).

Keyboard shortcut

Press Ctrl + Alt + F2 (or F3 through F6).

What just happened

- Linux runs multiple virtual consoles (TTYs) independent of any graphical
  display server.
- The graphical desktop runs on virtual terminal 1 ( tty1) or tty7. Switching to
  tty2 drops immediately to a clean, text-mode login prompt backed by the
  kernel.
- The display manager and graphical compositor are bypassed, allowing you to log
  in with your user credentials even if graphics rendering has completely locked
  up.

Diagnosing and recovering

Once logged into the virtual console, identify and terminate the hung process:

  
  # Check processes consuming CPU or memory
  top
  
  # Terminate an unresponsive application cleanly
  pkill -TERM problematic-app
  
  # Switch back to the graphical session
  Ctrl + Alt + F1
  

Common pitfall

Never reach immediately for the hardware power button when an application
freezes. Hard power cuts bypass disk flush routines and can leave filesystems
unclean. Virtual consoles provide a safe, non-destructive escape hatch.

Next step

Learn how to safely reboot an entirely locked kernel using Magic SysRq in the
intermediate section below.

Intermediate: The Magic SysRq (REISUB) emergency sequence

Summary: Use kernel Magic SysRq keys to cleanly terminate processes, sync disks,
and reboot a frozen machine without holding the power button.

What is Magic SysRq?

The Magic System Request key is a kernel-level interrupt handler that responds
even when the window manager, user space, and shell are completely frozen. The
standard emergency reboot sequence is remembered by the mnemonic REISUB (or
"Raising Elephants Is So Utterly Boring"):

Key  Kernel Action        Purpose                                               
---  -------------------  ------------------------------------------------------
R    unRaw keyboard       Takes keyboard control back from the X11/Wayland      
                          server into TTY mode.                                 
E    tErminate processes  Sends SIGTERM to all processes except init, allowing  
                          clean exit.                                           
I    kIll processes       Sends SIGKILL to any stubborn tasks that refused to   
                          terminate.                                            
S    Sync filesystems     Flushes all dirty data in RAM buffers to physical     
                          storage disks.                                        
U    re-mount read-Only   Remounts all mounted filesystems read-only to prevent 
                          corruption.                                           
B    reBoot               Immediately triggers a clean hardware reboot.         

Executing REISUB

Hold down Alt + SysRq (the PrintScreen key on most keyboards) and press each
letter in order, pausing 2–3 seconds between keypresses (especially after E
and S to allow disk writes to finish):

  
  Alt + SysRq + R
  Alt + SysRq + E
  Alt + SysRq + I
  Alt + SysRq + S
  Alt + SysRq + U
  Alt + SysRq + B
  

Enabling Magic SysRq in sysctl

Inspect your current SysRq enablement mask:

  
  cat /proc/sys/kernel/sysrq
  

A value of 1 enables all SysRq functions. To make this permanent across reboots,
ensure kernel.sysrq = 1 is set in /etc/sysctl.d/99-sysctl.conf.

Completion task

Audit whether your system provides the necessary privilege tools to manage
system recovery. Complete the command below (marked with ___):

  
  tam install check ___
  

Target output: [pass] privilege_pkexec: polkit pkexec is available.

Verification hints

- Run tam install check privilege_pkexec to confirm privilege tool presence.
- Tamlinux relies on pkexec for non-interactive administrative inspections.

Expert: Live USB rescue and chroot recovery

Summary: Boot a rescue live USB, mount encrypted and Btrfs storage pools, and
chroot into the workstation environment to repair kernels, initramfs, and
bootloaders.

Step-by-step live USB chroot workflow

When a kernel upgrade fails or boot configuration becomes corrupted, boot an
Arch or Tamlinux live USB installation medium:

1. Unlock encrypted volumes (if using LUKS):

  cryptsetup open /dev/nvme0n1p2 cryptroot

2. Mount the root Btrfs subvolume:

  mount -o subvol=@ /dev/mapper/cryptroot /mnt

3. Mount boot and ESP partitions:

  mount /dev/nvme0n1p1 /mnt/boot

4. Bind virtual kernel filesystems into the target:

  
  for dir in /dev /dev/pts /proc /sys /run; do
      mount --bind "$dir" "/mnt$dir"
  done
  

5. Enter the installed environment:

  chroot /mnt /bin/bash

6. Repair system configuration:

  
  # Rebuild initramfs images
  mkinitcpio -P
  
  # Or restore package database state / reinstall kernel
  pacman -S linux linux-firmware
  

7. Exit and cleanly unmount before rebooting:

  
  exit
  umount -R /mnt
  reboot

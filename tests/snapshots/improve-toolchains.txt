Native Toolchains and Multi-Agent Workflows

Depth: beginner, intermediate, expert. Every level is shown below; follow one to
read only that depth.

Tamlinux builds its core commands in native C against libtam, achieving sub-5
millisecond startup times and minimal memory consumption. By combining optimized
C compilation with isolated Git worktrees and scope claims, multiple autonomous
AI coding agents can develop, test, and package software concurrently without
stepping on one another.

Beginner: Building native C projects with Make

Summary: Compile native C programs, inspect compiler flags, and run local
development builds without requiring root privileges.

Prerequisites: Terminal and editor ergonomics ( Terminal and Editor Ergonomics).

Command sequence

  
  make -C ~/src/tam test-command
  ./build/tam --version
  

Expected output:

  
  cc -DTAM_DATADIR=... -O2 -Wall -Wextra -std=c11 src/tam.c ... -ltam -o build/tam
  tam command 0.21.0 (dev abc1234)
  

What just happened

- make -C instructs GNU Make to build the C binary directly in the project
  directory using GCC or Clang.
- The binary is compiled with -O2 optimizations and linked with an embedded
  runpath ( -Wl,-rpath) that finds libtam.so automatically.
- The resulting standalone executable starts in less than 5 milliseconds and
  requires no external interpreter runtime.

Common pitfall

Never install development binaries directly into system directories like
/usr/bin or /usr/local/bin. In Tamlinux, development builds install cleanly
under PREFIX=$HOME/.local/dev, which is placed first on $PATH without touching
root.

Intermediate: Isolated Git worktrees for concurrent development

Summary: Spin up isolated working directories sharing a single Git repository
object database for multi-agent pair programming.

Worked example

When multiple agents or developers work on separate features, switching branches
in a single working tree causes collisions and invalidates build artifacts.
Instead, create a separate worktree:

  
  git worktree add ../tam-feature-work branch-name
  git worktree list
  

To inspect active worktrees:

  
  /home/user/src/tam                 a1a08ab [develop]
  /home/user/src/tam-feature-work   b2c3d4e [branch-name]
  

When work is complete and merged, prune the worktree cleanly:

  
  git worktree remove ../tam-feature-work
  

Completion task

Create a new isolated Git worktree branched from develop into a sibling folder
named../tam-test-lane. Complete the command by filling in the missing worktree
verb (marked with ___):

  
  git worktree ___ ../tam-test-lane develop
  

Target output: Preparing worktree (checking out 'develop').

Verification hints

- The subcommand is add: git worktree add <path> <branch>.
- Worktrees share the main.git database, so commits, tags, and stashes are
  instantly visible across all worktrees.

Expert: Compiler optimization flags and tam-work scope reservation

Summary: Understand machine code generation flags ( -march=native, -flto),
dynamic linking rpaths, and the tam-work concurrency coordination contract.

Native compilation optimization flags

Tamlinux builds optimize C code specifically for the host workstation's CPU
microarchitecture:

Compiler Flag   Purpose                Performance Benefit                      
--------------  ---------------------  -----------------------------------------
-O2             Standard optimization  Enables loop vectorization, function     
                                       inlining, and instruction scheduling     
                                       without code size explosion.             
-march=native   Target host CPU        Enables all instruction set extensions   
                                       supported by the local processor (AVX2,  
                                       FMA, BMI2, AES-NI).                      
-pipe           Compiler pipes         Uses pipes rather than temporary disk    
                                       files between compilation stages,        
                                       speeding up builds in memory.            
-Wl,-rpath,DIR  Embedded library path  Binds the exact runtime directory of     
                                       libtam.so into the ELF binary header,    
                                       eliminating dynamic linker lookup        
                                       ambiguities.                             

Concurrency coordination with tam-work

When multiple autonomous agents (e.g. Claude, Codex, agy, OpenCode) collaborate
in a shared repository checkout, they coordinate file access using tam-work:

  
  tam-work begin --scope src --scope knowledge --note "Feature development"
  

- Lanes: Repositories divide into independent lanes (e.g. in tam: the command
  lane in src/ vs the corpus lane in knowledge/). Agents claiming disjoint lanes
  work in parallel without blocking.
- Strict Git hygiene: Agents commit strictly their claimed paths ( git commit -m
  "..." -- <paths>), never running indiscriminate git add -A.
- Handoff: When a task finishes or is accepted, the agent releases its
  reservation with tam-work finish.

Tamlinux Terminology: The Botanical Analogy

Depth: beginner, intermediate, expert. Every level is shown below; follow one to
read only that depth.

Tamlinux uses a horticultural conceptual framework to describe system
architecture, boot stages, base operating systems, and userland environments.
Rather than thinking of an operating system as a single monolithic block,
developer Fred conceives of the workstation through six interconnected botanical
layers: the greenhouse, the pot, the nut, the root-stock, the cultivar, and the
fruit.

The Six Layers

1. The Greenhouse (Hardware): The physical machine. The CPU, RAM, motherboard,
   storage drives, thermal heatpipes, and displays provide the shelter, light,
   and physical resources that allow software to live and run.
2. The Pot (Bootloader or Virtual Machine): The containing vessel placed inside
   the greenhouse. A pot is the UEFI firmware environment, a bootloader like
   systemd-boot, or a virtual machine container (such as QEMU/KVM) that prepares
   the soil and bounds the environment for germination.
3. The Nut (Minimal Bootable System): An extremely compact, self-contained
   seed—a Unified Kernel Image (UKI) or minimal initramfs containing only a
   Linux kernel and an essential text shell. When system control transfers to
   the nut, it sprouts: it initializes fundamental hardware, establishes network
   access, and prepares the environment so a larger operating system can take
   root.
4. The Root-stock (Base Linux Distribution): The hardy, established base
   distribution (such as Void Linux or Arch Linux) that provides the core system
   libraries (libc), service supervision (runit or systemd), and hardware
   drivers. The nut may fetch and plant the root-stock across the network, or
   the root-stock may already be established on local disk.
5. The Cultivar (Tamlinux Desktop & Suite): A specific cultivated variety
   grafted onto the root-stock. The cultivar is Tamlinux itself: the tiling
   Wayland compositor, Quickshell status bar, fred.* desktop plugins, terminal
   tools, and application suite. If the root-stock and the cultivar are
   compatible, the cultivar will thrive.
6. The Fruit (End-User Applications): The ultimate yield of the tree:
   applications such as Suspra, web browsers, document editors, and AI agents
   that users run to accomplish real work. The entire tree exists to produce
   healthy, dependable fruit.

Why This Mental Model Matters

Understanding this analogy clarifies why Tamlinux can run across different base
distributions without losing its identity. A rose cultivar can be grafted onto
different hardy root-stocks depending on the soil and climate; similarly,
Tamlinux can run on an Arch Linux root-stock today, transition to a Void Linux
root-stock tomorrow, or run inside a virtual machine pot for testing, while
providing the identical desktop experience.

Command Varieties across the Botanical Layers

To respect hardware constraints and dependency boundaries across the layers,
Tamlinux defines three varieties of core utilities:

- *-nut (e.g. tam-nut): Extremely minimal utilities designed for the Nut UKI
  environment. Bounded strictly by the Linux kernel, a text terminal, and basic
  ramfs tools; focused on inspecting the greenhouse (hardware resources) and
  installing the root-stock.
- *-root (e.g. tam-root): Utilities running directly on the base Root-stock
  Linux distribution, limited strictly to the libraries and services the
  root-stock provides (e.g. POSIX libc, runit/systemd).
- * (e.g. tam): Flagship utilities running in the full Cultivar environment,
  taking advantage of Tamlinux packages, Nix/Home Manager integrations, and rich
  documentation.

The Germination and Grafting Sequence

When a Tamlinux workstation boots, control passes progressively up the botanical
ladder:

1. The greenhouse powers on; UEFI firmware locates the active pot (the ESP boot
   partition).
2. The bootloader loads the nut (a signed UKI image under 100 MB).
3. The nut boots the Linux kernel and mounts a ramfs, executing /init. If the
   underlying disk lacks a root-stock, the nut enables networking (DHCP/Wi-Fi)
   and fetches the base system image.
4. Control pivots to the root-stock: the real root filesystem mounts (Btrfs
   subvolume @), and the service manager (systemd or runit) launches core
   daemons.
5. The root-stock launches the cultivar: the user session initializes Wayland,
   Quickshell renders the bar, and the Tamlinux desktop is live.
6. The user launches fruit: applications like Suspra or terminal tools to get
   productive work done.

Architectural Invariants & Grafting Compatibility

The botanical separation enforces architectural discipline and failure isolation
across Tamlinux development:

- Nut Immutability: The nut is cryptographically signed and read-only. It
  contains no stateful configuration, no desktop dependencies, and no background
  services. If a root-stock or cultivar update introduces a boot failure, the
  nut remains intact and capable of launching recovery tools or restoring a
  Btrfs snapshot.
- Graft Compatibility Matrix: A cultivar cannot assume arbitrary base
  distribution packages. All communication between the cultivar and the
  root-stock occurs through standard POSIX syscalls, C library interfaces (
  libtam), standard stream pipes, or package abstractions. This ensures the
  cultivar can be lifted from Arch and planted onto Void with zero desktop code
  modifications.
- Environmental Boundaries: The cultivar respects greenhouse resources: zero
  unnecessary CPU wakeups (Virtue V03), zero background polling daemons (Virtue
  V04), and explicit memory compression via ZRAM.

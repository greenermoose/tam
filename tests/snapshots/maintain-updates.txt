Non-Disruptive Updates and Package Lifecycle

Depth: beginner, intermediate, expert. Every level is shown below; follow one to
read only that depth.

Linux updates running software without forcing disruptive system reboots.
Tamlinux takes advantage of POSIX filesystem semantics to maintain software
seamlessly across distinct package tiers.

Beginner: Safe updates and package status

Summary: Check for pending package updates and apply them confidently without
interrupting active terminal workflows.

Prerequisites: Basic command execution ( The Shell and Streams) and the System
Maintenance overview.

Command sequence

  
  tam-update --check
  tam-update
  

Expected output when checking:

  
  tam-update: checking package tiers...
    [base]     3 packages upgradable (pacman)
    [tamlinux] up to date (cultivar 0.4.2-d)
    [tools]    up to date (mise)
  Run 'tam-update' to synchronize packages.
  

What just happened

- tam-update --check inspects each configured package layer and reports pending
  upgrades without modifying disk state.
- When updates are applied, newly downloaded binaries are written to storage
  immediately while active processes continue running undisturbed.
- Unlike operating systems that lock active executable files on disk, Linux
  allows files in use to be replaced safely.

Common pitfall

Do not reboot the entire machine after updating user packages or command-line
utilities. A reboot is only strictly required when activating a newly installed
Linux kernel or updated low-level system firmware.

Intermediate: Package tiering architecture

Summary: Understand the three-tier software model: base OS packages, Tamlinux
product packages, and user development runtimes.

The three package tiers

Tier        Manager                  Scope and Responsibility                   
----------  -----------------------  -------------------------------------------
Base OS     pacman                   Linux kernel, systemd init, glibc, Mesa    
                                     graphics drivers, and hardware firmware.   
Tamlinux    tamlinux-packages / Nix  Desktop shell, tiling compositor plugins,  
                                     libtam, and system lifecycle tools.        
User tools  mise                     User-specific CLI utilities, compilers,    
                                     language runtimes, and local developer     
                                     tools.                                     

Worked example

Trace which package management layer owns a specific command or file on your
workstation:

  
  pacman -Qo /usr/bin/bash
  which tam
  

Expected output:

  
  /usr/bin/bash is owned by bash 5.2.037-1
  /usr/local/bin/tam
  

Completion task

Identify which package manager and repository provides the curl binary on your
system. Complete the command below by filling in the missing flag (marked with
___):

  
  pacman ___ /usr/bin/curl
  

Target output: /usr/bin/curl is owned by curl <version>.

Verification hints

- The -Q option queries the local package database, and -o (owns) resolves a
  filesystem path to its owning package.
- Check the availability of package managers on your host with tam install
  inspect.

Expert: Inode unlinking mechanics and running process tracking

Summary: Examine the filesystem mechanics of unlink(2), directory entry deletion
versus active inode reference counts, and identify processes holding replaced
binaries.

POSIX inode unlinking semantics

In Unix and Linux filesystems, a directory entry is merely a hard link
associating a filename with an underlying inode number. When a package manager
installs an updated executable (e.g. /usr/bin/nvim):

1. The package manager unpacks the new file to a temporary name in the same
   filesystem.
2. It calls rename(2) or unlink(2) to point /usr/bin/nvim to the new inode.
3. Any process currently running the old executable still retains an open file
   descriptor or memory mapping to the previous inode.
4. The kernel maintains the previous inode data on disk as long as its open
   reference count exceeds zero. Storage space is freed only when the last
   running process closes the file or exits.

Inspecting unlinked files held open in memory

To detect running daemons or user processes that continue executing deleted or
upgraded code on disk, query open file references with lsof:

  
  lsof +L1
  

Any entry marked with a link count of 0 ( (deleted)) indicates an active process
running an unlinked inode. Restarting the specific service (via systemctl
restart <unit>) or closing and re-opening the application smoothly migrates
execution to the newly installed binary without disturbing other workstation
workloads.

Extending and Improving Your Workstation

Tamlinux is designed to be inspected, tuned, and extended by its user and
autonomous AI coding agents. Unlike opaque monolithic operating systems, every
configuration layer, script, and component in Tamlinux is transparent,
accessible, and built to extract maximum responsiveness from physical hardware.

The six improvement pillars

Zero-polling and event-driven architecture
    Eliminate periodic polling loops by leveraging kernel inotify, epoll, and
    Wayland compositor event sockets to keep the CPU in deep idle C-states and
    preserve battery life.

Memory compression with ZRAM
    Double effective memory capacity and prevent catastrophic disk thrashing
    using ultra-fast in-RAM swap compression backed by LZ4 and zstd.

Terminal and editor ergonomics
    Achieve sub-10ms shell startup latency and master the micro editor with
    automatic live disk reload (Virtue V11) when AI agents modify files
    concurrently.

Shell scripting and tool conventions
    Write rock-solid utilities following strict Bash headers, safe whitespace
    quoting, and Tamlinux namespace conventions (system-wide tam-* vs personal
    fred-* tools).

Native toolchains and multi-agent workflows
    Compile native C tools with libtam, apply architecture-tuned optimization
    flags (-O2, -march=native), and isolate concurrent coding agents with Git
    worktrees.

Physics of local AI generation
    Understand how hardware memory bandwidth dictates local LLM token generation
    speeds ($Tokens/s \approx Bandwidth / ModelSize$) and evaluate model
    quantization tradeoffs (Q4_K_M vs FP16).

Guiding principles for improvement

- Resource respect (Decision D53): New tools and features must not consume
  ongoing CPU cycles or memory when idle. Prefer event-driven wakeups over
  periodic timers.
- Strict offline default: Tamlinux tools run entirely offline with zero
  background tracking telemetry or obligatory network dependencies.
- Single best tool (Virtue V15): Standardize decisively on proven, minimal tools
  (e.g. micro for terminal Markdown, bash for scripting, native C for core
  utilities) rather than accumulating redundant alternatives.

Guide / Programming / Databases and data storage / The relational model and SQL

Many programs keep facts in tables: one list of members, another list of loans. SQL is the language used to ask questions of those tables and to change the facts they hold.

Tables of facts

A table holds rows, one for each item, and columns, one for each kind of fact. The schema says what the columns are called and what kind of value each may hold.

Why it matters

Names and shapes make questions precise. If every member row has an id and a name, you can ask for one member by id without guessing which word in a paragraph is the name.

How to think about it

Imagine a spreadsheet with a strict rule: every column keeps the same kind of value on every row. A primary key is like a student number that identifies one row. A foreign key points to a row in another table, so a loan can say which member made it.

A join brings rows from two tables together using a shared value. SQL describes the rows you want; the database works out how to fetch them.

Check yourself

What is the difference between a primary key and a foreign key?

A primary key identifies a row inside its own table. A foreign key is a value in one table that refers to a key in another table, which is how a join finds the matching row.

Why do we call SQL declarative?

You state which rows you want, not the loop or lookup steps to obtain them. The database plans the access, so the same question can use an index or a scan without the query changing.

How it works

A query is parsed into a plan. Conceptually, FROM and JOIN choose source rows, WHERE filters them, GROUP BY and HAVING aggregate groups, the select list forms output columns, and ORDER BY and LIMIT shape the result. Optimisers may reorder these steps when the result stays the same. SQL is a language interface to the engine: the statement says what to return, while the engine decides how to read it.

Edge cases and failure modes

  • NULL means unknown, not zero or empty text. col = NULL is not true; use IS NULL.
  • Without ORDER BY, result order is not guaranteed even when rows look sorted today.
  • An inner join drops rows with no match; an outer join keeps them with null columns on the missing side.
  • SQL injection happens when untrusted text is concatenated into a statement. Use bound parameters instead.

Check yourself

A join returned more rows than the member table contained. What is the likely cause?

A one-to-many relationship: one member can have several checkouts, so each matching checkout produces a row. Check the key on the many side and add a filter or aggregation if you wanted one row per member.

Why should a query with user input use bound parameters?

Binding keeps the input as a value, so characters such as quotes cannot change the statement's structure. Concatenating text lets an attacker feed SQL syntax to the parser, which is the injection failure.

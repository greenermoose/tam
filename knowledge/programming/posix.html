The POSIX Programmer's Manual

This page introduces a set of shared rules that help software work across different computer systems.

The POSIX manual describes shared rules for programs and systems. Instructions for a specific Linux computer may also describe features beyond those rules.

The standard sections

Manual pages from the POSIX standard append the letter p to their section number:

Section 0p (C Headers)definitions, macros, and type declarations required in standard C headers such as stdio.h(0p), unistd.h(0p), and fcntl.h(0p).
Section 1p (Standard Commands and Utilities)standard shell commands, options, and exit statuses for utilities such as sh(1p), awk(1p), grep(1p), and make(1p).
Section 3p (System Interfaces and Library Functions)standard C library functions and system interfaces such as fork(3p), open(3p), and pthread_create(3p).

Standard interface versus host implementation

Linux commands, notably GNU coreutils and util-linux, frequently add helpful extensions, non-standard options, and relaxed syntax. For example, GNU grep supports -P (Perl regular expressions) and long options like --color, neither of which is required by POSIX.

Reviewing the POSIX page clarifies what is portable:

Portable shell scriptsScripts starting with #!/bin/sh should adhere to the POSIX shell command language specified in sh(1p) to avoid bash-specific constructs ("bashisms") that fail on other shells or distributions.
Portable buildsChecking make(1p) shows standard Makefile rules and macros that work with BSD make, GNU make, and other standard-compliant make tools.
C library contractsFunction pages like regcomp(3p) document POSIX-mandated return codes, error numbers in errno, and thread-safety requirements.

Anatomy of a POSIX page

POSIX pages follow a rigorous specification layout. Two sections provide particular value when designing software or debugging edge cases:

APPLICATION USAGEpractical advice on how to use the interface safely, common pitfalls, and guidance on avoiding undefined behavior.
RATIONALEhistorical context explaining why the working group chose a specific interface, trade-offs evaluated, and why certain alternative designs or historical behaviors were rejected.

Reaching POSIX pages in Tamlinux

Tamlinux includes the complete POSIX Programmer's Manual through the system manual package. You can reach any POSIX page directly from the command line or through tam's interactive reader:

Direct lookupOpen a page directly by passing its section and name: tam man 1p sh, tam man 3p fork, or tam man 0p stdio.h.
Browse by sectionRun tam man, select Browse a section, and enter 1p, 3p, or 0p to view a paginated list of all installed POSIX pages.
Open from discoveryIn tam man, select Open a page and enter sh(1p) or 1p sh.
Keyword searchSelect Find by keyword in tam man to search summaries across both Linux and POSIX manuals.
Hyperlinked cross-referencesReferenced manual pages in the SEE ALSO section are converted to live links. Press Tab to select a link and Enter to follow it. Press Left Arrow to return.

HTML and CSS foundations

HTML says what a page contains, and CSS says how that content should look.

What this is

HTML is a plain text file with labels around words, such as a heading label or a list label. CSS is another text file with rules about colour, spacing, and size.

Why it matters

A browser can read those two files on almost any computer. That is why one web page works on a phone, a laptop, and a TV without a separate installation.

How to think about it

HTML is the skeleton and the words. CSS is the clothes. The same skeleton can wear different clothes for a narrow screen, a dark room, or a printed page.

New words

Element
A piece of a page, usually written with an opening tag, content, and a closing tag.
Attribute
Extra information inside a tag, such as a link address or a class name.
Selector
The part of a CSS rule that chooses which elements to style.

Worked example

$ cat > index.html
<!doctype html>
<html lang="en">
<head><meta charset="utf-8"><title>My first page</title>
<link rel="stylesheet" href="style.css"></head>
<body><h1>Hello, web</h1><p class="note">Made with HTML and CSS.</p></body>
</html>
$ cat > style.css
h1 { color: #16324f; }
.note { font-size: 1.1rem; }
$ python3 -c "...read index.html with HTMLParser..."
title: My first page
$ wc -c index.html style.css
 222 index.html
  52 style.css
 274 total

Captured in a scratch directory on 2026-11-24. The byte counts depend on your exact whitespace; the title does not.

  1. <!doctype html> tells the browser to use standards mode.
  2. <head> holds information about the page. Its title appears in the tab.
  3. <body> holds what the reader sees. The class attribute lets CSS find the paragraph.

Try it

Add a second paragraph with class="note" and change h1 { color: ... } to a different colour. Open the file in a browser and confirm both paragraphs change.

If it goes wrong

The page shows raw tags
The file is not named with an .html suffix, or the server is sending the wrong content type.
CSS does not appear
Check that style.css sits beside the HTML file and that the selector matches the class or tag exactly.

Why keep HTML and CSS in separate files?

One page of structure can wear several styles, and one stylesheet can give many pages the same look. Browsers can also cache the stylesheet, so later pages load faster.

Documents, boxes, and cascade

Reference

ConceptRule
ParserHTML is tokenized and tree-built with error recovery; invalid markup still produces a document.
Box modelEach element has content, padding, border, and margin. box-sizing: border-box includes padding and border in a declared width.
CascadeOrigin, importance, specificity, then source order decide which declaration wins.
LayoutNormal flow, flexbox, and grid place boxes; position can remove a box from flow.

How it works

A browser parses HTML into a tree, combines it with styles, and builds a render tree. CSS selectors match elements in that tree. Values such as 1rem resolve against the root font size, while em resolves against the current element. Media queries let one stylesheet respond to width, colour preference, or motion preference. A valid document gives assistive technology a reliable structure; WCAG adds testable accessibility requirements.

Advanced usage

:root { color-scheme: light dark; }
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after { animation-duration: 0.01ms !important; }
}

Illustrative snippet: modern CSS can express user preferences without JavaScript. Use !important sparingly because it changes the ordinary cascade.

Edge cases and failure modes

  • Missing <meta charset="utf-8"> can corrupt non-ASCII text.
  • Fixed pixel layouts break when text is enlarged or translated.
  • A selector with many IDs can become brittle; prefer meaningful classes.
  • Using a div for a button loses keyboard and assistive-technology behaviour that a real button supplies.

Check yourself

Two rules match the same paragraph. One has a class selector, the other an element selector and appears later. Which wins?

The class selector wins because specificity is compared before source order. Model answer: origin and importance come first, then specificity, then order. Later source order only breaks a tie in specificity.

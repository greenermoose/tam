Guide / Programming / Web development / HTML and CSS foundations

HTML gives a page its structure, such as headings and paragraphs. CSS describes how that structure looks.

Structure and appearance

HTML marks up content as headings, links and lists. CSS chooses colours, spacing and fonts for those pieces.

Why it matters

Separating the two lets the same structure wear different styles, including styles that work better for accessibility.

How to think about it

HTML is the skeleton and CSS is the clothing. The skeleton decides what is there; the clothing decides how it presents.

What just happened

The title names the document in the browser tab and in results; the h1 is the visible top heading. The note class connects the paragraph to a CSS rule. These files are sample source held in the sandbox, not files on your machine.

Try it

Run cat style.css. The selector h1 targets the heading; .note targets any element with that class.

If it goes wrong

The sample source keeps head elements on one line, so grep prints that line.

How it works

The parser builds a DOM, resolves CSS rules against it, computes styles, then lays out boxes. MarkUp must be well-formed enough for the browser's recovery rules, but HTML is not XML. Author style, user style and browser defaults combine through the cascade.

Edge cases and failure modes

  • Malformed nesting produces a different DOM than the source suggests.
  • Inherited properties and shorthand rules interact in non-obvious ways.
  • Font loading changes layout after first paint.
  • Colour alone should not convey meaning.

Guide / Programming / Web development / Frameworks and tooling

Frameworks and tools help teams build larger web applications, but they still produce ordinary HTML, CSS, and JavaScript in the end.

Helpful machinery, ordinary output

A library offers reusable functions; a framework also shapes how your code is organised. A bundler combines files for delivery.

Why it matters

Tools scale a team's work, but debugging still comes back to the browser's view of HTML, CSS and JavaScript.

How to think about it

Pre-cut parts speed up building a cupboard, but the finished cupboard is still made of wood and screws.

How it works

Tooling resolves imports, transforms syntax for target browsers, and can remove unused code. Frameworks add conventions for state and components, but the browser still receives HTML, CSS and JavaScript. Keep a way to inspect that output when debugging.

Edge cases and failure modes

  • Source maps can be wrong after several transforms.
  • Tree shaking depends on static analysis and can miss dynamic imports.
  • Dependency duplication inflates bundles.
  • Rendering strategies change caching and authentication behaviour.

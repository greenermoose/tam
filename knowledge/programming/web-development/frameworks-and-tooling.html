Frameworks and tooling

Frameworks and tools help a team build larger web applications, but they still produce ordinary HTML, CSS, and JavaScript in the end.

What this is

A library is code you call when you need it. A framework supplies the shape of an application and calls your code at the right moments. A bundler combines many source files into fewer files a browser can load.

Why it matters

A framework handles repeated work such as updating a page when data changes. A tool catches mistakes before readers meet them. Knowing what each one does helps you choose instead of copying a template.

How to think about it

A library is a tool you pick up. A framework is a workshop with a bench and a workflow. Neither replaces knowing what the wood and the saw do.

New words

Module
A file with an explicit interface to other files.
SPA
An application that loads one page and updates it with script.
SSR
A server that builds page markup before sending it.

Check a module before you ship it

Goal: you will be able to syntax-check a JavaScript file, import a function from a module, and assert its result.

Learner path: previous: Web security; next: Testing, debugging, and performance.

Worked example

$ node --check app.mjs
$ node app.mjs
5
$ node --input-type=module -e "import { strict as assert } from 'node:assert'; assert.equal(2 + 2, 4); console.log('module and assert OK');"
module and assert OK

Captured on 2026-11-24 with Node.js 24.5.0. app.mjs exported an add function and printed add(2, 3).

  1. node --check parses the file and prints nothing when syntax is valid.
  2. The .mjs suffix selects ES modules, so import and export work.
  3. assert.equal stops with an error if the value is wrong; silence apart from the final line means it passed.

Try it

Add a multiply export to a scratch module and assert that multiply(3, 4) is 12. Change the expected value to 11 and read the failure message.

If it goes wrong

Cannot use import statement outside a module
Rename the file to .mjs or set "type": "module" in package.json.
The bundler cannot find an import
Check relative paths and file extensions. A browser needs a real URL; a build tool may add one for you.

Check yourself

Decide your answer before you reveal it.

When should you reach for a framework rather than a library?

Use a library for one job you control, such as formatting a date. Use a framework when many pages share the same lifecycle, routing, and state rules and you want those rules handled consistently. Both still rest on the browser APIs you already learned.

How it works

A build tool follows module imports from an entry file, applies transforms, and writes browser-ready assets. Dead code removal drops exports nothing reaches. A SPA sends a small shell and builds most markup in the browser; a SSR application builds the first markup on the server and then attaches browser behavior. That attachment step must match the markup the server produced, or the page can flicker or lose input. Source maps connect generated code back to source when debugging, but they should not be exposed with personal data.

Advanced usage

export default {
  build: { target: 'es2022' },
  server: { port: 5173 },
};

Illustrative configuration: a build target sets the syntax level emitted, and a local port lets the page use ordinary HTTP origins during development.

Edge cases and failure modes

  • Dev and production builds can take different code paths; test the production output.
  • A dependency added for one small helper can dominate bundle size; measure before accepting it.
  • SSR code that touches browser globals during server execution crashes at startup.
  • Generated files committed by mistake hide which source actually changed.

Check yourself

A page renders correctly on the server but loses form input after loading. Which boundary do you inspect?

Model answer: the handoff between server markup and browser attachment, often called hydration. Compare the first markup with what the browser renders, confirm the same data was supplied on both sides, and look for browser-only globals running during server rendering. Fix the mismatch before blaming the framework.

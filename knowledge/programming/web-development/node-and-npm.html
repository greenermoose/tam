Guide / Programming / Web development / Node.js and npm

Node.js runs JavaScript on a computer without a browser, and npm helps you find and manage reusable code.

JavaScript beyond the page

Node.js is a runtime that runs JavaScript outside a browser. npm is a package manager that installs reusable packages.

Why it matters

The same language can serve web pages, run command-line tools and build desktop apps. npm records which versions a project uses.

How to think about it

Node is the engine in a car without a windscreen; npm is the parts catalogue and invoice file.

Read a package manifest

Goal: find the command that npm start runs.

What just happened

The manifest is sample data in the sandbox. Its scripts object gives start a command; npm runs that command when asked. The version is data, not permission to publish anything.

Try it

Run grep version package.json. A version helps identify a build, but a release still needs an explicit decision by the project owner.

If it goes wrong

grep returned a whole object line.
The sample manifest keeps scripts on one line, so grep prints that line.
I expected a running server.
The sandbox only shows the manifest. A real npm start runs the command in your project.

Check yourself

Decide your answer before you reveal it.

What does npm start do?

Runs the command stored under the start key in package.json.

Why keep dependencies in a manifest?

So another machine can install the same set of packages rather than guessing.

How it works

npm resolves dependency ranges, records exact answers in a lockfile, and links packages into node_modules. Node loads modules through its resolver and executes them on an event loop. The Node.js documentation is authoritative for flags and APIs.

Edge cases and failure modes

  • Semver ranges can pull different versions without a lockfile.
  • Lifecycle scripts can run code during install; review dependencies.
  • Mixing module systems needs careful interop.
  • Global and local installs resolve modules from different places.

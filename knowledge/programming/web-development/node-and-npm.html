Guide / Programming / Web development / Node.js and npm

Node.js runs JavaScript on a computer without a browser, and npm helps you find and manage reusable code.

What this is

Node.js is a runtime that uses the same JavaScript language as a browser but supplies different services. npm is a package manager that downloads and records reusable packages.

Why it matters

One language can describe the page a person sees and the program that answers its requests. That shortens the distance between the two halves of an application.

How to think about it

A browser gives script a window, a mouse, and a page. Node gives script files, network ports, and processes. The language stays the same; the tools around it change.

New words

Module
A file that publishes named values for other files to use.
Package
A folder of code with a name and version that npm can install.
package.json
The file that names a project, its scripts, and its dependencies.

Run a small project

Goal: you will be able to run a JavaScript file with Node, read project metadata with npm, and start a named script.

Learner path: previous: Browser APIs and asynchronous JavaScript; next: Full-stack web architecture.

Worked example

$ node --version
v24.5.0
$ npm --version
12.2.1
$ npm pkg get name version
name = 'demo-web-app'
version = '0.1.0'
$ npm run start
demo app

Captured in a scratch directory on 2026-11-24. The package.json named the project demo-web-app, set its version to 0.1.0, and defined start as node index.js. On this machine npm also printed a warning that version 12.2.1 expects a different Node version; the commands still ran.

  1. node --version reports the runtime, not the language version.
  2. npm pkg get reads package.json without changing it.
  3. npm run start looks up the named script and runs its command.

Try it

In a scratch directory, create index.js with console.log('hello from my app');. Write a package.json with a start script, then run npm run start. Change the message and run it again.

If it goes wrong

node: command not found
Node.js is not installed or not on your search path. Check with your package manager.
Missing script: start
Open package.json and add a scripts entry named start.
A dependency behaves differently from the browser
Node and browsers expose different global objects. Check whether the package is meant for a browser, a server, or both.

Check yourself

Decide your answer before you reveal it.

Name two services a browser supplies that Node does not, and two that Node supplies that a browser does not.

A browser supplies a page tree, windows, and user input events. Node supplies filesystem access, network listening sockets, and process control. Both share the JavaScript core language and an event loop.

How it works

Node embeds the V8 JavaScript engine and adds C++ and JavaScript services around it. Its event loop uses libuv for filesystem and network work. JavaScript callbacks run one at a time, but asynchronous operations finish in the background and queue their results. npm resolves a dependency tree from package.json, writes the chosen versions to a lockfile, and places code under node_modules. The lockfile is what makes a second install repeat the first one.

Advanced usage

const http = require('node:http');
const server = http.createServer((request, response) => {
  response.setHeader('Content-Type', 'text/plain');
  response.end('Hello from Node');
});
server.listen(0, '127.0.0.1');

Illustrative snippet: port 0 asks the operating system for an unused port. A captured request to such a server returned 200 text/plain Hello from Node.

Edge cases and failure modes

  • A synchronous filesystem call blocks every other request in that process.
  • Installing without committing the lockfile lets a later install choose different versions.
  • Engine mismatches can change syntax support; record the Node version with the project.
  • Dependency scripts run code during install; review new packages before adding them.

Check yourself

A service hangs after a slow database query even though the query runs in a library. What do you inspect first?

Model answer: check for synchronous work or an unawaited promise on Node's event loop. A library using a blocking call stalls all requests; a forgotten await leaves the request unfinished. Instrument the handler and time each boundary before blaming the database.

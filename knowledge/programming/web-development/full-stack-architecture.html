Guide / Programming / Web development / Full-stack web architecture

A full-stack application joins the page a person sees, the program that answers it, and the place its data is kept.

Client, server and store

The browser is the client. A web server answers its requests, often using JSON for data. A database keeps information between visits.

Why it matters

Knowing which layer owns a problem helps you decide where to look: page layout, network request, server logic or stored data.

How to think about it

It is a shop: the page is the shopfront, the server is the counter, and the database is the storeroom.

What does JSON carry here?

Why keep client and server separate?

Each layer can change, scale and enforce rules without rewriting the other.

How it works

A client sends an HTTP request with a URL, method and headers. The server validates it, reads or writes data, and returns a status with a body. CORS controls which browser origins may read a response; WebSocket adds a long-lived channel for push messages.

Edge cases and failure modes

  • Retrying non-idempotent requests can duplicate effects.
  • Client-side validation is a convenience, not a security boundary.
  • Missing pagination can turn a small query into a huge response.
  • Clock skew affects token expiry checks.

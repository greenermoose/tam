JavaScript and its history

JavaScript is the programming language that lets web pages respond to what you do, and it now runs in servers and desktop programs too.

What this is

A web page can show words and pictures, but JavaScript lets it also do things: check a form, change a picture, or ask another computer for fresh information.

Why it matters

Without JavaScript, a page is like a printed book. With it, a page becomes a small program that can react, remember, and talk to other programs.

How to think about it

Think of a stage play. HTML is the scenery and the actors, CSS is the costumes and lighting, and JavaScript is the direction that says what happens when an actor speaks.

New words

Script
A short list of instructions a program follows.
Interpreter

Worked example

$ node -e "const greet = name => \`Hello, \${name}!\`; const xs = [1,2,3].map(n => n * n); console.log(greet('alex'), xs.join(','));"
Hello, alex! 1,4,9

Captured on a Linux system with Node.js 24.5.0, 2026-11-24. Your output will match if Node is installed.

  1. const greet = name => ... stores a function that takes a name.
  2. [1,2,3].map(n => n * n) makes a new array by applying a function to each value.
  3. console.log prints the result. A semicolon ends a statement, but JavaScript often finds the end for you.

Try it

In a scratch file, change the greeting to your own name and add .filter(n => n > 2) before .map. Predict what prints, then run it with node your-file.js.

If it goes wrong

node: command not found
Node.js is not installed. The browser examples later in this course also run JavaScript, but this command needs the Node runtime.
The backticks vanish or the shell complains
Use single quotes around the whole program in your shell, or put the program in a file first.

Why was JavaScript created, and why is it still used everywhere?

Brendan Eich created it at Netscape in 1995 so browser pages could do small interactive jobs. It survived because every major browser adopted it, it was standardized as ECMAScript, and later runtimes such as Node.js let the same language work outside the browser.

Language, standard, and runtimes

Reference

NameWhat it names
JavaScriptThe language family people write and run.
ECMAScriptThe specification, edited by Ecma International's TC39 committee, that defines the core language.
EngineThe program that parses and executes JavaScript, such as V8, SpiderMonkey, or JavaScriptCore.
RuntimeAn engine plus the surrounding services, such as a browser's DOM or Node's filesystem and network modules.

How it works

The first version was written by Brendan Eich at Netscape in ten days in May 1995, first called Mocha, then LiveScript, then JavaScript. The name suggested a family tie with Java, but the two languages are different. Netscape submitted the language to Ecma International, and the first ECMAScript standard appeared in 1997. The large ES6 revision in 2015 added classes, modules, promises, and arrow functions. TC39 now adds features each year after reaching broad agreement.

An engine parses source into an abstract syntax tree, compiles it to bytecode, and may use a just-in-time compiler for hot code. The language itself does not define windows, files, or networks; the host environment supplies those as APIs. That is why browser JavaScript and Node JavaScript share syntax but not the same global objects.

Advanced usage

const numbers = [1, 2, 3];
const total = numbers.reduce((sum, n) => sum + n, 0);
console.log(total); // 6

Illustrative snippet: reduce carries one value through a whole collection. Prefer clear named functions when a chain grows hard to read.

Edge cases and failure modes

  • == compares after conversion and can surprise; prefer ===.
  • Numbers are IEEE 754 doubles, so large integers can lose precision; use BigInt when exact large integers matter.
  • let and const are block-scoped; old var is function-scoped and is hoisted.
  • Automatic semicolon insertion can change a return statement when a newline follows return.

Check yourself

If two engines pass the same ECMAScript tests, why might a page still behave differently?

ECMAScript defines the core language, not browser APIs, rendering, storage policy, or timing. Engines also ship different feature versions and optimization behavior. Model answer: separate language semantics from host APIs and engine implementation when comparing behavior.

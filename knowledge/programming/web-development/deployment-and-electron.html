Guide / Programming / Web development / Deployment and Electron desktop apps

Deployment puts a web app where people can reach it; Electron can put the same interface inside a desktop program.

Serving and packaging

A web server sends pages to browsers over the network. Electron bundles a browser engine and Node with a web interface so it can run as a desktop program.

Why it matters

The same interface can reach people through a URL or sit in an application window. Each route has different security and update needs.

How to think about it

Deployment is publishing a poster where anyone can read it. Electron is framing that poster and selling it as a book.

Read a local server request

Goal: identify method, path and status in a sample server log.

127.0.0.1 - - [24/Nov/2026 08:09:18] "GET / HTTP/1.1" 200 - Sample: wrote dist/index.html and dist/app.js Try: python3 -m http.server --bind 127.0.0.1 The second sample command shows a typical build output. Try one of the two sample commands, or type help.

What just happened

The log line is sample output from a local server; the sandbox does not bind a port. A public deployment should use HTTPS, not plain HTTP. Electron's browser window still needs the same web security care as a hosted page.

Try it

Imagine the path changing from / to /app.js. The method and status stay the same; only the requested resource changes.

If it goes wrong

No server is listening.
Correct: the log line is scripted sample text, not a live service.
I expected a browser window.
Electron cannot be launched in the sandbox; the page only describes its role.

Check yourself

Decide your answer before you reveal it.

What does status 200 mean?

The server successfully answered the request.

Why does Electron still need web security?

It renders web content, so injection and unsafe APIs can affect the desktop app too.

How it works

A deployment pipeline builds assets, uploads them and invalidates caches. Electron documents describe the boundary between the privileged main process and renderer processes. Chromium supplies the rendering engine, while Node supplies local APIs.

Edge cases and failure modes

  • Stale cached assets can serve old JavaScript after a release.
  • Exposing broad Node APIs to renderer content turns XSS into local code execution.
  • Desktop auto-updates need signing and rollback planning.
  • Deep links must be validated before opening files or URLs.

Guide / Programming / Web development / Deployment and Electron desktop apps

Deployment puts a finished web application where people can reach it; Electron can put the same interface inside a desktop program.

What this is

A simple web application can be a folder of files served by a web server. Larger ones also run a Node server and a database. Electron combines Chromium and Node so a web interface can run in its own desktop window.

Why it matters

The same HTML, CSS, and JavaScript skills can reach a person through a browser tab or an application launcher. You still choose which one fits the task.

How to think about it

Deployment is moving a shop to a street where customers can find it. Electron is putting a copy of the shop's front room inside a person's house, with a private door to local files.

New words

Worked example

$ python3 -m http.server --bind 127.0.0.1
127.0.0.1 - - [24/Nov/2026 08:09:18] "GET / HTTP/1.1" 200 -

Captured on 2026-11-24 with Python 3.14.8. A local request then reported 200 text/html <!doctype html><title>Demo</title><h1>Deployed</h1>. The local server is a rehearsal; it is not a public deployment.

  1. A folder held one index.html file. The server answered a request for / with status 200.
  2. The content type was text/html, so the browser rendered the file instead of showing raw text.
  3. A public deployment adds HTTPS, a stable address, backups, and a way to roll back a bad release.

Try it

Create a scratch folder with an index.html file, start the local server, and open the printed address. Stop the server with Ctrl+C when you are done.

If it goes wrong

The browser shows a directory listing
There is no index.html in that folder, or you opened a subdirectory.
The page works locally but not after upload
Compare paths that begin with / against the deployed base URL, and check the server's content type.

Check yourself

Decide your answer before you reveal it.

What did the local server prove, and what did it not prove?

It proved that the files can be served with the right status and content type. It did not prove public reachability, encrypted transport, correct behaviour under load, or safe rollback. Those belong to a deployment plan.

How it works

Electron runs a main process with Node privileges and one or more renderer processes that display web pages. Because the renderer is Chromium, browser APIs behave much as they do online, while the main process can use files and operating-system services. That split is also the security boundary: a renderer that receives untrusted page content should not be given unrestricted access to the filesystem. A deployment pipeline builds once, records what was built, installs that exact artifact, and keeps a rollback path. HTTPS is terminated at a trusted edge, and secrets stay in the server environment rather than the client bundle.

Advanced usage

// Main process: expose only named operations to a renderer.
const { app, BrowserWindow, ipcMain } = require('electron');
ipcMain.handle('read:preferences', async () => readPreferences());

Illustrative snippet: a renderer asks for a named operation; the main process decides what it may read. Do not expose a general file path supplied by page script.

Edge cases and failure modes

  • An Electron update bundles a large browser engine; users need a reliable rollback and update channel.
  • Node globals in a renderer can turn an XSS finding into local file access; disable them when they are not needed.
  • Assets cached by a browser can outlive a release; give changed files versioned names.
  • A deployment that builds twice may ship different dependencies even with the same source.

Check yourself

When would you choose a plain web app over Electron, and when would Electron earn its cost?

Model answer: choose the web when browser access, central updates, and small installs matter. Choose Electron when the product needs deep desktop integration, offline local files, or a consistent window across systems and the team can maintain a bundled browser engine. Reject Electron when a browser tab already meets the need.

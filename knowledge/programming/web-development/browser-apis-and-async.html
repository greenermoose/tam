Guide / Programming / Web development / Browser APIs and asynchronous JavaScript

Browser APIs let a page react to clicks, fetch data and remember small amounts of state. Asynchronous code keeps the page responsive while it waits.

What the browser offers

A browser API is a built-in feature a page can use, such as listening for a click or asking for data. A Promise represents a result that will arrive later.

Why it matters

Network requests take time. If a page waited for them without doing anything else, buttons and scrolling would freeze.

How to think about it

Imagine ordering at a café. You place the order, then sit at a table while it is prepared. The event loop is the person who calls your number when it is ready.

Check yourself

Decide your answer before you reveal it.

What does await pause?

Only the async function containing it, not the entire page or event loop.

Why keep long work off the main thread?

A busy main thread cannot respond to input or redraw the page.

How it works

The event loop runs a task, drains microtasks, then may render before choosing the next task. Promise continuations are microtasks, so they can starve rendering if chained endlessly. Same-origin policy and CORS decide which responses a page may read.

Edge cases and failure modes

  • A rejected promise without a handler becomes an unhandled rejection.
  • Async functions return promises even when they appear to return plain values.
  • Timers are minimum delays, not exact schedules.
  • Background tabs may throttle timers heavily.

Guide / Programming / Web development / Browser APIs and asynchronous JavaScript

Browser APIs let a page react to people, ask for data, and remember small amounts of information without freezing the page.

What this is

A browser page is always listening. An event is something that happens, such as a click or a key press. A browser API is a built-in way for script to ask the browser to do a job, such as fetch data or save a preference.

Why it matters

Without these services, JavaScript could calculate but could not hear a click, read a typed value, or ask another computer for fresh information. With them, a page becomes an application.

How to think about it

Think of a restaurant. The page is the dining room, events are customers raising a hand, and browser APIs are the staff who bring food or take a message to the kitchen. Your code decides what to do when a hand goes up.

New words

Browser API
A service the browser gives to script, such as events, storage, or network requests.
Promise
An object that stands for a result that will arrive later.
Event loop
The browser's way of taking one waiting job at a time.

Worked example

$ node -e "const delay = ms => new Promise(resolve => setTimeout(resolve, ms)); (async () => { console.log('start'); await delay(1); console.log('after await'); })(); console.log('before await ends');"
start
before await ends
after await

Captured on 2026-11-24 with Node.js 24.5.0. Browsers use the same ordering idea for a delayed timer or a network reply.

  1. delay(1) returns a promise that finishes after about one millisecond.
  2. await pauses that one function, not the whole program, so the last line prints next.
  3. When the timer fires, the paused function continues and prints after await.

Try it

Change delay(1) to delay(100) and add another console.log after the await. Predict the order before you run it.

If it goes wrong

The last line never prints
You may have used await at the top level in an older runtime. Put the code inside an async function or use a module.
A network request fails with a CORS message
The server did not permit your page's origin. Read CORS; a local file usually needs a local web server instead.

Check yourself

Decide your answer before you reveal it.

Why does before await ends print before after await?

await suspends only the async function that contains it. The event loop keeps running other work while the timer waits, then resumes the suspended function when its promise settles.

How it works

Each browser tab has a main event loop with a task queue and a microtask queue. Script runs to completion; it cannot be interrupted mid-statement. Promises queue microtasks, which drain before the next task. A fetch reply, a timer, and a click are tasks supplied by the host. Long synchronous work delays rendering because paint waits for the loop. The same-origin policy limits which replies script may read; CORS is the server's way to grant an exception.

Advanced usage

const controller = new AbortController();
const response = await fetch('/api/items', {
  signal: controller.signal,
  headers: { 'Accept': 'application/json' },
});
if (!response.ok) throw new Error(`HTTP ${response.status}`);
const items = await response.json();

Illustrative snippet: an abort signal lets a page cancel a stale request when the user navigates away or types again.

Edge cases and failure modes

  • An unhandled rejected promise reports an error even when no catch exists; attach handlers at the boundary.
  • Timers are throttled in background tabs, so they are unsuitable for precise scheduling.
  • Old replies can arrive after new ones; compare a request id before applying a result.
  • localStorage stores strings only and is synchronous, so large values block the main loop.

Check yourself

A click handler starts a long calculation and the page stops responding. Where is the fault, and what would you measure?

Model answer: the main event loop is blocked by synchronous work. Record a performance trace, find the long task, and move the calculation to a Web Worker or split it into smaller tasks. A faster repaint cannot fix a blocked loop.

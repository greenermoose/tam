The bar and menus around your windows

This page explains the software that provides the bar, menus, and other controls around your windows.

What desktop toolkits does Tamlinux use?

A graphical toolkit is the building-block library—providing buttons, text boxes, panels, and menus—that applications and desktop shells use to draw their user interfaces on screen.

Why it matters

The top bar, launcher menus, and status panels around your windows come from a desktop shell built on a toolkit. Knowing that the shell is separate from the window compositor makes it clear which piece to inspect or restart if a bar or menu misbehaves.

How to think about it

Think of the compositor as the gallery wall that hangs and frames every window, and the desktop shell toolkit as the carpentry kit used to build the clock, menus, and status bar mounted along the edge of the wall.

New words

Compositor
The program that arranges and draws windows on screen.
Quickshell
The Qt Quick / QML desktop shell framework Tamlinux uses for its bar, menus, and widgets.
QML
The declarative user-interface language used to describe Quickshell panels and widgets.

Separate shell and compositor

Goal: describe how the desktop shell relates to a compositor and its toolkit.

Mental model

A compositor manages application surfaces; a shell supplies interface elements such as panels; a toolkit helps implement them.

Worked example

The page below describes Quickshell as the toolkit and the Tamlinux shell as the interface built with it.

The desktop shell is the visible interface around your windows: the bar, menus, workspace indicators, notifications, and pop-up panels. Tamlinux keeps window management (the compositor) separate from this presentation layer and builds its own shell, the Tamlinux shell, with Quickshell and Qt Quick.

Why Quickshell

Quickshell is a toolkit for building desktop shells in QML on top of Qt Quick:

Declarative and reactiveQML properties bind directly to system state, so the interface updates when the state changes, without polling.
Layer-shell panelsbars and panels anchor to screen edges through the wlr-layer-shell protocol and reserve space for themselves.
Multiple monitorsa bar per output follows displays as they are connected and disconnected.

Independence from Omarchy

The Tamlinux shell began from components ported from Omarchy 4.0.4, keeping their MIT notices. Independence from Omarchy as a runtime dependency is complete: a Tamlinux desktop installs without Omarchy software, packages, or servers. Omarchy remains a peer project that Tamlinux watches for useful ideas and fixes.

Standard protocols firsta shared, compositor-neutral layer reads workspace and output facts from standard Wayland protocols such as ext-workspace-v1 and wl_output; small per-compositor adapters fill only the gaps. This is what lets the same shell move from Hyprland to Sway.
Shared componentsplugins use a common hover tooltip and a shared version footer in their panels.
Copyleftthe shell is maintained publicly in the tamlinux repository under GPL-3.0-or-later.

Alternatives considered

Waybara capable, lightweight status bar, but focused on bar modules rather than rich interactive panels.
Astal and AGSGTK widget frameworks scripted in TypeScript through GJS.
EWWa standalone widget engine in Rust with its own configuration language, Yuck.

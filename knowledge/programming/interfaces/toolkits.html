Guide / Programming / Application interfaces / The bar and menus around your windows

The bar, menus and controls around your windows are drawn by a desktop shell. It uses toolkits and a compositor to turn program code into the interface you see.

What draws the desktop

A compositor places windows on the screen. A desktop shell draws extras such as a bar and menus, often with Quickshell and QML.

Why it matters

Separating the shell from applications means the desktop can change without rewriting every program.

How to think about it

The compositor is the stage, applications are the performers, and the shell is the signage and lighting around them.

New words

Wayland
The protocol applications use to talk to the compositor.
Hyprland
The compositor that manages windows on Tamlinux.

How it works

QML describes visual objects and bindings; Qt Quick renders them. The shell creates surfaces that the compositor places alongside ordinary application windows. GTK and GJS are other toolkit routes, with different licensing and integration trade-offs.

Edge cases and failure modes

  • Compositor plugin ABI changes can break shell plugins after an update.
  • Wayland clients cannot read another client's contents without explicit protocols.
  • Binding loops in QML produce repeated updates.
  • A shell crash should not close applications, but it removes the bar and menus.

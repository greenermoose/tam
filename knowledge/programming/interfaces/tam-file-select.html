Guide / Programming / Application interfaces / Selecting files natively with tam-file-select

tam-file-select opens the desktop file chooser so a script can ask you to pick a file. It returns the chosen path and an exit status your script can check.

Letting a person choose

A script sometimes needs a file name from you. tam-file-select opens the desktop's XDG chooser and gives the chosen path back to the script.

Why it matters

Using the native chooser looks familiar and avoids making every script invent its own file list.

How to think about it

It is like handing someone a form and waiting for them to tick a file. If they cancel, the form comes back marked as unfinished.

Read a chooser result

Goal: check whether a file was chosen before using the returned path.

/home/alex/Pictures/logo.svg /home/alex/Pictures/logo.svg exit=0 Try: tam-file-select --title "Pick PNG or SVG" --extensions "png svg" Append ; echo $? to see the sample exit status. Try the tam-file-select command shown above, or type help.

What just happened

The path and status are sample output. The sandbox cannot open a real chooser, and no desktop portal is involved. In a script, a zero exit status means the path can be used; a cancelled pick should stop the script.

Try it

Think about the safe order: check the status first, then quote the path when passing it to another command. A path with spaces would otherwise split into several arguments.

On Tamlinux: the utility is written in C, links libtam, and is meant for shell scripts and theme tools.

If it goes wrong

No chooser window appeared.
The sandbox scripts the result as text. It does not open desktop windows.
I wanted a different extension.
Only the sample png/svg command is scripted. Real scripts can pass other extensions.

Check yourself

Decide your answer before you reveal it.

Why check the exit status?

A cancelled chooser gives no usable file path, so the script should stop instead of guessing.

Why quote the chosen path?

Paths can contain spaces or other shell characters; quoting keeps them as one argument.

How it works

The utility asks the portal for a file, prints the selected path on standard output, and uses its exit status to signal success. A script captures the output into a variable, checks the status, then passes the quoted path onward. The chooser's extension list is a convenience filter; the script should still validate the file it receives.

Edge cases and failure modes

  • No portal service in a bare session: the request cannot complete.
  • Cancellation produces no path; old variables may still hold a previous value.
  • Symlinks and relative paths need care before writing back to a file.
  • Accepted extensions do not guarantee a file's real type.

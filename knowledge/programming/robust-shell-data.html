Handling real data safely

This page shows how to handle filenames and input lines that contain spaces, quotes or other shell characters.

Data is not always tidy

A filename can contain a space. A line of input can begin with spaces that matter. A shell treats spaces as places to split words, so you need a way to say that a value came from data and must stay whole.

You do not need to run anything here. The examples show commands that were already tried in a temporary directory, which was removed afterwards.

Why it matters

A script that splits a filename into two pieces will look for two files. A script that passes data as shell text can also run commands hidden inside that data.

How to think about it

Imagine moving glassware between two shelves. You wrap each piece before carrying it. Quotes and read loops are the wrapping: the value arrives intact, whatever characters it contains.

New words

Word splitting
The shell step that cuts unquoted values into fields.
IFS
The variable holding the separator characters used by that step.
Script
A file containing shell instructions.

Goal: you will be able to process a list of values without losing spaces or splitting filenames.

Worked example

$ for f in $(printf '%s\n' 'Quarterly Report.pdf' 'invoice.txt'); do printf '<%s>\n' "$f"; done
<Quarterly>
<Report.pdf>
<invoice.txt>
$ printf '%s\n' 'Quarterly Report.pdf' 'invoice.txt' | while IFS= read -r line; do printf '<%s>\n' "$line"; done
<Quarterly Report.pdf>
<invoice.txt>

Captured on Arch Linux, 2026-11-22, in a scratch directory that was removed afterwards.

What just happened

  1. The command substitution in the first loop produced two lines of text.
  2. Because it was unquoted, word splitting cut the filename with a space into two names.
  3. The read loop takes one line at a time. IFS= stops it trimming leading and trailing spaces, and -r stops backslashes being interpreted.
  4. Quoting "$line" then passes the whole line to printf as one argument.

Try it

In a temporary directory, create two files whose names contain spaces and one whose name starts with a space. Print their names with a while IFS= read -r loop fed by find ... -print. Check that each printed name keeps its spaces, then remove the directory.

If it goes wrong

The last line is missing
A read loop needs its input to end with a newline. Use while IFS= read -r line || [ -n "$line" ] to process a final unterminated line.
Leading spaces vanish
You used read -r without IFS=. Add the empty IFS assignment to that command.

The usual interactive shell on Tamlinux is bash, described in Tamlinux components, so arrays and read -d are available in ordinary scripts. For a script that must run under a stricter shell, use the portable forms in POSIX Shell Command Language.

Check yourself

Decide before revealing the explanation.

Why does a for loop over unquoted command output split a filename with a space?

The output of the substitution is subject to word splitting before the loop begins, so the space in the filename becomes a word boundary.

What do IFS= and -r each protect in a read loop?

IFS= prevents trimming leading and trailing IFS characters; -r prevents backslashes from being treated as escapes. Together they preserve the line as written.

How it works

Unquoted expansions are re-tokenized by field splitting, and later by pathname expansion if they contain pattern characters. Data that must survive unchanged therefore has to be quoted, read field by field, or carried in an array. A NUL-delimited stream is the only common form that can represent every byte allowed in a filename, because NUL is the one byte a pathname cannot contain and a shell variable cannot store.

Advanced usage

$ find . -type f -print0 | sort -z | while IFS= read -r -d '' path; do printf '<%s>\n' "$path"; done
<./invoice.txt>
<./odd$name.txt>
<./Quarterly Report.pdf>

Edge cases

  • Command substitution strips every trailing newline, so it cannot faithfully carry text whose final line endings matter.
  • A pipeline stage runs in a subshell in many shells, so a variable set inside a while fed by a pipe may not survive; redirect from a here-string or process substitution when that matters.
  • Unquoted data can be interpreted as an option or as a command name. Use -- where a utility supports it, and never build commands by concatenating unquoted data.
  • Globbing and splitting happen before the command is identified, so a value that expands to a command name can change what is executed.

Check yourself

Why is a NUL-delimited stream the strongest way to transfer arbitrary filenames?

NUL is not allowed in a pathname, so it can never appear inside a name and is unambiguous as a separator. Shell variables cannot hold NUL, but the read loop can consume the stream field by field.

What is the injection risk in command substitution used to build a command line?

Unquoted results are split, can match filename patterns, and can supply command names or options. Quoting and arrays keep data as data.

Guide / Programming / Handling real data safely

Real filenames can contain spaces and odd characters. A shell script must keep each name as one piece instead of splitting it into words.

Names are not words

Shells split unquoted text on whitespace. A file called Quarterly Report.pdf can therefore look like two items. Quoting and IFS control that splitting.

Why it matters

A script that breaks names can rename, overwrite or skip the wrong file. Safe input handling prevents that.

How to think about it

A delivery label with two words is still one parcel. You would not treat "Quarterly" and "Report.pdf" as separate boxes.

Check yourself

Decide your answer before you reveal it.

What does IFS= do in read?

It prevents leading and trailing whitespace from being trimmed from the line.

Why use -r with read?

It stops backslashes from being treated as escape characters in the input.

How it works

The shell expands unquoted results using word splitting based on IFS. Newlines are valid characters in filenames, so line-based loops still have limits. NUL-delimited streams avoid that because NUL cannot appear in a path.

Edge cases and failure modes

  • Command substitution strips trailing newlines.
  • Pipelines run loops in a subshell in some shells, losing variable changes.
  • sort -z and read -d '' must be used together.
  • Glob patterns expand before a command sees its arguments unless quoted.

Guide / Programming / C and native toolchains / Object files, static libraries, and compilation stages

A compiler does not turn source straight into a finished program. It first makes object files, then a linker combines them with libraries.

From pages to a bound book

A compiler translates each C source file into an object file. A linker joins object files and libraries into one runnable program.

Why it matters

Stages let a large project rebuild only what changed. They also let one compiled object be reused in a static library.

How to think about it

Each source file is a chapter. Object files are the printed chapters; the linker binds them into a book and fills in references between chapters.

What lives in an object file?

Machine code, data, symbols and relocation information for one translation unit.

Why link a static archive?

It supplies object files that define symbols used by the program, without shipping them as separate source.

How it works

The compiler emits ELF relocatable objects with placeholders for external references. The linker resolves symbols, applies relocations, assigns addresses and chooses a layout. An ar archive is an index of member objects; the linker pulls in only members that satisfy a needed symbol.

Edge cases and failure modes

  • Order matters for static libraries: a library must follow the object that needs it.
  • Duplicate strong symbols cause link errors; weak symbols allow overrides.
  • Mixing object files built for different ABIs produces subtle failures.
  • Strip removes symbols needed for later debugging, not just size.

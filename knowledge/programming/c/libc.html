This page explains a collection of building blocks that many computer programs need to run.

Compare C libraries

The C standard library (libc) sits between almost every program and the Linux kernel. Tamlinux runs on glibc today and plans to compare it with musl on the target Void base, which offers both.

The two libraries

glibc (the GNU C Library)the standard C library of most Linux distributions. Feature-complete, heavily optimized, and the library that pre-built binary software expects.
musla small, simple, standards-focused C library with first-class static linking, used by Alpine Linux and available on Void.

Workstation trade-offs

Pre-built softwarebinaries such as Google Chrome and VS Code are built for glibc. On musl they need a compatibility layer such as gcompat or a glibc environment.
Proprietary driversproprietary GPU drivers are built for glibc. Open-source Mesa drivers work with either.
Size and speedmusl is smaller; glibc's tuned routines can be faster for some workloads.

The Tamlinux approach

Lower disk and memory use and better security are hypotheses to test, not assumptions. On Void, Tamlinux plans to compare full workloads on glibc and musl using matched application versions. A problem that appears only on musl is first checked on Void's glibc build, so that the C library is not blamed for a Void issue. The plan is published in the tamlinux repository as base-operating-system.md.

Check yourself

What evidence would support choosing one libc for a workstation?

Compare compatibility, complete workload measurements, security maintenance and recovery on representative hardware. A smaller library alone does not establish a better system.

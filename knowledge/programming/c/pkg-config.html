pkg-config: finding compiler and linker flags

pkg-config is a command that tells a build which settings an installed library needs.

A build turns written source code into a program. When your program uses a library, the build needs to know where that library keeps its header files and which library files to add. pkg-config reads a small description installed with the library and prints those settings for you.

What pkg-config is

Software is often split into reusable parts called libraries. A library ships a description of itself along with the code. pkg-config reads that description when you name the library, then prints the exact settings a build needs. You can also ask which version of the library is installed.

Why it matters

Typing those settings by hand is easy to get wrong. They change when a library moves to a different directory or starts depending on another library. Asking the library for its own settings keeps a build working without editing every recipe.

How to think about it

Think of pkg-config as a librarian for a shelf of libraries. You name the library you want. The librarian reads its catalogue card and hands you the directions for using it, including the directions for any other library it needs.

New words

Library
Reusable code that a program can use without containing that code itself.
Compiler
A program that turns written source code into machine code.
Linker
The step that joins compiled code with the libraries it uses to make a runnable program.
Environment variable
A named setting that a shell passes to commands it starts.

Behind the scenes, each description is a small file ending in .pc. The expert section shows what is inside one.

Asking a library for its flags

Goal: you will be able to ask pkg-config for a library's version and build flags, and say where the answers come from.

Worked example

$ pkg-config --modversion libtam
0.7.1
$ pkg-config --cflags --libs libtam
-I/home/alex/.local/include -L/home/alex/.local/lib -ltam
$ pkg-config --list-all | grep libtam
libtam                         libtam - Tamlinux C foundation library
libtam-portal                  libtam-portal - Tamlinux desktop portal library

Captured on an Arch Linux workstation, 2026-11-19. Your paths, versions and library list will differ.

What just happened

  1. --modversion prints the version recorded in the library's description: 0.7.1.
  2. --cflags prints the -I option that tells the compiler where to find header files. --libs prints the -L option for the library directory and the -l option naming the library.
  3. --list-all lists every description pkg-config can find. Filtering it with grep shows the two Tamlinux libraries installed under the user prefix.

Try it

List the descriptions on your own machine with pkg-config --list-all | less, pick a library you recognise, then ask for its version with pkg-config --modversion library-name. The name must match the listing exactly.

If it goes wrong

Package libtam was not found
The description is not on the search path. Check the spelling, then check whether the library was installed with development files; a runtime-only install often has no description.
Package 'libtam', required by 'libtam-portal', not found
A library that the first one depends on is missing from the search path. Install or build that dependency too.
The version printed is older than the one you just built
Two descriptions with the same name exist. pkg-config uses the first one it finds, so check the directories in PKG_CONFIG_PATH.

On Tamlinux

Development builds install under the user prefix, so their descriptions live in the user's ~/.local/lib/pkgconfig directory. The Tamlinux shell environment adds that directory to the PKG_CONFIG_PATH environment variable, which lets builds find libraries such as libtam without root. Packaging supplies the descriptions for system libraries in /usr/lib/pkgconfig and /usr/share/pkgconfig.

Check yourself

Decide your answer before you reveal it.

You ask for --cflags but the build still cannot find the library's header files. What do you check first?

Check the -I path that pkg-config printed and confirm the headers are really there. --cflags only reports the path recorded in the description; it cannot verify that the installed files match. A moved or partly removed development install leaves a stale path.

Package metadata and the search path

Reference

OptionWhat it prints
--cflagsAll compiler flags for the named packages.
--libsAll linker flags, including flags for dependencies.
--modversionThe version of each named package.
--list-allEvery package description found on the search path.
--atleast-version=VERSIONNothing, but exits successfully only when the package is new enough; useful in build recipes.
--variable=NAMEThe value of a variable in a package description, such as prefix.
--with-path=DIRAdds a directory to the search path for this invocation.
--print-errorsReports errors that pkg-config would otherwise keep quiet.

How it works

A description is a text file with a .pc suffix. This is the file for the local libtam build, with the example account's home directory:

prefix=/home/alex/.local
includedir=${prefix}/include
libdir=${prefix}/lib

Name: libtam
Description: Tamlinux C foundation library
Version: 0.7.1
Cflags: -I${includedir}
Libs: -L${libdir} -ltam

Cflags and Libs are the strings printed by --cflags and --libs. Variables such as ${prefix} keep the file short and let a relocated install adjust its paths. Requires names other packages whose flags must be included too.

The search path is built from the directories in PKG_CONFIG_PATH, followed by the command's built-in directories. On the workstation used for the example, the built-in directories are /usr/lib/pkgconfig and /usr/share/pkgconfig. The first description with a given name wins.

Because dependencies are folded in, asking for libtam-portal returns more than its own library:

$ pkg-config --libs libtam-portal
-L/home/alex/.local/lib -ltam-portal -ltam -ldbus-1

That output comes from Requires: libtam = 0.7.1, dbus-1 in the libtam-portal description. pkg-config adds the flags for both dependencies.

Advanced usage

A build recipe can drop the flags straight into a compiler command. This is illustrative, not a student exercise:

$ cc hello.c $(pkg-config --cflags --libs libtam) -o hello

For a guarded build, combine a version test with --print-errors so a missing or old dependency stops the recipe instead of failing later at link time.

Edge cases and failure modes

  • Two descriptions with the same name in different directories produce whichever one appears first on the search path. Put the intended directory first in PKG_CONFIG_PATH rather than relying on the built-in order.
  • Version constraints such as Requires: libtam = 0.7.1 are checked while walking dependencies. A version mismatch fails the whole query, even when the requested package itself is present.
  • pkg-config prints flags; it does not check that the files they name exist. A library removed without its description leaves flags that look valid but fail during compilation or linking.
  • The command on Arch-based systems is pkgconf, installed as pkg-config. Its --version reports the pkg-config specification it supports, not necessarily the pkgconf package version.

Check yourself

A build finds libtam on one workstation but not on another with the same package installed. What is the most likely difference?

The search path. pkg-config only reads .pc files in PKG_CONFIG_PATH and its built-in directories. If the package was built under a user prefix, that prefix must be on the path in the second environment; installing the package alone does not add it. Version and dependency checks run only after a description has been found.

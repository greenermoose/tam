Guide / Programming / C and native toolchains / pkg-config: finding compiler and linker flags

pkg-config asks an installed library for the compiler and linker settings it needs. Build scripts use those answers instead of guessing paths.

Asking a library for its settings

A library needs include paths for its headers and link flags for its code. pkg-config reads a small description file and prints those settings.

Why it matters

Hard-coded paths break when a package is installed somewhere else. Asking the library keeps a build portable across user and system installs.

How to think about it

Imagine calling a supplier for the exact parts list instead of guessing what size screws you need. The answer comes from the source that knows.

Compare cflags and libs

Goal: explain why header flags and link flags are different answers.

0.7.1 -I/home/alex/.local/include -L/home/alex/.local/lib -ltam -I/home/alex/.local/include -L/home/alex/.local/lib -ltam Try: pkg-config --modversion libtam Type pkg-config --cflags libtam. Now type pkg-config --libs libtam. Try one of the four pkg-config commands, or type help.

What just happened

The version, include path and link flags are authored samples for a user-local libtam install. The sandbox does not inspect your system. Include flags help the compiler find headers; link flags help the linker find code.

Try it

Run pkg-config --cflags --libs libtam. Build scripts often place this whole answer directly on a compiler command line.

If it goes wrong

The paths mention /home/alex.
That is the sample account used by the sandbox. On your system the answer depends on where the library was installed.
The sandbox did not find my library.
Only the sample commands are scripted; it does not read your system package database.

What does --cflags provide?

Include and define flags needed while compiling source that uses the library.

What does --libs provide?

Search paths and library names needed while linking.

How it works

pkg-config reads description files from its search path and substitutes variables such as ${prefix}. It emits flags for the requested packages and their dependencies. A build script should quote the result or use an array so spaces do not split arguments incorrectly.

Edge cases and failure modes

  • Multiple .pc files with the same name: the first search hit wins.
  • Cross-compilation needs a sysroot-aware pkg-config wrapper.
  • Missing private dependencies appear only when static linking is requested.
  • A wrong prefix produces headers from one install and libraries from another.

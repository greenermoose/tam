Guide / Programming / C and native toolchains / Compiler sanitizers, AddressSanitizer, and memory safety in C

A sanitizer adds checks to a compiled program so it reports memory mistakes when they happen. AddressSanitizer catches reads or writes outside the memory a program owns.

Runtime smoke alarms

A sanitizer is a compiler feature that adds checks to a program. AddressSanitizer, or ASan, watches memory accesses and reports a buffer overflow or use-after-free.

Why it matters

Memory mistakes can crash a program or be exploited. A clear report during development is much easier to fix than a strange failure much later.

How to think about it

It is like a smoke alarm in a workshop. The work still happens, but the alarm points to the exact moment something starts burning.

What does -g add?

Debug information that lets the report name source files and lines.

Why combine ASan and UBSan?

They catch different classes: invalid memory access and undefined operations such as signed overflow.

How it works

ASan reserves shadow memory that records which bytes are addressable, surrounds allocations with redzones, and quarantines freed regions. A checked access consults the shadow state and reports the nearest source location from DWARF data. UBSan instruments individual language rules instead.

Edge cases and failure modes

  • ASan increases memory use and slows execution; it is a development tool.
  • Some errors appear only with particular optimization levels.
  • Custom allocators may need explicit annotations to be checked.
  • Leak detection can be disabled when third-party libraries retain allocations.

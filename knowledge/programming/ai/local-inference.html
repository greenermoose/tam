Guide / Programming / Working with AI / The speed and energy use of AI on your computer

Local AI runs a model on your own computer. Its speed depends on memory, the processor or graphics card, and how much work each request asks for.

What uses the computer

Running an AI model on your own machine means keeping its weights and working data in RAM. A GPU can do many simple sums at once, which suits this work.

Why it matters

A model that does not fit in memory can become very slow because the system starts swapping. Knowing what to check helps you choose a smaller model or a shorter request.

How to think about it

Think of a kitchen. RAM is the counter space, the processor is the cook, and the model is a very detailed recipe. More counter space means less time fetching ingredients from storage.

What just happened

The report is sample output, not a reading from your machine. The free column ignores memory that can be reclaimed from caches; the available column estimates what new work can actually use. Model weights and the context being processed both need room.

Why is available RAM a better guide than free RAM?

Available includes memory the system can reclaim from caches; free counts only what is untouched right now.

What happens when a model exceeds RAM?

The system may swap to disk, which is much slower, or the process may fail to allocate memory.

How it works

Decode inference is usually memory-bound: the accelerator streams weights for each token rather than performing enough arithmetic to saturate its compute units. Batch processing changes that balance. Remote APIs move the cost to a server and add HTTP, URL and TLS considerations.

Edge cases and failure modes

  • Thermal throttling can reduce sustained speed below short bursts.
  • Unified-memory systems share bandwidth between CPU and GPU.
  • Very long contexts can dominate memory even when weights fit.
  • Optional layers and adapters change the real footprint.

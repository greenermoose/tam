Guide / Programming / Numbers in computers / Fractions, decimals and floating point

A binary memory can hold a fraction by agreeing that some bit positions count for less than one.

Whole numbers were covered on the previous page. This page moves the place value past the ones column.

Places smaller than one

In decimal, the first place after the point is tenths, then hundredths. In binary, the first place after the point is halves, then quarters, then eighths. A fixed-point value puts the point in an agreed position. A floating-point value stores where the point belongs along with the digits.

Why it matters

Sizes, temperatures, prices and measurements are rarely whole numbers. A representation has to say which fractions are available and how much error is acceptable when a value is stored.

How to think about it

Think of a ruler. A ruler marked in millimetres cannot show half a millimetre. Binary memory is similar: it has a finite set of marks. Some decimal fractions, such as one tenth, do not land on a binary mark exactly, so the nearest mark is stored instead.

New words

Fixed point
A number with a set number of bits reserved for the fractional part. See fixed-point.
Floating point
A number stored as digits plus an exponent, so the point can move. See floating-point.
Rounding
Choosing the nearest representable value when the exact one does not fit.
BCD
A way of storing each decimal digit separately, often used when decimal exactness matters.

Store a fraction and see the rounding

Worked example

$ python3 -c "scale=256; v=int(1.5*scale); print(v, format(v,'016b'), v/scale)"
384 0000000110000000 1.5
$ python3 -c "print(format(0.1, '.20f')); print(0.1+0.2, (0.1+0.2)==0.3); from fractions import Fraction; print(Fraction(13,32))"
0.10000000000000000555
0.30000000000000004 False
13/32

Captured on a Linux system with Python 3, 2026-11-24. Your output will match for these values.

What just happened

  1. The first command used a scale of 256. The stored integer 384 means 384 divided by 256, which is exactly 1.5. Eight fractional bits give steps of 1/256.
  2. The second command printed the stored binary floating-point approximation of 0.1. It is close, not exact.
  3. Adding 0.1 and 0.2 gives 0.30000000000000004, so an exact equality check against 0.3 fails. Fraction 13/32 is exact because 32 is a power of two.

Try it

In a scratch directory, repeat the fixed-point command for 0.5, 0.25 and 0.1. Which values come back exactly? Then check whether 0.1 + 0.1 + 0.1 == 0.3 is true.

If it goes wrong

A fixed-point result is slightly off
The scale may not divide the value evenly. Increase the scale or use an exact fraction type when the value must be exact.
A money total drifts
Binary floating point is the wrong tool for currency. Use fixed integer minor units or an exact decimal type.

Check yourself

Decide your answer before you reveal it.

Which is exact in binary: 1/8 or 1/10? Why?

1/8 is exact because 8 is a power of two, so it is 0.001 in binary. 1/10 has a repeating binary expansion, so it can only be approximated in a finite word. Decimal notation and binary notation have different sets of exact fractions.

How it works

IEEE 754 stores a value as sign times significand times two to the exponent. The significand carries the digits; the exponent sets the scale, much like scientific notation in decimal. Normal binary values have an implicit leading 1 bit, which saves one bit of storage. Subnormal values give up that leading 1 to represent numbers very close to zero. Special patterns represent infinity and NaN.

Rounding is required whenever a real value falls between representable values. IEEE 754 defines several modes; round-to-nearest, ties-to-even is the default. Precision is the number of digits carried; it is not the same as accuracy, which describes how close a value is to the true quantity. Overflow produces infinity in the default mode, while underflow can produce zero or a subnormal.

Advanced usage

$ python3 -c "import struct; print(struct.pack('>f',13.5).hex()); print(struct.unpack('>f',bytes.fromhex('41580000'))[0])"
41580000
13.5

Illustrative sequence: 13.5 is exactly representable because it is 1.6875 times 2^3, and 1.6875 has a short binary expansion. Most decimal fractions do not.

Edge cases

  • Comparing floating-point values for exact equality is usually wrong. Compare within a tolerance chosen for the problem.
  • Adding a very small value to a very large one can lose the small value entirely; the exponent must shift before the digits can align.
  • Java, Python, SQL and hardware decimal units may use different decimal rules. A format name alone does not define rounding for money.
  • Catastrophic cancellation occurs when subtracting nearly equal values: leading digits cancel and the remaining digits carry mostly previous rounding error.

Check yourself

A program stores money in binary64. What can go wrong, and what would you change first?

Two tenths may not be exact, so repeated additions can leave a total such as 0.30000000000000004. Equality and rounding to cents can then fail. First change the representation: store integer cents or use a decimal type with an explicit rounding rule, then keep the scale fixed throughout the calculation.

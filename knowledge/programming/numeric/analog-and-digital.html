Analog values and digital approximations

Real-world measurements vary smoothly, while a computer stores one of a finite set of numbers for each moment it records.

From a smooth value to numbered snapshots

An analog value can be any level in a range, such as the voltage from a microphone. A digital system takes samples at separate moments and stores each one as a number. An analog-to-digital converter, or ADC, does the measuring. A digital-to-analog converter, or DAC, turns stored numbers back into a voltage.

Why it matters

Sound, light, temperature and radio arrive as changing physical levels. To store, send or process them in a computer, they must become numbers. The conversion always loses some detail, so knowing what was lost helps you judge whether a recording or measurement is good enough.

How to think about it

Think of a film camera. It takes separate pictures rather than a continuous record. More frames per second capture faster motion; finer colour steps capture subtler shading. A digital converter makes the same two choices: how often to look, and how finely to record what it sees.

New words

Sampling
Recording values at separate points in time. See sampling.
Quantization
Rounding each sample to the nearest available number. See quantization.
Bit depth
How many bits each sample uses, which sets the number of available levels. See bit depth.
Nyquist criterion
The rule that a sample rate must exceed twice the highest frequency you want to capture.

Round a voltage to a digital code

Goal: you will be able to map a voltage range onto a fixed number of codes and explain the resulting error.

Learner path: previous: fractions and floating point; next: fast numerical computing.

Worked example

$ python3 -c "levels=16; vals=(0.0,0.3,0.99,1.0); [print(f'{v:4.2f} V -> code {min(levels-1,round(v*(levels-1))):2d} -> {min(levels-1,round(v*(levels-1)))*1.0/(levels-1):4.2f} V') for v in vals]"
0.00 V -> code  0 -> 0.00 V
0.30 V -> code  4 -> 0.27 V
0.99 V -> code 15 -> 1.00 V
1.00 V -> code 15 -> 1.00 V

Captured on a Linux system with Python 3, 2026-11-24. Your output will match.

What just happened

  1. Sixteen levels need four bits, because 2^4 is 16. The codes run from 0 to 15.
  2. The input range 0 to 1 volt was multiplied by 15, then rounded. The code 4 means 4/15 volt, about 0.27 V, not 0.30 V.
  3. This is quantization error. More bits give more levels and a smaller step, but never a perfect copy of a continuous value.

Try it

In a scratch directory, change levels to 256 and repeat. What is the closest code for 0.30 V, and what voltage does it represent? How many bits does 256 levels need?

If it goes wrong

Your code is 16 or larger
The rounding reached the value after the last code. Real converters clip or saturate at the top of their range instead of wrapping.
The recording sounds gritty
Too few levels create audible quantization steps. Raising bit depth reduces that noise but uses more storage.

Check yourself

Decide your answer before you reveal it.

A sensor uses 12 bits over a 0 to 3.3 V range. How many levels are there, and roughly how large is one step?

2^12 = 4096 levels. The step is about 3.3 V / 4095, roughly 0.00081 V. Endpoints and converter design can shift the exact divisor, but the scale is set by the bit depth and range.

How it works

The Nyquist criterion says a signal with no frequency above B hertz can be recovered from samples taken more than 2B times per second. Without an anti-alias filter before the ADC, frequencies above half the sample rate fold into lower ones and cannot be removed later. Pulse-code modulation, or PCM, is the straightforward encoding: one code per sample at a fixed rate and width. Compressed audio often starts from PCM and then exploits prediction or frequency-domain coding.

A DAC holds or reconstructs a voltage from each code. A zero-order hold produces a staircase; an output filter smooths it. Clock jitter, non-linearity, noise and reference drift affect the result even when the digital numbers are exact. Conversion is a chain, not just a rounding step.

Advanced usage

$ python3 -c "import math; rate=48000; tone=19000; print(rate/2, tone, 'alias at', abs(tone-rate))"
24000.0 19000 alias at 29000

Illustrative sequence: a 19 kHz tone is below half of 48 kHz, so it is safe here. A 29 kHz tone would fold to 19 kHz after sampling at 48 kHz, which is why converters filter the input first.

Edge cases

  • Oversampling gives more samples than the minimum, which eases filter design and can reduce noise through averaging.
  • Dither adds a tiny controlled noise before quantization so error becomes less correlated with the signal, useful in audio and images.
  • Logarithmic encodings such as mu-law use uneven spacing to give fine resolution to quiet sounds and coarser resolution to loud ones.
  • One bit per sample can represent an on/off state, but a chain of such decisions can still describe a waveform through delta-sigma conversion.

Check yourself

You record a 44.1 kHz audio stream from a sensor that also emits a 30 kHz tone. What should the analog front end do before sampling?

Filter out everything above 22.05 kHz before the ADC. Otherwise the 30 kHz tone aliases into a lower frequency in the recording. Raising the sample rate above 60 kHz would also satisfy the criterion, but only if the converter and storage support it.

Number systems and bases

A number system is a way of writing a count using digits, and a computer mostly uses binary because its circuits have two stable states.

This page uses only whole numbers. Fractions and decimal values come later on the path.

Counting with different sets of digits

You count in tens because you learned the digits 0 through 9. A binary number uses only 0 and 1. A hexadecimal number uses 0 through 9 and then A through F. The radix, or base, tells you how many digit values a system has.

Why it matters

Computer memory is made of bits, each holding one of two states. Writing a value in binary shows those states directly. Writing the same value in hexadecimal keeps the same information but makes long strings shorter and easier to check.

How to think about it

Think of an odometer. In a decimal odometer, a wheel rolls over after 9. In a binary odometer, each wheel rolls over after 1. The rightmost wheel is the ones place; each wheel to its left is worth the base times the one before it.

New words

Radix (base)
The number of digit values in a system: 2 for binary, 10 for decimal and 16 for hexadecimal. See radix.
Bit
One binary digit, a 0 or a 1. Eight bits make one byte.
Byte order
Which byte of a multi-byte number is stored first in memory. See endianness.

Read and convert a whole number

Goal: you will be able to read a whole number in several bases and check a conversion with a short command.

Learner path: Start this path; next: whole numbers in binary memory.

Worked example

$ printf '%d %o %x\n' 42 42 42
42 52 2a
$ python3 -c "print(bin(42), oct(42), hex(42)); print(int('101010', 2), int('2a', 16))"
0b101010 0o52 0x2a
42 42

Captured on a Linux system with Python 3, 2026-11-24. Your output will match when you use the same commands.

What just happened

  1. printf printed one value three ways: decimal 42, octal 52 and hexadecimal 2a.
  2. Python's bin, oct and hex add prefixes so you can tell the bases apart.
  3. int(text, base) went the other way. Both 101010 in base 2 and 2a in base 16 are 42.

Try it

In a scratch directory, print your own age or a room number in decimal, octal and hexadecimal. Then convert one result back to decimal and check that you get the starting value.

If it goes wrong

ValueError: invalid literal for int()
The digits do not match the base you gave. Hexadecimal g and octal 8 do not exist.
The prefixes look wrong
Python uses 0b, 0o and 0x. A leading zero alone does not mean octal in Python 3.

Check yourself

Decide your answer before you reveal it.

Why does one hexadecimal digit replace exactly four binary digits?

Sixteen is two to the fourth power. Four bits have sixteen possible patterns, from 0000 to 1111, so each pattern maps to one hex digit from 0 to F without gaps or overlap.

How it works

For radix b, a numeral with digits d_n ... d_0 means the sum of d_i times b^i. Converting a whole number to another base is repeated division: record the remainders from right to left until the quotient is zero. Converting back is repeated multiplication and addition. A byte is eight bits, so it spans two hexadecimal digits; a 32-bit word spans eight.

Byte order is a separate question from the value. Memory is addressed by byte, so a value wider than one byte must choose which byte goes at the lower address. In little-endian order the least significant byte comes first; in big-endian order the most significant byte comes first. Network protocols have traditionally used big-endian order, which is why it is often called network byte order.

Advanced usage

$ python3 -c "import struct; v=0x12345678; print(struct.pack('I',v).hex(' '))"
78 56 34 12
12 34 56 78

Illustrative sequence: the same 32-bit value written to a byte buffer with the two byte orders. Reading with the wrong order gives a different number even though the bytes are unchanged.

Edge cases

  • Leading zeros change the width of a display but not the value. They matter when a field has a fixed size.
  • A base prefix is notation, not a different kind of number. Arithmetic is the same; only the written digits differ.
  • Endianness applies to bytes within a multi-byte value, not to the order of bits inside a byte and not to text characters.

Check yourself

A file stores the bytes 78 56 34 12. What is the 32-bit integer if it was written little-endian, and what if it was written big-endian?

Little-endian reverses the byte list before reading place value, giving 0x12345678. Big-endian reads the list as written, giving 0x78563412. The bytes alone do not tell you the order; the format or protocol must define it.

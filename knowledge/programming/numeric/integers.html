Whole numbers in binary memory

A fixed group of bits can hold a whole number, and the way its patterns are interpreted decides whether negative values are available.

Two ways to read the same bits

When every pattern means a positive count, the value is unsigned. When half the patterns are reserved for negative counts, the value is signed. Almost every modern computer uses two's complement for signed whole numbers.

Why it matters

Programs need both counts, such as the number of bytes in a file, and changes that can go below zero, such as a bank balance or a temperature. Two's complement lets one arithmetic logic unit add both kinds of numbers with the same circuit.

How to think about it

Imagine a three-digit odometer that wraps from 999 back to 000. For signed numbers, split the circle: 000 through 499 are positive, and 500 through 999 stand for -500 through -1. The last digit still counts upward; only the label changes when you cross the halfway point.

New words

Sign bit
The leftmost bit of a signed two's complement value. It is 1 for negative values and 0 for non-negative ones.
Overflow
When a result is too large or too small for the chosen width. See overflow.
Arbitrary precision
A representation that grows to hold larger values instead of using a fixed width. See arbitrary precision.

Recognise a negative value

Goal: you will be able to write a small negative number in eight-bit two's complement and explain what happens at the ends of the range.

Worked example

$ python3 -c "for v in (5, -5): print(f'{v:6d} -> {v & 0xff:08b}')"
     5 -> 00000101
    -5 -> 11111011

Output captured on a Linux system with Python 3, 2026-11-24. Your output will match.

What just happened

  1. The expression v & 0xff keeps the low eight bits, the width of one byte.
  2. Positive 5 needs no special treatment: 00000101 is 4 + 1.
  3. Negative 5 becomes 11111011. Invert the bits of 00000101 to get 11111010, then add one to get 11111011. Adding 5 and -5 in eight bits gives 00000000, with the extra carry discarded.

Try it

In a scratch directory, use the same command for -1, -128 and 127. Check that -1 is all ones, and that 127 is the largest positive eight-bit value.

If it goes wrong

The result has more than eight bits
The mask 0xff was left out. Without it Python shows an infinite string of leading ones for negative numbers.
127 plus 1 gives -128
That is signed eight-bit overflow. The pattern 10000000 means -128, not 128.

Check yourself

Decide your answer before you reveal it.

Why is the range of eight-bit two's complement -128 to 127 rather than -127 to 127?

Zero needs only one pattern. That frees 10000000, the pattern with the sign bit set and no positive partner, to represent -128. The positive half still runs from 0 to 127, so the total is 256 patterns.

Program width

The widths in this table describe stored values. An 8-bit, 32-bit or 64-bit program also names the ABI it was built for: pointer width, register mode, calling convention and libraries. That is why a 64-bit operating system can run a 32-bit program when compatibility libraries are installed, while a 32-bit system cannot run a 64-bit program.

How it works

For a width of k bits, unsigned values use 0 through 2^k - 1. Two's complement values use -2^(k-1) through 2^(k-1) - 1. Negation is bitwise inversion plus one, modulo 2^k. Addition, subtraction and multiplication use the same low-bit result for signed and unsigned operands; only the interpretation of the sign bit and the overflow test differ. This is why one adder serves both cases.

Fixed-width arithmetic wraps modulo 2^k. That is useful for counters and cryptography, but surprising for ordinary arithmetic. Languages differ on what they guarantee when signed overflow occurs, so check the language rule before relying on wrapping. Arbitrary precision integers avoid the bound by allocating more words as needed, at the cost of extra work and memory.

Advanced usage

$ python3 -c "u=0xff; print(u+1, (u+1) & 0xff); print((-5) & 0xff, ((-5) & 0xff)-256)"
256 0
251 -5

Illustrative sequence: the mathematical sum and the stored eight-bit result differ. Interpreting 251 as signed recovers -5 by subtracting 256, which is 2^8.

Edge cases

  • Shifting a signed negative value right can fill on the left with ones (arithmetic shift) or zeros (logical shift), depending on the language and type.
  • Byte order affects storage and interchange, not the arithmetic result once the value is loaded into a register.
  • Converting between widths needs sign extension for signed values and zero extension for unsigned values. Getting this wrong changes negative numbers into large positive ones.

Check yourself

You receive one byte 0xff and must interpret it. What are the two possible values, and how do you decide?

As unsigned it is 255; as eight-bit two's complement it is -1. The byte alone cannot settle it. A format, protocol or variable type must say whether the value is signed and how wide it is.

Guide / Programming / Numbers in computers / Fast numerical computing

Numerical code gets fast when data is arranged for the processor and the same small operation is repeated without wasted work.

Lots of small sums

A vector is a list of numbers; a matrix is a grid. Linear algebra describes operations on them, and libraries such as BLAS and LAPACK implement those operations efficiently.

Why it matters

The same mathematical result can take very different time depending on memory layout and how much work is repeated.

How to think about it

Imagine workers reading a row of numbered cards. Reading neighbours in order is quick; jumping around the table wastes time.

Why do BLAS libraries matter?

They encode tuned kernels for common vector and matrix operations instead of leaving every program to reinvent them.

What is a stride?

The distance in memory between successive elements of a vector or row.

How it works

BLAS_level routines reuse small kernels tuned for a CPU's registers and cache. LAPACK builds higher-level factorisations on BLAS. Precision choices change both storage and arithmetic cost; mixed-precision methods exploit that carefully.

Edge cases and failure modes

  • Alignment and aliasing can defeat vectorisation.
  • Transposed layouts change which loop has stride 1.
  • Reduction order changes floating-point results.
  • GPU transfers can cost more than the computation they enable.

Hardware Security and Privilege Management

This page explains physical authentication tokens, biometric fingerprint sensors, SSH remote access hardening, and administrative privilege management on Tamlinux.

What is hardware security?

Hardware security uses physical devices—such as USB security keys (FIDO2 or YubiKey) or built-in fingerprint readers—to verify your identity before performing sensitive tasks or logging in.

Why it matters

Passwords can be observed, guessed, or intercepted. Physical keys and fingerprints provide convenient hardware-backed alternative authentication that verifies your physical presence at the machine, allowing quick authorization while retaining password fallback.

How to think about it

The system uses PAM (Pluggable Authentication Modules) and Polkit to verify permissions. You can register a hardware key or fingerprint so that authorizing administrative actions or unlocking the screen only requires a touch.

New words

FIDO2
An open authentication standard that uses cryptographic keys stored on a hardware token to verify user identity without sending passwords.
Biometrics
Physical characteristics, such as fingerprints, used as a secure form of authentication.
Privilege
Permission granted by the operating system to modify system files, install software, or access hardware devices.

Inspect privilege and authentication settings safely

Goal: you will be able to check privilege configurations and understand how hardware keys protect administrative actions.

Worked example

  1. Check whether your current session requires sudo to interact with Docker: 
    $ tam-sudo-docker; echo "Exit status: $?"
Exit status: 0
    This silent predicate returns exit 0 when sudo is required, or exit 1 when Docker is directly accessible.
  2. When performing temporary administrative maintenance, you can enable a bounded passwordless sudo window (for example, 15 minutes): 
    $ tam-sudo-passwordless 15
    Note that during this active window, any process running as your user can execute any root command without prompting; the timeout limits only the duration, not the scope of authority.
  3. In scripts requiring repeated administrative actions, tam-sudo-keepalive keeps the authorization token fresh in the background while the parent script runs.

Try it

Run tam-sudo-docker --configured; echo $? in your terminal. With --configured, it checks account group membership rather than the live socket, returning exit 0 if the user will need sudo after logging in or exit 1 if the docker group is configured.

If it goes wrong

FIDO2 key not recognized when prompted
Ensure the key is securely seated in a USB port and its contact sensor illuminates; enter your normal account password as fallback.
Fingerprint reader fails on laptop lid close
Tamlinux includes clamshell gates that automatically bypass fingerprint prompts when the laptop lid is closed with external screens attached.

Every privileged step in Tamlinux requires explicit authorization; always record a rollback point before modifying system authentication configurations.

Check yourself

What command checks if Docker requires sudo?

tam-sudo-docker.

How long does a temporary tam-sudo-passwordless window last by default?

15 minutes, with automatic native cleanup.

Security setup and privilege command family

CommandRole
tam-setup-security-fido2Register FIDO2 hardware token and configure PAM stacks for sudo and polkit
tam-remove-security-fido2Remove FIDO2 modules from authentication stacks and remove helper packages
tam-setup-security-fingerprintEnroll biometric fingerprint reader and integrate with hyprlock and PAM
tam-remove-security-fingerprintRemove fingerprint authentication and restore default PAM configurations
tam-setup-security-sshdStart OpenSSH daemon, configure firewall rule, and disable password logins
tam-remove-security-sshdStop OpenSSH server and close firewall ports
tam-setup-security-sudoless-dockerAdd user to docker group after explicit root-equivalence confirmation
tam-remove-security-sudoless-dockerRemove user from docker group and restore sudo requirements
tam-sudo-dockerPredicate returning exit 0 when Docker requires sudo, exit 1 when accessible directly
tam-sudo-keepaliveMaintain an active sudo authentication token during long-running tasks
tam-sudo-passwordlessTemporarily activate bounded passwordless sudo for a specified number of minutes

Authentication setup tools directly edit PAM and systemd service configurations. Always record a rollback point or snapshot before altering system-wide authentication stacks.

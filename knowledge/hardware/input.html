Input Devices

This page explains how Tamlinux receives and configures input from keyboards, mice, touchpads, and touchscreens.

What are input devices?

Input devices allow you to talk to your computer. A keyboard types characters and sends shortcuts. A mouse or touchpad moves the pointer and clicks. Touchscreens let you interact directly with screen elements.

Why it matters

Comfortable pointer acceleration, natural scrolling, and disabling the touchpad while typing prevent errors and reduce wrist fatigue during long sessions.

How to think about it

The Linux kernel detects hardware events and passes them to libinput. The Hyprland compositor then reads those events, applies your personal configuration (such as sensitivity and scroll direction), and dispatches actions to windows.

New words

Tap-to-click
Tapping the touchpad surface lightly to produce a mouse click without pressing the physical button.
Natural scrolling
Scrolling where content moves in the same direction as your fingers, matching touchscreen behavior.
Pointer acceleration
Scaling the pointer speed based on how quickly you move your hand across the pad or desk.

Inspect input devices safely

Goal: you will be able to verify detected input hardware and understand touchpad toggles.

Worked example

  1. List your detected input hardware by querying Hyprland: 
    $ hyprctl devices
    The output groups devices into keyboards, mice, touchpads, and switches.
  2. Toggle touchpad touch responsiveness on or off using the hardware XF86TouchpadToggle key (or by running tam-toggle-input-device touchpad).
  3. Open Touchpad and keyboard shortcuts for complete step-by-step configuration.

Try it

Inspect your keyboard repeat rate and delay in the output of hyprctl getoption input:repeat_rate. This is a read-only query that changes nothing.

If it goes wrong

Touchpad does not register taps
Ensure tap-to-click is enabled in your Hyprland configuration under the input:touchpad section.
Cursor moves while typing
Verify that disable_while_typing = true is active in the compositor input block.

When switching focus between applications rapidly using shortcuts, Tamlinux uses tam-hyprland-focus-app to target the desired window class or title.

Check yourself

Which system layer processes raw hardware events before handing them to Hyprland?

libinput via the Linux kernel.

What command helper focuses an application window by matching its class or title?

tam-hyprland-focus-app.

Input architecture and routing

Tamlinux input configuration resides in compositor rules and desktop helpers. The primary helpers include:

Tool / ComponentRole
tam-hyprland-focus-appFocus the first window whose class or launch title matches a specified pattern
tam-toggle-input-deviceToggle, enable, or disable input devices such as touchpads
desktop/session/hypr/tamlinux/input.luaCompositor input device options (layout, repeat rate, touchpad gestures)
desktop/session/hypr/tamlinux/bindings/media.luaHardware media and input device hotkey bindings (including touchpad toggle)

For custom keyboard remappings, Tamlinux supports XKB options declared in user configuration without modifying system-wide layout files.

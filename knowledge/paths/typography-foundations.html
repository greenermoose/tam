Guide / Learn step by step / From marks to typefoundries

This path begins before computers and before printing. It follows how people made marks stand for language, how scribes and printers copied text, and how letter shapes became font files. Each stage tells you which lens to read with: Novice for the idea, Learner for a short sample task, and Expert for precise detail.

Every example is a labelled teaching sample. Nothing here installs a font or changes a system setting.

Outcome: You can explain how writing began, classify the world's major writing systems, trace the press from scribes to digital type, describe the parts of a letter, compare font formats and name the people and foundries behind common fonts.

Prerequisites: none beyond reading

Time: About 60 minutes, including checkpoints and the capstone.

If you're stuck: read the program manuals with tam man <command>, list built-in help with tam help, or search this guide with tam search -- <term>.

Stage 1: Marks that carry meaning

  1. From marks to meaning — separate a memory aid from a system that records language.

Checkpoint

Answer before you go on.

Why is a picture of a sheep on a pot not automatically writing?

Because it may only remind someone of a sheep. Writing records units of language with agreed signs and order. Reread From marks to meaning if the difference is unclear.

Expected sandbox state: The stage sandbox holds a sample classification list; after grep logogram marks.txt the reader sees only the logogram lines. No files on the real machine change.

Stage 2: Systems around the world

  1. Writing systems of the world — classify a script as an alphabet, syllabary, abjad, abugida or logography.

Checkpoint

Answer before you go on.

Why is an abjad not the same as an alphabet?

An abjad normally writes consonants and leaves short vowels to the reader; an alphabet writes consonants and vowels as separate signs. Reread Writing systems of the world and its worldwide catalogue.

Expected sandbox state: The sample table systems.txt is unchanged; the goal command filters it to one family. No sandbox files are added to the home directory.

Stage 3: Scribes and the press

  1. Scribes, manuscripts and the printing press — follow copying by hand through block printing, movable type and Gutenberg's press.

Checkpoint

Answer before you go on.

What did movable type change that block printing did not?

Individual reusable characters could be rearranged for a new page instead of carving a whole block. Reread Scribes, manuscripts and the printing press.

Expected sandbox state: No sandbox in this stage; no simulated files or output are expected.

Stage 4: The shape of letters

  1. Anatomy of a letterform — locate the baseline, x-height, ascender, bowl, counter and serif on a sample glyph.

Checkpoint

Answer before you go on.

Why do two fonts at the same point size look different in a paragraph?

Point size is not the same as visible letter height. x-height, ascenders, descenders and width all change how much space a font appears to occupy. Reread Anatomy of a letterform.

Expected sandbox state: The sample diagram is read from the page; no simulated files or output are expected.

Stage 5: Format families

  1. Font formats, complete map — place BDF, TTF, OTF, Type 1, WOFF2 and colour fonts in one map.

Checkpoint

Answer before you go on.

Is WOFF2 a new kind of letter drawing, or a container for an existing font?

It is a compressed web container for OpenType or TrueType data, so the outlines and tables inside still come from those formats. Reread Font formats, complete map.

Expected sandbox state: The sample format list is filtered by extension; no real font files are read or changed.

Stage 6: Makers of type

  1. Type foundries and the people who make fonts — connect historical presses and modern foundries to typefaces you meet today.

Checkpoint

Answer before you go on.

Why did industrial foundries matter as much as individual designers?

Because a press or foundry turned one designer's drawings into reproducible metal type, then into licensed digital fonts that many machines could use. Reread Type foundries and the people who make fonts.

Expected sandbox state: No sandbox in this stage; no simulated files or output are expected.

Capstone

Choose a book, a street sign and a code editor. On one page, identify for each: the writing system in use, the likely letterform family, the format a digital font would need, one historical development that made that design possible, and one accessibility trade-off. State which claims you can support from the guide and which need a specimen or a source.

A sound answer names the system (for example Latin alphabet with diacritics), the genre (serif text face, sans-serif sign face, monospace code face), a plausible file format (OTF or TTF, with WOFF2 for the web), a historical line from scribes through movable type to digital outlines, and an accessibility check such as x-height, contrast or distinguishability. Unsupported guesses are labelled as guesses. The reader checks the result by comparing it with the format table and the foundry table in the series.

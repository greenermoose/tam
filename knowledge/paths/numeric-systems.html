Guide / Learn step by step / Numbers and how computers use them

This path follows a number from written digits into binary memory, through fractions and physical measurements, and into fast numerical work.

No mathematics beyond junior-high arithmetic is assumed. Each stage gives a lens: start at Novice, then reread the same page at Learner or Expert. Answer the checkpoint before moving on.

Outcome: After this path, you can follow numbers from bases and memory bytes through fractions, analog signals and fast numerical math.

Prerequisites: none beyond reading

Time: About 50 minutes, including checkpoints and the capstone.

If you're stuck: read the program manuals with tam man <command>, list built-in help with tam help, or search this guide with tam search -- <term>.

Stage 1: Write a number in another base

Read Number systems and bases: learn place value, binary, hexadecimal and why byte order matters. Then reread the practice lens for conversions and the reference lens for exact byte layout.

Checkpoint

Why can one hexadecimal digit stand for four binary digits?

Sixteen is two to the fourth power, so four bits have exactly sixteen patterns. Each pattern maps to one hex digit with no gaps. Reread the novice section if place value is still unclear.

Stage 2: Store a negative whole number

Read Whole numbers in binary memory: see how a fixed width sets the range and how two's complement labels negative values. Continue with the practice lens and the reference lens for ranges and wrapping.

Checkpoint

What is eight-bit 11111111 as an unsigned value and as a signed value?

It is 255 unsigned and -1 in two's complement. The bits are the same; the format decides the interpretation. Reread the learner example if the inversion plus one step was hard.

Stage 3: Represent a decimal fraction

Read Fractions, decimals and floating point: move place value past the ones column. Then read the practice lens for fixed point and rounding, and the reference lens for IEEE 754 and decimal alternatives.

Checkpoint

Why is 1/8 exact in binary memory but 1/10 only approximate?

Eight is a power of two, so 1/8 is a short binary fraction. Ten has a prime factor that binary place values cannot cancel, so 1/10 repeats forever. Reread the worked example if the pattern is not yet clear.

Stage 4: Turn a physical value into numbers

Read Analog values and digital approximations: learn sampling, converters and bit depth. Continue with the practice lens for quantization and the reference lens for Nyquist and reconstruction.

Checkpoint

A 12-bit converter spans 0 to 3.3 V. What sets the step size, and what happens above the top of the range?

The range divided by the available levels sets the step, about 3.3 V / 4095. Above the top the converter saturates. Reread the learner example to see how a code maps back to a voltage.

Stage 5: Do the math quickly

Read Fast numerical computing: see vectors, matrices and the repeated dot-product pattern. Then read the practice lens and the reference lens for BLAS, LAPACK, SIMD, fused multiply-add and memory layout.

Checkpoint

Why can a tuned BLAS library beat the same multiplication written as a simple loop?

It blocks data for cache, uses wide instructions, reuses loaded values and chooses an implementation for the machine. The arithmetic count can be identical while the memory traffic and instruction count differ greatly.

Capstone: Trace one sensor reading into an answer

Scenario: a device samples a room temperature sensor, stores a running average and sends the result to a program that fits a line through a day of readings. Nothing needs to be changed on the system.

Task: explain the number at each hand-off. Name the base or format used, one rounding or quantization step, one overflow or range decision, and one library choice that would make the line fit fast. Say what extra information a reader needs to interpret each stored value.

Model approach:

  1. The ADC produces an integer code with a stated bit depth and voltage range. The code is binary in memory; the range and bit depth turn it into a physical value.
  2. Mapping the code to volts introduces quantization error. Averaging in fixed point needs a scale; averaging in floating point needs tolerance and rounding rules.
  3. The running total has a width. Choose one large enough that a day of samples cannot overflow, or accumulate in a wider type.
  4. The line fit is a least-squares matrix problem. LAPACK can solve it using BLAS kernels, which use SIMD and cache-friendly layout. Accumulation precision affects the last digits.

Each stored value needs its format, scale or range, byte order when exchanged, and precision before another program can interpret it correctly.

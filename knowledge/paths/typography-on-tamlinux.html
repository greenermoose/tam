Guide / Learn step by step / Readable text on Tamlinux

This path brings the typography series back to the desktop. It starts with the commands and configuration a reader meets on Tamlinux, then covers readable choices, likely faults, a diagnostic routine and the questions researchers still ask.

Every sample command is shown in a teaching sandbox. Nothing here installs a package, changes a system font or touches a boot setting.

Outcome: You can query the font in use, choose readable settings, explain common text faults, run a repeatable diagnostic routine and separate settled typography standards from open research.

Prerequisites: Typography for the vocabulary, or none beyond reading if you follow the linked pages as you go

Time: About 50 minutes, including checkpoints and the capstone.

If you're stuck: read the program manuals with tam man <command>, list built-in help with tam help, or search this guide with tam search -- <term>.

Stage 1: The product workflow

  1. Typography, fonts and text rendering — query the monospace family and see where font configuration lives.

Checkpoint

Answer before you go on.

Which tool reports the current monospace family, and where does it get the answer?

tam-font-current asks Fontconfig with fc-match monospace and prints the first family alias. Reread Typography, fonts and text rendering.

Expected sandbox state: The sandbox prints a sample family name from fc-match; no real command runs on the machine.

Stage 2: Readable text

  1. Readable text and accessibility — check contrast, size and character distinguishability for a theme.

Checkpoint

Answer before you go on.

Why does a high-contrast colour pair not guarantee readable text?

Contrast is necessary but not enough; size, x-height, spacing and character distinguishability still matter. Reread Readable text and accessibility.

Expected sandbox state: The sample contrast table stays inside the sandbox; no theme file is edited.

Stage 3: Likely faults

  1. When text looks wrong — match a symptom to a layer before changing anything.

Checkpoint

Answer before you go on.

Text is sharp in the browser but blurry in a terminal. What is the first boundary to check?

The terminal emulator's own font setting and hinting, not the browser or the font file alone. Reread When text looks wrong.

Expected sandbox state: The sample fc-match and coverage files remain in the sandbox; nothing is changed on the reader's machine.

Stage 4: The workbench

  1. A typography diagnostic workbench — gather evidence, change one thing and confirm the result.

Checkpoint

Answer before you go on.

Why change only one setting at a time?

Because several layers affect the same pixels; two simultaneous changes hide which layer mattered and make rollback uncertain. Reread A typography diagnostic workbench.

Expected sandbox state: The sandbox's sample rule file is the only thing "edited"; the real configuration is untouched.

Stage 5: What remains open

  1. Research frontiers in typography — tell a shipped specification from an active research question.

Checkpoint

Answer before you go on.

Why is encoding a script in Unicode not the same as supporting it well?

Encoding assigns code points; good support needs fonts with the right glyphs, shaping rules, line breaking and readable defaults. Reread Research frontiers in typography.

Expected sandbox state: No sandbox in this stage; no simulated files or output are expected.

Capstone

Write a one-page accessibility and diagnosis note for a shared work machine. State which font families a reader can expect from the generic names, how a reader checks the current monospace family, two readability settings worth changing at user level, one symptom that points to shaping and one that points to font selection, and one open research question that the note does not pretend to settle.

A sound note uses the sourced generic-family assignments from the product Fontconfig file, names tam-font-current and fc-match as the query path, keeps changes in user configuration, separates shaping symptoms (mark order, ligatures) from selection symptoms (wrong family, boxes), and labels research questions as open. It avoids promising that any setting has been tested on the reader's machine. The reader checks the note against the linked pages before sharing it.

Important algorithms for modern computing

This path introduces a small set of algorithms that shape modern computing. You will learn how signals become frequencies, how data gets ordered, why factoring is hard, and what core algorithms make large language models work.

Each stage gives a lens to read with. Start with the gentle explanation, then use the practice or reference lens. Answer the checkpoint before moving on; if it is unclear, reread the stage at an earlier lens.

Stage 1: See a signal as frequencies

Read Fourier transforms first: learn how a complicated signal can be described as a combination of waves. Then read the practice lens to see how a DFT picks out frequency bins from samples.

Checkpoint

What question does a Fourier transform answer that a plain time-domain view does not make obvious?

It answers how much of each frequency is present in a signal. That makes patterns like tones, periodic noise, or spectral components visible even when the time-domain waveform looks complicated. Reread the novice section if the time/frequency split is unclear.

Stage 2: Make the transform practical

Read Fast Fourier Transform first: understand why the FFT matters. Then read the practice lens for the O(N^2) versus O(N log N) difference, and the reference lens for Cooley-Tukey and fast convolution.

Checkpoint

Does the FFT produce a different result from the DFT?

No. It computes the same DFT result, but reorganizes the work to avoid repeated calculations. The importance of FFT is efficiency: it makes frequency-domain methods practical at sizes where a direct DFT would be too slow.

Stage 3: Use transforms in real media work

Read FFmpeg and media processing first: see how a practical tool handles containers, codecs, and filters. Then read the practice lens for inspect/convert/filter commands, and the reference lens for where FFT/DCT/MDCT-style processing appears in media pipelines.

Checkpoint

When should you copy a media stream instead of re-encoding it?

Copy when you do not need to change that stream's codec, bitrate, filters, or other encoded properties. Copying avoids unnecessary quality loss and CPU work; re-encoding is needed only when the stream itself must change.

Stage 4: Put data in order

Read Sorting algorithms first: learn why ordering data matters. Then read the practice lens to compare common sorts and stability, and the reference lens for complexity bounds and when non-comparison sorts win.

Checkpoint

Why can an algorithm with the same big-O time as another still be faster in practice?

Big-O ignores constants and machine effects. Cache behavior, memory allocation, branch prediction, data layout, and input characteristics can make one O(n log n) sort faster than another on real workloads. That is why practical systems often use hybrid sorts like Timsort or introsort.

Stage 5: Break numbers into factors

Read Factoring algorithms first: understand factoring and why it gets hard. Then read the practice lens for trial division versus smarter methods, and the reference lens for GNFS, ECM, and the cryptographic implications.

Checkpoint

Why does factoring matter to cryptography if most people never factor large numbers themselves?

Some cryptosystems rely on factoring being computationally difficult for appropriately chosen large numbers. The cost of factoring affects key sizes, security margins, and migration decisions, especially when new algorithms or quantum computing change the cost curve.

Stage 6: Understand the algorithms behind LLMs

Read Algorithms behind large language models first: get the big picture of next-token prediction. Then read the practice lens for the training and inference pipeline, and the reference lens for attention cost, optimization, decoding, and KV cache trade-offs.

Checkpoint

Why is attention useful in a language model?

Attention lets the model weigh relevant earlier tokens when building a representation for the current token. That helps it use context such as instructions, variable names, or earlier sentences instead of treating every token as equally relevant.

Capstone: Choose the right algorithmic lens

Scenario: you are building a system that records audio, cleans it up, stores searchable transcripts, and answers questions over them.

Task: identify where each algorithm family from this path appears. Name one place where an FFT or related frequency-domain method helps, one place where sorting helps, one place where factoring/hard-problem cryptography matters, and one place where LLM inference algorithms matter. For each, state the input, output, and main cost trade-off.

Model approach:

  1. FFT/frequency domain: audio cleanup or spectrum analysis. Input: sampled audio frames; output: frequency bins or filtered samples; trade-off: time/frequency resolution, windowing leakage, and compute/memory cost.
  2. Sorting: organizing transcript segments, timestamps, or search results. Input: records with keys; output: ordered records; trade-off: speed vs memory, stability, and data size/access pattern.
  3. Factoring/cryptography: securing stored or transmitted data. Input: keys/protocol parameters; output: confidential/authenticated communication; trade-off: security assumptions and key sizes vs performance and migration cost.
  4. LLM algorithms: answering questions over transcripts. Input: prompt plus retrieved context; output: generated tokens; trade-off: quality/latency/cost/context length, with risks like hallucination requiring grounding and verification.

The point is not to use every algorithm everywhere, but to recognize which problem shape each algorithm family fits.

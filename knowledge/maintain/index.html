System Maintenance and Reliability

This page introduces ways to keep your computer working and recover from problems.

What maintenance covers

You can check your software, prepare for changes, and learn what to do if something goes wrong. Maintenance is not one button: updates, rollbacks, logs and recovery each answer a different question.

Why it matters

A small inspection before a change is safer than guessing afterward. Knowing which guide matches your symptom saves time when something feels wrong.

How to think about it

Think of this hub as a front desk. Start from a symptom when something failed, or pick a maintenance guide when you want to prepare for a planned change.

If it goes wrong

You are unsure whether the problem is software or your documents
Read Returning to an earlier working state before changing anything. Software and data have different recovery paths.

Check yourself

Is inspecting an installed package version the same as updating it?

No. A query reads local information; an update changes software. Keep those steps separate.

Where should you start if the computer will not boot?

Start from the symptom index or boot-recovery guides, not from an ordinary package update page.

Automated inspection

Read-only inspection tools:

$ tam inspect
$ tam check

tam inspect reports host facts. tam check evaluates them against the offline Check Contract and links to maintenance guides when corrective steps are recommended.

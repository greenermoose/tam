How much power your computer uses

This page shows how to see how much electricity your computer's main chip is using, and what keeps it busy.

The tam-meter command reads the computer's own sensors. It only reads; it changes nothing and needs no administrator rights.

What tam-meter tells you

tam-meter reports power in watts, the processor's temperature, how busy the processor is, and how often it is woken up to do small jobs.

Why it matters

A computer that stays busy when you are not using it wastes electricity, runs warmer and, on a laptop, drains the battery. Seeing the numbers lets you notice when a program keeps the machine awake for no good reason.

How to think about it

Think of the electricity meter in a house. A quiet house still uses some power, but a meter that keeps spinning at night means something was left on. tam-meter is that meter for the processor, with a list of which programs were running.

New words

Watt
A unit of power: how fast energy is being used right now. A small light bulb uses a few watts.
CPU
The processor, the chip that runs programs.
Wakeup
A moment when the processor stops resting to handle something, such as a timer or a key press. Fewer wakeups usually mean less power.

Take a quick sample, then a careful reading

Goal: you will be able to take a one-off sample, watch power live, and run a settled reading you can compare with a later one.

Worked example

$ tam-meter now
APU power: 3.0 W | CPU temp: 49.1 °C | CPU busy: 1.0% | Wakeups: 2395 int/s, 3442 ctxt/s

Captured on an AMD desktop running Tamlinux 0.6.18, 2026-11-07, with tam-meter 0.1.0. Your numbers will differ, and they change from second to second.

What just happened

  1. APU power is what the main chip reports it is drawing. An APU is a processor with its graphics built in.
  2. CPU temp is the processor's temperature sensor.
  3. CPU busy is the share of time the processor was doing work rather than resting.
  4. int/s counts interrupts per second, signals from hardware and timers; ctxt/s counts context switches per second, when the processor changes from one task to another.

Try it

  1. Run tam-meter top for a live view of power, a small graph of recent readings, wakeups and the busiest programs. Press q or Esc to leave.
  2. Leave the computer alone and watch the power settle. Then move the mouse or play a video and watch it rise.
  3. When you want a number to keep, run tam-meter reading. It waits six minutes for the machine to settle, then samples every two seconds for ten minutes, so plan for about sixteen minutes without using the computer.

If it goes wrong

APU power is unavailable
Your processor does not report power through the sensor tam-meter reads. On a laptop running on battery it uses the battery's discharge rate instead.
The numbers jump around
That is normal for single samples. Use tam-meter reading, which reports the mean, median and range over many samples.
The reading finished but seems high
Look at its Busiest processes line. A browser or editor left open keeps waking the machine.

tam-meter ships with the Tamlinux commands. reading takes --settle SECONDS, --minutes MINUTES and --interval SECONDS; reading and now take --json for scripts. Its help calls reading the energy reading used when testing a Tamlinux candidate, so readings taken the same way can be compared across versions.

Check yourself

Decide your answer before you reveal it.

One tam-meter now shows 3 W and the next shows 13 W. Is something wrong?

Not necessarily. A single sample catches one moment, and power rises briefly whenever any program does some work. To judge whether the machine idles well, use a settled reading and look at the median.

Does the APU figure tell you what the whole computer draws from the wall?

No. It covers the main chip only. Memory, storage, networking, the power supply's own losses and the monitors are not included; a wall meter is needed for the whole machine.

What tam-meter measures and leaves out

Reference

FieldSource
APU powerpower1_input of the amdgpu hwmon device (package power tracking); otherwise, while a battery is discharging, its power_now, or current_now times voltage_now
CPU temperatureThe first hwmon temperature found from k10temp, then coretemp, then acpitz
CPU busy, interrupts, context switchesDifferences between successive readings of /proc/stat
Busiest processes (reading)CPU seconds each process used during the window, from /proc/PID/stat at the start and end
Displays (reading)The DPMS state of each connected DRM connector under /sys/class/drm, at the start and end
Memory (reading)Available memory and swap in use, from /proc/meminfo

How it works

reading sleeps for the settle time, samples for the window, then reports mean, median and range. It also reports the CPU time it used itself, so you can see that the meter is not what is being measured. Each report ends with a Not measured line: wall power, the RAPL package energy counter when only root can read it, and everything outside the APU.

Edge cases

  • Package power reported by the chip is a model of its own draw, useful for comparing one state with another on the same machine, not a calibrated wall measurement.
  • On Intel systems without an amdgpu sensor, power comes only from a discharging battery; on mains power it is unavailable.
  • Settling matters: background jobs, indexers and fans keep running for minutes after you stop typing. A reading with --settle 0 measures that tail.
  • Displays are in the report because a lit monitor changes graphics work; compare readings only with the same displays on or off. The state is what the graphics driver reports, which is not proof that a panel is physically lit.

Check yourself

Two readings of the same build differ by 1.5 W in median. What would you check before calling it a regression?

Whether the conditions matched: the same settle time and window, the same displays on, similar busiest processes, and similar memory and swap pressure. If one reading had a browser waking the machine, the difference belongs to that program. Repeat both readings; a stable difference under matched conditions is evidence, one pair is not.

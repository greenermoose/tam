Boot Process, UKIs, and Kernel Updates

This page covers how Tamlinux boots from UEFI firmware through the bootloader to the kernel, including Unified Kernel Images (UKIs), boot hooks, initramfs construction, and how boot images are regenerated on kernel updates.

Beginner: How a Linux System Boots (UEFI)

Summary: Understand the boot sequence from firmware to userspace on a UEFI system.

Prerequisites: Basic filesystem knowledge.

The UEFI boot sequence

  1. Firmware (UEFI): On power-on, UEFI firmware initializes hardware, checks NVRAM boot entries, and loads the bootloader from the EFI System Partition (ESP).
  2. ESP: The ESP (often mounted at /boot or /boot/efi) contains EFI executables (.efi files). UEFI looks for a boot entry pointing to a specific .efi file.
  3. Bootloader: The bootloader (Limine on Tamlinux) presents boot options, loads the kernel and initramfs into memory, and passes kernel command-line parameters.
  4. Kernel: The Linux kernel initializes drivers, mounts the root filesystem, and starts the first userspace process (init or systemd).
  5. Initramfs: A small temporary filesystem loaded with the kernel; it contains tools and modules needed to mount the real root (especially for encrypted, LVM, or Btrfs setups).
  6. Userspace: systemd takes over, starts services, mounts filesystems, and launches the display manager/desktop.

Key directories

  • EFI System Partition (ESP): Typically /boot on Tamlinux. Contains bootloader EFI files and optionally kernel/initramfs/UKIs.
  • Bootloader config: Limine uses /boot/limine.conf and entries generated by tools like limine-entry-tool.
  • Initramfs build config: /etc/mkinitcpio.conf and drop-ins in /etc/mkinitcpio.conf.d/.
  • Pacman hooks: /etc/pacman.d/hooks/ trigger actions when packages (like kernels) are installed/updated.

Intermediate: Bootloaders, UKIs, and mkinitcpio

Summary: Understand Limine, Unified Kernel Images, and how initramfs is built with mkinitcpio hooks.

Bootloaders on Tamlinux

Tamlinux uses Limine as its bootloader. Limine can boot kernels directly, or boot Unified Kernel Images (UKIs). It reads configuration from /boot/limine.conf and can auto-generate entries from discovered kernels/UKIs.

What is a Unified Kernel Image (UKI)?

A Unified Kernel Image (UKI) is a single UEFI PE executable that bundles the kernel, initramfs, kernel command line, and optional metadata (signatures, SBAT, etc.) into one .efi file. Benefits include:

  • Simplified boot entries: One file instead of separate kernel+initramfs+cmdline.
  • Secure Boot readiness: Easier to sign as a single unit.
  • Atomic updates: The whole boot payload is versioned together.
  • Discoverability: UKIs placed in /boot/EFI/Linux/*.efi can be discovered by some bootloaders/firmware.

Tamlinux's boot configuration may use UKIs (see /etc/default/limine with ENABLE_UKI=yes). When enabled, the build/deployment tooling generates UKIs containing the kernel, initramfs, and embedded command line.

Initramfs and mkinitcpio hooks

The initramfs (initial RAM filesystem) is a minimal rootfs loaded early in boot. It must contain:

  • Kernel modules needed to access storage (block, filesystem, encryption, LVM, etc.)
  • Userspace tools to mount the real root
  • Any necessary firmware files

Tamlinux builds initramfs using mkinitcpio. The HOOKS array in /etc/mkinitcpio.conf defines the boot process inside initramfs. Hooks run in order and each adds scripts/modules. Common hooks include:

  • base: Core initramfs functionality (required)
  • systemd: Use systemd inside initramfs instead of busybox
  • udev: Device detection via udev
  • autodetect: Only include modules needed for this hardware
  • microcode: Load CPU microcode updates early
  • modconf: Apply module configuration
  • kms: Kernel Mode Setting (GPU) early initialization
  • keyboard/sd-vconsole: Keyboard/console setup
  • block: Block device handling
  • sd-encrypt/encrypt/lvm2: Disk encryption/LVM support
  • filesystems: Filesystem support and mounting
  • fsck: Filesystem checks on boot

Custom mkinitcpio configs can be placed in /etc/mkinitcpio.conf.d/. After changing hooks or modules, regenerate initramfs for all installed kernels (usually handled by pacman hooks).

Hook lifecycle and ordering

Hook order is critical. For example, encryption hooks must run before filesystems, and block device detection before mounting. Run mkinitcpio -H <hook-name> for help on a specific hook.

Expert: Kernel Updates, Image Regeneration, and Safety

Summary: How pacman hooks, limine-mkinitcpio integration, and UKI generation work together when kernels update.

What happens on kernel update

When a kernel package (e.g., linux, linux-zen, linux-lts) is installed or updated via pacman:

  1. Kernel files installed: New kernel image (vmlinuz-*), modules, and potentially headers go into place.
  2. mkinitcpio runs: Pacman hooks trigger mkinitcpio to build initramfs images for the new kernel(s). This reads /etc/mkinitcpio.conf and drop-ins.
  3. Bootloader/UKI generation: Additional hooks (e.g., limine-mkinitcpio-hook) run to generate/update boot entries, UKIs, and sync with Limine's configuration.
  4. Limine sync: Tools like limine-mkinitcpio-hook and limine-snapper-sync update /boot/limine.conf and ensure entries point to the correct kernel/initramfs or UKI paths.
  5. ESP deployment: Updated UKIs (.efi files) and bootloader binaries are written to the ESP (/boot).

Key packages and hooks

  • mkinitcpio: Builds initramfs from kernel and config.
  • limine-mkinitcpio-hook: Integrates mkinitcpio with Limine; regenerates boot entries/UKIs after kernel/initramfs changes.
  • limine-snapper-sync: Syncs Limine boot menu with Btrfs snapshots managed by Snapper.
  • Pacman hooks in /etc/pacman.d/hooks/: Automate these steps on package transactions. These run in package install/remove/update order.

UKI generation specifics

When UKIs are enabled (ENABLE_UKI=yes in /etc/default/limine):

  1. The tooling bundles vmlinuz-*, the corresponding initramfs (initramfs-*.img or initramfs-*-fallback.img), and the kernel command line into a single PE executable.
  2. Resulting UKIs are typically written to /boot/EFI/Linux/<name>-<kernel-version>.efi (naming depends on config, e.g. omarchy-*.efi).
  3. Limine's config is updated to reference these UKI files. UKIs embed the cmdline, so the bootloader entry may be simpler.

Safety considerations

  • Never edit in-place blindly: Tools that rewrite boot images can corrupt them if used incorrectly. As noted in Tamlinux memory, certain objcopy invocations that rewrite files in-place can break checksum validation (e.g., breaking Limine BLAKE2B hashes). Always work on copies when inspecting/modifying UKIs.
  • Verify after updates: After kernel updates, verify boot entries in /boot/limine.conf are correct and point to existing files.
  • Keep fallback images: mkinitcpio typically generates both regular and fallback initramfs; fallback may be useful for recovery if autodetect misses modules.
  • Check hooks after changes: If you modify /etc/mkinitcpio.conf or add drop-ins, regenerate with mkinitcpio -P (all kernels) or per-kernel. Pacman hooks handle this automatically on package updates.
  • Boot recovery readiness: Keep a known-good boot entry and understand which dependencies each route shares. See Linux Boot Fallbacks and Rescue Routes.

Troubleshooting tips

  • Check mkinitcpio logs/errors: If initramfs build fails, pacman will show errors. Rebuild manually: mkinitcpio -v -k <kernel-version>
  • Verify UKI contents: Use tools like objdump, readpe, or inspect UKI sections if available (avoid in-place destructive operations).
  • Limine hash mismatches: If Limine complains about hashes, the UKI/initramfs changed without updating hashes in limine.conf. Regenerate via the proper hooks/tooling.
  • Check pacman hooks: List hooks: ls /etc/pacman.d/hooks/. Ensure limine/mkinitcpio hooks are present and enabled.

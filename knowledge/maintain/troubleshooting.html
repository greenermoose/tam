Troubleshooting and Diagnostics

This page explains how to diagnose process crashes, resolve desktop shell glitches, clear compiled caches, and run diagnostic tests on Tamlinux.

What is troubleshooting?

Troubleshooting means finding out why a program stopped working and applying a targeted fix. On Tamlinux, issues are isolated so one failing program does not bring down the entire computer.

Why it matters

When an application crashes or a status icon disappears, you can find the exact error message and recover without rebooting or guessing.

How to think about it

Separate symptoms by layer: application crash, desktop shell glitch, or system service fault. Always check recent logs before making changes.

New words

Crash
An unexpected termination of a running program caused by an unhandled error or signal.
Core dump
A snapshot of a program's memory recorded by the kernel when it crashes, used for debugging.
Cache
Temporary stored data designed to speed up loading, which can sometimes become stale after an update.

Investigate crashes and clear stale state safely

Goal: you will be able to review crash notices, purge compiled desktop caches, and execute diagnostic dry-runs.

Worked example

  1. When an application crashes, tam-crash-watch issues a desktop alert naming the process ID (PID).
  2. To gather crash evidence and view an automated report, run: 
    $ tam-agent-crash 12345
  3. If desktop status bar plugins fail to display updated code after an update, purge stale QML caches: 
    $ tam-qmlcache-purge
  4. Verify desktop layout without making changes using the test battery: 
    $ tam-desktop-test --dry-run

Try it

Run coredumpctl list -n 5 in your terminal. This prints recent process crash records recorded by systemd without altering any files.

If it goes wrong

The graphical desktop is completely unresponsive
Press Ctrl + Alt + F2 to switch to a text virtual console, log in, and check journal logs.
Inspecting or verifying a staged upgrade
Log in to a text virtual console and run tam-workstation-upgrade --check to inspect the upgrade plan without applying changes, or tam-workstation-upgrade --status to view the last local receipt.

Tamlinux services record detailed diagnostic traces in the system journal; cite boot IDs and precise time windows when reviewing issues.

Check yourself

Which background daemon monitors user processes for crashes and offers diagnosis?

tam-crash-watch.

What tool purges compiled QML caches when plugin code changes?

tam-qmlcache-purge.

Diagnostic and troubleshooting command family

CommandRole
tam-crash-watchMonitor user process exits and notify with AI diagnosis options
tam-agent-crashCollect stack trace and crash context for a PID using the default agent
tam-qmlcache-purgeRemove stale compiled Quickshell QML caches for deployed desktop plugins
tam-desktop-testExecute physical desktop test battery for layout and workspace validation
tam-workstation-upgradePerform workstation assembly upgrade and migration from text console

Home Manager stores deployed plugins with identical Unix timestamps (1970-01-01) in the Nix store. tam-qmlcache-purge clears cached bytecode by matching plugin paths against SHA-1 cache entries, preventing stale execution across version switches.

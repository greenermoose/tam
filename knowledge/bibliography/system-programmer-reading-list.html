Guide / Sources and further reading / System Programmer Reading List

This page is a curated reading list for system programmers. It focuses on programs that interact closely with operating systems, hardware, compilers, memory, concurrency, and performance: kernels, drivers, runtimes, databases, network services, embedded software, and low-level tools.

How to use this list

System programming requires strong C or systems-language fundamentals, a clear mental model of the machine, and careful debugging habits. Start with computer systems and operating systems, then add networking, concurrency, compilers, and performance. Build small programs that use files, processes, sockets, memory mapping, and threads.

Read with a Linux machine nearby. Use manual pages, source code, and debuggers to verify behavior. System programs must handle errors, resource limits, and undefined behavior carefully.

Core books

Computer systems and C

  • Brian W. Kernighan and Dennis M. Ritchie, The C Programming Language, 2nd ed., Prentice Hall, 1988. Essential C language foundation.
  • Randal E. Bryant and David R. O'Hallaron, Computer Systems: A Programmer's Perspective (CS:APP), Pearson (recent edition). The bridge between code, machine, OS, and runtime behavior.
  • Jens Gustedt, Modern C, Manning (recent edition). Modern C practice and semantics. Also available online.

Operating systems and Linux

  • Remzi H. Arpaci-Dusseau and Andrea C. Arpaci-Dusseau, Operating Systems: Three Easy Pieces (OSTEP), Arpaci-Dusseau Books (recent edition). Core OS concepts. Also available online.
  • Andrew S. Tanenbaum and Herbert Bos, Modern Operating Systems, Pearson (recent edition). Broad OS design and implementation perspective.
  • Michael Kerrisk, The Linux Programming Interface, No Starch Press, 2010. Detailed Linux/UNIX system programming APIs and concepts.
  • Robert Love, Linux Kernel Development, Addison-Wesley (recent edition). Practical introduction to Linux kernel design and subsystems.

Systems programming and UNIX APIs

  • W. Richard Stevens and Stephen A. Rago, Advanced Programming in the UNIX Environment (APUE), Addison-Wesley (recent edition). UNIX system programming fundamentals.
  • W. Richard Stevens, Bill Fenner, and Andrew M. Rudoff, UNIX Network Programming, Volume 1: The Sockets Networking API, Addison-Wesley, 3rd ed., 2003. Core network system programming reference.
  • Kay A. Robbins and Steven Robbins, UNIX Systems Programming: Communication, Concurrency, and Threads, Prentice Hall, 2nd ed., 2003. Practical process, signal, and concurrency patterns.

Concurrency, memory, and performance

  • Anthony Williams, C++ Concurrency in Action, Manning (recent edition). Practical concurrency model and patterns; useful even for non-C++ system programmers learning threading concepts.
  • Brendan Gregg, Systems Performance: Enterprise and the Cloud, Addison-Wesley (recent edition). Performance methodology and Linux observability.
  • Ulrich Drepper, "What Every Programmer Should Know About Memory," Red Hat, 2007. Essential paper on memory hierarchies, caches, and DRAM behavior.

Compilers, linkers, and toolchains

  • Alfred V. Aho, Monica S. Lam, Ravi Sethi, and Jeffrey D. Ullman, Compilers: Principles, Techniques, and Tools, Pearson, 2nd ed., 2006. Compiler foundations.
  • John R. Levine, Linkers and Loaders, Morgan Kaufmann, 1999. Object files, linking, loading, and runtime layout. Also available online.
  • Ian Lance Taylor, Linkers (blog series), 2007. Practical modern linker internals.

Key articles and references

These references deepen understanding of OS interfaces, low-level behavior, and system design trade-offs.

Operating systems and interfaces

  • Dennis M. Ritchie and Ken Thompson, "The UNIX Time-Sharing System," Communications of the ACM, 1974. Foundational UNIX design paper.
  • Jerome H. Saltzer and Michael D. Schroeder, "The Protection of Information in Computer Systems," Proceedings of the IEEE, 1975. Security design principles relevant to system boundaries.
  • Linux man-pages and kernel documentation. Primary references for system call behavior and Linux interfaces.
  • POSIX Shell Command Language and related POSIX specifications. Authoritative interface behavior.

Memory, concurrency, and correctness

  • Leslie Lamport, "Time, Clocks, and the Ordering of Events in a Distributed System," Communications of the ACM, 1978. Causality and ordering.
  • Maurice Herlihy and Nir Shavit, The Art of Multiprocessor Programming, Morgan Kaufmann (recent edition). Concurrent data structures and memory models.
  • Paul E. McKenney, Is Parallel Programming Hard, And, If So, What Can You Do About It?, Linux Foundation (recent edition). Practical low-level concurrency and RCU. Also available online.

Debugging and performance

  • Brendan Gregg, BPF Performance Tools, Addison-Wesley, 2019. Advanced Linux tracing.
  • GDB, Valgrind, perf, strace, ltrace, and eBPF tool documentation. Essential for observing real system behavior.
  • Intel 64 and IA-32 Architectures Software Developer Manuals, and relevant architecture manuals (ARM, RISC-V). Authoritative hardware behavior when working at the machine boundary.

Preparation for advanced system work

Advanced system programmers should be comfortable with:

  • Reading specifications, ABI documentation, and source code.
  • Debugging memory, concurrency, and performance problems.
  • Understanding process, memory, file system, network, and device boundaries.
  • Writing robust error handling and cleanup paths.
  • Measuring before optimizing and validating assumptions on real hardware.

This reference is for readers at all levels.

This reading list selects widely used system programming books and foundational papers. Verify behavior against the operating system, compiler, architecture, and manual pages you are using.

Some listed works are commercially published; others are freely available online from authors or standards bodies.

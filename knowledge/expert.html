The expert's path

Outcome: reason from process and descriptor behavior through TTYs and boot dependencies, evaluate system architecture tradeoffs, and develop a small tool in a controlled development context.

Prerequisites: practical shell experience, basic process concepts, and familiarity with the intermediate route. This route gives goals and references rather than step-by-step commands.

  1. Compare processes and job control with TTYs, VTs, and PTYs. Trace which process owns a terminal and how file descriptors are inherited.
  2. Map dependencies among boot stages, fallback paths, and recovery routes. Mark the shared dependencies before judging a recovery option.
  3. Read the architecture overview, then compare its pages on compositors, service supervision, and C libraries. Separate current choices from planned directions.
  4. Choose a small, reversible exercise in a development checkout and read toolchain guidance and tool conventions. State the test boundary and rollback before editing; do not practice on boot, package-removal, or privileged recovery paths.

Self-check: draw the process/descriptor/TTY relationships for a shell pipeline, identify one boot dependency shared by two recovery paths, and cite the authoritative source for a current-versus-planned architecture claim.

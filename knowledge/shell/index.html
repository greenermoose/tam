Giving your computer written instructions

This page explains how to give your computer written instructions and read its replies.

What is a shell?

A terminal is a place to type instructions and read replies. A shell is the program that reads those instructions. You can connect small programs to do more work together.

Why it matters

Recognizing what is a command and what is output helps you avoid typing a reply as if it were an instruction, or mistaking an error message for ordinary results.

How to think about it

Think of the shell as a receptionist who takes your written request, hands it to the right office, and brings back the reply. The three common reply channels are ordinary results, error messages, and the text you type in.

New words

Shell
The program that reads typed instructions and starts other programs.
Stream
A continuous flow of text into or out of a program.
Terminal
The window or console where you type and read text.

Commands and streams

Goal: recognize a command, its output, and the streams a shell connects.

Worked example

$ printf '%s\n' hello
hello

Captured on Arch Linux, 2026-10-27. The shell runs printf; the word on the second line is its output.

What just happened

  1. You typed a command after the prompt.
  2. The shell started printf with the argument hello.
  3. The program wrote hello to standard output, which appeared on your screen.

The standard streams

A program started by the shell usually has three standard streams:

0 — standard input (stdin)
Where the program reads input, usually from your terminal.
1 — standard output (stdout)
Where normal output goes, usually to your terminal screen.
2 — standard error (stderr)
Where messages about errors, warnings and progress go, separate from normal output.

A pipe (|) normally passes standard output to another program while error messages stay separate.

Try it

Change hello to pear in the example and predict the output before running it.

If it goes wrong

The terminal shows a continuation prompt
Check quotes and spacing. Ctrl+C cancels unfinished input; it does not undo commands that already ran.
You want to practice redirection
Redirection with > can overwrite a file. Practice only in a fresh temporary directory.

The tam hello and tam hi subcommands both open Welcome; they do not require a shell alias.

Check yourself

Which stream ordinarily carries diagnostics?

Standard error, stream 2, is separate from normal standard output.

Does the dollar sign in a sample need to be typed?

No. It represents a prompt; type the command after it.

Giving your computer written instructions

This page explains how to give your computer written instructions and read its replies.

A terminal is a place to type instructions and read replies. A shell is the program that reads those instructions. You can connect small programs to do more work together.

Commands and streams

Goal: recognize a command, its output and the streams a shell connects.

Why it matters: recognizing output helps you avoid typing it as a command or mistaking an error for data.

Before you start: use a terminal and read First steps. This example changes no files.

New to this? Type the text after the dollar sign at your prompt and press Enter. The next line is output.

Worked example

$ printf '%s\n' hello
hello

Captured on Arch Linux, 2026-10-27. The shell starts printf; the word on the second line is its output.

The standard streams

A program started by the shell usually inherits three standard communication channels, known by their file descriptor numbers:

0 — standard input (stdin)
The stream where the program reads its input data. By default, this is attached to your keyboard.
1 — standard output (stdout)
The stream where normal program output flows. By default, this is attached to your terminal screen.
2 — standard error (stderr)
The diagnostic stream where errors, warnings, and progress indicators flow, separate from normal output data.

Keeping error messages on stream 2 ensures that when you pipe output into another tool, error messages are not silently swallowed or parsed as data.

Stream redirection

The shell lets you redirect streams to and from files or other streams:

OperatorMeaning
< fileRead input from a file instead of the keyboard
> fileWrite stdout to a file, overwriting existing contents
>> fileAppend stdout to the end of a file
2> fileRedirect only error messages (stderr) to a file
2>&1Merge stderr into stdout so both follow the same path

Command substitution

Command substitution runs a command inside a subshell and places its output directly onto your command line using $(command):

For example, printf '%s\n' "$(printf '%s' hello)" prints hello. The inner command's output becomes an argument of the outer command.

User aliases and the one-place-to-look principle

The shell can define shorthand aliases. Their location and contents depend on the shell and its configuration. Inspect your own configuration before changing one. The tam hello and tam hi subcommands both open Welcome; they do not require a shell alias.

Try it

Change hello to pear in the example and predict the output before running it.

If it goes wrong

Check quotes and spacing if the shell asks for more input. Ctrl+C cancels unfinished input; it does not undo commands that already ran. Redirection with > can overwrite a file, so practice only in a fresh temporary directory.

Check yourself

Which stream ordinarily carries diagnostics?

Standard error, stream 2, is separate from normal standard output.

Does the dollar sign in a sample need to be typed?

No. It represents a prompt; type the command after it.

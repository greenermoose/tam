Guide / Networking / Network commands

Networking commands report the active connection, DNS settings and Wi-Fi state. Read-only checks and state changes have different boundaries.

Commands that report on the network

A network command can answer a narrow question: which connection is active, which router carries traffic, which DNS servers are configured, or whether a Wi-Fi radio has stalled. Reading that state is different from changing it.

Why it matters

When a page will not load, a specific answer is more useful than guessing. A status report separates a missing link from a bad address or a failed name lookup, and it gives you something clear to tell someone who helps you.

How to think about it

Think of these commands as cautions on a dashboard. Most only display what the system already knows. A few change settings, so they record the old state first and ask for authorization before writing.

Read the network state safely

Goal: identify the active interface, its address and gateway from a sample status report.

Before you start: The sandbox is a local model. Command replies here are authored sample output, not readings from your machine. Nothing you type changes your system.

Sandbox

iface enp1s0 ip 192.168.1.26 prefix 24 gateway 192.168.1.1 type ethernet router_ping_ms 0.684 internet_ping_ms 20.2 Current DNS provider: DHCP Servers: 192.168.1.1 band: 5 GHz available: 2.4, 5, 6 selected: auto Sample network report: status, DNS and band are separate commands. Try tam-dns to see the configured resolver. Now try tam-network-band to see the radio band. Try tam-network-status --verbose, tam-dns or tam-network-band (or type help).

What just happened

The report names the interface, address, prefix and gateway. The two ping fields are round-trip samples; a blank value means no reply arrived in that sample. tam-dns and tam-network-band answer narrower questions and do not change anything when used without arguments.

Try it

Run tam-dns and tam-network-band after the status command. Each answer comes from one authority: resolver configuration for DNS, and the Wi-Fi profile for the band. In a real terminal these commands read the live system.

If it goes wrong

The sandbox does not answer a command
Type help to see the simulated commands, or use the command in the goal exactly as written. Press Esc to close the sandbox.
A file looks empty or missing
Use ls to list the prepared files, then cat clues.txt (or the named file above) to see the exact text.

Check yourself

Which command would change DNS to DHCP?

tam-dns DHCP. A bare tam-dns only reports the current provider.

Command reference and boundaries

The status commands are read-only. tam-dns with an argument and tam-restart-wifi change state; the first preserves the previous DNS files and the second briefly drops active Wi-Fi. Treat them as distinct operations, not as variants of the same check.

Why the split matters

NetworkManager owns device and connection state; systemd-resolved owns name resolution. The Tamlinux commands read those authorities rather than keeping a second copy. A DNS change writes a drop-in, rewrites resolved configuration, reloads both services and reapplies active profiles before it is complete. A status command asks the kernel which device would carry traffic to a numeric address so that link, address and name failures stay separate.

Edge cases

  • Enterprise Wi-Fi has no shareable password, so the sharing commands refuse it.
  • A band pin takes effect only after reassociation.
  • Multiple default routes can exist; ip route get names the winner for a destination.
  • A VPN or captive portal can intercept traffic without changing the default route.

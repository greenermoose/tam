Guide / Networking / Internet protocol stack / Transport layer

The transport layer delivers data between programs on different hosts using ports and protocols such as TCP and UDP, each with a different delivery promise.

What the transport layer does

The internet layer can deliver a packet to the right machine. The transport layer helps deliver it to the right program on that machine. It also decides whether the conversation should be careful and ordered, like a phone call with confirmations, or quick and simple, like sending postcards.

Why it matters

Your computer can run many network programs at once: a browser, chat app, and update service. Transport-layer ports keep those conversations separate.

How to think about it

If an IP address is the building address, a port number is the apartment number. The transport layer makes sure the message reaches the right apartment.

How it works

The transport layer demultiplexes incoming packets to sockets using the 5-tuple: source IP, source port, destination IP, destination port, and protocol. TCP adds sequence numbers, acknowledgements, flow control, and congestion control. UDP provides a minimal header with ports, length, and checksum. QUIC builds reliable, encrypted transport features in user space over UDP.

Advanced usage

TCP info exposes round-trip time, congestion window, retransmissions, and other transport state useful for diagnosing performance.

Edge cases

  • NAT and firewalls: Middleboxes may rewrite ports or drop packets, making transport behavior depend on path state.
  • Ephemeral ports: Clients usually use temporary local ports chosen from a configured range.
  • Head-of-line blocking: TCP's ordered stream can delay later bytes when an earlier segment is lost; some applications avoid this with UDP/QUIC.

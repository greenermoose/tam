Guide / Networking / Internet protocol stack / Ports and sockets

A port identifies which program on a host should receive a network message, while a socket pairs that port with an address and transport protocol.

What is a port?

A port is a small number attached to a network message that says which program should receive it. An IP address identifies the computer; a port identifies the particular service or conversation inside it.

Why it matters

Without ports, a computer could only run one network program at a time. Ports let a web browser, a mail program and a printer service all use the same connection at the same time.

How to think about it

Think of a large apartment building. The street address gets a letter to the building; the apartment number gets it to the right household. The IP address is the street address and the port is the apartment number. A socket is the doorway that a program stands at to hand letters in and out.

New words

Port
A number from 0 to 65535 that identifies a service or conversation endpoint.
Socket
The endpoint a program uses to send and receive network data.
TCP
A transport protocol that keeps a reliable, ordered conversation.
UDP
A transport protocol that sends independent messages without a connection.

Check yourself

Can two programs use port 443 on one host?

Yes, if they bind different addresses or protocols; an address, protocol and port together identify the socket.

Linux actually draws ephemeral ports from /proc/sys/net/ipv4/ip_local_port_range, which usually defaults to a narrower range than the conventional one. Root privileges are needed only to bind a port below 1024, unless the process holds the CAP_NET_BIND_SERVICE capability.

How it works

A program calls socket(2) to create a socket, bind(2) to choose a local address and port, listen(2) to accept TCP connections, and accept(2) to obtain a new socket for each client. The original listening socket stays open. The kernel matches an incoming segment to a socket by hashing the four-tuple, with separate lookup tables for listening and established sockets. UDP uses sendto(2) and recvfrom(2), and preserves message boundaries: one send becomes one datagram. A socket appears in the process's file descriptor table, so /proc/<pid>/fd and lsof -i show which program owns it.

Advanced usage

Edge cases

  • A closed TCP connection spends time in TIME_WAIT so delayed duplicates cannot be mistaken for a new connection on the same four-tuple.
  • Two sockets cannot normally bind the same address and port. A wildcard 0.0.0.0 bind conflicts with a specific address bind on the same port unless options permit sharing.
  • Network namespaces each have their own port space, so containers can reuse the same ports without conflict.
  • A UDP socket with no peer receives datagrams from any source; an application that cares about identity must authenticate the sender itself.

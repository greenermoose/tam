Guide / Networking / Internet protocol stack / The internet protocol stack

A protocol stack splits network work into layers so a browser can send a request without knowing the details of every cable, radio and router along the way.

What is a protocol stack?

A protocol stack is a set of small jobs stacked on top of each other. Each job adds its own label to your message and passes it down to the next job. At the other end, the labels are read and removed in the reverse order until the original message arrives.

Why it matters

Layers let different kinds of equipment work together. A web page can travel from a laptop over Wi-Fi, through a router, across fiber, and into a server without the browser or the web server caring which cable carried each part. If one layer changes, the others do not have to be rewritten.

How to think about it

Think of sending a parcel. You write a note, put it in a box with a name on it, put the box in a mailbag with a route label, and hand the bag to a driver. The driver only reads the route label. When the parcel arrives, each wrapper is opened in reverse until the note is back in your friend's hands.

New words

Protocol
An agreed set of rules that two communicating programs follow.
Packet
A small piece of data with the addresses needed to deliver it.
IP address
The number that says which machine a packet is for.
Port
A number that says which program on that machine should receive the data.
Socket
The endpoint a program uses to send or receive network data.

The seven-layer OSI reference model splits the application layer into application, presentation and session, and splits the link layer into data link and physical. The four-layer internet model merges those pairs. Both describe the same exchange; neither is a separate implementation.

How it works

[ application data ]
[ TCP header ][ application data ]              segment
[ IP header  ][ TCP header ][ application data ] datagram
[ Ethernet header ][ IP header ][ TCP ][ data ][ FCS ] frame

Each layer reads only the header meant for it and passes the rest upward or downward. On the receive path a network interface places frames into memory, the driver raises an interrupt and the kernel's NAPI loop polls in batches to avoid an interrupt per packet. Each sk_buff carries header offsets that let layers add or remove headers without copying the payload. Netfilter hooks sit at PREROUTING, INPUT, FORWARD, OUTPUT and POSTROUTING, which is why a firewall rule can see a packet before or after a routing decision.

Edge cases

  • Checksums exist at several layers. A link-layer frame can be valid while the IP or transport checksum fails, so each layer reports its own errors.
  • A tunnel wraps an entire packet inside another one, adding another header pair and reducing the payload space available to the application.
  • Checksum offload and segmentation offload can make a captured frame look different from what the application wrote, because hardware fills in fields after the capture point.
  • A single physical interface can hold several addresses, and a network namespace gives each container its own stack with a separate loopback device.

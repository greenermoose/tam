Guide / Networking / Internet protocol stack / Internet layer

The internet layer is the part of the network stack that gives packets source and destination addresses and moves them across connected networks toward their destination.

What the internet layer does

When you send data across the internet, the internet layer puts an address label on each packet, like a postal address on an envelope. Routers read that label and decide where to send the packet next. This layer does not promise that every packet arrives, arrives once, or arrives in order; it focuses on getting packets from one network to another.

Why it matters

Without the internet layer, devices could only talk on the same local cable or Wi-Fi network. IP addresses and routing let packets cross many networks on the way to a distant server.

How to think about it

Think of the internet layer as the addressing and routing system for parcels. It decides which road or hub comes next, but it does not open the parcel or guarantee the recipient signs for it.

New words

IP address
A number that identifies a network interface so packets can be routed to it.
Router
A device that forwards packets between networks by choosing the next hop.

See internet-layer decisions on Linux

Goal: Identify an IP address, a route, and a next hop as internet-layer information.

Before you start: Read The internet protocol stack.

Worked example

$ ip -br addr show
$ ip route get 1.1.1.1

ip -br addr shows addresses assigned to interfaces. ip route get asks the kernel which next hop it would use for a destination. Both commands read state only.

What just happened

The kernel looked up the destination in its routing table. If the destination is on the local network, it can send directly. If not, it sends the packet to a gateway (next-hop router). The internet layer chooses the path; the link layer handles delivery on the local link.

Try it

Run ip route and find the line starting with default. That default route is the internet-layer path used when no more specific route matches.

If it goes wrong

No default route
Your machine may be able to reach local addresses but not remote networks. Check the connection configuration and local link first.
Wrong interface or source address
The kernel chooses routes based on its routing table and rules. Use ip route get <address> to see the chosen path.

Check yourself

Why is an IP address called a Layer 3 locator in OSI terms?

In the OSI model, Layer 3 is the network layer. IP addresses identify where a packet should be routed across networks, so they are Layer 3 locators. In the internet protocol stack, this is the internet layer.

How it works

The internet layer wraps transport data in an IP header containing source and destination addresses, hop limit/TTL, next-protocol field, and fragmentation or flow-related fields depending on version. Routers perform longest-prefix-match forwarding on the destination address. They do not maintain end-to-end application state; they forward each packet based on routing information. IPv4 is defined by RFC 791 and IPv6 by RFC 8200.

Advanced usage

$ ip -j route get 1.1.1.1
$ ip -6 route show

Use structured output for scripts and inspect IPv6 routing separately, because IPv6 link-local addresses and scope rules affect next-hop selection.

Edge cases

  • Fragmentation: IPv4 routers may fragment packets unless DF is set; IPv6 routers do not fragment in flight and send Packet Too Big messages.
  • Multiple addresses: One interface can have several IPv4/IPv6 addresses with different scopes and lifetimes.
  • Policy routing: Linux can choose routes based on rules beyond destination address, such as source address or firewall marks.

Check yourself

What does the internet layer guarantee, and what does it leave to higher layers?

It provides addressing and best-effort forwarding across networks. It does not guarantee delivery, ordering, duplicate suppression, or application-level meaning; transport and application protocols handle those needs when required.

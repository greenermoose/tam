Guide / Networking / Email / POP, IMAP and JMAP

SMTP carries mail to a mailbox; retrieval protocols let a client read it. POP, IMAP and JMAP make different choices about which side keeps the mail and its state.

Three ways to read a mailbox

POP usually downloads messages to one device and may remove them from the server. IMAP keeps messages on the server, so folders and read flags can follow you across devices. JMAP is a newer way for a client to ask the server for mail and changes using web-style requests.

Why it matters

The choice changes what happens when you read a message on a phone and later open a laptop. With server-side state, both devices see the same folders and read markers.

How to think about it

POP is like taking letters home. IMAP is like reading them in a shared filing cabinet. JMAP is like asking the cabinet for a structured list through a modern application interface.

New words

POP
Post Office Protocol, designed to fetch mail to a client.
IMAP
Internet Message Access Protocol, designed to work with mail kept on a server.
JMAP
JSON Meta Application Protocol, a newer mail access and submission protocol.
Webmail
A mail client that runs in a browser; it is not itself a retrieval protocol.

What just happened

  1. POP moved the centre of gravity to one device.
  2. IMAP kept the message store on the server and shared folders and flags.
  3. JMAP used structured requests and included submission as well as reading.
  4. Webmail was not a fourth protocol: a browser page is a client that uses one of these protocols or a provider-specific interface.

If it goes wrong

You assumed IMAP always downloads every message.
IMAP clients can fetch headers, search on the server and download only selected content.
You treated JMAP as a relay protocol.
JMAP is for client access and submission. Server-to-server relay still uses SMTP.

Check yourself

Decide your answer before you reveal it.

Which protocol best fits a person reading the same account on a phone and a laptop?

IMAP, because folders and flags stay on the server. POP can be configured to leave copies, but its normal model is a local download.

Is webmail a replacement for IMAP or JMAP?

No. Webmail is a client presented in a browser. It still needs a way to reach the message store, whether a standard protocol or a service-specific interface.

How it works

RFC 1939 defines POP3 with a small command set for listing and retrieving messages. It has limited folder and flag support. RFC 9051 defines IMAP4rev2 and obsoletes RFC 3501; it models mailboxes on the server, supports permanence flags, and allows a client to fetch selected message parts. JMAP core is defined by RFC 8620 and its mail extension by RFC 8621. JMAP batches methods into one HTTP request and uses push events to tell clients what changed.

Advanced usage

IMAP extensions such as IDLE provide push-style notifications, while CONDSTORE and QRESYNC let clients resynchronise flags without a full mailbox scan. JMAP has an analogous event model through its push protocol. Clients commonly authenticate with a password-based mechanism or OAuth, depending on the provider.

Edge cases

  • POP's RETR does not by itself delete a message; deletion policy is a separate client choice.
  • An IMAP flag change made offline must be reconciled later, and conflicts may need a deterministic rule.
  • JMAP submission sends a message for transfer; it does not replace SMTP between servers.

Check yourself

Why does IMAP support server-side search while POP generally does not?

IMAP's model keeps messages and metadata on the server, so the server can examine them and return matching identifiers. POP's model is centred on downloading messages to a client.

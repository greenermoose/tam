Guide / Networking / Email / SMTP and submission

SMTP is the conversation a mail client uses to hand a message to a server, and that mail servers use to pass it on. The message itself is carried after the routing information has been agreed.

A polite handover

Your client connects to a mail server and says hello. It says which address the message comes from and who should receive it. Only then does it send the message text. The server can say yes, try later, or no at each step.

Why it matters

Because the server checks each step, it can reject an unknown recipient before receiving a large message. It can also ask the client to try again later if the system is busy.

How to think about it

Imagine handing a parcel to a counter clerk. The clerk first asks where it came from and where it goes, then accepts the parcel. If the destination office is closed, the clerk keeps it and tries later.

New words

SMTP
Simple Mail Transfer Protocol, the language used to transfer mail.
Submission
Handing a newly written message to a server.
Relay
Passing a message from one mail server to another.
Extension
An optional capability a server announces and a client may use.

What just happened

  1. EHLO opened the session and invited the server to list extensions.
  2. MAIL FROM and RCPT TO built the envelope that servers use for routing and bounces.
  3. DATA began the message transfer, ended by a line containing only a period.
  4. The port list showed the common separation between relay and submission.

The session and output are teaching samples. The sandbox does not open a network connection, send mail or install an SMTP server.

If it goes wrong

The message text appears before the envelope in your notes.
SMTP negotiates the envelope first. The header is part of the DATA payload, not the envelope commands.
You assumed port 25 is always used by clients.
Client submission normally uses 587 or 465. Port 25 is the conventional server-to-server relay port and is often blocked for end users.

The guide describes standard SMTP behaviour rather than the settings of one mail service. A reader's provider chooses the submission host, port and authentication method.

Check yourself

Decide your answer before you reveal it.

Why does the server need RCPT TO before DATA?

It can accept or reject each recipient before spending bandwidth on the message, and it can record separate outcomes for multiple recipients.

What does EHLO add over the older HELO greeting?

EHLO lets the server advertise ESMTP extensions such as STARTTLS and SMTPUTF8, which the client may then use.

How it works

RFC 5321 defines the session, envelope and queue model. RFC 6409 adds the message submission role, including authentication and policy differences from general relay. STARTTLS is defined by RFC 3207: a plaintext session is upgraded after the client sees the advertisement and succeeds with the handshake. Implicit TLS on port 465 starts TLS before any SMTP command, as described by RFC 8314.

Advanced usage

Delivery status notifications request positive or negative reports for a queued message; they do not prove delivery to a human. Relay servers use the envelope return path and recipient set when constructing those reports. A submission server may require authentication and may rewrite headers or enforce size and rate limits before accepting a message.

Edge cases

  • STARTTLS can be opportunistic: if neither side insists on encryption, an active attacker may strip the advertisement and leave the session plaintext.
  • Acceptance with a 2xx reply means the receiving server took responsibility for the message, not that the user read it.
  • Each recipient has its own outcome; a partial 4xx or 5xx reply leaves other recipients unaffected.

Check yourself

Why is implicit TLS a different security starting point from STARTTLS?

Implicit TLS protects the connection from the first byte, so there is no plaintext greeting to strip. STARTTLS begins in cleartext and depends on correct advertisement, negotiation and policy.

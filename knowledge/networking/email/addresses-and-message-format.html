Guide / Networking / Email / Addresses and message format

An email message is structured text. Some lines tell people who wrote it; other information tells servers where to carry it. Attachments are added as separate parts without changing the basic message.

What is inside a message?

A message has a message header, a blank line and a body. The header contains lines such as From:, To: and Subject:. The body is what the reader sees. An email address names a mailbox, usually written as a name, an @ sign and a domain.

Why it matters

Servers and people need different information. A mailing list can show the list as the visible sender while still returning bounces to the list manager. Both pieces can be correct.

How to think about it

Think of a letter in an envelope. The address on the envelope tells the delivery service where it goes. The letter inside may say who wrote it and may include separate photographs.

New words

Header
Labelled lines at the top of a message that describe it.
Body
The main content after the blank line.
Envelope
The routing information exchanged by mail servers, separate from visible headers.
MIME
The rules that let a message carry several typed parts, including attachments.

Read a message as layers

Goal: you will be able to identify the header, the body and a MIME part in a sample message.

What just happened

  1. The first four lines were header fields with a label and a value.
  2. The blank line ended the header; the next line began the body.
  3. Content-Type described how a mail program should interpret the content. The sample part line stands in for a MIME attachment.
  4. The envelope sample showed that bounce routing can differ from the visible From: header.

Check yourself

Decide your answer before you reveal it.

Why is the SMTP envelope not identical to the visible header?

The envelope carries routing and bounce information between servers; the header carries information for people and mail programs. Mailing lists and aliases legitimately make them differ.

What does a blank line do in a message?

It ends the header block. Everything after it is body content until a MIME boundary introduces another part.

How it works

RFC 5322 defines the field syntax and the line-oriented shape of a message. RFC 2045 and its companion documents define MIME: a Content-Type describes each part, a transfer encoding makes binary data safe for a text channel, and boundaries separate parts in a multipart body. Header fields such as Received: are added by servers along the path and form a partial trace.

Advanced usage

SMTPUTF8 extends SMTP so that both the local part and the domain may use internationalised characters, provided each hop advertises support. Without that extension, servers may accept only ASCII addresses. A message identifier is intended to be globally unique, but a forwarded copy keeps its original identifier.

Edge cases

  • A header can be folded across lines; parsing must unfold it before interpreting the value.
  • MIME filenames and display names are untrusted input. Readers should not execute or open unexpected content because a name looks familiar.
  • Visible From: can be forged. Authentication systems decide which domains can be trusted, not the appearance of the header alone.

Check yourself

Why does SMTP need a separate envelope identity for bounces?

The return path identifies where delivery status should go. It may differ from the author's visible address, particularly for lists, relays and automated mail.

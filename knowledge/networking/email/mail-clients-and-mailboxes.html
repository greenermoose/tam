Guide / Networking / Email / Mail clients and mailboxes

The mail client is the part a person sees. It presents folders, flags and search, but the server usually holds the authoritative mailbox.

What the client keeps, and what the server keeps

A client needs an account address, a place to send messages and a place to read them. With IMAP or JMAP, folders and read flags live on the server, so several devices can see the same state. A client may also keep local copies for offline reading.

Why it matters

Knowing where state lives explains why marking a message read on a phone can change it on a laptop, and why deleting a local copy may not delete the server copy.

How to think about it

The server is the shared filing cabinet. Each client is a desk with its own notepad. A person can write notes at a desk, but the cabinet decides which folders exist for everyone.

New words

Account
The identity and mailbox a client connects to.
Folder
A named collection of messages in a mailbox.
Flag
A marker such as read, flagged or answered.
Alias
An additional address that delivers to the same mailbox.

If it goes wrong

A message stays unread on another device.
The second client may be offline or using a local copy that has not synchronised. Check the server-side state when it reconnects.
You expected a deleted local copy to remove the server message.
Deletion policy is a client setting. A local-only copy and a server mailbox are different stores.

The guide avoids prescribing a mail app. Readers choose their client and provider; the client/server rules stay the same across Tamlinux and other systems.

Check yourself

Decide your answer before you reveal it.

Why can a client work offline and still need a server later?

It uses cached copies for reading and composing, but changes such as sent mail and flags must be synchronised with the authoritative mailbox when a connection returns.

Is an alias a second mailbox?

Not necessarily. An alias is an additional address that routes into an existing mailbox.

How it works

IMAP models mailboxes and permanence flags on the server; JMAP models mailboxes and searchable records with batched method calls. Both allow a client to keep a cache. POP centres on downloaded messages and has little shared state. Encryption in transit protects a connection; end-to-end systems such as OpenPGP or S/MIME protect message content so that the store and intermediate servers cannot read it. Those systems require key management and do not hide envelope routing information.

Advanced usage

Configuration may be discovered automatically from the domain or supplied by the provider. OAuth-based authentication is common for hosted mail. Synchronisation must reconcile concurrent flag changes, local deletions and sent messages. A robust client keeps a durable local queue for messages composed offline and replays them after reconnecting.

Edge cases

  • End-to-end encryption breaks server-side content search unless the client searches decrypted local copies.
  • Aliases complicate SPF, DKIM and DMARC because the visible sender domain may differ from the delivery domain.
  • Webmail is a client with a server-side session; it does not remove the need for an access protocol behind the browser.

Check yourself

Why does end-to-end encryption not replace transport encryption?

End-to-end encryption protects message content, but metadata and connection behaviour remain visible. Transport encryption still protects the protocol exchange and any content not covered by the end-to-end layer.

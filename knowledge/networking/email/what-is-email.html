Guide / Networking / Email / What is email?

Email lets one person write a message and let another read it later. The two people do not have to be online at the same time, because mail servers keep the message until it can be delivered.

Messages that wait

Email is a way of sending written messages across a network. You write a message in a mail client, give it an email address, and send it. A mail server accepts the message and passes it onward. The receiver's server puts it in a mailbox, where a client can read it later.

Why it matters

People use different devices and work at different times. Email does not need a live call between both people. The message is stored at one or more points along the way, then forwarded when the next step is ready.

How to think about it

Think of a parcel service. You hand a parcel to a local counter. Counters sort it and pass it between depots. It waits at the recipient's local office until the recipient collects it. You do not follow the parcel yourself.

New words

Mail client
The program in which a person writes, sends and reads mail. It is also called a mail user agent.
Mail server
A program that accepts, relays or stores mail for other programs.
Mailbox
The stored collection of messages belonging to an account.
Store and forward
Accepting a message, keeping it safely, and sending it onward when possible.

Check yourself

Decide your answer before you reveal it.

Why can the receiver read a message while the sender is offline?

Because servers store the message along the path. Email is store and forward, so both people do not need a simultaneous connection.

Is a webmail page a mail server?

No. It is a mail client running in a browser. It talks to servers that submit, relay and store the mail; the page itself does not deliver it.

The architectural boundary

Reference

RoleActs forTypical protocol or store
Mail user agent (MUA)A personSubmission, POP, IMAP or JMAP
Mail submission agent (MSA)A sending domainSMTP submission
Mail transfer agent (MTA)A sending or relaying domainSMTP relay
Mail delivery agent (MDA)A receiving domainLocal mailbox or message store

How it works

The Internet Mail Architecture separates these roles because each has a different trust boundary. A client may authenticate to submit a message; relays use DNS to find the next hop; a receiving agent applies policy and writes to a store. The role names describe functions, not necessarily separate machines: one product may combine several roles.

Edge cases

  • Store and forward gives resilience, not a guarantee. A message can be delayed, rejected or filtered after it leaves the client.
  • A mailbox is a store, not a transport. Retrieval protocols read it; SMTP does not normally read it.
  • The visible header and the envelope can differ legitimately, for example with aliases and mailing lists.

Check yourself

When a single mail package handles submission, relay and local delivery, has it stopped being a client/server system?

No. The functions and boundaries still exist even if one process implements several of them. The distinction matters for authentication, policy and troubleshooting.

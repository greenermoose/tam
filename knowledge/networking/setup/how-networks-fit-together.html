Guide / Networking / Network setup / How networks fit together

Every network connection answers four questions: which link is up, which address is used, which route leaves the local network, and which resolver turns names into addresses.

The four questions of every connection

Imagine sending a letter. You need a way to hand it to the postal service, a street address for the recipient, knowledge of which sorting office handles other towns, and a way to look up an address from a person's name. A computer asks the same four questions.

Why it matters

When something breaks, these four layers fail independently. A cable can be unplugged while the address is still assigned; an address can be correct while the router is wrong; the router can work while a name lookup fails. Answering the questions in order turns a vague "the internet is down" into a specific fault.

How to think about it

1. LINK     which door does traffic leave?        a network interface
2. ADDRESS  what number identifies this machine?  an IP address
3. ROUTE    where do other networks live?         a gateway and a routing table
4. NAME     what number belongs to this name?     a DNS resolver

The kernel owns the first three. A service such as NetworkManager tells the kernel what to put there. The DNS resolver answers the fourth question by asking other machines.

New words

Network interface
The named doorway a computer uses to send and receive traffic, such as enp1s0 for wired Ethernet or wlp3s0 for Wi-Fi.
IP address
A number that identifies a machine on a network, much as a street address identifies a house.
Gateway
The router that carries traffic leaving your local network for other networks.
DNS
The Domain Name System, which turns a name such as example.com into an IP address.
DHCP
A service that hands out addresses and other settings automatically when a device joins a network.
Packet
A small block of data sent across the network, carrying part of a message and the addresses needed to deliver it.

Each prepared line answers one question. The link line names an active interface, the address line gives its IP and prefix, the route line names the next router, and the resolver line maps a name to an address. This is sample text, not a scan of your machine.

How it works

Outgoing data is wrapped as it descends. An application writes bytes to a socket; TCP or UDP adds a header with port numbers; IP adds source and destination addresses; the link layer adds a frame header with neighbor addresses. The routing table decides which interface carries each packet, and the neighbor table turns the next-hop IP address into a hardware address. On receive, the reverse happens.

NetworkManager does not implement the stack. It computes a desired configuration from saved profiles and pushes it into the kernel through netlink, then monitors the interface for changes. systemd-resolved listens on a local stub address and answers getent queries through the Name Service Switch, forwarding to the servers listed per link or globally. Keeping the authorities separate is why a broken resolver does not corrupt routes, and why a link flap does not erase saved profiles.

Edge cases

  • Loopback is a real interface with its own address. Traffic to 127.0.0.1 never leaves the machine, which makes it a safe place to test a service.
  • A link-local IPv6 address (fe80::/10) needs a scope identifier, written fe80::…%enp1s0, because the same prefix can exist on several interfaces.
  • A virtual interface such as docker0 or a VPN tunnel appears in the same lists as hardware. It may carry a route without any physical cable.
  • An address can be present while its route is marked linkdown. The kernel keeps the configuration, but no carrier means nothing can be delivered.
  • Name resolution is not a single service: /etc/hosts, NSS modules, mDNS and DNS each answer some names. The order is set in /etc/nsswitch.conf.

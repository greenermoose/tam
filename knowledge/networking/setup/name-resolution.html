Guide / Networking / Network setup / Name resolution

Name resolution turns a host name into an address. A local resolver may answer from cache or ask DNS servers, following delegation until it finds the zone that knows.

A phone book that asks other phone books

DNS is a distributed phone book. Your computer asks a local resolver; the resolver asks other servers, starting near the root of the name tree, until it finds the server responsible for the name. The answer is an IP address that the routing layer can use.

Why it matters

Names change address when a service moves. Using a name means a bookmark keeps working; using a hard-coded address breaks. When a name fails but a numeric address works, you know the link and the route are fine and only the lookup needs attention.

How to think about it

example.com
  --> local resolver (often your router or a public server)
  --> root server: "ask the .com servers"
  --> .com server: "ask the servers for example.com"
  --> authoritative server: "104.20.23.154"

A DNSSEC signature can prove an answer has not been altered, but it does not make the lookup private. Ordinary DNS queries travel in clear text unless an encrypted transport is configured.

New words

DNS
The Domain Name System, a hierarchical service that maps names to data such as addresses.
Host name
A label for a machine, which may be resolved locally or through DNS.
DHCP
The service that often tells a computer which resolver to use when it joins a network.
DNSSEC
Signed DNS records that let a resolver verify the origin and integrity of an answer.
mDNS
Multicast DNS, which answers names on the local link without a central server.

What just happened

getent returns the final address your system would use. resolvectl status shows which servers and scopes the resolver has, and resolvectl query records where the sample answer came from. All three replies are authored sample output.

Check yourself

Why can a recently changed DNS record still look old?

Resolvers cache answers for the record’s time to live, so different resolvers may update at different times.

How it works

A recursive resolver follows delegations from the root through top-level domains to an authoritative server, caching each answer for its time to live. An iterative client does that walk itself; most applications ask a recursive resolver instead. systemd-resolved exposes the result through a local stub and through the Resolve D-Bus API, while /etc/nsswitch.conf decides whether an application consults files, mDNS or DNS first.

Search domains append a suffix to a short name. A link marked +DefaultRoute is eligible for all queries; a link with a routing domain is used only for names inside that domain, which is how split DNS keeps a corporate name inside the tunnel. DNSSEC validation, when enabled, verifies signatures from the root down; it proves integrity and origin, not confidentiality. DNS over TLS and DNS over HTTPS address confidentiality by encrypting the query.

Advanced usage

Reading the cache-free form distinguishes a fresh answer from one the resolver remembered. Compare it with a normal query to see the cache in action.

Edge cases

  • /etc/hosts is consulted first on many systems, so an old entry can shadow a DNS answer that has changed.
  • A CNAME chain can return several names; the final address is what the application connects to, while the alias stays useful.
  • Resource records have a time to live. A cached answer can outlive a change made at the authoritative server until the timer expires.
  • Multiple addresses in one answer let a client try another if the first is unreachable; a single-address answer has no such fallback.
  • .local is reserved for link-local names. Sending it to a global DNS server is a common misconfiguration that produces NXDOMAIN.
  • DNS over UDP can lose a large answer; EDNS0 allows larger messages and TCP fallback handles truncation.

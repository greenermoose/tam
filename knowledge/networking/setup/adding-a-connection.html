Adding a connection

A connection is a saved recipe that tells the computer how to configure an interface: whether to ask for an address automatically or use a fixed one, which router to use, and which DNS servers to query.

Before this

Addresses and subnets explains the numbers a profile contains.

A recipe, not a one-time action

When you connect to a network, the operating system can either ask a DHCP server for settings or use settings you typed in. A saved connection remembers that choice, so the next time the cable is plugged in or the Wi-Fi network is in range, the same settings return without being entered again.

Why it matters

Saving a connection avoids repeating the setup and lets several profiles coexist. A laptop can keep one profile for home and another for work; a desktop can keep a wired profile and a fallback Wi-Fi profile. Editing a profile changes future connections, so knowing how to undo a change matters.

How to think about it

connection profile = { which interface, which SSID, how to get an address,
                       which DNS servers, whether to connect automatically }
        |
        v
NetworkManager applies it to the kernel when the link appears

Most home networks use DHCP: the router hands out an address, a prefix, a gateway and DNS servers. A printer, server or lab device often needs a fixed address so its address does not change.

New words

DHCP
A service that assigns an address and related settings automatically.
IP address
The number assigned to an interface; it may be leased from DHCP or set manually.
SSID
The public name of a Wi-Fi network, stored in a Wi-Fi profile.
Network interface
The device a profile is bound to, such as enp1s0.
Gateway
The router a profile uses for traffic outside the local network.

Inspect profiles before creating one

Goal: you will be able to list saved connections, tell which one is active, describe how it obtains an address, and say what you would delete to undo a new profile.

Before you start: these commands read profile state. In this exercise you do not need to create a profile; the creation command is shown for reference in the expert section, together with its undo.

Worked example

$ nmcli device status
DEVICE   TYPE      STATE                   CONNECTION
enp1s0   ethernet  connected               Wired connection 1
docker0  bridge    connected (externally)  docker0
lo       loopback  connected (externally)  lo
enp2s0   ethernet  unavailable             --
wlp3s0   wifi      unavailable             --
$ nmcli -t -f NAME,TYPE,DEVICE connection show | grep -E ':(802-3-ethernet|bridge|loopback):'
Wired connection 1:802-3-ethernet:enp1s0
docker0:bridge:docker0
lo:loopback:lo
Wired connection 2:802-3-ethernet:
$ nmcli -f IP4.METHOD,IP4.ADDRESS,IP4.GATEWAY connection show 'Wired connection 1'
IP4.METHOD:  auto
IP4.ADDRESS: --
IP4.GATEWAY: --

Captured on a wired Arch Linux workstation on 2026-11-21. Wi-Fi profile names are omitted from the second command so the output stays focused on wired profiles; your list will differ.

What just happened

  1. nmcli device status shows devices and the profile in use on each. unavailable means no carrier; connected (externally) means something other than NetworkManager configured the device.
  2. nmcli connection show lists saved profiles, including ones not currently active. Wired connection 2 is saved but unused.
  3. The fields printed in the third command describe the profile, not the live interface. auto means DHCP; manual would mean a fixed address written in the profile.
  4. The second output is in -t (terse) form with selected fields, which is easier to read in scripts and avoids printing secrets.

Try it

On your own machine, run nmcli device status, then nmcli connection show --active. Pick the active connection and print its method with nmcli -g IP4.METHOD connection show '<name>'. This is read-only. Write the profile name down: nmcli connection delete '<name>' is the undo for a profile you create.

If it goes wrong

Error: unknown connection
The name must match a saved profile exactly; quote names that contain spaces. List them again with nmcli connection show.
A new profile does not connect
Check nmcli device status for carrier and confirm the profile is bound to the right interface. A profile for enp2s0 cannot configure enp1s0.
The profile shows auto but no address is assigned
No DHCP server answered on that link. Look at journalctl -u NetworkManager for lease errors before assigning a fixed address.
A Wi-Fi profile asks for a password every time
The saved secret may be missing or marked for this user only. Recreate the profile with the correct key management settings rather than typing the password into a command you later paste into a log.

Tamlinux keeps connection management in NetworkManager and binds the desktop network panel to Meta + CTRL+W. Changing DNS providers goes through tam-dns, which saves the previous configuration before writing it. Those behaviors are recorded in the public tamlinux repository and in the connection reference page.

Check yourself

What is the difference between a device and a connection in nmcli?

A device is the hardware or virtual interface; a connection is a saved profile that can be applied to a compatible device. Several profiles can exist for one device, but only one is active on it at a time.

Why read a profile's IP4.METHOD instead of the interface address?

The method records the intent (auto or manual), while the live address records the current result. When a lease has not arrived yet, the profile still tells you what should happen.

Which command undoes a newly created profile?

nmcli connection delete '<name>' removes the saved profile. It does not delete files on other systems or change the network itself.

How it works

NetworkManager stores profiles as keyfiles under /etc/NetworkManager/system-connections/ or in its private D-Bus state. The settings names above are the same keys a keyfile uses, grouped into sections such as [ipv4] and [802-11-wireless]. nmcli connection add creates a profile; nmcli connection up applies it; nmcli device reapply pushes edited settings into the active connection without a full reconnect.

A DHCP lease is not a permanent address. It carries a lifetime, and the client renews it before expiry; if renewal fails the address can disappear while the cable stays connected. A manual profile has no such timer, which is why printers and servers use one.

Advanced usage

$ nmcli connection add type ethernet con-name 'Lab wired' ifname enp2s0 \
    ipv4.method manual ipv4.addresses 192.168.2.10/24 \
    ipv4.gateway 192.168.2.1 ipv4.dns '192.168.2.1'
Connection 'Lab wired' (...) successfully added.
$ nmcli connection up 'Lab wired'
Connection successfully activated ...
$ nmcli connection delete 'Lab wired'
Connection 'Lab wired' (...) successfully deleted.

Illustrative sequence for reference, not an exercise on a working machine. The last command is the recorded undo. Activation changes kernel state; deleting the profile does not undo changes made to other systems.

Edge cases

  • A Wi-Fi profile without a secret can still connect through an enterprise method or a stored system secret; reading it back requires suitable permissions.
  • Setting both a manual address and ipv4.method=auto leaves the manual address unused; the method decides which values are applied.
  • Two profiles for the same interface can both have autoconnect=yes. The one with the higher autoconnect priority or the most recent activation usually wins, which can look random.
  • A VPN profile is a connection too. It adds a virtual device and its own routes rather than configuring the physical interface.
  • Changing DNS in a profile does not immediately change the running resolver; the profile must be reapplied or the connection reactivated.

Check yourself

Why is deleting a profile the right undo for a profile you just created?

The profile is the persistent change. Removing it restores the previous set of profiles; the live configuration returns to whatever the remaining active profile supplies on the next reactivation.

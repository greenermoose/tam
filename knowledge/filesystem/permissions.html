File Permissions and Ownership

Permissions control access through an owner, a group and everyone else. Practice on temporary files before changing permissions on real documents.

Run your own small script

Goal: you will be able to add execute permission for yourself and confirm the result.

Why it matters: a downloaded or newly written script may be readable without being directly executable. You can grant just the access you intend.

Before you start: read filesystem basics. This example creates one script in a temporary directory.

Enter commands in a terminal one line at a time. Do not type the leading $ shown in sessions. A command that prints nothing can still have succeeded. ./hello.sh means the file named hello.sh in the current directory.

Worked example

For this section, make a new temporary directory and enter it. These commands print nothing when they succeed. Keep this terminal open while you work through the section.

work=$(mktemp -d)
cd "$work"

$ printf '%s\n' '#!/bin/sh' 'printf "hello\n"' > hello.sh
$ chmod 600 hello.sh
$ stat -c '%A %a %n' hello.sh
$ chmod u+x hello.sh
$ stat -c '%A %a %n' hello.sh
$ ./hello.sh
-rw------- 600 hello.sh
-rwx------ 700 hello.sh
hello

Captured on Arch Linux, 2026-10-21. GNU stat omits variable owner names, sizes and timestamps from this display.

What just happened

  1. printf writes a two-line shell script.
  2. chmod 600 sets a known starting mode: only the owner can read and write.
  3. chmod u+x adds execute for the owner (user) without granting it to group or others.
  4. stat shows the mode change; running the script prints hello.

Try it

In this scratch directory, use chmod u-x hello.sh. Inspect with the same stat command. Add execute back before trying the script again.

If it goes wrong

No such file or directory
Check the spelling and current directory with pwd and ls.
Permission denied when executing
Check the owner execute bit. A noexec mount can also prevent direct execution; do not change mount settings for this exercise. sh hello.sh can read this known script even without its execute bit.

cd /tmp

Check yourself

Answer before revealing the explanation.

Which command adds execute only for the owner: chmod u+x or chmod a+x?

chmod u+x. The a form asks for owner, group and others; u changes only the owner class.

Does chmod printing no output mean that it failed?

No. Successful chmod is normally silent. Inspect the mode with stat; an error message or nonzero exit status signals failure.

Choose modes for private and shared work

Goal: choose file and directory modes without granting unnecessary write access.

Mental model

owner | group | other
 r w x | r w x | r w x
 4 2 1 | 4 2 1 | 4 2 1

Add the values within each class: 6 is read+write, 7 adds execute. For a directory, read lists names, execute searches/traverses, and write permits changing entries when search access is also available.

Worked example

For this section, make a new temporary directory and enter it. These commands print nothing when they succeed. Keep this terminal open while you work through the section.

work=$(mktemp -d)
cd "$work"

$ mkdir shared
$ chmod 2770 shared
$ stat -c '%A %a %n' shared
$ (umask 0027; printf '%s\n' note > shared/note.txt)
$ stat -c '%A %a %n' shared/note.txt
drwxrws--- 2770 shared
-rw-r----- 640 shared/note.txt

Captured on Arch Linux, 2026-10-21, in a fresh directory without default ACLs. The leading 2 sets SetGID: children inherit the directory's group. It does not grant group write. The umask removes requested creation permissions; 0027 yields 0640 for this ordinary file creation.

Completion task

Create note.txt containing private, then fill the mode in chmod ___ note.txt so its owner can read/write, its group can read, and others have no access. Inspect it with stat.

$ printf '%s\n' private > note.txt
$ chmod 640 note.txt
$ stat -c '%A %a %n' note.txt
-rw-r----- 640 note.txt

Use 640: 4+2 for the owner, 4 for the group, 0 for others. Captured on Arch Linux, 2026-10-21.

Independent task

Create a directory named private that only you can list, enter and change.

$ mkdir private
$ chmod 700 private
$ stat -c '%A %a %n' private
drwx------ 700 private

Directory execute allows traversal. Read/write without execute is insufficient for ordinary directory use. Captured on Arch Linux, 2026-10-21.

Check yourself

Answer before revealing the explanation.

A team directory has SetGID but new files are not group-writable. Which property should you check?

Check the creating program mode, umask and default ACL. SetGID controls group inheritance, not the file write bits.

A user can write a file but cannot remove its name. Is that contradictory?

No. Changing file data uses file access; removing a name uses permissions on the containing directory and may be restricted by the sticky bit.

Reason about inodes and access checks

Reference: Linux st_mode combines file-type and permission bits. Use S_IFMT and the S_IS* macros rather than assuming the C type has a fixed width. Ordinary access also depends on process credentials, ACLs, mount flags and security policy.

How it works

Hard links name the same inode; chmod through either name changes the same mode. Symlinks have separate inodes; normal chmod follows their targets. See stat(2), path_resolution(7) and capabilities(7).

02000 SetGIDCredential effect on eligible executables; group inheritance on directories
01000 stickyRestricts removal/rename in directories to the file owner, directory owner or a suitably privileged process

Explore

For this section, make a new temporary directory and enter it. These commands print nothing when they succeed. Keep this terminal open while you work through the section.

work=$(mktemp -d)
cd "$work"

$ printf '%s\n' original > original
$ chmod 600 original
$ ln original alias
$ chmod 640 alias
$ stat -c '%a %h %n' original alias
640 2 original
640 2 alias

Captured on Arch Linux, 2026-10-21. Both names report mode 640 and link count 2. Changing a hard link's permissions does not isolate its contents.

Edge cases and cost

A read-only mount, immutable attribute or security module can deny an operation even when mode bits allow it. GNU chmod treats directory SetGID preservation specially; consult its manual before assuming a numeric mode clears every special bit. Recursive permission changes cost filesystem walks and can damage unrelated access; diagnose the failing path first.

How would you distinguish a directory traversal failure from a file ACL failure?

Inspect search permission along the path first, using the failing identity. Then inspect the target mode and ACL, followed by mount and security policy. A single ls on the target does not establish access through all ancestors.

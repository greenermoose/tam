Selecting files natively with tam-file-select

tam-file-select is a fast C utility (linking libtam) that opens the desktop XDG file chooser portal so shell scripts and theme tools can ask you to pick files or folders cleanly.

Picking a file cleanly from scripts and themes

When a desktop action—such as choosing a custom background image—needs you to pick a PNG or SVG file, tam-file-select opens your native graphical file dialog, prints the chosen file path to standard output, and exits immediately.

Why it matters

Delegating to the XDG portal avoids pulling heavy graphical toolkits into every small script while respecting your current desktop theme.

How to think about it

Every run returns one clear exit status: 0 when at least one path was chosen, 1 when you cancelled without choosing, and 2 if the portal could not open.

New words

Exit status
The numeric result code telling a calling script whether a file was chosen (0), cancelled (1), or failed (2).
Path
The chosen file or folder path printed one line per selection on stdout.

Options, filters, and exit codes

Goal: call tam-file-select with optional title, multi-select, directory mode, or extension filters and handle cancellation cleanly in shell scripts.

Before you start: running tam-file-select requires an active graphical session with an XDG desktop portal backend. Cancelling the dialog makes no filesystem changes.

Worked example

Prompt the user for one image file (png or svg) without modifying any files:

$ picked=$(tam-file-select --title "Pick PNG or SVG" --extensions "png svg")
$ printf 'exit=%s picked=%s\n' "$?" "$picked"
OptionEffect
--title <title>Set dialog window title (default: Select file)
--multipleAllow selecting multiple files, printed one path per line
--directorySelect a folder instead of a file
--extensions "<ext ...>"Space-separated filename extension filter list

Try it

In a graphical terminal, run tam-file-select --directory --title "Test pick" and press Cancel to observe exit status 1 cleanly without touching any files.

If it goes wrong

Command exits with status 2
Either no XDG desktop portal is available (for example on a headless text VT), an invalid flag was passed, or tam_bundle_guard refused execution while a bundle update is switching versions.
Script fails when user presses Cancel
Always handle exit status 1 explicitly instead of treating empty stdout under set -e as a selected filename.

tam-file-select guards against mid-upgrade state transitions via tam_bundle_guard, instructing users to inspect tam-bundle status from the console if a version switch or recovery is in progress.

Check yourself

Answer before revealing the explanation.

What exit status does tam-file-select return when the user cancels the dialog?

Exit status 1 (while 0 means a selection was printed and 2 means chooser failure).

How should shell scripts separate multiple extensions passed to --extensions?

Space-separated inside quotes, for example --extensions "png svg".

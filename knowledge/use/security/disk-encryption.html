Disk encryption and LUKS passphrases

This page explains what full-disk encryption protects while your computer is turned off, why unlocking happens early at boot, and how Tamlinux manages encrypted drives.

Locking your drive when the machine is off

If someone removes the storage drive from a powered-off laptop, disk encryption scrambles the files on that drive so they look like random noise without the unlock passphrase or key.

Why it matters

Your login password stops someone sitting at a locked screen, while disk encryption protects your files even if the physical laptop or SSD is lost or stolen.

How to think about it

Think of disk encryption as locking the entire filing cabinet while the computer is shut down. Once you unlock the drive at startup, the running system can read files normally until you power off again (or lock the screen while away).

New words

Encryption
Scrambling stored bytes with a secret key so they cannot be read without unlocking them.
LUKS
Linux Unified Key Setup, the standard Linux disk-encryption format used on root and external drives.
Boot
The early startup sequence that unlocks encrypted storage before launching your desktop.

Inspect encrypted drives and manage passphrases safely

Goal: distinguish what is encrypted from unencrypted boot partitions and inspect LUKS drives safely without altering key slots.

Before you start: listing block devices and partition types is read-only. Changing a LUKS passphrase modifies disk header key slots; ensure you keep at least one tested recovery passphrase stored safely offline before changing slots.

Worked example

List block devices, filesystems, and mount points read-only to see which partitions hold crypto_LUKS versus your EFI boot partition:

$ lsblk -f

You can inspect detailed size, model, and mount information for a specific device path without changing it:

$ tam-drive-info /dev/nvme0n1

When a drive uses LUKS, notice that the small EFI system partition (containing the boot loader and kernel images) remains unencrypted so your firmware can start the unlock prompt.

Try it

Run lsblk -o NAME,TYPE,FSTYPE,MOUNTPOINTS in a terminal. Identify which partition carries crypto_LUKS and which mapped device sits underneath your root filesystem.

If it goes wrong

Passphrase rejected at boot unlock
Check keyboard layout or Caps Lock, since early boot prompts normally default to US layout. Test carefully before repeating wrong attempts.
Need to update an encrypted drive passphrase
Menu → Update → Password → Drive Encryption runs tam-drive-password (which selects drives via tam-drive-select). Never remove the only working key slot before verifying the replacement passphrase.

Disk encryption protects data at rest when powered down or hibernated; while unlocked and running, rely on screen locking (Meta + Escape or tam-system-lock) and normal file permissions.

Check yourself

Answer before revealing the explanation.

Does disk encryption replace locking your screen when you step away from a running laptop?

No. Once booted, the encrypted drive is unlocked in memory; you still need screen locking and user permissions while running.

Which read-only command helps identify whether a partition uses crypto_LUKS?

lsblk -f (or blkid -t TYPE=crypto_LUKS read-only with privileges).

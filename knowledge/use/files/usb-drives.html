Using USB drives safely

This page explains where removable USB drives appear on Tamlinux, how to copy files onto them, and why you should always eject or unmount before pulling the plug.

Plugging in and removing a thumb drive

When you insert a USB flash drive in a graphical Tamlinux session, the desktop automatically makes it appear as a folder (usually under /run/media/$USER/ and in the sidebar of the Files window, Meta + Shift + F).

Why it matters

Linux temporarily holds copied file data in memory before finishing the physical write to flash chips. Pulling a USB stick out early can leave half-written or corrupt files.

How to think about it

Mounting attaches the drive's folders into your filesystem tree so programs can read and write it; unmounting flushes any pending writes cleanly so removing the cable is safe.

New words

Mount
Attach a filesystem on a storage device to a directory path so files become accessible.
Mount point
The folder path where a connected filesystem appears, such as /run/media/$USER/<label>.
USB
Universal Serial Bus, the connector standard used by external flash drives and peripherals.

Inspect mounted drives and unmount cleanly

Goal: verify where a removable drive is mounted read-only and unmount its filesystem cleanly before disconnecting.

Before you start: checking block devices is read-only. Never force-unmount or unplug while a copy command is still writing or a terminal still sits inside the mount folder.

Worked example

List connected drives, their filesystem types, and current mount folders read-only:

$ lsblk -o NAME,RM,SIZE,FSTYPE,LABEL,MOUNTPOINTS

Drives with RM equal to 1 are removable media. Inspect full hardware and mount details for a specific device path with:

$ tam-drive-info /dev/sda

When finished copying files, leave any terminal shell pointing inside the drive (for example cd ~), then unmount cleanly from the Files eject icon or run udisksctl unmount -b /dev/sdX1 using your actual partition name.

Try it

Run lsblk -o NAME,RM,SIZE,MOUNTPOINTS in a terminal right now. Identify which drives are fixed internal storage (RM=0) and whether any removable storage (RM=1) is currently mounted.

If it goes wrong

Target is busy when unmounting
An open terminal, editor, or file window still uses a file or folder inside the drive. Close the file or cd back to ~, then unmount again.
Plugged-in drive shows no mount point
On a graphical session udiskie handles automounting; check lsblk -f to see whether a partition exists or requires unlocking (if encrypted).

Tamlinux launches udiskie --automount at desktop startup so removable drives mount automatically without requiring manual root commands.

Check yourself

Answer before revealing the explanation.

Why is unmounting safer than immediately unplugging a USB drive after copying finishes?

Unmounting flushes buffered writes out of memory onto the drive and marks the filesystem clean before power is cut.

What usually causes a “target is busy” error when unmounting?

A program still has a file open on the drive or a terminal's working directory is still inside the mount point.

Quoting decides whether a shell value becomes one argument or several, and whether a dollar sign starts an expansion.

One word, not many

A shell reads what you type and uses spaces to decide where one word ends and the next begins. Sometimes you want a space to stay inside a word, for example in the name My notes.txt. Quoting is the way to say that several characters belong together.

Type after the terminal prompt; do not type the dollar sign shown in examples. A missing closing quote leaves the shell waiting for more input. Ctrl+C cancels that unfinished line and returns you to a fresh prompt.

Why it matters

A filename with a space is one file. If the shell treats it as two words, the command looks for two files and fails.

How to think about it

Picture a parcel tied with string. The string is the quote: everything inside travels as one package, even when it contains spaces.

How it works

The shell recognizes quotes while it turns input into tokens. Quote characters remain part of the token during that stage, which is what tells later stages which characters came from literal text. Field splitting looks only at unquoted expansion results, and pathname expansion leaves quoted pattern characters alone. In the final quote-removal step the shell drops the quote characters themselves; what was quoted stays marked so the shell still knows it was literal.

Advanced usage

Edge cases

  • A newline after an unquoted backslash is removed before tokenization, so it cannot separate words.
  • Inside double quotes, a backslash is special only before dollar sign, backquote, backslash, newline or a double quote.
  • A quoted empty string still produces one empty argument; an unquoted empty expansion can disappear entirely.
  • A here-document with an unquoted delimiter performs expansions, while a quoted delimiter keeps the body literal.

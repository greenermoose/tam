Guide / Terminals and shells / Giving your computer written instructions / Keeping words together

This page shows how quotes keep several characters together as one word when you type instructions for a shell.

One word, not many

A shell reads what you type and uses spaces to decide where one word ends and the next begins. Sometimes you want a space to stay inside a word, for example in the name My notes.txt. Quoting is the way to say that several characters belong together.

Type after the terminal prompt; do not type the dollar sign shown in examples. A missing closing quote leaves the shell waiting for more input. Ctrl+C cancels that unfinished line and returns you to a fresh prompt.

Why it matters

A filename with a space is one file. If the shell treats it as two words, the command looks for two files and fails.

How to think about it

Picture a parcel tied with string. The string is the quote: everything inside travels as one package, even when it contains spaces.

New words

Choose the right quote

Goal: you will be able to keep a value containing spaces as a single argument.

Worked example

$ name='Quarterly Report.pdf'
$ printf '[%s]\n' $name
[Quarterly]
[Report.pdf]
$ printf '[%s]\n' "$name"
[Quarterly Report.pdf]
$ printf '[%s]\n' 'Quarterly Report.pdf'
[Quarterly Report.pdf]

Captured on Arch Linux, 2026-11-22. The format [%s] puts brackets around each argument, so you can count the arguments the command received.

What just happened

  1. The assignment stores one value with a space inside it.
  2. Unquoted $name expands, then word splitting divides the result into two arguments.
  3. Double quotes expand the variable but keep the result as one argument.
  4. Single quotes stop expansion too, so the literal text $name would stay literal.

Try it

a b a b Type: printf '%s\n' 'a b' Try printf '%s\n' 'a b' or printf '%s\n' a b.

If it goes wrong

The prompt changes to a continuation line
A quote is unfinished. Press Ctrl+C to cancel the line, then retype it with a matching closing quote.
The command reports two missing files
A value with spaces was left unquoted. Wrap the expansion in double quotes and try again.

Check yourself

Decide before revealing the explanation.

Why does "$name" give one argument while $name can give two?

Double quotes protect the expansion result from word splitting. Without quotes, the space inside the value is treated as a separator.

Which form prints a dollar sign followed by the letters name?

'$name'. Single quotes preserve every character literally; inside double quotes the dollar sign would start an expansion.

How it works

The shell recognizes quotes while it turns input into tokens. Quote characters remain part of the token during that stage, which is what tells later stages which characters came from literal text. Field splitting looks only at unquoted expansion results, and pathname expansion leaves quoted pattern characters alone. In the final quote-removal step the shell drops the quote characters themselves; what was quoted stays marked so the shell still knows it was literal.

Advanced usage

$ printf '[%s]\n' "${arr[@]}"
[a b]
[c]
$ printf '[%s]\n' "${arr[*]}"
[a b c]

Captured on Arch Linux, 2026-11-22, after arr=('a b' c). Double-quoted ${arr[@]} keeps each element as its own argument; ${arr[*]} joins them using the first character of IFS.

Edge cases

  • A newline after an unquoted backslash is removed before tokenization, so it cannot separate words.
  • Inside double quotes, a backslash is special only before dollar sign, backquote, backslash, newline or a double quote.
  • A quoted empty string still produces one empty argument; an unquoted empty expansion can disappear entirely.
  • A here-document with an unquoted delimiter performs expansions, while a quoted delimiter keeps the body literal.

Check yourself

Why can an unquoted asterisk in a variable match filenames even though the variable held only text?

Field splitting happens before pathname expansion. If splitting leaves an unquoted asterisk in a field, the next stage treats it as a pattern and expands it to matching filenames.

What does a backslash before a newline do, and why is that different from a quoted space?

It removes both characters before tokenization, joining the lines with no separator. A quoted space keeps a separator character inside a word, so the two operations are different.

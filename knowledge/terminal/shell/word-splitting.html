Guide / Terminals and shells / Giving your computer written instructions / IFS and splitting

IFS controls how unquoted shell expansions are split, and a non-whitespace separator can preserve empty fields.

A list of separators

IFS is a small list of characters stored by the shell. The shell uses the characters in that list as places where an unquoted value can be cut into pieces. The usual list contains a space, a tab and a new line. If you change the list to a comma, the shell cuts at commas instead.

This page records commands that were already run, so you can read it without typing anything. The dollar sign at the start of a line is a prompt, not part of the command.

Why it matters

Data often arrives with separators built in: a comma-separated line, a list of names on one line, or a filename with a space. IFS determines how the shell interprets those separators.

How to think about it

Picture a row of beads joined by different kinds of string. IFS tells the shell which string colour means “cut here”. Change the colour and the same row breaks in different places.

Check yourself

Why does comma preserve an empty field but a space not?

Runs of IFS whitespace collapse; non-whitespace separators terminate each field.

The splitting algorithm

Reference

IFS stateEffect on unquoted expansion
UnsetSplitting behaves as if IFS held space, tab and newline
Default whitespaceRuns of separators are collapsed; leading and trailing runs produce no empty fields
Non-whitespace character such as commaEach character terminates a field; adjacent separators can produce empty fields
Empty stringNo splitting, but a field made entirely from an empty expansion is removed
Mixed whitespace and other charactersEach kind follows its own rule above

How it works

The shell scans only the parts of a field that came from unquoted expansion. Literal characters from the original word stay attached to the candidate. An IFS whitespace character ends the current candidate and is discarded; more whitespace is skipped before a new candidate begins. A non-whitespace IFS character also ends the candidate, but it delimits a field even when the candidate is empty. At the end of the input, a non-empty candidate becomes a field. If no field was delimited at all, the result is zero fields rather than one empty field.

Advanced usage

Edge cases

  • Only space, tab and newline are always IFS whitespace; other locale whitespace is implementation-defined.
  • IFS is also used by read and by the unquoted expansion of *, so changing it affects more than command arguments.
  • A value containing bytes that are not valid characters gives unspecified results during field splitting.
  • NUL bytes cannot be stored in a shell variable or passed in an argument, so splitting cannot represent them.

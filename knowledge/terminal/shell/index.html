Guide / Terminals and shells / Giving your computer written instructions

From a terminal, you can give a shell written instructions and read its replies.

What is a terminal and a shell?

A terminal is a place to type instructions and read replies. A shell is the program that reads those instructions and decides what to do with them.

Think of the shell as a receptionist who takes your written request, hands it to the right office, and brings back the reply. Sometimes the reply channel is an ordinary result, and sometimes it is an error message.

Commands and streams

Goal: learn how to send commands and read results.

Hello, world!

The traditional first thing to do for any software engineer to do on a system is figure out how to get it to print "Hello, world!" Open the sandbox below and see if you can figure that out.

Welcome to the shell sandbox. Hello, world! Hello, world! Type: echo "Hello, world!" (or type help to see simulated commands). In this sandbox, try echo "Hello, world!" or ls.

The shell evaluates what you've typed after you press your Return key (which may be labeled Enter on your keyboard); the line below your command is its output.

What just happened

  1. You typed a command after the prompt.
  2. The shell looked for the echo program, found it, and started it with the argument Hello, world!.
  3. The echo program wrote Hello, world! to standard output, which appeared on your screen.

The standard streams

A program started by the shell usually has three standard streams:

0 — standard input (stdin)
Where the program reads input, usually from your terminal.
1 — standard output (stdout)
Where normal output goes, usually to your terminal screen.
2 — standard error (stderr)
Where messages about errors, warnings and progress go, separate from normal output.

A pipe (|) normally passes standard output to another program while error messages stay separate.

If it goes wrong

The terminal shows a continuation prompt
Check quotes and spacing. Ctrl+C cancels unfinished input; it does not undo commands that already ran.
You want to practice redirection
Redirection with > can overwrite a file. Practice only in a fresh temporary directory.

Check yourself

Which stream ordinarily carries diagnostics?

Standard error, stream 2, is separate from normal standard output.

Does the dollar sign in a sample need to be typed?

No. It represents a prompt; type the command after it.

Reference and system behavior

A shell parses command text, expands names and connects input and output streams before starting programs. Quoting and redirection therefore change what a command receives.

Emacs is a modeless editor whose named commands and key chords can be looked up, changed and extended while it runs.

One editor, many named commands

Emacs does not have an insert mode. Ordinary typing inserts text, and a key combination such as Ctrl + X followed by Ctrl + S runs a command. That command is not a secret code: it has a name, save-buffer, and you can run any command by typing its name instead of its shortcut.

The design is called modeless editing. vi asks which mode you are in; Emacs asks which command you want. Commands are ordinary functions written in Emacs Lisp, the programming language built into the editor. That is why Emacs can be a file editor, a Git interface, a mail client, a calendar, and a document authoring system without becoming several programs.

Why it matters

Emacs is a long-lived, self-documenting environment. It can tell you what a key does, show the documentation for a command, and let you change the behaviour while it runs. It is available on most operating systems, works in a terminal or a graphical window, and keeps the same editing model across them. For a reader who spends hours in text, that consistency is valuable.

How to think about it

Think of a workshop where every tool has a name and a labelled hook on the wall. You can learn the hook for the tools you use often, or ask for a tool by name. The workshop also contains a manual and a workshop for building new tools. The cost is that the wall is large: there are hundreds of commands, and no one knows them all. You do not have to.

New words

Modeless
An editor design in which typing inserts text and commands are separate actions, so there is no separate insert mode.
Buffer
The in-memory text Emacs is editing. A buffer may visit a file, or may exist only inside Emacs.
Keybinding
The association between a key or key sequence and a command. C-x C-s is the default binding for saving a buffer.
Meta key
The modifier written M- in Emacs documentation. On most keyboards it is Alt; on a terminal without a working Meta key, press Esc and then the next key.
Major mode
The mode that defines the main behaviour of a buffer, such as text mode, programming mode, or a specific language mode.

How it works

Emacs is a Lisp interpreter with an editor attached. A buffer holds text and has a major mode plus any number of minor modes. A key sequence is looked up in active keymaps, and the resulting binding names an interactive function. M-x bypasses the keymap and calls a function by name. Because the same mechanism is available to your own code, a configuration is a program, not a list of settings.

Init files are read in a documented order. Emacs looks for ~/.emacs.el, ~/.emacs, or ~/.emacs.d/init.el, in that order. It can also use the XDG location ~/.config/emacs/init.el, but the older locations win if they exist, so you must remove or rename them to move to the XDG path. early-init.el runs before the package system and the initial frame, which makes it the place for settings that must take effect before packages load. -q skips the init file; -Q adds no site file, no site Lisp, no X resources, and no splash screen. --batch implies -q but still loads site-start.el.

The package system is built in. package-archives names the archives; M-x list-packages shows what they offer; package-install installs into user-emacs-directory, usually ~/.emacs.d/elpa. The 31.1 package bundled use-package, which groups a package's configuration with its installation. Native compilation turns Emacs Lisp into .eln machine code; the load path for those files is derived from user-emacs-directory, and compilation can happen asynchronously in the background. A first start after a package change can therefore be slower than later starts.

For repeated use, a daemon keeps one Emacs process alive and emacsclient asks it to open a file. emacsclient -c creates a graphical frame, emacsclient -t creates a terminal frame, and emacsclient -n returns without waiting. The daemon calls server-start after initialization and opens no initial frame. This is the usual way to make Emacs feel as fast as a small editor while keeping one Lisp environment loaded.

Advanced usage

This batch script reads every file named on the command line and prints its line count. It is illustrative, not an exercise. Save it as count-lines.el and run it with emacs --script count-lines.el FILE....

--script runs in batch mode and ignores file-local variables in the script, which is a safety property: a downloaded script cannot change Emacs settings before its code runs. command-line-args-left holds the remaining arguments after Emacs has consumed its own options. with-temp-buffer keeps the work out of your visible buffers.

Edge cases

  • File-local variables can execute code. A file can end with a local-variables block that sets variables or evaluates an expression. Emacs asks before applying unsafe values, but the prompt is a security boundary. Read it; do not approve a block you do not understand. In batch mode there is no one to ask, so Emacs assumes "no".
  • A daemon outlives the terminal. If the daemon was started with an old environment, emacsclient inherits that environment rather than your current shell's. Restart the daemon after changing PATH or language settings, or start clients with the environment they need.
  • emacsclient without a server. The client waits by default. -a "" starts a new Emacs when no server exists; -n returns immediately. In a script, an unconditional wait can hang a job.
  • Native compilation and stale .eln files. A package upgrade can leave compiled files that no longer match their source. Emacs usually recompiles in the background, but startup warnings about a missing or outdated .eln mean the cache needs attention. Do not delete the whole cache as a first step; read the warning.
  • Huge buffers and long lines. Emacs is fast on ordinary source files but slow on a single multi-megabyte line, especially with font locking and syntax highlighting enabled. so-long-mode exists for this case. A terminal editor has the same problem for a different reason: the display must redraw the line.
  • Batch failures and exit status. A Lisp error in batch mode prints a backtrace and exits nonzero. Check the status in the calling script; a successful exit means the forms completed, not that they did what you intended.
  • Killing Emacs does not save buffers. C-x C-c asks; kill-emacs from Lisp and a signal do not. Auto-save and recovery files are a safety net, not a substitute for saving or version control.

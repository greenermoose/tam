Understanding the whole system

This page shows how the parts of a Tamlinux computer fit together, from the physical machine up to the apps on your screen.

Meet your computer, layer by layer

A modern computer can look like a giant tangle of unfamiliar names—kernels, compositors, shells, packages. Underneath, though, it is organized in clean, friendly layers, where each layer has one clear job and hands work off to the next.

Why it matters

When you know which layer does what, your computer stops feeling like a black box. Want to change how windows look? You know to look at the desktop layer. Want to free up disk space or update software? You know that belongs to the package and system layers. Nothing stays mysterious for long.

How to think about it

Tamlinux uses a simple botanical analogy (see Botanical analogy used in Tamlinux). Think of your physical computer as the host. The base operating system installed on that host (such as Arch Linux, Void Linux, Windows, or macOS) is the rootstock. The initial, minimal Tamlinux package installed on the rootstock is the bud, which you use to grow the rest of the Tamlinux scion—the Tamlinux software that runs on top. Each major + minor version of Tamlinux (such as 0.6 or 0.7) is a cultivar, and the everyday apps you use to work, learn, and build with your family are the fruit.

New words

Operating system
The core software that manages your computer's hardware and lets you run programs.
Kernel
The central piece of the operating system that talks directly to hardware and shares memory and processor time.
Rootstock
Tamlinux's name for the base operating system (today Arch Linux) installed on a host.
Scion
Tamlinux's own software layered on top of the rootstock to make the workstation fast, keyboard-friendly, and pleasant.
Cultivar
A major + minor version of Tamlinux (such as 0.6 KBN WB), named from tamarack tree varieties.
Compositor
The program that arranges windows and draws them onto your display.
Shell
A program that reads your typed commands and runs them for you.

The Tamlinux stack and its choices

Goal: you will be able to trace how Tamlinux's current and planned components fit together and inspect what is running on your own machine.

If you have used Linux before, the quickest way to orient yourself is to see which tools Tamlinux picks today—and where it plans to go next. Tamlinux is not a separate distribution built from scratch; it is a curated workstation scion installed onto a lean rootstock.

Why these choices?

Tamlinux follows a "1 way to do 15 things" rule: instead of handing you ten terminals and five shells to configure yourself, it picks one fast, reliable default for each job so you can get to work without falling into the fiddling trap. It also avoids unnecessary background polling loops, keeps documentation available offline in tam, and uses human-supervised AI assistance to build and test tools cleanly. Worked example

You can ask tam inspect to report the layers it sees on your machine right now without changing a single file:

$ tam inspect
Host Information:
  Operating system:  Arch Linux (rolling)
  Kernel release:    7.2.11-arch1-1.1
  Architecture:      x86_64
  Tamlinux cultivar: KBN WB 0.6.30

Installation Capabilities:
  Init system:       unknown
  Package tools:     pacman, mise
  Privilege tool:    pkexec, sudo
  Root filesystem:   tmpfs
  Graphics device:   /dev/dri/card1 (available)

Captured on a Tamlinux system, 2026-11-18; your exact kernel, cultivar, and filesystem lines vary by machine.

Try it

Open a terminal and run tam inspect. Match each line it prints—operating system, kernel release, package tools, and graphics device—to the layers in the table above. Because tam inspect is read-only, it is completely safe to run anytime.

If it goes wrong

tam: command not found
The shell could not find the command. Check with command -v tam; if it prints nothing, tam is not installed or its directory is not on your PATH.
The report differs from the capture above
That is expected. Each line describes the machine you are using, so compare the labels and their order rather than the exact values.
A line reads unknown, unavailable or not deployed
The inspection reports only what it can detect on this host. Keep the line as evidence and use the other rows to place it in the stack; nothing was changed.

Check yourself

Decide your answer before you reveal it.

In Tamlinux, what is the difference between the rootstock and the scion?

The rootstock is the base OS (today Arch Linux) installed on the host. The scion is Tamlinux's own software layered on top—its commands, desktop configuration, plugins, and the tam guide.

Why does Tamlinux list Void Linux and Sway as "planned" rather than current?

Today's working Tamlinux workstation runs on Arch Linux with Hyprland and Quickshell. Void Linux (with runit) and Sway are documented target migrations, not what is running on a current Arch-based host.

Architecture, boundaries, and ownership

Component boundaries

Tamlinux separates third-party base packaging, product source repositories, and deployed workstation assemblies so updates stay reproducible and rollback-safe:

BoundaryResponsibilityAuthoritative reference
Rootstock & carried patchesUpstream Arch packages plus minimal local fixes published on public forks and retired automatically when upstream ships them.Carried patches
Scion sourceProduct code across tamlinux (commands/, desktop/, desktop/plugins/fred.*), tam (C11 reader + HTML corpus), and tamlinux-tools (standalone utilities).The tam command
Recorded assembliesTest and Run use a recorded candidate delivery built from pinned Git commits. Development builds can be installed separately for local trials.Source-install delivery records in tamlinux-packages
User configurationPersonal overrides live under ~/.config/ following XDG standards, separate from packaged defaults.Philosophy and principles

Design invariants

  • Zero-polling efficiency: prefer event-driven protocols and on-demand CLI tools over permanent background daemons.
  • C11 for core native tools: deterministic builds, AddressSanitizer verification, and minimal runtime overhead (Language choices).
  • Stage discipline: candidate builds move through Develop, Test, Run, and Release only on the developer's explicit instruction.

Check yourself

Why does Tamlinux separate the rootstock from the scion instead of maintaining a full custom Linux distribution?

Keeping the rootstock minimal and third-party lets Tamlinux rely on upstream kernels, drivers, and security updates while concentrating its own engineering on ergonomic tools, C11 utilities, and desktop polish—making future rootstock transitions (such as Arch to Void) tractable without rewriting the entire OS.

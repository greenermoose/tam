Session and desktop

These readings follow sign-in from a text console to a graphical desktop and back.

Stage 1: Consoles and login

TTYs and virtual consoles, then display managers as the optional or historical greeter model. Current cultivars: text login, then tam-desktop.

Check yourself

On console-first Tamlinux, when does the graphical desktop start?

When you run tam-desktop (or an equivalent documented launcher), not automatically at greeter time.

Stage 2: Compositor

Compositors and the desktop.

Check yourself

Which compositor does Tamlinux run today?

Hyprland. Sway is planned.

Stage 3: Input

evdev and the Meta key.

Check yourself

If keys work on a VT but not in the GUI, where is the fault more likely?

In the graphical input path (compositor, seat, libinput) rather than the physical keyboard alone.

Stage 4: Everyday devices

touchpad and shortcuts, sound devices, and Bluetooth devices.

Check yourself

Which command prints the current audio output sink?

tam-audio-output-sink. The audio panel is Meta + Ctrl + A.

Capstone

Write the shortest recovery note for "GUI frozen, keyboard dead in GUI": VT chord, what you will record, what you will not restart yet.

Use Ctrl+Alt+Fn to reach a text console. Record time, last action, whether VTs accept input, and whether tam-desktop or the compositor process is alive. Do not restart display managers as a first guess; collect evidence first.

From gates to machine code

These readings follow bits from logic gates up to the instructions a CPU runs.

Finish From atoms to bits first if digital logic is new.

Stage 1: Architecture

Computer architecture: name CPU, memory and buses.

Check yourself

Why separate memory from the CPU in the basic model?

Programs and data live in memory; the CPU fetches and operates on them over interconnects. Mixing the roles hides latency and failure boundaries.

Stage 2: Instruction cycle

Instruction cycle: fetch, decode and execute.

Check yourself

What does fetch retrieve?

The next instruction (and related fetch traffic) from memory into the processor pipeline.

Stage 3: Assembly

Assembly: read a human-facing view of machine instructions.

Check yourself

Is assembly the same as the high-level language you write daily?

No. Assembly is close to the machine encoding; compilers translate higher languages into it or into machine code.

Capstone

Take one simple command such as printing a line in a terminal and name the layers from logic gates to a running process without claiming you traced every gate on your CPU.

Gates form functional units; the architecture organizes those units and memory; the instruction cycle runs encoded operations; assembly or machine code is what the CPU executes; the kernel loads and schedules the process that issues the write. Your evidence at the workstation is the process and syscall boundary, not a gate-level probe.

How software runs

These readings follow a program from the kernel up through filesystems and services.

Stage 1: Kernel and process

Kernel and processes: syscalls, drivers and PIDs.

Check yourself

What sits between a normal program and a hardware device?

Usually a syscall into the kernel and then a driver path.

Stage 2: Filesystems

Filesystems that keep state: disks, Btrfs and recovery domains.

Check yourself

Name two recovery domains that are not the same.

Filesystem snapshots and Home Manager generations are different; mutable documents may be a third.

Stage 3: Init and boot context

Init and services and Boot phases: who starts services after the kernel.

Check yourself

Which init runs on current Arch-based Tamlinux?

systemd. Runit is planned for a future rootstock.

Stage 4: Delivery and ownership

Package versions: follow a source revision through the delivered package to the process that is actually running.

Check yourself

Does a source commit prove what the running command contains?

No. Resolve the executable's owner and version, then inspect a running process separately.

Capstone

Pick tam --version. Name the process, the package/delivery story you would check next, and one service you would not blame without evidence.

The command runs as your user process. Next evidence is path resolution and assembly or package ownership (package versions). Do not restart unrelated system units because a version string looks odd.

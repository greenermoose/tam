First steps

Gain: you will be able to open a terminal, try a small file task and return to the Guide without changing system settings.

For you if: you have never used a terminal, or know one on another system and want a safe first task here. You can leave answers closed until you have tried each question.

Levels: starts before Beginner and reaches level 1; allow about three short reading sessions, pausing after any checkpoint.

Stage 1: Open a terminal and type a command

  1. Read the desktop keys on Welcome. On the Tamlinux Hyprland desktop, SUPER+RETURN opens a terminal. SUPER is often the key with a Windows logo.
  2. Read Shell and streams, then return here using Left Arrow in the pager.

A prompt is the terminal text waiting for your command. Examples below use $ for it; your prompt may look different. Type only the text after it, then press Enter.

$ printf '%s\n' hello
hello

Captured on Arch Linux, 2026-10-21. A command is different from its output: do not type hello again as a command.

To paste into the terminal, use Tamlinux's SUPER+V shortcut. Read a command before pasting; pasted newlines may execute commands immediately. For this first task, type the short line yourself. Ctrl+C cancels unfinished input or interrupts a foreground command; it does not undo completed work.

Check yourself

Answer before revealing the explanation.

Which text do you type: the leading dollar sign, the printf command, or the output hello?

Type only the printf command and press Enter. The dollar sign represents the prompt; hello is the result. Reread Stage 1 if these are easy to confuse.

Stage 2: Make one safe file

  1. Read Filesystem basics for names and directories.
  2. Work through File permissions in its fresh temporary directory. The New to this? fold explains the small steps. Finish that exercise's cleanup before returning here.

Check yourself

Answer before revealing the explanation.

chmod prints nothing. What do you do before assuming failure?

Inspect the mode with stat, as in the permissions page. Many successful commands print nothing. An error message needs attention; silence alone is not failure.

Stage 3: Connect two commands

  1. Read Pipelines.
  2. Predict its count, run the fixed-input example, and try the pear variation.

Check yourself

Answer before revealing the explanation.

Why can you predict this example more reliably than counting a running application?

The example supplies the same three lines every time. Running applications change, and a process-search command can match itself. Return to the pipeline worked example if needed.

Stage 4: Find your way back

  1. Read Using the Guide.
  2. In the pager, press the backtick key to open the Guide index. Use ] to select a link and Enter to follow it. Left Arrow goes back.
  3. Press Esc to return to the terminal. Type tam welcome and press Enter to open Welcome again.

Check yourself

Answer before revealing the explanation.

Which action leaves tam, and which returns to the Guide index while keeping tam open?

Esc leaves tam for the terminal. The backtick key opens the Guide index inside the pager. You can reopen the welcome page with tam welcome.

Capstone: Make and inspect a tiny report

In a fresh temporary directory, create colours.txt with red, blue, red on separate lines. Count whole lines equal to red. Create ready.txt containing ready and make it readable and writable only by you. Inspect its numeric mode. Remove these two files and the temporary directory when done, then reopen Welcome and find this path again.

For this section, make a new temporary directory and enter it. These commands print nothing when they succeed. Keep this terminal open while you work through the section.

work=$(mktemp -d)
cd "$work"

$ printf '%s\n' red blue red > colours.txt
$ grep '^red$' colours.txt | wc -l
$ printf '%s\n' ready > ready.txt
$ chmod 600 ready.txt
$ stat -c '%a %n' ready.txt
2
600 ready.txt

Captured on Arch Linux, 2026-10-21. The count is 2 and the file mode is 600. These verify different things: stream filtering and file access.

rm -- colours.txt ready.txt
cd /tmp
rmdir -- "$work"

In a separate terminal command, run tam welcome, select Paths by Goal, then First steps. If your result differed, return to the pipeline or permissions example before trying again.

These readings help you become more confident giving your computer written instructions.

What does a pipe pass?

The printed byte stream, not a filename or an argument list.

Stage 2: Control access

  1. Permissions: make only your scratch script executable.

Check yourself

Decide before revealing the explanation.

Why use u+x rather than a+x for a private script?

u changes only the owner class; a requests all classes. Grant only the access the task needs.

Stage 3: Manage the task

  1. Jobs and signals: complete the owned-child example before changing signals.
  2. Jobs and signals: wait for or signal only a child you started.

Why avoid a name-wide kill in this exercise?

It can include unrelated processes. Save the child PID and use its lifecycle evidence.

A final counter succeeds after a producer failure. What evidence is missing?

Inspect the producer status and stderr. Default last-command status does not prove every stage succeeded.

Capstone

In a scratch directory, create a three-line red/blue/red input, write a private executable report script that counts red lines in its file argument, start it in the background, wait for that child, then inspect its report and mode. Remove only your exercise files.

Make and enter a fresh temporary directory for this capstone.

work=$(mktemp -d)
cd "$work"
$ printf '%s\n' red blue red > colours.txt
$ printf '%s\n' '#!/bin/sh' 'grep "^red$" "$1" | wc -l' > report.sh
$ chmod 700 report.sh
$ ./report.sh colours.txt > count.txt &
$ report=$!
$ wait "$report"
$ cat count.txt
$ stat -c '%a %n' report.sh
2
700 report.sh

Captured on Arch Linux, 2026-10-21. The report contains 2 and the script mode is 700. wait connects the readback to this shell's completed report task. This demo assumes the readable fixed input you created. A general-purpose report must also handle input errors; successful wc alone does not establish producer success.

rm -- colours.txt report.sh count.txt
cd /tmp
rmdir -- "$work"

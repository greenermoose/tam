Display and GPU

These readings explain how images reach your eyes and how to separate a cable fault from a software fault.

Stage 1: Graphics ideas

Computer graphics and GPU architecture: frames, pixels and accelerators.

Check yourself

What is a framebuffer for?

It holds pixel values that a display path reads to light the panel.

Stage 2: Cables and history

Display cables and Display history: HDMI, DisplayPort and why standards matter.

Check yourself

Does a lit panel prove the compositor is healthy?

No. Firmware or a static image can light a panel. Check session and compositor evidence separately.

Stage 3: Desktop boundary

Compositors and the Tamlinux desktop: Wayland roles and recovery to a VT.

Check yourself

Which key chord moves to a text virtual console for recovery?

Ctrl + Alt + Fn (for example Ctrl + Alt + F2), then work from the text login or shell. Exact VT numbers depend on the installation.

Capstone

Write a blank-screen checklist with four layers: power/panel, cable/protocol, GPU/DRM, compositor/session. Mark each check as read-only.

Power/panel: is the monitor powered and input selected? Cable/protocol: reseat or try a known-good cable/port; note HDMI vs DisplayPort. GPU/DRM: from a VT, inspect connector state with documented read-only tools. Compositor/session: is the session alive; does tam-desktop apply; can you reach a VT? Do not restart display services as a first guess.

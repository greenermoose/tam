Understand the design

These readings explain how the parts of Tamlinux fit together.

Rootstock is not a common term, but one that Fred Horch, the Tamlinux developer, made up to explain how Tamlinux works: it is the kernel and core system software on which the Tamlinux cultivar is installed. The cultivar is all the software in the Tamlinux release that allows the computer to be used effectively and efficiently by both humans and AI agents. Fred defines the rootstock to be the set of software that third-parties publish and is necessary to be installed so that the software we write can function properly. Our goal is to minimize the size of the rootstock and maximize its speed and efficiency. Currently we are using Arch Linux as our rootstock but we plan to migrate to Void Linux in future versions of Tamlinux. Beyond that we are considering a microkernel to further reduce the code size of the rootstock and improve its performance per watt.

Check yourself

Does a source commit alone prove what is running?

No. Establish the selected package and runtime as separate evidence.

Stage 3: Trace login and session

Trace login and session: Compare authentication, session launch and desktop startup, including the text-login route.

Check yourself

Does successful authentication prove the desktop is working?

No. Authentication, session launch and rendering have separate failure boundaries.

Capstone

Explain where you would investigate a changed application setting, a missing native service and an unexpected command version. Name the evidence you would seek without changing the system.

For a changed theme, first identify the active user configuration and its previous value. For a missing system service, inspect its unit and system journal. For a command version, resolve the executable path and identify its package; inspect a running process separately. A user-generation rollback need not restore mutable files.

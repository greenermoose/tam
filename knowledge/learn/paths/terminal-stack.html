Terminal stack

This path follows one character from a program to the pixels on screen: terminfo capabilities, ncurses drawing, font selection, colour themes, and the Lua configuration that ties the desktop together. It suits readers who are already comfortable typing commands.

The examples read state and change only a variable inside one command. Editing your desktop configuration is a separate, reversible task for the last stage.

Stage 1: How a terminal draws text

  1. How terminals display text — escape sequences, TERM, terminfo, tput and infocmp.
  2. ncurses — the virtual screen, wide-character support, and how tam links it.

Checkpoint

Answer these before you go on.

What does a full-screen program look up from terminfo?

The cursor, colour and screen-control escape sequences for the terminal named by TERM. If the name and the real terminal disagree, the program emits the wrong control bytes.

Why does tam link libncursesw rather than the narrow ncurses library?

The wide-character library handles Unicode text and cell widths correctly. The narrow library is not enough for the guide's content.

Which command reports the font Fontconfig picks for monospace?

fc-match monospace. Add -f "%{file}: %{family}\n" when you need the file path and family together.

Where does the current theme link point?

~/.local/state/tamlinux/current/theme, which points at an isolated, timestamped generation. Switching themes swaps that link atomically rather than editing files one by one.

Checkpoint

Answer these before you go on.

Which file is the desktop's Lua entry point?

~/.config/hypr/hyprland.lua. It prepares module paths and loads the packaged baseline plus your bindings and monitor files.

Does hyprctl repl change the configuration on disk?

No. It evaluates Lua in the running compositor. A durable change belongs in a configuration file with a written undo step.

Capstone: Diagnose a terminal that refuses to start

A full-screen program prints unknown terminal type and exits. Work out whether the program, the terminal emulator or the environment is wrong, using only read-only queries and a variable that lasts for one command.

Start by recording what the shell advertises, then ask the terminfo database whether it agrees. The demonstration below sets TERM only for the command that follows, so your session is unchanged afterwards.

$ printenv TERM
xterm-256color
$ infocmp >/dev/null; echo "infocmp exit=$?"
infocmp exit=0
$ TERM=definitely-not-a-terminal tput cols
tput: unknown terminal "definitely-not-a-terminal"
$ TERM=definitely-not-a-terminal clear
'definitely-not-a-terminal': unknown terminal type.

Captured on Arch Linux, 2026-11-13. tput exits 3 and clear exits 1 for an unknown name. The database is healthy because infocmp succeeded for the real TERM; the failure follows the name you supplied.

  1. printenv TERM shows the name the program will query.
  2. infocmp compares that name with the installed terminfo database. A match means the database entry exists.
  3. The failing command changes only its own environment. If the error follows the changed name, the name is the problem, not the program.
  4. Restore the real value and confirm: TERM=xterm-256color tput cols prints your width, for example 80.

If the real TERM also fails infocmp, the entry is missing or the database path is wrong; that is a package question, not a configuration typo. Do not "fix" it by exporting a random terminal name in your shell startup file.

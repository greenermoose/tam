Cryptography and quantum safety

This path takes you from zero prior technical knowledge—assuming only junior-high math and science—through modern ciphers, SHA hashes, public-key math, and post-quantum cryptography.

If any page feels too advanced, step back one stop along the path until the terms feel familiar. Every exercise uses read-only commands or temporary scratch directories.

Stage 1: Foundations and randomness

  1. Foundations of Cryptography — Kerckhoffs's principle, clock arithmetic, randomness, and formal security games.

Checkpoint

Answer these before you go on.

Why does modern cryptography publish its algorithms instead of keeping them secret?

By Kerckhoffs's principle, security rests solely on keeping the key secret so public scrutiny can find flaws and keys can be rotated easily.

Stage 2: Symmetric encryption and AEAD

  1. Symmetric Cryptography and Authenticated Encryption — shared-key ciphers, AES, ChaCha20, nonces, and tamper-evident AEAD.

Checkpoint

Answer these before you go on.

What happens if you reuse the same (Key, Nonce) pair in AES-GCM?

Reusing a nonce leaks the XOR of plaintexts and allows an attacker to recover the GHASH authentication key and forge future tags.

Stage 3: Cryptographic hashes, SHA, and KDFs

  1. Cryptographic Hash Functions, SHA, HMAC, and Key Derivation — digital fingerprints, SHA-256 vs. SHA-3, HMAC, and Argon2id.

Checkpoint

Answer these before you go on.

Why can a fast hash like SHA-256 check a file download safely yet still be unsafe for storing user passwords?

Attackers can test billions of password guesses per second against fast hashes; password storage needs salted, memory-hard KDFs like Argon2id or yescrypt.

Stage 4: Public-key cryptography and PKI

  1. Public-Key Cryptography, Elliptic Curves, and PKI — Diffie-Hellman, RSA, Curve25519/Ed25519 signatures, and X.509 certificates.

Checkpoint

Answer these before you go on.

What binds a website's domain name to its public key in HTTPS?

An X.509 certificate signed by a trusted Certificate Authority (and publicly logged in Certificate Transparency).

Stage 5: Quantum computing and quantum-safe algorithms

  1. Quantum Computing and Quantum-Safe Cryptography — Shor's and Grover's algorithms, Harvest Now Decrypt Later, ML-KEM, ML-DSA, and SLH-DSA.

Checkpoint

Answer these before you go on.

Why do quantum computers break RSA and ECC in polynomial time while AES-256 remains safe?

Shor's algorithm uses the Quantum Fourier Transform to solve factoring and discrete logarithms exponentially faster, whereas Grover's algorithm only halves the effective bit-strength of unstructured symmetric search (leaving AES-256 at ~128-bit quantum security).

Capstone: Audit your workstation's cryptographic primitives, read-only

Verify that your workstation's OpenSSL and OpenSSH tools provide modern AEAD ciphers, SHA-2/SHA-3 hashes, Ed25519 signatures, and post-quantum hybrid key exchange without changing any system file.

Run these read-only checks in a terminal:

$ printf 'tamlinux' | sha256sum
$ openssl ciphers -v -s -tls1_3
$ openssl list -kem-algorithms | grep -iE 'ml-?kem'
$ ssh -G localhost | grep '^kexalgorithms'

Confirm that TLS 1.3 offers only AEAD suites, OpenSSL lists ML-KEM-768 and X25519MLKEM768, and OpenSSH prefers mlkem768x25519-sha256 / sntrup761x25519-sha512 ahead of classical-only ECDH.

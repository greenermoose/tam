Safe practice and self-checks

This page helps you practice using your computer without changing its system settings.

Practice without system changes

Goal: navigate the Guide and connect commands using a temporary file.

Why it matters: A scratch directory gives the exercise a separate place to write.

Before you start: The pipeline exercise writes only its newly created temporary directory.

New to this? Start in the Guide; follow links with the reader and press Left Arrow to return through history. At a terminal, do not type a leading dollar sign shown as a prompt.

Worked example

Follow the pipeline exercise below as a complete block. Its two counts show one apple and two pears; the directory is removed only when empty.

Use temporary files in a directory you own. These exercises read or change only that scratch directory; they do not require privilege, package changes, boot changes, or recovery actions.

Exercise: navigate documentation

  1. Open Guide Search and search for streams.
  2. Open a result and follow its breadcrumb parent.
  3. Open Man pages, look up printf, then press Left Arrow.

Check: you can name which action returned through history and which key opens the Guide root. Hint: history and Guide are separate actions.

Exercise: a pipeline in a temporary directory

A directory holds files. This exercise creates a temporary one and a file inside it. A pipeline passes one command's output to another. Type or paste the whole block into a shell, then press Enter.

if scratch=$(mktemp -d); then
    printf '%s\n' pear apple pear > "$scratch/fruit.txt"
    sort "$scratch/fruit.txt" | uniq -c
    rm -- "$scratch/fruit.txt"
    rmdir -- "$scratch"
else
    printf '%s\n' 'Could not create a temporary directory.'
fi

mktemp -d creates a new directory and puts its name in scratch. The quotes keep that name together if it contains spaces. The if runs the exercise only if creation succeeds. Expect one apple and two pears; spacing can vary.

Cleanup removes the named file, then rmdir removes the directory only if it is empty. If cleanup reports an error, read it and inspect the directory before deciding what to remove. Do not use recursive removal to clear unexpected contents.

Check: explain which command reads the file, which sorts its lines, and why uniq follows sort. If the output differs, check the commands you entered and try again.

If it goes wrong

If temporary-directory creation or cleanup fails, read the message and inspect the named directory before deciding what to remove.

Check yourself

Why does the exercise remove a named file before using rmdir?

The file is the known exercise output; rmdir then refuses to remove a directory with unexpected contents.

What should you do when a result differs from the example?

Read the result and the relevant documentation, then check the input and prerequisites before changing anything.

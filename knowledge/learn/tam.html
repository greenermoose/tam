Using the tam guide command

This page explains how to find and read information in the Tamlinux guide.

Find a guide entry

Goal: choose a tam entry point and navigate back to the Guide.

Why it matters: A search, a manual and a guide page serve different needs.

Before you start: The example displays help without changing files.

New to this? Start in the Guide; follow links with the reader and press Left Arrow to return through history. At a terminal, do not type a leading dollar sign shown as a prompt.

Worked example

At a terminal, run tam --help. On an Arch Linux workstation on 2026-10-27, its first line was "tam - the Tamlinux command". Your installed version may differ.

The tam command includes offline guide and documentation readers. Use this page to choose an entry point; implementation and development details remain in The tam command.

Open and find material

  • tam show opens the guide root.
  • tam show shell/pipelines?level=beginner opens a topic at a supported depth.
  • tam search "permissions" searches the guide; in the reader choose Search to enter a query.
  • tam explain --level expert lists topics with that depth.

Use references

Open tldr pages for concise command examples, Man pages to find an installed manual by name, section, or keyword, and tam info to open the installed Info directory. The documentation lesson explains how to move among Guide, tldr, Man, and Info while keeping history.

Return to the guide with the backtick key. Press ? for help and q to leave the reader. See safe practice to try these actions without changing system state.

Try it

Open tam show and follow one link, then press Left Arrow.

If it goes wrong

If tam is not found, check whether it is installed and which command path your shell uses; do not install a copy just to complete this lesson.

Check yourself

Does tam search execute the commands it finds?

No. It searches guide content; reading a result is separate from executing an example.

What should you do when a result differs from the example?

Read the result and the relevant documentation, then check the input and prerequisites before changing anything.

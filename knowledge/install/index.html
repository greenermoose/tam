Guide / Installing and maintaining Tamlinux

Installing and maintaining Tamlinux

Tamlinux keeps your software and your settings in clear, layered pieces so that each can be understood and reversed on its own.

The installation framework

The installation framework is designed as a four-step lifecycle. Only the first step works today; the other three are planned and print "not implemented yet":

  1. Inspect: tam inspect checks host facts, architecture, package tools, and supported profiles without changing anything.
  2. Plan (planned): tam install plan will print the planned changes without modifying the system.
  3. Apply (planned): tam install apply will apply a reviewed installation plan.
  4. Verify (planned): tam install verify will verify installed components and desktop integration.

tam install on its own shows this overview and the planned commands.

The layers

  1. The base system, managed by the distribution package manager.
  2. User command-line tools, which can be updated independently.
  3. Desktop shell plugins, each with its own version and release.

Staying healthy

Before a big change, take a snapshot so you can return to a known-good state. tam inspect gathers host facts and recognized capabilities before any installation work begins, while tam check evaluates system health findings against the Check Contract. See Snapshots and generation rollbacks and Non-disruptive updates.

Recovery and diagnostics

If something goes wrong, read the diagnostics first. A truthful error message is more useful than a guess. Learn how to inspect logs in Truthful system diagnostics and logs, manage system power in The progressive power ladder, and recover from freezes in Emergency disaster recovery.

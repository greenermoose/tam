Guide / Systems and administration / Mobile communications / Texting and instant messaging / Internet messaging apps

An internet messaging app sends words over a data connection instead of through the carrier's text service. The app provider keeps the conversation, the account and the delivery records, while the phone's operating system helps wake the app when something arrives.

Chat over data

Some messages travel through the mobile network's text service. Others travel through the internet like a web page or a video. Apps that do this are called OTT (Over-The-Top) services: they run on top of the network rather than inside the carrier's messaging system.

Why it matters

Internet apps can add read receipts, typing indicators, group chats, stickers and sync across several devices. They can also work on Wi-Fi, because they use data rather than a phone number route.

How to think about it

Think of two ways to send a note across town. A carrier text is like handing the note to the postal service. An internet app is like uploading the note to a shared noticeboard that both people visit.

New words

Instant messaging
Chat that appears on a screen while both people are using the service.
Push notification
A small alert that tells an app to check for something new.
Account
The identity the app provider uses to decide which chats belong to a person.
Sync
Copying conversation state between a person's devices.

If it goes wrong

You assumed the push alert always contains the message.
Push services are best treated as small wake-up notices. The app usually fetches the encrypted conversation from its provider afterwards.
You expected the phone number to authenticate the person.
A phone number can be an address used for discovery. Real account security depends on how the provider binds that number to a credential.

Check yourself

Decide your answer before you reveal it.

Why might a lock-screen preview reveal a message even when the chat uses end-to-end encryption?

The notification is generated by the app or operating system for display before the reader unlocks the app. Encryption in transit does not prevent a trusted device from showing a preview on screen.

What does sync across devices add to the security question?

Each device must receive keys or plaintext, and backups may hold conversation history. More devices and backups mean more places where protection depends on account security.

How it works

A centralised app provider stores account records, contact graphs, conversation state and device push tokens. The operating system's push service wakes the app; the app then opens a transport to its provider, typically protected by TLS, and reads the conversation. Apple's APNs documentation and Firebase Cloud Messaging documentation describe the push side. XMPP is specified in RFC 6120 and RFC 6121; the Matrix specification defines another federated model. Federation moves trust across servers; it does not automatically make content private or make every server behave alike.

Edge cases

  • Contact discovery that uploads phone numbers can expose a person's social graph to the provider. Hashing numbers does not by itself make discovery private, because the number space is small enough to enumerate.
  • Push notifications may be delayed or suppressed by the operating system. A delivery receipt inside the app is a different signal from a push confirmation.
  • Cloud backups, linked devices and session restoration each add a place where ciphertext, keys or plaintext can be stored. Threat models must name those places explicitly.
  • A central provider can change visibility, retention and interoperability rules without changing the app's visible conversation layout.

Check yourself

Why does a federated chat network solve a different problem from end-to-end encryption?

Federation answers who may run a server and exchange messages. Encryption answers who can read the content. A federated network can have weak encryption, and a centralised service can have strong content encryption while still learning metadata.

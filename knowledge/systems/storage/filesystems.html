Kernel and processes

What does a filesystem keep?

A filesystem is the structure an operating system uses to turn raw storage blocks on a drive into named files, folders, permissions, and—on filesystems like Btrfs—snapshots.

Why it matters

Updates, backups, and mistakes are much safer when you know which files live on which filesystem or subvolume, because recovery boundaries follow those divisions.

How to think about it

Think of a blank drive like an empty warehouse and a filesystem like the shelving, aisle labels, and inventory catalog that let the computer find any document by name and keep separate rooms for system files and personal files.

New words

Btrfs
A modern Linux filesystem that supports copy-on-write subvolumes and snapshots.
Filesystem
The rules and structures that organize raw disk space into named files and directories.

Check yourself

Does a Btrfs snapshot always restore a document you edited today?

No. Snapshots cover configured subvolumes at taken times. Mutable files outside that boundary need their own backup story.

Checksums, CoW and evidence

Btrfs copy-on-write snapshots and checksums change failure modes: bitrot detection and cheap snapshot creation trade against free-space and balance concerns. Before rollback, inventory Snapper checkpoints and confirm the subvolume layout. Never treat teaching snapshot IDs as live identifiers.

Check yourself

Why record the subvolume and checkpoint ID before a rollback?

Rollback is targeted. The wrong subvolume or ID can discard the wrong state or miss the intended recovery point.

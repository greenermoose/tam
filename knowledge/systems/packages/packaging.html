How software is delivered

This page explains how software is collected, installed, and updated in Tamlinux.

Before this

System Maintenance and Reliability

Different tools manage different parts of the software. This page explains where each part comes from and how Tamlinux records what it installs.

How is Tamlinux software packaged?

Software on Tamlinux comes from two clear layers: the underlying rootstock's native package manager (currently pacman on Arch Linux) installs ecosystem software, while Tamlinux's own bespoke programs and desktop files are built and installed cleanly from pinned Git source repositories.

Why it matters

Before reporting a bug or planning an update, you need to know which layer owns a program and which exact version is installed. Read-only package queries let you inspect installed software safely without changing anything or needing administrator privileges.

How to think about it

Think of a package manager as a shipping clerk who keeps an exact manifest of every box delivered to the building: asking the clerk “what version is in box X?” only reads the clipboard and never moves a single crate.

New words

Package
A named archive of program files, libraries, and metadata tracked by a package manager.
Upstream
The original authors and repository of an open-source software project.
Query
A read-only check that inspects package records without changing the system.

Query installed packages safely

Goal: you will be able to query an installed package's version and metadata with the native package manager without modifying any system packages.

Before you start: open a terminal. On Arch Linux, pacman is the native package manager. Running query operations (-Q) requires no root or administrative privileges and touches no system files. See First steps if you are new to the command line.

A package is a bundle of program files, documentation, and metadata. In pacman, uppercase -Q means "query" what is already installed on your computer. You do not need sudo or pkexec to inspect installed packages.

Mental model

Rootstock (Kernel, Drivers, Core OS)    --> Pacman (/usr/bin)
Tamlinux Cultivar (Desktop & Commands) --> Make source install (/usr/bin, /usr/lib/tamlinux/)
User Toolchains (Developer / Agent CLIs) --> Mise (~/.local/share/mise)

Each command on your system should have one clear owner. Pacman owns the rootstock (the base operating system beneath the Tamlinux scion; currently Arch Linux, with plans to migrate to Void Linux and later explore a microkernel). Tamlinux builds and installs its own desktop and bespoke tools from pinned Git clones with make and make install (transitioning away from earlier bundle tools; Nix and Home Manager are retired). Fast-moving developer and agent CLIs are owned by Mise.

Worked example: Query an installed package

$ pacman -Q bash
bash 5.3.20-1

Captured on an Arch Linux workstation, 2026-10-25. Your version may differ.

  1. pacman is invoked with the -Q query flag.
  2. bash is the package name being inspected.
  3. 5.3.20-1 reports upstream version 5.3.20 and packaging release 1. Because this is a query, nothing was downloaded or modified.

Try it

Query detailed package information for coreutils using pacman -Qi coreutils. Inspect the Version, Description, and Install Date fields. No packages are modified.

If it goes wrong

package 'foo' was not found
The package is not installed through pacman. It may be provided by a Tamlinux source install, Mise, or a user-local build in ~/.local/bin.
error: you cannot perform this operation unless you are root
You used an installation flag such as -S or -R instead of the query flag -Q. Use only -Q for safe, unprivileged queries.

Tamlinux strictly enforces that product software reaches your session only through a recorded candidate delivery built from pinned Git sources (or a recorded transitional bundle), never from an unrecorded checkout or raw copied payload. Furthermore, when local package patches are required, Tamlinux builds self-retiring packages in ~/pkgs with a release suffix rather than using IgnorePkg or modifying files under /usr.

Check yourself

Decide your answer before you reveal it.

Does running pacman -Q bash require administrator privileges?

No. -Q only reads local package databases in /var/lib/pacman/local/ and requires no root access.

What does the release number (-1) after the package version represent?

The package build revision created by the distribution maintainer, distinct from the upstream software release.

Packaging architectures, immutable stores, and patch lifecycles

Reference

ArchitectureMechanismGuarantees
Tamlinux Source Install/usr/lib/tamlinux/source/Pinned Git commits built via Make, verified by SHA-256 manifest digest, with root-owned state and console rollback.
Pacman DB/var/lib/pacman/local/Transactional package archives (.pkg.tar.zst) with strict file ownership checks.
XBPS/var/db/xbps/Atomic package state machine and binary transactions for the Void Linux target rootstock.
Mise~/.local/share/mise/Per-directory or global tool version shims without root access.

How it works

Tamlinux delivers its own components from pinned Git clones built with make and applied through a single root-owned make install transaction under /usr/bin and /usr/lib/tamlinux/source/, recording every destination path and SHA-256 digest. Native ecosystem dependencies stay under pacman governance, and user-local overrides under ~/.local/ and /usr/local/ are preserved untouched.

Why Tamlinux chose this

Tamlinux adopts a hybrid package-management model to balance system stability with developer flexibility. Using the native package manager for the rootstock ensures proper hardware driver integration and kernel lifecycle management. Building bespoke Tamlinux components directly from pinned Git clones with Make avoids duplicate runtime layers, keeps native library linkage clean, and records exact manifests so every cultivar upgrade remains verifiable and reversible.

Edge cases

  • ABI drift across layers: if a native rootstock update upgrades a shared library or Hyprland plugin ABI, compiled components linked against the previous ABI must be rebuilt against the updated headers.
  • PATH shadowing: having multiple versions of a CLI installed across ~/.local/bin, Mise, and /usr/bin can cause unexpected execution order; always verify with type -a or which -a.

Explore

Trace which layer owns an installed command:

$ tam where /usr/bin/bash

tam where checks active Tamlinux cultivar paths and manifests first, then queries the rootstock package manager (pacman -Qo on Arch Linux).

Check yourself

How does a Tamlinux source-install rollback differ from a Btrfs filesystem snapshot rollback?

A source-install rollback restores only the recorded Tamlinux cultivar files under /usr/ to the previous stage without altering rootstock packages or kernel files. A Btrfs snapshot rollback restores the entire snapshotted subvolume, including system configuration, kernel, and pacman databases.

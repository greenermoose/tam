What this reference is for

A command is a short instruction typed into a terminal. The prompt marks where typing begins; it is not part of the command.

This page collects the curated everyday commands used across desktop, network, package, and system pages, in short groups you can scan. It focuses on commands readers meet day to day rather than trying to dump all internal helpers.

Commands marked read-only inspect status safely; commands that change system packages or host policy are labelled in each table so you can prepare a recovery step first.

  • Desktop commands: screenshots, clipboard, notifications, sound, Bluetooth, displays, input, locking, and night light.
  • Network commands: connection status, speed test, Wi-Fi keys and QR codes, DNS settings, and Wi-Fi restarts.
  • Package and update commands: package checks, installation, removal, update status, firmware checks, and upgrades.
  • System, drive, power, and session commands: resource stats, drive checks, power profiles, battery status, hibernation, and locking.

Use the command reference

Goal: read a command and predict its effect before trying its simulated example.

How to read a command

A line beginning with $ shows the shell prompt, not something you type. Type the text after it and press Return. Put arguments that contain spaces inside double quotes.

Try: tam-notification-send "Tea is ready" "Take the kettle off the heat" Read the command after the prompt; do not type the prompt. The sandbox uses sample data and cannot change the host. Try tam-notification-send "Tea is ready" "Take the kettle off the heat" (or type help).

The output is fixed teaching data; no desktop setting or system package changes.

The command prints nothing when it succeeds; the notification is the result. If a command cannot do its job, it prints an error message and returns a non-zero exit status.

Before you run something

Read the whole line first. The commands on the reference page change only desktop settings: volume, brightness, clipboard behaviour, and similar. None of them install software, delete files, or ask for an administrator password. If a command you find elsewhere does ask for a password, stop and read its documentation first.

Reference and safety

A successful notification command may produce no terminal text because its result is a desktop event. Programs report failures through diagnostics and a non-zero exit status.

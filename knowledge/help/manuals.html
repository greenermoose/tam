Guide / Navigation Help / Finding instructions for programs

This page helps you find detailed instructions for programs installed on your computer.

What are man pages?

Manual pages (often called man pages) are the built-in reference sheets installed right alongside Linux commands and libraries. Each page describes one program, file format, or system call in a consistent, concise layout.

Why it matters

Unlike web tutorials that may describe an older or different version of a tool, your local manual pages document the exact version installed on your machine and work completely offline.

How to think about it

Think of this Guide as a textbook that teaches concepts in order, and man pages as the owner's manual tucked into the glovebox of every individual tool—short, exact, and organized for quick lookup.

New words

Command
A program or instruction you can run from a terminal.
Terminal
The text window where commands and manual pages are displayed.

Read a manual

Goal: find a manual page and identify its synopsis and description.

Before you start: This exercise reads documentation and changes no files.

New to this? Start in the Guide; follow links with the reader and press Left Arrow to return through history. At a terminal, do not type a leading dollar sign shown as a prompt.

Try the idea in a sandbox

LS(1) User Commands Try: man ls The NAME section states what ls does. SYNOPSIS shows the command form. Try the command shown above (or type help).

The output is fixed teaching data; the sandbox does not inspect or alter your system.

The anatomy

NAMEone line saying what it does.
SYNOPSISthe shape of the command.
DESCRIPTIONand OPTIONS — the details.
EXAMPLESFILES and SEE ALSO — how to use it and what to read next.

The numbered sections

  1. User commands, such as ls and grep.
  2. System calls, the kernel's interface.
  3. Library calls and functions.
  4. Special files and device interfaces.
  5. File formats and configuration, such as fstab.
  6. Games and demonstrations.
  7. Miscellaneous topics and conventions, such as regular expressions.
  8. Administration commands and daemons.
  9. Kernel routines, when provided by the installed system.

A p after the number, as in sh(1p), marks a page from the POSIX Programmer's Manual. It describes the standard interface; the Linux behavior can differ, and the page says so. See The POSIX Programmer's Manual for details on the standard sections and how to review them.

Finding the right page

man -k (also called apropos) searches the short descriptions; whatis prints the one-line summary. Bare tam man opens a discovery page with Open a page, Find by keyword, and Browse a section. Lookup input is entered in the reader, results are selectable links, and the section list explains the conventional meanings. Inside a manual, / searches the current page, n repeats, ? opens navigation help, and q quits.

Hyperlinked manuals with tam man

Tamlinux includes an integrated manual page viewer: tam man [SECTION] PAGE. It automatically converts system manual pages into hyperlinked views, letting you jump between referenced commands with Tab and Enter.

For example, view the manual page for the Tamlinux command itself: tam(1), or explore foundational commands like ls(1) and sh(1p).

Authoritative GNU Info manuals with tam info

While man pages provide concise reference entries, the GNU Project's Info manuals provide longer explanations organized into related nodes. Tamlinux includes an Info reader: tam info [MANUAL [NODE]].

Start with the installed Info Directory catalog. Available manuals depend on installed packages. Choose Info for a manual's linked chapters and nodes; choose Man pages for a concise command, system-call, or file-format reference. Use u for an Info manual's real parent node and Left Arrow for browsing history.

Example-first command pages with tam tldr

When you want practical invocation examples before reading every flag in a manual page, open tldr pages or run tam tldr [COMMAND]. Each page shows common command patterns with both short and long option forms (such as [-C|--directory]) and links to related tldr pages and the full manual page (for example tar or pacman).

If it goes wrong

If the page is missing, confirm the name and installed documentation. Use the Guide or Info as another source when available.

Check yourself

Does the number in ls(1) identify an option?

No. It is the manual section, here user commands.

What should you do when a result differs from the example?

Read the result and the relevant documentation, then check the input and prerequisites before changing anything.

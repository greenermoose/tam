Software Packaging and Delivery

The base distribution's native package manager owns the kernel, drivers, and core system. Tamlinux product software reaches a session through a recorded tamlinux-packages assembly and tam-deploy. User tools have their own Home Manager or Mise owner.

On existing distributions: Nix and Home Manager

On distributions such as Arch, Tamlinux package assemblies use a Nix flake and Home Manager integration:

  • Isolated store paths: each package is built into its own path under /nix/store, and exact versions are locked in flake.lock.
  • Recorded delivery: a candidate assembly is recorded and delivered with tam-deploy; a checkout is not a deployment source.
  • Rollback: every deployment is a Home Manager generation; returning to an earlier generation restores the previous desktop without touching the base system.

User command-line tools

Pacman remains the owner of operating-system components. Home Manager declares stable reproducible user tools, while Mise declares the fast-moving agent CLIs. Each interactive command should have one intended owner; check the active path in the shell or launch context that uses it.

On Void: native packages

On the target Void base, Tamlinux plans to deliver native packages built with xbps-src from the same sources. XBPS is written in C and installs packages in atomic transactions.

The base: native package managers

  • pacman (Arch): fast and transparent, with simple PKGBUILD recipes.
  • XBPS (Void): the native manager of the target base.
  • Also considered: Debian's APT and dpkg, and Gentoo's Portage.

Patched packages without silent overwrites

When a third-party package needs a fix, Tamlinux never edits files under /usr and never hides a package from updates with IgnorePkg. The patched package is rebuilt with a visible local release suffix and retires itself when upstream ships the fix; see Carried patches.

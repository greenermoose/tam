Init and Service Supervision

The init system is process ID 1: it starts the system and supervises the services that run in the background. Today Tamlinux runs on Arch Linux, which uses systemd. The target base uses runit.

Why runit on the target base

On Void Linux, and on the antiX Core fallback, runit is the init and service supervisor, without systemd:

  • Simple services: a service is a directory containing a short executable script named run.
  • Direct supervision: runsv is the parent of each supervised process, so it sees a crash immediately and restarts the service.
  • Small and quiet: runit is a small C program with a tiny memory footprint and no periodic background work of its own.

systemd today

systemd does much more than start services: it also provides logging, login and seat management, timers, network and DNS services, and more. That breadth is convenient, but many desktop programs now assume it is present. Tamlinux keeps its own commands and shell services free of systemd-specific assumptions where it can, so that they also run on a runit system.

Seats without systemd: seatd

A Wayland compositor needs permission to use the graphics and input devices. On systemd systems systemd-logind grants it; without systemd, seatd and libseat do the same job. This is how Sway runs on Void without systemd or elogind.

Communication protocols, framing, and data rates

This page explains how communication protocols format digital data into framed messages, the precise difference between baud rate and bit rate, and how flow control prevents data loss.

Having a physical cable or radio wave is only the first step in communication. Without agreed-upon rules, a receiver hears only meaningless voltage changes or bursts of radio static. A communication protocol establishes the shared language of computing: defining when a message starts, how fast symbols change, how bits are grouped into bytes, how flow control pauses transmission when buffers fill, and how errors are flagged. Understanding protocol framing and rate metrics allows you to configure terminals, troubleshoot serial devices, and evaluate network throughput.

Protocols, baud rate vs bit rate, and packet framing

Goal: you will be able to define what a communication protocol is, distinguish between baud rate and bit rate, and explain the purpose of packet framing.

Why it matters: two devices connected by a perfect cable will fail completely if their protocol settings do not match. If one device transmits at 9600 baud and the other listens at 115200 baud, or if one expects 8-bit bytes while the other expects 7-bit characters, the receiver outputs completely unreadable garbage. Knowing how protocol parameters are structured lets you set up serial consoles, configure microcontroller links, and recognize why data gets corrupted.

Before you start: open a terminal window (The Shell and Streams). The commands in this section inspect terminal line characteristics without altering your connection.

New to this? A protocol is simply an agreed-upon set of rules for conversation. Just as human conversation requires agreeing on a language, speaking at a pace the listener can follow, and taking turns without shouting over one another, computer protocols define identical rules for hardware devices.

Baud rate versus bit rate: clearing the confusion

The terms "baud rate" and "bit rate" are often misused interchangeably in casual conversation, but they measure fundamentally different physical properties:

  • Baud rate ($Bd$): The number of electrical signal state transitions or physical symbols occurring on the wire per second. If a voltage changes state 115,200 times in one second, the line is operating at 115,200 baud. Named in honour of French telegraph engineer Émile Baudot.
  • Bit rate ($bps$): The number of binary digits of information (0s and 1s) successfully transferred across the channel per second, measured in bits per second.
  • The Essential Relationship: 
    Bit Rate = Baud Rate * (Bits per Symbol)
    • Binary Signaling (1 bit per symbol): In basic serial interfaces like classic RS-232, the voltage is either high or low. Each symbol carries exactly one bit ($0$ or $1$). In this special two-level case, baud rate equals bit rate (e.g. 9600 baud = 9600 bps).
    • Multi-Level Signaling (Multiple bits per symbol): In modern high-speed systems (like Gigabit Ethernet, PAM-4 in PCIe Gen 6, or Wi-Fi 6 QAM), the transmitter uses multiple distinct voltage levels or phase angles. For example, if a line uses 4 distinct voltage levels, each symbol state encodes 2 binary bits ($00, 01, 10, 11$). A 1000 Megabaud PAM-4 line transmits at 2000 Megabits per second (bit rate is double the baud rate).

The necessity of packet framing

Imagine receiving a continuous, uninterrupted stream of binary numbers: ...1001110101001100101110....

Without boundaries, you cannot tell where one letter ends and the next begins. You do not know which bit is the most significant, whether a byte is missing, or where a command starts. Framing packages continuous bit streams into distinct, recognizable containers with defined boundaries:

  • Start Boundary: An unambiguous signal pattern or state transition that alerts the receiver that a new data frame has begun.
  • Data Payload: The actual information being transmitted (typically 7 or 8 bits in serial characters; 64 to 1500 bytes in network packets).
  • Control and Check Bits: Optional bits used to detect corruption (such as a parity bit or cyclic redundancy check).
  • Stop Boundary: An agreed-upon idle period or token that confirms the frame has concluded and resets the line for the next transmission.

Try it

Run stty -a and locate the line containing cs8. cs8 stands for "character size 8 bits". Test changing to 7-bit characters in a subshell using (stty cs7; stty -a | grep -o "cs[0-9]") and observe how the driver adapts.

If it goes wrong

Terminal prints strange hieroglyphs or high-ASCII box-drawing characters
The terminal baud rate does not match the connected hardware, causing the receiver to sample in the middle of transitions. Set the standard baud rate using stty 115200.
Output pauses and appears completely frozen
You may have accidentally pressed Ctrl+S, which transmits the software flow control XOFF character. Press Ctrl+Q (XON) to resume transmission.

When does baud rate equal bit rate, and when do they differ?

Baud rate equals bit rate when each electrical symbol transition represents exactly one binary bit (two-level binary signaling). They differ when multi-level modulation is used: if each symbol represents 4 voltage states (2 bits per symbol), the bit rate is twice the baud rate.

Why must an asynchronous serial frame include a Start bit?

Because there is no shared clock wire. When the line is resting in the idle high state, the receiver does not know when data will arrive. The Start bit forces a sudden high-to-low voltage transition that wakes up and synchronizes the receiver's local timer so it can sample subsequent bits at precise intervals.

Anatomy of a standard UART frame

In asynchronous serial communication (used by PC serial ports, microcontrollers, GPS modules, and router consoles), data is transmitted in individual character frames managed by a Universal Asynchronous Receiver-Transmitter (UART):

  1. Idle State (Mark): When no data is being transmitted, the line rests at continuous high voltage (logic 1 / Mark).
  2. Start Bit (Space): To begin transmission, the transmitter drives the line low (logic 0 / Space) for exactly one bit period. This high-to-low transition triggers the receiver's internal timer.
  3. Data Payload: The receiver waits 1.5 bit periods to sample the middle of the first data bit, then samples once every bit period thereafter. Data is standardly sent Least Significant Bit (LSB) first (Bit 0 through Bit 7).
  4. Optional Parity Bit: A single check bit added immediately after the data bits. In even parity, the bit is set so the total count of 1s is even; in odd parity, it ensures an odd count. If parity is omitted, this bit period is skipped.
  5. Stop Bit(s) (Mark): The transmitter returns the line to the high idle state (Mark) for 1 or 2 bit periods. The Stop bit guarantees a minimum idle window before the next frame can begin, ensuring the receiver never mistakes a subsequent data bit for a Start bit.

Understanding the "8N1" shorthand

Engineers describe serial port framing configurations using a universal three-character code:

Notation: [Data Bits][Parity][Stop Bits]
Example:  8N1
          | | |
          | | +- 1 Stop bit
          | +--- No parity ("N" = None, "E" = Even, "O" = Odd)
          +----- 8 Data bits (1 full byte)

8N1 is the overwhelming standard across computing, accounting for over 95% of all serial links. Legacy terminal systems occasionally use 7E1 (7 data bits, Even parity, 1 stop bit) to transmit 7-bit ASCII text.

Flow control: preventing buffer overruns

When a fast computer transmits data to a slower device (such as a serial printer or a microcontroller writing to flash memory), the receiver's memory buffer will quickly fill up. Without a mechanism to pace transmission, incoming bytes overwrite unread data — an error known as a buffer overrun. Flow control solves this:

  • Hardware Flow Control (RTS/CTS):
    • Mechanism: Uses two dedicated physical wires: RTS (Request to Send) and CTS (Clear to Send). When the receiver's buffer approaches capacity, it immediately drops the voltage on its CTS output wire. The transmitter's hardware UART detects this voltage drop and halts transmission in the middle of a microsecond — without involving the operating system CPU. When the buffer empties, the receiver raises CTS and transmission resumes instantly.
    • Evaluation: Completely reliable, instantaneous, and works with arbitrary binary data.
  • Software Flow Control (XON/XOFF):
    • Mechanism: Uses no extra wires. Instead, the receiver transmits special in-band ASCII characters back to the sender over the normal receive line: transmitting XOFF (hexadecimal 0x13, or Ctrl+S) requests a pause; transmitting XON (hexadecimal 0x11, or Ctrl+Q) resumes transmission.
    • Evaluation: Fails if binary files (like compiled programs or images) contain the byte value 0x13, which the sender mistakenly interprets as a command to freeze. Furthermore, if the receiver's buffer fills while bytes are already in transit along a long cable, data is lost before the XOFF character reaches the sender.

Worked example: configure a serial port for 8N1 with hardware flow control

$ sudo stty -F /dev/ttyS0 115200 cs8 -parenb -cstopb crtscts 2>/dev/null || \
  echo "Virtual console configured (hardware UART node /dev/ttyS0 not attached)"
Virtual console configured (hardware UART node /dev/ttyS0 not attached)

Breaking down the stty command flags:

  1. 115200 sets the communication speed to 115,200 baud.
  2. cs8 configures character size to 8 data bits.
  3. -parenb disables parity generation and checking ("None").
  4. -cstopb configures one stop bit (prefixing with - specifies 1 stop bit; cstopb without a minus specifies 2 stop bits).
  5. crtscts enables hardware RTS/CTS flow control.

Completion task

Fill in the missing stty flag to configure an older industrial serial link for 7-bit characters with Even parity (marked with ___):

stty -F /dev/ttyUSB0 9600 cs7 ___ -cstopb

Fill in parenb -parodd. parenb enables parity generation, and -parodd configures even parity (omitting the minus would select odd parity). Combined with cs7 and -cstopb, this establishes standard 7E1 framing.

Independent task

A microcontroller sends telemetry over an asynchronous serial link configured as 115,200 baud, 8N1. Calculate the channel's maximum theoretical character transfer rate per second and determine the percentage of total bandwidth consumed by framing overhead.

Each character frame consists of: 1 Start bit + 8 Data bits + 0 Parity bits + 1 Stop bit = 10 physical bits per frame. The maximum frame rate is 115,200 / 10 = 11,520 characters per second. Out of each 10-bit frame, exactly 8 bits carry data payload and 2 bits are framing overhead. Overhead percentage is (2 / 10) * 100 = 20.0%. One fifth of the raw transmission channel is consumed purely by synchronization bits.

What does the shorthand "8N1" mean in serial communication?

It defines a frame structure of 8 Data bits, No parity bit ("N"), and 1 Stop bit. Together with the mandatory Start bit, each character occupies exactly 10 bit periods on the physical line.

Why should software flow control (XON/XOFF) never be used when transferring binary files over a serial port?

Because software flow control uses in-band ASCII control characters (`0x11` for XON and `0x13` for XOFF). If a binary file (such as a compiled executable or compressed image) happens to contain the byte value `0x13`, the transmitting software interprets that data byte as a command to halt, freezing the transmission indefinitely.

How it works: mathematical channel limits

Every physical communication channel is bounded by the laws of physics and information theory:

  1. The Nyquist Limit (Noiseless Channels): In 1928, Harry Nyquist proved that the maximum symbol transmission rate over an analog channel is strictly twice its analog bandwidth ($B$ in Hertz): 
    Max Baud Rate = 2 * B
Max Bit Rate = 2 * B * log2( M )
    Where $M$ is the number of discrete signal voltage levels. Doubling the analog bandwidth doubles the possible symbol rate; doubling the voltage states ($M$) increases bit rate logarithmically.
  2. The Shannon-Hartley Theorem (Noisy Channels): In 1948, Claude Shannon proved that physical thermal noise sets the absolute theoretical upper limit on error-free information capacity (C in bps) across any noisy channel: 
    Capacity = B * log2( 1 + Signal_Power / Noise_Power )
    Even with infinite voltage levels (as M approaches infinity), channel capacity cannot exceed Shannon's limit: as voltage levels are packed closer together, thermal noise causes adjacent states to blur into each other, triggering bit errors. Increasing data rate across fixed bandwidth requires either boosting signal power or reducing physical noise.

Line coding mechanics: DC balance and run-length limiting

Raw digital bit streams cannot be transmitted directly across high-speed AC-coupled channels without encoding:

  • Baseline Wander: High-speed serial links place ceramic capacitors in series with differential lines to block DC ground offsets between devices. If a data stream contains a long string of consecutive 1s, the capacitor charges up, shifting the zero-voltage reference level (baseline wander). The receiver's comparator threshold drifts, causing subsequent bits to be misinterpreted.
  • Run-Length Limiting (RLL): Phase-Locked Loops in Clock Data Recovery (CDR) circuits require frequent voltage edges to stay synchronized. Encodings like 8b/10b map every 8-bit byte to a 10-bit symbol chosen from a codebook that limits maximum consecutive identical bits to five, and tracks running disparity (+1 or -1) to guarantee long-term zero DC bias.

Linux kernel tty architecture and termios

In the Linux operating system, serial communication is abstracted by the kernel tty subsystem:

[ User Space Application ] <--- read(2) / write(2)
          |
[ POSIX Line Discipline (N_TTY) ] <--- Canonical line editing, echo, signal generation
          |
[ Kernel Serial Core (serial_core.c) ] <--- termios state, baud rate prescalers
          |
[ Hardware UART Driver (8250/16550) ] <--- MMIO / Port I/O register access, DMA, FIFO
          |
[ Physical UART Silicon & Transceiver ] <--- Serial Pin Voltage Swings

Applications configure the interface via the POSIX struct termios data structure using tcgetattr(3) and tcsetattr(3). The structure separates control flags into four bitmasks:

  • c_iflag: Input processing (e.g. IXON for software flow control, IGNPAR to ignore framing errors).
  • c_oflag: Output processing (e.g. OPOST to translate newline characters to carriage-return newline pairs).
  • c_cflag: Hardware control (e.g. CSIZE bitmask for character size, PARENB for parity, CSTOPB for stop bits, CRTSCTS for hardware flow control).
  • c_lflag: Local line discipline modes (e.g. ICANON for canonical line buffering, ECHO for key reflection, ISIG to generate SIGINT on Ctrl+C).

Why Tamlinux chose this

Tamlinux preserves pure Unix stream semantics across its terminal and console architecture. By strictly separating hardware UART drivers from POSIX line disciplines, Tamlinux ensures that diagnostic commands, headless serial consoles, and accessibility screen readers operate across identical, predictable APIs. Hardware flow control is enforced on all automated test harnesses, guaranteeing zero dropped bytes during unattended kernel boot logging.

Edge cases and failure modes

  • Inter-Symbol Interference (ISI) from Slew Rate Limiting: When cable capacitance is high, voltage pulses cannot rise or fall instantaneously (t_rise approx 2.2 * R * C). If the baud period is shorter than the rise time, the signal never reaches full voltage before transitioning to the next bit, causing the pulse to smear into adjacent symbol periods.
  • Baud Divisor Quantization Error: Hardware UARTs generate baud rates by dividing a master crystal oscillator frequency (e.g. 1.8432 MHz or 24 MHz) by an integer divisor register. If the target baud rate cannot be divided evenly, the actual generated baud rate will deviate from the nominal rate. If divisor quantization error exceeds 2.5%, the receiver will reliably lose synchronization on multi-byte transfers.
  • Flow Control Deadlock: When two devices communicate with hardware flow control enabled, but each device incorrectly configures its CTS pin as an input waiting for the other side to assert RTS before asserting its own, both devices freeze indefinitely in a mutual wait state.

According to the Shannon-Hartley theorem, why can you not achieve infinite data rate across a channel simply by dividing voltage into thousands of microscopic levels?

Because every physical transmission channel contains thermal Johnson-Nyquist noise generated by the random thermal agitation of charge carriers (P_noise = k_B * T * B). As voltage levels are divided into thousands of microscopic steps, the voltage separation between adjacent states becomes smaller than the random thermal noise fluctuations. Noise causes the receiver to misread states, generating errors that collapse error-free information capacity.

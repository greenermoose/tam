Communication protocols, framing, and data rates

This page explains how communication protocols format digital data into framed messages, the precise difference between baud rate and bit rate, and how flow control prevents data loss.

Having a physical cable or radio wave is only the first step in communication. Without agreed-upon rules, a receiver hears only meaningless voltage changes or bursts of radio static. A communication protocol establishes the shared language of computing: defining when a message starts, how fast symbols change, how bits are grouped into bytes, how flow control pauses transmission when buffers fill, and how errors are flagged. Understanding protocol framing and rate metrics allows you to configure terminals, troubleshoot serial devices, and evaluate network throughput.

What is a communication protocol?

Two devices connected by a perfect cable will fail completely if their protocol settings do not match. If one device transmits at 9600 baud and the other listens at 115200 baud, or if one expects 8-bit bytes while the other expects 7-bit characters, the receiver outputs completely unreadable garbage. Knowing how protocol parameters are structured lets you set up serial consoles, configure microcontroller links, and recognize why data gets corrupted.

New words

Baud rate
The number of electrical signal state transitions or symbols occurring on a communication channel per second.
Bit rate
The total number of binary information bits transferred across a connection per second.
Framing
The practice of organizing raw bit streams into discrete packets with defined starting and ending boundaries.

Worked example: query and set serial line speed

$ stty speed

$ python3 -c 'baud=115200; bits_per_char=10; print(f"Max throughput: {baud/bits_per_char:.0f} bytes/sec ({baud*8/bits_per_char/1000:.1f} kbps)")'
Max throughput: 115200 bytes/sec (92.2 kbps)

Captured on a Tamlinux workstation, 2026-11-01. The terminal queries its configured communication speed and calculates theoretical byte throughput.

What just happened

  1. stty speed prints the baud rate configured on standard input (38,400 baud).
  2. The Python calculation demonstrates how serial framing affects transfer speed: in standard asynchronous serial communication, each 8-bit byte of data requires 10 physical bit periods on the wire (1 Start bit + 8 Data bits + 1 Stop bit).
  3. At 115,200 baud, the line transmits a maximum of 11,520 payload bytes per second (92.2 kbps net data throughput), with 20% of the raw bandwidth consumed by framing overhead.

Try it

Run stty -a and locate the line containing cs8. cs8 stands for "character size 8 bits". Test changing to 7-bit characters in a subshell using (stty cs7; stty -a | grep -o "cs[0-9]") and observe how the driver adapts.

If it goes wrong

Terminal prints strange hieroglyphs or high-ASCII box-drawing characters
The terminal baud rate does not match the connected hardware, causing the receiver to sample in the middle of transitions. Set the standard baud rate using stty 115200.
Output pauses and appears completely frozen
You may have accidentally pressed Ctrl+S, which transmits the software flow control XOFF character. Press Ctrl+Q (XON) to resume transmission.

On Tamlinux: serial line disciplines are managed through the kernel tty core. When configuring serial login terminals (`agetty`), Tamlinux units explicitly pass `115200,38400,9600` in their unit definitions. If a remote console cannot synchronize at 115,200 baud, `agetty` automatically steps down through the fallback baud rates upon receiving a break signal.

When does baud rate equal bit rate, and when do they differ?

Baud rate equals bit rate when each electrical symbol transition represents exactly one binary bit (two-level binary signaling). They differ when multi-level modulation is used: if each symbol represents 4 voltage states (2 bits per symbol), the bit rate is twice the baud rate.

Why must an asynchronous serial frame include a Start bit?

Because there is no shared clock wire. When the line is resting in the idle high state, the receiver does not know when data will arrive. The Start bit forces a sudden high-to-low voltage transition that wakes up and synchronizes the receiver's local timer so it can sample subsequent bits at precise intervals.

How it works: mathematical channel limits

Every physical communication channel is bounded by the laws of physics and information theory:

  1. The Nyquist Limit (Noiseless Channels): In 1928, Harry Nyquist proved that the maximum symbol transmission rate over an analog channel is strictly twice its analog bandwidth ($B$ in Hertz): 
    Max Baud Rate = 2 * B
Max Bit Rate = 2 * B * log2( M )
    Where $M$ is the number of discrete signal voltage levels. Doubling the analog bandwidth doubles the possible symbol rate; doubling the voltage states ($M$) increases bit rate logarithmically.
  2. The Shannon-Hartley Theorem (Noisy Channels): In 1948, Claude Shannon proved that physical thermal noise sets the absolute theoretical upper limit on error-free information capacity (C in bps) across any noisy channel: 
    Capacity = B * log2( 1 + Signal_Power / Noise_Power )
    Even with infinite voltage levels (as M approaches infinity), channel capacity cannot exceed Shannon's limit: as voltage levels are packed closer together, thermal noise causes adjacent states to blur into each other, triggering bit errors. Increasing data rate across fixed bandwidth requires either boosting signal power or reducing physical noise.

Line coding mechanics: DC balance and run-length limiting

Raw digital bit streams cannot be transmitted directly across high-speed AC-coupled channels without encoding:

  • Baseline Wander: High-speed serial links place ceramic capacitors in series with differential lines to block DC ground offsets between devices. If a data stream contains a long string of consecutive 1s, the capacitor charges up, shifting the zero-voltage reference level (baseline wander). The receiver's comparator threshold drifts, causing subsequent bits to be misinterpreted.
  • Run-Length Limiting (RLL): Phase-Locked Loops in Clock Data Recovery (CDR) circuits require frequent voltage edges to stay synchronized. Encodings like 8b/10b map every 8-bit byte to a 10-bit symbol chosen from a codebook that limits maximum consecutive identical bits to five, and tracks running disparity (+1 or -1) to guarantee long-term zero DC bias.

Linux kernel tty architecture and termios

In the Linux operating system, serial communication is abstracted by the kernel tty subsystem:

[ User Space Application ] <--- read(2) / write(2)
          |
[ POSIX Line Discipline (N_TTY) ] <--- Canonical line editing, echo, signal generation
          |
[ Kernel Serial Core (serial_core.c) ] <--- termios state, baud rate prescalers
          |
[ Hardware UART Driver (8250/16550) ] <--- MMIO / Port I/O register access, DMA, FIFO
          |
[ Physical UART Silicon & Transceiver ] <--- Serial Pin Voltage Swings

Applications configure the interface via the POSIX struct termios data structure using tcgetattr(3) and tcsetattr(3). The structure separates control flags into four bitmasks:

  • c_iflag: Input processing (e.g. IXON for software flow control, IGNPAR to ignore framing errors).
  • c_oflag: Output processing (e.g. OPOST to translate newline characters to carriage-return newline pairs).
  • c_cflag: Hardware control (e.g. CSIZE bitmask for character size, PARENB for parity, CSTOPB for stop bits, CRTSCTS for hardware flow control).
  • c_lflag: Local line discipline modes (e.g. ICANON for canonical line buffering, ECHO for key reflection, ISIG to generate SIGINT on Ctrl+C).

Why Tamlinux chose this

Tamlinux preserves pure Unix stream semantics across its terminal and console architecture. By strictly separating hardware UART drivers from POSIX line disciplines, Tamlinux ensures that diagnostic commands, headless serial consoles, and accessibility screen readers operate across identical, predictable APIs. Hardware flow control is enforced on all automated test harnesses, guaranteeing zero dropped bytes during unattended kernel boot logging.

Edge cases and failure modes

  • Inter-Symbol Interference (ISI) from Slew Rate Limiting: When cable capacitance is high, voltage pulses cannot rise or fall instantaneously (t_rise approx 2.2 * R * C). If the baud period is shorter than the rise time, the signal never reaches full voltage before transitioning to the next bit, causing the pulse to smear into adjacent symbol periods.
  • Baud Divisor Quantization Error: Hardware UARTs generate baud rates by dividing a master crystal oscillator frequency (e.g. 1.8432 MHz or 24 MHz) by an integer divisor register. If the target baud rate cannot be divided evenly, the actual generated baud rate will deviate from the nominal rate. If divisor quantization error exceeds 2.5%, the receiver will reliably lose synchronization on multi-byte transfers.
  • Flow Control Deadlock: When two devices communicate with hardware flow control enabled, but each device incorrectly configures its CTS pin as an input waiting for the other side to assert RTS before asserting its own, both devices freeze indefinitely in a mutual wait state.

Decide your answer before you reveal it.

According to the Shannon-Hartley theorem, why can you not achieve infinite data rate across a channel simply by dividing voltage into thousands of microscopic levels?

Because every physical transmission channel contains thermal Johnson-Nyquist noise generated by the random thermal agitation of charge carriers (P_noise = k_B * T * B). As voltage levels are divided into thousands of microscopic steps, the voltage separation between adjacent states becomes smaller than the random thermal noise fluctuations. Noise causes the receiver to misread states, generating errors that collapse error-free information capacity.

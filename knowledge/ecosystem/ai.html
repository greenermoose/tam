AI Tooling and Human Agency

Trace AI-assisted work

Goal: explain the boundary between human direction, an AI tool and public provenance.

Mental model

A person directs work; the tool assists; records describe what happened. These are separate roles.

Worked example

Find the provenance file named below and identify the tool, task and verification it records.

AI coding assistants help build Tamlinux. They work under human direction: a person sets the goals, reviews the results, and decides what is tested, deployed, and released.

Public provenance

  • Every public Tamlinux repository keeps an AI_PROVENANCE.md file and session records under docs/ai/.
  • Each record names the tool and its version, the model, the guiding prompts, and the commits it produced, so anyone can see how a piece of code came to be.
  • Commits made with AI assistance carry trailers naming the tool and model.

Respecting upstream projects

Some projects do not accept AI-assisted contributions. Tamlinux follows each project's policy: where AI involvement is not wanted, as in Hyprland, Tamlinux does not submit AI-written work and instead publishes fixes on public forks; see Carried patches.

Agents in the product

Tamlinux's desktop lets you choose a default AI agent to launch. Support for OpenClaw and Hermes has been retired from those defaults.

Tools used in development

  • Claude Code (Anthropic)
  • Codex (OpenAI)
  • Antigravity CLI, agy (Google)
  • Cursor, an AI-assisted editor

The provenance files in each repository record which tool did which work.

Completion task

Name which part of a record states the human request and which describes verification.

The guiding prompt records the human request; the verification section records the checks. Neither substitutes for reviewing the resulting change.

Independent task

Choose a public repository record and identify what remains unverified.

Choosing

Use provenance to understand authorship; use tests and review to evaluate the actual change.

Troubleshooting

A record is not proof that the resulting work is correct. Inspect the diff and verification evidence.

On Tamlinux: Public records document AI-assisted work under human direction.

Check yourself

Does a model name establish that its change passed review?

No. A model identifies the tool used; review and verification are separate evidence.

What evidence separates a proposed change from a delivered one?

Inspect the relevant plan, selected package and acceptance evidence; a proposal alone establishes none of those.

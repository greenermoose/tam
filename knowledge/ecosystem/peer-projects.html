Peer desktop projects

This page introduces the desktop, shell and base-system projects Tamlinux studies, and says what each one is worth watching for.

These projects are peers, not dependencies. Tamlinux does not install them as a set, and being listed here is not a recommendation. Some are complete distributions, some are shells for one compositor, and some are configuration sets. They solve related problems in different ways, so their choices are useful evidence even when Tamlinux takes a different path.

The details are a snapshot from 31 October 2026. Projects change their leadership, release rhythm and scope. Check a project's own site before relying on a name, version or channel. The people and public meeting places behind these projects are on Peer developers and communities.

Terms and how to read an entry

Compositor
Software that combines application windows into the picture on screen and decides which window receives input. A Wayland compositor also manages outputs, seats and the window protocol.
Desktop shell
The visible layer around the compositor: bar, launcher, panels, notifications, lock screen and settings. A shell may also provide session startup and a greeter.
Desktop distribution
A complete installable system that combines a compositor, a shell, default applications and an installer.
Dotfile set
A collection of configuration files, often shared with an installer. It is not a packaged desktop, even when it looks like one.
Rootstock
The kernel and core system software on which the Tamlinux cultivar is installed. See Rootstocks for Tamlinux's current and planned choices.

Each entry gives the same four fields where they apply: what the project is, what makes it distinct, why Tamlinux watches it, and where to find it. The links are online; the rest of this guide works offline.

Desktop distributions

Omarchy

What it is
An Arch Linux desktop built around Hyprland, a Quickshell-based shell, curated defaults, themes and installer scripts. It is maintained by the Omacom Foundation, which also sponsors Hyprland work.
What makes it distinct
It presents a complete, opinionated desktop as a small set of scripts and defaults rather than as a separate distribution image.
Why Tamlinux watches it
Its installer, upgrade path and packaging discipline are useful evidence for a small team supporting a large community. Tamlinux no longer depends on Omarchy, so this is a study of integration work, not a dependency.
Where to find it
github.com/omacom/omarchy and omarchy.org.

Hyprland shells and dotfile sets

Dux Shell

What it is
A full desktop shell for Hyprland built with Quickshell. It was formerly called DankMaterialShell, and the old repository links redirect to the new name.
What makes it distinct
It ships a bar, launcher, notifications, settings and other desktop components as one shell, rather than leaving those pieces to separate projects.
Why Tamlinux watches it
It shows how a shell can keep its own components together while still depending on a separate compositor. Its rename is also a reminder that project names and repository addresses change.
Where to find it
github.com/duxlabs-dev/dux-shell and duxlabs.dev/docs.

Noctalia

What it is
A Quickshell-based desktop shell that has moved core parts to native C++ and now includes its own compositor, Umbriel, and a greeter.
What makes it distinct
It grows from a shell into a larger desktop stack, including the session and login pieces that many shells leave to other projects.
Why Tamlinux watches it
It is a live test of what a shell gains and loses when it moves beyond QML and takes responsibility for the compositor and greeter.
Where to find it
github.com/noctalia-dev/noctalia and docs.noctalia.dev.

Caelestia

What it is
A Quickshell desktop shell and Hyprland configuration set with a strong visual theme, packaged for people who want the whole look and behaviour.
What makes it distinct
It treats appearance and configuration layout as part of the product, not as an afterthought.
Why Tamlinux watches it
It shows how a dotfile set can become a reusable shell, and where that transition creates packaging and support work.
Where to find it
github.com/caelestia-dots/shell and caelestiashell.com.

end-4's dots-hyprland

What it is
A widely used Hyprland dotfile set with an installer, documentation and a large collection of configuration files.
What makes it distinct
It is explicitly a configuration set, not a distribution, and it invests heavily in the first-install experience.
Why Tamlinux watches it
Its installer and migration guidance are useful evidence for people arriving from other desktops. It also shows the support cost of a large configuration set.
Where to find it
github.com/end-4/dots-hyprland.

Compositors

Tamlinux's current desktop uses Hyprland, and the plan is to move to Sway on wlroots. The full comparison is in Compositors and windowing; this section records only the peer relationship.

Hyprland

What it is
A dynamic tiling Wayland compositor with animations, plugins and its own configuration language. The Omacom Foundation sponsors work on it.
What makes it distinct
It supports a plugin ecosystem and a configuration style that many shell projects build around.
Why Tamlinux watches it
It is the current compositor, and its plugin ABI and configuration compatibility are practical lessons in how tightly a shell can depend on a compositor.
Where to find it
github.com/hyprwm/Hyprland and wiki.hypr.land.

Sway and wlroots

What it is
Sway is an i3-compatible tiling Wayland compositor built on wlroots, a library that provides compositor building blocks.
What makes it distinct
It keeps the i3 model and relies on a shared library for protocol and backend work, rather than implementing everything in one project.
Why Tamlinux watches it
It is the planned compositor. Sway's own development is quiet, while wlroots remains active; quiet is not the same as abandoned, and the two projects should be judged separately.
Where to find it
github.com/swaywm/sway and gitlab.freedesktop.org/wlroots/wlroots.

niri

What it is
A scrollable-tiling Wayland compositor: windows sit in columns on an infinite horizontal strip, and the workspace scrolls instead of switching between fixed pages.
What makes it distinct
It changes the workspace and input model, not just the theme or the default keybindings.
Why Tamlinux watches it
It is a different answer to window management and a useful comparison for input and workspace design. It is not a planned replacement.
Where to find it
github.com/niri-wm/niri.

Shell toolkits and independent shells

Quickshell

What it is
A toolkit for building desktop shells with QML and Qt. Tamlinux's own shell is built on it.
What makes it distinct
It provides shell building blocks without requiring one compositor or one finished desktop.
Why Tamlinux watches it
It is both a dependency and a peer: its choices affect Tamlinux's shell, and other shell projects show how far those choices stretch. See Desktop shell and UI toolkits.
Where to find it
github.com/quickshell-mirror/quickshell.

Regolith

What it is
A desktop environment for Ubuntu and Debian-based systems, built around Sway and i3, with its own session and configuration layer.
What makes it distinct
It packages a tiling desktop for people who expect a general-purpose distribution and a conventional login session.
Why Tamlinux watches it
Its session management and packaging show how a tiling desktop reaches users who do not want to assemble one themselves.
Where to find it
github.com/regolith-linux/regolith-desktop and regolith-desktop.com.

nwg-shell

What it is
A GTK-based shell for sway and Hyprland, with panels, launchers and a collection of small desktop utilities.
What makes it distinct
It favours small, separate programs over one large shell process.
Why Tamlinux watches it
It is evidence for component boundaries and for how utilities can work across more than one compositor.
Where to find it
github.com/nwg-piotr/nwg-shell.

COSMIC

What it is
System76's Rust desktop environment, with its own compositor, settings, greeter and applications.
What makes it distinct
It is a complete native desktop built outside the GNOME and KDE ecosystems, with a single project owning most of the stack.
Why Tamlinux watches it
It shows what a coherent session and settings architecture looks like when one project controls the compositor, shell and applications together.
Where to find it
github.com/pop-os/cosmic-epoch.

Base-system peers

The base system is covered in more detail by Rootstocks and the Operating systems reference. Two independent distributions matter here because their maintainers and design choices overlap with the desktop projects above.

Void Linux

What it is
An independent Linux distribution with its own package manager, XBPS, and runit as its init and service supervisor.
Why Tamlinux watches it
It is the target rootstock. Its small service model and package ownership are the main comparison with the current Arch Linux base.
Where to find it
github.com/void-linux/void-packages and voidlinux.org.

Chimera Linux

What it is
An independent Linux distribution built with musl and the LLVM toolchain, with its own package and init choices.
Why Tamlinux watches it
It is a useful comparison for a base system assembled without the usual GNU and glibc assumptions.
Where to find it
github.com/chimera-linux/cports and chimera-linux.org.

What not to infer

  • A similar goal does not mean compatible code, licensing or architecture.
  • Popularity is not a security review, and activity is not proof of maturity.
  • A public maintainer is not a support desk, and a name here is not an invitation to contact someone privately.
  • A dated snapshot is not a live status. Check the project before relying on a release, a repository address or a channel.

Tamlinux's own choices are recorded in Rootstocks, Compositors and windowing and Desktop shell and UI toolkits.

Check yourself

Decide your answer before you reveal it.

A peer project has many stars and frequent commits. Does that make it a safe rootstock?

No. Popularity and activity say nothing by themselves about security, maintenance quality, licensing or fit. A rootstock choice needs evidence about package ownership, update policy, architecture and the cost of carrying fixes, not a count of stars.

What is the difference between a compositor and a desktop shell?

The compositor combines windows into the screen image and routes input. The shell draws the bar, launcher, panels, notifications and settings around it. A project can provide one, the other, or both, so the terms are not interchangeable.

Why does Tamlinux still watch Omarchy after removing the dependency?

Because its installer, upgrade path and packaging discipline are still useful evidence for a small team supporting a large desktop community. Watching a project is not the same as depending on its packages.

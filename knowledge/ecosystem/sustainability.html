Sustainability and Hardware Longevity

Consider the hardware lifecycle

Goal: describe how continued use and repair can affect a hardware decision.

Why it matters: Replacing a machine and keeping one in service have different costs; the answer depends on its condition and use.

Before you start: Read the capability and repair sections; do not alter the machine for this exercise.

New to this? Read the explanation below, then try the question. Follow links in the Guide and use Left Arrow to return through history.

Worked example

Consider a working computer with a software problem. Identify the fault before deciding that replacement hardware is needed.

Software usually becomes bloated, abandoned, or insecure long before the hardware fails. Manufacturing accounts for much of a computer's lifetime environmental cost, so keeping a working machine in use is one of the most effective ways to reduce electronic waste. A lighter, more efficient system keeps older machines useful and makes the computer you already have faster.

Profiles by capability, not age

Tamlinux aims for the best possible experience on any hardware. Rather than excluding machines by age, it chooses a graphical or terminal profile by what a machine can actually do:

  • Graphical profile: the full desktop, on machines with suitable graphics drivers and enough memory.
  • Terminal-only profile: for 32-bit machines, very old machines without the graphics drivers Wayland needs, and machines with too little memory to compile code or run a modern browser comfortably.
  • Older machines as test cases: machines from around 2006 remain useful validation examples, and Sway's software rendering is to be tested on representative older graphics hardware.

Gains on modern hardware too

Using fewer resources is not only for old computers. On modern hardware it means lower energy use, cooler and quieter operation, longer battery runtime, and longer life for components with finite cycle counts, such as battery cells and flash storage.

Repair instead of replacement

When a machine becomes unusable, it is often hard to tell hardware failure from software rot. Tamlinux aims for introspection: the system should help you diagnose and repair itself. See System resources and performance for how to read memory and CPU use.

Others with the same goals

Other projects work toward reuse and lower energy use too, from desktop distributions for donated computers to energy measurement and eco-labels for software. See Environment-minded systems and desktops.

If it goes wrong

If the fault is unknown, record the symptoms and seek evidence rather than assuming hardware is broken.

Check yourself

Does a slow application alone prove that a computer must be replaced?

No. Diagnose the workload, software and hardware before deciding.

Where can you check a current capability before relying on it?

Use its current product documentation and the evidence for the installation you are using.

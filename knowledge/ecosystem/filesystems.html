Filesystems that keep state

This page explains how a computer organizes files on a disk and how snapshots help recovery.

Files live on a filesystem

Goal: you will be able to say what a filesystem is and that Btrfs can take snapshots.

Why it matters: updates and mistakes are safer when you know which recovery boundary covers which files.

Before you start: read-only commands only.

A filesystem is the rules and structures that turn a disk into named files and directories.

Worked example

$ findmnt -T /
TARGET SOURCE FSTYPE OPTIONS
/ /dev/... btrfs ...

Captured pattern on Arch Linux, 2026-11-02. Your device name and options differ. If the type is btrfs, snapshot tools may apply; if not, do not invent Snapper steps.

Try it

Run findmnt -T /home as well and compare types.

If it goes wrong

findmnt missing
Use the documentation for your rootstock; do not invent filesystem types.

Check yourself

Does a Btrfs snapshot always restore a document you edited today?

No. Snapshots cover configured subvolumes at taken times. Mutable files outside that boundary need their own backup story.

Subvolumes and recovery domains

Goal: separate filesystem snapshots from Home Manager generations and hand-edited files.

Mental model

Btrfs subvolume snapshot  |  Home Manager generation  |  mutable documents

Each column recovers different state. A healthy plan names which column covers the change you are about to make.

On Tamlinux: Snapper timelines and deploy generations are both used; neither replaces the other. See rollback.

Worked example

Before any cleanup, write which column of the mental model covers the change you fear.

Example: removing a Snapper timeline entry does not restore a hand-edited document.

Completion task

Name one change covered by a Home Manager generation and one that is not.

A packaged user program path may roll with a generation; a paragraph in a personal notes file usually will not.

Independent task

Read the rollback page headings only and list the recovery domains it names.

Expect filesystem snapshots and generation rollback as separate ideas.

Choosing

Match the recovery tool to the domain you identified; do not start with destructive cleanup.

Troubleshooting

Disk-full symptoms: see disk pressure.

Check yourself

You updated a theme file by hand. Which recovery domain should you check first?

The mutable file's own backup or previous copy. A package generation may not restore that edit.

Checksums, CoW and evidence

Btrfs copy-on-write snapshots and checksums change failure modes: bitrot detection and cheap snapshot creation trade against free-space and balance concerns. Before rollback, inventory Snapper checkpoints and confirm the subvolume layout. Never treat teaching snapshot IDs as live identifiers.

Check yourself

Why record the subvolume and checkpoint ID before a rollback?

Rollback is targeted. The wrong subvolume or ID can discard the wrong state or miss the intended recovery point.

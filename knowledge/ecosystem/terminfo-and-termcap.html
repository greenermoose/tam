How terminals display text

A terminal draws a grid of character cells. Programs send ordinary text and special control sequences; terminfo and termcap name those capabilities so software can clear the screen, move the cursor, or set colors without hard-coding every terminal type.

How do terminals describe their capabilities?

Full-screen tools and pagers decide how to clear, color, and move the cursor from the terminal type named by TERM. If that name is wrong or missing, keys and layout misbehave.

Type the lines after the dollar sign and press Enter. printenv TERM prints a short name such as foot or xterm-256color. tput cols prints a number: the width of the terminal in character cells.

Mental model

A program writes bytes to its terminal device. Those bytes are either printable characters or control sequences. A desktop terminal emulator (or a kernel virtual console) interprets the sequences and updates a grid of cells. Libraries and tools avoid hard-coding every sequence by consulting a capability database keyed by $TERM.

program  -->  escapes or library  -->  PTY / console  -->  emulator paints cells
                 ^
                 |
         terminfo (usual) or termcap (older)

Termcap is the older database: terminal descriptions as colon-separated capability strings. Terminfo is the usual modern database on Linux: compiled entries that tput, ncurses, and many other tools read. Both answer the same kind of question—“how does this terminal type clear the screen?”—with different file formats.

A wrong TERM means the wrong descriptions: clear may fail, colors may be wrong, or special keys may print garbage.

Worked example

$ printenv TERM
xterm-256color
$ tput cols
80
$ tput lines
24

Captured on Arch Linux with TERM=xterm-256color, 2026-10-30. Your TERM and sizes may differ (for example foot inside the Tamlinux desktop terminal).

What just happened

  1. printenv TERM showed the terminal type name the shell exports to programs.
  2. tput cols and tput lines looked up that type’s capability database and reported the current width and height in cells.
  3. Ordinary characters fill cells; control sequences (looked up by name, not typed by hand here) clear the screen or move the cursor.

Try it

Run printenv TERM and tput cols in your own terminal. Resize the window and run tput cols again. Compare with tput clear, which clears the screen using the same database (your scrollback may keep older lines depending on the emulator).

If it goes wrong

TERM is empty or dumb
Interactive full-screen programs may refuse color or cursor control. Use a real terminal window, or set TERM only when you know the correct type name.
tput: No value for $TERM and no -T specified
TERM is unset. Open a desktop terminal or export a known type such as xterm-256color for a temporary check.

On Tamlinux: the desktop terminal is foot, which sets TERM=foot. When connecting to remote servers that lack the foot-terminfo package, key sequences or backspace may misbehave. Install foot-terminfo on the remote machine or use TERM=xterm-256color as a temporary fallback. Details live under terminal comfort; this page does not retell foot’s Wayland redraw path.

What does tput cols measure?

The width of the terminal in character cells for the current TERM, not the pixel width of the window.

Compiled terminfo and capability names

Reference

ItemMeaning
Compiled terminfoBinary entries under the system terminfo tree (often /usr/share/terminfo), selected by the first character of the type name
Capability namesShort identifiers such as clear, cup (cursor address), setaf / setab (foreground / background color)
VT / ANSI sequencesThe byte strings many emulators actually implement; terminfo stores them per type rather than forcing every app to embed them
infocmpReconstructs or compares terminfo source for a type name

How it works

setupterm and related library calls load the compiled entry for $TERM. Tools such as tput and libraries such as ncurses expand parameterized capabilities (for example cursor address) into the sequences the emulator understands. Capability names are stable labels; the bytes behind them differ across linux, xterm-256color, foot, and others. Emulator behavior and the database entry can disagree: an entry may advertise a feature the emulator implements poorly, or the reverse.

$ infocmp -1 xterm-256color | head -8

Captured on Arch Linux with ncurses 6.6-2, 2026-10-30. Paths and flags vary by distribution.

Why Tamlinux chose this

Tamlinux does not ship a custom terminfo format. It relies on the rootstock’s ncurses terminfo database and on packages such as foot-terminfo when a remote host must understand TERM=foot. That keeps local and remote capability lookup aligned with ordinary Linux practice.

Edge cases

  • Hardware virtual consoles and TERM=linux omit features common in desktop emulators (for example some hyperlink controls).
  • TERM=dumb signals a minimal device; interactive pagers may fall back to plain text.
  • Nested multiplexers can rewrite TERM; check the innermost value programs actually see.

Explore

Run infocmp "$TERM" and find the clear and cup lines. Compare with infocmp -A /usr/share/terminfo -B /usr/share/terminfo "$TERM" xterm-256color only if both entries exist—read the man page before comparing databases.

Check yourself

What breaks if an application hard-codes xterm escape sequences while TERM is linux?

Sequences the Linux console does not implement are ignored or printed as garbage. Capability lookup via terminfo for TERM=linux would select console-appropriate strings instead of assuming an xterm.

Improve it

Terminal emulator settings for Tamlinux live under the desktop configuration; remote terminfo packages are ordinary rootstock packages. Document capability issues with the exact TERM value and infocmp output rather than guessing sequences.

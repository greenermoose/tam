Lua: The Embedded Scripting Language

Lua is a small, fast scripting language designed to be embedded inside larger programs. Tamlinux ships it as a capability of the programs you already run rather than as an application of its own: your compositor, your editor, and your media player each contain a Lua interpreter, and the desktop configuration you edit every day is written in it.

Lua is the language of your desktop

Goal: you will be able to run Lua one-liners, inspect the desktop interpreter version, and locate your compositor's configuration files.

Why it matters: Why Lua is included: unlike traditional Linux desktops that use static INI or XML files, Tamlinux configures the Hyprland compositor, Neovim, and media players with Lua scripts. Knowing how Lua executes and where your configurations live lets you tune keybindings and display layouts safely without altering package files.

Before you start: open a terminal. Lua is installed natively on your system. These commands inspect versions and evaluate expressions in memory; they do not alter files. See The Tamlinux Desktop for desktop navigation basics.

Lua is a lightweight scripting language designed to be embedded inside larger programs. The terminal command lua runs the standalone interpreter. The prompt $ means the shell is waiting; do not type the $. The flag -e executes one line of Lua code directly.

Worked example: Run a one-line Lua command

$ lua -e 'print("hello from " .. _VERSION)'
hello from Lua 5.5

Captured on an Arch Linux workstation, 2026-10-25.

  1. lua is the standalone interpreter installed by the lua package (version 5.5), matching the version Hyprland embeds.
  2. -e executes the given string as a statement without creating a file.
  3. .. is Lua's string concatenation operator.
  4. _VERSION is a global variable holding the interpreter's version string.

Try it

Evaluate a calculation and format text using a temporary scratch script:

$ scratch=$(mktemp -d)
$ cat << 'EOF' > "$scratch/hello.lua"
local msg = "Workstation ready"
local cores = 16
print(msg .. " across " .. cores .. " cores")
EOF
$ lua "$scratch/hello.lua"
Workstation ready across 16 cores
$ rm -rf "$scratch"

The script prints the formatted string and exits immediately. Cleaning up the scratch directory leaves no temporary files on disk.

If it goes wrong

syntax error: unfinished string
A quotation mark was opened but not closed before the end of the line. Check matching quotes.
attempt to concatenate a nil value
A variable referenced in a .. expression does not exist or was misspelled. Lua variables default to nil rather than throwing unbound-variable errors.
command not found: lua
The lua package binary is missing from your PATH. On Tamlinux, /usr/bin/lua is installed by default as a dependency of Hyprland.

Check yourself

Decide your answer before you reveal it.

What operator does Lua use to join two strings together?

Lua uses two dots (..) for string concatenation (e.g. "hello " .. "world"), not +.

What does an uninitialized Lua variable evaluate to by default?

It evaluates to nil. Lua does not abort on uninitialized variables; referencing an unassigned variable returns nil.

Desktop modules, table structures, and compositor configuration

Goal: you will be able to structure Lua tables, inspect your desktop configuration modules in ~/.config/hypr/, and test configuration changes safely using hyprctl reload.

Mental model

~/.config/hypr/hyprland.lua  --> main entry point, prepares module paths
  |--> tamlinux/defaults     --> read-only system baseline
  |--> ~/.config/hypr/bindings.lua --> your keyboard shortcuts
  |--> ~/.config/hypr/monitors.lua --> your display layout
hyprctl reload --> re-executes Lua scripts inside the running compositor

The compositor loads hyprland.lua on startup, which sets the package path and loads individual modules in order. Tables are Lua's only data structuring mechanism: sequential elements form array lists starting at index 1, while named keys form associative dictionaries.

Worked example: Working with Lua tables

$ cat << 'EOF' > table_demo.lua
local users = { "alex", "root" }
for i, name in ipairs(users) do
    print(i .. ": " .. name)
end
EOF
$ lua table_demo.lua
1: alex
2: root

Captured on an Arch Linux workstation, 2026-10-25.

  1. A table in braces is Lua's one structured type.
  2. ipairs traverses the array part of a table in numerical order.
  3. Lua indices count from 1, so the first element is at index 1, not 0.

Completion task

Fill the gap (marked ___) so the script accesses table fields and prints the total wattage:

local watts = { idle = 8, load = 65 }
print("total: " .. ___ .. " W")

Fill in watts.idle + watts.load. Table fields are accessed using dot notation. Arithmetic binds tighter than string concatenation, so watts.idle + watts.load evaluates to 73, producing total: 73 W.

Independent task

Validate the syntax of your local Hyprland configuration files using luac -p ~/.config/hypr/bindings.lua to confirm there are no syntax errors before asking the compositor to reload.

Run luac -p ~/.config/hypr/bindings.lua. If the file is valid, it prints nothing and exits with code 0. If a syntax mistake exists, it reports the exact line number without disrupting your running graphical session.

How a host embeds Lua: the C API stack protocol

Reference: A host program creates one Lua state, loads script files into it, and exchanges values with it over a single shared virtual stack. Positions on that stack count up from the bottom (1, 2, 3…) or down from the top (-1 is the value most recently pushed or returned).

Hyprland implements this directly: readelf -d /usr/bin/Hyprland lists liblua.so.5.5 as a needed shared library, and its binary imports luaL_loadfilex, lua_pcallk, and lua_next to execute your configuration files.

A minimal exchange

The host loads a function from a script file:

function create_window(title, width, height)
  return { title = title, area = width * height, mapped = true }
end

Then pushes the function and its arguments, executes a protected call, and inspects the returned table:

lua_getglobal(L, "create_window");     /* push function       */
lua_pushstring(L, "Terminal");         /* argument 1: title   */
lua_pushnumber(L, 1920.0);             /* argument 2: width   */
lua_pushnumber(L, 1080.0);             /* argument 3: height  */

if (lua_pcall(L, 3, 1, 0) != LUA_OK) { /* 3 in, 1 out         */
    fprintf(stderr, "error: %s\n", lua_tostring(L, -1));
    lua_pop(L, 1);                     /* pop error message   */
    return;
}

if (lua_istable(L, -1)) {              /* result table on top */
    lua_getfield(L, -1, "area");       /* push table.area     */
    printf("area: %.0f\n", lua_tonumber(L, -1));
    lua_pop(L, 1);                     /* pop area value      */
}
lua_pop(L, 1);                         /* pop table           */

The protected call consumed the function and its arguments, leaving one result at -1. Every lua_getfield pushes a value onto the stack, requiring a balancing lua_pop to prevent stack leaks.

Calls worth knowing

CallEffect
lua_getglobal(L, "name")Push the global name (function or value) onto the stack
lua_pushstring, lua_pushnumber, lua_pushbooleanPush a typed primitive value onto the stack
lua_pcall(L, nargs, nresults, 0)Protected call; returns LUA_OK on success; error string at -1 on failure
lua_istable, lua_tostring, lua_tonumber, lua_tobooleanType-check and convert stack values for the C host
lua_getfield(L, -1, "key")Push table.key for the table currently at index -1
lua_pushnil(L) then lua_next(L, -2)Traverse table keys and values; pops key and pushes next key/value pair
lua_pop(L, n)Pop n elements from the top of the stack

How it works: execution lifecycle

When Hyprland initializes, it calls luaL_newstate() to allocate an isolated execution context and luaL_openlibs() to populate standard libraries (math, string, table). It registers custom C functions (such as bind dispatchers and monitor hooks) into the global table. When executing hyprctl reload, the compositor re-runs the Lua scripts in place without restarting the Wayland display server.

Why Tamlinux chose this

Embedding Lua gives users full programmatic control over desktop layouts, conditional keybindings, and dynamic window rules without incurring the memory footprint of heavier language runtimes. The Lua interpreter consumes only ~1.6 MiB of disk space, starts in under a millisecond, and requires zero background daemon processes, upholding Tamlinux's zero-polling and resource efficiency standards.

Edge cases and failure modes

  • Stack leaks in host C code: Failure to balance pushes with pops gradually exhausts the Lua stack space (default limit 1,000,000 slots), eventually causing memory aborts.
  • Unprotected calls: Using lua_call instead of lua_pcall will invoke panic() and terminate the host process if a script encounters a runtime error. Host applications must always invoke user configuration scripts through lua_pcall.
  • Global variable leakage: Variables declared without local pollute the global environment and can inadvertently overwrite host-provided API functions.

Explore: Live repl evaluation

Inspect running compositor state in real time by opening an interactive Lua prompt inside Hyprland:

$ hyprctl repl

You can also evaluate single read-only expressions directly from the terminal:

$ hyprctl repl 'print("active workspace:", hl.activeworkspace())'

Check yourself

Decide your answer before you reveal it.

Why must a C host call lua_pcall rather than lua_call when executing user desktop configuration files?

lua_call is unprotected: if the user's script contains an error (such as a typo or missing variable), Lua triggers an uncaught panic that terminates the entire host process (crashing the compositor). lua_pcall catches errors safely, pushes the error message to the stack, and returns a non-zero status code so the host can display a diagnostic message and continue running.

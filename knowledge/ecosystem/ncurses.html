ncurses

ncurses is a C library that helps programs draw and update a full-screen terminal interface without hard-coding every terminal’s escape sequences.

Recognize programs that use ncurses

Goal: you will be able to name common programs that use ncurses and confirm that a binary links libncursesw.

Why it matters: when colors, clear-screen, or keys break in a full-screen text program, the cause is often TERM or missing terminfo—not the application logic alone. Knowing that the program goes through ncurses points you at the right checks.

Before you start: skim how terminals display text for TERM and terminfo. The example only runs ldd on installed binaries.

ldd lists shared libraries a program needs. A line containing libncursesw means that program is linked against wide-character ncurses. You do not need to call the library yourself to use clear, nano, or tam show.

Worked example

$ ldd /usr/bin/clear | grep ncurses
	libncursesw.so.6 => /usr/lib/libncursesw.so.6
$ ldd /home/alex/src/tam/build/tam | grep ncurses
	libncursesw.so.6 => /usr/lib/libncursesw.so.6

Captured on Arch Linux with ncurses 6.6-2, 2026-10-30. Paths differ on your system; the important part is the libncursesw.so.6 name. On this machine tput and nano also linked libncursesw the same way.

What just happened

  1. clear and tput ship with the ncurses tools and use the library to emit the right sequences for $TERM.
  2. nano is a full-screen editor that uses ncurses to manage the text UI.
  3. tam links the same library so its pager can look up terminal capabilities (explained at intermediate level).

Other full-screen tools on many Linux systems also use ncurses (for example htop, dialog, or ncdu when installed). Only claim a program uses ncurses after ldd (or packaging metadata) shows it; this page does not list tools that were not present on the capture host.

Try it

Run ldd "$(command -v clear)" and look for libncursesw. If you have nano, repeat for that binary.

If it goes wrong

ldd shows no ncurses line
That binary may use another UI library, be a script, or call a helper. Do not assume every TUI uses ncurses.
Command not found
The example program is not installed. Use clear or tam if those are on your PATH.

Two ways to use ncurses

Goal: you will be able to distinguish a full-screen ncurses application from a program that only uses ncurses terminfo helpers, and state how tam fits.

Mental model

Typical flow:

application  -->  ncurses  -->  terminfo for $TERM  -->  update sequences  -->  emulator paints cells

Many TUIs call the high-level API: create a screen (initscr), draw into windows, then refresh so ncurses sends only the changes needed. That virtual screen idea keeps applications from repainting every cell on every keystroke.

Other programs link ncurses but draw themselves. They call lower-level terminfo helpers such as setupterm, tigetstr, and tparm to look up clear, cursor address, and color sequences, then write those sequences with their own UI code.

A wrong TERM still breaks both styles: ncurses can only emit what the named terminfo entry describes.

Does tam use ncurses? Yes. The tam binary links wide-character ncurses (-lncursesw / libncursesw). The interactive pager needs capabilities that vary by $TERM (cursor address, clear, colors, alternate screen, and related strings). Rather than hard-coding escapes, tam_terminal_init in src/terminal.c calls ncurses terminfo entry points (setupterm, tigetstr, tigetnum, tigetflag, tparm). What it does not do: tam does not build its UI with the high-level ncurses window API (initscr, newwin, library-managed refresh). It has its own pager and renderer; ncurses is the capability layer. So tam show is not “an ncurses app” in the same sense as nano, even though both link libncursesw. Build and linkage details also appear on tam and toolchains.

Independent task

Compare ldd on clear and on tam. Both should name libncursesw; then decide which is a small terminfo tool and which is a custom pager that only borrows capability lookup.

Wide-character ncurses and lookup boundaries

Reference

ItemMeaning
ncurseswWide-character build; preferred on UTF-8 workstations
Terminfo lookupLoad compiled entry for $TERM from the terminfo database directories
High-level APIScreen, windows, input queue, refresh optimization (ncurses(3))
Terminfo APIsetupterm, tigetstr, tparm, and related calls (curs_terminfo(3))

How it works

The library requests sequences described by terminfo; the emulator decides what to paint. If the database overstates a feature, or the emulator ignores a sequence, the failure sits on that boundary—not necessarily in application logic. Wide-character builds track display width for Unicode glyphs so columns stay aligned when combining characters or wide East Asian cells appear.

On Tamlinux, tam’s Makefile prefers pkg-config flags for ncursesw. The pager initializes capabilities only when TERM is set and not dumb, and treats missing cursor-address or related capabilities as non-interactive.

Why Tamlinux chose this

Linking the system wide-character ncurses reuses the rootstock terminfo database and keeps tam aligned with the same capability source as tput and common TUIs, without embedding a private escape table.

Edge cases

  • Soname bumps on a rolling rootstock can break a binary built against an older libncursesw until it is rebuilt or pinned.
  • Programs linked only to libtinfo may share terminfo without the full high-level ncurses API.
  • nmtui on this capture host used libnewt / slang rather than libncursesw—another reminder to verify with ldd.

Explore

Check yourself

What fails if terminfo advertises color but the emulator ignores setaf?

ncurses and tools that trust the entry will emit color sequences that have no visible effect (or print noise). The mismatch is between database and emulator, not automatically a bug in the calling application.

The Linux text console

This page explains the text screens you can reach with Ctrl + Alt + F2, how the kernel turns keys into input there, and why a key can behave differently from the same key in a terminal window.

A text screen without a desktop

A Linux computer can show several text screens at once. Each one is a virtual console, often shortened to VT. You can switch between them with the keyboard. Each screen can run its own login and its own programs, and each one keeps working while the others are hidden.

On most systems Ctrl + Alt + F1 through Ctrl + Alt + F12 select a text screen. One of those screens may also hold the graphical desktop. The exact number depends on how the machine started, so the safe rule is to look before you switch.

Why it matters

The text console is the usual recovery route when the desktop is stuck. It also shows a different keyboard path: there is no compositor and no terminal emulator, so the kernel itself decides what each key sends. That makes it a clean place to test a keyboard and a useful contrast with a terminal window.

How to think about it

Think of a building with several identical offices. Only one office has its light on. The keyboard is the person at the front desk: pressing Ctrl + Alt + F2 asks the building manager to switch the light to office 2. The person keeps typing at the same desk, but a different office now receives the paper. Nothing is copied between offices unless a program arranged it.

New words

Virtual console
A text screen managed by the Linux kernel, separate from a terminal window inside a desktop.
Teletype (TTY)
The historical name for a text terminal; Linux still calls its terminal devices TTYs.
Keymap
A table that tells the kernel which character or action each key produces. Console keymaps live under /usr/share/kbd/keymaps/.

Inspect a key on a text console

Goal: you will be able to switch to a text console, identify the bytes and keycodes a key produces there, and return to your desktop safely.

Worked example

First, find which text screen is active without leaving the session. The kernel exposes the answer in sysfs.

$ cat /sys/class/tty/tty0/active
tty1
$ ls -l /dev/tty0 /dev/tty1
crw------- 1 root tty 4, 0 Nov  9 15:46 /dev/tty0
crw------- 1 fred tty 4, 1 Nov 12 21:10 /dev/tty1

Captured on Arch Linux, 2026-11-13. tty1 is the active console. /dev/tty0 is the current console and belongs to root; /dev/tty1 is the first console device and belongs to the logged-in user. Your numbers and owners will differ.

The linux terminfo entry describes the escape sequences the console expects. Its function keys differ from foot's.

$ infocmp -1 linux | grep -E '^\s+(kbs|kcuu1|kcub1|khome|kf1|kf5)='
	kbs=^?,
	kcub1=\E[D,
	kcuu1=\E[A,
	kf1=\E[[A,
	kf5=\E[[E,
	khome=\E[1~,

Captured on Arch Linux, 2026-11-13. \E means the escape byte 0x1B. The Linux console sends ESC [ A for Up and ESC [ [ A for F1. foot sends ESC O A and ESC O P for the same keys, which is why a program that hard-codes one terminal's sequences fails on the other.

Try it

Do this on a text console, not in a terminal window. Save your work first, and note which function key returns to your desktop.

$ showkey -a
$ showkey -k
$ dumpkeys | grep -E 'keycode +(14|28|57|59) '

showkey -a prints the decimal, octal and hexadecimal value of each key according to the current keymap. Press a, Ctrl + H, Backspace, Up and F1, and compare the values. showkey -k prints kernel keycodes instead. dumpkeys prints the loaded keymap. Each mode ends after ten seconds without a key press, except -a, which ends on Ctrl + D.

If it goes wrong

Couldn't get a file descriptor referring to the console
showkey, dumpkeys and loadkeys need a real console. They do not work in a terminal window or over SSH. Switch to a VT first.
The screen is black after switching
Wait a moment. The console may be blanked, or the display may be reconfiguring. Press a key, then try the function key that returns to your desktop. Do not press a sequence of random keys in a panic.
The keyboard does not respond on the console
The console may be in an unusual keyboard mode, or the kernel may be busy. Try another VT. If the whole machine is unresponsive, use the emergency recovery procedure rather than guessing.
You cannot return to the desktop
The desktop may be on a different VT number. Try Ctrl + Alt + F1 through Ctrl + Alt + F7, pausing between attempts. If the desktop crashed, the text console is now the place to diagnose it.

On Tamlinux: the active console is reported by the kernel, not chosen by a Tamlinux convention. Read /sys/class/tty/tty0/active or run fgconsole on a console before assuming that F1 or F2 returns to the desktop.

Check yourself

Decide your answer before you reveal it.

Does Ctrl + Alt + F2 send a special byte to the program on the current console?

No. The kernel's console keymap maps the chord to the action Console_2, and the console driver switches the active VT. The program on the old console does not receive a key press; it simply stops being the visible console.

Why does F1 produce ESC [ [ A on the Linux console but ESC O P in foot?

The two terminals use different key encodings, described by different terminfo entries. The program asks terminfo for the sequence, or parses both. The physical key and the kernel keycode can be the same while the terminal bytes differ.

Is the console keycode for a letter the same as the XKB keycode?

No. The console keymap uses kernel keycodes, such as 30 for a. XKB and Wayland use the kernel keycode plus 8, so the same key is 38. The console never adds that offset.

How it works

The kernel's keyboard driver turns a hardware event into a Linux keycode, the same KEY_A = 30 numbering described on From key press to character. The console layer then looks up that keycode in the loaded keymap. A keymap line names a keycode and the keysym or action it produces under a modifier combination. These lines come from the default US keymap on the machine where this page was checked:

alt_is_meta
keycode  14 = Delete
keycode  15 = Tab
keycode  28 = Return
keycode  29 = Control
keycode  42 = Shift
keycode  56 = Alt
keycode  57 = space
	control	keycode  57 = nul

Keycode 14 is the Backspace position, named Delete in this keymap; keycode 15 is Tab, 28 is Return, 29 is Control, 42 is Shift, and 56 is Alt. alt_is_meta makes Alt act as a Meta modifier. The line for keycode 57 says that Ctrl + Space produces NUL.

Function keys and console switches are ordinary keymap entries too. The default keymap defines F1 to F10 on keycodes 59 to 68, F11 and F12 on 87 and 88, and the console switches as actions:

plain keycode  59 = F1
plain keycode  60 = F2
plain keycode  87 = F11
plain keycode  88 = F12
alt keycode  59 = Console_1
alt keycode  60 = Console_2
control alt keycode  59 = Console_1
control alt keycode  60 = Console_2

That is the precise meaning of Ctrl + Alt + F2: the keymap maps Control plus Alt plus keycode 60 to Console_2. The console driver then activates VT 2. A program can influence that switch only if it has put the VT into process mode; it cannot intercept the key as ordinary input.

In K_XLATE mode the console converts the resulting keysym to a byte or an escape sequence. Printable keysyms become their character code; function keys use the console's own strings, such as ESC [ [ A for F1 and ESC [ 17~ for F6. The program reads those bytes from its controlling terminal.

Advanced usage

The kernel exposes keyboard and VT state through ioctls. These are reference forms, not commands to run casually.

RequestPurpose
KDGKBMODE, KDSKBMODERead or set K_RAW, K_XLATE, K_MEDIUMRAW, K_UNICODE or K_OFF
KDGKBMETA, KDSKBMETARead or set meta handling: K_METABIT or K_ESCPREFIX
KDGKBENT, KDSKBENTRead or write one keymap entry
KDGKBSENT, KDSKBSENTRead or write a function-key string
KDGKBDIACR, KDSKBDIACRRead or write dead-key diacritics
VT_ACTIVATE, VT_WAITACTIVERequest a VT and wait for the switch
VT_GETSTATERead the active VT and the VT state flags
VT_SETMODEChoose VT_AUTO or VT_PROCESS switching
VT_RELDISPAllow or refuse a switch in process mode
VT_OPENQRY, VT_DISALLOCATEFind a free VT or release one

K_RAW delivers raw keyboard bytes, K_MEDIUMRAW delivers keycodes, and K_XLATE delivers translated characters. K_UNICODE is a UTF-8-aware translation mode, and K_OFF disables keyboard input. K_METABIT sets the high bit of a byte for Alt; K_ESCPREFIX prefixes it with ESC instead, which is the safer choice for UTF-8.

The console implements a subset of VT102 and ECMA-48 as documented in console_codes(4). It recognises BEL, BS, HT, LF, VT, FF, CR, SO, SI, CAN, SUB, ESC and DEL, and it supports cursor movement, erase, colour and mode setting. ESC [ ? 1 h enables DECCKM, which makes cursor keys send ESC O instead of ESC [. ESC = and ESC > select application and numeric keypad modes.

Edge cases

  • Process-mode VTs. A program that has called VT_SETMODE with VT_PROCESS must acknowledge a switch with VT_RELDISP. Until it does, the console can appear to ignore the function key.
  • Ctrl + Alt + Del is not a terminal key. The kernel or init handles it as a reboot request. Its effect depends on the running init and its configuration.
  • Magic SysRq. Alt + SysRq + letter is handled by the kernel's sysrq code when enabled. It is not delivered to the console program.
  • Serial consoles. A console on ttyS0 receives bytes from a serial line, not from a local keyboard. The same line discipline and terminal semantics apply, but there is no console keymap and no Ctrl + Alt + Fn.
  • Kernel messages can overwrite the screen. A warning printed to the console changes what you see without changing the program's input. Read the kernel log rather than assuming the program drew the text.
  • Keycode remapping is persistent only if loaded. loadkeys changes the running console; a reboot restores the configured keymap unless the change was installed in the system configuration.

Check yourself

A user says Ctrl + Alt + F2 does nothing on a machine where the desktop is healthy. What layers would you check, and in what order, before changing the keymap?

First confirm that a second VT exists and is not already active: read /sys/class/tty/tty0/active or run fgconsole on a console. Then check whether the focused application or compositor grabbed the chord; a full-screen compositor may handle it before the kernel sees it, or the kernel may be in a VT process mode that refuses the switch. Next check whether the keymap still maps Control+Alt+F2 to Console_2 and whether the function key produces the expected keycode. Only after those should you consider reloading a keymap, because the evidence so far does not show a keymap fault.

How a key press becomes input

This section follows one key press from the keyboard, through the operating system and the terminal, to the exact bytes and signals a program such as an editor receives.

A key press is not a character. It is a small chain of translations, and every link can change the answer. The letter a, the Backspace key, and the chord Ctrl + H are easy to confuse because several layers reuse the same numbers for different purposes. This section separates those layers so you can predict what a program will see, and diagnose the case where it sees something else.

The short version

  1. A switch under the keycap closes. The keyboard's controller identifies the key and sends a report to the computer.
  2. The kernel's input driver turns that report into a numbered key event and publishes it through evdev.
  3. On a graphical session, the compositor reads the event, applies the keyboard layout, and sends a key code and modifier state to the focused window through Wayland.
  4. The program in that window translates the key code into a meaning. A terminal emulator such as foot translates it into bytes and writes them to a pseudo-terminal.
  5. The kernel's line discipline may edit those bytes, turn some of them into signals, or pass them through. The program then reads bytes, not keys.
  6. A full-screen program parses those bytes again, sometimes as escape sequences, and acts.

On a Linux virtual console, steps 3 and 4 are different: the kernel itself applies a console keymap and delivers bytes or escape sequences to the program on that text screen. The destination is still a program reading bytes from a terminal.

Who decides what a key means

LayerQuestion it answersExample
Keyboard hardwareWhich switch moved?USB usage 0x04
Kernel input driverWhich Linux key is it?key code 30 (KEY_A)
Compositor and layoutWhich symbol does this key produce with these modifiers?keysym a, or H with Shift
Terminal emulatorWhich bytes represent that symbol or chord?a, 0x1B 0x5B 0x41 for Up
Line disciplineIs this an editing command, a signal, or data?0x7F erases; 0x03 sends SIGINT
ProgramWhat does this byte sequence mean here?move left, delete a character, open help

The Ctrl + H puzzle

The chord Ctrl + H produces byte 0x08, which is the ASCII Backspace control. Many terminals send 0x7F for the Backspace key instead, so the two are usually different bytes. But not always: foot sends 0x08 for Ctrl + Backspace, and the key parser in libtam 0.7.0 decodes both 0x08 and 0x7F as the same Backspace event. A help command bound to Ctrl + H can therefore open when the reader presses Backspace. The last page of this section works through that case and the alternatives.

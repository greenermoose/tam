Declarative Distributions

In a declarative distribution you do not change the system step by step. You describe the whole system in configuration files, and the system is built from that description. Every build is kept as a generation that you can boot or roll back to. Packages are stored under paths that include a hash of everything used to build them, so different versions never overwrite each other.

Tamlinux already uses this idea without these distributions: it delivers its desktop with the Nix package manager and Home Manager on top of the base distribution. Having the Nix tools does not make a system NixOS. See Packaging and delivery.

NixOS

  • Lineage: independent, built on the Nix package manager and the Nixpkgs collection, one of the largest package collections in Linux.
  • Kernel, init and C library: Linux, systemd, glibc.
  • Releases: stable releases twice a year, each supported for a limited period, and a rolling unstable channel.
  • Tamlinux role: evaluate as a whole-system declarative base, and idea donor for reproducibility.

GNU Guix System

  • Lineage: independent, part of the GNU Project. It applies the same functional approach as Nix, written in the Guile Scheme language.
  • Kernel and init: Linux-libre, a Linux kernel without non-free firmware, and the GNU Shepherd service manager.
  • Known for: strict free-software policy, reproducible builds, and work on building the whole system up from a very small trusted starting binary.
  • Tamlinux role: evaluate; not yet assessed. Its firmware policy matters for hardware support.

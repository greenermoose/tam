The BSDs

The BSD operating systems descend from the Berkeley Software Distribution of Unix. Unlike a Linux distribution, which assembles a kernel and tools from many separate projects, each BSD develops its kernel, C library and core commands together as one base system, released and documented as a whole. Extra software comes from a separate ports or package collection. Most BSD code uses the permissive BSD license.

For Tamlinux the BSDs are horizon systems: not candidate bases today, but sources of well-engineered ideas.

FreeBSD

  • Known for: jails, which isolate groups of processes; first-class ZFS; the bhyve hypervisor; DTrace tracing; and the FreeBSD Handbook, a model of complete documentation.
  • Packages: the ports tree and binary packages with pkg. It can also run many Linux programs through a compatibility layer.
  • Tamlinux role: horizon, and idea donor for a coherent base system, jails, ZFS and documentation.

OpenBSD

  • Known for: security and correctness first, with code audits, secure defaults, and system calls such as pledge and unveil that let a program give up abilities it no longer needs. OpenSSH comes from the OpenBSD project.
  • Releases: about every six months, with binary patches for the supported releases.
  • Tamlinux role: horizon, and idea donor for security engineering and clear manual pages.

NetBSD

  • Known for: portability to a very wide range of hardware. Its pkgsrc package collection also builds on other operating systems, including Linux.
  • Tamlinux role: horizon, and idea donor for portability.

DragonFly BSD

  • Lineage: forked from FreeBSD in 2003.
  • Known for: the HAMMER2 file system with cheap snapshots, virtual kernels that run as ordinary user programs for kernel development, and its own approach to multiprocessor scaling.
  • Tamlinux role: horizon, and idea donor for snapshots and kernel design. Its recent activity has not been checked.

Mental model

A Wayland compositor presents application surfaces and manages placement and input. The desktop shell (panels, menus) is separate. Tamlinux runs Hyprland today and has selected Sway on wlroots as a long-term planned compositor.

Worked example

From a working desktop, press Meta + K and confirm keybindings still list Meta + Return. That shows the compositor is receiving keys. If nothing responds, move to a virtual console instead of forcing power off.

Try it

Press Meta + Return to open a terminal, then Meta + Q to close only that empty window.

If it goes wrong

No response to Meta keys
Switch to a VT with Ctrl + Alt + Fn and continue from text.

On Tamlinux: check packaged bindings under the product session tree, not stock Hyprland defaults.

Check yourself

Is the compositor the same as a web browser window?

No. The compositor is the display server that places all windows; a browser is one client.

Blank-screen boundaries

Separate panel power, cable/protocol, DRM/KMS programming, compositor process, and client faults. Plugin ABI churn and carried multi-monitor patches are reasons Tamlinux plans to leave Hyprland; contribution policy also blocks some upstream paths. Capture hyprctl or DRM connector evidence from a working VT when documenting a fault. Do not restart display stacks as a first exploratory step.

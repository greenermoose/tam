How windows appear on your screen

This page explains the software that puts windows on your screen and lets you move among them.

The compositor draws the desktop

Goal: you will be able to say what a compositor is and that Tamlinux uses Hyprland today on Wayland.

Why it matters: a frozen GUI often needs a text console, not more mouse clicks in a stuck compositor.

Before you start: you need a working graphical session or a text console. Do not restart display services while learning.

If the graphical desktop stops responding, try Ctrl + Alt + F2 (or another Fn key) for a text console. Exact numbers depend on the installation.

Worked example

From a working desktop, press Meta + K and confirm keybindings still list Meta + Return. That shows the compositor is receiving keys. If nothing responds, move to a virtual console instead of forcing power off.

Try it

Press Meta + Return to open a terminal, then Meta + Q to close only that empty window.

If it goes wrong

No response to Meta keys
Switch to a VT with Ctrl + Alt + Fn and continue from text.

Check yourself

Is the compositor the same as a web browser window?

No. The compositor is the display server that places all windows; a browser is one client.

The Tamlinux desktop.

Compare compositor roles

Goal: distinguish the current compositor from planned alternatives and from the shell.

Mental model

A Wayland compositor presents application surfaces and manages placement and input. The desktop shell (panels, menus) is separate. Tamlinux runs Hyprland today and has selected Sway on wlroots as a long-term planned compositor.

Why Wayland

  • Client isolation compared with classic X11 open access.
  • Whole-frame presentation that reduces tearing.
  • Per-monitor scaling for mixed displays.

Why Sway is planned

  • Small C code base and stable i3-compatible IPC.
  • Software rendering paths useful on older GPUs.
  • Seat access via seatd/libseat without requiring systemd-logind.

The Sway transition remains planned (integration, daily use, Hyprland removal). Adapters in source are not proof of delivery. Independence from Omarchy on the Hyprland desktop is complete; Omarchy is a peer, not a runtime dependency.

On Tamlinux: check packaged bindings under the product session tree, not stock Hyprland defaults.

Worked example

Identify the current compositor name from session documentation or process list when the desktop works; treat Sway mentions as planned unless evidence shows otherwise.

Blank-screen boundaries

Separate panel power, cable/protocol, DRM/KMS programming, compositor process, and client faults. Plugin ABI churn and carried multi-monitor patches are reasons Tamlinux plans to leave Hyprland; contribution policy also blocks some upstream paths. Capture hyprctl or DRM connector evidence from a working VT when documenting a fault. Do not restart display stacks as a first exploratory step.

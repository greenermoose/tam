Shell and Bar Plugins

This page explains how Tamlinux status bar plugins work, how to manage them, and how to author new extensions.

What is a Tamlinux plugin?

A plugin is an extension module that adds items to the top status bar or opens specialized desktop panels. Plugins can display a clock, battery metrics, workspace status, or system resource meters.

Why it matters

Plugins let you customize what information is visible on your screen at a glance without modifying the compositor or rewriting the main desktop shell.

How to think about it

Tamlinux desktop plugins (named in the fred.* namespace) run inside Quickshell. Each plugin lives in its own directory with a declarative manifest and QML interface files. Plugins interact with the system through bounded helpers rather than arbitrary root access.

New words

QML
Qt Modeling Language; a declarative language used to define user interface components and layouts.
Manifest
A JSON description file (manifest.json) declaring a plugin's identifier, version, title, entry points, and permissions.
Quickshell
The flexible Wayland desktop shell engine powering Tamlinux panels, bars, and overlays.

Inspect and test plugins safely

Goal: you will be able to list installed desktop plugins and understand how development plugins are linked for testing.

Worked example

  1. List installed plugins and their active states: 
    $ tam-plugin list
fred.bar
fred.clock
fred.monitor
fred.sysinfo
fred.workspaces
  2. Inspect the status of a specific plugin: 
    $ tam-plugin status fred.clock
Plugin: fred.clock
Version: 1.3.3
Status: active
  3. When authoring a plugin, link your development checkout into the local test directory: 
    $ tam-plugin dev link my-plugin

Try it

Run tam-plugin --help in your terminal to see the commands available for listing, enabling, linking, and testing plugins.

If it goes wrong

Plugin fails to appear on the bar
Check the journal for Quickshell QML parse errors using journalctl --user -u quickshell.
Plugin shows old assets after editing
Restart the shell or run tam-plugin dev reload to clear live memory caches.

Plugins follow strict security architecture: single entry point, bounded execution environments, and no privileged commands.

Check yourself

Which command manages and tests Tamlinux shell plugins?

tam-plugin.

What language is used to write Tamlinux desktop plugin user interfaces?

QML (Qt Modeling Language) running under Quickshell.

Plugin architecture and development

Tamlinux product plugins are developed in the core repository under desktop/plugins/fred.<id>/. Each plugin directory contains:

  • manifest.json: declares id, name, version, author, and QML entry point.
  • Bar.qml or Panel.qml: top-level interface component.
  • assets/: icons and static graphic resources.
Command / ToolRole
tam-pluginManage live, development, and test plugin registrations
tam-plugin devLink development checkouts into active testing directories
tam-plugin testRun plugin test suites against isolated mock environments

All plugins run within the unprivileged user session. Any persistent settings should be stored under descriptor-relative cache paths or standard XDG state directories.

The speed and energy use of AI on your computer

This page explains what affects the speed and energy use of artificial intelligence running on your own computer.

An AI model is software that produces an answer from a request. Running it on your own computer may avoid sending the request elsewhere, but privacy depends on the software and settings you choose.

What limits local AI inference?

An oversized workload can slow the machine, fail to load, or trigger memory pressure. The exact result depends on the runtime, memory and swap configuration.

How to think about it

Local generation speed is bounded by memory bandwidth and model size. Check headroom before starting a large model.

Check memory before inference

Goal: inspect memory headroom and identify where a query is sent before asking a local model.

Before you start: open a terminal and read resources. The example only reads memory statistics.

New to this? Type the command after the dollar sign and press Enter. Output is a snapshot and changes as programs run.

Mental model

Model weights, context and runtime state occupy memory. Computation and memory transfers both influence response time. Device placement, context, quantization, concurrency and other work affect measurements.

Worked example

$ free -h
               total        used        free      shared  buff/cache   available
Mem:            28Gi        10Gi       8.7Gi       121Mi        10Gi        17Gi
Swap:           56Gi       6.1Gi        50Gi

Captured on Arch Linux, 2026-10-27. Available memory estimates headroom; model weights, context, runtime overhead and other work all consume resources. This snapshot does not guarantee that a particular model fits.

Try it

Run free -h and compare available memory with the model's documented requirements. If the model, server or headroom is unknown, leave inference pending.

If it goes wrong

A missing model or server is different from memory pressure. Read the message and inspect the configured endpoint. Do not download a model or change swap merely to complete this exercise.

On Tamlinux: tam ask defaults to http://127.0.0.1:11434, but --server or TAM_ASK_SERVER can select another host. The current client accepts non-loopback hosts and sends plain HTTP, even when a URL begins with https://. Do not use it to send sensitive data to a remote endpoint. A server or model can have its own network behavior.

Check yourself

Does available memory alone guarantee a model will run without pressure?

No. Runtime overhead, context and competing workloads also matter, and available memory changes.

Is a cited answer automatically correct?

No. Open the cited source and check whether it supports the answer.

Limits of resource estimates

Weight size is only one part of a deployment's memory use. Context state and runtime buffers depend on implementation and configuration. Memory bandwidth can constrain autoregressive inference, but compute, data placement, caching, batching and scheduling can also matter. Treat a bandwidth calculation as an upper-bound model with explicit assumptions, then measure the actual workload.

The current tam ask implementation resolves its configured host and uses plain HTTP sockets; its help describes a local server but does not enforce loopback or transport encryption. Review the endpoint before submitting a prompt and do not treat an https:// prefix as TLS protection in this client.

Check yourself

How would you distinguish a memory-bandwidth limit from another bottleneck?

Hold model, context and workload constant; measure throughput and resource use across comparable runs, then vary one relevant factor at a time. Record uncertainty and avoid attributing a slowdown to bandwidth from core count alone.

See resource inspection and the inference runtime's own documentation for its allocation and networking behavior.

Shell Scripting and Tool Conventions

Scripts in Tamlinux automate tasks safely and predictably. By following strict Bash execution headers, safe argument forwarding, and deliberate naming namespaces, you can write scripts that run reliably across different machines and user accounts.

Beginner: The strict Bash script template

Summary: Write dependable scripts using a defensive header that catches silent errors, uninitialized variables, and pipeline failures.

Prerequisites: Shell pipelines (Shell Pipelines) and permissions (File Permissions and Ownership).

The canonical script template

#!/usr/bin/env bash
set -euo pipefail

echo "Script executed safely with arguments: $#"

Why each flag matters

FlagNameProtective Behavior
-eerrexitExits immediately if any command exits with a non-zero status.
-unounsetTreats references to unset variables as fatal errors, preventing accidental operations on empty paths.
-o pipefailpipefailPrevents pipeline masking: the return value of a pipeline is the status of the last command to fail, not the last command executed.

What just happened

  • The shebang #!/usr/bin/env bash locates the bash executable portably across Nix, Arch, and standard Linux distributions.
  • With set -euo pipefail active, typographical errors in variable names (like rm -rf "$MISTYPED_DIR/*") abort immediately with an error rather than wiping unintended files.

Common pitfall

Never rely on unquoted variables when passing arguments. Always quote variable expansions (e.g. "$target" instead of $target) to prevent accidental word splitting when paths contain spaces.

Intermediate: Safe argument handling and cleanup traps

Summary: Forward argument arrays without mangling spaces, and ensure temporary files are guaranteed to be cleaned up on exit.

Worked example

Handle arbitrary filenames containing spaces and ensure temporary directories are removed even if the script fails midway:

#!/usr/bin/env bash
set -euo pipefail

tmp=$(mktemp -d)
trap 'rm -rf "$tmp"' EXIT

for file in "$@"; do
    cp "$file" "$tmp/"
done
echo "Processed $# files safely in $tmp."

Verification hints

  • The pseudo-signal EXIT (or 0) catches normal exits, set -e aborts, and syntax errors.
  • To also handle abrupt terminal interruptions, specify EXIT INT TERM.
  • Always quote "$@" (double quotes) to expand each argument as a separate, distinct word.

Expert: Tool namespaces (tam-* vs fred-*) and POSIX exit contracts

Summary: Master the architectural separation between system-wide portable tools and personal user scripts, and standard exit codes.

The Tamlinux command namespace contract

To keep the operating system clean and shareable, Tamlinux establishes a strict namespace separation between public tools and personal scripts:

PrefixOwnershipScope and Design Rules
tam-*Tamlinux ProductPortable, system-wide commands developed in public repositories (e.g. tam-work, tam-update). They must never contain hardcoded user home directories, must support --help and --version, and must operate cleanly in non-interactive pipelines.
fred-*Personal MachinePrivate, user-specific scripts tailored to a single user's workstation, local aliases, or specific hardware setups.

Standard exit code contracts

Tamlinux tools adhere strictly to the POSIX exit code conventions:

  • 0: Success. Expected output emitted to standard output; standard error is empty.
  • 1: General runtime error. Truthful, informative diagnostic message written to standard error; no partial corrupt state left on disk.
  • 2: Command-line usage or syntax error (invalid flags, missing mandatory arguments, or non-interactive refusal contract). Points the user directly to --help.

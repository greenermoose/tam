Terminal and Editor Ergonomics

Your terminal is the central workbench of a Tamlinux system. Tamlinux pairs an ultra-low-latency Wayland terminal with the micro text editor, delivering intuitive editing, rich Markdown highlighting, and automatic live disk reloading when files are edited by background AI agents.

Beginner: Intuitive terminal editing with Micro

Summary: Edit configuration files and Markdown documents effortlessly using standard, universal keyboard shortcuts.

Prerequisites: Basic command execution and shell streams (The Shell and Streams).

Command sequence

micro README.md

Or launch the editor anywhere from the desktop with the keyboard shortcut:

SUPER + Shift + W

What just happened

  • micro opened directly in your terminal without modal modes or complex command syntax.
  • Terminal mouse clicking, scrolling, and dragging work out of the box to position the cursor or select text.
  • High-contrast syntax highlighting is applied automatically for Markdown, HTML, C, JSON, and shell scripts.

Common pitfall

Do not attempt modal Vi commands like :wq in Micro. Use the familiar Ctrl+S to save and Ctrl+Q to quit.

Intermediate: Multi-agent pair programming and live disk reload

Summary: Experience how Micro's live disk autoreload synchronizes buffer contents when background AI agents or Git commands modify files on disk.

Worked example

Open a document in micro, then append content from another terminal or background AI process:

echo -e "\n## Appended by agent" >> README.md

When you return focus to micro, the editor detects the updated on-disk inode and timestamp via stat(2), refreshes the buffer contents instantly, and preserves your exact cursor position and undo history.

Completion task

Ensure that Micro always prompts or reloads external changes automatically without asking. Complete the configuration command below by filling in the missing setting (marked with ___):

micro -set ___ true

Target output: Set autoreload to true.

Verification hints

  • The setting is named autoreload and persists in ~/.config/micro/settings.json.
  • Inspect active editor configuration by pressing Ctrl+E inside Micro and typing show autoreload.

Expert: Sub-10ms shell startup and Wayland terminal architecture

Summary: Benchmark interactive shell startup latency, prune expensive shell hooks, and understand the foot Wayland terminal engine.

Sub-10ms shell startup latency

A responsive workstation demands that new terminal windows appear instantly. Tamlinux mandates a sub-10ms startup budget for interactive shells. Benchmark your startup time with:

time bash -i -c exit

Target performance: real 0m0.006s (6 milliseconds). To maintain this budget:

  • Keep ~/.bashrc strictly free of dynamic command substitutions (such as $(git branch) or $(nvm ...) on every prompt).
  • Place environment variables in ~/.bash_profile or ~/.config/bash/tamlinux/env so they are evaluated once at login rather than on every subshell.
  • Use lightweight, pre-computed prompt symbols without spawning subprocesses.

The foot terminal architecture

Tamlinux standardizes on foot as its primary Wayland terminal emulator. Unlike bloated Electron or VTE-based terminals, foot:

  1. Communicates directly with the Wayland compositor via shared memory (wl_shm) or DMA-BUF without X11 translation layers.
  2. Pre-renders glyphs in an asynchronous thread with FreeType and HarfBuzz, caching them in GPU-accessible textures.
  3. Emits damage regions precisely matching modified character cells, resulting in zero compositor repaints when idle.

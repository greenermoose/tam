Contributing to Tamlinux

This page explains how to report problems, propose ideas, claim working paths in shared repositories, and test contributions.

How to contribute

You can help improve Tamlinux by reporting bugs, suggesting features, writing documentation, or submitting code changes. Clear reports help developers understand and fix issues quickly.

Why it matters

Tamlinux values precision and transparency. Every bug report with verifiable journal evidence makes the system more reliable for all users.

How to think about it

Keep changes focused and test each step. Developers work directly in shared checkouts and coordinate paths using non-overlapping claims.

New words

Bug report
A clear description of an unexpected behavior, including reproduction steps and journal log excerpts.
Path claim
A recorded reservation on specific repository directories so concurrent developers do not overwrite each other's work.
Fleet
A group of computers running Tamlinux coordinated under registered host profiles.

Claim paths and test components safely

Goal: you will be able to check working claims and run local component checks without building a full release.

Worked example

  1. Check active repository claims before starting edits: 
    $ tam-work status
  2. Claim the repository paths you will change: 
    $ tam-work begin --scope knowledge/my-topic.html --note 'Improve documentation'
  3. Build and test your local component changes using the developer loop: 
    $ tam-dev check tam
  4. When working with multiple machines in a fleet, inspect host deployment status: 
    $ tam-fleet status

Try it

Run tam-dev --help in your terminal. It displays the available subcommands for building, checking, and running preview trials of Tamlinux components.

If it goes wrong

tam-work reports a path conflict
Review tam-work status; wait for the other session to finish or choose disjoint paths.
Component check reports build errors
Inspect compiler diagnostics; remember never to invoke Nix directly during rapid local dev loops.

Public Tamlinux repositories maintain provenance records under docs/ai/ and AI_PROVENANCE.md for all AI-assisted contributions.

Check yourself

Which tool coordinates path claims in a shared checkout?

tam-work.

What command tests local components without assembling a full package candidate?

tam-dev.

Developer and contribution command family

CommandRole
tam-workManage concurrent developer session claims, inbox messages, and scopes
tam-devFast developer loop for building, checking, and previewing components
tam-fleetOne-shot host registration, reconciliation, and fleet deployment

All contributions follow strict repository etiquette: commit only your claimed paths, never run blanket staging (git add -A), and cite real journal evidence with boot IDs for any diagnosed bugs.

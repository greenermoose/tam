Native Toolchains and Multi-Agent Workflows

Tamlinux builds its core commands in native C against libtam, achieving sub-5 millisecond startup times and minimal memory consumption. By combining optimized C compilation with one shared clone and path claims, multiple autonomous AI coding agents can develop, test, and package software concurrently without stepping on one another.

Beginner: Building native C projects with Make

Summary: Compile native C programs, inspect compiler flags, and run local development builds without requiring root privileges.

Prerequisites: Terminal and editor ergonomics (Terminal and Editor Ergonomics).

Command sequence

make -C ~/src/tam test-command
./build/tam --version

Expected output:

cc -DTAM_DATADIR=... -O2 -Wall -Wextra -Wpedantic -std=c11 src/tam.c ... -ltam -o build/tam
tam command 0.25.2 (dev 1a2b3c4)

What just happened

  • make -C instructs GNU Make to build the C binary directly in the project directory using GCC or Clang.
  • The binary is compiled with -O2 optimizations and linked with an embedded runpath (-Wl,-rpath) that finds libtam.so automatically.
  • The resulting standalone executable starts in less than 5 milliseconds and requires no external interpreter runtime.

Common pitfall

Never install development binaries directly into system directories like /usr/bin or /usr/local/bin. In Tamlinux, development builds install cleanly under PREFIX=$HOME/.local/dev, which is placed first on $PATH without touching root.

Intermediate: Concurrent work in one shared clone

Summary: Several people or AI agents work in the same checkout at once. Each claims the paths it will edit, commits only those paths, and releases the claim when done.

Worked example

Before editing, claim exactly the files you will change. Set your identity once per session:

export TAM_WORK_OWNER=alex TAM_WORK_SESSION=docs-fix-1
tam-work begin --scope knowledge/shell/jobs.html --note 'Label the job examples'

Another session can claim src/pager.c in the same checkout at the same time, because the paths do not overlap. When your change is ready, commit only your paths and release the claim:

git commit -m 'Label the job examples' -- knowledge/shell/jobs.html
tam-work finish --note 'Committed the job example labels'

Never use git add -A, git add . or git commit -a in a shared clone: they would commit another session's unfinished work. Do not switch branches, stash, reset or rebase there either.

Completion task

Fill in the missing tam-work option (marked with ___) so the claim covers two files:

tam-work begin ___ src/pager.c ___ tests/run.sh --note 'Pager fix'

Verification hints

  • The option is --scope, repeated once per path.
  • tam-work status lists every active claim, so you can see who is working on what before you begin.

Why not Git worktrees?

Git can also give one repository several working directories with git worktree. Tamlinux's own repositories do not use them. Each extra checkout has to be set up, built and merged back, and for small changes that setup cost more than the change itself; tests that look for sibling repositories also failed inside a worktree. Instead, everyone works in one shared clone and claims the paths they will edit. Sessions whose paths do not overlap work at the same time in the same checkout, and each commits only its own paths.

Expert: Compiler optimization flags and tam-work scope reservation

Summary: Understand machine code generation flags (-march=native, -flto), dynamic linking rpaths, and the tam-work concurrency coordination contract.

Native compilation optimization flags

Tamlinux builds optimize C code specifically for the host workstation's CPU microarchitecture:

Compiler FlagPurposePerformance Benefit
-O2Standard optimizationEnables loop vectorization, function inlining, and instruction scheduling without code size explosion.
-march=nativeTarget host CPUEnables all instruction set extensions supported by the local processor (AVX2, FMA, BMI2, AES-NI).
-pipeCompiler pipesUses pipes rather than temporary disk files between compilation stages, speeding up builds in memory.
-Wl,-rpath,DIREmbedded library pathBinds the exact runtime directory of libtam.so into the ELF binary header, eliminating dynamic linker lookup ambiguities.

Concurrency coordination with tam-work

When multiple autonomous agents (e.g. Claude, Codex, agy, OpenCode) collaborate in a shared repository checkout, they coordinate file access using tam-work:

tam-work begin --scope src --scope knowledge --note "Feature development"
  • Lanes: Repositories divide into independent lanes (e.g. in tam: the command lane in src/ vs the corpus lane in knowledge/). Agents claiming disjoint lanes work in parallel without blocking.
  • Strict Git hygiene: Agents commit strictly their claimed paths (git commit -m "..." -- <paths>), never running indiscriminate git add -A.
  • Handoff: When a task finishes or is accepted, the agent releases its reservation with tam-work finish.

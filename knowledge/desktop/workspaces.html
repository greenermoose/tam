Organizing windows and screens

This page explains how to organize open windows into groups and move between them.

What is a workspace?

A workspace is a group of windows you can switch between. You can move between groups, move a window into another group, or move a whole group to another screen.

Why it matters

Workspaces keep related windows together so you can leave a messy layout behind without closing programs.

How to think about it

Think of workspaces as separate desks in the same room. Switching desks changes which papers you see; moving a paper to another desk is different from walking to that desk yourself.

New words

Workspace
A named group of windows you can switch to as a set.
Focus
The window that receives keyboard input.

Choose the right thing to move

Goal: move an empty practice window between workspaces and return it, without confusing window movement with display layout changes.

Use the active bindings from Meta + K if you have overrides. The example below uses the packaged US QWERTY number-row bindings.

Worked example

  1. Record your starting workspace. Open an empty terminal with Meta + Return.
  2. Choose a known practice destination, for example workspace 2.
  3. With the empty terminal focused, Meta + Shift + 2 moves it to workspace 2 and follows it.
  4. Move the same terminal back with Meta + Shift plus the starting workspace key. Close the empty terminal only after confirming focus.

The sequence is sourced from the binding definitions; live GUI behavior and personal overrides still need human verification.

What just happened

  1. A workspace switch changes which group you are viewing.
  2. A window move changes which group contains the focused window.
  3. Recording the start point gives a specific undo step.

Try it

With an empty practice terminal, compare a workspace switch (Meta + 3) with a window move (Meta + Shift + 3), then return both your focus and the window to their starting workspace.

If it goes wrong

Window stayed behind
You switched workspace only. Return, focus the practice window, and use the move binding.
Move to monitor does nothing
There may be no display in that direction. Use a workspace operation instead.

Ctrl + Shift + S moves the focused window silently to the scratchpad; Meta + S toggles it. See The Meta key and desktop modifiers.

Check yourself

Which operation moves one utility window without changing every other window's workspace?

Move the focused window to a workspace or the scratchpad.

Why record the starting workspace instead of assuming workspace 1?

You may have existing work elsewhere. Recording the start gives a specific undo step.

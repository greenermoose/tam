Organizing windows and screens

This page explains how to organize open windows into groups and move between them.

A workspace is a group of windows you can switch between. You can move between groups, move a window, or move a group to another screen.

Choose the right thing to move

Goal: move an empty practice window between workspaces and return it, without confusing window movement with display layout changes.

Mental model

display --shows--> workspace --contains--> windows
focus selects a window; a movement command selects what changes location

Use the active bindings from SUPER+K if you have overrides. The example below uses the packaged US QWERTY number-row bindings.

Worked example

  1. Record your starting workspace. Open an empty terminal with SUPER+RETURN.
  2. Choose a known practice destination, for example workspace 2, without assuming it is empty.
  3. With the empty terminal focused, SUPER+SHIFT+2 moves it to workspace 2 and follows it.
  4. Move the same terminal back with SUPER+SHIFT plus the starting workspace key. Close the empty terminal only after confirming focus.

The sequence is sourced from the binding definitions; live GUI behavior and personal overrides still need human verification.

Completion task

Fill the missing modifier: SUPER+___+3 moves the active window to workspace 3, while SUPER+3 changes your workspace.

SHIFT. The packaged move follows the window. Adding ALT to SUPER+SHIFT+3 requests a silent move instead; choose deliberately.

Independent task

With an empty practice terminal, compare a workspace switch with a window move, then return both your focus and the window to their starting workspace.

Record the starting workspace. SUPER+3 switches without moving the terminal; switch back. SUPER+SHIFT+3 moves the focused terminal and follows it. Move that terminal back with SUPER+SHIFT plus its original workspace key. Recheck focus before closing it.

SUPER+ALT+S moves the focused window silently to the special scratchpad; SUPER+S toggles it. The number-row bindings use key codes. Other keyboard layouts or personal overrides can change the apparent keys.

Check yourself

Decide before revealing the explanation.

Which operation should you choose to move one utility window without changing the workspace of every other window?

Move the focused window to a workspace or the scratchpad. Moving a whole workspace to a monitor changes a different scope.

Why should the exercise record its starting workspace instead of assuming workspace 1?

The reader may have existing work elsewhere. Recording the starting state gives a specific undo step without imposing another layout.

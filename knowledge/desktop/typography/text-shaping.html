Guide / Desktop and applications / Typography / From characters to shaped glyphs

Typing a few letters does not directly choose the shapes you see. A program first works out which glyphs belong together and where each one should sit.

Letters are not always separate

When you write some words, two letters may join into one shape. In other scripts, a letter changes form depending on what comes before it, or a mark moves above and below a base letter. That work is called text shaping.

Shaping uses a Unicode string and a font to produce a list of ready-to-draw shapes with positions. The list then goes to the part of the system that paints pixels.

Why it matters

A typed character is an idea, not a drawing. The same idea can be drawn several ways. Shaping picks the right way for the font and the writing script before drawing begins.

How to think about it

Think of a row of people entering a room. Some pairs hold hands and walk as one, some change clothes when they meet, and others stand above or below a friend. The final arrangement is what you see; the original list of names is still the same.

New words

Code point
A number that stands for one character in Unicode.
Grapheme
The smallest unit a reader thinks of as one character.
Ligature
One shape used for a pair or group of letters, such as fi.
Glyph run
A stretch of text using one font and one direction, ready to be positioned.

If it goes wrong

You expected the typed order and the drawn order to match.
Bidirectional scripts reorder runs after determining direction; the drawn order can differ from the stored order.
A ligature did not appear.
The font must contain the feature and the shaping engine must have the right script and language. A missing feature leaves the original glyphs in place.

Check yourself

Decide your answer before you reveal it.

Which step turns f plus i into a single glyph?

GSUB, the substitution stage. The cmap lookup first maps each character to its own glyph ID; GSUB then applies the ligature substitution to replace that pair with one glyph.

Why can two programs draw different shapes for the same Unicode string?

They may choose different fonts, pass different script or language tags, support different OpenType features, or fall back to different fonts for part of the string. The input characters do not fix the output shapes by themselves.

How it works

Unicode identifies characters as numbers. Unicode normalization matters because a letter with an accent can be one precomposed code point or a base plus a combining mark; the two forms must normalize before comparisons and feature matching behave consistently. Cluster segmentation then groups the code points a reader treats as one unit. The bidi algorithm uses directional properties to turn stored logical order into visual order, with neutral characters resolved from their neighbours.

The font's cmap maps each code point to a glyph ID. An unmapped code point yields the missing-glyph glyph, which is why shaping can succeed while the screen shows boxes. Coverage is checked per run: when one font lacks a code point, Pango can split the run and ask another font for that stretch.

GSUB lookups are organised by script, language system and feature. A ligature substitution replaces a sequence with one glyph; a contextual alternate changes a glyph because of its neighbours; mark forms choose the appropriate shape for an attached mark. GPOS then applies pair adjustment, which is the general form of kerning, plus mark-to-base, mark-to-ligature and cursive attachment. The old kern table only adjusts pairs and lacks the script-aware structure of GPOS. Feature files that define these lookups are described in the Adobe type notes. Unicode Standard OpenType specification 1.9.1 Adobe type notes and AFDKO feature-file spec

GDEF makes the mark rules usable: it labels base, ligature, mark and component glyphs, groups marks by attachment class and can record caret positions inside ligatures. Without those classes, a mark has no reliable point to attach to. The same table also helps a shaping engine skip mark glyphs when deciding whether characters join.

Arabic joining needs contextual substitution to pick isolated, initial, medial or final forms, followed by mark positioning. Indic scripts can reorder consonant and vowel signs before drawing, with GDEF classes helping GPOS attach marks to the right base. Thai places vowel and tone marks above or below a base by using mark attachment classes. These are font-and-engine features, not special cases in the rasterizer.

Shaping is not rendering. HarfBuzz returns glyph IDs, advances and offsets in font units; Pango arranges those runs into lines; the toolkit asks the rasterizer to turn each outlined glyph into pixels. Colour emoji and bitmap glyphs may skip the outline path, but they still need the run and substitution decisions. HarfBuzz manual Pango reference and rendering pipeline

Comparing the first two commands shows which glyph IDs change when a feature is disabled. The third lists the features the font advertises. All three only read the font file.

Edge cases and failure modes

  • A zero-width joiner can request a joining form; if the font has no such substitution, the joiner may render as a missing glyph.
  • Fallback splits a run, so kerning and ligatures cannot span the boundary between two fonts.
  • Vertical writing uses different metrics tables, but the substitution and positioning stages still produce glyph IDs and offsets.
  • Bidi isolation controls are needed when numbers or neutral punctuation sit inside a right-to-left run.
  • Caching shaped runs by text alone is wrong: font, script, language, direction and feature settings are all inputs.

Check yourself

Why might a missing ligature be a font problem rather than a rasterizer problem?

Ligatures are GSUB substitutions applied before rasterization. If the font has no substitution for that sequence, the rasterizer receives two ordinary glyph IDs and draws them. Changing antialiasing or hinting cannot create the missing shape.

What is lost if a program skips bidi ordering but still uses the correct font?

Mixed-direction text appears in the wrong visual order. The glyphs are correct, but neutral characters and runs are placed on the wrong side, so a reader sees numbers or punctuation where they do not belong.

Guide / Desktop and applications / Typography / Readable text and accessibility

Readable text is easier to see, follow, and understand. Good typography helps, but it works only when the text also has enough contrast, sensible spacing, and clear structure.

Making words easy to read

When people talk about accessible text, they often start with the font family, the named design used for letters. The font matters, but it is only one part. A beautiful font can still be hard to read if it is too small, too pale, packed into long lines, or squeezed together.

Why it matters

Readers come with different eyes, screens, lighting, and reading needs. Someone may read on a dim phone outdoors, use large text, read with dyslexia, or listen with a screen reader. Choices that help one of these situations often help everyone.

How to think about it

Think of text like a sign on a path. The letter shape is the lettering style, but the sign also needs enough contrast against its background, enough size to see from the right distance, and enough space around it so it is not cluttered.

New words

Contrast
The difference in brightness between text and its background.
Leading
The vertical space between lines of text.
Measure
The length of a line of text.
Monospace
A font where most characters take the same horizontal width.
Proportional
A font where character widths vary, such as narrow i and wide w.

A monospace font helps code because columns, indentation, and similar characters line up. A proportional font usually helps ordinary reading because its spacing fits the natural shape of words. Neither is always better; the job decides.

Some typefaces are designed for legibility. Atkinson Hyperlegible is a typeface designed to make letters easier to distinguish. Dyslexia-friendly design can also help by avoiding ambiguous letterforms and crowded spacing, but no single font fixes every reading difficulty. Good layout, plain language, and user control still matter.

A screen reader does not read pixels. It reads structure: headings, paragraphs, labels, links, and language information. A visible font choice can make text easier to see, but it cannot replace semantic structure.

What just happened

  1. The sample file showed three color pairs with precomputed contrast ratios. The values are teaching samples, not a measurement from your screen.
  2. The muted gray text had a 4.47:1 ratio. For normal-sized text, WCAG 2.2 asks for at least 4.5:1 at Level AA and 7:1 at Level AAA.
  3. The banner sample passed 3:1 for large text, but that does not make it good for small body text.

A small contrast-ratio worked sample

Contrast is calculated from relative luminance. You do not need to memorize the formula to use it, but seeing one example makes the rule less mysterious. Suppose body text is near-black #222222 on white #ffffff. White has relative luminance 1.0. The dark gray has relative luminance about 0.015. The contrast ratio is:

(L1 + 0.05) / (L2 + 0.05)
(1.0 + 0.05) / (0.015 + 0.05)
1.05 / 0.065 = 16.15:1

That is far above the 4.5:1 AA threshold for normal text. Now compare #777777 on white. Its relative luminance is about 0.184, so the ratio is about 4.47:1. It looks readable to some people, but it misses normal-text AA. This is why "looks fine to me" is not enough.

Size, measure, and spacing

Text size should respond to the reader. Browser zoom, system text scaling, and large-text modes are accessibility features, not design failures. Measure matters too: very long lines make it harder to find the next line. A common range for body text is around 45 to 75 characters, but the right value depends on font, language, and layout. Leading should give lines room to breathe; tight lines make reading tiring, especially at small sizes.

Fonts, dyslexia, and screen readers

For code, a monospace font makes columns and symbols predictable. For prose, a proportional font usually reads more naturally. Distinct letterforms can help readers tell I, l, and 1 apart. Atkinson Hyperlegible is one example designed around character recognition.

Dyslexia-friendly design is broader than picking one "dyslexia font". Evidence varies across readers. Useful choices include clear letter shapes, generous spacing, avoiding justified text rivers, and letting users pick fonts and sizes. Most important, visible font styling does not help a screen reader unless the document has semantic structure: real headings, lists, labels, language, and reading order.

Try it

Pick one page or app theme you use. Check body text contrast, zoom to 200%, and see whether lines still wrap without losing content. Then try a screen reader or heading outline: can you understand the page from structure alone?

If it goes wrong

The contrast ratio passes, but text still feels hard to read.
Check font size, weight, line length, leading, and background noise. Contrast is necessary, not sufficient.
A dyslexia-friendly font did not help a reader.
Do not force one font. Offer choices, increase spacing, improve layout, and keep the content plain.
Large text breaks the layout.
The layout is too rigid. Responsive spacing and reflow are part of accessibility.

Check yourself

Decide your answer before you reveal it.

A theme uses 4.47:1 contrast for body text. Is that enough for WCAG AA?

No. Normal text needs at least 4.5:1 for WCAG 2.2 Level AA. Large text can pass at 3:1, but small body text cannot.

Why can a screen reader user still struggle with a page that uses a beautiful accessible font?

Because screen readers rely on semantic structure such as headings, labels, lists, and reading order. A visible font choice changes appearance, not the underlying structure.

How it works

Contrast evaluation uses relative luminance, not perceived aesthetic distance. Two colors can look "different" and still fail. WCAG thresholds are minimums; they do not guarantee comfort for every reader, font weight, or display. Thin light text on a dark background can meet a ratio and still feel weak because of halation, subpixel rendering, or font design.

Font selection affects recognition, not comprehension by itself. Letter differentiation, x-height, apertures, and spacing influence how quickly readers distinguish glyphs. For Latin text, serif and sans-serif families can both be readable; the outcome depends more on design quality, size, spacing, and rendering than on the category label. In code, a monospace design supports alignment and symbol disambiguation; in long-form reading, proportional spacing usually produces a more even rhythm.

Atkinson Hyperlegible, described by Braille Institute, is a concrete example of a design aimed at character recognition. It is useful evidence that type design can target legibility. It is not evidence that one family is universally best. For dyslexia, avoid overclaiming: controlled studies show mixed results, and user preference and layout controls are often more reliable than prescribing a single font.

Use real content, not lorem ipsum alone. Test body text, headings, UI labels, code blocks, error states, focus indicators, and disabled-looking but active controls. Include zoom, dark mode, high-DPI displays, and non-Latin samples where relevant.

Edge cases and failure modes

  • Contrast passes, readability fails: thin weights, low x-height, tight tracking, or long measure can still cause fatigue.
  • Accessible font, inaccessible document: a screen reader cannot infer structure from visual styling. PDF tags, HTML headings, and form labels matter.
  • Large text breaks layout: clipped containers, overlapping lines, or hidden buttons become functional barriers.
  • Color-only meaning: red/green status text fails users with color vision differences even when contrast is adequate.

Check yourself

A team wants to "fix accessibility" by switching everything to Atkinson Hyperlegible. What evidence would you ask for before accepting that claim?

A good answer separates font recognition from whole-document accessibility. Ask for contrast measurements, zoom/reflow results, semantic structure checks, screen-reader testing, and user feedback across tasks. A font change may help some readers, but it cannot by itself satisfy WCAG criteria for contrast, structure, resize, focus, or non-text content.

Why can a 5:1 contrast pair still be a poor choice for dense body text?

Contrast ratio is only one variable. Small size, light weight, low x-height, tight leading, long measure, or poor rendering can reduce readability. WCAG gives minimum contrast thresholds, but good typography also needs appropriate spacing, size, and layout.

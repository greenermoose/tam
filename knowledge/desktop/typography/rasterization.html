Guide / Desktop and applications / Typography / From outlines to pixels

A font stores shapes as numbers, but a screen shows tiny squares of colour. Rasterization is the step that turns those numbers into the squares you see.

From drawing instructions to dots

An outline font describes a letter with curves and straight lines, much like a drawing that can be resized. Before the letter appears on screen, a program works out which pixels lie inside the drawing and how dark each pixel should be.

At small sizes, a perfect curve may cross only a few pixels. The program then has to choose which squares to colour so the letter still reads clearly. This is why the same letter can look different in a heading and in a footnote.

Why it matters

Text on a screen is made of pixels, not curves. A thoughtful conversion keeps letters legible at sizes where a simple on-or-off choice would break them.

How to think about it

Imagine colouring a grid from a curved template. A square that is half covered can be coloured halfway, which makes the edge look smoother than a hard black-or-white outline.

If it goes wrong

You expected a curve to look the same at every size.
The number of pixels available to draw it changes, so both the outline and any hinting decisions change.
You mixed up DPI and PPI.
DPI describes output such as a printer; PPI describes the screen's own pixel grid. Matching them is what makes a font size look physically similar.

The Tamlinux font configuration file 50-tamlinux.conf assigns Liberation Sans, Liberation Serif and JetBrainsMono Nerd Font to the generic families. Different designs place stems and curves differently, so the same pixel size can rasterize quite differently across those families.

Check yourself

Decide your answer before you reveal it.

What does unitsPerEm set?

It sets the size of the design square. Every coordinate and advance in the font is a fraction of that square, so dividing the requested pixel size by unitsPerEm gives the scale used to place outline points.

Why does LCD filtering matter after subpixel rendering?

A LCD has separate red, green and blue stripes. Sampling each stripe can sharpen text, but it can also add colour fringes. Filtering spreads the samples so the fringe is less visible.

FreeType is the rasterizer used by many Linux text stacks. It loads outlines and metrics, applies hinting, renders a bitmap and exposes the result to callers; it does not decide which font to use or shape the string.

How it works

TrueType outlines use quadratic curves: off-curve points control the bend between on-curve points. CFF outlines use cubic charstrings with their own hint operators. Both describe the same visual idea, but a rasterizer must interpret different instructions to align them to a grid. TrueType Reference Manual OpenType specification 1.9.1

The em is the design square; unitsPerEm divides it into integer units. A 12-pixel em with 2048 units per em gives a scale of 12/2048, so design coordinate 1024 lands at pixel 6. Hinting can then shift the result to a whole pixel or change the advance. Grayscale antialiasing assigns a coverage value between zero and one to edge pixels; LCD rendering treats each colour stripe as a separate sample and applies a filter chosen for the panel's stripe order.

Vector graphics stay sharp when enlarged because the curves are recomputed. A rasterized glyph is a bitmap at one size, so enlarging that bitmap does not recover detail. This is why a glyph looks different at different sizes: the outline is evaluated against a new grid, and any hinting program can make different decisions at each size.

Colour glyphs add another path. COLR layers are painted from outlines and a palette; COLR/CPAL (color layers and palettes) supplies the layer and colour data. CBDT/CBLC, sbix and SVG tables can carry ready-made colour bitmaps that bypass outline scan conversion. A monochrome outline still goes through hinting and antialiasing.

Web and toolkit sizes are specified in absolute or relative units; CSS defines pixel and inch-based units so a requested size can be translated into device pixels using the display's density. CSS Fonts Module Level 4

Edge cases and failure modes

  • Hinting can change advance widths, so a hinted and unhinted run may have different total lengths even with identical glyph IDs.
  • Subpixel rendering assumes a known stripe order. On a rotated or unusual panel, the filter can make text worse.
  • At very small sizes, grayscale antialiasing may soften a stem until it disappears; hinting protects it by snapping, at the cost of exact outline shape.
  • Variable axes are evaluated before rasterization, so an axis change alters the outline the rasterizer receives.
  • Bitmap colour glyphs have no hinting step; their quality depends on the sizes supplied in the font.

Check yourself

Why can turning hinting off make a curve look smoother but a word look worse?

Without hinting, the rasterizer follows the mathematical outline and coverage varies smoothly. At small sizes the stems may fall between pixels, becoming uneven or faint. Hinting deliberately distorts the outline to keep stems consistent, trading geometric accuracy for legibility.

What breaks if a rasterizer assumes every outline uses quadratic curves?

CFF charstrings are cubic and carry different hint information. Reading them as quadratic contours produces wrong shapes or failures. A general rasterizer must inspect the font's outline format and use the matching interpreter.

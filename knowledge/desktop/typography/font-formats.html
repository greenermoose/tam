Guide / Desktop and applications / Typography / Font formats, complete map

A font file is a container for letter shapes plus the rules that place them. Different formats store those shapes in different ways, and this page maps the families you will meet on a Linux desktop and on the web.

Three questions about a font file

What this is

When you see a file ending in .ttf, .otf or .woff2, the ending tells you how the font is packed. A bitmap font stores each letter as a small grid of pixels. An outline font stores a mathematical description of each shape, so it can be drawn at any size. A web format wraps an outline font so a browser can fetch it efficiently.

The older bitmap formats include BDF (Bitmap Distribution Format), PCF (Portable Compiled Format), PSF (PC Screen Font) and FON. The common outline formats are TrueType, OpenType and Type 1.

Why it matters

The format decides where a font works. A PSF font is for a text console, not a word processor. A WOFF2 file is for a web page, not a printing workflow. A variable font can hold many weights in one file, while an older family may need one file per weight.

How to think about it

Think of three separate ideas that often get confused. The file format is the box the font arrives in. The font program is what is inside: outlines, a pixel grid, or even a small drawing program. The encoding is the numbering system that says which character a shape belongs to. A single font can be repacked from one box into another without changing the letters it draws.

If it goes wrong

You put WOFF2 with the outline formats.
Both descriptions are true at different layers. WOFF2 is a compressed web container that usually holds outline data, so this sample groups it by where it is used.
You expected Type 3 to be a bitmap format.
Type 3 stores outlines through a small PostScript program. It is an outline font program, not a pixel grid.

Bitmap formats are still real on a text console. Linux 6.12 keeps thirteen built-in bitmap fonts in its font library, with documented console names from VGA8x8 to TER16x32; setfont loads PSF fonts into a virtual terminal. Tamlinux's graphical desktop takes the other route: its fontconfig configuration strongly assigns generic families such as serif and monospace to installed outline fonts.

Check yourself

Decide your answer before you reveal it.

Why can the same design ship as OTF and as WOFF2?

Because the outlines and layout tables can be packed into different containers. OTF suits desktop installation; WOFF2 compresses the same data for web transfer. The file format changes, the letterforms need not.

Which question does a format answer, and which does an encoding answer?

A format answers how the font data is stored and delivered. An encoding answers which character number a glyph belongs to. A conversion between formats should leave the encoding unchanged.

How it works

An sfnt file is a table directory followed by named tables. TrueType stores outlines in the glyf table and locates them through the loca table; CFF and CFF2 store outlines with a different, PostScript-derived structure TrueType Reference Manual OpenType specification. OpenType adds layout tables for shaping and script support, which is why a font can carry more than outlines Adobe type notes.

WOFF and WOFF2 wrap sfnt tables with compression for web delivery; WOFF2 uses Brotli and is defined by W3C WOFF 1.0 WOFF 2.0. The Open Font Format standardises the same family of sfnt-based formats ISO/IEC 14496-22. Color glyphs use separate tables: layered outlines in COLR/CPAL, bitmap sequences in CBDT/CBLC, image glyphs in sbix, and SVG colour data in its own table OpenType color tables.

Variable fonts add design axes and named instances, letting one file stand in for many static faces. Advanced layout engines such as Graphite and HarfBuzz supply shaping behaviour beyond the basic tables; Graphite needs its own engine support in the application SIL Graphite HarfBuzz manual. FreeType reads the outlines and rasterises them for display FreeType documentation.

Advanced usage

These read-only commands inspect font structure without altering any file:

ttx -l Sample.ttf
ttx -l Sample.otf
fc-query -f '%{family} %{style}\n' Sample.otf
python3 -c 'from fontTools.ttLib import TTFont; print(TTFont("Sample.ttf")["head"].unitsPerEm)'

The first two lines list the tables inside a font, which is the fastest way to tell glyf from CFF outlines or to spot a COLR table. The third asks fontconfig what it reads from the file. The last prints the units-per-em value from the head table using fontTools fontTools and TTX.

Edge cases

  • A font FILE format is not a font PROGRAM format. TrueType and OpenType are file containers; PostScript Type 3 is a program that draws outlines when interpreted.
  • A format is not an encoding. Converting OTF to WOFF2 should preserve the character mapping, which depends on Unicode and the font's cmap table The Unicode Standard.
  • TTC collections share tables between faces. Editing one face in place can damage the others; extract a face before changing it.
  • Subsetting reduces file size by removing unused glyphs, but a later document that needs those glyphs will fall back to another font. Subsetting can also disturb shaping features if the wrong tables are dropped.
  • DSIG signatures may be stripped by subsetting or conversion, so a signed font can become unsigned downstream.
  • PDF embedded fonts are often subsets. A document can look correct while the embedded font carries only a fraction of the original characters ISO 32000-1, PDF 1.7.
  • SVG fonts were removed from the web font specification; SVG colour inside an sfnt font is a different, still-supported idea.
  • AAT and Graphite are layout systems, not font file formats. They require application support even when the font tables are present.

Check yourself

You need one family to cover five weights on a web page. Which format choice reduces downloads?

A variable font delivered as WOFF2. The axes let one file represent several weights, and WOFF2 compresses the tables for transfer. Static WOFF files would need one download per weight.

Why might a converted font stop shaping a complex script correctly?

Because conversion or subsetting dropped layout tables, or the target engine does not support the shaping model the font expects. Outlines can survive while the rules that position glyphs do not.

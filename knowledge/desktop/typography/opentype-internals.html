Guide / Desktop and applications / Typography / Inside OpenType and TrueType files

An OpenType font is one file that holds letter shapes, spacing numbers and rules for using them. Programs read named sections of that file to decide which shape to draw and where to place it.

A file of named parts

Think of a font file as a small library. One shelf holds the shapes of letters, another says how far to move after each letter, and another connects typed characters to those shapes. The sfnt container is the outer box that keeps those shelves together.

Each shape in the library is a glyph. A glyph is one drawable piece, such as the letter a or a joined pair such as fi. The file also records a design size, so the same shape can be drawn large or small.

Why it matters

When a document moves between machines, the font file travels with the instructions for using it. Named sections let a program read the character map without needing to understand the shape data first.

How to think about it

Imagine a cookbook with a contents page. The page tells you which shelf holds the recipes and how long each one is. The font file has the same idea: a short list at the front names every part and where it begins.

New words

Table
One named part of a font file, with a fixed job.
Glyph
A single shape a program can draw from the file.
Design size
The imaginary square on which the shape was drawn; it sets the scale for all other numbers.
Hinting
Extra instructions that help a shape stay tidy on a coarse pixel grid.
OTF (OpenType Font)
A common name for an OpenType file, whether it uses either kind of outline.

Check yourself

Decide your answer before you reveal it.

Which tables tell a program how many glyphs exist and where each outline begins?

maxp records the glyph count in numGlyphs. For quadratic outlines, loca holds offsets into glyf, so the two work together. Neither alone describes an outline.

Why is a ligature not just another entry in cmap?

A cmap entry maps one character to one glyph. A ligature replaces a sequence of glyphs with one glyph, so the substitution belongs in GSUB, which is applied after the initial lookup.

The sfnt container, field by field

Reference

An sfnt file starts with a 12-byte offset table: a four-byte version tag, then numTables, searchRange, entrySelector and rangeShift, each two bytes. Each following table record is 16 bytes: four-byte tag, checksum, offset and length. The version tag is 0x00010000 for TrueType outlines and OTTO for CFF-based OpenType.

How it works

A glyph ID is a 16-bit index into the font's glyph order. Glyph ID 0 is .notdef. The cmap answers "which ID for this code point"; GSUB and GPOS then work on IDs, not on characters. The value in unitsPerEm sets the coordinate system: an advance of 1024 with 2048 units per em means half an em.

TrueType hinting lives in instructions attached to glyf outlines; a rasterizer executes them to align stems and edges. CFF charstrings instead carry stem hints and hint masks. Both are hinting data, but they are not interchangeable.

GSUB holds scripts, language systems, features and lookups. Its substitution types include single, ligature, alternate and contextual forms, including mark forms. GPOS carries pair adjustment, mark attachment, cursive attachment and contextual positioning; the older kern table is a narrower predecessor. GDEF classes glyphs as base, ligature, mark or component and defines mark attachment classes, which GPOS needs to attach a mark to the right point.

A variable font adds fvar, which defines axes and named instances. TrueType designs use gvar tuple deltas; CFF2 blends deltas inside charstrings. avar remaps normalised axis values, and HVAR varies horizontal metrics. Static defaults remain in head, hhea and hmtx.

The name table stores strings as numbered records: name ID 1 is the family, 2 the subfamily, 4 the full name and 6 the PostScript name. Each record carries a platform and encoding pair, so the same name may appear more than once in different encodings. OS/2 adds the weight and width classes that allow applications to place a font in a menu and to synthesise a bold or italic style when no real face exists.

Colour glyphs may be layered through COLR/CPAL, supplied as colour bitmaps through CBDT/CBLC or sbix, or carried as SVG documents. A DSIG (Digital Signature) table can sign the font; editing or subsetting it breaks the signature because the signed bytes change. Table checksums are big-endian sums padded to four-byte boundaries, and head.checkSumAdjustment is chosen so the checksum of the whole file has the magic value 0xB1B0AFBA.

ttx -l LiberationSans-Regular.ttf
ttx -q -t head -o - LiberationSans-Regular.ttf | head -n 40
ttx -q -t cmap -o - LiberationSans-Regular.ttf | grep -n 'format="12"'

TTX from fontTools converts binary tables to XML and back. Listing and dumping, as above, only read the font; recompiling an edited dump changes the bytes and invalidates any DSIG.

Edge cases and failure modes

  • A font with a valid cmap but no GSUB entry for a language will still produce base glyphs; the expected joining or alternates simply do not happen.
  • Short loca stores offsets divided by two; reading it as long doubles every position and produces nonsense outlines.
  • A format 4 cmap cannot represent code points outside the BMP; a supplementary-plane character needs format 12 or 13.
  • A missing post version with names is fine for rendering but limits tools that expect glyph names, such as older feature-file workflows.
  • A CFF2 variable font has no glyf or loca; tools that assume quadratic outlines will miss its variation data.
  • An OS/2 version that is too old does not carry the later typographic metrics, so line spacing can differ between otherwise similar fonts.

Check yourself

What breaks if you edit one glyph in a font that carries DSIG?

The signature covers the file bytes. An edit changes those bytes, so the signature no longer verifies. The font can still render, but tools that check signatures will reject or warn. Re-signing requires the signing key.

Why can two fonts with the same unitsPerEm draw the same glyph at different widths?

unitsPerEm only sets the coordinate scale. The actual advance comes from hmtx, or HVAR in a variable font. Designers choose different advances, side bearings and contour shapes, so equal design squares do not imply equal widths.

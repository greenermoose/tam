Guide / Desktop and applications / Typography / Fonts built into the Linux kernel

The Linux text console can draw letters without any desktop font file. It uses small fixed pictures of characters, selected when the kernel boots or changed later from the console.

Letters as tiny pictures

Before a desktop starts, Linux can still show text on the screen. The framebuffer console draws that text from a set of tiny pictures, one for each value a byte can hold. Each picture is a glyph, and every glyph occupies the same small rectangular cell.

These are bitmap fonts. The picture for a letter is stored as rows of bits, not as a curve that can be scaled. The cell has a fixed width and height, and the kernel keeps thirteen such sets available in the version described here.

Why it matters

A console font works very early in boot and in rescue situations, when no desktop session exists. It also works on a plain text terminal where no graphical text engine is running.

How to think about it

Imagine a pegboard with identical square tiles. Each tile holds one stamped letter. You can swap the whole tile set for another, but you cannot stretch a single tile without making the stamp look wrong.

New words

Bitmap
A picture stored as a grid of dots or bits.
Console
A text-only screen provided by the kernel before a desktop runs.
Byte value
One of 256 possible numbers; here, each number picks one stored picture.
Width
How many pixels a glyph cell occupies across the screen.

Check yourself

Decide your answer before you reveal it.

Where are all thirteen built-in fonts in Linux 6.12?

In lib/fonts/. There is no drivers/video/fonts/ directory in Linux 6.12, even though older descriptions sometimes place fonts there.

What does fbcon=font:VGA8x8 select?

It sets the console font name that fbcon looks up with find_font(), selecting the descriptor whose name is VGA8x8. That descriptor points at the 8 by 8 bitmap array with 256 entries.

How it works: Kconfig gates and defaults

CONFIG_FONT_SUPPORT is the tristate master gate. It is selected by FRAMEBUFFER_CONSOLE, STI_CONSOLE, DRM_PANIC and SGI_NEWPORT_CONSOLE. CONFIG_FONTS gates the individual font prompts.

CONFIG_FONT_AUTOSELECT is def_bool y only when all fonts except 8x16 are off; in that state it selects FONT_8x16. With FONTS=n and not SPARC, FONT_8x8 and FONT_8x16 default to y. Architecture defaults add FONT_6x11 on MAC, FONT_PEARL_8x8 on AMIGA and FONT_ACORN_8x8 on ARM && ARCH_ACORN.

fonts.c registers each descriptor under its matching #ifdef and exposes find_font() and get_default_font(). A descriptor carries the width, height, data pointer and character count that fbcon copies into a virtual console.

Boot names and runtime changes

fbcon parses fbcon=font:<name> into fontname. It calls find_font(name), or get_default_font(xres, yres, blit_x, blit_y) when no name is given, then copies width, height, data and charcount into vc->vc_font. Built-in fonts are used with userfont=0. fbcon_set_font accepts user fonts with a charcount of 256 or 512 through KDFONTOP; fbcon_set_def_font restores a built-in by name or through get_default_font().

The documented names are exactly 10x18, 6x10, 6x8, 7x14, Acorn8x8, MINI4x6, PEARL8x8, ProFont6x11, SUN12x22, SUN8x16, TER16x32, VGA8x16 and VGA8x8. These are display names; the Kconfig symbols have a different spelling. Linux 6.12 fbcon docs

PSF, setfont and the kernel path

setfont(8) loads a PSF (PC Screen Font) file, and also accepts .cp and raw formats. In kbd v2.10.0 the work happens in kfont_load_fonts(), which issues ioctl(KDFONTOP) with KD_FONT_OP_SET, KD_FONT_OP_SET_TALL or KD_FONT_OP_SET_DEFAULT. The kernel path is vt_ioctl.c to vt.c to the fbcon hooks. setfont(8) kbd v2.10.0 setfont source

Each array has 256 slots indexed by a byte value. There is no table of code points, no outline curve, no shaping table and no palette. A character reaching the console is translated to one of those 256 slots; what the slot draws depends on the console's translation rules. A desktop font can cover thousands of code points and run shaping before rasterization, which these sets cannot do.

KMScon is a separate userspace terminal emulator with its own 8x16, Unifont and Pango font backends. It is outside the kernel tree, does not use CONFIG_FONT_* and does not travel through setfont's kernel console font path. KMScon v9.1.0 README

Edge cases and failure modes

  • A user font with 512 entries has twice the console character count; built-in arrays always have 256.
  • A font name that is misspelled falls back to the default chosen from the screen's resolution and blit geometry.
  • Autoselect only applies in the narrow configuration where every font except 8x16 is off; it is not a general fallback policy.
  • A tall user font takes the SET_TALL path, so it is not interchangeable with an ordinary 256-entry font.
  • Some Kconfig symbols would suggest names that are not accepted after fbcon=font; the kernel's display names are the thirteen short forms, not the symbol text.
  • A built-in set selected at compile time still needs its descriptor registered in fonts.c; a bitmap array alone is not discoverable by name.

Check yourself

Why does a PSF loaded by setfont not change the fonts available to a browser?

setfont talks to the kernel virtual console through KDFONTOP. A browser runs in a graphical session and uses desktop font files through its own text stack. KMScon, if used, is userspace too and has its own backends. The two paths never meet.

What is misleading about the path drivers/video/fonts/ in older notes?

In Linux 6.12 that directory does not exist. All thirteen built-in bitmap fonts live in lib/fonts/, with their Kconfig rules in lib/fonts/Kconfig and registration in lib/fonts/fonts.c. Repeating the old path sends a reader to the wrong tree.

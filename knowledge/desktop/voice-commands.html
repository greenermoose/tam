Shell Voice Commands

This page explains how to speak commands directly at your shell prompt while guaranteeing that spoken words are never executed without your explicit confirmation.

Unlike desktop dictation (which simulates raw keystrokes into any window), shell voice commands validate your speech against a known command vocabulary and place the command onto your shell prompt for inspection before running.

Issue a voice command at the shell prompt

Goal: issue a command in your terminal using your voice with confirmation safety.

Mental model

prompt check (empty?) --> F10 capture --> Whisper transcript --> allowlist validation --> Readline line (no execution)
The user reviews the inserted line and presses Enter manually to execute it.

Typing arbitrary spoken text directly into a command prompt is dangerous. A misheard word, background speech, or coughing could accidentally form a destructive command. Tamlinux isolates shell commands so they are never executed automatically.

F10 is bound inside Bash Readline (as \e[21~). It works only at an empty shell prompt, not while an editor or interactive agent is running. Normal F9 dictation still types unrestricted prose elsewhere.

Worked example

  1. Ensure your command prompt is empty.
  2. Press F10. The prompt displays: Speak a command. Enter finishes; Escape cancels.
  3. Speak clearly: "codex" (or "open codex").
  4. Press Enter on your physical keyboard to finish recording.
  5. The system checks the speech and confirms: Recognized codex. Press Enter at the prompt to run it.
  6. The word codex now appears at your prompt.
  7. Press Enter on your physical keyboard to execute the command.

This walkthrough is checked against the packaged voice command helper, not a claim that an interactive terminal test was performed in your session.

Completion task

What happens if you speak an unrecognized command or sentence using F10?

The helper checks the transcript against its allowlist. If the command is unrecognized, it reports an error message and leaves the prompt completely empty. Nothing is inserted.

Independent task

Try cancelling a voice command: at an empty prompt, press F10, then immediately press Escape or Ctrl+C.

The capture loop detects Escape or Ctrl+C, stops the recording daemon, removes the private temporary directory, and prints a cancellation notice. The prompt line remains empty and ready for normal typing.

Check yourself

Decide before revealing the explanation.

Will a recognized shell voice command run immediately when transcription finishes?

No. Tamlinux inserts the command text into the Readline prompt buffer and waits for you to review it and press Enter yourself.

Can you speak arbitrary shell pipelines like "cat file | grep text" using F10?

No. The voice command helper enforces a strict allowlist of approved commands and rejects arguments, options, and shell syntax for your safety.

Under the hood: Voice command architecture

  1. Readline integration: The terminal translates F10 into the escape sequence \e[21~, which Bash binds to a shell function. This prevents F10 from intercepting keys inside text editors or full-screen programs.
  2. Session locking: A lock file in $XDG_RUNTIME_DIR/ ensures only one voice command runs at a time and prevents clashes with regular dictation.
  3. Isolated temporary transcript: The audio transcript is saved into a private, temporary file in memory (tmpfs). The file is erased immediately after validation.
  4. Two-stage verification: The Python helper checks the command against an internal allowlist and confirms it exists on PATH. The Bash shell wrapper validates the output a second time before updating the prompt.
  5. Buffer injection: The result is assigned directly to the shell's READLINE_LINE variable. Because no newline character is appended, the shell waits for physical user input.

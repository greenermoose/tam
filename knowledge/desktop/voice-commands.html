Shell Voice Commands

This page explains how to speak commands at your shell prompt while guaranteeing that spoken words are never executed without your confirmation.

Why shell voice is different from dictation

Desktop dictation types unrestricted prose into any window. Shell voice commands validate speech against a known command vocabulary and place the result on your prompt for inspection before anything runs.

Why it matters

A misheard word at a command prompt could form a destructive command. Isolating shell capture from ordinary dictation keeps confirmation under your control.

How to think about it

empty prompt --> F10 capture --> Whisper transcript --> allowlist check --> Readline line (no execution)

You review the inserted line and press Enter yourself to run it.

New words

Allowlist
The short set of approved command names the helper will insert.
Readline
The line editor Bash uses for the interactive prompt.

Issue a voice command at the shell prompt

Goal: issue a command in your terminal using your voice, with confirmation before it runs.

Learning path: Desktop voice — Start | ← Back | Next →

Before you start: open a terminal with an empty Bash prompt. Do not practice inside an editor or interactive agent.

F10 is bound inside Bash Readline. It works only at an empty shell prompt. Ordinary F9 dictation still types unrestricted prose elsewhere.

Worked example

  1. Ensure your command prompt is empty.
  2. Press F10. The prompt displays: Speak a command. Enter finishes; Escape cancels.
  3. Speak clearly: "codex" (or "open codex").
  4. Press Enter on your physical keyboard to finish recording.
  5. The system confirms recognition and inserts the word at your prompt.
  6. Press Enter again only if you want to run it.

This walkthrough is checked against the packaged voice command helper, not a claim that an interactive terminal test was performed in your session.

What just happened

  1. F10 started a locked capture that does not execute anything.
  2. Whisper produced a transcript checked against the allowlist.
  3. The helper assigned the result to READLINE_LINE without a newline, so Bash waits for you.

Try it

At an empty prompt, press F10, then immediately press Escape or Ctrl+C to cancel. Confirm the prompt stays empty. Then try F10 with an unrecognized phrase and confirm nothing is inserted.

If it goes wrong

Prompt says "Clear the prompt first"
Press Ctrl+C or Ctrl+U to clear the line, then press F10 again.
"I don't understand"
Speak only an approved tool name (for example codex, agy, or claude).
Voxtype is busy
Release F9 or finish the Meta + Ctrl + X toggle before starting F10.

F10 is bound as \e[21~ in Bash Readline so it does not intercept keys inside full-screen programs. General prose still uses desktop dictation.

Check yourself

Will a recognized shell voice command run immediately when transcription finishes?

No. Tamlinux inserts the command into the Readline buffer and waits for you to press Enter.

Can you speak arbitrary pipelines like "cat file | grep text" using F10?

No. The helper enforces a strict allowlist and rejects arguments, options, and shell syntax.

Under the hood

  1. Readline integration: F10 becomes \e[21~, bound only at the shell prompt.
  2. Session locking: a lock under $XDG_RUNTIME_DIR/ prevents clashes with dictation.
  3. Isolated transcript: temporary transcript storage is erased after validation.
  4. Two-stage verification: allowlist check plus PATH existence before updating the prompt.
  5. Buffer injection: assignment to READLINE_LINE with no trailing newline.

This page explains the software that puts windows on your screen and lets you move among them.

What does a compositor do?

A compositor is the program that draws every application window onto your screen, arranges where each window sits, and routes your keyboard and mouse input to the active window.

Why it matters

Knowing that the compositor is separate from the rest of the operating system helps when graphics freeze: a stuck desktop often still leaves the underlying system healthy and reachable from a text console.

How to think about it

Imagine each open program painting onto its own clear sheet of glass. The compositor is the stage manager who stacks those sheets in order, places them side by side or overlapping, and shines the spotlight on whichever window receives your typing.

New words

Compositor
Program that draws and places windows on screen.
Wayland
The modern display protocol used by Linux compositors and graphical applications.

The compositor draws the desktop

Goal: you will be able to say what a compositor is and that Tamlinux uses Hyprland today on Wayland.

Before you start: you need a working graphical session or a text console. Do not restart display services while learning.

If the graphical desktop stops responding, try Ctrl + Alt + F2 (or another Fn key) for a text console. Exact numbers depend on the installation.

Mental model

A Wayland compositor presents application surfaces and manages placement and input. The desktop shell (panels, menus) is separate. Tamlinux runs Hyprland today and is writing its own compositor, tam-pane, for later integration. Sway and wlroots are not part of the plan.

Worked example

From a working desktop, press Meta + K and confirm keybindings still list Meta + Return. That shows the compositor is receiving keys. If nothing responds, move to a virtual console instead of forcing power off.

Try it

Press Meta + Return to open a terminal, then Meta + Q to close only that empty window.

If it goes wrong

No response to Meta keys
Switch to a VT with Ctrl + Alt + Fn and continue from text.

On Tamlinux: check packaged bindings under the product session tree, not stock Hyprland defaults.

Check yourself

Is the compositor the same as a web browser window?

No. The compositor is the display server that places all windows; a browser is one client.

Blank-screen boundaries

Separate panel power, cable/protocol, DRM/KMS programming, compositor process, and client faults. Plugin ABI churn and carried multi-monitor patches are reasons Tamlinux plans to move from Hyprland to tam-pane; contribution policy also blocks some upstream paths. Capture hyprctl or DRM connector evidence from a working VT when documenting a fault. Do not restart display stacks as a first exploratory step.

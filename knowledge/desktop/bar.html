The top bar

This page explains the strip along the top of the Tamlinux desktop and the fred.* plugins that live there.

What is the top bar?

The top bar is a thin strip that shows status and opens small panels: clock, weather, system info, and more. You can hide or show it with a keyboard chord when you need a clearer screen.

Why it matters

The bar answers “what time is it?” and “is the network up?” without opening a full app, and it is where Tamlinux ships its desktop plugins.

How to think about it

Treat the bar like a dashboard row: glance for status, click or activate a module for detail, then return to your windows.

New words

Bar
The desktop status strip (also called a panel).
Plugin
A packaged bar module with an id such as fred.clock.

Show the bar and open a plugin

Goal: you will be able to toggle the bar and recognize the packaged fred.* modules by name.

Worked example

  1. Press Meta + Shift + Space to toggle the top bar (tam-shell tamlinux-shell toggleBar from utilities.lua).
  2. If you hid it, press the same chord again to bring it back.
  3. Locate the clock area—that module is fred.clock. Other modules use ids such as fred.weather and fred.sysinfo.

Module ids come from each plugin's packaged manifest in the product tree. Layout can vary by host profile.

What just happened

  1. The shell toggled bar visibility.
  2. Each fred.* plugin owns one kind of status or panel.

Try it

With the bar visible, open Meta + K and confirm the bar toggle chord. Then hide and show the bar once without changing themes or layouts.

If it goes wrong

Bar will not return
Press Meta + Shift + Space again. If the session is wedged, use a text virtual terminal for recovery as noted on the desktop hub.
A module is missing
Host profiles may omit optional plugins; the packaged set is listed in the expert section.

Plugins are product code under desktop/plugins/fred.*/ and reach the session through packaged Tamlinux assemblies, not by copying folders by hand.

How it works

The Tamlinux shell (Quickshell-based) loads bar modules declared for the cultivar. Each plugin directory holds a manifest with id, name, and version. fred.workspaces may already appear in workspace documentation; the full id list above is the coverage set for the bar.

Advanced usage

Theme and background menus are separate (Meta + Shift + T, Meta + Ctrl + Space). Plugin authoring and tam-plugin belong under Improving, not this page.

Edge cases

  • Optional modules can be absent on a host without breaking the bar.
  • Hiding the bar does not quit plugins; it only changes visibility.

Check yourself

Why document plugin ids such as fred.sysinfo instead of only the friendly label?

Ids are stable product names used in packaging and coverage checks; labels can vary in the UI.

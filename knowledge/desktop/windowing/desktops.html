Guide / Desktop and applications / Windowing systems / GNOME, KDE Plasma and other desktops

A desktop environment is the complete graphical workspace around your applications. It combines a compositor, a shell, settings, and core applications.

What this is

GNOME and KDE Plasma are two well-known Linux desktops. Each supplies a way to launch programs, switch windows, change settings and use familiar applications.

Why it matters

Knowing that a desktop is a bundle explains why one part can fail while another keeps working. A broken panel is not necessarily a broken compositor.

How to think about it

Think of an office. The compositor provides the desks and lighting, the shell provides the reception area and notice boards, the settings are the building rules, and the applications are the people doing work.

Try the idea in a sandbox

Sample: Type=wayland; Desktop=Hyprland Try: loginctl show-session "$XDG_SESSION_ID" -p Type -p Desktop The login manager records the session type and desktop. Different sessions can provide different shells and compositors. Try the command shown above (or type help).

The output is fixed teaching data; the sandbox does not inspect or alter your system.

Try it

Look at one panel, one application window and one notification on your desktop. Write which layer probably owns each: compositor, shell or application toolkit. Do not change settings.

If it goes wrong

Panel disappears but windows still work
Suspect the shell or its plugin before the compositor.
Windows appear without borders or focus
Suspect the compositor or window manager, not the application's toolkit.

Check yourself

Decide your answer before you reveal it.

Is GNOME the same thing as GTK?

No. GTK is a widget toolkit that GNOME applications often use, and other projects use it too. GNOME is the whole desktop: compositor, shell, settings, services and applications.

How it works

A full desktop adds session management, a shell process, settings services, a notification daemon and core applications above the display protocol. Toolkits render the shell's own widgets. A modular setup lets the reader choose those pieces separately; an integrated desktop tests them together and ships consistent defaults.

Advanced usage examples

A shell panel often uses a layer-shell protocol to reserve space at an output edge. A settings daemon writes configuration and notifies applications over D-Bus. A portal service mediates file choosers and screen capture so applications need not know which desktop is present.

Edge cases and failure modes

  • A window manager and a compositor are not synonyms; a compositing window manager does both jobs.
  • Desktop sessions can offer both X11 and Wayland modes with different component sets.
  • Shell extensions can run inside the compositor process in some designs, making an extension fault look like a display fault.
  • Sway and wlroots are not part of Tamlinux's compositor plan; Hyprland is current and tam-pane is planned.

Check yourself

A notification never appears, but input and windows work. Where would you look first?

Model answer: the shell or notification service, not the compositor. The compositor is still presenting surfaces and routing input. Check the shell process and its settings or plugin state before considering display-server evidence.

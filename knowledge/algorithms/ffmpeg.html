FFmpeg is a widely used open-source toolkit for working with audio and video. It can inspect, convert, stream, filter, and encode media by wiring together containers, codecs, and processing filters.

What FFmpeg does

Media files usually contain compressed audio and video inside a container. FFmpeg can read that container, decode the streams, change them, and write a new result. You might use it to convert a video format, extract audio, resize a clip, or inspect what codecs a file uses.

Why it matters

FFmpeg is behind many media workflows and products. It gives you a practical way to see how algorithms meet real files: compression, filtering, resampling, and synchronization all happen in concrete pipelines.

How to think about it

Think of FFmpeg as a media workshop. A file comes in, is unpacked from its box, processed on workbenches, and packed into a new box. The codecs are the compression specialists; the filters are the editing tools.

New words

FFmpeg
A collection of programs and libraries for processing audio and video.
Codec
A method for encoding and decoding media data, often with compression.
Container
A file format that holds one or more media streams, metadata, and timing information.
Filter
A processing step that transforms audio or video, such as scaling, cropping, or volume change.

Inspect, convert, and filter

Goal: understand the basic FFmpeg pipeline: demux, decode, filter, encode, mux.

Worked example

$ ffprobe -hide_banner -i input.mp4
Input #0, mov,mp4,m4a,3gp,3g2,mj2, from 'input.mp4':
  Duration: 00:00:10.00, start: 0.000000, bitrate: 1200 kb/s
  Stream #0:0[0x1](und): Video: h264, yuv420p, 1280x720, 30 fps
  Stream #0:1[0x2](und): Audio: aac, 48000 Hz, stereo

$ ffmpeg -hide_banner -i input.mp4 -vn -c:a mp3 output.mp3
# extracts audio, decodes it, and encodes as MP3

$ ffmpeg -hide_banner -i input.mp4 -vf "scale=640:-1" -c:a copy output-small.mp4
# scales video, copies audio without re-encoding

Illustrative commands. Actual output depends on the input file and installed codecs.

What just happened

  1. ffprobe inspected the container and streams without changing them.
  2. The first ffmpeg command demuxed the input, decoded audio, ignored video (-vn), encoded MP3, and muxed the result.
  3. The second command applied a video filter (scale) while copying audio as-is. Copying avoids unnecessary quality loss and work.

Try it

Use ffprobe on a media file you own. Then try a safe conversion to a new filename. Keep the original file unchanged.

If it goes wrong

Unknown encoder or Encoder not found
Your FFmpeg build may not include that codec. Check ffmpeg -encoders and choose an available one.
Output looks or sounds wrong
Check pixel format, sample rate, channel layout, and whether you accidentally re-encoded with low quality defaults. Inspect with ffprobe.

Check yourself

Why can copying a stream be better than re-encoding it?

Copying preserves the existing encoded data, avoiding extra quality loss, CPU work, and time. Re-encoding is needed only when you want to change the codec, bitrate, filters, or another property of that stream.

How it works

FFmpeg's command line builds a processing graph. Containers handle packaging and timing; codecs handle compression; filters operate on decoded data. Many media algorithms are domain-specific: transform coding, motion estimation, quantization, entropy coding, resampling, and psychoacoustic models. Fourier-related transforms appear in analysis and in related frequency-domain methods used by codecs and audio processing (for example DCT/MDCT families in compression; FFTs in spectrum analysis and some filters).

Advanced usage

$ ffmpeg -i input.wav -lavfi "showspectrum=s=1280x720:mode=combined:color=intensity" -frames:v 1 spectrum.png
$ ffmpeg -i input.mp4 -vf "scale=1280:-2,format=yuv420p" -c:v libx264 -crf 23 -preset medium -c:a aac -b:a 128k out.mp4

Illustrative commands. They show analysis and controlled transcoding pipelines.

Edge cases

  • Timestamp and timebase mismatches can cause sync problems; inspect PTS/DTS when debugging.
  • Re-encoding is lossy for most delivery codecs; preserve masters when possible.
  • Color space, range, and pixel format conversions can change appearance if not handled explicitly.
  • Hardware acceleration changes performance characteristics and sometimes available options/quality trade-offs.

Check yourself

Where do Fourier transforms fit in a tool like FFmpeg?

Not every FFmpeg operation uses an FFT, but frequency-domain thinking is central to media processing. FFTs are used directly for spectrum analysis and some filters, while related transforms such as DCT/MDCT are fundamental to many audio and video codecs. FFmpeg is a practical place where algorithmic theory meets real media pipelines.

Guide / Systems and computing / Important algorithms for modern computing / Sorting algorithms

A sorting algorithm puts items into an order, such as numbers from smallest to largest or names alphabetically. Sorting is fundamental because many other problems become easier once data is ordered.

Why sorting matters

Sorted data is easier to search, group, and display. A phone contact list, a file browser, a leaderboard, and a database index all rely on ordering. The same task can be done by different algorithms, and some are much better for large data.

How to think about it

Sorting is like organizing books on a shelf. You can compare two books at a time and swap them, split the shelf into piles and merge them, or pick the smallest book repeatedly. Each strategy has different effort and space needs.

New words

Sorting algorithm
A procedure for arranging items in a defined order.
Stable sort
A sort that keeps equal items in their original relative order.
In-place
An algorithm that needs only a small constant amount of extra memory beyond the input.

Python's sorted is stable: the two items with key 1 keep their original order.

What just happened

  1. The key selected the number for ordering.
  2. Items with equal keys remained in their original relative order because the sort is stable.
  3. Stability matters when you sort by one field after another, or when equal keys carry meaning.

Check yourself

Why isn't there one "best" sorting algorithm?

Different algorithms make different trade-offs: average speed, worst-case guarantees, memory use, stability, implementation complexity, cache behavior, and whether data fits in memory or arrives as a stream.

How it works

Comparison sorts can be modeled as decision trees: each comparison gives one bit of information. With n! possible orderings, the tree height must be at least log2(n!), which is Ω(n log n). Non-comparison sorts avoid this bound by using key structure, such as integer ranges or digit positions.

Edge cases

  • Quicksort's worst case is O(n^2); randomized pivots or introsort mitigate it.
  • Stability is not just cosmetic - it affects multi-key sorts and user-visible behavior.
  • Sorting pointers/records can make comparison and move costs more important than raw comparison count.
  • For security-sensitive contexts, avoid timing/data-dependent behavior that leaks secrets through side channels.

Check yourself

When can radix sort beat merge sort?

When keys have fixed-size or bounded structure (such as integers, fixed-length strings, or digit/byte representations) and the key distribution/length makes linear or near-linear passes cheaper than comparison-based n log n sorting. It trades generality for assumptions about keys.

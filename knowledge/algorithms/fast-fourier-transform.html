Guide / Systems and computing / Important algorithms for modern computing / Fast Fourier Transform

The Fast Fourier Transform (FFT) is an algorithm for computing the Discrete Fourier Transform quickly. It produces the same result as a direct DFT, but with far less work for large inputs.

Why "fast" matters

A direct DFT checks every sample against every frequency. If you have 1,000 samples, that is roughly a million combinations. If you have a million samples, it becomes a trillion - too much for many real-time uses. The FFT reorganizes the same math to avoid repeating work.

Why it matters

The FFT made frequency analysis practical at scale. It helps audio players equalize sound, phones compress voice, Wi-Fi and cellular systems process radio signals, medical scanners reconstruct images, and media tools like FFmpeg analyze and filter audio and video. Many problems that look unrelated to waves become faster after an FFT.

How to think about it

Imagine sorting mail by checking every letter against every mailbox one by one. The FFT is like noticing a pattern that lets you split the pile, sort smaller piles, and combine the results. You get the same final mailboxes, but with much less walking around.

Worked example

$ python3 - <<'PY'
import math, time
def dft(x):
    N=len(x); out=[]
    for k in range(N):
        re=sum(x[n]*math.cos(2*math.pi*k*n/N) for n in range(N))
        im=-sum(x[n]*math.sin(2*math.pi*k*n/N) for n in range(N))
        out.append(complex(re,im))
    return out

# A tiny power-of-two size keeps the demo quick.
N=256
x=[math.sin(2*math.pi*3*n/N)+0.3*math.cos(2*math.pi*20*n/N) for n in range(N)]
t0=time.time(); dft(x); t1=time.time()
print(f"direct DFT: {N*N} sample-frequency combinations")
print(f"FFT class: about {N*int(math.log2(N))} work units")
print(f"elapsed: {t1-t0:.4f}s for N={N} (illustrative)")

Illustrative timing; exact numbers vary by machine. The key point is the growth rate: DFT grows like N^2, FFT grows like N log N. See Time complexity and Big-O notation for how these growth rates are compared.

What just happened

  1. The direct DFT computed every frequency from every sample.
  2. The FFT class count shows why the same result can be obtained with far fewer operations.
  3. As N grows, the gap becomes enormous. This is why FFT is not just an optimization - it changes what is feasible.

Try it

Double N several times in your head: N^2 becomes four times larger, while N log N grows much more gently. For audio at 48,000 samples per second, that difference is decisive.

Check yourself

Does the FFT give a different answer than the DFT?

No. The FFT computes the same DFT result (within normal floating-point rounding). It is a faster algorithm for the same mathematical transform.

Why is FFT important outside audio?

Many problems can be expressed as frequency analysis or convolution: image filtering, polynomial multiplication, solving some differential equations, radar, MRI, and compression. The FFT makes those frequency-domain methods fast enough to use.

How it works

The common Cooley-Tukey FFT uses the divide-and-conquer idea. A DFT of size N can be written as a combination of smaller DFTs of even-indexed and odd-indexed samples. The "twiddle factors" e^(-2πi*k/N) combine those smaller results. When N factors nicely, especially powers of two, the recursion or iterative stages remove repeated computation.

DFT(x[0..N-1])
  = DFT(even samples) + W^k * DFT(odd samples)
  = DFT(even samples) - W^k * DFT(odd samples)  (for the upper half)

Advanced usage

  • Fast convolution: filter a signal by multiplying spectra, then inverse FFT.
  • Polynomial multiplication: multiply coefficient polynomials by transforming, pointwise multiplying, and inverse transforming.
  • Spectral analysis: STFT/FFT windows power audio editors, spectrum analyzers, and speech features.
  • Compression and codecs: related transforms (DCT/MDCT) are central in media formats; FFT itself is used in analysis, filtering, and some processing pipelines.

Edge cases

  • Input size and padding matter: many FFT implementations are fastest at power-of-two sizes, while mixed-radix FFTs handle other sizes.
  • Window choice affects spectral leakage and resolution.
  • Floating-point FFTs introduce rounding error; for some integer/exact problems, number-theoretic transforms are used instead.
  • Performance depends on memory layout and cache behavior, not only arithmetic count.

Check yourself

Why did the FFT have such a large historical impact?

It turned an O(N^2) transform into O(N log N), making frequency-domain computation practical for large real-world data. That enabled efficient digital signal processing across audio, communications, imaging, scientific computing, and many algorithmic tricks such as fast convolution.

Algorithms behind large language models

Large language models (LLMs) are built from several algorithms working together: text is turned into tokens, tokens become vectors, neural networks learn patterns, and inference algorithms generate output one token at a time.

What an LLM is doing

At a simple level, a language model learns to predict what token is likely to come next given previous tokens. By training on huge amounts of text and using a large neural network, it learns patterns of language, code, and facts well enough to generate useful responses.

Why it matters

LLMs power chat assistants, code completion, search, summarization, and translation. Understanding the underlying algorithms helps you see both their strengths and limits: they are powerful pattern learners, not magic oracles.

How to think about it

Imagine autocomplete trained at enormous scale. Instead of only suggesting the next word from a small local pattern, it uses a model with billions of parameters and an attention mechanism to weigh relevant context from the input.

New words

Large language model (LLM)
A large neural network trained on text to model and generate language.
Token
A chunk of text, such as a word piece, used as the model's input/output unit.
Parameter
A numeric value learned during training that shapes model behavior.

Inference pipeline

prompt -> tokens -> embeddings -> transformer layers -> logits
      -> select next token -> append -> repeat

During generation, the model produces probabilities (logits after softmax) for the next token, selects one, appends it, and repeats. Techniques like KV cache avoid recomputing attention for previous tokens.

Try it

When using an LLM, notice how changing the prompt changes the next-token distribution. Asking for a short answer, a table, or code constrains what tokens are likely next.

Check yourself

Why is attention important in transformers?

Attention lets each token weigh other tokens in the context when computing its representation. This helps the model use relevant earlier words, code symbols, or instructions instead of treating all context equally.

How it works

In a transformer, input token embeddings are transformed through layers. Self-attention computes query, key, and value vectors; attention scores determine how much each token attends to others. Feed-forward networks apply nonlinear transformations per token. Training minimizes next-token prediction loss over large corpora. Fine-tuning and alignment methods can further adapt behavior after pretraining.

Edge cases

  • Hallucination/confabulation: plausible text is not guaranteed to be true; models optimize likelihood/policy objectives, not a truth oracle.
  • Context limits: finite context windows and attention cost constrain how much input can be used directly.
  • Data and bias: training data shapes capabilities and failure modes.
  • Evaluation: benchmarks measure specific behaviors; no single score captures general reliability.

Check yourself

Why is inference optimization different from training optimization?

Training optimizes billions of parameters over batches to minimize loss, requiring gradients and backpropagation. Inference keeps parameters fixed and optimizes latency, throughput, memory, and cost while generating tokens, using techniques like KV caching, quantization, batching, and efficient kernels.

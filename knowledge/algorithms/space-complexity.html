Space complexity and memory use

Space complexity describes how much memory an algorithm needs as input grows. Fast code can still be unusable if it needs too much memory.

Memory is a cost too

An algorithm may run quickly but need extra room to store copies, tables, or intermediate results. On a small input that is fine; on a large input it can exhaust memory or slow down because data no longer fits in fast caches.

Two common questions

  • Total space: How much memory is used overall, including the input?
  • Auxiliary space: How much extra memory beyond the input does the algorithm need?

When people say an algorithm is "in-place", they usually mean it uses O(1) or very small auxiliary space.

Counting extra memory

Worked example

$ python3 - <<'PY'
# O(1) auxiliary space
def sum_list(xs):
    total = 0
    for x in xs:
        total += x
    return total

# O(n) auxiliary space (new list)
def doubled(xs):
    return [x*2 for x in xs]

print(sum_list([1,2,3]))
print(doubled([1,2,3]))
PY
6
[2, 4, 6]

The first function keeps only a few variables. The second creates a new list proportional to the input.

Check yourself

Can a recursive algorithm use extra memory even if it creates no new arrays?

Yes. Each recursive call uses stack space for parameters, local variables, and return address. A recursion depth of n means O(n) stack space in the usual model.

How it works

Space analysis counts memory cells or bytes as a function of input size under a chosen model. It includes data structures, buffers, recursion stack, and sometimes output. Real programs also pay allocator metadata, object headers, padding, and fragmentation costs not captured by simple asymptotic notation.

Edge cases

  • Output space: some definitions exclude output; others include it. State the convention.
  • Tail recursion: can be optimized to O(1) stack in some languages/compilers, but not guaranteed in all Python/C implementations unless specified.
  • Cache locality: an algorithm with smaller asymptotic memory may still be slower if its access pattern causes cache misses.
  • Shared memory/copy-on-write: measuring "memory used" in modern OSes requires care (RSS, VSZ, shared pages).

Check yourself

Why might you choose an O(n) extra-space algorithm over an in-place O(1) one?

If it gives better time complexity, simpler correctness, stability (as in merge sort vs quicksort variants), better parallelism, or safer behavior. The right choice depends on input size, memory limits, latency requirements, and correctness properties.

Space complexity describes how memory use grows when input grows. Code that looks fast can still fail if it needs a second copy of a huge file.

Extra memory counts

Space complexity asks how much working memory a method needs as the input grows. Auxiliary space is the extra memory beyond the input itself.

Why it matters

A method that copies a list uses roughly as much extra memory as the list. If the list is enormous, the copy may fail even though the method is fast.

How to think about it

Adding a column of numbers needs only a running total. Photocopying the whole sheet before adding needs a second stack of paper. Both give the same answer, but the second uses more room.

Does input storage count as auxiliary space?

Usually no. Auxiliary space is the extra working storage; the input is counted separately unless stated.

Can recursion use extra space?

Yes. Each pending call occupies a stack frame, so recursion depth contributes to space complexity.

How it works

State clearly whether you count stack frames, output storage and temporary buffers. A method may be in-place with respect to working memory yet still return a large new result. Time and space trade off: caching precomputed values speeds lookups but consumes memory.

Edge cases and failure modes

  • Small constants can dominate asymptotic advantage for tiny inputs.
  • Virtual memory overcommit can hide a real out-of-memory failure.
  • Copy-on-write sharing changes the practical cost of an apparent copy.
  • Recursive algorithms can overflow the stack before memory is exhausted.

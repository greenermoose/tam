Guide / Systems and computing / Important algorithms for modern computing / Algorithm analysis

Algorithm analysis predicts how much time and memory a method needs as its input grows. It helps you compare approaches before a slow one meets a huge file.

Why counting steps matters

Two methods can solve the same problem, but one may become unusably slow when the input gets large. A stopwatch reports one run; analysis describes the pattern behind many runs.

Why it matters

Choosing a method that grows gently means your program still works when a list grows from a hundred items to a million. Choosing one that grows quickly can turn a small delay into hours.

How to think about it

Imagine finding a name in a phone book. Reading every page works, but splitting the book in half again and again works much better as the book thickens. Analysis gives names to those two strategies.

Why is worst-case analysis common?

It gives a guarantee: no input of that size needs more work. That matters when a slow run would be unacceptable, even if typical inputs are easier.

Does a stopwatch result replace analysis?

No. A stopwatch records one machine and one input. Analysis explains how the work grows when either changes.

How it works

Analysis fixes a cost model, counts the model's steps as a function of input size, then simplifies with Big-O notation and related notations. It yields machine-independent growth trends, not exact seconds. Define n explicitly: a list's length, a number's bits, a graph's vertices plus edges, and an image's pixels lead to different bounds.

Edge cases and failure modes

  • For small n, constants dominate; a method with a worse bound can win.
  • Memory hierarchy effects can outweigh operation counts.
  • Amortized bounds describe sequences, not one isolated call.
  • Average-case bounds depend on an input distribution that may not hold.

64-bit

64-bit means that 64 bits form one unit, such as an integer or a memory address.

Sixty-four bits have enough patterns for very large whole numbers and for a huge range of memory addresses. Most modern desktop and server programs are built as 64-bit programs because their processors and operating systems use this width.

An unsigned 64-bit integer runs from 0 to 18,446,744,073,709,551,615. As a signed two's complement value it runs from -9,223,372,036,854,775,808 to 9,223,372,036,854,775,807. A 64-bit pointer can in principle address 2^64 bytes, or 16 EiB, though real systems use fewer address bits. A 64-bit program is compiled for a 64-bit ABI, with 64-bit instruction-set mode, wider registers and 64-bit libraries. Programs moved to 64-bit gain room for large address spaces and large counters, which is why new desktop builds use it; the change needs a 64-bit processor and operating system.

Is a 64-bit program always faster than a 32-bit one?

No. Wider registers help some large calculations, but larger pointers also use more memory and cache space. Speed depends on the work, the compiler and the processor; the main reason to choose 64-bit is address space and range.

The full 64-bit pointer width is not always used for addresses: current x86-64 systems commonly implement 48-bit or 57-bit canonical virtual addresses and require upper bits to match the sign bit. Data models also differ. Linux and macOS use LP64, where long and pointers are 64 bits but int stays 32 bits; Windows uses LLP64, where long long and pointers are 64 bits but long stays 32 bits. A 64-bit operating system can run a 32-bit program through compatibility mode and 32-bit libraries when both are present; a 32-bit operating system cannot load a 64-bit program. The instruction-set mode, ABI and library set must match the build.

Guide / Glossary A–Z / Terms beginning with a number / 32-bit

32-bit means that 32 bits form one unit, such as an integer or a memory address.

Thirty-two bits have 4,294,967,296 patterns. Used as an unsigned count, they run from 0 to 4,294,967,295. Many older desktop programs are called 32-bit because their instructions and addresses were built around this unit.

As a signed two's complement integer, 32 bits run from -2,147,483,648 to 2,147,483,647. A 32-bit pointer holds a memory address in 32 bits, so one process can address up to 2^32 bytes, or 4 GiB. A 32-bit program is compiled for a 32-bit ABI: it uses 32-bit instruction-set mode, 32-bit registers for addresses and 32-bit libraries. Both widths still exist because old hardware, old operating systems and older plug-in formats need 32-bit builds, while smaller pointers can suit a program that never needs a large address space.

Can a 64-bit computer run a 32-bit program?

Usually yes, if the processor and operating system support 32-bit compatibility and the needed libraries are installed. The reverse does not work: a 32-bit operating system cannot run a program built for a 64-bit ABI.

On x86, a 32-bit build targets IA-32 mode; a 64-bit operating system may run it in a compatibility mode while keeping a 64-bit kernel. Linux 32-bit user space uses an ILP32 data model, where int, long and pointers are 32 bits. Physical Address Extension let 32-bit x86 systems use more physical memory, but it did not widen a process's 32-bit pointers, so the virtual address space stayed at 4 GiB, often less after operating-system reservations. Mixing 32-bit and 64-bit object code in one process needs matching calling conventions and data layouts; otherwise the call crosses incompatible ABIs. A 32-bit integer field inside a 64-bit program is only a data width, not a 32-bit program.

PNG - Portable Network Graphics

A widely used lossless raster image format that preserves exact pixel data and supports transparency.

Think of PNG like a ZIP archive for pictures: unlike JPEG, which throws away subtle details to shrink photos (and leaves fuzzy smudges around sharp text), PNG packs every pixel cleanly and unpacks it identically. That makes it the go-to format for screenshots, icons, and diagrams—and because it supports transparent backgrounds, logos saved as PNGs blend cleanly onto any page.

PNG excels at flat colors, sharp edges, and UI screenshots, while photographic scenes usually compress much smaller in lossy formats like JPEG or WebP. It supports 8-bit indexed palettes, 24-bit RGB, and 32-bit RGBA alpha transparency; tools such as oxipng or optipng can shrink existing PNG files losslessly by testing better row filters and DEFLATE settings without changing a single pixel.

Why is JPEG usually a poor choice compared to PNG for a terminal screenshot?

JPEG’s lossy block compression blurs sharp, high-contrast text edges and introduces ringing artifacts, whereas PNG keeps every character crisp and pixel-exact.

Specified in ISO/IEC 15948, a PNG stream opens with an 8-byte signature followed by length-prefixed, CRC-32–protected chunks—critically IHDR, optional PLTE, IDAT, and IEND, plus ancillary metadata chunks such as sRGB, iCCP, and tEXt. Before zlib/DEFLATE compression, each scanline passes through one of five predictive byte filters (None, Sub, Up, Average, Paeth) to reduce entropy across color types 0, 2, 3, 4, and 6 (up to 16 bits per sample), with optional Adam7 progressive interlacing.

Guide / Glossary A–Z / Terms beginning with P / PAM - Pluggable Authentication Modules

PAM (Pluggable Authentication Modules) is a modular Linux and Unix framework that handles user authentication, account checks, password updates, and session setup.

When you log in at the desktop, unlock your screen, or run an admin command, each program needs to verify who you are—but it would be chaotic if every app had to invent its own password or fingerprint checker. PAM acts like a central security desk that programs call instead. Administrators can plug in different check methods (like a password, a fingerprint reader, or a security key) in one place, and every login program automatically follows those rules.

PAM organizes rules per service under /etc/pam.d/ (such as login, sshd, or sudo) across four management types: auth (verify identity), account (check expiry or access rules), password (update credentials), and session (set up home directories, limits, or keyrings). Contrasting with hardcoding /etc/shadow lookups into each daemon, PAM lets you add a FIDO2 key or fingerprint module without recompiling any application. Misconfiguring a PAM file can lock out logins, so keep a root shell open when testing edits.

If you want to require a hardware security key in addition to a password for sudo without changing sshd, where do you configure that?

In /etc/pam.d/sudo. Because PAM uses per-service configuration files, editing the sudo stack changes how sudo authenticates without affecting SSH or other services.

PAM implements an OS-level shared-library API (libpam, RFC 86 / Linux-PAM) where PAM-aware services invoke pam_start(), pam_authenticate(), pam_acct_mgmt(), and pam_open_session() via a conversation callback. Each stack in /etc/pam.d/<service> evaluates modules sequentially using control flags (required, requisite, sufficient, optional, include, substack, or bracketed return-code maps) that determine whether failure aborts immediately or continues to avoid leaking which check failed. Common pitfalls include sufficient short-circuiting subsequent checks, pam_unix.so needing setuid helper unix_chkpwd for non-root screen lockers, and missing pam_systemd.so session hooks breaking user runtime directories.

Path claim

A recorded reservation of specific files or directories in a shared Git checkout so concurrent contributors do not overwrite each other.

When several people or AI assistants work inside the same project folder at once, a path claim is like putting a sticky note on the specific files you are editing so nobody else edits those same files at the same time.

In Tamlinux repositories, contributors run tam-work begin with --scope flags to claim only the paths they plan to edit, commit only those paths, and release the claim with tam-work finish once done.

Why should a path claim name only the files you will edit rather than the whole repository?

Narrow claims allow other contributors to work safely on unrelated files in the same checkout at the same time without blocking each other.

Path claims are enforced via tam-work metadata in the shared checkout without creating separate clones; exclusive claims are reserved for whole-tree builds or repository-wide operations that read neighboring files.

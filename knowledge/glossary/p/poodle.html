POODLE (Padding Oracle On Downgraded Legacy Encryption)

A 2014 cryptographic attack on SSL 3.0’s CBC-mode padding that allowed attackers to decrypt traffic byte by byte.

Imagine guessing a secret message by slipping slightly altered envelopes into a mailroom and watching which ones get rejected for being the wrong thickness. In 2014, researchers showed that an attacker on the same network could trick a browser into falling back to an outdated 1990s encryption protocol (SSL 3.0) and then send hundreds of tweaked requests to read secret login cookies one letter at a time—which finally forced the internet to retire SSL 3.0.

At the time, browsers automatically retried failed TLS 1.2 handshakes using SSL 3.0 for compatibility with old servers, so a network attacker could force a downgrade and use JavaScript in a hidden page to trigger repeated requests until session cookies leaked. Fixing POODLE required disabling SSL 3.0 across browsers and servers and deploying TLS_FALLBACK_SCSV so clients reject unexpected protocol downgrades.

Why did disabling SSL 3.0 on servers matter even when most browsers already supported TLS 1.2?

Without disabling SSL 3.0 or enabling downgrade protection, an active attacker could block TLS 1.2 handshakes and force the browser to fall back to the vulnerable SSL 3.0 protocol.

Tracked as CVE-2014-3566, POODLE exploits SSL 3.0’s MAC-then-pad-then-encrypt CBC construction, where padding bytes prior to the final length byte are neither covered by the MAC nor checked by the receiver. By shifting a target plaintext byte to the end of a block and substituting that ciphertext block into the final padding block, an attacker observes a 1-in-256 acceptance oracle when the unverified padding length matches block_size − 1, recovering Plast = D(Ctarget) XOR Cprev. Mitigated by retiring SSL 3.0, enforcing TLS_FALLBACK_SCSV (RFC 7507), and using AEAD ciphers in TLS 1.2/1.3.

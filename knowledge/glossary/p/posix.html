POSIX - Portable Operating System Interface

The standard that defines common operating system interfaces so software can run across Unix-like systems.

Think of POSIX like a standard electrical outlet: if different operating systems follow the same basic rules for opening files, running commands, and talking to programs, a program written for one system can move to another without being rewritten from scratch.

In Linux and BSD, POSIX covers the C library API, standard utilities (such as ls, grep, and sh), and shell syntax. Knowing the boundary between POSIX sh and Bash-specific extensions helps you write portable scripts that work even on minimal systems using dash or BusyBox.

Why might a script starting with #!/bin/sh fail on one Linux system even though it worked on another?

Because /bin/sh may point to a strict POSIX shell like dash rather than Bash. Features such as [[ ... ]] or arrays are Bash extensions, not POSIX, so a minimal POSIX shell rejects them.

IEEE Std 1003.1 (the Single UNIX Specification) standardizes source-level C APIs (open, fork, pthread_create), signal semantics, and shell grammar rather than a binary ABI—portable binaries still depend on matching kernel ABIs and libc conventions. Real-world systems also diverge in edge cases such as readdir ordering, O_DIRECT alignment, and cross-mount rename returning EXDEV; setting POSIXLY_CORRECT switches GNU utilities into stricter POSIX option-parsing mode.

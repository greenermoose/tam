Guide / Glossary A–Z / Terms beginning with P / Partition

A partition is a defined section of a physical or virtual storage device that an operating system manages as its own separate space.

Think of a large bookshelf divided into labeled sections with bookends—one shelf for work, another for photos, and another for system backups. Even though it is all one physical drive, dividing it into partitions lets the computer keep different kinds of data separate, run more than one operating system, or erase one section without touching the others.

On Linux, a disk like /dev/nvme0n1 or /dev/sda stores a partition table at the start of the drive, and the kernel exposes each partition as its own block device (such as /dev/nvme0n1p1 or /dev/sda1) that can hold a filesystem, swap space, or an LVM physical volume. Modern systems use GPT (GUID Partition Table), while older drives may use MBR, which is limited to four primary partitions and 2 TiB disks. Tools like lsblk, fdisk, and parted inspect and edit these layouts.

What is the difference between a disk device like /dev/sda and a partition device like /dev/sda1?

/dev/sda represents the entire raw storage device, including its partition table. /dev/sda1 represents only the specific range of blocks assigned to the first partition, which is where you normally format and mount a filesystem.

A partition is a metadata entry in a disk label mapping a contiguous range of Logical Block Addresses (LBAs) plus type/attribute flags. GPT (UEFI specification) stores a protective MBR at LBA 0, a primary header at LBA 1, and a CRC32-checksummed array of 128-byte partition entries (with backup structures at the end of the disk), supporting 128+ partitions and 64-bit LBA addressing. The Linux kernel parses these tables via block/partitions/ at probe time (or on BLKRRPART / partx ioctls) and creates child block_device nodes; misaligned partition boundaries that do not match physical 4 KiB sectors or flash erase blocks can trigger read-modify-write amplification.

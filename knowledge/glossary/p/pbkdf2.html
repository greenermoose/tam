Guide / Glossary A–Z / Terms beginning with P / PBKDF2 (Password-Based Key Derivation Function 2)

PBKDF2 (Password-Based Key Derivation Function 2) is an older cryptographic method for turning a human password into a fixed-length encryption key.

Human passwords are usually short and predictable, so turning one straight into an encryption lock would make it easy for an attacker to guess. PBKDF2 slows attackers down by running a scrambling step thousands of times in a row before producing the key. It still works for older systems, though newer methods do a better job of resisting modern graphics-card cracking rigs.

PBKDF2 mixes a password, a random salt, and a pseudorandom function (usually HMAC-SHA256) for a configurable iteration count. On Linux, you may encounter it in older LUKS1 encrypted volumes or Wi-Fi WPA2 pre-shared keys. Because PBKDF2 requires almost no RAM, specialized hardware like GPUs and ASICs can test billions of guesses per second in parallel—which is why modern Linux tools default to memory-hard KDFs like Argon2id instead.

Why do modern disk-encryption setups prefer Argon2id over PBKDF2 even when PBKDF2 uses hundreds of thousands of iterations?

PBKDF2 is purely CPU-bound and uses negligible memory, so attackers can run thousands of parallel cracking instances on GPUs or ASICs. Argon2id requires substantial RAM per guess, making large-scale parallel cracking far more expensive.

Defined in RFC 8018 (PKCS #5 v2.1), PBKDF2 computes each hLen-bit output block T_i by XORing c chained evaluations of a PRF (typically HMAC-SHA-256 or HMAC-SHA-512) keyed by the password over salt || INT_32_BE(i). Its time cost scales linearly with c and output block count (an attacker only needs the first block when verifying a password hash), while space complexity remains O(1). Consequently, PBKDF2 is retained mainly for FIPS 140-2/140-3 compliance (NIST SP 800-132) and legacy protocols (WPA2-PSK, LUKS1, ZIP/PKCS#12), whereas new deployments should use Argon2id.

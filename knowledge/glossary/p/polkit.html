Guide / Glossary A–Z / Terms beginning with P / Polkit (PolicyKit)

A Linux authorization framework that decides whether unprivileged users or desktop sessions may perform privileged system actions.

Instead of handing you the master key to the entire computer every time you need to mount a USB drive, change the time zone, or install a system update, Linux uses Polkit like a building’s security desk. Your desktop asks the security desk for permission for that one specific task, and Polkit checks who you are and whether you need to type your password first.

Unlike sudo, which grants a full command or root shell based on /etc/sudoers, Polkit authorizes fine-grained D-Bus actions—such as org.freedesktop.udisks2.filesystem-mount—used by systemd, NetworkManager, and desktop settings panels (as well as pkexec). Custom rules live in /etc/polkit-1/rules.d/, and a desktop authentication agent displays the password dialog when an action requires confirmation.

How does Polkit’s permission model differ from sudo?

sudo launches an entire process as root, whereas Polkit lets a non-privileged app ask a privileged system daemon to perform one specific, policy-checked action.

The polkitd daemon acts as a central D-Bus authority: privileged mechanisms call CheckAuthorization with a Subject (e.g., unix-process or system-bus-name correlated with a systemd-logind session) and an Action ID declared in XML .policy files with allow_any, allow_inactive, and allow_active defaults. JavaScript rules in rules.d (evaluated lexically via polkit.addRule) can override decisions or trigger a registered AuthenticationAgent backed by polkit-agent-helper-1 and PAM, avoiding ambient root privileges.

Prompt

A prompt is text displayed by a program—most often a command-line shell—to show that it is waiting for you to type an instruction.

Think of a prompt like a cursor blinking next to a blank line on a form, or a cashier saying “Next, please.” It tells you the computer has finished its previous task and is ready for your next command. In tutorials, you will often see a symbol like $ at the start of a line; that symbol represents the prompt itself, so you only type the command after it.

In a Linux shell such as Bash or Zsh, the prompt commonly displays useful context—such as your username (alex), hostname, current working directory, and whether you are running as a regular user ($) or root (#). A multi-line command that is still waiting for a closing quote or brace shows a secondary continuation prompt (often >) instead of executing immediately.

Check: you copy-paste $ ls -la from a guide into your terminal and get “$: command not found”. Why?

The leading $ in the guide represents the shell prompt, not part of the command. Typing it tells the shell to run a program literally named $, so omit the prompt symbol and enter only ls -la.

POSIX shells render primary and secondary prompts from PS1 and PS2 (plus PS3 for select and PS4 for xtrace), while Zsh also supports right-hand RPS1 and prompt-expansion escapes (%n, %~). Non-printing ANSI escape sequences (colors, OSC 8 links, OSC 133 shell-integration marks) must be wrapped in \[...\] (Bash) or %{...%} (Zsh) so Readline/ZLE computes visible column width accurately; omitting them corrupts line wrapping and cursor positioning. Because prompt strings are purely cosmetic and trivially forged by any user or process, never treat a # prompt or colored badge as an indicator of effective UID or privilege.

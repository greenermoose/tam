Password

A password is a secret string of characters that a user provides to verify their identity when logging in or unlocking a resource.

A password works like a house key made of text: you type it in, and the computer checks whether it matches what it expects before letting you into your account. Because anyone who learns your password can act as you, using unique, hard-to-guess passwords—and storing them in a password manager—keeps one leaked account from compromising everything else.

On Linux, local user passwords are not stored in plain text; instead, /etc/shadow holds a salted cryptographic hash for each account, and tools like login, passwd, and sudo verify what you type through PAM (Pluggable Authentication Modules). Because the same password reused across websites can be exposed in a data breach, good practice is to use a unique password per service and prefer SSH keys or passkeys where supported.

Why can’t a system administrator look up your forgotten Linux password in /etc/shadow?

/etc/shadow stores a one-way salted hash of the password, not the password itself. The system can verify a candidate password by hashing it and comparing the result, but it cannot reverse the hash back into the original text.

As a knowledge authentication factor, passwords are verified either via server-side salted key-stretching hashes (such as yescrypt, Argon2id, or bcrypt, identified by modular crypt format prefixes like $y$ or $2b$ in /etc/shadow) or via zero-knowledge / PAKE protocols (e.g., SRP, OPAQUE) so the plaintext secret never traverses the wire or sits in server memory long-term. Per-user random salts defeat precomputed rainbow tables, while high work factors (time, memory, and parallelism parameters) bound offline brute-force throughput on GPUs and ASICs.

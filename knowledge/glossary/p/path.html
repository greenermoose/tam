Path

A path is a text address that tells an operating system or program where to find a file or directory.

Think of a path like a mailing address for your files. Instead of street, city, and house number, it lists the folders you walk through to reach a document—like /home/alex/notes.txt. Knowing how paths work helps you tell programs exactly which file to open or save without getting lost.

On Linux, paths use forward slashes (/) as separators. An absolute path starts at the root directory (/home/alex/notes.txt) and always points to the same place regardless of where you are, while a relative path (notes.txt or ../docs/plan.md) is resolved from your current working directory (pwd). Special segments . (current directory) and .. (parent directory) let you navigate relative to your location.

If your current working directory is /home/alex/projects, where does the relative path ../notes.txt point?

It points to /home/alex/notes.txt. The .. segment moves up one level from projects to /home/alex, and then selects notes.txt inside that parent directory.

The Linux VFS resolves paths component-by-component via path_lookupat(), consulting the dentry cache (dcache), crossing mount points, and expanding symbolic links (bounded by ELOOP / MAXSYMLINKS = 40). Because hard links allow multiple directory entries to reference the same inode, a path is a name rather than the object’s identity. POSIX requires PATH_MAX (4096 bytes on Linux) and NAME_MAX (255 bytes per component) limits for syscalls like openat(2); relative lookups with openat() and RESOLVE_NO_SYMLINKS / RESOLVE_BENEATH in openat2(2) prevent TOCTOU and symlink-traversal races.

Guide / Glossary A–Z / Terms beginning with P / PIE (Position-Independent Executable)

A Position-Independent Executable (PIE) is a compiled program whose machine code can be loaded at an arbitrary virtual memory address each time it runs.

Normally, a program expects to be placed at one fixed address in memory, which makes it easier for attackers to guess where specific instructions live. A PIE program is built like a modular building that works wherever the operating system places it, so Linux can drop it at a different random memory location every time it starts.

Modern Linux distributions compile user-space binaries with -fPIE -pie by default so Address Space Layout Randomization (ASLR) protects the main executable itself, not only shared libraries and the stack. You can check whether a binary is PIE with file (which reports pie executable or shared object) or readelf -h. By contrast, older fixed-address (ET_EXEC) binaries still load at a predictable base address even when ASLR is enabled.

Why does ASLR need a binary to be compiled as PIE to protect the program’s own code?

Without PIE, the executable’s machine code relies on fixed virtual addresses and must load at a predetermined base address. Compiling as PIE makes the code relocatable so the kernel can randomize its base address on every launch.

At the ELF level, a PIE binary carries e_type = ET_DYN rather than ET_EXEC, alongside a PT_INTERP header and an entry point (e_entry) relative to the randomized load bias chosen by the kernel’s ELF loader. It relies on PC-relative addressing (RIP-relative on x86-64, ADRP/ADD on AArch64) and GOT/PLT indirection for external symbols, avoiding text relocations (TEXTREL) that would violate W^X page protections. Trade-offs include slight register/code-size overhead on architectures without cheap PC-relative addressing (such as 32-bit x86) and special self-relocation startup for -static-pie binaries.

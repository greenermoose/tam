Procfs (process filesystem)

A virtual filesystem that exposes process and kernel information.

Even though /proc looks like a normal folder full of files, nothing inside it is stored on your hard drive. Instead, the operating system creates those files on the fly so tools and users can peek at what programs are running and how memory and CPU are doing.

Mounted at /proc, procfs exposes per-process directories by PID (such as /proc/self/status), hardware summaries (/proc/cpuinfo, /proc/meminfo), and live kernel tunables under /proc/sys/ (managed with sysctl). Reading procfs files is safe, whereas writing to /proc/sys/ as root changes kernel behavior immediately until reboot.

Why do files inside /proc often show a size of 0 bytes in ls -l even when reading them prints lots of text?

Because procfs files do not exist on disk with a precomputed size. The kernel generates their contents dynamically at the moment a program opens and reads them.

procfs is a pseudo-filesystem whose VFS handlers invoke kernel callbacks on access rather than reading backing storage. Process entries enforce ptrace_may_access and hidepid mount options. Reads across multiple files or large buffers are not globally atomic, and /proc/<pid> path lookups are racy against process exit and PID reuse—modern Linux code uses pidfd_open(2) for stable process references. In containers, /proc is partially masked or mediated (e.g., via LXCFS) so host metrics like /proc/meminfo do not leak or mislead.

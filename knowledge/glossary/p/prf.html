PRF (Pseudorandom Function)

Keyed deterministic function whose outputs are indistinguishable from a truly random function.

A PRF works like a locked magic box: you feed in a label and it always hands back the same messy, random-looking number. Anyone without the secret key cannot predict the output or tell it apart from pure coin flips, even after seeing many examples.

Protocols like TLS and SSH use HMAC and HKDF as PRFs to derive session keys and authentication tags from a shared secret. Unlike a plain hash function, a PRF takes a secret key, and its deterministic behavior lets both sides compute the exact same keys independently.

If a PRF is deterministic—always returning the same output for the same key and input—why is it called “pseudorandom”?

Without the secret key, an observer cannot distinguish the outputs from truly random values, even if they choose the inputs. Determinism is required so both parties holding the key derive identical results.

A keyed family F_K: {0,1}^n -> {0,1}^m computationally indistinguishable from a uniform random function to any PPT oracle adversary. Unlike a PRP (Pseudorandom Permutation, such as AES), a PRF need not be invertible; by the PRF/PRP switching lemma, a PRP behaves as a PRF up to q^2 / 2^(n+1) queries (the birthday bound). Plain Merkle–Damgård hashes H(K || m) fail as PRFs due to length-extension attacks, whereas HMAC is a proven PRF under compression-function assumptions.

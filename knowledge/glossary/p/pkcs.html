PKCS (Public-Key Cryptography Standards)

A numbered family of standards that define formats and interfaces for public-key cryptography, key files, and hardware tokens.

Just as standardized electrical plugs let appliances from different brands fit the same wall outlet, security software needs agreed-upon formats so keys and certificates made by one program work in another. PKCS is a set of numbered rulebooks that cover everything from how a private key file is structured on disk to how your computer talks to a USB security key.

In everyday Linux administration, you regularly run into a few key members of the family: PKCS#1 defines RSA keys and signatures, PKCS#5 covers password-based key derivation, PKCS#8 is the standard algorithm-agnostic format for private key files (BEGIN PRIVATE KEY in PEM), PKCS#11 provides a plugin API for smart cards and HSMs, and PKCS#12 (.p12/.pfx) bundles a certificate and its private key into one password-protected file.

Why do modern tools prefer PKCS#8 over PKCS#1 when storing private keys?

PKCS#1 only describes RSA keys, whereas PKCS#8 wraps an algorithm identifier alongside the key bytes so one format handles RSA, ECDSA, and Ed25519 uniformly.

Originally published by RSA Laboratories and now maintained across IETF RFCs and OASIS, the suite specifies ASN.1 DER encodings and APIs: PKCS#1 v2.2 (RFC 8017) defines RSASSA-PSS and RSAES-OAEP alongside legacy v1.5 padding; PKCS#5 v2.1 (RFC 8018) specifies PBKDF2 and PBES2; PKCS#8 (RFC 5958) defines PrivateKeyInfo and OneAsymmetricKey; PKCS#11 (OASIS Cryptoki) exposes slots, tokens, sessions, and mechanisms used on Linux via p11-kit and OpenSC; and PKCS#12 (RFC 7292) defines authenticated, encrypted PFX archive bags.

Ping

Ping is a network diagnostic tool that sends echo requests to a target host and measures whether—and how quickly—replies come back.

Think of ping like calling out “Are you there?” across a canyon and listening for an echo. It sends a tiny test message to another computer or website and times how long the reply takes to return, helping you see whether the connection is working and how responsive it feels.

On Linux, ping sends ICMP (or ICMPv6) Echo Request packets and reports round-trip time (RTT), jitter, and packet loss. Keep in mind that ping only tests basic IP reachability and ICMP handling—not whether a web server or SSH port is listening. Conversely, a healthy server can time out on ping if a firewall drops ICMP Echo packets. Unlike Windows, Linux ping runs until you press Ctrl+C or pass -c 4.

If ping to a server fails with 100% packet loss, does that prove the website or SSH service on that server is down?

No. ping tests ICMP Echo Request/Reply, which firewalls and cloud security groups frequently block or rate-limit independently of TCP services such as HTTPS or SSH.

ping uses ICMP Type 8 / Code 0 (Echo Request) and Type 0 / Code 0 (Echo Reply) for IPv4 (RFC 792), or ICMPv6 Types 128/129 for IPv6 (RFC 4443). On modern Linux, unprivileged ping typically opens a SOCK_DGRAM IPPROTO_ICMP socket governed by net.ipv4.ping_group_range instead of requiring CAP_NET_RAW. Interpreting results requires accounting for router control-plane policing (which rate-limits CPU-generated ICMP replies without affecting transit traffic), asymmetric routing, and DF-bit Path MTU probing via ping -M do -s <size>.

Port

A numbered endpoint used by network protocols to route traffic to the right service on a host.

Think of an IP address as the street address of an apartment building, and a port number as the apartment number inside it. When data arrives at your computer, the port number tells the operating system which program should receive it—web traffic goes to one apartment, file transfers to another—so many network apps can share one internet connection at the same time.

TCP and UDP ports run from 0 to 65535: well-known ports (0–1023, such as 22 for SSH and 443 for HTTPS) are used by standard services, registered ports (1024–49151) by applications, and ephemeral ports (controlled on Linux by net.ipv4.ip_local_port_range, typically 32768–60999) are assigned automatically to outgoing client connections. You can list listening ports on Linux with ss -tulnp and restrict external access with a firewall.

Can two different programs on the same machine listen on port 443 at the same time?

Normally no for the same IP address and transport protocol (e.g., two TCP servers on 0.0.0.0:443), though one program can use TCP 443 while another uses UDP 443 (such as HTTP/3 over QUIC).

A 16-bit unsigned integer (0–65535) in the transport header (TCP, UDP, SCTP) that demultiplexes flows within a host; a connected TCP socket is uniquely keyed by the 5-tuple (protocol, src_ip, src_port, dst_ip, dst_port). On Linux, binding ports below net.ipv4.ip_unprivileged_port_start (default 1024) requires CAP_NET_BIND_SERVICE; SO_REUSEADDR allows rebinding over sockets in TIME_WAIT, whereas SO_REUSEPORT lets multiple sockets bind the same address/port for in-kernel accept load balancing.

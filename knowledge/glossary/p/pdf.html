Guide / Glossary A–Z / Terms beginning with P / PDF (Portable Document Format)

PDF is a fixed-layout document format (ISO 32000) designed to preserve fonts, page geometry, images, and vector graphics consistently across different devices and printers.

Unlike a webpage or word-processor file that reflows text to fit your screen, a PDF is like a digital sheet of printed paper. Whether you open it on a phone, a Linux laptop, or a print shop’s press, the margins, fonts, and diagrams stay in the exact same place.

On Linux, lightweight viewers such as zathura or evince render PDFs via Poppler or MuPDF, while tools like qpdf, pdftoppm, and print dialogs generate or split them. Unlike HTML or Markdown, PDF stores positioned glyphs rather than flowing paragraphs, making direct text editing awkward. Scanned PDFs may also contain only raster images unless an OCR text layer was added.

Why can you open some PDFs with crisp-looking text and still be unable to highlight or search any words?

Those PDFs likely store each page as a scanned raster image rather than embedded font glyphs and text operators. Without an OCR (Optical Character Recognition) text layer, viewers have no character data to select or search.

Standardized in ISO 32000-2 (PDF 2.0), a PDF is a graph of typed objects indexed by a cross-reference (xref) table or stream for random page access. Content streams use postfix stack-based graphics operators derived from PostScript (without Turing-complete loops) alongside embedded CFF/TrueType/Type 0 fonts, ICC profiles, and XMP metadata. Security and parsing pitfalls include incremental updates that retain unredacted prior revisions, embedded JavaScript/launch actions, and strict archival subsets like PDF/A that forbid external fonts or encryption.

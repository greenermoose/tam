PCR (Platform Configuration Register)

A PCR is a tamper-evident register inside a Trusted Platform Module (TPM) that stores cryptographic measurements of each stage of the boot process.

Think of a PCR as a tamper-proof logbook that can only be added to, never erased, until the computer restarts. At each step of turning the machine on—firmware, startup menu, operating system—the security chip mixes a digital fingerprint of what just ran into the register. If any startup file was swapped or altered, the final fingerprint will not match, so the chip refuses to hand over saved secrets like disk-unlock keys.

In Linux measured boot, tools such as systemd-cryptenroll seal LUKS2 disk keys to specific TPM2 PCRs—commonly PCR 7 for Secure Boot policy and certificates, or PCR 0 and 4 for firmware and bootloader code. You can inspect live values with tpm2_pcrread. A common pitfall is sealing to PCRs that change on routine updates without keeping a fallback recovery passphrase.

Why does a firmware or bootloader update often break TPM2 automatic disk unlock?

Because PCR values are cryptographic hashes of the exact code and configuration measured during boot. Updating the firmware or bootloader changes those measurements, so the TPM sees a different PCR state than the one the LUKS2 key was sealed against and refuses to unseal it.

TPM 2.0 PCRs are grouped into hash-algorithm banks (typically SHA-256) and can only be cleared on platform reset—or locality-restricted reset for dynamic PCRs 17–22 in DRTM—and updated via TPM2_PCR_Extend: PCR_new = H(PCR_old || digest). Because extension is one-way and order-dependent, software cannot forge an earlier state. Binding keys via TPM2_PolicyPCR is brittle across updates, whereas TPM2_PolicyAuthorize (or signed PCR policies like systemd-pcrlock) allows authorized future measurements without losing unseal capability.

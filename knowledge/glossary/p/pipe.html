Pipe

A connection that sends one program’s output directly into another program’s input.

Think of a pipe like a bucket brigade or a garden hose between two machines: as soon as the first program produces data, it flows straight into the second program without needing to save a temporary file on disk. This lets you snap small, focused tools together to do bigger jobs.

In a Linux shell, the | operator creates an anonymous pipe connecting the first command’s standard output (stdout) to the next command’s standard input (stdin), so both run concurrently. Unlike redirecting to a file with >, a pipe streams data in memory and passes error output (stderr) to the terminal unless explicitly redirected. Named pipes (FIFOs, created with mkfifo) work similarly but appear as entries in the filesystem so unrelated processes can open them.

Why does running yes | head -n 5 stop immediately instead of hanging forever?

Once head reads five lines and exits, the read end of the pipe closes. When yes tries to write more data, the kernel sends it a SIGPIPE signal, terminating it cleanly.

Created via pipe(2) or pipe2(2), an anonymous pipe is an unlinked inode in the kernel’s pipefs virtual filesystem backed by a ring buffer of memory pages (16 pages / 64 KiB by default on Linux, adjustable via F_SETPIPE_SZ). POSIX guarantees writes up to PIPE_BUF (4096 bytes on Linux) are atomic. Reads block when empty and return 0 (EOF) only after every file descriptor referencing the write end is closed; writes block when full and fail with EPIPE (raising SIGPIPE unless ignored) when no read descriptors remain. Data can also move between pipes and other file descriptors without userspace copies via splice(2) and tee(2).

PKGBUILD

A shell-script build recipe used by Arch Linux’s makepkg tool to download, compile, and package software.

A PKGBUILD is like a recipe card for building a program from source code. It lists where to download the ingredients, how to check that they were not corrupted or tampered with, what tools are needed to cook them, and where the finished files belong so the package manager can install or cleanly remove the program later.

A typical PKGBUILD sets metadata variables (pkgname, pkgver, pkgrel, depends, source, sha256sums) and defines functions such as prepare(), build(), check(), and package(). Inside package(), files are installed into $pkgdir—a temporary staging directory mirroring /—rather than directly onto your live system, before makepkg compresses them into a .pkg.tar.zst archive.

Why should you read an unfamiliar AUR PKGBUILD before running makepkg?

A PKGBUILD is an executable Bash script, so makepkg runs arbitrary shell commands from it under your user account as soon as it sources the file.

makepkg(8) sources the PKGBUILD in Bash, validates sources against checksums or PGP validpgpkeys, and executes package() inside fakeroot so root-owned paths are recorded in the archive without escalating privileges. A single PKGBUILD can define a split package via pkgbase and multiple package_<name>() functions, emitting .PKGINFO, .BUILDINFO, and .MTREE metadata inside the zstd-compressed tarball; accompanying .SRCINFO files provide static key-value metadata for AUR indexing without executing untrusted Bash.

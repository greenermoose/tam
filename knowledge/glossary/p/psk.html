PSK (Pre-Shared Key)

A PSK (Pre-Shared Key) is a secret key or passphrase shared between two parties ahead of time—outside the network connection itself—and used to authenticate and encrypt their communication.

Think of a pre-shared key like a secret password you tell a friend in person before you start sending coded notes. Your home Wi-Fi password is the most familiar example: every phone and laptop that knows the password can prove it belongs on the network and scramble its traffic so neighbors cannot read it.

In Wi-Fi (WPA2-PSK and WPA3-Personal) and VPNs (such as WireGuard’s optional PresharedKey), both endpoints must already hold the same secret—unlike public-key certificates where a server proves its identity using a Certificate Authority. TLS 1.3 also uses PSKs for session resumption, letting a client reconnect quickly using a secret ticket issued during an earlier full handshake.

Check: if you change the PSK on a Wi-Fi router, why do all connected devices immediately lose access until updated?

Because PSK authentication is symmetric: both the access point and every client must derive session keys from the exact same pre-shared secret, so any device still holding the old key fails the handshake.

PSK security depends heavily on how the shared secret enters key derivation. Legacy WPA2-PSK runs PBKDF2-HMAC-SHA1 (4096 iterations, salted with the SSID) to map a passphrase to a 256-bit PMK, exposing the 4-way handshake to offline dictionary attacks; WPA3-Personal replaces this with SAE (Simultaneous Authentication of Equals, Dragonfly), an online-only PAKE that resists offline cracking and provides forward secrecy. In TLS 1.3 (RFC 8446), psk_ke derives session keys from the PSK alone (sacrificing forward secrecy if the ticket key leaks), whereas psk_dhe_ke combines the PSK with an ephemeral ECDHE exchange to preserve forward secrecy. Similarly, WireGuard mixes an optional 256-bit PSK into its Noise_IKpsk2 handshake solely as a post-quantum symmetric hedge alongside Curve25519.

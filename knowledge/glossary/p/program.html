Program

A program is a set of instructions a computer can follow.

A program is like a written recipe saved on your computer—such as your web browser or a text editor. While it sits on your drive, it is just stored instructions waiting to be used; it only starts doing work when you open it.

Contrast a program (static files on disk, such as /usr/bin/ls or a script) with a process (a live, running instance in memory). Starting the same program multiple times creates multiple independent processes.

If you delete a program’s file from disk while it is still running, why might it keep working until you close it?

The running process already has its code mapped into memory and its file inode open in the kernel. Deleting the directory entry only removes the name; the kernel frees the underlying data once the last process closes it.

On Linux, an executable program is typically an ELF binary (with .text, .rodata, .data, and PT_INTERP naming the dynamic linker) or a script with a #! shebang handled by binfmt_script in execve(2), often alongside shared libraries (DT_NEEDED) and data assets. The kernel maps read-only code pages (MAP_PRIVATE) so concurrent processes running the same program share physical RAM for .text while keeping isolated writable data segments.

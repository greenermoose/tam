Guide / Glossary A–Z / Terms beginning with P / Privilege

Special permission to do something restricted.

On a computer, everyday accounts can open their own files and run apps, but cannot erase system files or change settings for everyone. Privilege is the extra permission needed for those protected actions—like a master key that should only be used when truly necessary.

In Linux, an ordinary user (such as alex) runs unprivileged processes and temporarily elevates privilege via sudo or pkexec only for administrative tasks. Following the principle of least privilege limits the damage a buggy or compromised app can cause.

Why is it safer to run daily apps as a regular user and elevate only when needed, instead of logging in as root?

Every program inherits the privileges of the user who launches it. Running as a regular user confines any bug or malicious file to that user’s own data, whereas running as root exposes the entire operating system.

Linux decomposes traditional UID 0 root power into per-thread POSIX capabilities (e.g., CAP_NET_BIND_SERVICE, CAP_DAC_OVERRIDE, CAP_SYS_ADMIN) tracked across effective, permitted, inheritable, bounding, and ambient sets via prctl and setcap. Modern sandboxing layers MAC policies (SELinux/AppArmor), seccomp-bpf syscall filters, NoNewPrivs (blocking setuid/file-capability escalation across execve), and user namespaces (CLONE_NEWUSER) where capabilities hold only inside the namespace.

Packet

A packet is a formatted unit of data sent across a network, pairing a small block of payload with delivery information.

Imagine mailing a long letter by splitting it onto numbered postcards, each showing the sender’s address, the destination address, and its page number. Networks work the same way: instead of tying up a wire with one giant file all at once, computers chop data into small packets. Each packet can travel independently and be put back in order when it arrives, so many people can share the same network smoothly.

In the TCP/IP model, “packet” usually refers to a Layer 3 (IP) unit carrying a header—with source/destination IP addresses, TTL, and protocol number—and a payload that holds a Layer 4 segment (TCP) or datagram (UDP). By contrast, a Layer 2 “frame” wraps that packet with MAC addresses for the local link. Tools like tcpdump and wireshark let you inspect packet headers to see why traffic is dropped or misrouted.

Why does a large file download get split into many packets instead of being sent as a single multi-megabyte IP packet?

Physical links enforce a Maximum Transmission Unit (typically 1500 bytes for Ethernet). Splitting data into smaller packets fits link limits, allows routers to interleave traffic from many users, and avoids re-sending the entire file if one chunk is lost.

An IPv4 or IPv6 packet is a network-layer PDU encapsulated inside a link-layer frame, governed by link MTU and path MTU discovery (PMTUD). In IPv4, routers may fragment packets unless the DF (Don’t Fragment) bit is set, whereas IPv6 forbids in-flight router fragmentation and relies on ICMPv6 Packet Too Big messages and source-side fragmentation extension headers. Header checksums (present in IPv4, omitted in IPv6 in favor of L2/L4 checksums), DSCP/ECN fields, and TTL/Hop Limit dictate forwarding, congestion signaling, and loop prevention; modern NICs often coalesce or segment packets in hardware (TSO/GSO/GRO) above the wire MTU.

Parity

Parity is a simple error-checking bit added to a group of bits to detect whether data was corrupted during storage or transmission.

Imagine counting the ones in a row of switches and adding one extra switch at the end so the total number of “on” switches is always even. If electrical noise accidentally flips one switch along the way, the receiver recounts them, sees an odd total, and knows something went wrong. It cannot tell which switch flipped or fix the mistake on its own, but it gives a quick warning that the data should be re-sent.

Parity computes the modulo-2 sum (XOR) of a word’s data bits: in even parity, the parity bit makes the total count of 1s even; in odd parity, it makes the count odd. You will see parity settings in serial port configurations (such as 8N1—8 data bits, No parity, 1 stop bit—or 8E1) and in storage arrays like RAID 5, where a parity block lets the array rebuild a single failed drive. Its main limitation is that an even number of simultaneous bit flips leaves the parity unchanged.

If a byte uses even parity and two bits flip during transmission, will the receiver detect the error?

No. Flipping two bits changes the count of 1s by +2, 0, or -2, which preserves whether the total is even or odd. Single-bit parity can only detect an odd number of bit errors.

A single parity check forms a [n, n-1, 2] linear block code over GF(2) with minimum Hamming distance d_min = 2, yielding single-error detection (all odd-weight error patterns) and zero error-correction capability. In hardware, parity trees are implemented with cascaded XOR gates; in memory and storage subsystems, orthogonal parity checks—such as Hamming SECDED (single-error correction, double-error detection) in ECC DRAM or XOR/Reed–Solomon syndrome stripes in RAID 5/6—combine multiple parity equations over distinct bit subsets to localize and invert faulty bits or reconstruct erased blocks.

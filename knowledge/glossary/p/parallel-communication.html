Parallel Communication

Parallel communication sends multiple bits of data at the same time over separate physical wires.

Think of cars driving side by side on an eight-lane highway instead of lining up single file on a one-lane road. An entire 8-bit byte can travel in a single tick because each bit gets its own wire. Older printers and disk drives used wide, flat ribbon cables for this, and it still matters inside modern computers where short, fast connections between chips need to move lots of data at once.

In a parallel bus, all data wires are sampled together against a shared clock signal. On Linux, you still encounter legacy parallel hardware in kernel module names like lp or parport, though external cables—such as Centronics printer ports and PATA/IDE drives—were replaced by serial links like USB and SATA because tiny differences in wire length cause bits to arrive out of step (clock skew) at high frequencies. Inside the machine, however, memory channels (DDR4/DDR5) remain parallel because traces on a circuit board are short and tightly length-matched.

Why did external cables switch from parallel to serial even though sending 8 or 16 bits at once sounds faster?

At high speeds, slight differences in wire length and electrical interference cause bits on parallel wires to arrive at slightly different times (skew), forcing the clock to slow down. Serial links avoid inter-wire skew and use differential signaling to run at much higher clock rates.

Wide-bus synchronous interfaces (such as legacy 32-bit/64-bit PCI, ATA/IDE, and modern DDR4/DDR5 SDRAM channels) trade pin count and PCB routing complexity for per-cycle throughput. Key physical-layer limits include flight-time skew across traces, simultaneous switching noise (SSN) on shared power/ground return paths, and capacitive/inductive crosstalk between adjacent conductors. While external interconnects migrated to embedded-clock serial SerDes lanes (PCIe, SATA, USB), memory buses retain parallel DQ/DQS architectures by enforcing picosecond-scale trace-length matching (serpentine routing), per-bit deskew training during initialization, and on-die termination (ODT).

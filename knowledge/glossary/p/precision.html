Precision

Precision describes how finely a representation can distinguish numbers.

A ruler marked in millimetres is more precise than one marked only in centimetres. The extra marks let you write a more detailed measurement, though the measurement can still be wrong.

A 64-bit floating-point number carries about 15 to 17 decimal digits; a 32-bit one carries about 6 to 9. More precision reduces rounding error but uses more memory and may run slower. Precision is not accuracy: a value written to many digits can still be far from the true quantity if the sensor or method was poor.

If a calculation prints 0.30000000000000004, is it accurate to 17 digits?

No. Those digits show the format's precision, not the truth of the result. The input 0.1 was already approximated, so the trailing digits mostly describe binary rounding.

In IEEE 754 binary formats, unit roundoff is half the spacing at the current exponent; relative error for correctly rounded normal operations is bounded by that value. Binary64 has 53 significand bits including the implicit bit, giving about 16 decimal digits. Mixed-precision workflows choose narrow storage and wide accumulation, but operation order and cancellation still govern result quality. Condition numbers measure how input error is amplified by the problem itself, independently of the arithmetic precision.

Guide / Glossary A–Z / Terms beginning with P / Paging

Paging is a memory-management technique that divides memory into fixed-size blocks called pages and moves them between RAM and storage as needed.

Picture a small desk where you can only spread out a few pages of a big book at once; the rest of the book sits on a shelf nearby. Your computer treats fast working memory (RAM) like that desk and your disk or SSD like the shelf. Paging quietly moves inactive chunks of data off the desk to free up space for what you are actively using, then brings them back when you need them again.

Linux manages memory in fixed-size pages (commonly 4 KiB) so programs see a clean, contiguous virtual address space even when physical RAM frames are scattered. Under memory pressure, the kernel writes inactive anonymous pages out to swap space (or compressed RAM like zram) and keeps file-backed pages ready to re-read from disk. Heavy paging—called thrashing—shows up as high disk I/O and sluggish responsiveness in tools like vmstat.

If a system still has free space on its swap partition, why can heavy paging still make the desktop feel frozen?

Storage (even an NVMe SSD) is orders of magnitude slower than RAM. When active working sets no longer fit in RAM and pages are constantly written out and faulted back in, the CPU spends its time waiting on I/O.

Paging implements demand-paged virtual memory via multi-level hardware page tables (e.g., 4- or 5-level paging on x86-64 with 4 KiB, 2 MiB, or 1 GiB huge pages) cached in the TLB. Accessing an unmapped or swapped-out virtual page raises a page fault (minor if the page is already in the page cache or zero-filled, major if storage I/O is required). Unlike legacy whole-process swapping, Linux’s kswapd and direct reclaim use active/inactive LRU lists (or MGLRU) to evict individual pages, balancing page-cache reclaim against anonymous swap-out according to vm.swappiness and cgroup memory limits.

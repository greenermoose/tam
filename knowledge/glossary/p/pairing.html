Guide / Glossary A–Z / Terms beginning with P / Pairing

Pairing is the setup process in which two devices verify each other and establish shared security keys so they can communicate privately.

Pairing is like introducing two people and agreeing on a secret handshake so they recognize each other next time. When you put wireless headphones or a keyboard into pairing mode and confirm them on your computer, the two devices trade credentials once. After that, they can reconnect automatically without asking you to repeat the setup or letting strangers listen in.

In Bluetooth, pairing creates temporary encryption for the current session, while “bonding” saves the resulting keys so the devices trust each other across future reconnects. On Linux you typically manage this through a desktop Bluetooth panel or bluetoothctl (pair, trust, connect). If a device stops reconnecting after a dual-boot or hardware reset, removing the old pairing on both sides and re-pairing resolves key mismatches.

Why does pairing a Bluetooth mouse in one OS often break its automatic connection in another OS on the same dual-boot PC?

Both OSes share the same Bluetooth adapter MAC address, but each generates a different link key during pairing. The mouse stores only the most recent key for that MAC address, so the other OS’s saved key no longer matches.

Bluetooth pairing executes an authentication and key-generation protocol to derive a Link Key (BR/EDR) or Long Term Key (LE) and optionally store it as a persistent bond. Secure Simple Pairing (SSP) and LE Secure Connections use ECDH (P-256) key exchange with association models—Numeric Comparison, Passkey Entry, Out-of-Band, or Just Works—where only the first three authenticate against active MITM attacks. Key distribution, Identity Resolving Keys (IRKs) for randomizable BLE privacy addresses, and BlueZ’s per-adapter storage under /var/lib/bluetooth/ govern how bonded devices re-encrypt links on reconnection.

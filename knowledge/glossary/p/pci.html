PCI - Peripheral Component Interconnect

PCI (Peripheral Component Interconnect) is an older parallel expansion bus standard used to connect add-in cards and built-in devices inside a computer.

Before modern PCI Express slots took over, desktop computers used white PCI slots on the motherboard to add sound cards, network cards, and modems. Even though those physical slots are mostly gone today, the way computers discover and talk to hardware still builds directly on PCI’s design.

Conventional PCI used a shared parallel bus (typically 32 bits wide at 33 MHz, giving 133 MB/s shared across all slots) where every card competed for the same wires. While physically replaced by point-to-point PCI Express (PCIe), PCI’s software model lives on: on Linux, lspci still lists devices by PCI Bus/Device/Function (BDF) addresses like 00:1f.3 because PCIe keeps backward-compatible PCI configuration space.

Why does lspci still show devices on a modern laptop that has no physical PCI slots?

PCI Express (PCIe) and many integrated chipset devices preserve the PCI software configuration model—including Vendor/Device IDs and Bus:Device.Function addressing—so operating systems can enumerate and configure hardware uniformly.

Conventional PCI (PCI Local Bus Specification) defines a synchronous, reflected-wave parallel bus with multiplexed 32/64-bit address and data lines (AD[31:0]), centralized arbitration (REQ#/GNT#) for bus-mastering DMA, and level-triggered shared interrupts (INTA#–INTD#, later joined by MSI). Each function exposes a 256-byte configuration space (extended to 4 KiB in PCIe via ECAM) containing Vendor/Device IDs, Command/Status registers, and Base Address Registers (BARs) programmed by firmware/OS during enumeration to assign non-overlapping MMIO and legacy I/O port windows.

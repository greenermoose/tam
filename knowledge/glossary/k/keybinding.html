Keybinding

A keybinding is a key or key combination that triggers an action—such as opening a terminal, switching windows, or saving a file—instead of typing text.

Think of a keybinding like a speed-dial button on a phone: instead of clicking through menus to open an app or close a window, pressing one shortcut (like Meta+Enter or Ctrl+C) runs that command right away. Keybindings matter because they let you keep your hands on the keyboard and work much faster once you learn a few common ones.

In Linux, keybindings are handled at different layers depending on what they control. Global shortcuts (such as switching workspaces or launching a terminal) are intercepted by the desktop compositor before any window sees them, while application shortcuts (such as saving a file or copying text) are handled by the focused program itself. When two layers bind the same combination, the outer layer wins unless it forwards the key.

If you press Ctrl+C in a terminal and it stops a running command instead of copying text, which layer handled the key?

The terminal’s shell or foreground process handled it (by turning the control character into an interrupt signal), because the compositor did not intercept Ctrl+C as a global shortcut.

A keybinding pairs a modifier mask and either a layout-dependent keysym (such as XKB_KEY_Return) or a physical keycode with an action handler. Binding by keysym follows the active keyboard layout (for example, Dvorak vs. QWERTY), whereas binding by raw keycode anchors physical finger positions regardless of layout. Compositors and X11 window managers use passive grabs (XGrabKey in X11, or compositor-internal key tables in Wayland) so global bindings preempt client input focus, while also deciding repeat-rate behavior, release-vs-press triggers, and whether chords consume the event or pass it through.

Kitty keyboard protocol

The Kitty keyboard protocol is a modern terminal input standard that reports exact key presses, releases, and modifier combinations using unambiguous escape sequences.

Classic terminals were designed for 1970s teletypewriters, so many distinct keys look identical to a terminal app—for example, pressing Esc and pressing Ctrl+[ send the exact same byte, and terminals cannot tell when you let go of a key. The Kitty keyboard protocol upgrades that link so modern editors and games can tell every key combination apart, just like a native desktop app.

Supported by terminals such as Kitty, foot, Ghostty, and WezTerm, the protocol encodes keys as CSI code ; modifiers u instead of legacy control bytes. Applications opt in at runtime rather than forcing it on shells that do not understand it: an editor enables progressive enhancement flags when entering raw mode and disables them on exit. This lets tools like Neovim or Kakoune distinguish Ctrl+I from Tab, recognize Ctrl+Shift+letter, and detect key-release events.

What happens if a terminal supports the Kitty keyboard protocol, but the shell or program running inside it never opts in?

The terminal continues sending legacy ASCII and VT escape sequences so older programs keep working normally; the enhanced CSI ... u reporting only activates after the application requests it.

The Kitty protocol uses a stack-based progressive enhancement mechanism: clients query current flags with CSI ? u and push/update bitmask flags with CSI > flags u (or CSI = flags ; mode u), popping on exit with CSI < u. Five bit flags control disambiguation (1), event types—press, repeat, release (2), alternate keys—shifted and base-layout keys (4), reporting all keys as escape codes including modifiers alone (8), and associated text (16). The full wire grammar is CSI unicode-key-code : shifted-key : base-layout-key ; modifiers : event-type ; text-as-codepoints u, where modifiers encode 1 + bitmask (bit 0 = Shift, bit 1 = Alt, bit 2 = Ctrl, with higher bits for extended and lock modifiers). Including the base-layout key allows editors to bind physical keys across non-Latin layouts without losing layout-aware text input.

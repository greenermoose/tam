KVM (Kernel-based Virtual Machine)

KVM (Kernel-based Virtual Machine) is the virtualization subsystem built into the Linux kernel that turns Linux into a hypervisor using hardware CPU extensions.

Running a virtual machine means running a whole second operating system inside your computer. Without hardware help, software has to translate every instruction one by one, which is slow. KVM lets the Linux kernel hand virtual machine code directly to special virtualization features built into your CPU, so guest systems run at nearly the same speed as a physical machine.

KVM itself lives inside the kernel (kvm.ko plus kvm-intel.ko or kvm-amd.ko) and exposes /dev/kvm to user-space virtual machine monitors such as QEMU, Cloud Hypervisor, or Firecracker. KVM handles CPU execution and memory virtualization, while the user-space program handles virtual disks, network cards, displays, and boot firmware. You can verify hardware support by checking for /dev/kvm or vmx/svm flags in /proc/cpuinfo.

Why do people often say “QEMU/KVM” together instead of using KVM by itself?

Because KVM only virtualizes CPUs and memory inside the kernel; a user-space VMM like QEMU is still needed to emulate devices (disks, NICs, graphics) and manage the VM lifecycle.

User-space opens /dev/kvm and issues KVM_CREATE_VM, KVM_CREATE_VCPU, and KVM_RUN ioctls. Inside KVM_RUN, the kernel enters VMX non-root mode (Intel) or SVM guest mode (AMD), executing guest instructions natively until a VM-exit occurs (for example, on privileged I/O, MMIO, or EPT/NPT page faults). Guest-physical to host-physical address translation is offloaded to hardware two-dimensional paging (Intel EPT / AMD NPT), while vhost/ioeventfd/irqfd bypass user-space round-trips for high-throughput VirtIO queues.

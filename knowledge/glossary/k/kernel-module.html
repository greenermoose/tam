Kernel module

A kernel module is a piece of compiled kernel code—most often a hardware driver or filesystem—that can be loaded into and unloaded from a running kernel without rebooting.

Think of a kernel module like a plug-in adapter for your operating system’s core: when you plug in a new USB Wi-Fi stick or need a special disk format, the system can load just that piece of support on the fly instead of keeping every possible driver built in all the time or forcing a restart.

On Linux, loadable kernel modules live under /lib/modules/$(uname -r)/ as .ko (often compressed) files. You inspect loaded modules with lsmod, load one with dependencies via modprobe, and check its metadata with modinfo. Unlike a normal user program, a kernel module runs inside kernel space, so a bug in a module can crash the entire system rather than just one app.

Why is modprobe usually preferred over insmod when loading a kernel module manually?

Because modprobe reads modules.dep to automatically load any prerequisite modules first, whereas insmod tries to insert a single file and fails if its dependencies are missing.

A Linux loadable kernel module (LKM) is a relocatable ELF object (ET_REL) loaded via finit_module(2)/init_module(2), where the kernel resolves exported symbols (EXPORT_SYMBOL / EXPORT_SYMBOL_GPL) and applies relocations directly in kernel virtual address space. Because Linux has no stable internal kernel ABI, modules must be compiled against the exact kernel headers and configuration (or via DKMS), and may be blocked by Secure Boot lockdown or CONFIG_MODULE_SIG_FORCE if unsigned. Out-of-tree or proprietary modules set the kernel taint flag, complicating crash-dump diagnosis.

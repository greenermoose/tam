KMAC (Keccak Message Authentication Code)

KMAC (Keccak Message Authentication Code) is a cryptographic message authentication code and pseudorandom function built directly on the SHA-3 / cSHAKE family (NIST SP 800-185).

A message authentication code is like a tamper-evident wax seal stamped with a secret key: anyone who shares the key can verify that a message was not altered in transit. KMAC is a modern way to make that seal using the same mathematical sponge design as SHA-3, avoiding the extra wrapping steps older methods needed.

While HMAC has to wrap a traditional hash function in two nested passes (inner and outer key padding) to prevent length-extension attacks, KMAC absorbs the secret key directly into the Keccak sponge state alongside the message. It also acts as an extendable-output function (XOF), meaning you can request a tag or derived key of any length rather than being locked to a fixed digest size. KMAC comes in 128-bit and 256-bit security strengths (KMAC128 and KMAC256).

Why doesn’t KMAC need the double-hashing construction that HMAC uses?

Because the Keccak sponge construction is already immune to length-extension attacks and uses explicit domain separation, so absorbing the padded key once before the message is sufficient.

Defined in NIST SP 800-185, KMAC128(K, X, L, S) and KMAC256(K, X, L, S) are parameterized instances of cSHAKE128 and cSHAKE256 with function-name string N = "KMAC" and optional customization string S. The key K is encoded via encode_string(K) and padded with bytepad(..., 168) for KMAC128 (rate 1344 bits) or bytepad(..., 136) for KMAC256 (rate 1088 bits) before absorbing X and right_encode(L). Encoding the requested output length L at the end ensures domain separation between fixed-length MAC mode and arbitrary-length XOF mode (L = 0), preventing related-output attacks when the same key is used for different output sizes.

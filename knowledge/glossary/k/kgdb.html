Guide / Glossary A–Z / Terms beginning with K / KGDB (Kernel GNU Debugger)

KGDB (Kernel GNU Debugger) is a source-level debugger built into the Linux kernel that lets a second machine inspect and step through a running or crashed kernel over a serial port or network.

When a normal app crashes, you can inspect it with a debugger on the same screen. When the operating system kernel itself freezes, the whole screen and keyboard freeze with it—so you need an outside lifeline. KGDB acts like a diagnostic cable plugged into the car’s engine computer, letting a developer on a second laptop pause the frozen system and see exactly where it got stuck.

In practice, KGDB is most commonly used over a UART serial console via kgdboc (KGDB over console), configured on the kernel command line with parameters like kgdboc=ttyS0,115200. You can trigger a break-in on demand with Magic SysRq (echo g > /proc/sysrq-trigger) or let a kernel panic drop into the debugger, then attach gdb against the unstripped vmlinux binary from the host machine. Unlike crash-dump tools such as kdump, KGDB halts the target live so you can inspect variables and single-step.

Why do you normally need a second machine (or VM host) to use KGDB instead of running GDB directly on the machine being debugged?

Because when KGDB breaks into the kernel, all CPUs on the target system are halted—meaning user-space programs, the local terminal, and local input on that machine cannot run until GDB tells the kernel to resume.

KGDB implements the GDB remote serial protocol inside kernel/debug/gdbstub.c, using architecture hooks (arch/*/kernel/kgdb.c) to save register state, install software or hardware breakpoints, and round-up secondary CPUs via NMI or IPI so the kernel executes in a quiescent single-CPU debug context. kgdboc registers as a polling I/O driver (kgdb_io) using the serial driver’s poll_get_char/poll_put_char callbacks—which bypass interrupts and locks—so debugging remains functional even inside interrupt handlers or atomic contexts. Trade-offs include sensitivity to watchdog timers (NMI lockup detectors may need tuning during long pauses) and the requirement for symbol/KASLR alignment (nokaslr or lx-symbols) when resolving module addresses.

KDC (Key Distribution Center)

A KDC (Key Distribution Center) is a trusted authentication server—most famously in Kerberos—that issues temporary tickets and session keys so users and services can verify each other.

Think of a KDC like a trusted badge office in a large building: instead of every office door knowing your password, you prove who you are to the badge office once, and it hands you a temporary pass that the other doors trust. This keeps your password in one place instead of spreading it across every computer on the network.

In a Kerberos network, the KDC combines two logical roles: the Authentication Server (AS), which checks your initial login and issues a Ticket-Granting Ticket (TGT), and the Ticket-Granting Server (TGS), which exchanges that TGT for tickets to individual services like SSH or file shares. If the KDC is unreachable, users with a cached, unexpired TGT can still open new sessions to services, while users without a TGT cannot log in.

Why doesn’t a Kerberos KDC need to be contacted on every single packet sent to a file server?

Because the KDC issues a time-limited service ticket and session key upfront; the client and server then authenticate directly using that ticket until it expires.

In Kerberos v5 (RFC 4120), the KDC acts as a trusted third party in a symmetric-key Needham–Schroeder variant, storing long-term principal keys in its database (or backing LDAP/AD store). Because the KDC mints both the encrypted ticket (sealed with the target service’s long-term key) and the session key returned to the client, a compromised KDC—specifically the krbtgt key—allows forging arbitrary tickets (“Golden Ticket” attacks). Production deployments mitigate availability and single-point-of-failure risks via primary/replica KDCs, kpropd or LDAP replication, and PKINIT (RFC 4556) for pre-authentication.

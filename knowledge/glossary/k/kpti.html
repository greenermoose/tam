Guide / Glossary A–Z / Terms beginning with K / KPTI (Kernel Page-Table Isolation)

KPTI (Kernel Page-Table Isolation) is a Linux kernel security mitigation against the Meltdown CPU vulnerability that unmaps most kernel memory whenever user-space programs are running.

Normally, every running app shares a map that includes both its own memory and the operating system kernel’s memory—the kernel part is marked “off-limits,” so apps are not supposed to read it. A CPU hardware bug called Meltdown lets a clever program peek at those off-limits pages anyway during speculative execution. KPTI solves this by hiding the kernel’s map whenever normal apps are running, only swapping it back in when the system actually enters the kernel.

Introduced to mitigate Meltdown (CVE-2017-5754) on affected x86_64 processors, KPTI maintains two page-table roots per process: one for user mode (with almost no kernel mappings) and one for kernel mode. Switching between them on every system call and interrupt adds overhead—especially for syscall-heavy workloads like databases or network proxies—though modern CPUs with PCID (Process-Context Identifiers) reduce the cost of TLB flushes. You can check whether KPTI is active in /sys/devices/system/cpu/vulnerabilities/meltdown.

If KPTI hides kernel memory while user programs run, how does the CPU know how to transition into the kernel when a program makes a system call?

A tiny, read-only “trampoline” page (containing the entry code, IDT, and minimal stack/GDT mappings) remains mapped in the user page table so the CPU can safely switch to the kernel page table on entry.

Originally developed as KAISER, Linux x86_64 KPTI allocates an 8 KiB-aligned PGD pair (kernel PGD followed by user PGD at +4 KiB, toggled by flipping bit 12 of CR3). In the user PGD, kernel text/data and the direct physical map are absent; only the entry_SYSCALL_64 / interrupt trampoline, cpu_entry_area, and LDT/IDT stubs remain mapped, marked global or tagged with PCIDs (CR4.PCIDE) so switching CR3 avoids full TLB invalidation via bit 63 (no-flush). On hardware unaffected by Meltdown (such as AMD CPUs or Intel parts with RDCL_NO in IA32_ARCH_CAPABILITIES), Linux disables KPTI at boot unless forced with pti=on.

Keysym

A keysym is the symbolic meaning a keyboard layout gives to a key—such as a, A, Return, or BackSpace.

If a keycode is the numbered seat on your keyboard, a keysym is the label telling software what that key means right now. Holding Shift or switching from an English layout to a French layout changes the keysym produced by the exact same physical key, so your computer knows whether you meant a lowercase “a”, a capital “A”, or an accented letter.

XKB combines a keycode with the active modifier state (such as Shift, Ctrl, or AltGr) and layout group to produce a keysym. Printable ASCII letters match their character codes (a is 0x0061, A is 0x0041), while non-printing keys use named constants (BackSpace is 0xFF08, Return is 0xFF0D). A terminal emulator or GUI toolkit then translates that keysym into UTF-8 text, an escape sequence, or a command.

Does a keysym always represent a single printable character?

No. Keysyms also name non-printable actions like BackSpace, modifier keys like Shift_L, and dead keys like dead_acute that wait for the next keystroke to compose an accented character.

Keysyms are 32-bit integers standardized in xkbcommon-keysyms.h and X11/keysymdef.h. Values 0x0020–0x00FF align with Latin-1, 0x01000100–0x0110FFFF encode arbitrary Unicode code points as 0x01000000 | codepoint, and 0xFF00–0xFFFF cover function, cursor, keypad, and modifier keys. An XKB keymap can map one keycode to multiple keysyms across shift levels and attach state actions (such as SetMods or LockGroup) alongside symbol emission. Note that a single physical key press can even yield multiple keysyms in sequence, and xkbcli how-to-type can invert the mapping to show which keycode and modifiers produce a given keysym.

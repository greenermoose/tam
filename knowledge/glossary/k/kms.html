KMS - Kernel Mode Setting

KMS (Kernel Mode Setting) is the Linux kernel subsystem that configures display resolutions, refresh rates, and monitor outputs directly in kernel space.

Older Linux systems had to rely on desktop display servers to talk directly to graphics hardware, which often caused the screen to flicker or go blank during boot and user switching. With KMS, the kernel itself takes charge of setting your screen’s resolution and refresh rate early at startup, giving you a smooth boot screen and clean switching between text consoles and the desktop.

KMS exposes display hardware through the Direct Rendering Manager (DRM) device nodes in /dev/dri/card*, replacing legacy user-space mode setting (UMS) and old fbdev drivers. Because the kernel owns the display state, Wayland compositors and Xorg’s modesetting driver can share a unified interface, and kernel panic messages can even be drawn directly onto the screen. You can inspect active outputs and modes under /sys/class/drm/.

Why did moving mode setting into the kernel make switching between a graphical desktop and a virtual terminal (Ctrl+Alt+F3) faster and less error-prone?

Because the kernel holds a single authoritative view of the display hardware instead of user-space programs racing to reprogram video registers when handing control back and forth.

In the DRM/KMS object model, framebuffers (FB) attach to planes (primary, overlay, cursor), which feed a scanout controller (CRTC), which drives an encoder and physical connector. The modern Atomic KMS API (DRM_IOCTL_MODE_ATOMIC) validates and commits multi-plane, multi-CRTC state transitions—including VRR/adaptive sync and color-management properties—in a single all-or-nothing transaction via TEST_ONLY checks and asynchronous page-flip events. Only one process at a time can hold DRM master (DRM_MASTER) privileges to commit modesets; logind/seatd arbitrates master handoff across VT switches via DRM_IOCTL_SET_MASTER and DRM_IOCTL_DROP_MASTER.

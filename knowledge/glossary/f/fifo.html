FIFO - First-In, First-Out

A queuing discipline in which the first item added is the first item removed, preserving arrival order.

A FIFO works just like a checkout line at a grocery store: whoever gets in line first is served first, and newcomers wait at the back. Computers use this same rule whenever data arrives in bursts and needs to be handled in the exact order it showed up.

In Linux and computing, FIFO appears in two common places: as an in-memory queue or ring buffer, and as a named pipe (created with mkfifo), which looks like a file on disk but streams bytes in order from a writer process to a reader process without storing data in a regular file. Unlike a stack (LIFO, last-in first-out) used for function calls, a FIFO decouples a fast producer from a slower consumer while keeping event order intact.

If you run mkfifo mypipe and then echo hi > mypipe in a terminal without a reader running, why does the shell appear to hang?

Opening a Linux named pipe (FIFO) for writing blocks by default until another process opens the same FIFO for reading, because a FIFO has no persistent storage buffer until both ends are connected.

In software, bounded FIFOs are commonly implemented as lock-free single-producer/single-consumer ring buffers using head and tail indices with acquire/release memory barriers to avoid false sharing across cache lines. In POSIX/Linux IPC, a named FIFO (S_IFIFO) shares kernel pipe buffer mechanics (PIPE_BUF = 4096 bytes for atomic writes; default capacity 64 KiB, tunable via F_SETPIPE_SZ), raising SIGPIPE/EPIPE when all readers close and blocking (with O_NONBLOCK clear) or failing with EAGAIN/ENXIO on empty reads or unpaired opens. Hardware UARTs and network NICs likewise use shallow silicon FIFOs to absorb interrupt-latency jitter and trigger watermark interrupts or DMA bursts.

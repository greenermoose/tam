FORS (Forest of Random Subsets)

A hash-based few-time digital signature scheme used inside the post-quantum SLH-DSA (SPHINCS+) standard.

Some digital signature methods are like single-use paper tickets: if you ever sign two different messages with the same ticket, an attacker can forge your signature. FORS is a stronger kind of ticket book designed to safely sign a small handful of messages using only simple, quantum-resistant math, serving as a core building block inside a larger modern signature system.

Inside SPHINCS+ (standardized by NIST as SLH-DSA), signing a message starts by hashing it into an index that selects a FORS key pair at the bottom of a large tree of keys. Unlike WOTS+ (which is strictly one-time and breaks completely if reused), FORS is a few-time signature: it tolerates signing a small number of messages with the same leaf before security degrades, which lets SPHINCS+ stay stateless without tracking a counter of every signature ever made.

Why does SLH-DSA (SPHINCS+) need FORS instead of using one-time WOTS+ keys directly to sign messages?

WOTS+ loses security immediately if a key is used twice, so signing directly with it would require tracking state to avoid reuse. FORS is a few-time scheme whose security degrades gracefully over a small number of collisions, enabling stateless signing.

Specified in FIPS 205 (SLH-DSA), FORS signs a k × a-bit message digest by partitioning it into k indices of a bits each, revealing one secret value and its a-node Merkle authentication path from each of k independent binary hash trees of height a (each having 2^a leaves). Public key compression hashes all k roots together; WOTS+ then authenticates that FORS public key inside the hypertree. Each reuse of the same FORS instance leaks k additional leaf preimages per tree, trading signature size (k × (a + 1) × n bytes) against r-time forgery probability.

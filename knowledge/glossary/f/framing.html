Framing

Framing is the practice of wrapping data in a structure with clear boundaries so a receiver can tell where each message begins and ends.

Imagine reading a long letter where every sentence runs together with no spaces, capitals, or periods—you would not know where one thought ends and the next begins. Computers face the same problem when data arrives as a continuous stream of ones and zeros over a wire or radio signal. Framing solves this by adding markers or length information around each chunk of data, like putting each letter in its own envelope, so the receiving device can separate messages cleanly and notice if one arrived incomplete.

In Linux networking and serial communication, different layers use different framing strategies: Ethernet adds a preamble, header, and frame check sequence around a payload, while higher-level streams like TCP give applications a continuous byte stream that requires its own framing (such as newline delimiters or length prefixes in HTTP/2). When framing fails—for example, mismatched MTU settings or a dropped byte on a serial port—the receiver either discards corrupted frames or misinterprets where the next message starts.

Why does an application running over TCP still need its own message framing?

TCP guarantees ordered, reliable delivery of bytes, not message boundaries. Two separate send() calls on the sender can arrive combined in one recv() read on the receiver, or one large write can arrive split across multiple reads, so the protocol itself must mark where each message ends.

Framing defines the encapsulation and synchronization boundary of a protocol data unit (PDU) at a given layer, typically pairing a header (addresses, type, or length) with an optional trailer (such as Ethernet’s 32-bit CRC-32 FCS). Byte-oriented links that rely on sentinel octets (such as PPP’s 0x7E flag or SLIP’s END) must escape matching payload bytes (byte stuffing), whereas bit-oriented links like HDLC use bit stuffing after five consecutive ones to preserve flag uniqueness; length-prefixed framing avoids escaping overhead but is vulnerable to desynchronization if the length field is corrupted without an independent header check. On Linux, serial line disciplines (n_tty, n_hdlc) and NIC drivers handle framing in kernel space before passing skbs up the stack.

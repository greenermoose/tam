File extension

The suffix at the end of a filename—usually after the final dot—that hints at the file’s format or purpose.

A file extension is the short tag at the end of a file’s name, like .txt for plain text or .jpg for a photo. It works like a label on a jar: it helps both you and your computer guess what is inside and which app should open it, even before opening the file.

On Linux, a file extension is a naming convention rather than a strict rule enforced by the filesystem. Unlike Windows, where .exe is required to launch a program, Linux checks execute permissions (+x) and internal headers (magic bytes or a #! shebang) to decide how to run a file. Renaming photo.png to photo.txt may fool a file manager, but file photo.txt inspects the bytes inside and still identifies it as a PNG image.

If you rename an executable script backup.sh to backup.txt on Linux, can you still run it from the terminal with ./backup.txt?

Yes, as long as it has execute permission (chmod +x) and a valid #! shebang on the first line. The Linux kernel executes files based on permissions and magic bytes or shebangs, not the filename suffix.

At the VFS and inode level, POSIX filenames are arbitrary byte strings (excluding / and \0), so . carries no kernel semantics. Desktop environments (via the XDG Shared MIME-Info database) determine MIME types by matching glob patterns (.tar.gz, Makefile) first and falling back to magic-byte signatures when extensions are missing or ambiguous; file(1) (libmagic) relies primarily on magic offsets and structural heuristics. Relying solely on extensions for security checks (such as upload allowlists) is a common vulnerability—double extensions, trailing characters, or mismatched Content-Type headers bypass naive suffix validation.

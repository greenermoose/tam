FIDL (Fuchsia Interface Definition Language)

A strongly typed interface definition language and binary wire format used by the Fuchsia operating system’s Zircon microkernel for inter-process communication.

In a microkernel system like Fuchsia, different parts of the operating system run in separate, isolated boxes so one bug can’t crash everything. FIDL is the shared rulebook that describes what messages those isolated programs can send to each other—like a strict order form that makes sure both sides agree on what data is being passed.

Unlike monolithic kernels (such as Linux) where drivers and filesystems share kernel memory and communicate via direct function calls or untyped ioctl buffers, microkernels rely on message passing over IPC channels. FIDL defines protocols, structs, tables, and capability handles in .fidl files, then generates type-safe client and server bindings for languages like C++, Rust, and Go. Notably, FIDL separates data bytes from kernel capability handles (to channels, memory objects, or sockets), which are transferred alongside the payload rather than forged as integers.

Why does FIDL treat kernel handles separately from ordinary data fields in a message?

Handles represent kernel-enforced capabilities, such as access to a channel or shared memory object. Keeping them in a separate handle table lets the kernel validate and transfer rights securely across process boundaries, preventing a process from forging access by guessing an integer.

The FIDL compiler (fidlc) parses .fidl schemas into an intermediate JSON representation, which language backends (fidlgen_rust, fidlgen_cpp) consume to emit stubs over Zircon zx_channel_write and zx_channel_read syscalls. Its binary wire format uses 8-byte alignment, out-of-line depth-first traversal for envelopes, vectors, and strings, and explicit handle dispositions (zx_handle_disposition_t) carrying object type and rights masks. For ABI evolution, FIDL distinguishes fixed-layout struct types from extensible table types and flexible unions or protocols, allowing unknown ordinals or fields to be skipped or handled gracefully across independently compiled components.

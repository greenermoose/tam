Guide / Glossary A–Z / Terms beginning with F / Fallback route

An alternate startup path that bypasses a failed component so a computer can still boot.

If the main road into town is blocked, you take a detour so you can still get home. A fallback route is that detour for your computer: when an update or damaged file stops the normal startup from working, the system uses a backup path to reach a working screen.

On Linux, a fallback route can mean choosing an older kernel or recovery entry in the boot menu, or booting from an external USB drive when the internal boot configuration is broken. Having a fallback route lets you inspect logs and undo a bad change instead of reinstalling your system.

Why is keeping at least one previous boot entry or kernel generation useful after an update?

If the newest kernel or boot configuration fails to start—for example, because of a missing driver or broken parameter—selecting the previous entry gives you an immediate fallback route back into a working system.

A fallback route operates at one of several boot boundaries: firmware failover (UEFI BootOrder progression, A/B slot boot-attempt counters, or removable-media \EFI\BOOT\BOOTX64.EFI), bootloader selection (booting a prior kernel/initramfs generation or appending systemd.unit=rescue.target / rd.break), or initramfs emergency shells when root-mount or decryption hooks fail. Effective fallback paths isolate the broken stage without mutating the primary state until diagnosis is complete.

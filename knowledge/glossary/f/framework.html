Guide / Glossary A–Z / Terms beginning with F / Framework

A framework is a reusable shape for an application: it provides the structure and calls your code when something needs to happen.

A library is a tool you pick up when you need it. A framework is more like a kit with a frame and instructions; you fit your pieces into the places it expects.

A web framework may own routing, rendering and data loading. You write components or handlers and let the framework call them at the right moment.

When would you choose a library instead of a framework?

Choose a library for one focused job you control, such as parsing a date. Choose a framework when many pages share routing, state and rendering rules that benefit from one consistent structure.

Frameworks apply inversion of control: the framework owns the lifecycle and the application supplies hooks. That gives consistency and speed for common cases, but upgrades can change conventions and escape hatches must be understood before a team relies on them.

Font

A digital collection of character shapes and spacing rules used to display text on screen or in print.

A font is the visual design of letters, numbers, and symbols—like the difference between neat printed handwriting and bold block letters. Your computer uses font files to know what each character should look like and how much space to leave around it when drawing text in a document or terminal.

On Linux, fonts are usually distributed as scalable outline files such as TrueType (.ttf) or OpenType (.otf), installed under /usr/share/fonts for all users or /home/alex/.local/share/fonts for a single account. Unlike fixed-size bitmap fonts, outline fonts store mathematical curves so the same file renders crisply at any size, while monospace fonts keep every character the same width so columns align in terminals and code editors.

Why do terminals and code editors strongly prefer monospace fonts over proportional fonts?

In a monospace font every glyph has the same horizontal advance width, so characters align in predictable vertical columns for tables, indentation, and cursor positioning, whereas proportional fonts vary width per letter.

A digital font file (SFNT container for TrueType, OpenType, or WOFF2) maps Unicode code points to glyph IDs via the cmap table, stores vector contours in glyf (quadratic Béziers) or CFF/CFF2 (cubic Béziers), and encodes per-glyph advance widths and bearings in hmtx. Complex scripts and ligatures require OpenType layout tables (GSUB for substitution, GPOS for positioning), evaluated by a text shaper such as HarfBuzz before FreeType rasterizes and hints outlines for grayscale or subpixel antialiasing. Variable fonts (fvar/gvar tables) interpolate axes like weight and optical size from a single file.

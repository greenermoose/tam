Fetch

To retrieve the next instruction or piece of data from memory or cache.

Before a chef can chop an ingredient or stir a pot, they have to walk to the pantry and grab what they need. In a computer, fetching is that “go get it” step—the processor grabs the next instruction from memory so it can see what to do next.

In the CPU instruction cycle, fetch reads instruction bytes from the memory address in the program counter (PC) and advances the PC toward the next instruction. In everyday computing, “fetch” also appears in tools like git fetch (downloading remote commits without merging) or web requests, though at the hardware level it specifically means bringing instructions or data into the processor.

Why does fetching an instruction usually read from L1 cache instead of going straight to main RAM?

Main RAM takes dozens to hundreds of CPU cycles to respond, whereas the on-chip L1 instruction cache responds in a few cycles. Fetching from cache keeps the CPU pipeline busy instead of stalling on slow memory.

In a pipelined CPU front end, the Fetch (IF) stage translates the virtual PC through the iTLB and reads a cache line from the L1 instruction cache (L1i) into a fetch/predecode buffer. To prevent pipeline bubbles on control-flow changes, modern front ends couple fetch with branch prediction (BTB, TAGE/perceptron direction predictors, and return address stack) to speculatively fetch along predicted targets before branches resolve, while decoupled fetch queues and micro-op caches absorb variable-length decode stalls.

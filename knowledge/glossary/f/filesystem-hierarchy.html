Guide / Glossary A–Z / Terms beginning with F / Filesystem hierarchy (FHS)

The standardized directory layout used by Linux and Unix-like systems to organize programs, configuration, data, and runtime state under a single root (/).

Just as a well-organized house keeps dishes in the kitchen, clothes in the bedroom, and tools in the garage, Linux systems follow a shared map of folders starting at /. Knowing that personal files live in /home and system settings live in /etc helps you find things on almost any Linux computer without guessing.

The Filesystem Hierarchy Standard (FHS) defines standard top-level directories: /etc for host-specific configuration, /home for user directories (such as /home/alex), /var for changing data like logs (/var/log) and caches, /usr for shared read-only programs and libraries, and /tmp for temporary files. Notice the contrast between /etc (configuration files on disk) and /proc or /sys (virtual directories generated on the fly by the running kernel).

Why shouldn’t a service store its growing log files inside /usr instead of /var/log?

/usr is intended for static, shareable program binaries and libraries and may be mounted read-only. /var is specifically designated for variable runtime data like logs, spools, and databases that grow during normal operation.

Modern Linux distributions follow FHS 3.0 conventions alongside the usr-merge (/bin, /sbin, /lib symlinked into /usr/*) and /run (tmpfs replacing /var/run for early-boot PID and socket state before /var mounts). Pseudo-filesystems—procfs (/proc), sysfs (/sys), devtmpfs (/dev), and cgroup2 (/sys/fs/cgroup)—extend the tree with kernel-object introspection and control interfaces rather than persistent storage. Immutable or declarative systems deviate from mutable /usr hierarchies by keeping versioned store paths and symlinked profiles while preserving /etc, /var, /home, and /run for FHS compatibility.

Floating-point

Floating-point stores digits plus a scale, so the same format covers tiny and huge values.

Writing 1,500 as 1.5 times 1,000 is a way of moving the point. A floating-point number does the same inside a computer: it keeps the digits and remembers where the point belongs.

A floating-point value has a sign, a significand for the digits and an exponent for the scale. That makes it possible to store both 0.0015 and 1,500,000,000 in one format. The cost is that many familiar decimal fractions, such as 0.1, cannot be stored exactly. Comparing results by exact equality is often wrong; use a tolerance chosen for the problem.

Why does 0.1 + 0.2 not equal 0.3 exactly in many programs?

Both inputs are rounded to the nearest binary floating-point values, and their sum is rounded again. The stored result is close to 0.3 but not the same pattern as the stored 0.3.

IEEE 754 defines the widely used binary32 and binary64 formats, rounding modes, special values and exception flags. Relative precision is roughly constant across the normal range; absolute precision grows with magnitude. Overflow, underflow, cancellation and operation order affect reproducible results. Decimal floating-point formats keep decimal digits exact but are a different encoding.

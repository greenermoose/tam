FUSE (Filesystem in Userspace)

FUSE (Filesystem in Userspace) is a Linux kernel interface that lets regular userspace programs act like mounted filesystems without modifying the kernel.

Normally, only the core Linux kernel is allowed to manage disk drives and folders, because a bug there can crash the whole computer. FUSE acts like a safe translator: it lets an ordinary program pretend to be a folder on your system. That way, you can mount a remote server over SSH, browse inside a compressed archive, or connect cloud storage as if it were a local drive, without needing administrator privileges or risky kernel changes.

Common Linux tools built on FUSE include sshfs, rclone mount, and AppImage runners. When you list or read a file inside a FUSE mount, the kernel forwards the request through /dev/fuse to the userspace daemon, which fetches or computes the data and sends it back. You can spot FUSE mounts in mount or findmnt by types starting with fuse.; because every operation crosses between kernel and userspace, FUSE is more flexible than in-kernel filesystems like ext4, though slower for metadata-heavy workloads.

Why can a frozen FUSE daemon cause commands like ls or df to hang?

Those commands issue standard filesystem system calls (like statfs or getdents) that the kernel forwards to the FUSE daemon via /dev/fuse. Until the userspace daemon replies or the mount is forcibly unmounted, the calling processes wait in the kernel for a response.

The kernel module (fs/fuse/) registers a VFS filesystem whose operations serialize requests into ring/queue messages read by a userspace daemon from /dev/fuse via read()/write() or io_uring (in newer kernels) and routed through libfuse. Each uncached metadata or I/O call incurs context switches and copies between kernel page cache and userspace, though writeback_cache, splice, and FUSE passthrough (FUSE_DEV_IOC_BACKING_OPEN) reduce overhead for bulk I/O. Unprivileged mounts rely on the setuid fusermount3 helper (or user-namespace mounts with nosuid,nodev) and expose edge cases around deadlocks when the FUSE daemon itself accesses paths under its own mountpoint or triggers memory reclaim.

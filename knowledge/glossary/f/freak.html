Guide / Glossary A–Z / Terms beginning with F / FREAK (Factoring RSA Export Keys)

FREAK (Factoring RSA Export Keys) is a 2015 TLS vulnerability that allowed an attacker to downgrade encrypted connections to weak 512-bit export-grade RSA keys.

In the 1990s, United States export rules forced software makers to ship weaker encryption abroad than what was allowed at home. Decades later, many web servers and browsers still carried leftover support for those weak settings. FREAK took advantage of that old leftover code: an attacker sitting between you and a website could trick both sides into using the weak 1990s lock instead of a modern one, then break the weak key and read or alter your traffic.

FREAK (CVE-2015-0204) affected OpenSSL, SChannel, and Apple Secure Transport clients that accepted ephemeral RSA_EXPORT parameters even when they had not asked for an export cipher suite. In practice, administrators on Linux check server cipher lists with openssl ciphers or testssl.sh and disable all EXP and weak 512-bit suites. TLS 1.3 eliminates the entire class of export downgrade attacks by removing weak legacy cipher suites and signing the full handshake transcript.

Why could an attacker use FREAK even against a browser that did not advertise export cipher suites?

Vulnerable client TLS stacks had a state-machine bug: if the server replied with a ServerKeyExchange message containing a 512-bit export RSA key for a normal RSA key-exchange suite, the client accepted and used that weak key anyway instead of rejecting the unexpected message.

FREAK exploits a cross-protocol/state-machine flaw where a man-in-the-middle rewrites the client’s ClientHello to request an RSA_EXPORT suite while the server—often reusing a single 512-bit ephemeral RSA key across sessions—responds with a signed ServerKeyExchange containing that 512-bit modulus. Because factoring a 512-bit RSA modulus via the General Number Field Sieve (GNFS) became feasible in hours on cloud hardware by 2015, an attacker could factor the server’s export key once and decrypt any session using it to recover the premaster secret. Mitigations combined removing EXPORT suites on servers, patching client state machines to forbid unrequested export parameters, and—in TLS 1.3 (RFC 8446)—eliminating static/export RSA key transport entirely in favor of authenticated (EC)DHE with transcript signatures.

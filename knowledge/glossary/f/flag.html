Flag

A command-line option or status indicator that toggles a behavior on or off without taking a separate value.

When you type a command in a terminal, a flag is like a simple light switch you add to change how the command behaves. Instead of giving it a filename or a number, you just include the flag—such as --verbose to ask for more details—and its presence alone flips that setting on.

In Unix and Linux CLIs, flags are boolean options written with a single dash for short forms (like -l or -a in ls -la, which can be bundled together) or a double dash for long forms (like --help or --recursive). Unlike key-value options such as --output file.txt, a flag takes no argument; its presence enables the option, though some tools provide a --no-... counterpart to override a default.

What is the difference between passing -la and --la to a standard GNU command?

With a single dash, -la is parsed as two bundled single-letter flags, -l and -a. With a double dash, --la is treated as a single long option named “la”, which fails unless that exact long flag exists.

At the parser level (POSIX getopt(3) and GNU getopt_long(3)), flags correspond to no_argument entries in struct option, distinct from required_argument and optional_argument; -- terminates option parsing so subsequent tokens starting with - are treated as positional arguments. Beyond CLIs, the term also denotes single-bit status or control fields in CPU registers (x86 RFLAGS carry, zero, and interrupt flags), file descriptors (O_NONBLOCK, FD_CLOEXEC), and page-table entries, where bitwise masks pack multiple boolean states into one machine word.

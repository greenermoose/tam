Command

A command is an instruction you type for your computer to carry out.

Think of a command as a short written order you give the computer in a text window instead of clicking menus or icons. You type a word—such as pwd to ask which folder you are in, or ls to list its contents—and press Enter. Commands let you ask the system to do a specific job quickly and repeatably.

When you type a command in a Linux shell, the first word is not always a separate program on disk. It can be a shell built-in (such as cd, which must change the shell’s own working directory), an alias or function you defined, or an executable file found through your PATH. You can check which kind a name resolves to with type.

Why is cd a shell built-in rather than a standalone program?

A standalone program runs in its own child process, and changes to a child’s working directory disappear when it exits. Making cd a built-in lets it change the shell’s own directory directly.

The shell tokenizes the command line, performs parameter, pathname, and quote expansions, wires up redirections and pipelines, and resolves the command name in order: special built-ins, shell functions, regular built-ins, and PATH lookup (unless the name contains a slash, which bypasses PATH). External commands are started via fork/clone and execve(2); if the file begins with #!, the kernel invokes the named interpreter. By convention, exit status 127 means command not found and 126 means found but not executable.

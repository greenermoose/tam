Guide / Glossary A–Z / Terms beginning with C / C99 (ISO C99)

C99 (ISO C99) is the 1999 update to the C programming language standard that modernized C with fixed-width integers, inline functions, and cleaner syntax.

Ten years after the first C standard, C99 updated the language to match how programmers actually wrote code and how modern hardware worked. It added everyday conveniences like // single-line comments, a true/false type, and integer types with guaranteed sizes so numbers behave predictably across different computers.

Part of the C standards family, C99 is widely used in Linux system and embedded code because it introduced <stdint.h> (uint32_t, int64_t), <stdbool.h>, inline functions, mixed declarations and code, for (int i = 0; ...) loop-scoped variables, and designated initializers (struct point p = { .y = 2 };). You can target it explicitly with -std=c99 in GCC or Clang.

Why do Linux system programs prefer uint32_t from <stdint.h> over plain int or long?

Plain int and long vary in bit width across platforms (for example, long is 32 bits on 64-bit Windows but 64 bits on 64-bit Linux). C99’s <stdint.h> guarantees exact bit widths, which is essential for binary protocols, file formats, and hardware registers.

ISO/IEC 9899:1999 (__STDC_VERSION__ == 199901L) introduced restrict pointer-aliasing qualifiers for optimizer vectorization, flexible array members (struct hdr { size_t n; char data[]; };), compound literals, variadic macros, _Complex/_Imaginary, and IEEE 754 (IEC 60559) floating-point semantics via Annex F and <fenv.h>. It also altered inline linkage rules compared to C++ and pre-C99 GNU C: an inline definition without extern or static is an inline-only definition and requires an external definition in another translation unit. Variable-length arrays (VLAs), mandatory in C99, proved problematic for stack safety and were downgraded to optional (__STDC_NO_VLA__) in C11.

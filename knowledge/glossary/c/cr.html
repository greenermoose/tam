CR (Carriage Return, 0x0D)

Carriage Return (CR, ASCII 0x0D, '\r') is a control character that moves the cursor back to the beginning of the current line without advancing to the next line.

The name comes from mechanical typewriters, where a lever pushed the paper carriage back to the left margin so you could type from the start of the line again. On computers, CR still means “go back to the start of this line.” Moving back to the left edge is separate from moving down a line, which is why some systems pair CR with a second character at the end of each line while Linux uses just one.

Part of the C0 control codes, CR (0x0D, Ctrl+M) is what the Enter key emits to a terminal. In cooked mode, the Linux termios driver’s ICRNL flag translates incoming CR into Line Feed (LF, 0x0A) so programs see standard Unix newlines. You see raw CR used intentionally in progress bars that overwrite one line with \r, and accidentally in Windows CRLF (\r\n) files that break Linux shell scripts.

Why does a shell script with Windows (CRLF) line endings often fail to run on Linux?

Linux treats only LF (0x0A) as a line terminator, so the preceding CR (0x0D) becomes part of the shebang path or command name, causing the kernel to look for an interpreter whose name ends with a literal carriage-return byte.

Defined in ANSI X3.4 and ECMA-48 as 0x0D, CR resets the active presentation position to column 1 of the current line. In POSIX termios, input flags ICRNL, IGNCR, and INLCR govern line-discipline translation, whereas cfmakeraw() clears ICRNL so full-screen TUIs and SSH receive literal 0x0D. Wire protocols including HTTP/1.1 (RFC 9112), SMTP (RFC 5321), and Telnet NVT mandate CRLF (0x0D 0x0A) delimiters, requiring strict parser normalization to avoid request-smuggling or header-injection bugs.

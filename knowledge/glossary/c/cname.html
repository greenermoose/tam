Guide / Glossary A–Z / Terms beginning with C / CNAME (Canonical Name)

A DNS record that makes one domain name an alias for another.

A CNAME record says "this name is another name for that name." For example, www.example.com can be a CNAME for example.com. When a program looks up the alias, DNS follows the CNAME to the canonical name and returns the answer for it. It is like a forwarding address: the label is different, but it points to the same place.

A CNAME record contains only a target name, not an IP address. The resolver follows the alias and then looks up records such as A or AAAA at the canonical name. A CNAME cannot usually coexist with other record types at the same owner name, and the zone apex normally cannot be a CNAME because it must hold SOA and NS records. Use dig www.example.com CNAME or dig www.example.com to see the alias and the final answer.

Why not put a CNAME at example.com itself?

The zone apex must carry records such as SOA and NS. A CNAME would claim that the name is only an alias, which conflicts with those required records. Services that need apex aliasing use provider-specific alias/ANAME records or publish A and AAAA records directly.

CNAME is defined in the DNS standards as an alias that causes a resolver to restart the query at the canonical name. The canonical name may itself resolve through another CNAME, but chains add latency and failure points. CNAME interacts with DNSSEC: the alias and the target records each need valid signatures in their zones. Because CNAMEs can cross zone boundaries, they are also a common source of dangling-record takeover risk when the target name is abandoned while the alias remains published.

Guide / Glossary A–Z / Terms beginning with C / Compiler

A compiler is a program that translates human-readable source code into another form, usually machine code that a processor can run directly.

People write programs in languages like C or Rust that are easier for humans to read, while a computer’s processor only understands raw binary instructions. A compiler acts like a translator that reads your whole recipe beforehand and turns it into a fast, ready-to-run program. Once compiled, anyone with a matching computer can run that program without needing the original source code.

In Linux, tools such as gcc, clang, and rustc compile source files before you run them, catching many syntax and type errors up front. This contrasts with an interpreter (such as python3), which reads and runs code line by line at runtime. Notice also that a compiler’s output depends on the target CPU architecture and operating system, so a binary compiled for x86_64 Linux will not run natively on ARM64 without cross-compilation or emulation.

Why do compiled C programs usually start faster and catch type errors earlier than interpreted scripts?

The compiler already translated and type-checked the entire program into native machine instructions ahead of time, so the CPU executes them directly without parsing source code at runtime.

A modern ahead-of-time compiler splits translation into a front end (lexical analysis, parsing, semantic and type checking, lowering to an intermediate representation such as LLVM IR or GIMPLE), a middle end (target-independent passes like SSA construction, dead-code elimination, inlining, and loop vectorization), and a back end (instruction selection, register allocation, instruction scheduling, and emitting object files or assembly). Optimization flags (-O2, -O3, -flto) trade compile time and debuggability for throughput, and aggressive optimizations assume no undefined behavior—meaning UB in C or C++ can cause seemingly valid checks to be elided.

Guide / Glossary A–Z / Terms beginning with C / CRC - Cyclic Redundancy Check

A Cyclic Redundancy Check (CRC) is a fast, non-cryptographic checksum that detects accidental bit errors in stored or transmitted data.

Think of a CRC as a quick mathematical fingerprint attached to a package of data. Before sending a message or saving a block to disk, the sender runs a calculation on the bits and appends the short result. The receiver runs the exact same calculation on what arrives; if noise on a cable or a disk glitch flips even one bit, the two results will not match, alerting the system that the data was corrupted.

CRCs come in standard widths—such as CRC-8, CRC-16 (Modbus, USB), and CRC-32 (Ethernet, PNG, ZIP)—trading a few extra bits of overhead for stronger error detection. Unlike a simple byte sum, which misses swapped bytes or paired cancelling errors, a CRC treats the data as a continuous bit stream and reliably catches multi-bit burst errors. On Linux, CRCs protect network frames and storage metadata, whereas cryptographic hashes like SHA-256 are used whenever security against deliberate modification is needed.

What advantage does a CRC have over simply adding up all the bytes in a message?

A simple byte sum misses reordered bytes and cancelling errors (such as +1 in one byte and −1 in another). A CRC’s polynomial division depends on bit positions, catching reordered data and contiguous burst errors up to the CRC’s bit width.

A CRC treats an n-bit message as a polynomial M(x) over the finite field GF(2) (addition is XOR without carry), multiplies by x^r, and computes the remainder modulo a degree-r generator polynomial G(x). Linearity (CRC(A XOR B) = CRC(A) XOR CRC(B)) enables incremental updates and carryless-multiply acceleration, while precluding cryptographic collision resistance. A well-chosen G(x) (commonly a primitive polynomial multiplied by x + 1) detects all 1-bit, 2-bit, odd-weight, and ≤r-bit burst errors; two implementations using the same polynomial still disagree if bit reflection (refIn/refOut), initial seed, or final XOR mask differ.

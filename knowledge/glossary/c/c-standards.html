C standards (C89, C90, C99, C11, C17, C23)

The family of official ISO/IEC 9899 specifications that define the C programming language and its standard library.

Just as traffic rules are written down and updated from time to time so everyone follows the same playbook, the C programming language has an official rulebook. Each updated edition is named after the year it was published so programmers and compilers agree on what valid C code means.

When compiling C on Linux with gcc or clang, you can choose a standard with flags such as -std=c11 or -std=c23. The C standard family includes C89, C90, C99, C11, C17, and C23; older baselines maximize compatibility with older compilers, while newer ones add features like threads and stronger type checking.

Why do compilers often default to modes like -std=gnu17 instead of strict -std=c17?

Strict -std=c17 disables GNU extensions and hides POSIX/Linux APIs unless feature-test macros are defined. Modes like -std=gnu17 follow the C17 standard while keeping widely used compiler extensions enabled by default.

ISO/IEC 9899 revisions: C89 / C90 (ANSI/ISO baseline), C99 (1999: VLAs, restrict, <stdint.h>), C11 (2011, Tamlinux baseline: memory model, _Atomic, _Generic), C17 (2018: defect-report fixes), and C23 (2024: nullptr, constexpr, #embed, K&R removal). Across revisions, fixed-width ABI types remain stable while strict aliasing, undefined-behavior rules, and optional feature macros (__STDC_NO_THREADS__, __STDC_NO_ATOMICS__) govern portable systems code.

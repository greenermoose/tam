Guide / Glossary A–Z / Terms beginning with C / Capability discovery

Capability discovery is the exchange that finds out which messaging features another person's client supports before a message is sent. A client can then choose chat, a file transfer or a fallback service with a better chance of working.

Two people can use the same app and still have different features available. One phone may support large group chats while another only supports short messages. Capability discovery asks what the other side can do instead of assuming that every contact has the same tools.

In RCS (Rich Communication Services), capability information travels through the IMS (IP Multimedia Subsystem) before a conversation starts. The GSMA Universal Profile defines the interoperable feature baseline that carriers and clients use. A client that learns the other side lacks a feature can fall back to a simpler transport; the visible conversation may then mix rich messages and short messages.

Capability discovery is a feature negotiation, not a security proof. A claimed capability does not authenticate the person or guarantee that end-to-end encryption is available for that conversation. Results also change over time as clients update or roam, so a cached answer can be stale. The term is unrelated to the Linux capability permission bit.

Guide / Glossary A–Z / Terms beginning with C / CBC (Cipher Block Chaining)

CBC (Cipher Block Chaining) is a classic block-cipher encryption mode that combines each plaintext block with the previous ciphertext block before encrypting it.

If you encrypt a picture block by block on its own, identical blocks turn into identical scrambled blocks, leaving patterns visible. CBC fixes that by mixing each new block with the previous scrambled block—like linking a chain so every link depends on all the links before it—starting from a random seed block called an initialization vector (IV).

CBC requires a unique, unpredictable IV for each message and padding (typically PKCS#7) so the plaintext fits exact block boundaries (16 bytes for AES). Because decryption can be parallelized while encryption is sequential, CBC was standard in older TLS, SSH, and disk encryption. However, CBC provides confidentiality only—never integrity—and without authentication (Encrypt-then-MAC), attackers can exploit decryption error messages in padding-oracle attacks. Modern protocols therefore prefer AEAD modes like AES-GCM or ChaCha20-Poly1305.

Why does CBC require a separate MAC (Encrypt-then-MAC), whereas AES-GCM does not?

CBC only scrambles data and does not detect tampering; an attacker can flip ciphertext bits or probe padding errors to recover plaintext (a padding-oracle attack). AES-GCM is an AEAD mode that builds authentication directly into the cipher.

Formally, CBC defines C_i = E_K(P_i XOR C_{i-1}) with C_0 = IV, and decryption P_i = D_K(C_i) XOR C_{i-1}. A predictable IV enables chosen-plaintext distinguishing attacks (such as BEAST in TLS 1.0), while a bit-flip in C_{i-1} randomizes block P_i completely (via D_K) and flips the exact corresponding bits in P_{i+1}. Without Encrypt-then-MAC verification before padding checks, timing or error differences leak whether PKCS#7 padding is valid (Vaudenay’s padding oracle, Lucky 13), allowing byte-by-byte plaintext recovery in O(128 × len) queries.

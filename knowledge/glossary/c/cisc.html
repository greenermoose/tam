CISC - Complex Instruction Set Computing

Complex Instruction Set Computing—a processor design style featuring a large set of rich, variable-length instructions that can perform multi-step operations.

Imagine giving a chef one single command—“make a grilled cheese sandwich”—instead of listing every tiny step like “pick up bread, spread butter, turn on the stove.” CISC processors understand high-level, multi-step instructions directly, which originally helped programmers fit more work into small, expensive memory.

On Linux, x86_64 (used in most PCs and servers) is the main CISC family, contrasting with RISC architectures like aarch64 (ARM) and riscv64. CISC instructions vary in byte length and can read, modify, and write memory in one instruction, whereas RISC uses fixed-width instructions and separates memory loads/stores from arithmetic.

If CISC instructions do more work per instruction, why aren’t CISC CPUs automatically faster than RISC CPUs?

Variable-length, multi-step instructions are harder to decode and pipeline cleanly. Modern x86 CPUs actually translate complex instructions into simpler internal micro-operations, narrowing the hardware difference with RISC.

Classic CISC ISAs (x86, VAX, m68k) optimize code density via variable-length encodings (1–15 bytes on x86), rich addressing modes (base + scaled index + displacement), and memory-operand read-modify-write semantics. The primary microarchitectural bottleneck is sequential length-decoding across variable prefixes and ModR/M bytes, which modern x86 cores mitigate with parallel pre-decode and decoded micro-op (µop) caches. Internally, contemporary x86 processors execute fixed-format, RISC-like µops on out-of-order superscalar pipelines, so the CISC/RISC divide today mostly governs front-end decode power, binary density, and memory-ordering strength (x86 TSO vs. ARM/RISC-V weak ordering).

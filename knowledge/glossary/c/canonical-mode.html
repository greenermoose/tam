Canonical mode (cooked mode)

Canonical mode (also called cooked mode) is the default terminal input mode in which the operating system collects and edits a full line of typed text before passing it to a program.

When you type a command at a terminal prompt, Backspace fixes typos and nothing runs until you press Enter. That happens because the system holds your keystrokes in a temporary scratchpad—canonical mode—and only hands the finished line to the program once you press Enter.

Controlled by the ICANON flag in POSIX termios, canonical mode delegates basic line editing—Backspace (ERASE), Ctrl+U (KILL), Ctrl+W (WERASE), and Ctrl+D (EOF)—to the kernel’s TTY line discipline. Programs like cat or simple scripts receive clean, edited lines automatically. By contrast, full-screen TUIs such as vim, less, or htop disable ICANON (entering non-canonical or raw mode) so they receive every keystroke immediately. You can inspect or toggle it with stty -a and stty -icanon.

Why does Backspace still edit your input when running a simple program like cat with no line-editing library?

Because the terminal starts in canonical mode (ICANON), so the kernel’s TTY line discipline buffers the line and handles Backspace before cat’s read() call ever sees the bytes.

With ICANON set in c_lflag (struct termios), Linux’s N_TTY line discipline buffers input in a canonical ring until a line delimiter (\n, VEOL, VEOL2, or VEOF) arrives, processing VERASE, VKILL, VWERASE, and VREPRINT in-kernel. A read() blocks until a complete line is available (ignoring VMIN/VTIME, which apply only when ICANON is cleared) and returns at most one line per call, up to MAX_CANON (4096 bytes on Linux); VEOF flushes the current buffer immediately so an empty line causes read() to return 0 (end-of-file).

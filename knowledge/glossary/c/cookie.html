Cookie

A cookie is a small piece of data that a server asks a browser to keep and send back with later requests.

A cookie is like a wristband at an event. The server gives it to your browser once, and the browser shows it on later visits so the server recognises the same session.

Cookies carry attributes such as Expiry, Path, Domain, Secure, HttpOnly and SameSite. A session identifier is a common use; the actual account data stays on the server.

Why should a session identifier be HttpOnly when script does not need it?

An XSS flaw could otherwise read the identifier and send it to an attacker. HttpOnly lets the browser send the cookie to the server while keeping it out of JavaScript.

HttpOnly hides a cookie from page script but does not prevent CSRF. Secure limits transport to HTTPS. SameSite controls sending on cross-site requests. Cookie scope follows domain and path rules, and a token kept in JavaScript has a different theft profile from a cookie.

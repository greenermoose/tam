Guide / Glossary A–Z / Terms beginning with C / CFF (Compact Font Format)

A compact outline font format used inside OpenType (.otf) fonts that describes letter shapes using cubic Bézier curves.

Fonts store letters as mathematical curves rather than pixel grids so they stay sharp at any zoom level. CFF is a space-saving way of storing those curves inside .otf font files, letting a single file hold crisp, detailed typefaces without wasting disk space or memory.

In Linux font stacks (FreeType and Fontconfig), you will commonly encounter two OpenType outline flavors: TrueType (.ttf), which uses quadratic Bézier curves, and CFF/OpenType (.otf), which uses PostScript cubic Bézier curves. CFF also supports subroutines—reusable stroke fragments like serifs or bowls—which shrink file sizes for large character sets such as CJK fonts.

How do .otf (CFF) and .ttf (TrueType) font files differ in how they represent glyph outlines?

CFF/OpenType uses cubic Bézier curves (from PostScript), whereas TrueType uses quadratic Bézier curves, which require more control points to approximate the same smooth shapes.

CFF (and its successor CFF2, designed for variable fonts) is stored as the 'CFF ' or 'CFF2' SFNT table inside an OpenType container, encoding Adobe Type 2 charstrings in a compact bytecode stack machine with local/global subroutines (callsubr/callgsubr) and declarative stem hints rather than TrueType’s imperative grid-fitting bytecode. FreeType’s CFF hinter (originally contributed by Adobe) automatically snaps stems and aligns blue zones at small ppem sizes without requiring hand-authored per-glyph programs, though CFF2 drops legacy PostScript dictionary fields (like encoding and charset tables) in favor of SFNT-level mappings and variation stores (HVAR/fvar).

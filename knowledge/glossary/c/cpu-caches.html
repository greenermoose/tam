CPU caches (L1, L2, L3)

CPU caches (L1, L2, L3) are small, high-speed memory layers built directly onto the processor chip to keep frequently used data and instructions close to the cores.

Imagine cooking at a stove: main memory (RAM) is like a pantry across the room, and the storage drive is a grocery store down the street. Instead of walking to the pantry for every pinch of salt, you keep a small spice rack right next to the stove. CPU caches work the same way—they hold the small pieces of data your processor is using right now so it does not have to pause and wait for slower main memory.

Each level trades size for speed: L1 (split into instruction and data caches, tens of kilobytes per core) sits closest to execution units; L2 (hundreds of kilobytes to a couple of megabytes per core) backs it up; L3 (several to tens of megabytes) is shared across cores. On Linux, you can inspect cache topology with lscpu or under /sys/devices/system/cpu/cpu0/cache/. Sequential array scans exploit spatial locality and hit caches well, whereas chasing pointers through linked lists causes frequent cache misses that stall the core.

Why can a program with a small memory footprint still run slowly if it jumps randomly through memory?

Caches load data in fixed chunks (cache lines) and rely on spatial and temporal locality. Jumping to unpredictable addresses causes repeated cache misses, forcing the CPU to stall while fetching each line from slower main RAM.

Modern x86-64 and ARM64 CPUs organize caches as set-associative SRAM arrays with 64-byte cache lines (128-byte on some Apple/POWER designs); L1 is typically virtually indexed, physically tagged (VIPT) to overlap TLB lookup with tag comparison. Multi-core coherence relies on MESI/MOESI derivatives (such as Intel MESIF or AMD MOESI), where false sharing—two cores writing independent variables within the same 64-byte line—triggers repeated invalidation traffic across the interconnect. L3 inclusion policies vary (inclusive on older Intel client/server dies, non-inclusive/victim on Skylake-SP and AMD Zen), and hardware prefetchers, speculative-execution side-channels, and Cache Allocation Technology (CAT) all shape real-world latency and isolation.

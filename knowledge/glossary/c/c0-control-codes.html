C0 control codes (ASCII 0x00-0x1F)

The 32 ASCII control characters (0x00–0x1F) used for line control, signaling, and framing rather than visible text.

On an old typewriter, pressing keys either stamped a letter on paper or moved the machine—returning the carriage, ringing a bell, or advancing a tab. C0 control codes are the digital equivalent: invisible byte values (0 through 31) that tell a terminal or program to perform an action like starting a new line or ringing an alert.

In a Linux terminal, you can send C0 codes with Ctrl plus a letter—for example, Ctrl+C sends ETX (0x03), Ctrl+D sends EOT (0x04), and Ctrl+J sends LF (0x0A). Whether a control byte triggers a signal or reaches your application unchanged depends on the kernel’s tty line discipline mode.

Why does pressing Ctrl+C stop a running command in a shell, yet get handled as an ordinary keystroke inside a full-screen editor?

In default canonical (cooked) tty mode, the kernel line discipline intercepts 0x03 (ETX) and sends SIGINT to the foreground process group. Full-screen editors switch the tty to raw mode so 0x03 is passed through directly as input data.

ECMA-48 / ISO 646 C0 set (0x00–0x1F): NUL, SOH, STX, ETX, EOT, ENQ, ACK, BEL, BS, HT, LF, FF, CR, SI, DLE, DC1, DC2, DC3, DC4, NAK, SYN, ETB, CAN, SUB. Note 0x1B (ESC) introduces multi-byte escape sequences, while 0x00 (NUL) terminates C strings and requires explicit framing or escaping in binary protocols.

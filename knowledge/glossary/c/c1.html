C1 (8-bit Control Characters)

The 8-bit control character range (0x80–0x9F) used in legacy 8-bit encodings as single-byte shortcuts for terminal escape sequences.

Think of C1 as old shorthand abbreviations that only work in one specific notebook. Older 8-bit terminals used byte numbers 128 to 159 as one-byte shortcuts for longer commands, but modern UTF-8 text uses those same byte numbers as building blocks for international characters, so modern terminals ignore them as commands.

In ISO 8859-1, byte 0x9B is a single-byte shortcut for the two-byte ESC [ sequence (CSI) used for colors and cursor movement. In UTF-8 mode on Linux, bytes 0x80–0x9F are needed inside multi-byte characters, so terminals disable 8-bit C1 parsing to avoid misreading text as commands.

What happens if a legacy program sends a raw 8-bit C1 byte like 0x9B to a modern UTF-8 terminal?

The terminal treats 0x9B as an invalid or orphaned UTF-8 continuation byte rather than CSI, printing a replacement glyph (or garbled text) instead of executing the escape sequence.

Defined by ECMA-48 / ISO 2022, C1 (0x80–0x9F) maps 1-to-1 onto 7-bit ESC + 0x40–0x5F (e.g., 0x8F = SS3, 0x9B = CSI, 0x9D = OSC, 0x9C = ST). In UTF-8, 0x80–0xBF are strictly continuation bytes (10xxxxxx), making raw 8-bit C1 bytes incompatible with UTF-8 framing; Unicode code points U+0080–U+009F encode as two-byte sequences (0xC2 0x80–0xC2 0x9F), which terminals also generally decline to interpret as C1 controls by default.

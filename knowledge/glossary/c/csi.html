CSI (Control Sequence Introducer)

CSI (Control Sequence Introducer) is the two-character prefix ESC [ (or single byte 0x9B) that begins most parameterized terminal control sequences.

When a terminal program wants to color text red, clear the screen, or move the cursor up, everything still has to travel through the same stream of text bytes. So it sends a special “attention” prefix—Escape followed by [—which tells the terminal: “do not print the next few characters on screen; treat them as a command.” The same prefix also works in reverse when you press arrow keys or function keys, letting the program know which key you hit.

Defined by ECMA-48, a CSI sequence starts with ESC [ (\x1b[), carries optional numeric parameters separated by semicolons, and ends with a single command letter. For example, \x1b[31m sets red text, \x1b[2J clears the screen, and \x1b[1;5C is sent by many terminals for Ctrl+Right. When you see raw [32m or ^[[A printed in a log or broken prompt, you are seeing a CSI sequence whose leading ESC byte was stripped or echoed literally.

Why do you sometimes see text like ^[[A appear in the terminal when pressing the Up arrow key?

The Up arrow sends the CSI sequence ESC [ A. When a program reads raw input without line-editing or key-binding support (like cat), the terminal echoes the leading ESC byte as ^[ followed by [A.

ECMA-48 Control Sequence Introducer begins with 7-bit ESC [ (0x1B 0x5B) or 8-bit C1 0x9B (avoided in UTF-8 streams because 0x9B is a UTF-8 continuation byte). Its grammar comprises zero or more parameter bytes (0x30–0x3F, 0–9:;<=>?), zero or more intermediate bytes (0x20–0x2F), and one final dispatch byte (0x40–0x7E). Colon-separated subparameters (such as ESC [ 38:2::255:0:0 m for 24-bit color) and private-mode prefixes (?, >, <, =) disambiguate extensions like SGR mouse reporting and the Kitty keyboard protocol; VT500-compatible parsers also execute embedded C0 controls and abort cleanly on CAN (0x18) or SUB (0x1A).

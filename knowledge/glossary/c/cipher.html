Cipher

A mathematical recipe for scrambling readable data into an unreadable form and unscrambling it back using a secret key.

A cipher is like the inner mechanism of a combination lock, except it uses math instead of metal tumblers. Anyone is allowed to know how the cipher works, because without the secret key (the combination), the scrambled message looks like meaningless gibberish and cannot be unlocked.

On Linux (in TLS, SSH, gpg, and disk encryption), symmetric ciphers use one shared key to encrypt either a stream of bytes (such as ChaCha20) or fixed-size blocks (such as AES), while asymmetric ciphers use a public/private key pair for key exchange or signatures. Block ciphers must be paired with a mode of operation (like GCM or XTS) so identical chunks of data do not encrypt to identical ciphertext.

Why is using a block cipher in ECB (Electronic Codebook) mode unsafe for multi-block files or images?

ECB encrypts each block independently with the same key, so identical plaintext blocks always produce identical ciphertext blocks, leaking visible patterns in the underlying data.

Formally, a symmetric cipher is a pair of efficiently computable algorithms (Enc, Dec) over key, message, and ciphertext spaces satisfying correctness (Dec(k, Enc(k, m)) = m). Security is defined via indistinguishability games: IND-CPA requires randomized or nonce-based encryption so repeated plaintexts never correlate, while IND-CCA2 / AEAD adds ciphertext integrity. Block ciphers like AES-128/256 model a pseudorandom permutation (PRP) over 128-bit blocks and hit birthday-bound limits around 2^64 blocks in CBC/CTR; ARX stream ciphers like ChaCha20 (256-bit key, 96-bit nonce) avoid S-box lookup tables and their cache-timing side channels.

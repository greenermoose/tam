CPA (Chosen-Plaintext Attack)

CPA (Chosen-Plaintext Attack) is a security model in which an attacker can obtain the encrypted output for any plaintext messages of their choice.

Imagine trying to figure out how a locked code machine works, except you are allowed to hand the operator any message you want and see the scrambled result that comes back. Even if you never learn the secret key directly, watching how specific inputs turn into outputs can reveal patterns unless the encryption is properly designed. Testing ciphers against CPA ensures they stay safe even when an attacker can influence what gets encrypted.

Chosen-plaintext scenarios happen in real systems—for example, when an attacker can inject known headers, filenames, or URLs into traffic that a server then encrypts. Because of this, any modern cipher must remain secure under CPA (see IND-CPA). Deterministic encryption (such as AES in ECB mode, or reusing a nonce in stream/AEAD modes) fails CPA immediately because encrypting the same plaintext twice produces the same ciphertext, leaking equality.

Why does deterministic encryption (encrypting the same message to the same ciphertext every time) fail against a chosen-plaintext attack?

An attacker can submit a candidate plaintext, observe its ciphertext, and then recognize whenever that exact plaintext is encrypted later—even without knowing the key.

Formally, CPA models a probabilistic polynomial-time adversary given oracle access to E_K(·) under a randomly sampled key K. In the IND-CPA (indistinguishability under chosen-plaintext attack) game, the adversary queries E_K(·) adaptively, submits two equal-length challenge plaintexts m_0 and m_1, receives E_K(m_b) for a random bit b, and continues querying before guessing b; security requires the adversary’s advantage |Pr[b’ = b] - 1/2| to be negligible in the security parameter. Achieving IND-CPA requires randomized or stateful encryption (fresh IVs/nonces in CBC, CTR, or AEAD modes such as AES-GCM or ChaCha20-Poly1305); CPA does not grant a decryption oracle, which is modeled separately by CCA/IND-CCA2.

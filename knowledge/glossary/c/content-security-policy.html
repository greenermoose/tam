Content security policy (CSP)

A content security policy, or CSP, is a header that tells a browser which sources may supply scripts and other resources to a page.

A CSP is a guest list for a page's code. If an unexpected script tries to join, the browser refuses it even if a bug let the script into the page.

Directives such as default-src 'self', script-src and connect-src name allowed sources. Report-only mode records violations without blocking them, which lets a team test a policy first.

Does CSP replace output escaping?

No. Escaping prevents untrusted text from becoming code in the first place. CSP limits what injected code could do if escaping fails. Keep both controls.

A strong policy avoids unsafe-inline and broad wildcard sources, using nonces or hashes for necessary inline code. frame-ancestors replaces older clickjacking headers. Worker and navigation directives cover newer execution paths; a policy is only as useful as the gaps you have checked.

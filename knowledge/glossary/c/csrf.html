Guide / Glossary A–Z / Terms beginning with C / CSRF (Cross-site request forgery)

CSRF is an attack where another site causes your browser to send a request you did not mean to send, using a session you already have.

You are logged in to a bank, then visit a page that silently asks the bank to move money. If the bank trusts the browser's cookie alone, the request may succeed.

Defences include SameSite cookies, a per-session token included in each state-changing request, and asking for the password again before sensitive actions. CORS does not stop a simple form from being submitted.

Does a Secure cookie stop CSRF?

No. Secure means the browser sends the cookie only over HTTPS. It says nothing about which site caused the request. Use SameSite plus a token or another action-bound check.

Any request that changes state needs an authorization decision tied to the intended user action, not merely to an ambient credential. SameSite=Lax blocks many cross-site POSTs but not every top-level navigation; tokens and reauthentication cover the remainder. Safe methods should remain free of side effects.

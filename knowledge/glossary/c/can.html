CAN (Cancel, 0x18)

CAN (Cancel, 0x18) is an ASCII control character (typed with Ctrl+X) that tells a terminal to discard an incomplete escape or control sequence.

Terminals use special multi-character codes starting with Escape to change colors or move the cursor. If one of those codes gets cut off halfway—for example, by a dropped network packet—the terminal could get stuck waiting for the rest of it. Sending the CAN character is like saying “never mind, throw away what I just started” so normal text output can resume cleanly.

Part of the C0 control codes, CAN (0x18, Ctrl+X) aborts an in-progress CSI, OSC, or ESC sequence in ECMA-48 / VT100-compatible terminals and returns the parser to its normal text state. By contrast, interactive programs such as Bash or nano bind Ctrl+X at the application layer for editing shortcuts when non-canonical input is active, whereas byte 0x18 sent in the output stream to the terminal emulator cancels an unfinished escape sequence.

Why does pressing Ctrl+X in nano exit the editor instead of sending a terminal Cancel sequence?

Because nano reads keystrokes from the terminal in non-canonical mode and interprets byte 0x18 as its exit shortcut; CAN only aborts an escape sequence when sent in the output stream to the terminal’s own parser.

In ECMA-48 (ISO/IEC 6429) and VT-series state machines (such as Paul Williams’s VT500 model), receiving 0x18 (CAN) or 0x1A (SUB) from anywhere inside ESC, CSI, DCS, OSC, SOS, PM, or APC states immediately transitions the parser back to Ground without dispatching the partial control function. Unlike ESC (0x1B), which aborts a previous sequence only to enter a new escape state, CAN leaves the parser cleanly in Ground—making it useful for resetting a wedged terminal stream.

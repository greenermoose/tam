Guide / Glossary A–Z / Terms beginning with C / CORS (Cross-Origin Resource Sharing)

CORS is a rule that lets a server say which other website origins may read its replies from browser script.

Browsers normally stop a page from reading replies from a different site. CORS is the server giving that page permission, like a librarian handing over a signed note.

The browser sends an Origin header. The server can answer with Access-Control-Allow-Origin. Some requests first send a small preflight request asking whether the real method and headers are allowed.

A curl request succeeds but the browser reports a CORS error. Did the server refuse the request?

Not necessarily. The server may have replied successfully, but the browser hides the body from script because no CORS permission was present. Read the status and response headers before changing authentication.

CORS relaxes the same-origin policy for reads; it does not stop requests from being sent. Credentialed requests require an explicit origin rather than a wildcard, and preflight results are cached. A permissive configuration can expose private data to any site.

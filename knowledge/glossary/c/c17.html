C17 (ISO C17)

The 2018 maintenance revision of the C programming language standard, fixing defects in C11 without adding new features.

Think of C17 like a second printing of a textbook that fixes typos and unclear sentences without adding any new chapters. Programs written for C11 work the same way under C17, just with fewer ambiguities for compiler writers to argue about.

Part of the C standards family, C17 is also called C18 because it was published in 2018 (GCC and Clang accept both -std=c17 and -std=c18). Because it adds no new syntax or library functions, moving a project from C11 to C17 rarely requires code edits, and modern compilers often use gnu17 as their default mode.

If C17 added no new language features, why does a separate -std=c17 flag exist?

C17 incorporates technical corrigenda and defect-report clarifications over C11 and updates the __STDC_VERSION__ macro to 201710L, allowing code and compilers to target the clarified specification cleanly.

ISO/IEC 9899:2018 (informally C17/C18) resolves defect reports against C11—clarifying edge cases in atomics, _Generic cvr-qualifier stripping, zero-size realloc behavior, and preprocessor rules—while bumping __STDC_VERSION__ to 201710L and deprecating ATOMIC_VAR_INIT. It leaves ABI, standard headers, and core language grammar unchanged from C11.

Guide / Glossary A–Z / Terms beginning with C / CLI (Command-Line Interface)

Command-Line Interface—a text-based way to control a computer by typing commands and reading text output.

If a graphical desktop is like pointing at pictures on a restaurant menu, a CLI is like writing a direct note to the kitchen telling it exactly what to do. Typing commands takes practice, but it lets you repeat tasks quickly, combine small tools together, and control remote computers over slow connections.

On Linux, you use a CLI inside a terminal emulator (or a virtual console) running a shell such as bash or zsh. You type a command name followed by options (like -l) and arguments (like a filename), and programs read from standard input and print to standard output or standard error. Unlike clicking buttons in a GUI, CLI commands are easy to save into shell scripts and automate.

Why do Linux administrators often prefer CLI tools over GUI apps when managing servers?

CLI tools work over low-bandwidth SSH connections without a graphical desktop installed, and commands can be chained into pipelines or saved in scripts for repeatable automation.

At the OS boundary, a POSIX CLI program is started via execve(2) with argv[] and envp[], inheriting three standard file descriptors—0 (stdin), 1 (stdout), and 2 (stderr)—and returning an 8-bit exit status (0 for success, non-zero for failure) collected by waitpid(2). Interactive shells layer job control (SIGTSTP, process groups, termios raw/cooked modes), line editing (Readline/ZLE), and completion on top, while pipelines wire descriptors with pipe(2); well-behaved tools check isatty(3) to adjust buffering and suppress ANSI color escapes when output is redirected.

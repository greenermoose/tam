Control character

A control character is a code that tells a terminal or a program to do something rather than print a visible symbol.

Think of a control character like an invisible instruction rather than a letter on the page—similar to pressing Enter for a new line or Tab to jump ahead. In a terminal, holding the Control key with a letter (such as Ctrl + C or Ctrl + H) sends one of these special codes. Depending on the situation, it might move the cursor, ask a running program to stop, or be handled as an ordinary shortcut inside an editor.

In ASCII, codes 0x00 to 0x1F and 0x7F are control characters. Holding Ctrl and pressing a letter normally clears bits 5 and 6 of the letter’s code, so Ctrl + A is 0x01, Ctrl + H is 0x08, and Ctrl + M is 0x0D. The byte alone does not decide what happens: the terminal emulator, the kernel’s line discipline, and the receiving program each assign meanings depending on the terminal mode.

Why does pressing Ctrl + C stop a command in a normal shell prompt, yet copy text or do something else inside a full-screen editor?

In canonical (cooked) mode, the kernel’s line discipline intercepts 0x03 (ETX) and sends SIGINT to the foreground process; full-screen editors switch the terminal to raw mode so they receive the 0x03 byte directly.

The C0 controls are named in ascii(7): NUL, SOH, STX, ETX, EOT, ENQ, ACK, BEL, BS, HT, LF, VT, FF, CR, SO, SI, DLE, DC1, DC2, DC3, DC4, NAK, SYN, ETB, CAN, EM, SUB, ESC, FS, GS, RS, US, followed by DEL at 0x7F. A terminal may treat BS, HT, LF, VT, FF, CR, SO, SI, CAN, SUB, ESC, and DEL as display/control actions; the line discipline may treat INTR, QUIT, and SUSP as signal requests; and a program may treat any remaining byte as data. Both 0x08 and 0x7F represent backspace in different conventions, which is why they collide. In UTF-8, the 8-bit C1 range is encoded as 0xC2 0x80 to 0xC2 0x9F, so a raw 0x9B byte is invalid UTF-8 and modern terminals use ESC [ instead.

Guide / Glossary A–Z / Terms beginning with C / CAA (Certification Authority Authorization)

CAA (Certification Authority Authorization) is a DNS record that lets a domain owner declare which Certificate Authorities are allowed to issue TLS certificates for that domain.

Normally, any trusted Certificate Authority (CA) in the world could be tricked or compromised into issuing a security certificate for your website. A CAA record is like posting an official guest list on your domain’s public noticeboard: it tells every CA, “Only the authorities listed here are allowed to create certificates for my site.”

Every publicly trusted CA is required under CA/Browser Forum Baseline Requirements and RFC 8659 to query a domain’s CAA record before issuing a TLS certificate. A record such as example.com. IN CAA 0 issue "letsencrypt.org" allows Let’s Encrypt while blocking other CAs, and issuewild controls wildcard certificates (*.example.com). If a subdomain has no CAA record, CAs walk up the DNS tree to the parent domain’s record; you can inspect a domain’s policy with dig CAA example.com.

If sub.example.com has no CAA record, can any Certificate Authority issue a certificate for it?

Not necessarily. CAs climb the DNS hierarchy toward the root and enforce the first CAA record they find—so a restrictive CAA record on example.com automatically protects sub.example.com unless the subdomain overrides it.

DNS resource record type 257 (RFC 8659, obsoleting RFC 6844) encodes a 1-byte flags field (bit 0 is the issuer-critical flag), a length-prefixed ASCII property tag, and a value. Standard tags are issue, issuewild (which takes precedence over issue for wildcard SANs; an empty ";" value forbids all issuance), and iodef (a mailto: or https: URI for violation reports). Two operational subtleties apply: DNSSEC validation is mandatory when checking CAA so spoofed NXDOMAIN responses cannot suppress enforcement (SERVFAIL blocks issuance), and CNAME chains are followed before tree-climbing to parent labels.

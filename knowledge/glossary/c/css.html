CSS (Cascading Style Sheets)

CSS (Cascading Style Sheets) is a declarative styling language used to control colors, fonts, spacing, and layout in web browsers and Linux desktop toolkits such as GTK and Waybar.

If a web page or desktop panel is a house, the HTML or widget layout is the wooden frame and walls, while CSS is the paint, wallpaper, lighting, and furniture arrangement. By keeping style rules in separate .css files, you can change the entire look—such as switching from a bright daytime theme to a dark theme—without rewriting the underlying structure of the page or program.

In CSS, rules pair selectors (such as .module, #workspaces button.active, or window) with declarations (color, background, padding). “Cascading” means multiple stylesheets layer together, resolving conflicts by source order and selector specificity (IDs beat classes, which beat element names). On Linux, you edit CSS not only for web pages, but also for GTK apps (~/.config/gtk-3.0/gtk.css or gtk-4.0/gtk.css) and Wayland bars/launchers like Waybar and Wofi—though desktop toolkits implement a subset tailored to their own widget nodes.

Why might a valid CSS rule you wrote in a Waybar or GTK stylesheet have no visible effect?

Either a more specific selector in the active theme overrides your rule in the cascade, or the property is a web-only CSS feature (such as certain grid or pseudo-element rules) not supported by GTK’s CSS engine.

The W3C CSS cascade resolves conflicting declarations by origin and importance (!important, user-agent, user, author, animations, transitions), specificity (a, b, c) tuples, and source order, feeding box-model layout (content, padding, border, margin; Flexbox and CSS Grid formatting contexts). GTK 3/4 and gtk-layer-shell clients such as Waybar use a custom CSS parser and style-context engine supporting @define-color variables, :hover/:active pseudo-classes, and widget-tree node selectors while omitting web DOM APIs and many CSS3/4 layout features; GTK 4 also removes legacy GTK 3 properties (such as -gtk-icon-effect) in favor of standard transforms and filters.

Guide / Glossary A–Z / Terms beginning with C / C10 (Deepest CPU Package C-state)

The deepest idle power-saving state on modern Intel CPUs, cutting core, cache, and ring voltages when the whole chip is idle.

If a lighter sleep state turns off one room’s lights while keeping the hallway lit, C10 is shutting down the main breaker for the whole floor between keystrokes. On a laptop, reaching C10 during quiet moments is what lets the battery last for hours while you read a page.

On Linux laptops, tools like powertop show whether the processor reaches PC10 (Package C10). Even when CPU usage is near zero, a misbehaving USB device, disabled PCIe ASPM (Active State Power Management), or frequent background timers can trap the chip in shallower states like PC2 or PC3 and drain the battery.

Why can a single active PCIe or USB device prevent the CPU from entering Package C10 even when all cores are idle?

Package C10 powers down shared ring and interconnect logic. If a device keeps DMA or PCIe links active without low-power ASPM states, the SoC must keep the ring powered to service it, blocking PC10.

Intel Package C-state PC10—a prerequisite for S0ix modern standby—gates core clocks, Last-Level Cache (LLC), and ring/uncore voltage rails once every logical core resides in core CC6/CC7+ and platform LTR (Latency Tolerance Reporting) constraints permit. Blockers preventing PC10 residency are diagnosed via /sys/kernel/debug/pmc_core/package_cstate_show and substate_requirements, inspecting LTR votes, display PSR/DC states, and PCIe ASPM L1.2 readiness.

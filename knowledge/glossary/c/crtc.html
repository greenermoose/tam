Guide / Glossary A–Z / Terms beginning with C / CRTC (Cathode Ray Tube Controller)

A display controller that reads pixels from memory and sends them to a display output.

The name comes from old cathode-ray tube displays, but the idea is still used today. A CRTC is the part of the graphics system that takes an image from a framebuffer and scans it out, line by line, to a screen. If you have two monitors, the graphics card usually needs a CRTC for each active display output.

In Linux's DRM/KMS model, a CRTC is the scanout engine that combines a framebuffer plane with a display mode and timing. It connects to encoders and connectors that represent the physical output path. Tools such as drm_info or modetest can show CRTCs, their modes, and which connector they drive. Running out of CRTCs can limit how many independent displays can be active at once.

Why can a GPU with three ports sometimes drive only two monitors?

The ports are not the only limit. The GPU may have fewer CRTCs than connectors, so it cannot scan out an independent image to every port at the same time.

A DRM CRTC represents the hardware block that reads plane buffers, applies cursor/overlay composition as supported, and generates display timings for an encoder. Atomic KMS updates commit CRTC state, plane state, and connector state as one validated transaction. CRTC capabilities vary by driver: some support scaling, gamma/CTM color management, or VRR, while others expose limits such as maximum pixel clock or plane count. The historical CRT name remains in the API even though modern outputs drive LCD, OLED, or other panel technologies.

Guide / Glossary A–Z / Terms beginning with C / C90 (ISO C90)

C90 (ISO C90) is the 1990 international standard for the C programming language, adopting the 1989 American standard for worldwide use.

After the United States published its first official C rulebook in 1989, the international standards body (ISO) adopted the exact same rules in 1990 under a global name. Think of it like a book printed in a second country with a new cover and chapter numbers, while the story inside stays the same.

Part of the C standards family, C89 and C90 define the exact same C language and standard library—only the publisher and section numbering differ. In Linux toolchains, GCC and Clang treat -std=c90, -std=c89, and -ansi as aliases for the same language mode, while -std=iso9899:199409 (C94/C95) adds Amendment 1 headers like <iso646.h> and <wchar.h>.

If a project’s Makefile specifies -std=c90 instead of -std=c89, does it enable newer C features?

No. C90 is technically identical to C89; both flags select the same 1989/1990 language specification, differing only in whether you refer to the ANSI or ISO publication.

Formally ISO/IEC 9899:1990, C90 adopted ANSI X3.159-1989 with ISO formatting—splitting the ANSI Rationale out and renumbering clauses (for example, ANSI §3 became ISO §6). Because __STDC_VERSION__ was not defined in the original 1990 text, portable preprocessor checks distinguish C90 from later revisions by testing defined(__STDC__) && !defined(__STDC_VERSION__). ISO later issued Technical Corrigenda (TC1 in 1994, TC2 in 1996) and Normative Amendment 1 (ISO/IEC 9899/AMD1:1995, setting __STDC_VERSION__ to 199409L), which added digraphs, <wchar.h>, <wctype.h>, and <iso646.h> before C99 superseded the 1990 baseline.

Guide / Glossary A–Z / Terms beginning with C / Context switch

A context switch happens when the processor stops running one task and switches to running another.

Imagine a chef working on soup, pausing to check an oven timer, writing down where they were in the recipe, and then switching to chop vegetables for a salad before coming back later. A single processor core can only run one task at a time, so the operating system rapidly switches between programs—saving one’s place and restoring another’s—so everything appears to run at once.

Every time a program waits for disk, network input, or its turn on a busy CPU, the kernel performs a context switch by saving the outgoing thread’s registers and loading the incoming thread’s saved state. Switching between threads of the same process is cheaper than switching between different processes because threads share the same memory map. Even so, switching thousands of times per second wastes CPU time and cools down caches—one reason tools like vmstat or perf track context-switch rates.

Why are excessive context switches bad for performance even if each switch takes only microseconds?

Beyond the direct time spent saving and restoring registers in the kernel, the new task’s instructions and data evict the previous task’s hot entries from CPU caches and translation buffers, slowing execution after the switch.

A full task context switch in the Linux kernel (__schedule() / context_switch()) saves and restores general-purpose, floating-point/SIMD, and control registers, switches the kernel stack, and—when crossing address spaces—updates the page-table base register (such as CR3 on x86_64 or TTBR0_EL1 on ARM64). Address-space switches can invalidate or tag TLB entries (mitigated by PCID/ASID) and trigger branch-predictor mitigations (such as IBPB across untrusted boundaries). Voluntary switches occur when a task blocks on I/O or a futex; involuntary switches occur on timer or wakeup preemption, both incurring indirect costs from L1/L2 cache thrashing and cross-core migration.

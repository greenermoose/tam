CSP (Content Security Policy)

Content Security Policy (CSP) is an HTTP response header that lets a website tell the browser which scripts, styles, images, and frames are allowed to load and run.

Think of CSP as a guest list at the door of a venue. Normally, if a malicious note slips onto a web page—say, through a comment box—the browser might blindly run any script it finds there. With CSP, the website hands the browser an official guest list ahead of time: “Only run scripts from my own server, and ignore any script written directly into the page or loaded from strangers.” Even if an attacker injects bad code, the browser refuses to execute it.

Websites deliver CSP via the Content-Security-Policy HTTP header (or Content-Security-Policy-Report-Only to test rules without breaking pages). Key directives include default-src (fallback), script-src (allowed JavaScript origins, nonces, or hashes), style-src, img-src, and frame-ancestors (preventing clickjacking). By default, enabling script-src blocks inline <script> tags and eval(), stopping most Cross-Site Scripting (XSS) payloads unless weakened by 'unsafe-inline' or 'unsafe-eval'.

Why does adding 'unsafe-inline' to script-src undermine CSP’s main protection against XSS?

XSS attacks typically inject inline <script> tags or event handlers like onload= into HTML. Allowing 'unsafe-inline' permits those injected scripts to execute instead of requiring a cryptographic nonce or hash.

W3C CSP Level 3 evaluates directives independently (falling back only to default-src for fetch directives) and applies the intersection when multiple Content-Security-Policy headers are sent. Strict nonce-based policies pair per-response cryptographic nonces ('nonce-...') with 'strict-dynamic' so trusted scripts can load dependencies without brittle host allowlists—which are frequently bypassed via JSONP endpoints, open redirects, or allowlisted CDNs hosting gadgets like AngularJS. Hardening also requires base-uri 'none' and object-src 'none' to block relative-URL hijacking via injected <base> tags and plugin execution.

Guide / Glossary A–Z / Terms beginning with C / CPU (Central Processing Unit)

A Central Processing Unit (CPU) is the main processor in a computer that fetches, decodes, and executes program instructions.

If a computer is a workshop, the CPU is the worker following a recipe step by step. Whenever you open a browser, type a letter, or play audio, software breaks the job into tiny instructions—like adding two numbers or moving a value—and the CPU carries them out billions of times per second. Modern CPUs have multiple “cores,” which is like having several workers at the workbench so different tasks can run at the same time.

A CPU core runs an instruction cycle using fast internal registers backed by on-chip caches before reaching RAM. Unlike a GPU, which is built to run thousands of simple math operations in parallel, a CPU is optimized for low-latency control flow, branching, and operating-system scheduling. On Linux, lscpu and /proc/cpuinfo distinguish physical cores from hardware threads (SMT/Hyper-Threading), while cpufreq governors scale clock speed and voltage to balance responsiveness and power draw.

Why does a 4-core CPU with 8 hardware threads not double the speed of 4 threads on every workload?

Hardware threads (SMT) share a physical core’s execution units and caches. They improve throughput when one thread stalls on memory, but CPU-bound workloads that already saturate the core’s pipelines contend for the same hardware resources.

Modern general-purpose CPUs (such as x86-64 and AArch64 implementations) present an in-order architectural state while executing instructions out-of-order via superscalar front-ends, register renaming, reorder buffers, and speculative branch predictors. Privilege levels (rings 0–3 on x86, EL0–EL3 on ARM) enforce kernel/user isolation alongside hardware virtualization extensions (VMX/SVM) and MMU page-table walkers. Sustained throughput is bounded by decode/fetch width, execution-port contention, memory-level parallelism, and thermal/power limits (TDP, PL1/PL2) managed through DVFS and idle C-states.

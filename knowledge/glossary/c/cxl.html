Guide / Glossary A–Z / Terms beginning with C / CXL (Compute Express Link)

A high-speed, cache-coherent interconnect layered over PCIe 5.0 and 6.0 for connecting CPUs, memory expanders, and accelerators.

Normally, an add-in card like a graphics card keeps its own separate memory, so the CPU has to copy data back and forth like mailing packages between two offices. CXL is a newer high-speed connection built on top of standard PCIe slots that lets the CPU, accelerators, and memory expansion cards share the same workspace directly without slow copying.

CXL runs over PCIe physical lanes and defines three device roles: Type 1 (accelerators without local RAM that cache host memory, like smart NICs), Type 2 (accelerators with local RAM, like GPUs), and Type 3 (memory expanders). On Linux, Type 3 CXL memory is managed via /sys/bus/cxl and cxl-cli, appearing to the kernel as an additional NUMA memory node.

How does CXL memory expansion differ from standard PCIe device memory?

Standard PCIe relies on explicit DMA copies or uncached MMIO accesses managed by drivers, whereas CXL maintains hardware cache coherency so the CPU can read and write CXL-attached memory with normal load/store instructions just like system RAM.

A protocol suite multiplexing three sub-protocols over the PCIe 5.0/6.0 physical layer using fixed-size FLITs (528-bit in CXL 1.x/2.0, 256-byte in CXL 3.0) with link-layer CRC and retry: CXL.io (PCIe-compatible enumeration, config, interrupts, and DMA), CXL.cache (device-initiated coherent caching of host memory), and CXL.mem (host load/store access to device-attached memory via HDM decoders). Trade-offs: hardware coherency at 64-byte cacheline granularity eliminates software cache-flush overhead, but CXL-attached memory has higher latency than local DDR5 DRAM—requiring Linux NUMA memory tiering—while CXL 3.0 adds fabric switching and back-invalidation channels for multi-host memory sharing.

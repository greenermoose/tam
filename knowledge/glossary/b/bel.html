BEL (Bell, 0x07)

The ASCII control character 0x07 (Ctrl+G), originally used to ring a teletype bell and now used for terminal alerts and sequence termination.

Long before computer screens, teletype machines printed text on paper and had a real metal bell to get an operator’s attention. Sending the BEL character made the bell ring. Today, in a terminal window, it triggers a chime or a brief screen flash—and behind the scenes, programs also use it as an invisible marker to signal the end of certain terminal commands.

Part of the C0 control codes, BEL (0x07, \a in C, Python, and bash printf) triggers the terminal’s audible or visual bell when printed directly. However, in xterm-compatible terminal emulators, BEL is also widely used as an alternative terminator for Operating System Command (OSC) sequences—for example, setting a window title with \e]0;Title\a.

Why does running printf '\e]0;Build done\a' change your terminal title without ringing the bell?

Because the terminal parser is inside an OSC sequence started by \e]. In that state, 0x07 (BEL) is consumed as the OSC string terminator rather than triggering the alert bell.

ASCII 0x07 (BEL, ^G, \a). Standard ECMA-48 defines ST (ESC \, 0x1B 0x5C, or C1 0x9C) as the canonical String Terminator for OSC/DCS/APC sequences, while xterm popularized 0x07 as a single-byte OSC terminator for compactness and 7-bit safety. Parsers must therefore treat 0x07 contextually: executing the bell action in ground state, but terminating and dispatching the buffered OSC payload when inside an OSC string state (without sounding the bell).

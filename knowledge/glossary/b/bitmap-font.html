Guide / Glossary A–Z / Terms beginning with B / Bitmap font

A bitmap font stores each glyph as a fixed pixel pattern, so it is sharp only at its designed size.

A bitmap font is like a stamp: each letter is a small grid of dots that the computer copies onto the screen. At the size it was made for it looks perfectly crisp; enlarge it and the dots become blocky. Early computers used them because they were cheap to draw.

Terminals and the Linux virtual console use bitmap fonts because a fixed grid gives predictable character cells. Linux 6.12 ships 13 built-in fonts in lib/fonts/, including VGA8x8, VGA8x16 and TER16x32; each has 256 characters and a fixed cell size. setfont can replace them with a PSF user font. Scalable outline fonts have largely replaced bitmaps in desktop applications.

Kernel bitmap strikes are packed rows of bits plus width, height and charcount in a font descriptor registered by fonts.c. The console selects one with fbcon=font: or get_default_font() based on dimensions, and KDFONTOP installs user fonts of 256 or 512 glyphs. Rendering skips outline rasterization and hinting entirely: the result is deterministic but cannot scale cleanly. Userspace consoles such as KMScon use different backends.

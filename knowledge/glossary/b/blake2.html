BLAKE2

BLAKE2 is a fast, secure cryptographic hash function family (BLAKE2b and BLAKE2s) designed as a high-speed alternative to SHA-2 and SHA-3 in software.

A cryptographic hash turns any file or password into a fixed-length digital fingerprint so you can verify it has not been tampered with. Older standard hashes like SHA-256 can feel sluggish on ordinary processors unless the chip has special hardware instructions. BLAKE2 was designed to run much faster in plain software while keeping the same strong security guarantees.

Defined in RFC 7693, BLAKE2 comes in two main variants: BLAKE2b (optimized for 64-bit platforms, producing digests up to 64 bytes) and BLAKE2s (optimized for 32-bit and embedded CPUs, up to 32 bytes). On Linux, you can compute digests with b2sum from GNU Coreutils, and BLAKE2 underpins WireGuard, the Argon2 password KDF, and ZFS checksums. Unlike SHA-256, BLAKE2 natively supports keyed hashing (MAC), eliminating the need for a separate HMAC wrapper.

When should you pick BLAKE2b versus BLAKE2s?

Choose BLAKE2b on 64-bit servers and desktops where 64-bit word operations are native and you may want digests up to 512 bits; choose BLAKE2s on 32-bit microcontrollers or protocols constrained to 32-bit words and 256-bit digests.

BLAKE2 refines the SHA-3 finalist BLAKE using a HAIFA-derived chaining structure and ChaCha-inspired ARX (Add–Rotate–XOR) quarter-round G functions, reducing round counts from 14/16 to 12 (BLAKE2b, 64-bit words, rotations 32, 24, 16, 63) and 10 (BLAKE2s, 32-bit words, rotations 16, 12, 8, 7). Parameter blocks XORed into the initial state vector IV support built-in keying, personalization, salt, and tree-hashing modes (BLAKE2bp/BLAKE2sp for SIMD/multi-core parallelism) without length-extension vulnerabilities. Note that on x86_64/ARM64 CPUs with SHA-NI or ARMv8 Crypto extensions, hardware-accelerated SHA-256 can surpass software BLAKE2b, though BLAKE2 remains faster on CPUs without SHA extensions.

Bootloader

A small program that starts after hardware firmware and loads the operating system kernel into memory.

When a computer turns on, the built-in firmware only knows enough to check the hardware and look for a starting program on a drive—it does not know how to run a full operating system on its own. The bootloader is that middleman: it reads the operating system’s main program from storage, places it into memory, and hands over control. If you have more than one system installed, the bootloader is also what shows the menu asking which one to start.

On Linux systems, common bootloaders include GRUB, systemd-boot, and Limine. A bootloader lets you pick between kernel versions or recovery entries and pass kernel command-line parameters (such as quiet or systemd.unit=rescue.target) for troubleshooting. Unlike firmware, which lives on motherboard flash, the bootloader lives on disk—usually in the EFI System Partition—so reinstalling an OS or misconfiguring its entry can leave the machine unable to find its kernel.

What is the difference between system firmware (UEFI) and a bootloader?

Firmware is stored on the motherboard and initializes hardware at power-on; a bootloader is stored on a drive and knows how to locate kernels, pass boot arguments, and present OS choices. Firmware starts the bootloader, which in turn starts the kernel.

On UEFI platforms, a bootloader is a PE/COFF EFI application (e.g., grubx64.efi, systemd-bootx64.efi) invoked from the FAT32 ESP (\EFI\...), using UEFI Boot Services (LoadImage, StartImage, EFI_SIMPLE_FILE_SYSTEM_PROTOCOL) before the kernel calls ExitBootServices(). It parses configuration (such as Boot Loader Specification snippets or grub.cfg), loads the kernel image, initramfs cpio, and optional device tree or microcode updates into memory, and transfers control according to the target architecture’s boot protocol (such as the Linux x86 Boot Protocol’s boot_params setup header or EFI handover). Legacy BIOS bootloaders instead rely on a 446-byte MBR Stage 1 jumping to Stage 1.5/2 sectors via INT 13h, constrained by 16-bit real mode and 512-byte sector boundaries.

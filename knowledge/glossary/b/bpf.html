BPF / eBPF (Berkeley Packet Filter)

An in-kernel virtual machine that runs small, safety-checked programs inside the Linux kernel for networking, tracing, and security.

Normally, changing how the operating system kernel handles network packets or monitors programs means writing risky kernel code that could crash the whole computer if it has a bug. eBPF (extended Berkeley Packet Filter) works like a strict security checkpoint inside the kernel: you can attach tiny helper scripts to watch network traffic or system activity, and the kernel checks every line beforehand to make sure it cannot freeze or corrupt the system.

Tools like tcpdump, nftables/XDP, bpftrace, and systemd sandboxing (such as RestrictAddressFamilies) rely on classic BPF or extended eBPF. Because eBPF programs filter or summarize events directly inside the kernel without copying every packet or syscall out to user space, they achieve much lower overhead than polling /proc or capturing full traffic logs.

Why can an eBPF program be loaded into the kernel without risking a kernel panic from an infinite loop?

Before any eBPF program is attached, the kernel’s in-kernel verifier statically walks all execution paths, rejecting unbounded loops, invalid pointer arithmetic, and uninitialized reads—guaranteeing the program terminates safely.

Originally a 2-register accumulator VM for socket filtering (SO_ATTACH_FILTER), extended BPF (eBPF) provides eleven 64-bit registers (R0–R10, where R10 is a read-only frame pointer), a 512-byte stack, and typed helper/kfunc calls, loaded via bpf(BPF_PROG_LOAD, ...). The kernel verifier performs abstract interpretation over register value ranges (tnum and min/max bounds), reference tracking, and CFG DAG or bounded-loop checks before the JIT compiler lowers bytecode to native instructions (with Spectre v1/v4 mitigations). Programs communicate with user space via BPF maps (BPF_MAP_TYPE_HASH, ring buffers, per-CPU arrays) and attach to hooks including XDP, tc, kprobes, tracepoints, fentry/fexit, and LSM hooks; verifier complexity limits (1M processed instructions) and BTF/CO-RE relocations govern portability across kernels.

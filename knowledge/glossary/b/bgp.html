BGP (Border Gateway Protocol)

The routing protocol that connects independent networks (autonomous systems) across the internet.

The internet isn’t one big network—it’s tens of thousands of separate networks run by ISPs, universities, and cloud providers. BGP is how those networks talk to each other to share maps of which direction to send traffic to reach a given IP address, much like international postal hubs agreeing on which airline carries mail to each country.

Each major network has an Autonomous System Number (ASN) and uses BGP to announce which IP prefixes it owns or can reach. Unlike interior routing protocols (such as OSPF) that pick the fastest path inside one organization, BGP is policy-driven—choosing routes based on business relationships, shortest AS path, and local preferences. Because classic BGP trusts announcements, RPKI (Resource Public Key Infrastructure) adds cryptographic origin validation to prevent route hijacking.

Why can a misconfigured BGP announcement at one ISP break reachability for other networks worldwide?

BGP propagates reachability announcements between autonomous systems by trust unless filtered. If an ISP accidentally announces a more specific IP prefix it does not own (a route leak or hijack), neighboring ASes may prefer that route and send traffic into a black hole.

BGP-4 (RFC 4271) is an incremental, path-vector inter-domain protocol running over TCP port 179, exchanging NLRI (Network Layer Reachability Information) prefixes and path attributes (AS_PATH, NEXT_HOP, LOCAL_PREF, MED, COMMUNITY). Best-path selection follows a deterministic tie-break pipeline (highest LOCAL_PREF, shortest AS_PATH, lowest ORIGIN, lowest MED, eBGP over iBGP, lowest IGP cost to NEXT_HOP, lowest BGP router ID). Operational hardening relies on prefix-list filtering, RPKI Route Origin Validation (ROV, RFC 6811), and Graceful Restart or BFD for faster failure convergence.

Build

The process of turning human-readable source files into runnable software or installable packages.

Think of building software like baking from a recipe: source code is the list of ingredients and instructions, and building is mixing and baking them into a finished program you can actually run. Computers cannot run most human-written code directly until it is translated and assembled into machine-ready form.

On Linux, a build usually runs through distinct stages—configuring options and finding libraries, compiling source files into object code, linking them into executables or shared libraries, and optionally packaging the output. Tools such as make, cmake, and meson track timestamps so incremental builds only recompile what changed.

Why does an incremental build sometimes fail or produce stale output after you change a header or build option?

Incremental builds skip steps whose tracked inputs look unchanged. If a build script misses a header dependency, or if you change a compiler flag without cleaning old object files, old compiled pieces get linked with new ones and cause subtle bugs or link errors.

Builds trade speed (incremental caching, parallel -j job slots, precompiled headers) against hermiticity and reproducibility. Non-hermetic builds leak host state—PATH, locale, timestamps, or ambient headers—breaking bit-for-bit reproducibility. Reproducible builds pin toolchain versions, normalize SOURCE_DATE_EPOCH, remap build paths with -ffile-prefix-map, and isolate inputs in sandboxes or chroots so identical inputs yield identical output digests.

Guide / Glossary A–Z / Terms beginning with B / Btrfs (B-tree filesystem)

A copy-on-write Linux filesystem that supports snapshots, subvolumes, and data checksums.

A filesystem is how the computer organizes files and folders on a disk. Btrfs is a Linux filesystem that can take “snapshots”—like instant bookmarks of a folder’s state—without copying every file from scratch. Tamlinux uses Btrfs with Snapper so you can roll back some kinds of system change if something goes wrong, though snapshots do not cover every file and personal documents may still need separate backup.

Btrfs provides copy-on-write (CoW) snapshots, subvolumes (independently mountable directory trees sharing one storage pool), and checksums. Snapper typically manages snapshot timelines on selected subvolumes: rolling back restores filesystem state at that boundary, while Home Manager generations and mutable user files remain separate recovery domains. Use btrfs filesystem df rather than relying only on df, because CoW snapshots and metadata reservations behave differently from traditional filesystems like ext4.

Why doesn’t taking a Btrfs snapshot immediately double your disk usage?

Btrfs uses copy-on-write (CoW): a new snapshot shares the exact same underlying data blocks as the original subvolume and only consumes extra space later when files are modified or deleted and new blocks are written.

Used on Tamlinux for snapshot-backed recovery boundaries via Snapper, Btrfs stores both data and metadata in copy-on-write B-trees, verifying integrity with per-block checksums (CRC32C by default, or xxhash64/SHA256/BLAKE2b) in the checksum tree and supporting transparent compression, subvolume quotas (qgroups), and incremental btrfs send | btrfs receive streams. Operational caveats include CoW write amplification and fragmentation on random-write workloads (such as VM images or databases, often mitigated with nodatacow via chattr +C, which also disables checksums and compression for that file), the RAID5/6 write-hole on unclean shutdown, and ENOSPC conditions when metadata chunks exhaust unallocated space despite free data space, requiring btrfs balance.

Bundle

A bundle is all the files of one version of some software, with a name, a version and a fingerprint, installed and removed as one unit.

Think of a bundle like a sealed box with a label on the outside and a packing slip inside. Instead of scattering loose files across your computer where they can get mixed up with other programs, keeping every file for one version together lets the system install, check, or swap back to an older box cleanly.

In tam-bundle, a bundle is a directory holding a built file tree plus two text records: BUNDLE (name, version, hash, sources) and MANIFEST (every path with its mode and SHA-256 hash). Its id is name-version- followed by twelve hash characters, which lets you tell two builds of the same version apart at a glance.

Why does a bundle include a MANIFEST listing every file’s mode and SHA-256 hash?

Recording each file’s path, permissions, and hash lets the installer verify that no file was corrupted or altered after the build, and ensures removal or rollback touches only the exact files belonging to that bundle.

A content-addressed file set: the bundle hash is SHA-256 over the identity record without its build time, followed by the sorted file list, so identical inputs produce an identical id across rebuilds. Unlike a Nix store path, it is installed as real files into target paths and carries no transitive dependency closure; native library and runtime requirements are only checked at install time, trading multi-version side-by-side isolation for a standard filesystem layout.

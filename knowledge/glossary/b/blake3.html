BLAKE3

BLAKE3 is a modern cryptographic hash function built as a Merkle tree so it can run in parallel across SIMD vector lanes and multiple CPU cores.

Most classic hash functions process a file one piece after another in a single line, so a computer with 16 processor cores cannot hash one big file any faster than a computer with 1 core. BLAKE3 splits the data into small chunks and hashes them in a tree structure at the same time, letting modern processors hash gigabytes of data in a fraction of a second.

BLAKE3 unifies hashing, keyed MACs, key derivation (KDF), and extendable-output functions (XOF) into a single algorithm rather than separate modes. Because its Merkle tree hashes 1 KiB chunks independently, a tool like b3sum saturates AVX-512 or NEON SIMD lanes and scales across threads on large files—yet produces the exact same digest whether computed single-threaded or multi-threaded. Its tree structure also enables incremental verification of individual chunks without reading an entire file.

Why does BLAKE3 produce the same hash whether it runs on 1 thread or 16 threads?

Its Merkle tree structure fixes how data is split into 1 KiB chunks and how pairs of chunk digests are combined up to the root, so parallel workers compute the exact same internal nodes in a deterministic tree rather than depending on thread count.

Designed by O’Connor, Aumasson, Neves, and Wilcox-O’Hearn (2020), BLAKE3 derives from BLAKE2s and Bao, reducing the compression function from 10 to 7 ARX rounds based on cryptanalytic margins against rotational-XOR and rebound attacks. Inputs are partitioned into 1024-byte chunks (16 × 64-byte blocks) arranged in a binary Merkle tree with domain-separation flags (CHUNK_START, CHUNK_END, PARENT, ROOT, KEYED_HASH, DERIVE_KEY) and a 64-bit chunk counter. Because SIMD implementations process 8 or 16 independent chunks simultaneously via AVX2/AVX-512, throughput scales nearly linearly with vector width and core count, though inputs ≤ 1 KiB incur only a single compression call with no tree overhead.

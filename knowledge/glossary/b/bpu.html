Guide / Glossary A–Z / Terms beginning with B / BPU (Branch Prediction Unit)

Hardware inside a modern CPU that guesses which way conditional branches will go before they resolve so the processor does not have to wait.

A modern processor works like an assembly line, starting new instructions before earlier ones finish. Whenever your program hits an “if” decision, waiting to see which path to take would stall the whole line. The Branch Prediction Unit (BPU) guesses the answer ahead of time and keeps feeding instructions from that path; if it guesses right, everything stays fast, and if it guesses wrong, it discards the guessed work and switches to the real path.

Predictable branches—such as a loop that repeats many times or checks on sorted data—let the BPU hit over 95% accuracy, while random, unpredictable branches cause frequent pipeline flushes. When profiling with perf stat, a high branch-misses rate often points to a hot loop that could be sped up by sorting data or using branchless conditional moves (cmov). Because the CPU executes predicted paths speculatively before checking permissions, BPU state also enabled Spectre-class leaks and led to mitigations like IBRS and Retpoline.

What happens when the BPU makes a wrong prediction?

The CPU flushes all speculatively fetched and partially executed instructions from the wrong path out of the pipeline and restarts fetching from the correct target address, costing roughly 10–20+ clock cycles of lost throughput.

Sitting in the CPU frontend fetch stage, the BPU combines directional predictors (such as TAGE—TAgged GEometric history length—and perceptron/loop predictors indexed by PC and global branch history registers) with target predictors: the Branch Target Buffer (BTB) for direct/indirect targets, the Return Address Stack (RAS) for call/ret pairing, and indirect target caches. Mispredictions trigger pipeline squash and reorder-buffer rollback; shared indirect branch prediction across privilege domains or SMT siblings enabled Spectre v2 (Branch Target Injection), mitigated via hardware isolation (IBRS, eIBRS, IBPB, STIBP) or software retpoline thunks, alongside BHB-clearing and RSB-stuffing sequences on affected microarchitectures.

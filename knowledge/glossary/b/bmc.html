Guide / Glossary A–Z / Terms beginning with B / BMC (Baseboard Management Controller)

A BMC (Baseboard Management Controller) is a dedicated service processor on server motherboards that provides out-of-band monitoring, power control, and remote console access independently of the main CPU.

If your home PC freezes or shuts off, you have to walk over and press the power button or look at the monitor. Servers often sit in locked data centers miles away, so they include a tiny, separate computer built right onto the motherboard called a BMC. As long as the server has standby power and a network cable plugged in, an administrator can check fan speeds, read temperatures, watch the boot screen, or force a reboot—even when the main operating system has crashed or is powered off.

Vendor implementations include Dell iDRAC, HPE iLO, and Lenovo XClarity, while open-source firmware like OpenBMC is common on hyperscale and modern Linux servers. A BMC typically has its own dedicated management NIC (or shares a host NIC via NC-SI) and speaks protocols such as IPMI (legacy, UDP port 623) or Redfish (modern HTTPS/REST JSON). From the host Linux OS, administrators can query sensors or configure the BMC locally via /dev/ipmi0 using ipmitool, and pair it with Serial-over-LAN (SOL) to access GRUB and kernel boot logs remotely.

Why should a BMC network interface always be placed on an isolated management VLAN rather than a public network?

A BMC has full hardware-level control—power cycling, virtual media mounting, firmware flashing, and console access—bypassing the host OS entirely; exposing its web UI or IPMI interface to untrusted networks creates a critical persistence and takeover risk.

Physically, a BMC is an embedded SoC (commonly ASPEED AST2500/AST2600 running an embedded Linux stack) wired to motherboard I²C/SMBus/PMBus sensors, fan PWM controllers, eSPI/LPC buses for host POST codes and KCS/BT interfaces, PCIe/USB for virtual KVM and virtual media, and RMII/RGMII or NC-SI for out-of-band Ethernet. IPMI 2.0’s RMCP+ authentication (Cipher Suite 3/17) and historical RAKP hash disclosure flaws make Redfish over TLS with mutual auth or strict network ACLs strongly preferred. Because the BMC shares SPI flash or platform buses with the host, compromised BMC firmware can persist across OS reinstalls, driving adoption of hardware Root of Trust (RoT) and SPDM attestation.

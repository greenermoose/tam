Guide / Glossary A–Z / Terms beginning with B / BKZ (Block Korkine-Zolotarev)

BKZ (Block Korkine–Zolotarev) is a lattice basis-reduction algorithm used to find short vectors in high-dimensional lattices and estimate the security of post-quantum lattice cryptography.

Imagine a giant, tilted grid of dots in hundreds of dimensions. Lattice-based encryption hides secrets inside that grid so that an attacker must find a very short step between grid points—a problem that gets astronomically harder as the grid grows. BKZ is the main tool cryptographers use to test how well a determined attacker could untangle that grid, helping them choose key sizes that stay safe against both regular and quantum computers.

Compared to LLL (Lenstra–Lenstra–Lovász), which reduces pairs of basis vectors in polynomial time and works well only in small dimensions, BKZ generalizes reduction to blocks of size β (beta). Increasing β produces much shorter vectors—getting closer to solving the Shortest Vector Problem (SVP)—at a cost that grows exponentially with β. Cryptanalysts use BKZ simulators and “core-SVP” cost models to size NIST post-quantum standards such as ML-KEM (Kyber) and ML-DSA (Dilithium) so that the required block size β exceeds what any classical or quantum attacker can run.

Why do post-quantum cryptographers tune the block size parameter β when evaluating a lattice scheme?

Because β controls the trade-off between attack power and runtime: a larger β finds shorter vectors needed to break the scheme, but solving SVP inside each β-dimensional block grows exponentially with β, letting researchers pinpoint the minimum block size (and thus security bits) needed for an attack.

Introduced by Schnorr and Euchner (1994), BKZ iterates over projected sublattices L_{[i, min(i+β−1, d)]} of rank up to β, invoking an exact SVP oracle (classically lattice enumeration or sieving) on each block and LLL-reducing the updated basis until no shorter projected vector is found. BKZ 2.0 (Chen–Nguyen) adds extreme pruning, early abort, and preprocessing of local bases, achieving a Hermite factor δ₀^d where δ₀ ≈ ((πβ)^(1/β) · β / (2πe))^(1/(2(β−1))). Under the core-SVP model, one call to a β-dimensional sieving oracle costs ≈ 2^(0.292β) classically or ≈ 2^(0.265β) with Grover-accelerated sieving, which directly determines the 128/192/256-bit security margins of LWE/MLWE parameter sets.

BMI2 (Bit Manipulation Instruction Set 2)

BMI2 (Bit Manipulation Instruction Set 2) is an x86_64 CPU instruction extension that accelerates bit-level extraction, deposit, shifting, and wide multiplication.

Programs often need to pull out or rearrange specific bits tucked inside a larger number—for example, unpacking compressed data, calculating chess moves, or running cryptography. Normally a processor has to do that with several slow steps of masking and shifting. BMI2 adds dedicated hardware shortcuts to the CPU so it can pluck out or rearrange those bits in a single step.

BMI2 was introduced with Intel Haswell (2013) and AMD Excavator/Zen, and it is a mandatory part of the x86-64-v3 microarchitecture baseline used by modern Linux distributions and toolchains. You can check whether your CPU supports it by running lscpu or searching /proc/cpuinfo for bmi2, and compile for it with -mbmi2 or -march=x86-64-v3. One famous caveat: on AMD Zen 1 and Zen 2 CPUs, PDEP and PEXT were implemented in slow microcode (~18+ cycles) rather than dedicated hardware, so some libraries avoided them until Zen 3 introduced full-speed execution.

Why might a binary compiled with -march=x86-64-v3 fail to run on a 2011 Sandy Bridge CPU?

The x86-64-v3 feature level requires BMI2 (along with AVX2 and FMA), which did not exist on Sandy Bridge; executing a BMI2 instruction on an older CPU raises an invalid opcode (SIGILL) crash.

BMI2 (CPUID.(EAX=07H, ECX=0):EBX[bit 8]) adds VEX-encoded 32/64-bit instructions: PEXT (parallel bit extract) and PDEP (parallel bit deposit) using a bitmask, BZHI (zero high bits starting at bit index), MULX (unsigned multiply without modifying RFLAGS, enabling parallel carry chains alongside ADCX/ADOX in big-integer/ECC arithmetic), RORX (non-destructive rotate), and flagless shifts (SARX, SHLX, SHRX). Flagless shifts and MULX reduce false register dependencies on CF/OF in out-of-order pipelines, while hardware PEXT/PDEP execute in 3 cycles with 1-cycle throughput on Intel Haswell+ and AMD Zen 3+.

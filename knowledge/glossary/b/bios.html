BIOS - Basic Input/Output System

BIOS (Basic Input/Output System) is the traditional PC firmware interface that initializes hardware at power-on and hands control to an operating system bootloader.

When you press a computer’s power button, the main operating system is still sitting asleep on the disk and cannot load itself. BIOS is a tiny built-in startup program stored on a chip on the motherboard. It wakes up the screen, keyboard, and drives, checks that basic parts are working, and then reads the very first piece of the disk to start the operating system.

Legacy BIOS boots by reading the 512-byte Master Boot Record (MBR) from the first sector of the chosen disk into memory and executing it in 16-bit real mode. On modern PCs and Linux systems, BIOS has largely been replaced by UEFI, though many UEFI boards include a Compatibility Support Module (CSM) to boot legacy MBR disks. You can tell how a running Linux system booted by checking whether /sys/firmware/efi exists: if it is present, the system booted via UEFI; if absent, it booted via legacy BIOS (or CSM).

What is a practical limitation of legacy BIOS MBR booting compared to UEFI?

Legacy BIOS relies on the MBR partition table, which uses 32-bit sector addresses and therefore cannot address disks larger than 2 TiB (with 512-byte sectors) and supports at most four primary partitions, whereas UEFI natively uses GPT with 64-bit LBA addressing.

After the Power-On Self-Test (POST) and option-ROM initialization, BIOS loads the 512-byte MBR (signature 0x55AA) to physical address 0x7C00 and jumps to it with the CPU in 16-bit x86 real mode (1 MiB addressable space, segmented addressing) and A20 disabled. Bootloaders like GRUB Stage 1/1.5 or Syslinux must invoke real-mode software interrupts (such as INT 13h for disk I/O and INT 15h E820h for the physical memory map) before switching the processor to 32-bit protected mode and 64-bit long mode. Unlike UEFI, legacy BIOS provides no standardized cryptographic boot verification (Secure Boot), no native filesystem drivers, and no runtime firmware services once the OS takes over hardware interrupts.

Binary

Binary is a base-2 number system that represents all values using only two digits: 0 and 1.

We count in tens because we have ten fingers, using digits 0 through 9. Computers do not have fingers—they are built from billions of tiny electrical switches that are either off (0) or on (1). Binary is simply the language of counting with just those two states, which lets hardware store numbers, letters, pictures, and programs reliably even when electrical signals vary slightly.

In base-2 positional notation, each column from right to left represents a power of two (1, 2, 4, 8, 16, …), so the binary number 1011 equals 8 + 0 + 2 + 1 = 11 in decimal. On Linux, you regularly encounter binary-aligned sizes and permissions: file mode bits (like 0755 = 111 101 101 in binary for rwxr-xr-x), IPv4 netmasks (like /24 = 24 leading 1s), and powers-of-two memory sizes (KiB = 2^10 = 1024 bytes, contrasted with decimal KB = 1000 bytes). Hexadecimal (base 16) is used as a compact shorthand because each hex digit maps cleanly to exactly four binary digits.

Why do programmers and Linux tools often display binary data in hexadecimal instead of raw 0s and 1s?

Raw binary strings are long and error-prone to read, whereas one hexadecimal digit (0–F) represents exactly four bits (a nibble). A 32-bit value takes 32 binary digits but only 8 hex digits, preserving bit boundaries without losing precision.

In base-2 arithmetic, an unsigned k-bit word represents integers in [0, 2^k − 1], while signed integers on modern CPUs use two’s complement ([−2^(k−1), 2^(k−1) − 1]), where negation is bitwise inversion plus one (~x + 1) and addition/subtraction share identical ALU hardware regardless of sign. Non-integer values use IEEE 754 binary floating-point (sign, biased exponent, implicit-leading-1 significand), which cannot represent common base-10 fractions such as 0.1 exactly (0.1₁₀ = 0.0001100110011…₂), causing rounding drift in financial or equality checks unless decimal or fixed-point types are used. Endianness (little-endian on x86_64/ARM64 vs. big-endian network byte order) governs how multi-byte binary words are laid out across byte-addressed memory.

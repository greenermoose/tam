BOM (Bill of Materials / Byte Order Mark)

BOM refers either to a Bill of Materials (a structured inventory of hardware parts or software dependencies, often called an SBOM) or to the Unicode Byte Order Mark (U+FEFF) at the start of a text file.

The acronym BOM has two very different meanings in technology. In engineering and security, a Bill of Materials is like the ingredients list on a food label: it lists every part in a device or every third-party code library inside a program so you know what you are running. In text files, a Byte Order Mark is an invisible marker placed at the very start of a file to tell text editors how the characters are encoded.

In Linux and DevOps, an SBOM (Software Bill of Materials) is generated in formats like SPDX or CycloneDX so security teams can quickly check which containers or packages contain a vulnerable library (such as Log4j or OpenSSL). By contrast, a UTF-8 Byte Order Mark (the three bytes EF BB BF) is common in Windows CSV exports but is usually discouraged on Linux because it can break shell scripts (#! shebang lines fail if EF BB BF precedes #!) and confuse CLI parsers. You can strip a UTF-8 BOM in place with sed -i '1s/^\xEF\xBB\xBF//' file.txt.

Why does a UTF-8 BOM at the start of a shell script cause "No such file or directory" or syntax errors on Linux?

The Linux kernel checks the very first two bytes of an executable script for the #! magic bytes; if the three-byte UTF-8 BOM (EF BB BF) appears before #!, the kernel fails to recognize the shebang interpreter.

For supply-chain provenance, CycloneDX (OWASP/ECMA-424) and SPDX (ISO/IEC 5962) encode component graphs, PURLs (Package URLs), CPEs, cryptographic hashes, and VEX vulnerability status, integrating with SLSA attestations and container registries (e.g., Syft/Cosign). For text encoding, Unicode U+FEFF signals endianness in UTF-16 (FE FF big-endian vs. FF FE little-endian) and UTF-32 (00 00 FE FF vs. FF FE 00 00); RFC 3629 §6 notes that UTF-8 has no byte-order ambiguity and advises against emitting a UTF-8 BOM unless required by legacy protocols.

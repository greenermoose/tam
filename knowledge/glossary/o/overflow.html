Guide / Glossary A-Z / Terms beginning with O / Overflow

Overflow happens when arithmetic produces a value beyond the range a number format can hold.

An eight-bit counter has room up to 255. If you add one more, the stored result cannot be 256. Something must give: the counter wraps, stops at the top, or reports an error.

In unsigned eight-bit arithmetic, 255 plus 1 wraps to 0. In signed eight-bit two's complement, 127 plus 1 wraps to -128. Floating-point overflow usually produces infinity under the default rule. Languages differ: some define wrapping, some define saturation, and some say signed overflow is an error with unpredictable consequences.

Why can overflow be dangerous in a program that adds lengths?

A wrapped length can become small or negative, so a later check may read past a buffer or allocate too little memory. Range checks and wider accumulator types prevent the bad value from reaching that point.

Hardware typically reports overflow in a status flag and keeps the low bits of the result. Compilers may exploit language rules to optimize on the assumption that signed overflow never occurs. Floating-point overflow can raise an exception flag and, with traps enabled, stop the program; the default IEEE 754 result is a correctly signed infinity. Guard against overflow with checked arithmetic, wider intermediate types or explicit saturation, and distinguish it from underflow at the other end of the range.

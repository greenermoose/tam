Option

A command-line option is a flag or parameter passed to a program when you run it to change how it behaves.

If typing a command like ls is like ordering a cup of coffee, an option is the extra instruction you add—such as “iced” or “decaf”—to change how it is prepared. In the terminal, options usually start with one or two dashes, like -l or --all, so the program knows you are giving it a setting rather than a file name.

Most Linux tools follow POSIX and GNU conventions: short single-letter options use one dash (-a, often combined like -la), while descriptive long options use two dashes (--all or --color=auto). Options are distinct from operands (the target files or inputs). If a filename itself begins with a dash—say -notes.txt—passing -- tells standard utilities to stop reading options and treat everything afterward as a filename.

What does a standalone -- do in a Linux command line?

It marks the end of options, telling the command to treat any following arguments (even ones starting with a dash) strictly as positional operands such as filenames.

Command-line options are parsed from the process argv vector, conventionally via POSIX getopt() or GNU getopt_long(), which support option bundling, required/optional arguments, and (unless POSIXLY_CORRECT is set) argument permutation. Failing to separate options from operands creates option-injection vulnerabilities in shell scripts and automation: an untrusted filename starting with - expanded by an unguarded glob (e.g., rm *) can be interpreted as a destructive flag unless guarded with -- or a path prefix such as ./*.

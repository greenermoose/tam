Guide / Glossary A–Z / Terms beginning with O / OpenType

A scalable font format that stores letter outlines together with rules for shaping text.

An OpenType font is a file that tells a computer how to draw letters at any size. It can hold the simple curved outlines used by TrueType or the PostScript-style outlines known as CFF. It also carries extra instructions: when two letters should join, where accents belong, and which shapes to use for a particular language. The same file can therefore serve a book, a web page and a terminal that understands it.

You meet OpenType whenever you choose an .otf or a modern .ttf font. Both can be OpenType fonts; the extension alone does not tell you which outline style is inside. fc-query and ttx -l show the tables in a file, so you can see whether it uses glyf or CFF outlines and whether it has shaping tables. A font without those tables can still draw plain Latin text but cannot correctly join Arabic letters or place Indic vowel signs.

Why can two fonts both be called OpenType but need different rendering code?

OpenType is a container. One font may hold quadratic TrueType outlines in glyf and another cubic CFF charstrings; a rasterizer must understand the outline language actually present, even though the surrounding tables share the same format.

OpenType is built on the sfnt container: a table directory followed by named tables. Required tables include head, hhea, hmtx, maxp, cmap, name, OS/2 and post. Outlines live in glyf with loca offsets, or in CFF / CFF2 charstrings. Layout is described by GSUB for substitutions such as ligatures, GPOS for positioning and kerning, and GDEF for glyph classes. Variable fonts add fvar, gvar, avar and variation metrics; color fonts add COLR/CPAL or bitmap image tables. A cmap maps a code point to a glyph identifier; shaping runs before rasterization decide which glyph identifiers are actually drawn.

The specification is maintained by Microsoft and Adobe, and the Open Font Format standard (ISO/IEC 14496-22) is based on it. A font may carry a DSIG signature, but conversion and subsetting can remove it. Support is not uniform: a table can be present while an application's shaping engine ignores it.

Operating system

An operating system (OS) is the foundational software that manages a computer’s hardware and provides the environment in which applications run.

Imagine a theater production: the actors—your web browser, text editor, or music player—focus on their own performance, while the stage manager and crew control the lights, sound, and doors so nobody trips over anyone else. An operating system plays that behind-the-scenes role on a computer, sharing the processor, memory, screen, and storage safely among all your programs.

A Linux distribution is more than the Linux kernel alone: it pairs the kernel (which handles hardware drivers, scheduling, and memory) with core user-space software such as the C library, an init system like systemd, a shell, and system utilities. Knowing that boundary helps when troubleshooting: hardware and driver errors appear in kernel logs (dmesg), whereas service or application crashes are tracked in user-space logs (journalctl).

Why is the Linux kernel alone not considered a complete operating system by most users?

The kernel manages hardware, processes, and memory, but users and apps also rely on user-space components—such as the C library, shell, init system, and core utilities—to boot, log in, and run software.

At the architectural level, an operating system enforces privilege separation between kernel space (ring 0 / EL1) and unprivileged user space (ring 3 / EL0), exposing hardware resources through a stable system-call ABI, per-process virtual address spaces, preemptive scheduling, and a Virtual File System (VFS). The exact boundary of “operating system” varies by design: monolithic kernels like Linux keep drivers, filesystems, and networking in kernel space for low-overhead calls, whereas microkernels push those subsystems into isolated user-space servers at the cost of IPC overhead.

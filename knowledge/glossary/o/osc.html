Guide / Glossary A–Z / Terms beginning with O / OSC (Operating System Command)

OSC (Operating System Command) is a terminal escape sequence starting with ESC ] that lets a program send metadata or control requests to the terminal emulator itself.

Normally, when a program prints text in a terminal, every character appears inside the grid of letters on your screen. An OSC sequence is like a quiet side note addressed to the terminal window itself—for example, “change the window title bar to ‘Build complete’” or “make this text a clickable link”—so the terminal updates its own interface without cluttering your screen with codes.

An OSC sequence starts with ESC ], carries a numeric code and text payload, and ends with BEL (0x07) or ST (ESC \). You encounter OSC sequences in everyday Linux workflows: shells use OSC 0 or OSC 2 to update the window title, tools like ls --hyperlink and ripgrep emit OSC 8 for clickable links, and OSC 52 lets remote programs over SSH copy text into your local clipboard.

Why is OSC 52 useful when working over SSH?

A remote program on another machine cannot access your local desktop clipboard directly. By emitting an OSC 52 escape sequence, it asks your local terminal emulator to place the encoded text onto your local clipboard.

Defined in ECMA-48, an Operating System Command uses the 7-bit introducer ESC ] (0x1B 0x5D) or 8-bit C1 byte 0x9D and is terminated by String Terminator (ESC \ / 0x9C) or legacy BEL (0x07). Security is a primary concern: if a terminal permits unrestricted OSC 52 clipboard reads, printing untrusted text (e.g., catting a crafted file or log) can silently exfiltrate clipboard contents, and unrestricted palette/title queries can leak state. Modern terminals therefore disable OSC 52 reads by default, while multiplexers such as tmux require explicit passthrough configuration to forward OSC sequences.

Opcode (operation code)

An opcode (operation code) is the part of a machine-language instruction that specifies which operation the processor should perform.

Think of a recipe step like “chop 2 onions” or “bake for 20 minutes.” The action verb—chop or bake—tells you what to do, while “2 onions” or “20 minutes” tells you what to do it to. Inside a CPU, an opcode is that action verb in binary form: it tells the processor whether to add two numbers, move data, or jump to another part of a program.

When you inspect compiled code on Linux with a disassembler like objdump -d, each instruction shows raw hexadecimal bytes alongside a readable mnemonic (such as add, mov, or jmp) and its operands (registers, constants, or memory addresses). Fixed-width RISC architectures like AArch64 and RISC-V place the opcode in consistent bit positions for simple decoding, whereas variable-length CISC architectures like x86-64 pack prefixes, one- to three-byte opcodes, and operand-specifier bytes together.

In a machine instruction, what is the difference between the opcode and the operands?

The opcode names the action the CPU must execute (such as add or load), while the operands specify the data, registers, or memory addresses that the action operates on.

An opcode is the primary operation-selection field of an instruction word, decoded by the CPU’s front-end decode stage via hardwired combinational logic or a microcode ROM sequencer. On x86-64, instruction decoding must parse variable-length legacy/REX/VEX/EVEX prefixes, escape bytes (0x0F, 0x0F 0x38), ModR/M, and SIB fields; on RISC-V, a 7-bit major opcode combines with funct3/funct7 subfields inside a fixed 32-bit word. Encountering an unrecognized or disabled opcode raises an invalid-instruction exception (#UD on x86, illegal-instruction trap on ARM/RISC-V), which the Linux kernel delivers to user space as SIGILL.

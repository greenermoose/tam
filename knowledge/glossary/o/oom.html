Guide / Glossary A–Z / Terms beginning with O / OOM (Out of Memory)

OOM (Out of Memory) is the condition when a system runs out of usable RAM and swap space, forcing the operating system to terminate a process so the rest of the system can keep running.

Think of RAM as your computer’s workbench: every open app spreads its work out on the table. If too many programs pile onto the bench until there is not even an inch of space left to move, the whole computer can freeze. When that happens, Linux steps in like a shop manager and closes one big, memory-hungry program so the rest of the system can recover.

On Linux, virtual memory overcommit means programs can request more memory than physical RAM holds, and real pages are only allocated when touched. When RAM fills up, the kernel first swaps or drops clean file caches; compressed in-RAM swap (zram) buys extra breathing room without hitting slow disks. Because waiting until the very last byte can leave a desktop frozen in swap thrashing, systemd-oomd watches Pressure Stall Information (PSI) and stops a runaway cgroup early before the kernel OOM killer has to strike.

Why do modern Linux desktops use systemd-oomd or zram instead of relying only on the kernel OOM killer?

The kernel OOM killer only triggers after memory and swap are exhausted, by which time heavy disk thrashing may already have frozen the desktop. PSI-based tools like systemd-oomd act earlier on memory pressure, and zram compresses pages in RAM to delay exhaustion.

Kernel OOM occurs when page-frame reclamation in __alloc_pages_slowpath() fails to satisfy an allocation, invoking out_of_memory() in mm/oom_kill.c (or cgroup v2 memory.max enforcement). Victim selection ranks tasks by oom_score—reflecting RSS, swap usage, and page-table size—biased by user-configurable oom_score_adj (-1000 to +1000, where -1000 exempts critical daemons), and can kill an entire cgroup atomically when memory.oom.group is set. Under heavy anonymous-page thrashing, the kernel can livelock without hitting strict allocation failure; systemd-oomd avoids this by monitoring cgroup v2 memory.pressure (PSI some/full stalls) and proactively sending SIGKILL to offending units.

Guide / Glossary A–Z / Terms beginning with D / D-Bus

D-Bus is a message bus used on Linux desktops so that programs can find each other and exchange small messages without sharing a private connection.

When one part of the desktop asks another to do something, it can send a message to the bus instead of opening a direct link. The bus passes the message to the service that owns the matching name. This is how a panel can ask a settings service for a value, for example.

A bus here is a shared communication path, not a wire on a circuit board. A system bus carries session-wide services such as power and network state; a session bus carries services for one logged-in user. The names and objects on each bus are well known, so a client does not need to know a service's process ID.

D-Bus defines object paths, interfaces, methods, properties and signals; messages carry a typed body. freedesktop.org specifications describe the bus and the higher-level interfaces layered on it. Access policy is enforced by the bus daemon, including who may own a name and who may send to it. Authentication and encryption are separate questions from the transport: a desktop message bus is a local IPC mechanism, not an end-to-end content protection system.

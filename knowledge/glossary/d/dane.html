Guide / Glossary A–Z / Terms beginning with D / DANE (DNS-based Authentication of Named Entities)

DANE lets a domain owner publish the TLS key that a service should use, protected by DNSSEC.

The letters stand for DNS-based Authentication of Named Entities. Instead of trusting only a certificate authority, a client can also check a signed note in DNS that says which key belongs to the mail server.

For SMTP, the note is a TLSA record at a name such as _25._tcp.mail.example.com. A sender's mail server checks the record after validating DNSSEC. If the record is bogus or the key does not match, delivery must stop rather than fall back quietly.

RFC 6698 defines DANE TLSA records and RFC 7672 applies them to SMTP. DANE depends on a validated DNSSEC chain of trust, unlike MTA-STS, which uses an HTTPS policy and a DNS signal. DANE and MTA-STS are alternative or complementary ways to enforce TLS, not mere encryption hints.

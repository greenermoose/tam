Guide / Glossary A–Z / Terms beginning with D / DHCP (Dynamic Host Configuration Protocol)

The network protocol that automatically assigns IP addresses and basic network settings to devices joining a network.

When your laptop connects to home or coffee-shop Wi-Fi, you do not have to type in a numeric network address by hand. DHCP acts like a hotel front desk: your device asks for a room, and the router hands it a temporary IP address along with the directions it needs to reach the internet.

A DHCP server leases an IPv4 address for a limited time and bundles options such as the subnet mask, default gateway, and DNS servers. On Linux, clients like NetworkManager, systemd-networkd, or dhcpcd renew the lease automatically at half the lease duration (T1); you can inspect the active address and route with ip addr and ip route.

What happens if a DHCP server goes offline while a client’s lease is still active?

The client keeps using its leased IP address until the lease expires, attempting to renew at T1 and rebind at T2 before losing the address.

A BOOTP-derived UDP protocol (ports 67/68 for IPv4; RFC 2131) using the four-step DORA exchange (Discover, Offer, Request, Acknowledge) and DHCP relay agents (giaddr, Option 82) across routed subnets. Operational failure modes include rogue DHCP servers on L2 segments, broadcast-filtering misconfigurations, and pool exhaustion; IPv6 uses SLAAC (ICMPv6 RA) and/or DHCPv6 (UDP 546/547) governed by RA M/O flags.

Guide / Glossary A–Z / Terms beginning with D / DC4 (Device Control 4, 0x14)

DC4 (Device Control 4) is an ASCII control code (0x14, typed with Ctrl+T) originally reserved for hardware device control, and commonly used in terminals to swap adjacent characters or query process status.

Like DC2, DC4 was one of four general-purpose "device control" codes in early ASCII for operating attached hardware. On a modern Linux command line, pressing Ctrl+T sends this code to swap two adjacent letters—handy for fixing a quick typo—while on some Unix systems it asks a running program for a progress update.

Part of the C0 control codes, DC4 (Ctrl+T) was reserved for hardware-specific control. In Bash and Readline it runs transpose-chars, whereas on BSD and macOS terminals Ctrl+T also triggers VSTATUS (SIGINFO) to print a status line for the foreground job—a feature Linux terminals do not implement natively.

What happens when you press Ctrl+T at a Bash prompt on Linux versus while running a command on BSD?

At a Bash prompt, Readline receives byte 0x14 and swaps the two characters before or under the cursor (transpose-chars). On BSD/macOS, the TTY driver also maps Ctrl+T (VSTATUS) to SIGINFO, printing a one-line status summary for the foreground process, which Linux omits.

ASCII 0x14 (DC4, ^T), an ECMA-48 C0 control character with no standardized ISO/IEC 6429 semantics. Linux’s termios (asm-generic/termbits.h) defines no VSTATUS entry in c_cc and lacks SIGINFO, contrasting with 4.4BSD-derived kernels where VSTATUS defaults to 0x14. In non-canonical line-editor input loops (GNU Readline, libedit, Emacs), 0x14 passes directly to user space and binds to character transposition unless intercepted by a terminal multiplexer prefix.

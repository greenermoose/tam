DLE (Data Link Escape, 0x10)

DLE (Data Link Escape, ASCII 0x10) is a non-printing control character historically used in serial protocols to mark that the next byte is raw data rather than a framing command.

Imagine talking on a two-way radio where saying "over" ends your message. If you actually need to say the word "over" inside a sentence, you need a signal that means "take the next word literally." On older serial links, DLE was that signal—telling the receiver not to treat the next byte as a special command.

Part of the C0 control codes at hexadecimal 0x10 (decimal 16), DLE corresponds to typing Ctrl+P on a keyboard. In modern Linux shells using GNU Readline (such as bash in default Emacs mode), pressing Ctrl+P invokes previous-history to recall your last command rather than escaping serial bytes.

Why does pressing Ctrl+P in a Linux terminal shell recall your previous command even though 0x10 is named Data Link Escape?

Terminal line disciplines and Readline assign interactive editing actions to ASCII control bytes; in Emacs-mode Readline, 0x10 (Ctrl+P) is bound to previous-history instead of link framing.

ASCII 0x10 (^P). In character-oriented protocols such as IBM BISYNC, transparent binary mode enters via DLE STX and exits via DLE ETX; any literal 0x10 in the payload is byte-stuffed as DLE DLE so arbitrary binary data cannot prematurely close a frame. Later async framing standards (HDLC/PPP over serial) replaced DLE with 0x7E frame flags and 0x7D escape octets (XORing escaped bytes with 0x20).

Desktop environment

A complete graphical desktop built from several coordinated components.

When you turn on a computer and see a wallpaper, a taskbar, icons, a file browser, and a settings app that all look and work together, you are using a desktop environment. Think of it as a furnished apartment: instead of buying a bare room and picking out every lamp and chair yourself, everything is already arranged in one matching style.

A desktop environment (such as GNOME, KDE Plasma, or Xfce) bundles a display server integration (Wayland compositor or X11 window manager), a panel or shell, a settings daemon, notification handling, and core utilities. By contrast, a standalone window manager or compositor handles only window placement and keybindings, leaving you to assemble bars, launchers, and automounting separately.

What is the practical difference between installing a desktop environment and installing only a window manager?

A desktop environment provides integrated settings, notifications, power management, and default apps out of the box, whereas a standalone window manager only manages windows and requires you to configure those services yourself.

An integrated user-session stack spanning a Wayland compositor (or X11 WM and compositor), shell UI, D-Bus-activated settings and power daemons (e.g., systemd --user units, xdg-desktop-portal backends for sandboxed file and screen-share access), Polkit authentication agents, and a shared toolkit/icon theme. Portal and D-Bus interface mismatches—rather than window rendering—are the typical failure mode when mixing components across environments.

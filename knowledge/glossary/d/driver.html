Driver

Software that allows an operating system kernel to communicate with and control a specific piece of hardware.

Your operating system knows how to draw windows and save files, but every printer, Wi-Fi chip, and graphics card speaks its own internal dialect. A driver acts like a translator: it turns the operating system’s general requests (“send this packet,” “read this disk block”) into the exact signals that particular hardware model expects. Without the right driver, a device may plug in physically but remain unusable.

On Linux, most hardware drivers live directly inside the kernel—either compiled in or loaded on demand as kernel modules (.ko files)—rather than requiring separate downloads from hardware vendors. You can see which driver is bound to a PCI or USB device with lspci -k or lsusb -t, and check loaded modules with lsmod. Some devices (like many printers via CUPS or scanners via SANE) also rely on user-space drivers that talk over generic kernel USB/network interfaces.

What command can you run on Linux to see which kernel driver is currently bound to your Wi-Fi or graphics card?

lspci -k lists PCI devices alongside the kernel driver in use and available kernel modules for each device.

In the Linux kernel device model, a struct device_driver registers with a bus subsystem (PCI, USB, platform, I2C) and binds to a matching struct device via vendor/device ID tables or Devicetree/ACPI compatible strings, invoking probe(). Kernel-space drivers run in ring 0, mapping MMIO/PIO register apertures (ioremap), allocating DMA buffers via the DMA API, registering IRQ handlers (top-half/threaded bottom-half), and exposing standard subsystem abstractions (such as net_device, blk_mq_ops, or drm_driver) to user space through /dev, /sys, or netlink.

DHE (Ephemeral Diffie-Hellman)

A key exchange method that generates fresh temporary Diffie-Hellman keys for every session to provide forward secrecy.

If two people reused the same secret lockbox key for years, anyone who eventually stole that key could unlock all their recorded messages from the past. Ephemeral Diffie-Hellman (DHE) creates a brand-new, throwaway session key for every single conversation and erases it afterward, so past traffic stays safe even if a server’s long-term key leaks later.

In TLS, you will see key-exchange groups labeled DHE (finite-field) or ECDHE (elliptic-curve). Unlike older static RSA key exchange—where leaking the server’s private key decrypted captured traffic—TLS 1.3 requires ephemeral key exchange (most commonly X25519 or P-256 ECDHE) so every connection has forward secrecy.

Why does TLS 1.3 require ephemeral key exchange instead of static RSA key transport?

Static RSA lets anyone who later compromises the server’s private key decrypt past recorded sessions, whereas ephemeral key exchange discards session secrets after use.

Ephemeral Diffie-Hellman signs freshly sampled per-session key shares with the server’s long-term identity key to authenticate the handshake while preserving forward secrecy. Finite-field DHE (standardized named groups in RFC 7919 to defeat precomputation and Logjam-style attacks) has largely been superseded in TLS 1.3 by ECDHE (X25519, P-256) because ~128-bit security requires 3072-bit primes in FFDHE versus 256-bit curve elements.

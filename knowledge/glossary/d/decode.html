Decode

Decode is the process of translating an encoded instruction, byte sequence, or compressed signal back into a form that hardware or software can act on.

Decoding is like reading a recipe written in shorthand and turning it back into plain steps. Inside a computer, it happens both when the processor reads raw binary instructions to see what work to do, and when a media player unpacks a compressed video file back into pictures on your screen.

In Linux and hardware, decode appears in two main contexts: CPU instruction decoding (turning machine-code opcodes and operands into execution steps) and data or media decoding (such as decoding UTF-8 bytes into text, Base64 into binary, or H.264/AV1 video into pixel frames). Offloading video decode to the GPU via VA-API or NVDEC keeps CPU usage and battery drain much lower than software decoding.

What is the difference between CPU instruction decoding and video decoding?

CPU instruction decoding happens inside the processor pipeline every clock cycle to turn machine-code bytes into internal control signals. Video decoding is an application or GPU workload that decompresses a video bitstream back into raw pixel frames for display.

In CPU microarchitecture, decode sits between fetch and rename/issue: fixed-width ISAs (AArch64, RISC-V) extract opcode and register fields in parallel, whereas variable-length ISAs (x86-64, 1–15 bytes with legacy/REX/VEX/EVEX prefixes) suffer serial length-decoding bottlenecks mitigated by L1I predecode bits and a decoded μop cache (DSB); invalid encodings raise #UD. In data and codec pipelines, decoding must validate canonical forms (such as rejecting overlong UTF-8 or malformed bitstreams) to prevent parser-differential vulnerabilities.

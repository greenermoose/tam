Development prefix

A user-owned directory used to hold temporary test installs without affecting the rest of the system.

When someone is testing a new version of a program, they do not want to overwrite the working copy everyone else relies on. A development prefix is a private sandbox folder inside your own home directory where test builds can live safely—like trying out a new recipe on a side plate before putting it on the dinner table.

On Tamlinux, development builds use the user prefix ~/.local, with executables in ~/.local/bin and libraries in ~/.local/lib. That directory comes before system directories on PATH, so your shell picks up test builds first without needing root privileges. Every released Tamlinux version is installed under /usr/bin and /usr/lib. Once the release is deployed, remove the development build so old test binaries do not silently shadow the real ones.

What happens if you forget to remove a test binary from your development prefix after deploying a release?

Because the development prefix sits earlier on PATH, your shell keeps running the stale test binary instead of the newly deployed release.

An unprivileged install root (e.g., ~/.local) with its own bin/, lib/, include/ and generation layout, isolated from system-wide roots and package-managed stores. Relying on PATH or LD_LIBRARY_PATH precedence introduces shadowing and ABI-skew risks if left active after promotion, so teardown is part of the release lifecycle.

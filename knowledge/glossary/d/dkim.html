Guide / Glossary A–Z / Terms beginning with D / DKIM (DomainKeys Identified Mail)

DKIM lets a sending domain sign a message so a receiver can verify that it was not changed in transit.

The letters stand for DomainKeys Identified Mail. The sender adds a signed seal to the message. The receiver looks up the sender's public key in DNS and checks that the seal still fits.

The signature lives in a DKIM-Signature header. The d= field names the signing domain and s= names the selector. The public key is a TXT record at selector._domainkey.domain.

RFC 6376 defines DKIM. Signatures cover selected header fields and a hash of the body, so an intermediary may add trace headers without breaking the signature if those fields are not signed. A valid signature shows responsibility by a domain; it does not say that the visible From: domain signed, which is why DMARC alignment matters.

Guide / Glossary A–Z / Terms beginning with D / DSIG (Digital Signature)

DSIG is an optional OpenType table that stores a cryptographic signature for a font.

A DSIG table is like a sealed label on a font file. It can help confirm that a font has not been altered since someone signed it, much like a tamper-evident seal on a package.

The table is defined in the OpenType specification but is rarely used in practice; most fonts distributed on Linux are not digitally signed. Browsers and desktop font loaders generally do not validate DSIG, so it is not a security boundary. If a font is signed, verification depends on the signer's certificate chain and on tools that actually check it.

The four-byte tag is DSIG; the table contains a header and signature records with format, key and signature data, typically a PKCS#7-style blob over the font's binary content. Because signing covers the whole file, any later edit—including subsetting, hinting changes or table reordering—invalidates it. The OpenType specification treats DSIG as deprecated for new fonts; package signatures and HTTPS carry modern distribution trust.

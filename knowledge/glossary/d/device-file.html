Device file

A special file in the filesystem that represents a hardware device or kernel service.

Linux treats hardware—like keyboards, hard drives, and printers—as if they were files inside the /dev folder. That lets ordinary programs read from a microphone or write to a USB stick using the same basic open, read, and write steps they already use for normal documents, without needing to know the hardware’s wiring details.

In ls -l /dev, device files start with c (character devices, which stream bytes one at a time, like /dev/tty0 or /dev/urandom) or b (block devices, which transfer fixed-size blocks and support random access, like /dev/nvme0n1). Instead of a file size, the listing shows two numbers—major and minor—that tell the kernel which driver and specific device instance to use.

Why does ls -l /dev/sda show two comma-separated numbers instead of a byte size?

Those are the major and minor device numbers: the major number identifies the kernel driver, and the minor number identifies the specific drive or partition handled by that driver.

An inode of type S_IFCHR or S_IFBLK holding a dev_t (major/minor pair) rather than data extents. On open(2), the VFS dispatches through chrdev_open or blkdev_open to bind the driver’s file_operations or block_device_operations struct; modern systems populate /dev dynamically via devtmpfs and udev rules that manage ownership, permissions, and persistent symlinks such as /dev/disk/by-uuid/.

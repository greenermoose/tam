Guide / Glossary A–Z / Terms beginning with D / DNS - Domain Name System

The distributed directory that translates human-readable domain names into IP addresses and other network records.

Computers find each other on the internet using numeric addresses, much like phone numbers, which are hard for people to remember. DNS works like a global address book: when you type a name such as example.com into your browser, your device asks a DNS server for the matching number so it knows where to send your request. Because this lookup happens automatically in the background, you can use memorable names instead of memorizing long strings of numbers.

On a Linux system, applications typically call the C library resolver (getaddrinfo), which consults /etc/hosts and local stub resolvers such as systemd-resolved before querying an upstream recursive resolver. That recursive resolver walks the hierarchy—root servers, top-level domain (.com) servers, and the domain’s authoritative nameservers—and caches answers according to each record’s Time to Live (TTL). You can inspect individual record types (A, AAAA, MX, TXT) directly with dig or resolvectl query, bypassing or observing local caches.

Why might a change to a domain’s IP address not take effect immediately for all users?

Recursive resolvers and client stub resolvers cache DNS answers for the duration of the record’s TTL (Time to Live). Until that cached timer expires, resolvers continue returning the old IP address instead of querying the authoritative server again.

Defined in RFC 1034 and RFC 1035, DNS uses a delegated tree of zones where each zone’s authoritative servers publish resource record sets (RRsets). Queries default to UDP port 53 (with EDNS0 advertising larger UDP payload sizes, typically 1232 bytes to avoid IP fragmentation), falling back to TCP port 53 when the TC (truncated) bit is set or for zone transfers (AXFR/IXFR). Modern deployments add encrypted transports—DoT (DNS over TLS, port 853) and DoH (DNS over HTTPS, port 443)—to prevent on-path eavesdropping, while DNSSEC adds cryptographic signatures to authenticate answers without encrypting them.

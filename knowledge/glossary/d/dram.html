DRAM - Dynamic Random-Access Memory

The high-density, volatile memory technology used for main system RAM, which stores each bit as an electrical charge that must be periodically refreshed.

When you open programs, your computer loads them into RAM so the processor can reach them quickly. DRAM is the specific kind of chip used for that main memory. Each tiny cell in DRAM holds a bit of data like a leaky bucket holding water: the charge slowly drains away, so the computer has to top up (“refresh”) every cell thousands of times per second—and when you cut the power, everything in DRAM disappears.

DRAM trades raw speed for capacity and low cost per gigabyte. Inside the CPU, ultra-fast caches use SRAM (static RAM), which needs 6 transistors per bit and never needs refreshing; main memory sticks (DDR4, DDR5) use DRAM, which needs only one transistor and one capacitor per bit (1T1C). On Linux, tools like dmidecode -t memory or free -h show your installed DRAM capacity and speed, while the kernel’s page cache uses spare DRAM to speed up file reads.

Why do CPUs use SRAM for L1/L2 caches instead of DRAM, even though DRAM is much cheaper?

SRAM does not require capacitor charging or periodic refresh cycles, so it responds in a few clock cycles, whereas DRAM access takes tens of nanoseconds due to row activation and sensing delays.

A 1T1C DRAM cell stores charge on a trench or stacked capacitor accessed through a wordline transistor onto a bitline; reading is destructive, requiring sense amplifiers to restore the row’s charge after sensing. Memory is organized into channels, ranks, bank groups, banks, rows, and columns. Because leakage degrades stored charge, JEDEC DDR specifications mandate periodic REF commands (typically every tREFI = 7.8 microseconds in DDR4, or 3.9 microseconds in DDR5, across a 64 ms / 32 ms retention window) to refresh all rows. High-density cells are susceptible to Rowhammer disturbance errors, mitigated in modern hardware via Target Row Refresh (TRR) and ECC.

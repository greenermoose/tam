DEFLATE

DEFLATE is a lossless data compression algorithm (RFC 1951) that combines LZ77 pattern matching with Huffman coding, used in gzip, zlib, ZIP, and PNG.

Lossless compression shrinks a file without losing a single bit, so decompressing it restores the exact original. DEFLATE does this in two steps: first it replaces repeated chunks of text with short "go back and copy" pointers, and then it assigns the shortest bit codes to the most common symbols—like Morse code using a single dot for the letter E.

Standardized in RFC 1951, DEFLATE is the raw compression engine behind several common wrappers: zlib adds a 2-byte header and Adler-32 checksum (used inside PNG images and Git objects), while gzip adds file metadata and a CRC-32 checksum (used for .gz files and HTTP). Combining DEFLATE with secret data over TLS enables CRIME and BREACH side-channel attacks, because compression shrinks repeated guesses and leaks secrets through response size.

How do DEFLATE, zlib, and gzip differ if they all use the same compression algorithm?

DEFLATE is the core RFC 1951 compressed bitstream. zlib wraps it with a minimal header and Adler-32 checksum (used in PNG and Git), while gzip wraps it with filename/timestamp metadata and a CRC-32 checksum for .gz files and HTTP.

RFC 1951 defines a stream of blocks: uncompressed (BTYPE=00, up to 65,535 bytes), fixed Huffman (BTYPE=01), or dynamic Huffman (BTYPE=10, transmitting canonical code-length trees via RLE). LZ77 searches a 32 KiB sliding window for 3–258 byte matches, coding literals (0–255), end-of-block (256), and lengths (257–285 + extra bits) in one alphabet, with distances (0–29 + extra bits) in a second. Trade-offs: fast decoding with ~32 KiB state, but lower compression ratio than Zstandard or LZMA2 due to the 32 KiB window cap and Huffman’s 1-bit-per-symbol floor (lacking fractional-bit ANS/arithmetic coding).

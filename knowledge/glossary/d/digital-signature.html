Digital signature

A digital signature is a cryptographic proof created with a private key and verified with a public key to confirm who produced a message or file and that it has not been altered.

Think of a digital signature like a tamper-evident seal that only one person knows how to stamp, but anyone can inspect. If someone changes even a single letter of a signed file or email, the check fails immediately. This is how your computer verifies that software updates and downloads really came from the publisher and were not modified on the way.

In Linux and everyday security, digital signatures protect package repositories (such as apt or pacman metadata), Git commits, and TLS certificates. Unlike a symmetric MAC, where both sides share the same secret key, a digital signature lets anyone verify authenticity using the signer’s public key without being able to forge a new signature.

Why doesn’t a SHA-256 checksum alone replace a digital signature when downloading a file from a mirror?

A checksum only detects accidental corruption or tampering if you already trust the source of the checksum. If an attacker compromises a mirror, they can replace both the file and its checksum, whereas they cannot forge a digital signature without the publisher’s private key.

Formally an asymmetric (KeyGen, Sign, Verify) tuple targeting EUF-CMA (existential unforgeability under chosen-message attacks), typically built via hash-then-sign or Fiat–Shamir transforms. Modern deployments favor deterministic Ed25519 (RFC 8032) to avoid ECDSA’s catastrophic private-key leakage under nonce reuse or biased RNGs, alongside RSA-PSS and post-quantum NIST standards ML-DSA (lattice-based) and SLH-DSA (stateless hash-based). Real-world failures usually stem from missing canonicalization, weak key-revocation checks, or algorithm-confusion bugs rather than breaking the underlying primitive.

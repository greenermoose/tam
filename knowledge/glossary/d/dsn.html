DSN (Device Serial Number)

An optional PCIe extended capability that gives a hardware device a unique, factory-programmed 64-bit identifier.

Like a car’s VIN stamped onto the frame at the factory, a DSN is a permanent serial number built into a PCIe expansion card or motherboard chip. Even if you move the card to a different slot or computer, that ID stays the same so software can tell identical cards apart.

Unlike a PCI bus/device/function address (such as 0000:03:00.0), which can shift when you move a card or add another NVMe drive, a DSN stays tied to the physical hardware. On Linux, lspci -vv prints the Device Serial Number when the device implements it, which is handy for hardware inventory, udev matching, and RMA tracking.

Why shouldn’t you rely on a PCIe Device Serial Number to identify every PCIe card in a fleet?

DSN is an optional PCIe capability: many budget or embedded devices omit it completely, and some multi-function cards share one DSN across functions or report all-zero placeholder values unless the vendor programmed unique EUI-64s.

Defined in the PCI Express Base Specification as Extended Capability ID 0x0003 in extended configuration space (0x100–0xFFF), DSN consists of a 4-byte capability header followed by Lower and Upper 32-bit registers encoding an IEEE EUI-64 (24-bit OUI/MA-L plus 40-bit extension). The Linux kernel reads it via pci_get_dsn(); inspecting extended config space via lspci -vv requires root privileges when MMCONFIG access is restricted. In virtualization and SR-IOV setups, VFs and VFIO passthrough devices frequently omit or mask capability 0x0003 to avoid leaking host hardware identity across tenants.

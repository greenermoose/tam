Deploy

Deploy means delivering a recorded Tamlinux software assembly onto a machine through the packaging tools, not by copying a checkout by hand.

Instead of dragging loose files from a programmer’s working folder onto your computer, deploying uses an official installer to put a complete, checked bundle in place. That way, everyone knows exactly which version is running, and if something goes wrong, you can step back to the previous working bundle.

On Tamlinux, deployment switches Home Manager generations tied to a locked package assembly using tools such as tam-deploy. Stage moves (Test, Run, Release) follow the developer’s word and recorded digests. When the wrong binary appears on PATH, diagnosis starts by checking path resolution (which or command -v) and assembly status rather than rebuilding from memory.

Why shouldn’t you copy binaries from a development checkout straight into your live session?

Copied binaries bypass the recorded package assembly and its digest, making versions untraceable and breaking clean generation rollbacks.

A Tamlinux deployment activates an immutable, digest-bound package assembly by switching the user’s Home Manager generation atomically. Because stage progression (Test, Run, Release) is gated on explicit approval and recorded digests, reproducing or auditing a session’s software state reduces to inspecting the active generation symlink and assembly manifest rather than host-local mutable state.

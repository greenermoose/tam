DDC - Display Data Channel

DDC (Display Data Channel) is the communication link inside a video cable that lets a computer identify a monitor and adjust settings like brightness or input source.

When you plug in an external monitor, your computer immediately knows its model name and sharpest resolution—and can sometimes dim the screen from software—without you typing anything in. DDC is the quiet two-way channel inside the display cable that lets the computer and monitor exchange that information.

Display Data Channel serves two distinct roles on Linux: reading the monitor’s read-only EDID (supported resolutions and timings) during hotplug, and sending live control commands over DDC/CI (such as brightness or input switching) using tools like ddcutil via /dev/i2c-*. Laptop built-in panels usually skip DDC/CI and use /sys/class/backlight instead.

Why does ddcutil work on an external monitor when /sys/class/backlight is empty?

/sys/class/backlight typically only exposes integrated laptop panel backlights controlled by GPU or ACPI firmware. External monitors expose brightness and input controls over the video cable’s I2C bus via DDC/CI, which ddcutil accesses through /dev/i2c-*.

VESA E-DDC and DDC/CI specifications define an I2C control plane alongside video transport: 100 kHz SDA/SCL lines on VGA/DVI/HDMI (7-bit addresses 0x50 for EDID, 0x30 for E-DDC segment pointer, 0x37 for DDC/CI) or I2C-over-AUX encapsulation on DisplayPort (AUX_CH, exposed via Linux drm_dp_aux_dev and i2c-dev). DDC/CI exchanges VESA MCCS VCP feature codes (e.g., 0x10 luminance, 0x60 input source). Failure modes include monitor firmware hanging on rapid back-to-back I2C polls, DP MST hubs dropping AUX transactions, and missing i2c-dev permissions.

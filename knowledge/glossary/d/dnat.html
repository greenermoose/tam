DNAT (Destination Network Address Translation)

Firewall rule rewriting a packet’s destination IP address or port (often called port forwarding).

Imagine an apartment building with one street address and a front-desk clerk who forwards mail to the right apartment number. On a home or office network, only the router has a public address on the internet, while your laptop, phone, and media server have private addresses inside. DNAT lets the router take incoming traffic aimed at its public address and redirect it to the specific internal computer or service that should answer it.

In Linux, DNAT is configured with nftables (or legacy iptables) in a prerouting hook—before the kernel makes its routing decision—so the packet’s new destination IP or port determines whether it is delivered locally or forwarded out another interface. Unlike SNAT (which rewrites the source address on outgoing traffic in postrouting), DNAT rewrites the destination on incoming connections. Because Linux tracks connections with conntrack, you only write the rule for the first packet; reply packets are automatically un-translated in reverse.

Why must a DNAT rule be placed in the prerouting hook rather than postrouting?

The kernel decides whether a packet is meant for the local host or needs to be forwarded to another machine during routing. Rewriting the destination in prerouting ensures the routing lookup uses the new destination address.

Netfilter’s NAT engine hooks into NF_INET_PRE_ROUTING (or NF_INET_LOCAL_OUT for locally generated traffic) and consults nf_conntrack: only the NEW packet of a flow evaluates the nftables dnat to statement, which stores the rewritten tuple in the conntrack entry’s reply direction. Subsequent packets in both directions bypass rule evaluation and are translated in-place by conntrack. Edge cases include hairpin NAT (a LAN client reaching a local server via the router’s external IP, requiring both DNAT in prerouting and SNAT/masquerade in postrouting so replies return through the router) and application-layer protocols (like FTP or SIP) that embed IP addresses in payloads and need a conntrack helper.

DMA - Direct Memory Access

DMA (Direct Memory Access) is a hardware feature that lets peripheral devices transfer data directly to or from RAM without the CPU copying every byte.

Imagine a busy chef who needs crates moved from the loading dock to the pantry. Instead of carrying every box personally, the chef hands a delivery list to a helper and keeps cooking until the helper rings a bell to say the move is finished. DMA works the same way for storage drives, network cards, and graphics cards, keeping your computer responsive during heavy transfers.

In modern Linux systems, NVMe SSDs, network interfaces, audio controllers, and GPUs use bus-mastering DMA to move large blocks directly into RAM and notify the kernel with an interrupt when done. Without DMA, the CPU would have to copy every word itself via programmed I/O, saturating processor cores during disk or network transfers.

Why can an NVMe SSD or 10 GbE network card move gigabytes per second without pinning a CPU core at 100% usage?

The device’s DMA engine transfers data directly between the peripheral and RAM over the PCIe bus, involving the CPU only to set up buffer descriptors and handle completion interrupts.

Modern PCIe peripherals perform bus-mastering DMA using scatter-gather descriptor rings in host memory, streaming across non-contiguous physical pages. Because raw DMA bypasses the CPU’s MMU, an IOMMU (Intel VT-d, AMD-Vi, ARM SMMU) translates device-visible I/O Virtual Addresses (IOVAs) to physical pages, preventing rogue DMA attacks and enabling safe VFIO device passthrough to virtual machines. On non-cache-coherent architectures, drivers must explicitly synchronize CPU caches around transfers using the Linux DMA API (dma_map_single, dma_sync_single_for_cpu).

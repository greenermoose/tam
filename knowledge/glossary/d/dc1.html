DC1 (Device Control 1 / XON, 0x11)

DC1 (Device Control 1, also called XON) is an ASCII control code (0x11, typed with Ctrl+Q) used in terminals to resume paused output.

If you have ever seen a terminal suddenly freeze and stop responding to what you type, you may have accidentally pressed Ctrl+S. DC1 (Ctrl+Q) is the matching "unfreeze" signal—like pressing play after pause—telling the terminal to start showing output again.

Part of the C0 control codes, DC1 acts as XON in software flow control (IXON). When enabled, Ctrl+S pauses terminal output and Ctrl+Q resumes it. In modern shells and editors, people often run stty -ixon so Ctrl+S and Ctrl+Q pass through to applications like Bash or Vim instead of pausing the screen.

Why might pressing Ctrl+Q in a frozen terminal unfreeze it, and when would it not?

If the terminal paused output because software flow control (IXON) intercepted Ctrl+S (DC3), Ctrl+Q (DC1) sends XON to resume transmission. It will not unfreeze a program that is genuinely hung, waiting on I/O, or running with stty -ixon.

ASCII 0x11 (DC1 / XON, ^Q). In the Linux kernel n_tty line discipline, when IXON is set in termios.c_iflag, an incoming byte matching c_cc[VSTART] (default 0x11) clears the stopped-output state and restarts TTY transmission suspended by VSTOP (DC3 / XOFF). Unlike hardware RTS/CTS (CRTSCTS), in-band XON/XOFF collides with binary payloads and requires cfmakeraw() (or clearing IXON/IXOFF) on non-text serial or PTY links; with IXANY set, any received byte acts like VSTART.

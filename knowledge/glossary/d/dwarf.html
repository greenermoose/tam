DWARF (Debugging With Attributed Record Formats)

The standard debugging-information format embedded in ELF binaries that maps compiled machine code back to source files, line numbers, and variable types.

Compiled programs are like a baked cake—the computer no longer sees the original recipe. DWARF is an extra map tucked alongside the program so a debugger or crash report can point to the exact source file and line number where something went wrong.

Compiling with -g embeds DWARF sections (.debug_info, .debug_line, .debug_frame) into ELF binaries so GDB, AddressSanitizer, and perf can display readable stack traces and inspect local variables. Because debug data can be larger than the program itself, Linux distributions often strip it into separate .debug packages or serve it on demand via debuginfod.

What is the difference between running strip --strip-debug and strip --strip-all on an ELF binary?

strip --strip-debug removes DWARF .debug_* sections (losing line numbers and local variable types) while keeping the symbol table so function names still appear in stack traces; strip --strip-all removes both, leaving only raw addresses unless separate debuginfo is loaded.

DWARF (v4/v5) encodes Debugging Information Entries (DIEs) as a tag/attribute tree in .debug_info using LEB128 variable-length integers and .debug_abbrev templates, paired with a bytecode state machine in .debug_line for PC-to-source mapping and .debug_loclists/.debug_rnglists (DWARF 5) to track variables across optimized register lifetimes. Call Frame Information (.debug_frame / .eh_frame) provides CFA unwind tables so stack unwinding works even with -fomit-frame-pointer. Split DWARF (-gsplit-dwarf producing .dwo/.dwp files) and DWZ compression reduce link-time memory and ELF size in large C++ codebases.

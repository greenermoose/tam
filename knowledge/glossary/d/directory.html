Directory

A directory is a container in a filesystem used to organize files and other directories, often called a folder in graphical desktops.

Imagine a hanging folder in a filing cabinet that holds documents and smaller folders inside it. Without directories, every photo, document, and program on a computer would be dumped into one giant list, making anything hard to find or back up.

In Linux, directories form a single tree starting at / (root), navigated with commands such as cd and ls, with special entries . (current directory) and .. (parent directory). Directory permissions behave differently from file permissions: r lets you list names, w lets you create, rename, or delete entries inside it, and x lets you traverse into it to access its contents.

If a user has read (r) permission on a directory but lacks execute (x) permission, what happens when they try to read a file inside it?

They can list the filenames with ls, but they cannot cd into the directory or open any file inside it because x is required to traverse the directory and resolve paths.

In POSIX filesystems and the Linux VFS, a directory is an inode whose payload maps filename strings to target inode numbers (making hard links simply multiple directory entries referencing the same inode). Within a single filesystem, rename(2) atomically updates directory entries; the sticky bit (01000, as on /tmp) restricts unlink and rename to the entry owner, directory owner, or root. Modern filesystems avoid linear O(n) scans in large directories using indexed structures (ext4 HTree, XFS/Btrfs B-trees), while the VFS dentry cache (including negative dentries) accelerates repeated path lookups.

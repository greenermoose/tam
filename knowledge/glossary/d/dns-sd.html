DNS-SD (DNS-Based Service Discovery)

A convention for using ordinary DNS records to list the services available on a network and to resolve one of them to a host and port.

DNS-SD is the list-making part of local discovery. Instead of asking for one fixed address, a computer asks "what printers are here?" and receives a list of named instances. After the user picks one, another query gives the address and port. It works with multicast DNS on the local link and with conventional DNS servers.

A service has a type such as _ipp._tcp and instances such as Demo Printer._ipp._tcp.local. A PTR query for the type lists instance names; an SRV query for one instance gives its target host and port; a TXT query gives small key/value attributes. With Avahi, avahi-browse _ipp._tcp -t -r -p performs both steps and prints the result.

Why does DNS-SD browse with PTR records rather than SRV records?

PTR records provide a list of user-facing instance names to choose from. SRV records assume the instances are interchangeable and give a target directly, which would not let a user pick a particular printer.

DNS-SD adds no new DNS message types. The instance name is <Instance>.<Service>.<Domain>, where the service is an underscore-prefixed name plus _tcp or _udp. Browsing queries PTR records at <Service>.<Domain>; resolution queries SRV and TXT records at the instance name. Every DNS-SD service must have a TXT record, even an empty one containing a single zero byte, and unknown TXT keys must be ignored. Service type enumeration uses _services._dns-sd._udp.local; subtypes narrow a browse. The design is specified in RFC 6763 and is normally paired with mDNS for zero-configuration operation.

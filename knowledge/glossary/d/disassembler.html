Guide / Glossary A–Z / Terms beginning with D / Disassembler

A disassembler is a tool that translates binary machine code back into human-readable assembly instructions.

When programmers build software, human-written code is turned into raw numbers that only the processor understands. A disassembler reverses one step of that process so a person can see the exact processor instructions a compiled program runs—useful when debugging a crash or checking what an unknown program actually does.

On Linux, tools like objdump -d, gdb (disassemble), and Ghidra read compiled binaries and display assembly mnemonics and memory addresses for a specific CPU architecture. Unlike a decompiler, which tries to guess higher-level C-like code, a disassembler stays faithful to the exact machine instructions present in the binary.

Why does disassembling a stripped binary show raw registers and addresses instead of original variable names and comments?

Comments and local variable names are discarded during compilation (or removed by strip) because the CPU only needs machine instructions, so the disassembler has no source metadata left to recover them.

Disassemblers typically use either linear sweep (decoding sequentially through .text, as objdump -d does) or recursive traversal (following control-flow edges from entry points and symbol tables). On variable-length ISAs such as x86-64, linear sweep can desynchronize when inline data, jump tables, or anti-disassembly padding appear inside code sections, whereas recursive traversal struggles with indirect branches, virtual calls, and runtime-computed targets. Available ELF sections—such as .symtab, .dynsym, PLT stubs, and DWARF unwind tables (.eh_frame)—strongly determine how accurately function boundaries and call targets are recovered.

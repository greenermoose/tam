Guide / Glossary A–Z / Terms beginning with D / Deployment

Deployment is the work of putting a finished program where its users can reach it and keeping a way to undo a bad release.

Writing the program is only half the job. Deployment is moving the finished version into place, like putting a new sign outside a shop after the paint has dried.

A simple deployment copies built files to a server. A larger one records a versioned artifact, applies database changes carefully and checks that the new version responds correctly.

Why build one artifact and promote it instead of rebuilding in production?

Rebuilding can resolve different dependencies or apply different settings, so the tested code is not the shipped code. Promoting the recorded artifact preserves the evidence from testing.

Reliable releases build once and promote the same artifact through environments. Blue-green or canary rollouts send a small share of traffic to the new version first. Secrets stay outside the artifact, and a tested rollback path is part of the release.

TOML (Tom's Obvious Minimal Language)

TOML (Tom’s Obvious Minimal Language) is a human-readable configuration file format that uses clear section headers, key-value pairs, and explicit data types.

Many Linux programs store their settings in plain text files so you can edit them in any text editor. TOML is designed to look neat and predictable—with bracketed headings like [theme] and simple name = "value" lines—so you are less likely to break a file with an accidental extra space.

You will see TOML in Cargo (Cargo.toml), Python packaging (pyproject.toml), and desktop tools like Alacritty or Starship. Unlike traditional .ini files, TOML distinguishes strings, integers, booleans, arrays, and dates unambiguously, and unlike YAML, whitespace indentation is ignored because structure comes from [table] headers and [[array_of_tables]].

Why is TOML often less error-prone to edit by hand than YAML?

TOML does not attach structural meaning to indentation and requires quotes around strings, avoiding YAML pitfalls such as misaligned spaces or unquoted values like no being parsed as booleans.

The TOML v1.0.0 specification defines a case-sensitive UTF-8 grammar mapping cleanly to hash tables, with bare, quoted, and literal strings, RFC 3339 timestamps (offset, local date-time, date, time), homogeneous or heterogeneous arrays, and inline tables ({ a = 1, b = 2 }) that must stay on one line without trailing commas in v1.0. Dotted keys (a.b.c = 1) and [table] headers share the same namespace and reject redefinition of an already-defined table or key, making schema validation deterministic.

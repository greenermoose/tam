Terminal

A text-based interface where you type commands for the computer and read the text output it sends back.

A terminal is like a text-message chat window between you and your computer: you type an instruction, press Enter, and the computer replies in words instead of buttons and icons. It matters because many system tasks, automation scripts, and remote connections are faster and more precise when you can type exact commands.

People often say “terminal” when referring to two separate pieces: the terminal itself (which draws characters and captures keystrokes) and the shell running inside it (such as bash or zsh, which interprets your commands). On Linux, pressing Ctrl+Alt+F3 switches to a full-screen kernel virtual console (/dev/tty3), whereas opening a terminal app in your desktop starts a graphical window backed by a pseudo-terminal (/dev/pts/*).

What is the difference between a terminal and a shell?

The terminal handles input and output—displaying characters and passing keystrokes—while the shell is the command-interpreter program running inside it that parses what you type and launches commands.

On Linux, “terminal” spans three implementations sharing the kernel TTY/termios abstraction: hardware serial UARTs (/dev/ttyS*), kernel-rendered virtual consoles (/dev/tty[1-63]) with a built-in VT100-subset parser, and graphical emulators backed by a PTY master/slave pair (/dev/ptmx and /dev/pts/N). In the PTY model, the emulator reads byte streams from the master fd, parses ECMA-48/ANSI escape sequences (CSI, OSC, DCS) into a cell grid, and writes encoded keystrokes back; the kernel line discipline sits between master and slave, managing job-control process groups (tcsetpgrp), SIGWINCH on resize, and canonical or raw buffering.

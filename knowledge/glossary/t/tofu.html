Guide / Glossary A–Z / Terms beginning with T / TOFU (Trust On First Use)

TOFU (Trust On First Use) is a security model that accepts an unverified cryptographic key the first time you connect to a server and warns you if that key ever changes later.

Think of recognizing a neighbor’s voice on the phone the first time they call and remembering it from then on. You might not have checked their passport on day one, but if someone else calls from the same number with a completely different voice next week, you immediately know something is wrong.

OpenSSH uses TOFU by default: the first time you run ssh alex@server, it prints the host key fingerprint and saves it to ~/.ssh/known_hosts if you answer yes. On every later visit, SSH refuses or warns loudly if the server presents a different key—though you should still verify the initial fingerprint out-of-band (or via DNSSEC SSHFP records) on untrusted networks.

What does a TOFU “WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED!” message tell you?

It means the server’s current host key does not match the key recorded in ~/.ssh/known_hosts from an earlier connection. Either the server was legitimately rebuilt/rekeyed, or an attacker is intercepting your connection.

TOFU trades the central Public Key Infrastructure (PKI) requirement of web TLS for decentralized key pinning, accepting a narrow initial-contact window vulnerable to an active man-in-the-middle attack while guaranteeing detection of subsequent key substitution. In OpenSSH, StrictHostKeyChecking=ask enforces interactive pinning, accept-new auto-pins only unseen hosts, and HashKnownHosts HMAC-hashes hostnames to limit lateral reconnaissance if ~/.ssh/known_hosts leaks; SSH certificates (@cert-authority) eliminate TOFU entirely by anchoring trust to a CA.

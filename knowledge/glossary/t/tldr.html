tldr pages

tldr pages are community-maintained, concise command cheat sheets that show the most common ways to run a command-line tool.

Traditional Unix manuals list every option a program supports, which can feel overwhelming when you just want to extract an archive or search a folder. tldr pages (short for “too long; didn’t read”) skip the long theory and give you five or six practical examples you can adapt right away.

Use tldr when you already know roughly which command you need and want syntax fast, and turn to man or --help when you need exact flag semantics, exit codes, or edge-case behavior. Here, tam bundles curated offline tldr pages accessible via tam tldr <cmd> or the Guide index, so examples remain available without internet access.

When should you switch from a tldr page to a full man page?

Switch to a man page whenever you need authoritative details—such as exact exit statuses, subtle flag interactions, environment variables, or version-specific behavior—because tldr pages intentionally omit rare options and edge cases to stay short.

The upstream tldr-pages corpus stores one Markdown file per command and platform directory (common/, linux/, osx/, etc.) using a constrained template: a title, brief description, optional URL, and alternating description/command blocks with {{placeholder}} tokens. Because pages are community-edited and platform-agnostic by default, flags shown in common/ may assume GNU coreutils rather than BSD or BusyBox variants; tam’s offline reader indexes a curated snapshot of these Markdown pages rather than generating them dynamically from installed binaries.

TDX (Trust Domain Extensions)

Intel’s hardware-based confidential computing technology that isolates virtual machines—called Trust Domains—from the host operating system, hypervisor, and physical memory snooping.

Normally, whoever controls the host computer (such as a cloud provider’s administrator) can peek inside any virtual machine running on it. TDX puts a virtual machine inside a locked, hardware-encrypted box so even the host computer’s own software cannot read or alter what is inside. It matters for running sensitive workloads on shared or remote servers without having to fully trust the server’s operator.

TDX is Intel’s counterpart to AMD SEV-SNP. The host hypervisor (such as QEMU/KVM on Linux) still schedules guest vCPUs and allocates memory pages, but it cannot inspect guest registers or plaintext RAM and must exchange I/O through explicitly shared buffers. Before sending secrets to a TDX guest, a remote party verifies a cryptographic attestation quote signed by Intel hardware to confirm the guest’s boot state.

In a TDX setup, can the host hypervisor still stop or deny resources to a guest VM?

Yes. TDX protects the confidentiality and integrity of guest memory and execution state, not availability. Because the host hypervisor still controls CPU scheduling, memory allocation, and I/O routing, a malicious host can pause or terminate the VM, though it cannot silently read or tamper with its private state.

TDX introduces a CPU-authenticated software layer—the Intel TDX Module—running in Secure Arbitration Mode (SEAM) alongside Multi-Key Total Memory Encryption (MKTME) with per-domain AES-XTS keys and page-ownership tracking in the Physical Address Metadata Table (PAMT). Transitions (TDENTER/TDEXIT) scrub architectural register state, while guest-host I/O uses shared GPA mappings (via the shared address bit) and bounce buffers such as swiotlb. Remote attestation binds build-time (MRTD) and runtime (RTMR) measurements into a TD Report signed by a Quoting Enclave (TDX-ECDSA), while side channels (cache timing, page-fault patterns) and the CPU/TDX-Module TCB remain part of the threat model.

TPM 2.0 (Trusted Platform Module 2.0)

The modern Trusted Platform Module specification (ISO/IEC 11889) for hardware key storage, cryptographic operations, and measured boot.

TPM 2.0 is the current generation of the built-in security chip found on modern PCs and laptops. While older security chips only understood one fixed scrambling method, TPM 2.0 is built to stay useful as security standards evolve. It keeps your encryption keys locked inside hardware and only hands them over—or uses them on your behalf—when the computer starts up cleanly without unexpected changes.

On modern Linux systems, the kernel exposes the chip at /dev/tpm0 and /dev/tpmrm0 (the resource-managed device), and tools like systemd-cryptenroll --tpm2-device=auto bind LUKS2 volume keys to specific TPM 2.0 PCR measurements. Compared to TPM 1.2, TPM 2.0 supports stronger algorithms like SHA-256 and elliptic-curve cryptography, and lets multiple user-space services share the chip concurrently through the in-kernel resource manager.

Why should Linux user-space tools open /dev/tpmrm0 instead of /dev/tpm0?

/dev/tpmrm0 routes commands through the kernel’s TPM 2.0 resource manager, which virtualizes transient handles and prevents concurrent tools from colliding or exhausting the chip’s small volatile memory.

Specified by the TCG TPM Library Specification 2.0 (ISO/IEC 11889), TPM 2.0 replaces TPM 1.2’s fixed SHA-1/RSA-2048 design with algorithm agility (SHA-256/384/512 PCR banks, ECC P-256/P-384, AES-CFB) and three distinct hierarchies (Platform, Storage, Endorsement) plus a Null hierarchy. Authorization uses enhanced policy sessions (TPM2_StartAuthSession, TPM2_PolicyPCR, TPM2_PolicySigned), enabling signed-PCR policies that survive planned kernel or firmware updates without re-sealing. Subtle failure modes include PCR bank mismatches (firmware extending SHA-256 while a tool queries SHA-1) and discrete SPI/LPC bus-interception attacks when unsealing secrets without salted, encrypted parameter sessions.

Guide / Glossary A–Z / Terms beginning with T / Threat model

A structured description of what you are protecting, who or what might compromise it, and which defenses address those risks.

Before buying locks for your house, you decide whether you are guarding against a curious roommate, a burglar, or a flood—each calls for very different protections. A threat model does the same thing for computers: it helps you focus effort on the real risks instead of adding complicated security steps that protect against the wrong problem.

A threat model lists four things: assets (what must stay secret or intact), trust boundaries (where data crosses between trusted and untrusted zones), adversary capabilities (what an attacker can actually do), and mitigations. For example, full-disk encryption protects files if a laptop is stolen while powered off, whereas TLS protects data in transit over public Wi-Fi—they solve different threats.

Does full-disk encryption protect your files if an attacker runs malicious code inside your already-logged-in session?

No. Once you unlock the disk at boot, the operating system transparently decrypts files for authorized processes, so malware running as your user reads them normally. Full-disk encryption addresses physical theft or offline disk inspection, not runtime compromise.

Formal threat modeling specifies assets, security properties (confidentiality, integrity, availability), explicit TCB and trust boundaries, and an adversary model—such as Dolev–Yao active network attackers, probabilistic polynomial-time (PPT) cryptographic adversaries, local unprivileged users, or physical/side-channel attackers. Frameworks like STRIDE (Spoofing, Tampering, Repudiation, Information Disclosure, Denial of Service, Elevation of Privilege) and attack trees enumerate failure modes and residual risk, guarding against assumption mismatches such as enforcing access checks on an untrusted client or ignoring traffic-analysis side channels when only payload encryption is deployed.

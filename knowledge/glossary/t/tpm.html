Guide / Glossary A–Z / Terms beginning with T / TPM (Trusted Platform Module)

A hardware security chip built into a computer that stores cryptographic keys and records measurements of the startup process.

Think of a TPM as a tiny, locked safe soldered onto your computer’s main circuit board. Regular programs cannot simply reach inside and copy the secret keys stored there. Each time the computer turns on, the chip also acts like a tamper-evident logbook, recording a fingerprint of the startup software so the system can tell whether anything unexpected changed before your operating system loaded.

On Linux, a TPM is commonly used for measured boot and automatic disk unlocking—for example, binding a LUKS encryption key to expected boot measurements so the drive unlocks only when the firmware and bootloader match. Unlike a USB security token you carry between machines, a TPM is tied to one motherboard and cannot be moved to another computer to decrypt the same keys.

Why does binding a disk key to a TPM stop working if you move the hard drive to another PC?

Because the encryption key is sealed inside the original motherboard’s TPM and never leaves it in plain form; the new PC has a different TPM without that secret.

A TPM is an isolated cryptographic coprocessor implementing Platform Configuration Registers (PCRs), a hardware RNG, and a hierarchy of storage, endorsement, and platform keys. Boot stages extend PCRs via PCR_Extend(new) = Hash(PCR_old || measurement), making pre-measurement tampering irreversible without a platform reset. Sealed objects bind decryption to a PCR policy digest, while remote attestation signs a PCR quote with an Attestation Identity Key (AIK). Because PCRs change on firmware updates, bootloader rebuilds, or kernel command-line edits, brittle PCR policies without a recovery passphrase can lock out legitimate updates.

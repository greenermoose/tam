Guide / Glossary A–Z / Terms beginning with T / Target

A target in systemd is a special unit that groups and orders other units to bring a Linux system to a well-defined state.

When a computer boots up, dozens of background programs need to start in a sensible order—networking before file sharing, graphics before the login screen. A systemd target works like a named milestone or checklist (such as “ready for text login” or “ready for graphical desktop”) so the system knows which group of services belongs together for each stage.

systemd targets replace traditional SysV runlevels: multi-user.target corresponds roughly to runlevel 3 (non-graphical multi-user system), graphical.target to runlevel 5 (desktop login), and rescue.target to single-user recovery mode. You can check the boot default with systemctl get-default, list active targets with systemctl list-units --type=target, or switch states on the fly with sudo systemctl isolate multi-user.target (which stops units not wanted by that target).

What is the difference between a .service unit and a .target unit in systemd?

A .service unit launches and supervises an actual process or command, whereas a .target unit starts no process of its own—it acts purely as a synchronization and grouping milestone that pulls in other units via dependencies.

A .target unit is a passive synchronization point in systemd’s dependency graph: it has no [Service] or ExecStart= section, instead aggregating units through Wants=, Requires=, BindsTo=, Before=, and After= edges (often populated via .wants/ and .requires/ symlink directories in /etc/systemd/system or /usr/lib/systemd/system). Standard boot targets such as sysinit.target, basic.target, network-online.target, and graphical.target establish happens-before barriers, while DefaultDependencies=yes implicitly adds After= and Conflicts=shutdown.target unless overridden for early-boot targets. A common pitfall is assuming After=network.target guarantees routable IP connectivity; network.target only marks network-stack setup start, whereas services needing an assigned address must order After=network-online.target and Wants=network-online.target.

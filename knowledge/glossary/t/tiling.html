Tiling

Tiling is a way of arranging application windows so they divide the screen into non-overlapping regions automatically.

Think of arranging tiles on a kitchen wall instead of scattering papers on a desk: every window gets its own rectangle without covering the others. When you open a new app, the desktop shrinks and shifts existing windows to make room, so you spend less time dragging edges and hunting for hidden windows.

In a tiling window manager or Wayland compositor, new windows split the workspace according to a layout (such as master-and-stack, binary space partitioning, or tabbed/scrolling columns), and keyboard shortcuts with Meta move focus, swap panes, or resize splits. Tiling is not absolute: dialog boxes, popups, and explicitly floated windows sit above the tiled layer, while fullscreen apps cover the entire output.

Why can a floating dialog still cover a tiled window if tiling is enabled?

Because tiling is a layout mode for normal managed windows rather than a rule that forbids overlap. Popups, modal dialogs, and windows toggled into floating mode are placed in a separate layer above tiled panes so small prompts do not distort your whole screen layout.

In Wayland compositors, tiling is a compositor-side layout policy rather than a protocol guarantee. Clients still negotiate state via xdg_toplevel configure events (such as activated, maximized, fullscreen, and tiled_* edges), and applications with fixed minimum sizes or aspect-ratio hints can refuse or distort requested dimensions. Layer-shell surfaces (zwlr_layer_shell_v1) such as panels and notifications reserve exclusive zones or overlay outputs independently of the tiling tree, and XWayland override-redirect windows bypass layout management altogether.

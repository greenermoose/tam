TAGE (TAgged GEometric history length)

TAGE (TAgged GEometric history length) is a high-accuracy CPU branch-predictor design that uses multiple tagged lookup tables indexed by exponentially growing branch histories.

Modern processors try to read and prepare many instructions ahead of time, but whenever code hits an “if” statement or a loop, the CPU has to guess which way the program will go before the answer is ready. TAGE is a clever pattern-matching trick that remembers both recent choices and much older ones, letting modern chips guess right more than 99% of the time so they rarely stall and throw away work.

Simple branch predictors track only a fixed, short history of recent branches, so they miss patterns hidden inside nested loops or long call chains. TAGE solves this by running several prediction tables in parallel: a base bimodal predictor plus tagged tables using short, medium, and very long global branch histories. The longest history table whose tag matches wins, while a usefulness counter prevents rare noisy branches from evicting valuable long-history entries.

Why does TAGE use multiple tables with different history lengths instead of one huge table with a very long history?

A single huge table with a long history takes too long to warm up and suffers aliasing when branches only depend on recent outcomes. Geometric history lengths let short-history tables learn quickly while long-history tables capture deep correlations only when their tags match.

Proposed by Seznec and Michaud, TAGE pairs a tagless base predictor T0 with M partially tagged components T1..TM indexed by hashed global branch/path history of geometric lengths (spanning from a few bits to hundreds or thousands of branches). On lookup, the longest-history hitting table supplies the provider prediction and the next-longest hit (or T0) supplies the alternate prediction. On misprediction, TAGE allocates entries in tables with longer histories than the provider (preferring entries with usefulness u == 0 and decaying u on allocation failure) and uses a use_alt_on_na counter for newly allocated weak entries. Because branch-history tables are shared across contexts or SMT siblings, TAGE state is also a vector for speculative-execution side channels (Spectre v2 / Branch History Injection), mitigated via IBRS/eIBRS, BHB clearing, and retpolines.

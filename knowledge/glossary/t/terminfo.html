Guide / Glossary A–Z / Terms beginning with T / Terminfo (terminal information)

A database that describes the capabilities and control codes of different terminal types so text programs can work consistently across them.

Different terminals use different special codes to clear the screen, move the cursor, or show colors. Terminfo is like a translation dictionary that lists what each terminal understands. Programs look up your terminal in this dictionary instead of having to memorize every terminal model ever made.

On Linux, terminfo replaces the older termcap system and stores one compiled file per terminal name under directories like /usr/share/terminfo/. You can inspect the active entry with infocmp or query a single capability with tput (for example, tput colors or tput cols). Because programs read the entry named by $TERM, an outdated or missing terminfo database on a remote machine is a common reason full-screen tools look broken over SSH.

Why do shell scripts often use tput instead of hardcoding raw escape sequences?

tput looks up the requested capability (such as bold or foreground color) in the terminfo entry for the current TERM, so the script emits the right sequence for that terminal—or nothing if unsupported—rather than assuming every terminal is ANSI-compatible.

Terminfo compiles human-readable source descriptions via tic into a binary format (term(5), including ncurses 6.1+ 32-bit extended numeric headers for values above 32,767) partitioned into boolean flags (am, bce), numeric values (cols, colors), and parameterized string capabilities (cup, sgr0, setaf) evaluated with stack-based %-expressions via tparm(). libtinfo/ncurses searches $TERMINFO, $TERMINFO_DIRS, ~/.terminfo, and system paths, while modern tools increasingly pair static terminfo with runtime escape queries (XTGETTCAP, DECRQM) for features terminfo models poorly, such as 24-bit RGB or synchronized output.

Guide / Glossary A–Z / Terms beginning with T / Throughput

The actual rate at which data or work is successfully delivered over a given period of time.

A highway’s speed limit and number of lanes tell you its maximum capacity, but traffic jams and tollbooths determine how many cars actually get through per hour. Throughput is that real-world count of how much data arrives—not the theoretical top speed printed on the box.

Throughput is distinct from both raw link bandwidth (the theoretical signaling rate, such as 1 Gbps Ethernet) and latency (how long a single packet takes to travel). Protocol headers, acknowledgments, packet loss, and CPU or disk bottlenecks mean achieved application throughput—often called goodput—is lower than raw bandwidth; tools like iperf3 measure network throughput, while fio measures storage throughput.

Can a network link with high bandwidth still have poor TCP throughput if latency is very high?

Yes. TCP limits how much unacknowledged data can be in flight at once (bounded by the receive window and congestion window). When round-trip latency is high, waiting for acknowledgments stalls the sender unless window scaling and buffers are large enough to fill the bandwidth-delay product.

Throughput must be qualified by the measurement layer: physical-layer bit rate includes line coding (e.g., 64b/66b in 10GbE), link/network throughput counts frame and IP headers, and application goodput counts only non-duplicate payload bytes. In TCP, steady-state throughput is bounded by min(rwnd, cwnd) / RTT (requiring socket buffers ≥ Bandwidth-Delay Product) and scales roughly as MSS / (RTT × sqrt(p)) under loss probability p for AIMD congestion control. Across queuing systems, Little’s Law (L = λW) relates concurrency L, throughput λ, and latency W, explaining why latency spikes sharply as throughput approaches saturation.

TERM

The environment variable that tells command-line programs what kind of terminal they are running in so they can format text, colors, and keys properly.

Different screens and terminal programs understand different secret codes for things like “move the cursor up” or “print in red.” TERM is like a name tag your terminal wears so programs know which language of codes to speak. If the name tag is wrong, text can look scrambled or arrow keys can stop working.

When you open a terminal emulator or log in over SSH, TERM is set automatically (for example to xterm-256color, tmux-256color, or linux on a virtual console). Programs like less, vim, and htop read TERM to look up capabilities in the terminfo database. Manually setting TERM to a type your terminal does not match—or forwarding a newer terminal’s name to a server that lacks its entry—causes missing colors, garbled borders, or broken function keys.

If you SSH to a remote server and vim or top complains about an unknown terminal type, what is usually happening?

Your local terminal’s TERM value (such as an emulator-specific name) was forwarded by SSH, but the remote server’s terminfo database lacks an entry for that name. Installing the matching terminfo entry on the server or using a widely supported fallback like xterm-256color resolves it.

TERM is a POSIX environment variable read by libtinfo/ncurses (setupterm()) to locate a compiled binary terminfo record under $TERMINFO, ~/.terminfo, or system paths such as /usr/share/terminfo/<first-char>/<TERM>. Because TERM is only a static name rather than a runtime negotiation protocol, it cannot report dynamic dimensions (handled by the TIOCGWINSZ ioctl) or out-of-band features such as 24-bit color (COLORTERM=truecolor) or graphics protocols without escape-sequence queries (e.g., DA1, DECRQM). A mismatched TERM inside multiplexers like tmux or screen commonly breaks back-color-erase (bce) and alternate-screen (smcup/rmcup) handling.

Guide / Glossary A–Z / Terms beginning with T / TCB (Trusted Computing Base)

The set of hardware, firmware, and software components that must work correctly for a computer system’s security policy to hold.

Think of a bank vault: its security depends on the concrete walls, the lock mechanism, and the guards who hold the keys—not on the brochures in the lobby. In a computer, the Trusted Computing Base (TCB) is that inner circle of essential parts. If any piece inside the TCB has a flaw or is tricked, the whole system’s protections can fail, which is why security engineers try to keep that circle as small and simple as possible.

On a typical Linux system, the TCB includes the processor, system firmware, bootloader, Linux kernel, and privileged services (such as systemd or authentication helpers) that enforce user separation and file permissions. Unprivileged user applications—like a web browser, text editor, or image viewer—normally sit outside the TCB so that a bug in one app cannot compromise the rest of the machine. Moving complex tasks like file parsing or device emulation out of privileged code shrinks the TCB and reduces how much code must be trusted and audited.

Why does moving a complex file parser out of a root service into an unprivileged sandbox improve security?

Moving the parser out of privileged code removes it from the TCB. A bug in the parser might still crash or corrupt the sandboxed process, but it can no longer directly bypass kernel or system-wide security boundaries.

Formally defined in the DoD Trusted Computer System Evaluation Criteria (TCSEC) as the totality of protection mechanisms—hardware, firmware, and software—responsible for enforcing a security policy, the TCB encompasses the reference monitor (which must be tamperproof, always invoked for complete mediation, and small enough to be verified) plus any supporting state and privileged user-space components. Because any defect inside the TCB can violate confidentiality or integrity across trust boundaries, architectures such as L4/seL4 microkernels, NOVA microhypervisors, capability-based sandboxes, and confidential-computing enclaves (such as TDX, which removes the host OS from the guest TCB while retaining the CPU and TDX Module) seek to minimize TCB size and complexity.

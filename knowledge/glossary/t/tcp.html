TCP - Transmission Control Protocol

A core internet transport protocol that delivers a reliable, ordered stream of bytes between two programs over a network.

Sending data across a network is like mailing a long letter one page at a time: pages can arrive late, out of order, or get lost on the way. TCP numbers every page, checks that each one arrived, asks for missing ones to be sent again, and puts them back in order before handing the letter to the program. It matters because web pages, file downloads, and email would break or scramble if even a small piece went missing.

Unlike UDP—which sends independent datagrams with no delivery guarantee—TCP opens a stateful connection between an IP address and port pair, exposes a continuous byte stream to applications, and adapts its sending rate to network conditions. On Linux, you can inspect active TCP sockets and states (LISTEN, ESTABLISHED, TIME_WAIT) with ss -tan. Because TCP guarantees ordered delivery, a single lost packet stalls later packets already in the receive buffer until it is retransmitted.

If an application calls send() twice with 100 bytes each over TCP, is the receiver guaranteed to read two separate 100-byte chunks?

No. TCP provides an unstructured byte stream, not message framing. The kernel or network may coalesce both writes into one 200-byte segment or split them differently, so applications must define their own framing (such as length prefixes or delimiters).

TCP (RFC 9293) establishes full-duplex state via a three-way handshake (SYN, SYN-ACK, ACK) that synchronizes 32-bit initial sequence numbers and negotiates options including MSS, window scaling (RFC 7323), SACK (RFC 2018), and timestamps. Flow control bounds in-flight data to the receiver’s advertised rwnd, while congestion control adjusts cwnd via algorithms such as CUBIC (Linux default) or BBR in response to loss, ECN marks, or RTT inflation. Key operational edge cases include TIME_WAIT (2×MSL) preventing stale duplicate segments from corrupting reused 4-tuples, SYN cookies mitigating SYN-queue exhaustion, and transport-level head-of-line blocking motivating protocols like QUIC.

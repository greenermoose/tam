Truth table

A table listing every possible input combination for a logic rule or circuit and the output it produces.

A truth table is like a complete cheat sheet for a yes-or-no rule. If you have a rule with two switches—say, “the light turns on only if both switch A and switch B are on”—a truth table writes down all four ways those two switches could be set and marks whether the light is on or off in each case. Because nothing is left out, you can check how a rule behaves without guessing.

In digital logic and programming, truth tables map binary inputs (0 and 1, or false and true) to outputs for gates like AND, OR, XOR, and NAND, or for compound conditional expressions. Writing out a truth table helps catch subtle bugs in Boolean conditions—such as confusing !(A && B) with !A && !B (De Morgan’s laws)—and serves as the starting point for simplifying hardware circuits with Karnaugh maps.

How many rows does a truth table need for a logic gate with 4 binary inputs?

It needs 16 rows (2⁴), because each of the 4 inputs can independently take 2 values (0 or 1).

A truth table is an exhaustive extensional specification of a Boolean function f: {0, 1}ⁿ → {0, 1} (or multi-output {0, 1}ᵐ), containing 2ⁿ rows. Each row evaluating to 1 defines a minterm, enabling direct synthesis into canonical Sum-of-Products (disjunctive normal form) or Product-of-Sums circuits, as well as FPGA lookup tables (LUTs), where a k-input LUT literally stores the 2ᵏ-bit output column in SRAM. Exponential 2ⁿ growth makes explicit truth tables impractical beyond small n (typically n ≤ 6 in manual minimization or LUTs), requiring symbolic representations such as Reduced Ordered Binary Decision Diagrams (ROBDDs) or SAT-based synthesis for large combinational networks.

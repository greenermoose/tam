Guide / Glossary A–Z / Terms beginning with T / Toolchain

A toolchain is the coordinated set of software tools—such as a compiler, assembler, linker, and core libraries—used together to turn source code into runnable programs.

Building software is a bit like publishing a book: one tool checks and translates the draft, another binds the pages together, and another packages the final copy. A toolchain is that complete kit of matching tools working in sequence so human-readable code becomes an app your computer can run.

On Linux, a classic C/C++ toolchain pairs GCC or Clang (the compiler) with GNU Binutils or LLD (assembler and linker), a C library like glibc or musl, and build orchestrators like make or cmake. When cross-compiling—building on an x86_64 laptop for an aarch64 board—you need a toolchain targeting the destination architecture and C library, not just your host’s default compiler.

Why can’t you always copy a binary compiled with your laptop’s default toolchain onto a Raspberry Pi?

A default host toolchain emits machine instructions and links against libraries for your laptop’s CPU architecture (usually x86_64) and ABI. A Raspberry Pi typically uses ARM (aarch64), so the binary must be built with a matching cross-toolchain.

A toolchain is uniquely characterized by its host/target triples (e.g., x86_64-unknown-linux-gnu), sysroot (target headers and libraries), C runtime startup objects (crt1.o, crti.o), dynamic linker path (such as /lib64/ld-linux-x86-64.so.2), and ABI rules. Cross-compilation distinguishes build, host, and target platforms ("Canadian cross" when all three differ) and must align compiler flags, libgcc/compiler-rt unwinder, and target kernel UAPI headers so produced ELF binaries match the target’s ABI and symbol versions.

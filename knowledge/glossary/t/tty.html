TTY (Teletype)

Linux’s terminal device abstraction (/dev/tty*) that connects text-based programs to keyboards, screens, serial ports, and terminal windows.

Long ago, a “teletype” was a physical typewriter-like machine wired to a computer. Today, Linux still uses the name TTY for any text connection where you type commands and read text output—whether it is a full-screen text console you switch to with a key combo, or the channel behind a terminal window on your desktop.

Running tty prints the device path of your current terminal, such as /dev/tty1 on a virtual console or /dev/pts/0 inside a terminal emulator or SSH session; see also PTY. Knowing which TTY a process uses matters because backgrounded jobs, password prompts, and signals like Ctrl+C are routed through the controlling terminal.

Why does running tty inside a desktop terminal window print /dev/pts/N instead of /dev/ttyN?

Because a desktop terminal emulator is a graphical program that communicates with the shell through a pseudoterminal (PTY) slave under /dev/pts/ rather than a kernel virtual console (/dev/ttyN).

The kernel TTY subsystem (drivers/tty/) separates hardware and virtual drivers (tty_driver for UART serial ports, kernel VTs, and PTY pairs) from line disciplines (N_TTY by default, handling canonical buffering, echo, erase/kill, and signal generation) and session/process-group tracking (TIOCSCTTY, tcsetpgrp). Job control relies on the foreground process group receiving SIGINT/SIGTSTP from the line discipline and SIGTTIN/SIGTTOU when background jobs attempt terminal I/O. Edge cases include stty raw bypassing N_TTY processing and SIGHUP teardown when a controlling terminal or PTY master closes.

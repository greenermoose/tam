Nounset

A shell option that treats referencing an undefined variable as an error instead of silently expanding it to an empty string.

Normally, if you misspell a variable name in a shell script, the shell quietly treats it as blank and keeps running—which can turn a command like rm -rf "$DIR/" into deleting the wrong folder. Turning on nounset tells the shell to stop and complain immediately whenever a variable has not been defined.

In POSIX shells and Bash, you enable nounset with set -u (or set -o nounset). It catches typos and missing environment variables early, especially when paired with set -e. When a variable might legitimately be unset, you provide a fallback using parameter expansion like ${VAR:-default} so nounset does not abort the script.

How can you check or use an optional variable in a script when set -u is active?

Use default-value parameter expansion such as ${VAR:-} or ${VAR:-fallback}. The :- syntax tells the shell to substitute an empty string or fallback if VAR is unset, preventing nounset from triggering an error.

Specified by POSIX (set -u), nounset raises a non-zero exit (and aborts non-interactive shells) when expanding an unset parameter, with explicit exceptions for $@, $*, and conditional expansions (${var:-word}, ${var:+word}, ${var:=word}, ${var:?word}). A classic Bash-specific pitfall (especially prior to Bash 4.4) was empty arrays: "${arr[@]}" triggered an unbound-variable error even when arr=() was declared, requiring workarounds like ${arr[@]+"${arr[@]}"}. Also note that nounset only checks whether a variable is set, not whether it is non-empty (VAR="" passes).

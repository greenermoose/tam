NAND (NOT-AND)

The non-volatile flash memory technology used inside SSDs, USB flash drives, SD cards, and smartphone storage.

Unlike computer memory (RAM) that forgets everything the moment you turn off the power, NAND flash traps tiny pockets of electrical charge so your files stay saved without electricity. Because it has no spinning platters or moving parts like an old hard drive, storage built with NAND is fast, silent, and shock-resistant—though each storage cell can only be rewritten a limited number of times before wearing out.

NAND flash is organized into small pages (typically 4–16 KiB) grouped into much larger erase blocks (often several megabytes). While data can be read and written one page at a time, existing data cannot be overwritten in place—an entire block must be erased before any page in it can be reused. That asymmetry is why SSDs rely on an internal controller (FTL) for wear leveling and garbage collection, and why Linux issues TRIM/discard commands so the drive knows which deleted blocks no longer hold valid data.

Why does an SSD perform better when the operating system sends TRIM/discard commands after files are deleted?

Because NAND cannot overwrite pages in place and must erase whole blocks; TRIM tells the drive which pages are no longer in use so it can erase and reclaim blocks ahead of time instead of stalling during writes.

Named after the NAND logic gate topology that wires floating-gate or charge-trap transistors in series for high density (contrasted with byte-addressable NOR flash used for firmware), modern 3D NAND stacks word-line layers vertically and stores 1 to 4 bits per cell (SLC, MLC, TLC, QLC) using distinct threshold-voltage distributions. Because higher bits-per-cell reduce voltage margins and endurance (from ~100k P/E cycles in SLC down to ~1k or fewer in QLC), controllers pair aggressive LDPC error-correcting codes with pseudo-SLC write caches, bad-block remapping, and Flash Translation Layer (FTL) logical-to-physical mapping—introducing write amplification when random overwrites force read-modify-erase-write cycles across blocks.

ncurses (new curses)

A programming library for building interactive text-based interfaces inside a terminal window.

Even without a mouse-driven desktop, programs can still show menus, buttons, and split panes inside a plain text terminal. Think of the terminal screen as a grid of letter-sized tiles: ncurses gives programmers a way to place text, highlights, and borders on any tile without redrawing the whole screen from scratch. That is why tools like text editors and system monitors feel responsive even over a slow remote connection.

In Linux, ncurses reads the TERM environment variable and looks up your terminal’s capabilities in the terminfo database, so the same program works across different terminal emulators (like xterm, tmux, or a Linux virtual console). Unlike simple line-by-line output with printf, ncurses switches the terminal to raw or cbreak mode, captures arrow and function keys, and batches screen updates with refresh() to minimize flicker.

Why can an ncurses program look garbled if TERM is set to the wrong value?

ncurses looks up escape sequences—such as cursor movement and color codes—in the terminfo entry matching TERM. If TERM describes a different terminal than the one actually running, ncurses sends sequences your terminal misinterprets or prints literally.

ncurses implements X/Open Curses with extensions including overlapping panel stacks, off-screen pad buffers, UTF-8 wide-character support (ncursesw), and SGR/X10 mouse reporting. Its core optimization diffs a virtual screen (curscr vs. newscr) and emits minimal ANSI/ECMA-48 escape sequences, avoiding full-frame repaints. A classic failure mode is calling non-reentrant ncurses functions from signal handlers (such as SIGWINCH on resize) or mixing stdio writes with wrefresh(), which desynchronizes curscr from the physical display.

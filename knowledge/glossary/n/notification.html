Guide / Glossary A–Z / Terms beginning with N / Notification

A short status message sent by an application to alert the user without interrupting their main window.

A notification is a brief pop-up banner—like a chat alert or a “download finished” message—that lets you know something happened while you are working in another window. It is meant to inform you without forcing you to stop what you are typing.

On a Linux desktop, applications do not draw notification pop-ups themselves; they send an asynchronous request over D-Bus to a notification daemon (such as mako, dunst, or the desktop shell’s built-in service). Notifications can carry urgency levels (low, normal, critical), optional action buttons, and a replacement ID so an app (like a volume slider) updates one banner instead of stacking dozens.

Why can notifications stop appearing even though the underlying applications are still running?

Applications hand notifications off to a separate notification daemon over D-Bus. If that daemon is not running, crashed, or is paused in Do Not Disturb mode, apps still send the D-Bus call (or queue it) without a banner appearing on screen.

Desktop notifications implement the freedesktop.org Desktop Notifications Specification over session D-Bus (org.freedesktop.Notifications, method Notify). Each call passes app_name, replaces_id, app_icon, summary, body, actions, hints (e.g., urgency, transient, desktop-entry), and expire_timeout. Edge cases include critical urgency notifications overriding expire_timeout (staying pinned until dismissed), sandboxes (Flatpak/portal org.freedesktop.portal.Notification) mediating permissions, and D-Bus activation races when multiple notification daemons are installed on the same system.

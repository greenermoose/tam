NSEC (Next Secure)

A DNSSEC record that proves a DNS name or record type does not exist.

Normal DNS can say "that name does not exist," but DNSSEC needs a way to prove that answer is real and not forged. An NSEC record does that by pointing from one existing signed name to the next existing signed name in the zone. If the name you asked for falls between them, the resolver can see that it truly is missing.

An NSEC record lists the next owner name in the zone's canonical order and the record types that exist at the current owner name. For a missing name, a validator uses NSEC records to prove there is a gap. For an existing name with a missing type, the NSEC record at that name shows which types are present. Because NSEC records form a chain through zone names, they can allow zone walking: an attacker can follow the chain to enumerate names in the zone.

Why might a zone use NSEC3 instead of NSEC?

NSEC3 hashes owner names so the chain does not directly reveal every name in plain text. It makes casual zone walking harder, though it does not make name enumeration impossible against determined attackers.

NSEC (RFC 4034/4035) provides authenticated denial of existence by asserting the canonical next owner name and an RR type bitmap. A proving non-existence response may include NSEC records covering the QNAME, a wildcard, and/or the closest encloser, depending on the case. NSEC enables trivial zone enumeration because the chain is traversable. NSEC3 (RFC 5155) replaces plaintext next names with hashed owner names and adds opt-out behavior, trading direct disclosure for offline dictionary attack resistance limits.

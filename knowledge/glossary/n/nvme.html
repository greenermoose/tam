Guide / Glossary A–Z / Terms beginning with N / NVMe (Non-Volatile Memory Express)

A high-speed storage protocol designed for solid-state drives connected directly over PCIe.

Older hard-drive connections (like SATA) were built for spinning disks and act like a single narrow checkout lane. NVMe lets modern flash memory drives plug straight into the computer’s fast PCIe highway with thousands of parallel lanes, so opening large files, booting up, and saving projects happen much faster.

On Linux, NVMe drives appear as /dev/nvme0n1 (controller 0, namespace 1, with partitions like /dev/nvme0n1p1) rather than /dev/sda used by SATA/SCSI drives. Designed around flash memory’s parallelism rather than spinning platters, NVMe supports up to 64K queues with 64K commands each, letting each CPU core submit I/O without fighting over a single lock; you can inspect health and SMART attributes using nvme smart-log /dev/nvme0 from nvme-cli.

Why do NVMe drives show up as /dev/nvme0n1 instead of /dev/sda on Linux?

The sd* names come from the SCSI/SATA subsystem, which routes commands through AHCI or SCSI layers. NVMe bypasses AHCI/SCSI entirely with its own Linux block driver that names devices by controller (nvme0) and namespace (n1).

NVMe defines a register-level host-controller interface and command set over PCIe (as well as Fabrics transports like NVMe-oF over RDMA, TCP, or Fibre Channel) using paired Submission Queues (SQ) and Completion Queues (CQ) in host DMA memory, notified via MMIO doorbell writes and MSI-X interrupts mapped per CPU core. The Linux nvme driver integrates directly with blk-mq (multi-queue block layer), mapping hardware queue pairs 1:1 to CPU cores to eliminate cross-core spinlock contention. Subtle operational considerations include Host Memory Buffer (HMB) usage on DRAM-less drives, Autonomous Power State Transitions (APST) causing latency spikes or controller drops on buggy firmware, and Zoned Namespaces (ZNS) exposing flash erase-block boundaries to host FTLs.

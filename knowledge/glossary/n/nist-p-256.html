NIST P-256 (secp256r1)

A widely used 256-bit elliptic curve standard for digital signatures and key exchange.

Modern encryption often relies on special mathematical curves to create keys that are both tiny and hard to crack. NIST P-256 is one of the most common of those curves—it is the math working behind the scenes when your browser verifies a website’s padlock certificate or when a security key signs a login challenge.

You will see the same curve under several names depending on the tool: P-256 (NIST), secp256r1 (SECG), and prime256v1 (OpenSSL). It provides about 128 bits of classical security with much smaller keys than 3072-bit RSA, and it is hardware-accelerated on many TPMs, smartcards, and FIDO2 keys. When generating SSH keys, you might see it as ecdsa-sha2-nistp256, though ed25519 is often preferred for new software-only keys because it avoids certain implementation pitfalls.

If a tool lists secp256r1 and prime256v1, are those different curves from NIST P-256?

No—they are three names for the exact same elliptic curve defined by different standards bodies (NIST, SECG, and OpenSSL). Keys and signatures generated under any of those names are mathematically identical and interoperable.

NIST P-256 (FIPS 186-4 / SEC 2) is a Weierstrass curve y^2 = x^3 - 3x + b over the prime field F_p where p = 2^256 - 2^224 + 2^192 + 2^96 - 1 (a Solinas prime enabling fast modular reduction), with cofactor h = 1 and a 256-bit prime-order base point G. It is used with ECDSA and ECDH (TLS 1.3 secp256r1). Critical failure modes include ECDSA nonce (k) reuse or bias—which leaks the private key algebraically—and invalid-curve attacks in ECDH if implementations omit point-on-curve validation. Deterministic nonces (RFC 6979) and constant-time complete addition formulas mitigate these risks.

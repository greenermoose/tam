NOVA (NOVA Microhypervisor)

A capability-based microhypervisor designed to run isolated virtual machines with a minimal trusted codebase.

Traditional virtualization systems put a lot of complex code—like virtual disk and network drivers—inside the most privileged part of the computer. NOVA takes a minimalist approach: it keeps the core hypervisor tiny and moves all that extra machinery into separate, restricted programs, so a bug in one virtual device is far less likely to compromise the whole machine.

NOVA follows microkernel principles applied to hardware virtualization (Intel VT-x / AMD-V). Instead of running a full Linux kernel or large hypervisor in root mode, the NOVA microhypervisor handles only CPU scheduling, memory mapping, IPC, and capability enforcement, while user-space virtual machine monitors (VMMs) handle device emulation. This shrinks the virtualization trusted computing base (TCB) compared to monolithic hypervisors like KVM+Linux.

How does NOVA reduce the risk of a bug in an emulated virtual device?

Device emulation runs in unprivileged user-space VMM processes rather than inside the privileged hypervisor kernel. A flaw in a virtual device model is contained by capability boundaries instead of immediately granting kernel-level control.

Introduced by Udo Steinberg and Bernhard Kauer (EuroSys 2010), the NOVA OS-oriented microhypervisor separates mechanism (microhypervisor in VMX root/kernel space) from policy (user-space VMMs such as Seoul/Vancouver or Genode’s VMM). Communication uses synchronous IPC portals with capability delegation across protection domains, and each vCPU is bound to a user-space execution context (EC) that traps VM exits to its VMM via portal IPC. The main trade-off versus monolithic type-1/type-2 hypervisors is higher VM-exit latency when exits must cross user-space IPC boundaries, requiring careful handling of performance-critical paths such as EPT/NPT faults and local APIC emulation.

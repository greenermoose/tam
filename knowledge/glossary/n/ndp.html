NDP (Neighbor Discovery Protocol)

An IPv6 protocol that lets devices on the same local network find each other, discover routers, and configure addresses.

When a device joins a home or office network, it needs to know who else is on the same wire and which box is the router to the internet. NDP is the neighborhood roll call for modern (IPv6) networks: devices call out to ask who has a certain address, announce themselves, and listen for routers. Without it, devices on the same local network would not know where to send packets.

NDP replaces IPv4’s ARP (Address Resolution Protocol) and adds router discovery and stateless address autoconfiguration (SLAAC). Instead of using a separate link-layer protocol like ARP, NDP runs inside ICMPv6 packets. That means if you write a host firewall rule that blocks all ICMPv6 traffic, local IPv6 connectivity breaks completely—even pings aside, the host cannot resolve link-layer MAC addresses or learn its default gateway.

Why does blocking all ICMPv6 in a firewall break IPv6 even when TCP and UDP are allowed?

Because IPv6 has no separate ARP protocol; it uses ICMPv6 Neighbor Solicitation and Neighbor Advertisement messages (NDP) to map IPv6 addresses to MAC addresses and find routers. Blocking ICMPv6 prevents the host from resolving next-hop link addresses.

Defined in RFC 4861 (with SLAAC in RFC 4862), NDP uses five ICMPv6 message types: Router Solicitation (133), Router Advertisement (134), Neighbor Solicitation (135), Neighbor Advertisement (136), and Redirect (137). Solicitations target solicited-node multicast addresses (ff02::1:ff00:0/104) rather than link-wide broadcast, reducing wakeup overhead on unrelated hosts, and Duplicate Address Detection (DAD) probes with an unspecified source (::) before an address leaves the tentative state. Because NDP is unauthenticated by default, local threats include rogue Router Advertisements and Neighbor Cache poisoning, mitigated via RA-Guard on switches or SEND (RFC 3971).

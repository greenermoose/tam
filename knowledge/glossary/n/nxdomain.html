NXDOMAIN (Non-Existent Domain)

A DNS response code meaning the requested domain name does not exist.

When you look up a name in DNS and that name has not been registered or published, the DNS server can answer with NXDOMAIN. It means "there is no such domain name." It is different from a name that exists but has no record of the type you asked for; in that case DNS usually returns a successful reply with no answer records.

NXDOMAIN is DNS response code 3 (Name Error). You can see it with dig nonexistent.example.com, which reports status: NXDOMAIN. Caching resolvers may cache NXDOMAIN responses for the negative TTL from the zone's SOA record, so a newly created name might not appear immediately everywhere. Some ISPs or networks intercept NXDOMAIN and return a search page instead, which can break tools that expect the standard DNS behavior.

Is NXDOMAIN the same as "no A record"?

No. NXDOMAIN means the name itself does not exist. "No A record" usually means the name exists, but it has no address record of that type; DNS can return NOERROR with an empty answer section.

NXDOMAIN is signaled by RCODE 3 in the DNS header. With DNSSEC, an authoritative server proves non-existence with signed NSEC or NSEC3 records, allowing validators to distinguish an authentic NXDOMAIN from forgery. NXDOMAIN synthesis by recursive resolvers or middleboxes (for captive portals, ads, or "search assistance") violates end-to-end DNS semantics and can interfere with DANE, certificate validation workflows, and application error handling. Negative caching follows RFC 2308 rules based on the SOA minimum/negative TTL.

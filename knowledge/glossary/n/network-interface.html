Guide / Glossary A–Z / Terms beginning with N / Network interface

A named connection point that the operating system uses to send and receive network traffic.

A network interface is like a doorway between your computer and a network. A laptop might have one doorway for Wi-Fi, another for a plugged-in cable, and an internal doorway (lo) that lets programs on the same machine talk to each other. Each doorway has a name so you and the system can tell which connection is which.

On Linux, you inspect interfaces with ip link and ip addr. Interfaces can be physical (like eth0 or wlan0, or predictable names like enp3s0) or virtual (like lo for loopback, tun0 for a VPN, or veth pairs for containers). Notice the difference between administrative state (UP, which you control) and operational carrier state (LOWER_UP, whether a cable or Wi-Fi association is actually present).

What does it mean if an interface shows UP in ip link but NO-CARRIER?

UP means the administrator or network manager enabled the interface, while NO-CARRIER means there is no physical or link-layer connection—such as an unplugged Ethernet cable or disconnected Wi-Fi. No packets can leave on the wire until a carrier is established.

In the Linux kernel, each network interface corresponds to a struct net_device registered in a network namespace, binding hardware or virtual driver callbacks (net_device_ops) to transmit/receive queues, MTU, and hardware offload flags (TSO, GSO, checksum offload). Routing tables (ip route) and neighbor caches (ip neigh) key off interface indices (ifindex), not names. A common nuance is that Linux follows the weak host model by default: an incoming packet for an IP assigned to eth0 may be accepted on eth1 unless rp_filter or policy routing restricts it.

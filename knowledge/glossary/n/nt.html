Guide / Glossary A–Z / Terms beginning with N / NT (Windows New Technology)

The hybrid kernel and operating system architecture underlying all modern versions of Microsoft Windows.

Think of Windows NT as the engine under the hood of Windows, separate from the dashboard and buttons you see on screen. Every modern Windows PC—from Windows XP to Windows 11—runs on this same core foundation, which manages memory, hardware, and running programs safely so one crashing app does not bring down the whole computer.

Unlike Linux’s monolithic kernel (where most drivers and filesystems run in kernel space) or pure microkernels (where drivers run in user space), NT uses a layered hybrid design: a Hardware Abstraction Layer (HAL) isolates board-specific hardware, while executive subsystems (I/O, memory, process, security) run in kernel mode alongside a small microkernel core. On Linux, you encounter NT concepts when mounting NTFS volumes, running Windows binaries under Wine/Proton (which reimplement NT’s Win32 and NTDLL interfaces), or interacting with SMB/Active Directory.

How does NT’s architecture differ from Linux’s kernel design?

Linux uses a monolithic kernel where core subsystems and most drivers share a single kernel address space. NT uses a hybrid design with an explicit Hardware Abstraction Layer (HAL) and modular executive subsystems, while keeping performance-critical components (including graphics/GDI since NT 4.0) in kernel mode rather than isolating all servers in user space.

Implemented in ntoskrnl.exe and hal.dll, the NT kernel separates mechanism (thread scheduling, interrupt/DPC/APC dispatch, synchronization primitives in the microkernel layer) from policy (Object Manager, Virtual Memory Manager, Process/Thread Manager, Security Reference Monitor, and asynchronous packet-driven I/O Manager using I/O Request Packets, or IRPs). System calls enter through ntdll.dll into the native NT API (Nt*/Zw* routines), above which environment subsystems—principally Win32 (kernel32.dll, user32.dll)—expose user-facing APIs. The IRP stack allows filter drivers (such as antivirus or encryption minifilters) to intercept and complete or pass down I/O asynchronously, a contrast to Linux’s VFS/bio model.

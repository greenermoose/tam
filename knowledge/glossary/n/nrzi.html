Guide / Glossary A–Z / Terms beginning with N / NRZI (Non-Return-to-Zero Inverted)

A signaling method that represents binary 0s and 1s by whether a signal switches state or stays the same at each clock beat.

Imagine tapping a light switch on each beat of a metronome: flipping the switch (up to down or down to up) means one digit, while leaving it alone means the other. Because the receiver only looks for changes rather than "high equals 1", both sides can still read the message even if the wire polarity is flipped or voltage levels drift slightly.

Used in USB 1.x/2.0 and 100BASE-FX Ethernet, NRZI contrasts with plain NRZ (where high voltage = 1 and low = 0). On a long run of "hold" bits (for example, consecutive 1s in USB), there are no transitions for the receiver to lock its clock onto, so USB inserts an extra transition-causing bit ("bit-stuffing") after six 1s in a row.

Why does USB pair NRZI with bit-stuffing?

Without periodic signal transitions, a receiver’s clock recovery circuit can drift out of sync with the sender during a long run of identical bits. Bit-stuffing guarantees a transition at least every seven bit times so the receiver stays locked onto the bit boundaries.

In USB 2.0 (D+/D− differential signaling, 0 = J/K state transition, 1 = no transition), bit-stuffing inserts a forced 0 after six consecutive 1s, trading up to ~16.7% worst-case bandwidth overhead and data-dependent jitter for bounded clock-recovery run length. Unlike Manchester encoding (which halves effective symbol rate by guaranteeing a mid-bit transition) or 4B/5B + NRZI in 100BASE-FX (which bounds run length at a fixed 25% overhead with deterministic timing and DC balance), raw NRZI is not DC-balanced and depends on higher-layer scrambling or block coding to avoid baseline wander.

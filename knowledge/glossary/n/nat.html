Guide / Glossary A–Z / Terms beginning with N / NAT (Network Address Translation)

A routing technique that rewrites source or destination IP addresses—and usually port numbers—as packets pass through a router or firewall.

Your home router usually gets only one public IP address from your internet provider, yet your laptop, phone, and TV can all browse the web at the same time. NAT works like a receptionist at a large office building: all outgoing mail goes out under the building’s single street address, and the receptionist keeps a notepad of who sent what so returning replies get delivered back to the right desk.

In typical home and container networks, outbound traffic uses Source NAT (SNAT, or MASQUERADE when the router’s public IP is dynamic) to replace private RFC 1918 addresses (such as 192.168.1.x or 10.x.x.x) with the router’s public IP and a tracked source port. Inbound port forwarding uses Destination NAT (DNAT) to rewrite the destination IP and port toward an internal server. Because NAT hides internal addresses behind one endpoint, inbound connections cannot reach a specific device unless a forwarding rule or hole-punching mechanism exists.

How does a home router know which internal device should receive a returning web-page packet when all devices share one public IP?

The router’s NAT connection-tracking table records each outbound flow’s original private IP, port, and translated public port, so incoming replies to that translated port are rewritten back to the matching internal device.

On Linux, NAT is implemented atop Netfilter’s nf_conntrack state machine inside nftables/iptables (nat table hooks at PREROUTING for DNAT and POSTROUTING for SNAT/masquerade): only the first packet of a flow hits the NAT rule chain, while subsequent packets—and related ICMP errors—are translated automatically via conntrack tuple expectations. Operational edge cases include port exhaustion under Carrier-Grade NAT (CGNAT), broken end-to-end connectivity for protocols that embed IP addresses inside application payloads (FTP, SIP, requiring fragile Application Layer Gateways), asymmetric routing failures when return packets bypass the stateful NAT box, and STUN/ICE traversal complexity for peer-to-peer UDP under symmetric (endpoint-dependent) NAT.

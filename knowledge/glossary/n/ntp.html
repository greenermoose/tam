Guide / Glossary A–Z / Terms beginning with N / NTP (Network Time Protocol)

A network protocol for keeping computer clocks synchronized to accurate reference time over a network.

Just like wristwatches slowly drift fast or slow, a computer’s internal clock gradually loses accuracy. NTP quietly checks trusted time servers over the internet and nudges your clock by tiny amounts so your timestamps match everyone else’s—preventing sudden jumps that could confuse running apps, and keeping secure websites and login tokens working properly.

Accurate time is essential on Linux: TLS/X.509 certificates, Kerberos tickets, DNSSEC signatures, and distributed log correlation all break if clocks drift by more than a few seconds or minutes. Modern Linux systems typically run chrony or systemd-timesyncd as an NTP client rather than the older ntpd; you can inspect sync status with chronyc tracking or timedatectl. Because standard NTP traffic is unauthenticated, NTS (Network Time Security) adds TLS key exchange and authenticated extension fields to prevent an attacker from spoofing time.

Why does NTP usually slew (gradually speed up or slow down) a clock instead of jumping it?

Sudden backward or forward jumps can break programs that rely on monotonic timestamps—causing build tools like Make to skip files, databases to corrupt transaction ordering, or log entries to appear out of sequence. Slewing adjusts the clock rate smoothly so time stays monotonic.

Defined in RFC 5905 over UDP port 123, NTP organizes servers into strata (Stratum 0 atomic/GPS clocks, Stratum 1 primary servers, down to Stratum 15) and estimates round-trip delay and offset using four timestamps (T1–T4) per exchange, assuming symmetric path latency. An intersection/clustering algorithm discards falsetickers, and a phase-locked/frequency-locked loop disciplines the local oscillator’s frequency skew (typically within milliseconds on WANs). Failure modes include asymmetric routing paths (introducing half the asymmetry as persistent offset error), unauthenticated amplification/spoofing attacks (mitigated by RFC 8915 NTS using AEAD-protected cookies and disabling monlist), and step thresholds when initial offset exceeds slewing limits (such as 128 ms in ntpd unless makestep is configured in chrony).

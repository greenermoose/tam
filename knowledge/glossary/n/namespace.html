Guide / Glossary A–Z / Terms beginning with N / Namespace

A Linux kernel mechanism that gives a group of processes its own isolated view of system resources such as process IDs, network interfaces, or mounted filesystems.

Normally, every program on a computer shares the same list of running tasks, the same network cards, and the same folder tree. A namespace acts like putting a program inside a private room with its own windows: from inside the room, it can only see its own tasks and its own network, even though it is still running on the same shared computer. This is the main building block that makes containers possible.

Linux provides eight namespace types—mnt (mount points), pid (process IDs), net (network stack), ipc (System V/POSIX IPC), uts (hostname/domain), user (UID/GID mappings), cgroup (cgroup root view), and time (boot/monotonic clocks). You can inspect a process’s namespaces under /proc/PID/ns/ or create temporary isolated environments with unshare and nsenter; note that namespaces only control what a process can see, whereas cgroups control how much CPU or memory it can use.

If you put a process in its own PID and network namespaces, does that automatically limit how much RAM or CPU it can consume?

No—namespaces only isolate visibility of resource identifiers (like PIDs and interfaces); enforcing CPU, memory, or I/O quotas requires cgroups alongside namespaces.

Each process holds a reference-counted struct nsproxy (plus a user_namespace pointer in its cred) created or switched via clone(2) flags (CLONE_NEW*), unshare(2), or setns(2) on /proc/PID/ns/* file descriptors. User namespaces enable unprivileged container creation by mapping an unprivileged host UID (for example alex at UID 1000) to UID 0 inside the namespace via /proc/PID/uid_map, granting capabilities scoped only to resources owned by that user namespace; kernel-level subtleties include hierarchical PID/user/cgroup namespaces (parent namespaces can see child PIDs), mount propagation interaction across mnt namespaces, and memory-accounting leaks if pinned ns file descriptors keep dead namespaces alive.

Guide / Glossary A–Z / Terms beginning with L / LZ4

LZ4 is a lossless data-compression format designed for extreme speed, trading a bit of file-size savings for near-instant compression and decompression.

Most compression tools, like creating a .zip archive, take a moment to squeeze files as small as possible. LZ4 takes the opposite approach: it focuses on being so fast that your processor barely notices the work, making it ideal when data needs to be shrunk and unpacked thousands of times per second—such as compressing memory in RAM or loading startup files during boot.

In Linux, LZ4 is widely used for zram compressed swap, kernel images, and initramfs archives because decompression speed often matters more than squeezing out the last few percent of size. Compared to zstd, LZ4 compresses less tightly but uses less CPU and memory, while lz4 -9 (high-compression mode) spends extra time compressing while keeping decompression just as fast. Tamlinux uses LZ4/zstd for fast compression where CPU latency matters more than squeezing out the last few percent of size.

Why is LZ4 a popular choice for initramfs and zram even though zstd or xz produce smaller outputs?

Both initramfs unpacking and zram page faults sit directly on the latency path—waiting for boot or waiting for a swapped memory page. LZ4 decompresses at multiple gigabytes per second per core, so the CPU finishes unpacking almost immediately instead of becoming the bottleneck.

LZ4 is a byte-aligned LZ77-family codec using a 64 KiB sliding window, 4-byte minimum match length, and a simple token format (4-bit literal length + 4-bit match length, optional extension bytes, raw literals, and 16-bit little-endian offset) with zero entropy-coding stage (no Huffman or ANS). Eliminating bit-level entropy decoding avoids branch mispredictions and bit-stream dependencies, enabling single-core decompression at several GB/s—often faster than reading uncompressed data from storage. Note the distinction between the raw block format (used in-kernel by zram/f2fs) and the framed format (lz4 CLI, magic 0x184D2204) with optional block/content xxHash32 checksums.

LLM (Large Language Model)

A neural-network model trained on large amounts of text to answer questions, summarize information, and assist with tasks such as writing code.

An LLM is a type of AI software that has learned patterns from huge collections of books, articles, and code so it can hold a conversation or draft text from a prompt. Rather than looking up fixed answers in a database, it predicts one word or piece of a word at a time—which makes it flexible, though it can still sound confident when it is wrong. On this system, local models can optionally be queried through Ollama via tam ask without sending your prompts to the cloud.

In Tamlinux, LLMs are strictly opt-in and run locally via Ollama (tam ask) rather than silently sending data to the cloud. Running a model locally keeps prompts on your own hardware and avoids external network dependencies, though response speed and quality depend heavily on your RAM/VRAM and model quantization. Because LLMs predict probable continuations rather than verifying facts, treat generated commands or code as drafts to check before running.

Why does running an LLM locally via Ollama differ in privacy and reliability from using a cloud-hosted model?

Local inference keeps prompts and context on your machine without sending data to third-party servers, and works offline. However, smaller local models constrained by local RAM or VRAM may be less accurate than large cloud models, and any LLM can still hallucinate plausible-looking commands that must be verified before execution.

Most modern LLMs are decoder-only Transformer architectures trained autoregressively to predict the next subword token given a context window, using multi-head self-attention and positional encodings (such as RoPE). Local runtimes like Ollama serve quantized weights (commonly GGUF formats with 4-bit or 8-bit integer quantization to fit consumer RAM or VRAM) over a local HTTP API, and tam ask invokes those local Ollama HTTP endpoints only on explicit user action. Inference cost scales with KV-cache memory across context length and memory-bandwidth bottlenecks during token generation, while output fidelity depends on sampling parameters (temperature, top-p) and prompt grounding.

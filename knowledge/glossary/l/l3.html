L3 cache (Level 3 / Last-Level Cache)

L3 cache (Level 3 cache, or Last-Level Cache) is a large on-die SRAM pool shared across CPU cores to reduce slow accesses to main RAM.

If L1 and L2 are each chef’s personal workstation, L3 is the shared cold-storage table in the middle of the kitchen that all the chefs can reach. It is bigger than L1 and L2 combined, and because every core shares it, one core can hand off data to another core through L3 without taking a slow trip out to main RAM.

Part of CPU caches, L3 often ranges from 16 MiB to 96 MiB or more (with roughly 40–70 cycles of latency) and acts as the Last-Level Cache (LLC) before main memory. On multi-chiplet processors, L3 may be shared per chiplet (CCX) rather than across the whole socket, which is why pinning communicating threads to cores that share the same L3 slice can noticeably improve throughput.

Besides holding more data than L1 and L2, what extra benefit comes from L3 being shared across cores?

Cores sharing an L3 cache can exchange shared data on-die through the cache rather than bouncing cache lines across external memory or inter-socket links.

As the Last-Level Cache (LLC), L3 is physically partitioned into slices distributed across a ring bus or 2D mesh interconnect, indexed via a hash of the physical address to spread traffic evenly. In many-core designs, the L3 slices also serve as the coherence directory / snoop filter for MESI/MOESI state across cores, tracking which private L1/L2 caches hold each line so invalidations target only the relevant cores. Notice the failure mode of LLC thrashing: streaming workloads or noisy neighbors can evict shared working sets unless mitigated with cache-allocation technology (such as Intel CAT / resctrl).

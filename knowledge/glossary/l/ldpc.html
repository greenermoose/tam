LDPC (Low-Density Parity-Check)

A high-efficiency error-correction code used to recover clean data from noisy signals in Wi-Fi, 10-gigabit Ethernet, and solid-state drives.

When data travels over noisy airwaves or sits inside worn flash memory chips, individual 0s and 1s can flip by mistake. LDPC adds carefully chosen check bits—like a giant Sudoku puzzle where every row and column must balance. Even if several bits get scrambled along the way, the receiver uses those cross-checks to pinpoint and fix the errors without asking for the data again.

As modern SSDs pack more bits into each flash cell and Wi-Fi 6/7 pushes higher speeds, raw bit errors rise sharply. Unlike older codes such as BCH, LDPC uses “soft” confidence values—how sure the hardware is about each bit—and refines its guesses over multiple passes to approach the Shannon channel limit.

How does an SSD controller’s LDPC decoder recover data that a simpler hard-decision code like BCH would fail to fix?

LDPC decoders can use soft-decision information—fine-grained voltage probabilities rather than just a binary 0 or 1 read—and pass confidence updates iteratively between check nodes, allowing correction at much higher raw bit-error rates.

A linear block code defined by a sparse parity-check matrix H and represented as a bipartite Tanner graph of variable and check nodes, decoded via iterative belief propagation (sum-product or hardware-friendly min-sum) on log-likelihood ratios (LLRs). Quasi-cyclic (QC-LDPC) matrices power IEEE 802.3an (10GBASE-T), IEEE 802.11ax/be (Wi-Fi 6/7), and modern TLC/QLC NAND flash controllers; key failure modes include error floors caused by short cycles and trapping sets in the Tanner graph, and read-latency spikes when NAND controllers escalate from hard-read LDPC to multi-threshold soft-decision LLR retries.

LZ77

A lossless compression method that replaces repeated text with references to earlier data in a sliding window.

If a file repeats the same phrase, LZ77 does not store the phrase again. Instead, it stores a short note like "go back 20 characters and copy 5." When the file is decompressed, that note is expanded back to the original text. This saves space without losing any information.

LZ77, published by Lempel and Ziv in 1977, is the basis for many practical compressors. DEFLATE combines LZ77-style matching with Huffman coding, and formats like gzip, PNG, and ZIP rely on it. LZ4 also uses LZ77-style backreferences but favors speed over maximum compression ratio. The "sliding window" limits how far back a match can refer, which affects both memory use and compression effectiveness.

Why can LZ77 compression make some encrypted or already-compressed files larger?

LZ77 needs repeated patterns to find matches. Random-looking or already-compressed data has few useful repeats, so the compressor adds overhead without finding much to shorten.

LZ77 encodes a stream as literals and (distance, length) match tokens referencing previously emitted bytes within a bounded window. In DEFLATE (RFC 1951), the window is 32 KiB and matches are 3-258 bytes; match/literal and distance symbols are then entropy-coded. LZ77-family designs trade compression ratio, speed, and memory by window size, hash-chain/HashTable match finding, lazy matching, and entropy stage choice. Because match length depends on secret content, LZ77-based compression in security-sensitive contexts can leak information through size side channels, as in CRIME/BREACH.

Guide / Glossary A–Z / Terms beginning with L / Line discipline

A kernel software layer between a TTY/PTY driver and user programs that handles line editing, character translation, and keyboard signals.

When you type in a basic terminal, Backspace erases the last letter, Enter sends the whole line, and Ctrl+C stops a runaway program. The raw keyboard or serial link only sends individual key codes one by one—it does not know how to edit a sentence. The line discipline is the kernel’s built-in helper in the middle, letting you fix typos before handing a finished line to the program, or tapping the program on the shoulder when you press Ctrl+C.

Linux’s default N_TTY line discipline supports two contrasting modes: in canonical (“cooked”) mode, used by simple tools like cat, the kernel buffers and edits each line until Enter; in raw/non-canonical mode, used by editors like vim or shells like bash, the program receives every keystroke immediately. If a raw-mode program crashes without restoring settings, stty sane resets the line discipline.

Why does pressing Ctrl+C in a terminal immediately interrupt a running program even if the program is busy and not reading input?

When the N_TTY line discipline’s ISIG flag is enabled, the kernel intercepts the Ctrl+C byte (0x03) as it arrives from the driver and sends a SIGINT signal directly to the foreground process group, without waiting for the program to call read().

The Linux TTY subsystem’s struct tty_ldisc_ops layer (default N_TTY in drivers/tty/n_tty.c) sitting between a tty_driver (UART, USB-serial, or PTY) and VFS read/write operations, configured via termios ioctls (TCGETS/TCSETS). It governs ICANON line buffering (4096-byte N_TTY_BUF_SIZE with VERASE/VKILL), ISIG signal generation (VINTR→SIGINT, VQUIT→SIGQUIT, VSUSP→SIGTSTP to the foreground PGID), ICRNL/OPOST/ONLCR translations, and VMIN/VTIME non-canonical timeouts; alternative disciplines such as N_PPP or N_HCI (switched via TIOCSETD) repurpose serial links for kernel-space packet framing.

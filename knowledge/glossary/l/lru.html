LRU (Least Recently Used)

LRU (Least Recently Used) is a replacement rule for caches and memory that discards whichever item has gone untouched for the longest time when space runs out.

Imagine a small desk where you keep the folders you are actively working on. When the desk is full and you need room for a new folder, you put away the one you have not opened for the longest time, assuming you are least likely to need it again soon. Computers use the same rule for fast memory and disk caches: instead of throwing away random data or the oldest file ever loaded, they keep recently used items handy and evict the ones sitting idle.

In Linux, the kernel’s page-reclaim subsystem separates pages into active and inactive lists (for both anonymous memory and file-backed page cache) so a single streaming read does not flush out hot working-set data. You can observe active and inactive memory counts in /proc/meminfo or via vmstat -s. Unlike FIFO (First-In, First-Out), which evicts purely by arrival time, LRU promotes items back to the front whenever they are accessed again.

Why can a large one-time file copy hurt a pure LRU cache, and how does Linux avoid that?

In a strict single-list LRU, reading a huge file once pushes every previously hot page out of the cache even though those file blocks will never be read again. Linux mitigates this with a two-list (or multi-generational) design: newly read pages enter the inactive list first and are only promoted to the active list if accessed a second time.

Exact LRU requires O(1) list manipulation on every access (typically a doubly linked list plus hash map), which creates prohibitive lock contention and cache-line bouncing on hardware page tables where reads do not trap into the kernel. Linux approximates LRU using the accessed/young PTE bit harvested lazily by kswapd and direct reclaim. Modern kernels (6.1+) replace the classic two-list split with Multi-Gen LRU (MGLRU), aging pages across multiple generations via page-table walks and bloom-filter/folio tracking to reduce thrashing and scan overhead under memory pressure.

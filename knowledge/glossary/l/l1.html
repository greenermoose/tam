L1 cache (Level 1 cache)

L1 cache (Level 1 cache) is the smallest, fastest memory buffer built directly into each CPU core, holding the instructions and data the core is actively executing.

Imagine a chef working at a stove: the L1 cache is the small cutting board right next to the pan holding the ingredients needed for the next few seconds. Because it sits right inside each CPU core, the processor can grab bytes from L1 almost instantly instead of waiting on slower main memory.

Part of CPU caches, L1 is split into two separate halves per core: L1i for instructions and L1d for data, typically 32–64 KiB each with roughly 4 cycles of access latency. Because each core has its own private L1, the CPU can fetch the next instruction and read or write data in the same clock cycle without the two streams colliding. You can inspect your system’s L1 sizes with lscpu.

Why is L1 cache split into L1i (instructions) and L1d (data) instead of using one combined buffer?

Splitting them lets the CPU’s front-end fetch instructions at the same time the execution units load or store data, avoiding port contention between code and data accesses.

L1 caches are private per-core SRAM arrays organized in a Harvard split (L1i + L1d), typically 8-way or 12-way set-associative with 64-byte cache lines. To hide address-translation latency, L1 is commonly virtually indexed and physically tagged (VIPT): the cache set index comes from page-offset bits (or handled alias bits) in parallel with the L1 TLB lookup, so tag comparison uses the physical frame number without stalling for a sequential TLB walk. Coherency across cores is maintained automatically by hardware (MESI/MOESI protocols) via cache-line invalidations.

Guide / Glossary A–Z / Terms beginning with L / LUKS - Linux Unified Key Setup

LUKS (Linux Unified Key Setup) is the standard format on Linux for encrypting whole disks and partitions.

If a laptop is stolen or an old drive is thrown away, anyone who plugs that drive into another computer can normally read every file on it. LUKS scrambles the entire drive so it looks like random noise without the right passphrase or recovery key. Once you type your passphrase at boot, Linux unlocks the drive transparently so your programs and files work just like normal.

LUKS stores a metadata header at the start of the block device containing the cipher parameters and up to several independent key slots. Because each key slot wraps the same underlying volume key, you can add a backup passphrase, a keyfile, or a hardware token with cryptsetup luksAddKey without re-encrypting the terabytes of data on the disk. You can inspect a device’s header and active slots with cryptsetup luksDump /dev/sdX.

Why can you change your LUKS passphrase almost instantly without re-encrypting the entire disk?

Your passphrase does not encrypt the disk sectors directly; instead, it encrypts a copy of the master volume key stored in one of the header’s key slots. Changing or adding a passphrase only updates that small key-slot entry, leaving the bulk data encrypted under the same volume key.

LUKS decouples user credentials from the bulk data-encryption key (typically AES-XTS-256 or 512-bit split keys) via a salted key-derivation function (PBKDF2 in LUKS1; Argon2id/Argon2i in LUKS2) and anti-forensic splitting (AF-splitter) that spreads each key-slot’s wrapped master key across multiple sectors so erasing a slot reliably destroys recovery. At unlock time, cryptsetup passes the unwrapped master key to the kernel’s dm-crypt device-mapper target via dm-ioctl; the header itself is plaintext metadata and must be backed up (luksHeaderBackup) because header corruption renders the entire volume unrecoverable.

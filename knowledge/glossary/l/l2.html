Guide / Glossary A–Z / Terms beginning with L / L2 cache (Level 2 cache)

L2 cache (Level 2 cache) is the mid-tier on-chip CPU cache that backs up L1, holding more instructions and data at slightly higher latency.

Continuing the kitchen analogy, if L1 is the cutting board right next to the pan, L2 is the prep counter right behind the chef. It holds much more than L1 and is still right inside the CPU core, so when something isn’t on the cutting board, the processor can grab it from L2 long before it has to walk out to the main RAM pantry.

Part of CPU caches, L2 is a unified cache (storing both code and data together) that typically ranges from 512 KiB to 2 MiB per core with around 12–15 cycles of latency. Unlike L1, which is always private to a single core, L2 is private on most desktop and server cores but often shared across a cluster of efficiency cores on hybrid CPUs. When a hot loop’s working set outgrows L1, staying inside L2 keeps performance high.

What happens when a CPU core needs a memory address that is not in L1, and how does L2 help?

An L1 miss stalls the load and queries L2; if the line is in L2 (an L2 hit), it is served in ~12–15 cycles instead of going out to L3 or main RAM (which takes tens to hundreds of cycles).

L2 is a unified, physically indexed and physically tagged (PIPT) SRAM array per core or core-cluster. Depending on microarchitecture, L2 may be inclusive, exclusive, or non-inclusive of L1—non-inclusive designs avoid duplicating L1’s capacity while still absorbing L1 evictions and hardware prefetcher streams. L2 also commonly houses the second-level unified TLB (STLB) and stream/stride prefetchers, acting as the primary buffer that absorbs burst misses before traffic reaches the shared interconnect and L3.

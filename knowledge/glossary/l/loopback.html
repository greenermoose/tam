Loopback

A virtual network interface that routes traffic from a machine directly back to itself without touching physical network hardware.

Even when a computer is not plugged into Wi-Fi or an Ethernet cable, programs on the same machine often talk to each other using network tools. The loopback interface is like an internal mailbox inside your own house: when an app sends a message to localhost (or 127.0.0.1), the system hands it straight back to another app on the same computer without ever sending it out over the internet.

On Linux, the loopback interface is named lo and is assigned 127.0.0.1/8 for IPv4 and ::1/128 for IPv6. Binding a local development server or database to 127.0.0.1 instead of 0.0.0.0 ensures only processes on the same host can connect, which is a common security boundary. Notice that 127.0.0.0/8 reserves over 16 million IPv4 addresses—not just 127.0.0.1—so 127.0.0.2 also loops back to the local host.

Why is binding a local service to 127.0.0.1 safer than binding it to 0.0.0.0?

127.0.0.1 listens only on the loopback interface, so traffic from external networks or other machines on the LAN cannot reach it. Binding to 0.0.0.0 listens on all interfaces, exposing the service to the network unless blocked by a firewall.

In the Linux kernel network stack, packets addressed to loopback (127.0.0.0/8 in IPv4, ::1/128 in IPv6) never leave the host or traverse a physical NIC; the lo driver’s loopback_xmit() immediately feeds the sk_buff back into the receive path via netif_rx(). Loopback supports a large default MTU (65,536 bytes on Linux) and checksum offloading because memory stays within the same kernel, though TCP/IP socket IPC still incurs full protocol-stack traversal and context switches compared to AF_UNIX domain sockets. Each Linux network namespace creates its own isolated lo device, which remains down until explicitly brought up.

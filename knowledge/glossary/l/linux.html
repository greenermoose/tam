Guide / Glossary A–Z / Terms beginning with L / Linux

Linux is a free operating-system kernel first written by Linus Torvalds in 1991. The name also means the complete computer systems that people build around that kernel.

Linus Torvalds was a student in Finland when he began Linux as a small hobby project, inspired by the Unix-like teaching system MINIX. He published the first version in 1991 and soon placed it under a free-software licence. The kernel is only the part that manages hardware and runs programs; a usable computer also needs commands, libraries and applications. Most of those came from the GNU project, so you will also see the name GNU/Linux. There is no single Linux desktop: different groups put the same kernel together with different tools.

Volunteers made the first complete distributions in the early 1990s by combining the kernel with GNU tools and the X11 display system. Slackware and Debian appeared in 1993, followed by Red Hat and SUSE in 1994. The families available today include Debian and Ubuntu, Fedora and Red Hat Enterprise Linux, Arch, openSUSE, and independent projects such as Alpine, Gentoo, Slackware, Solus and Void. Android uses the Linux kernel but not the usual GNU desktop. The Operating Systems Reference describes these families; Tamlinux uses Arch Linux as its rootstock today, with Void Linux planned. Linus Torvalds still decides which changes enter the main kernel. Developers send patches to subsystem maintainers, who review and merge them into their own trees. During a merge window the maintainers offer that work to Torvalds; release candidates and testing follow before the next final release. Stable and long-term teams backport fixes to older releases.

The kernel manages hardware and processes; each distribution chooses its own package manager, repositories, C library and init system. Those choices sit above the shared kernel.

Kernel development is a distributed, mailing-list-driven process. Torvalds created Git to maintain the kernel source, now mirrored at kernel.org; the MAINTAINERS file records who owns each subsystem and driver. Contributors send signed-off patches to the Linux kernel mailing list and subsystem lists, where reviewers test and improve them before a maintainer pulls them into a subsystem tree. After a roughly two-week merge window, release candidates are tested and a final release follows on a regular cadence. The stable and long-term series receive backported fixes. The kernel is licensed under GPL version 2; companies such as hardware vendors, distribution makers and cloud providers pay many of its contributors, while the Linux Foundation supplies infrastructure and volunteers supply much of the review. A complete system is an assembly of projects with separate owners. Firmware starts a bootloader, which loads the kernel and an initial RAM filesystem; the kernel then starts an init or service manager such as systemd, runit, OpenRC or dinit. Above it sit a C library (glibc or musl), core utilities (GNU Coreutils or BusyBox), a compiler toolchain (GCC or LLVM with binutils), a package manager (apt, dnf, pacman, apk or XBPS), a display stack (X11 or Wayland), a desktop such as GNOME or KDE Plasma, and applications. The GNU Project, the Linux Foundation, freedesktop.org, the GNOME and KDE foundations, the Qt Company, standards bodies such as IEEE, The Open Group and W3C, and many individual authors each own a layer. A distribution project such as the Debian or Fedora projects, the Arch Linux team or Canonical selects compatible versions, integrates and patches them, signs repository metadata and ships updates. Tamlinux follows the same pattern: an Arch Linux rootstock, the Tamlinux scion, and a Wayland compositor, with its own compositor planned.

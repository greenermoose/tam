libc (C standard library)

The standard C library that gives programs core functions for files, memory, text, and operating-system requests.

If a program is like a kitchen, libc is the basic utility hookup—running water, power, and standard measuring cups—that almost every recipe relies on. Instead of every program figuring out on its own how to ask the Linux kernel to open a file, reserve memory, or print text, it calls ready-made functions in libc, which handles the low-level details.

Most desktop Linux distributions use GNU libc (glibc), while containers and minimal images often use musl for smaller static binaries. Even programs written in Python, Rust, or Go frequently rely on libc for dynamic linking or DNS lookups, and running ldd /bin/ls shows which libc.so.6 an executable uses.

Why might a dynamically linked binary compiled on a newer Linux distribution fail on an older one with a “GLIBC_2.xx not found” error?

glibc uses symbol versioning to keep old binaries working on newer systems, but a binary compiled against a newer glibc can bind to newer versioned symbols that do not exist in the older system’s libc.so.6.

The userspace C runtime providing ISO C functions (malloc arena allocators, stdio buffering, locale/string routines), POSIX.1 interfaces, ELF startup/teardown glue (crt1.o, _start calling __libc_start_main before main), thread-local storage and pthread primitives, and architecture-specific syscall wrappers setting errno. glibc supports NSS dlopen plugins, iconv modules, and symbol versioning across releases, whereas musl targets static-friendly single-library simplicity and strict POSIX conformance, making the two ABI-incompatible for dynamically linked binaries.

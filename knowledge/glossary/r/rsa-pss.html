RSA-PSS (Probabilistic Signature Scheme)

RSA-PSS (Probabilistic Signature Scheme) is a randomized padding method for creating RSA digital signatures with strong, provable security guarantees.

When you sign a file with RSA, your computer first creates a short fingerprint (a hash) of the file and formats it before applying your private key. Older formatting methods always produce the exact same signature for the same file. RSA-PSS mixes in a fresh random number (a salt) each time you sign, giving stronger protection against mathematical forgeries.

Modern protocols such as TLS 1.3 require RSA-PSS (for example, rsa_pss_rsae_sha256) for RSA certificate and handshake signatures instead of legacy deterministic PKCS#1 v1.5, and in JWTs it corresponds to PS256/PS384/PS512. Signing the exact same document twice with RSA-PSS produces two different signatures because of the random salt, yet anyone holding the public key can verify both.

Why does signing the exact same file twice with RSA-PSS produce two different signatures, and why do both still verify?

RSA-PSS mixes a freshly generated random salt into the encoded message before signing. During verification, the verifier extracts that salt from the recovered signature block and checks that it hashes consistently with the file’s digest, so any valid salt verifies.

Standardized in PKCS#1 v2.2 (RFC 8017) as RSASSA-PSS, PSS combines the message digest, a random salt (typically matching the hash length, e.g., 32 bytes for SHA-256), and MGF1 masking into an encoded block EM before raising to d mod N. Unlike RSASSA-PKCS1-v1_5, RSA-PSS has a tight security reduction to the RSA problem proving EUF-CMA in the random oracle model. In X.509 certificates, general rsaEncryption keys can sign with PSS (rsa_pss_rsae_* in TLS 1.3), whereas dedicated id-RSASSA-PSS keys bind PSS hash and salt parameters directly into the public-key OID.

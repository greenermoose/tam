REPL (Read-Eval-Print Loop)

A REPL (Read–Eval–Print Loop) is an interactive programming prompt that reads one expression, evaluates it, prints the result, and loops back for the next.

Normally, writing a program means saving a file, running it, and reading the output. A REPL skips the file step and gives you a live conversation with the language: you type 2 + 2, press Enter, immediately see 4, and can test ideas one line at a time.

Common Linux REPLs include python3, node, lua, ghci, and nix repl. Many link against Readline or libedit for history and arrow-key editing, and store the last evaluated result in a special variable such as _ in Python. Unlike running a script file, a REPL keeps all variables and imports in memory across prompts until you exit.

Why can a snippet work inside a Python or Node REPL yet print nothing when saved and run as a script file?

A REPL automatically prints the return value of each evaluated expression (the “Print” step). When running a script file, expressions are evaluated without auto-printing, so you must explicitly call print() or console.log().

A language REPL wraps the runtime’s incremental parser (handling incomplete multi-line ASTs via continuation prompts), compiler/interpreter (bytecode or JIT evaluation), exception handler (preventing runtime errors from exiting the loop), and formatter (repr() vs str()). Implementing a robust REPL over a PTY requires careful handling of raw-mode line editing, async background output, and SIGWINCH resize signals, or decoupling UI from evaluation via protocols such as nREPL or Jupyter’s ZMQ wire protocol.

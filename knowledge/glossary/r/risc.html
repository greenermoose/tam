RISC - Reduced Instruction Set Computing

A processor design style that favors a small, regular set of simple instructions so hardware can decode and execute them rapidly.

Imagine two ways to build a kitchen: one with a few versatile tools like a sharp knife and a pan, and another with dozens of single-purpose gadgets. RISC takes the simple-tools approach for CPUs. By keeping each instruction short and predictable, the chip spends less circuitry figuring out what to do and more time actually running instructions.

In Linux and embedded computing, RISC architectures (such as ARM and RISC-V) contrast with CISC designs (such as x86). RISC processors typically use a load-store model: arithmetic instructions operate only on CPU registers, while separate load and store instructions move data to and from memory. Fixed-width instruction encodings and a large bank of general-purpose registers make it easier for compilers to schedule instructions and keep pipelines full.

In a load-store RISC architecture, can an ADD instruction read one operand directly from RAM?

No. Load-store designs separate memory access from arithmetic so every instruction has a predictable execution time and simple pipeline stage. The value must first be loaded into a register with a load instruction before ADD operates on it.

Classic RISC trades higher code density (more instructions per task, mitigated later by compressed encodings like Thumb-2 or RVC) for uniform 32-bit instruction decoding, single-cycle register-to-register execution, and simplified hazard detection. Modern high-performance x86 CISC cores actually translate variable-length macro-instructions into fixed-width internal micro-ops in hardware, blurring the microarchitectural boundary—though x86 still pays a front-end decode, power, and silicon-area penalty compared with native RISC front ends. On RISC platforms, compiler register allocation and instruction scheduling carry more responsibility for hiding load-use latency and avoiding pipeline stalls.

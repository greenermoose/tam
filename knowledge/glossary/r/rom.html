ROM - Read-Only Memory

Non-volatile memory that keeps its stored data or startup code even when the computer is powered off.

When you turn off a computer, its working memory (RAM) goes completely blank—like a whiteboard wiped clean at the end of the day. Yet when you press the power button again, the computer immediately knows how to wake up and check its hardware. It knows because those first instructions live in ROM, a permanent kind of memory that never forgets when the power goes out.

While classic ROM was written once at the factory, modern PCs and embedded devices store system firmware (such as UEFI or U-Boot) in electrically erasable flash ROM. Normal programs cannot overwrite it directly; updates require specialized flashing tools (such as fwupd on Linux) or dedicated hardware programmers, and the OS often mounts ROM-backed data read-only.

If UEFI firmware can be updated with a tool like fwupd, why is it still referred to as ROM or flash ROM?

Unlike RAM, it is non-volatile and cannot be written by ordinary memory-store instructions during normal operation. Reprogramming requires special erase-and-write command sequences, and hardware write-protection often locks critical regions after boot.

Historically spanning mask-programmed ROM, one-time-programmable PROM, UV-erasable EPROM, and byte-erasable EEPROM, modern “ROM” in computing is overwhelmingly NOR flash mapped into the CPU’s physical reset-vector address space (e.g., top of 4 GiB via SPI flash on x86). Because NOR flash supports execute-in-place (XIP) reads but requires block-level erase cycles before bit programming, firmware updates carry power-loss bricking risks mitigated by A/B redundant slots or SPI flash controller locks (such as Intel BIOSWE/BLE registers) that prevent OS-level tampering after PEI/DXE initialization.

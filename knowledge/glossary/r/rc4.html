RC4 (Rivest Cipher 4)

RC4 (Rivest Cipher 4) is an obsolete stream cipher with severe statistical biases that is now banned from modern security protocols.

A stream cipher scrambles data by mixing it with a long stream of random-looking bytes. RC4 was once wildly popular because it was fast and simple, powering early Wi-Fi and web encryption. Unfortunately, researchers found patterns in its output—like a shuffled deck of cards that is not truly random—allowing attackers to guess the secret data, so modern systems prohibit it completely.

In practice, RC4 failed famously in WEP Wi-Fi (where related initialization vectors let attackers recover the network key in minutes) and was banned from TLS by RFC 7465 in 2015 because attackers could recover repeated secrets such as HTTP session cookies. If you encounter RC4 in an old SSH, TLS, or Samba configuration, disable it and use AES-GCM or ChaCha20-Poly1305 instead.

Why was RC4 banned from TLS even though its key size (e.g., 128 bits) was not brute-forced?

RC4’s keystream is not uniformly random: specific bytes and byte-pair correlations are statistically biased. When the same secret (like a web cookie) is encrypted repeatedly across many connections, attackers can exploit those biases to recover the plaintext without brute-forcing the key.

Designed by Ron Rivest in 1987, RC4 maintains a 256-byte state permutation S initialized by the Key-Scheduling Algorithm (KSA) and stepped by the Pseudo-Random Generation Algorithm (PRGA). Fatal flaws include Fluhrer–Mantin–Shamir (FMS) key recovery when IVs are prepended directly to the key (breaking WEP), strong single-byte biases in the first 256 output bytes (e.g., byte 2 biased toward 0x00 at ~2/256 instead of 1/256), and Mantin’s ABSAB digraph biases exploited in the NOMORE TLS attacks.

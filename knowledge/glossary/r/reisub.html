REISUB (Magic SysRq emergency reboot)

REISUB is a six-key Linux Magic SysRq sequence that asks the kernel to sync disks and safely reboot a frozen system.

When a Linux computer freezes so badly that the mouse, Ctrl+Alt+Del, and terminal shortcuts do nothing, holding the power button can corrupt unsaved files on disk. REISUB is a built-in emergency brake: by holding Alt+SysRq (often Print Screen) and slowly typing R-E-I-S-U-B, you talk straight to the core of the operating system so it saves your disk data before restarting.

Each letter triggers a kernel action, remembered as “Reboot Even If System Utterly Broken”: r (unRaw keyboard from X/Wayland), e (tErminate processes with SIGTERM), i (kIll survivors with SIGKILL), s (Sync filesystems), u (Unmount/remount read-only), and b (reBoot). Wait a couple of seconds between s, u, and b so writes finish. Many distributions restrict SysRq by default; check sysctl kernel.sysrq (1 enables all functions; 176 enables sync, remount, and reboot).

Why should you pause briefly after pressing s and u before pressing b in the REISUB sequence?

Syncing dirty buffers (s) and remounting filesystems read-only (u) take time to flush pending writes to storage. Pressing b immediately resets the CPU before those disk operations complete, risking filesystem corruption.

Implemented in drivers/tty/sysrq.c, Magic SysRq intercepts keyboard scancodes at the input/VT layer (Alt+SysRq+<key>, or writes to /proc/sysrq-trigger) even when user space and the display server are deadlocked. Access is gated by the kernel.sysrq bitmask (0 disabled, 1 all, 16 sync, 32 remount-ro, 128 reboot/poweroff). On laptops where Print Screen shares a key with Fn or lacks a dedicated SysRq scancode, key-combo timing can prevent KEY_SYSRQ from registering, and REISUB cannot recover from a hard kernel panic or wedged storage controller interrupt.

RPM (RPM Package Manager)

RPM (RPM Package Manager) is a binary software package format (.rpm) and command-line tool used by Linux distributions such as Fedora, RHEL, and openSUSE.

On Linux, software is usually installed from packaged bundles rather than random installers downloaded from websites. An .rpm file is a sealed box containing a program’s files, instructions on where to put them, and a list of other packages it needs to run. It is one of the major Linux package formats, alongside Debian’s .deb and Arch Linux’s .pkg.tar.zst.

On Fedora or RHEL, users normally run higher-level tools like dnf (or zypper on openSUSE), which resolve dependencies from repositories and call rpm underneath to verify signatures and unpack files. You can inspect an uninstalled package with rpm -qpi file.rpm or list its contents with rpm -qpl file.rpm. By contrast, Tamlinux uses Arch’s pacman (.pkg.tar.zst) and never installs .rpm files directly.

Why do Fedora and openSUSE users normally run dnf or zypper instead of installing individual .rpm files directly with rpm -i?

The low-level rpm command only checks whether required dependencies are already installed and aborts if anything is missing, whereas dnf and zypper query configured repositories, download all missing dependencies automatically, and coordinate upgrades.

An .rpm archive pairs a lead and a GPG-signed metadata header (rich dependency capabilities such as Provides, Requires, Conflicts, and boolean expressions) with a compressed cpio payload (typically zstd or xz). Packages are built from .spec files via rpmbuild, recording file checksums, permissions, SELinux contexts, and lifecycle scriptlets (%pre, %post, %preun, %postun, and file triggers) in an SQLite-backed database under /var/lib/rpm. Unlike pacman or dpkg, RPM’s capability model allows dependencies on arbitrary file paths or shared-library sonames rather than only package names.

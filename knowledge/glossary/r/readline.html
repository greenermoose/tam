Readline

Readline is a software library that gives interactive command-line programs line editing, command history, and tab completion.

Without Readline, typing a command into a prompt feels like typing on a typewriter: you cannot press the Up arrow to reuse your last command, the Left arrow to fix a typo in the middle, or Tab to finish a long filename. Readline adds those familiar editing features so command-line tools feel responsive and forgiving.

GNU Readline powers bash, python3, gdb, and clients like psql. By default it uses Emacs-style shortcuts (Ctrl+A for start of line, Ctrl+E for end, Ctrl+R for reverse history search), which you can switch to vi mode or customize in ~/.inputrc. Tools linked against libedit behave similarly but read ~/.editrc instead.

If you add a custom keybinding to ~/.inputrc, why does it affect bash and gdb but not every interactive program?

Only programs linked against GNU Readline read ~/.inputrc. Tools that implement their own line editor (like zsh’s ZLE) or link against another library (like libedit) ignore ~/.inputrc and use their own configuration files.

GNU Readline puts the terminal into non-canonical mode via termios, queries terminfo/termcap capabilities to emit cursor-movement and clear-line escape sequences, and dispatches incoming bytes through hierarchical keymaps (emacs_standard_keymap, vi_insertion_keymap, vi_movement_keymap). Applications register custom rl_attempted_completion_function hooks and history expansion callbacks, while Readline’s GPLv3 license leads permissively licensed projects to choose libedit or linenoise instead.

Raw mode

Raw mode is a terminal input mode that sends every keystroke immediately to a program without kernel line editing or special signal handling.

Normally, when you type in a terminal, the system holds your characters until you press Enter so you can fix typos with Backspace. That is great for running commands, but it would break a full-screen text editor or a game where pressing an arrow key or q needs to work right away. Raw mode turns off that waiting room so the program sees every keypress the instant it happens.

Linux terminals default to canonical (“cooked”) mode, where the kernel buffers lines, echoes typed characters, and turns Ctrl+C into SIGINT. Programs like vim, less, or htop switch the terminal to raw mode (ICANON and ECHO off) so they can decode arrow-key escape sequences and draw their own UI. If a raw-mode program crashes without restoring terminal settings, your shell may stop echoing what you type—running reset or stty sane fixes it.

Why does pressing Ctrl+C inside some full-screen terminal programs not immediately kill them?

In raw mode, the ISIG flag is disabled, so the kernel terminal driver stops translating Ctrl+C into a SIGINT signal. Instead, the literal byte 0x03 is delivered to the program, which can ignore it, bind it to an editor action, or handle exiting itself.

POSIX cfmakeraw() clears IGNBRK, BRKINT, PARMRK, ISTRIP, INLCR, IGNCR, ICRNL, and IXON in c_iflag; OPOST in c_oflag; ECHO, ECHONL, ICANON, ISIG, and IEXTEN in c_lflag; sets CS8 and clears PARENB/CSIZE in c_cflag; and sets VMIN = 1, VTIME = 0 so read(2) returns on each byte. With OPOST off, newline no longer translates to CR+LF, and with ISIG and IXON off, interrupt and XON/XOFF bytes pass unmodified through the PTY line discipline.

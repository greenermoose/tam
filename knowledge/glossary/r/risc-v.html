RISC-V - Reduced Instruction Set Computing V

An open, royalty-free processor instruction set architecture (ISA) used to design CPUs ranging from tiny microcontrollers to server chips.

Think of an instruction set as the basic vocabulary a computer chip understands. For most popular chips, companies own that vocabulary and charge fees to use it. RISC-V is an open vocabulary that anyone—students, researchers, or hardware makers—can use to design their own processors without paying licensing fees.

Unlike monolithic instruction sets, RISC-V is modular: a chip starts with a small integer base (such as RV32I for 32-bit or RV64I for 64-bit) and adds only the standard extensions it needs, such as multiplication (M), atomics (A), floating point (F/D), or compressed 16-bit instructions (C). On Linux, uname -m reports riscv64, and user-space software typically targets the rv64gc profile (where G bundles IMAFD and Zicsr/Zifencei).

Why does a Linux distribution usually require extensions like A and C or G on top of RV64I?

RV64I alone lacks hardware multiplication, floating point, and atomic memory operations, which the Linux kernel and standard C libraries rely on for reasonable performance and thread synchronization. Targeting rv64gc gives a predictable baseline ABI.

RISC-V separates unprivileged ISA specifications from privileged modes (Machine M, Supervisor S, User U) and defines standard SBI (Supervisor Binary Interface) calls so an OS kernel does not hardcode platform timers or IPI hardware. All instructions are 32-bit aligned (16-bit when C is present), with 31 general-purpose registers plus hardwired-zero x0, and no condition-code flags—branches compare registers directly to avoid implicit register dependencies in out-of-order pipelines. A weak memory consistency model (RVWMO) requires explicit fence instructions around DMA and lock-free synchronization, while vector processing (RVV) uses vector-length-agnostic strip-mining rather than fixed-width SIMD registers.

Redirection

Redirection is the shell feature that changes where a command’s standard input comes from or where its output and error messages go.

Every command-line program normally reads from your keyboard and prints onto your terminal screen. Redirection lets you re-route those streams—sending a program’s output straight into a file to save a report, or feeding a saved file into a program instead of typing it all by hand.

In bash and POSIX shells, > overwrites a file with standard output (stdout, file descriptor 1), >> appends to it, < feeds a file to standard input (stdin, fd 0), and 2> captures errors (stderr, fd 2). A classic pitfall is sort file.txt > file.txt: the shell truncates file.txt before sort runs, leaving it empty.

Why does the order of > out.txt 2>&1 vs 2>&1 > out.txt matter in a shell command?

Redirections are evaluated left to right. > out.txt 2>&1 points fd 1 to out.txt first, then duplicates fd 1 into fd 2 so both go to the file. 2>&1 > out.txt points fd 2 to the original terminal first, then moves only fd 1 to out.txt.

Shells implement redirection in the forked child process prior to execve(2) by calling open(2) (e.g., O_WRONLY|O_CREAT|O_TRUNC for >) and dup2(oldfd, newfd) to replace descriptors 0, 1, or 2, closing the temporary descriptor afterward. O_APPEND (>>) is atomic per write(2) on local POSIX filesystems, >| overrides set -o noclobber, and process substitution (<(cmd)) passes /dev/fd/N or a named FIFO.

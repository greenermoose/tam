RAM - Random-Access Memory

Fast, temporary working memory that holds active programs and data while a computer is running, clearing its contents when power is turned off.

Think of RAM as your desk, while your SSD or hard drive is a filing cabinet. To run apps or edit files quickly, the computer pulls them out of the cabinet and spreads them on the desk; a bigger desk lets you keep more open at once without shuffling files back and forth, and everything on the desk clears when you shut down.

On Linux, tools like free -h show both memory used by programs and memory borrowed for the kernel’s disk page cache, which speeds up repeated file reads. When physical RAM fills up, the kernel moves inactive pages to swap (or compressed zram) before resorting to the Out-Of-Memory (OOM) killer.

Why does free -h often show very little “free” RAM on a healthy Linux system?

Linux uses otherwise idle RAM as a disk page cache to speed up file access; that cached memory counts toward “available” RAM because the kernel can reclaim clean cache pages instantly whenever an application needs memory.

Main system RAM is typically synchronous DRAM (DDR4/DDR5), storing bits as charge in capacitors that require periodic refresh (tREFI) and row-activation/precharge cycles across multi-channel buses. On multi-socket systems, NUMA topology makes remote-node DRAM access slower than local-node access; under memory pressure, Linux page reclaim balances anonymous vs. file-backed LRU lists, transparent huge pages (THP), and Pressure Stall Information (PSI).

RIP (Instruction Pointer Register)

The 64-bit Instruction Pointer register on x86_64 processors that holds the memory address of the next instruction to execute.

A processor runs a program one small step at a time, like reading a recipe line by line. RIP is the CPU’s built-in bookmark: it stores the exact memory address of the next instruction the processor is about to run, moving forward automatically after each step—or jumping to a new address when a program calls a function or takes a branch.

On modern Linux systems, programs are compiled as Position-Independent Executables (PIE) so ASLR can load them at a randomized address each time they start. Because the program does not know its fixed memory address ahead of time, x86_64 instructions use RIP-relative addressing (such as lea rax, [rip + offset]) to find global variables and strings relative to the current instruction’s location. When inspecting a crash in gdb or a kernel oops, the saved RIP value tells you which exact instruction failed.

Why does RIP-relative addressing make Position-Independent Executables (PIE) faster on x86_64 than on older 32-bit x86?

x86_64 supports addressing memory directly as an offset from RIP in a single instruction, whereas 32-bit x86 lacked IP-relative data addressing and had to waste a general-purpose register and extra call/pop instructions to compute its own address.

RIP (the 64-bit extension of EIP/IP) cannot be read or written directly by normal mov instructions; it is updated implicitly by sequential instruction fetch, control-flow instructions (jmp, call, ret), and interrupts/exceptions (which push the return RIP onto the stack or save it in RCX/SYSENTER MSRs). In 64-bit mode, ModR/M encoding mod=00, rm=101 specifies a signed 32-bit displacement relative to the next instruction’s RIP (after the current instruction’s length), limiting direct RIP-relative reach to ±2 GiB—which is why the x86_64 small code model constrains code and static data within a 2 GiB window and why control-flow hijacking targets saved return addresses or function pointers to redirect RIP.

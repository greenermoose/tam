RPKI (Resource Public Key Infrastructure)

RPKI (Resource Public Key Infrastructure) is a cryptographic system that lets routers verify which networks are authorized to announce given IP address prefixes over BGP.

Normally, internet routing works a bit like an honor system: any large network can announce “send traffic for these IP addresses to me,” and neighboring networks often trust that claim. Mistakes or malicious announcements can misdirect traffic (a route hijack). RPKI adds a verifiable digital permission slip so routers can check whether a network actually owns or is authorized to announce the IP addresses it claims.

IP address blocks and Autonomous System Numbers (ASNs) are delegated hierarchically from IANA to Regional Internet Registries and then to operators. An operator publishes a signed Route Origin Authorization (ROA) stating which ASN may originate a prefix and up to what maximum prefix length (maxLength). Routers query a local relying-party validator (such as Routinator or rpki-client) over the RTR protocol to mark BGP routes as Valid, Invalid, or NotFound, typically dropping Invalid routes.

In BGP Route Origin Validation, why do operators usually drop Invalid routes but still accept NotFound routes?

An Invalid route actively contradicts a published ROA (wrong origin ASN or more specific than maxLength), indicating a hijack or misconfiguration. A NotFound route simply has no covering ROA yet, so dropping it would break reachability to networks that have not deployed RPKI.

Defined in RFC 6480 and companion specifications, RPKI binds X.509 resource certificates (RFC 3779 IP/ASN extensions) to signed objects (ROAs, manifests, CRLs) fetched via RRDP or rsync by relying-party caches and delivered to BGP speakers over RPKI-to-Router (RFC 8210). Key failure modes include overly broad maxLength values enabling forged sub-prefix hijacks, expired or unreachable publication points causing ROAs to fall back to NotFound, and the scope boundary of origin validation: RPKI alone cannot detect path-spoofing where an attacker prepends the legitimate origin ASN (which requires BGPsec or ASPA).

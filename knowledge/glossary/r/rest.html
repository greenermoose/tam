REST (Representational State Transfer)

REST is a common style for a web API: a URL names a thing, and an HTTP method says what to do with it.

A REST API is like a library catalogue with ordered forms. You ask for a book's card, add a new card, replace one, or remove one, using a different verb each time.

GET usually reads a resource, POST creates one, PUT replaces one and DELETE removes one. The reply carries a status code such as 200 for success or 404 for a missing resource.

Why should GET not change server data?

Browsers, caches and link prefetchers may repeat a GET without asking. A state-changing action belongs in POST, PUT or DELETE so retries and caching do not create duplicate effects.

REST constraints include client-server separation, stateless requests, cacheable responses and a uniform interface. Idempotent methods such as PUT and DELETE can be retried safely; POST generally cannot. Good designs version breaking changes and return enough links or identifiers for a client to continue.

RFC (Request for Comments)

A numbered technical document series published by the IETF and partner bodies to specify internet protocols, formats, and operational practices.

For computers made by different companies to talk to each other over the internet, everyone has to follow the same rules—just like traffic laws or standard electrical outlets. An RFC is a free, numbered rulebook that writes those technical agreements down in public so any programmer can build compatible software.

Despite the historical name “Request for Comments,” published RFCs are permanent and never edited after release; if a protocol changes, a newer RFC is published that updates or obsoletes the older number. Not every RFC is a mandatory standard—some are informational notes or April Fools’ jokes—so you should check an RFC’s status header before treating it as a specification. Most protocol RFCs come from the IETF. See The IETF and how RFCs work.

If you find a bug in a published RFC, how does the IETF fix the specification?

Published RFCs are immutable and never overwritten; minor fixes are recorded as separate errata, and substantive changes are published as a brand-new RFC that marks the older one as updated or obsoleted.

An archival publication series administered by the RFC Production Center under RFC 9280 across four independent streams (IETF, IAB, IRTF, and Independent). Each RFC receives an immutable number and a category—Standards Track (Proposed Standard or Internet Standard), Best Current Practice (BCP), Informational, Experimental, or Historic—alongside machine-readable Updates and Obsoletes metadata. Working drafts circulate as time-limited Internet-Drafts before stream approval; implementations must also consult the RFC Editor errata database because verified technical errata are not folded into the original document text. See The IETF and how RFCs work.

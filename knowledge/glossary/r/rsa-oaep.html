Guide / Glossary A–Z / Terms beginning with R / RSA-OAEP (Optimal Asymmetric Encryption Padding)

RSA-OAEP (Optimal Asymmetric Encryption Padding) is a randomized padding scheme used with RSA to encrypt small payloads, such as symmetric keys, safely.

Encrypting a message directly with raw RSA math is unsafe: encrypting the same short secret twice produces the exact same scrambled output, and attackers can probe for patterns. RSA-OAEP mixes the message with fresh random data before applying RSA, so encrypting the same secret twice looks completely different each time and hides any patterns.

Because RSA can only encrypt a payload smaller than its key size (around 190 bytes for a 2048-bit key using OAEP with SHA-256), real systems use RSA-OAEP for hybrid encryption—encrypting a random AES key that protects the actual file or stream. Legacy PKCS#1 v1.5 encryption padding should be avoided because it has suffered repeated padding-oracle attacks (Bleichenbacher, ROBOT) that let attackers decrypt ciphertexts from error responses or timing.

Why is RSA-OAEP used to encrypt a small symmetric AES key rather than encrypting a 10 MB file directly?

RSA-OAEP can only encrypt a single block smaller than the RSA modulus (minus padding and hash overhead), and RSA math is orders of magnitude slower than AES, so RSA-OAEP wraps a small symmetric key that handles the bulk data.

Specified in PKCS#1 v2.2 (RFC 8017) from Bellare and Rogaway’s construction, RSA-OAEP applies a two-round Feistel transform using a mask generation function (commonly MGF1 over SHA-256), a fresh random seed, and an optional domain-separation label before modular exponentiation, achieving IND-CCA2 security in the random oracle model. Implementations must still unpad in constant time and return a uniform error without distinguishing label-hash mismatches, missing 0x01 separators, or non-zero leading bytes, otherwise side channels reintroduce Manger-style chosen-ciphertext oracles.

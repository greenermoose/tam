Root filesystem

The primary filesystem mounted at / that supplies the operating system’s core directories, libraries, and startup program.

When a computer turns on, it needs a main storage area that holds the operating system itself—the core programs, settings, and tools required to start up and show a login screen. That main storage area, attached at the very top of the folder tree (/), is the root filesystem.

The root filesystem holds essential directories such as /etc, /usr, and /bin, and you can inspect what device or subvolume provides it by running findmnt /. Other filesystems—like /home, /boot, or external drives—can live on separate partitions and be mounted onto directories inside the root filesystem during boot.

Can /home live on a completely different disk from the root filesystem?

Yes. The root filesystem only needs what is required to boot and mount the rest of the system; separate partitions or disks can be mounted onto subdirectories like /home once the root filesystem is mounted.

During Linux boot, the kernel first unpacks an in-memory initramfs (tmpfs/ramfs) as a temporary rootfs so early user space can load storage/encryption drivers (LUKS, LVM, RAID, Btrfs) and locate the real root device specified by root= on the kernel command line. Once mounted, switch_root (or pivot_root) transitions PID 1 to the real root filesystem—which may be a disk partition, a Btrfs subvolume, an immutable squashfs/erofs image, or an NFS mount—and frees the initramfs memory. Separating an immutable or read-only root filesystem from mutable /var or /home mounts prevents user data growth from exhausting root space and simplifies atomic OS updates.

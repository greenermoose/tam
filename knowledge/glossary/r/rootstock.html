Rootstock

In Tamlinux, rootstock means the base operating system installed on a host beneath the Tamlinux scion.

Rootstock is a gardening term that Fred uses to explain how Tamlinux is built. In horticulture, a rootstock is the root system and lower stem onto which another plant is grafted, supplying water, nutrients, and physical stability. In Tamlinux, the rootstock is the base operating system—such as Arch Linux, Void Linux, Windows, or macOS—installed on a host. The Tamlinux bud is installed on the rootstock and used to grow the full Tamlinux scion on top. Keeping the rootstock small and fast helps the whole computer run smoothly.

Currently Tamlinux uses Arch Linux as its rootstock, with plans to migrate to Void Linux in future versions and longer-term exploration of a microkernel to shrink the base even further. Notice the separation of roles: the rootstock’s native package manager maintains hardware drivers and core libraries, while the Tamlinux scion installs on top without altering the base distribution’s files.

Why does Tamlinux separate the rootstock from the scion instead of modifying the base distribution’s core files directly?

Keeping the scion separate means upstream rootstock updates—such as kernel or driver upgrades—can be applied cleanly or even swapped for another base like Void Linux without untangling custom edits mixed into core system directories.

The rootstock provides hardware drivers, kernel services, init/service supervision, and core system libraries under its native package manager (such as pacman on Arch or xbps on Void). The Tamlinux scion installs on top of this foundation without modifying distribution-managed files under /usr. Minimizing rootstock code size shrinks the trusted computing base (TCB), reduces background memory and power overhead, and eases future migration toward leaner init systems or microkernel-based isolation.

Rootstock

In Tamlinux, rootstock means the underlying operating system, kernel, and core system software on which the cultivar software depends.

Rootstock is not a common computing term, but a gardening analogy that Fred uses to explain how Tamlinux is built. In horticulture, a rootstock is the hardy root and lower stem that supports a grafted plant. In Tamlinux, the rootstock is the third-party base system—hardware support, the kernel, and essential system tools—that the cultivar software sits on top of so both humans and AI agents can work efficiently. Keeping the rootstock small and fast helps the whole computer run smoothly.

Currently Tamlinux uses Arch Linux as its rootstock, with plans to migrate to Void Linux in future versions and longer-term exploration of a microkernel to shrink the base even further. Notice the separation of roles: the rootstock’s native package manager maintains hardware drivers and core libraries, while the cultivar layer provides Tamlinux’s own tools without altering the base distribution’s files.

Why does Tamlinux separate the rootstock from the cultivar instead of modifying the base distribution’s core files directly?

Keeping the cultivar separate means upstream rootstock updates—such as kernel or driver upgrades—can be applied cleanly or even swapped for another base like Void Linux without untangling custom edits mixed into core system directories.

The rootstock provides hardware drivers, kernel services, init/service supervision, and core system libraries under its native package manager (such as pacman on Arch or xbps on Void). The Tamlinux cultivar layer installs on top of this foundation without modifying distribution-managed files under /usr. Minimizing rootstock code size shrinks the trusted computing base (TCB), reduces background memory and power overhead, and eases future migration toward leaner init systems or microkernel-based isolation.

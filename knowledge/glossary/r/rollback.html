Guide / Glossary A–Z / Terms beginning with R / Rollback

A controlled return to an earlier working state using a matching recovery procedure.

If you install a new app or change a setting and your computer starts misbehaving, a rollback is like hitting an undo button for the whole change. Instead of trying to fix every broken piece by hand, you switch back to the earlier setup that you already know works.

A rollback only works reliably when the recovery layer matches what was changed: native system packages, a recorded product assembly, or a user-tool selection each have their own rollback mechanism. Reverting only your user profile will not undo a broken system-wide package change, and vice versa.

If a system-wide update breaks networking, will rolling back only your user-level Home Manager generation fix it?

No. The recovery layer has to match the layer that changed. A user-level generation only restores user tools and configuration, so a system-wide change requires rolling back at the system or snapshot layer.

Switching to an earlier immutable generation atomically flips profile symlinks and user-space binaries, but it does not automatically revert mutable state (such as /var databases, home-directory caches, or schema-migrated configs) or firmware and bootloader state. A complete recovery contract separates immutable store generations from copy-on-write filesystem snapshots and documents any non-transactional boundaries—like NVRAM boot variables or external hardware firmware—that cannot be rolled back by switching generations alone.

Regular expression

A regular expression (regex) is a compact pattern language used to search, match, or transform text.

Instead of searching for one exact word like “cat”, a regular expression lets you describe a rule—such as “any four-digit year” or “a line that starts with Error”. Text editors, search tools, and scripts use these patterns to find, validate, or clean up text in seconds instead of by hand.

Tools like grep, sed, awk, and ripgrep use regexes every day, but syntax varies by flavor: POSIX Basic (grep) treats + and () as literal characters unless escaped, whereas Extended (grep -E) and PCRE (grep -P, Python) treat them as quantifiers and groups. Always quote regexes in the shell (e.g., grep -E '^[0-9]+' file) so the shell does not expand * or ? as filename globs first.

Why can grep 'a+b' file.txt fail to match aaab even though + means “one or more” in most regex guides?

By default, grep uses POSIX Basic Regular Expressions (BRE), where + matches a literal plus sign. Use grep -E 'a+b' (Extended Regular Expressions) or escape it as grep 'a\+b' so + acts as a quantifier.

Formally, pure regular expressions describe Type-3 regular languages recognized by deterministic or non-deterministic finite automata (DFA/NFA) in linear O(n) time (as in grep, re2, and Rust’s regex crate). Adding backreferences (\1) or lookaround moves engines like PCRE, Perl, and Python re beyond regular languages into backtracking NFAs, which can suffer catastrophic exponential backtracking (O(2^n)) on ambiguous nested quantifiers like (a+)+b—a common ReDoS vulnerability.

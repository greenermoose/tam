Guide / Glossary A–Z / Terms beginning with R / Runlevel

A traditional numbered system state in Unix-like operating systems that determines which services and login modes are active.

Think of runlevels like modes on a machine—such as "off", "maintenance mode", or "normal desktop mode". Older Linux systems used a single number to switch between starting only a basic repair screen, starting text-only multi-user logins, or starting the full graphical desktop.

In traditional SysV init, runlevels 0 through 6 each meant a specific state: 0 halted the system, 1 entered single-user rescue mode, 2–5 ran multi-user services (with 5 typically starting the graphical display manager on Red Hat-style distributions, while Debian used 2 for everything), and 6 rebooted. Modern systemd-based distributions replace runlevels with named targets such as multi-user.target and graphical.target, though commands like runlevel or telinit still exist as compatibility shims.

Why does running systemctl get-default return a target name instead of a number on modern Linux?

Systemd models boot states as dependency graphs of units called targets rather than a fixed sequence of numbered scripts, allowing parallel startup and cleaner service dependencies while keeping compatibility aliases like runlevel5.target.

Under SysV init, /etc/inittab defined the default runlevel (initdefault) and mapped each level to /etc/rcN.d/ symlinks executed sequentially by rc via S* (start) and K* (kill) prefixes. Systemd preserves backwards compatibility through systemd-sysv-generator and target aliases (runlevel0.target → poweroff.target, runlevel1.target → rescue.target, runlevel3.target → multi-user.target, runlevel5.target → graphical.target, runlevel6.target → reboot.target), while recording transitions in utmp/wtmp so legacy runlevel queries continue to report previous and current states.

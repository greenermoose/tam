Guide / Glossary A–Z / Terms beginning with R / RSA-3072

RSA-3072 is RSA public-key cryptography configured with a 3072-bit modulus, providing roughly 128 bits of security against classical computers.

In RSA, the key size—such as 2048 or 3072 bits—measures how huge the lock’s secret prime numbers are. As computers get faster, attackers can chip away at smaller keys, so recommended sizes have grown over time. RSA-3072 is a stronger, longer-term key size chosen when certificates or encrypted data need to stay protected for many years.

NIST estimates that RSA-2048 gives about 112 bits of classical security, whereas RSA-3072 reaches 128-bit classical security—matching AES-128 and SHA-256. You can generate one with openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:3072. The trade-off is size and speed: RSA-3072 keys and signatures are 384 bytes long and private-key operations are noticeably slower than RSA-2048, whereas elliptic-curve keys like P-256 or Ed25519 achieve 128-bit classical security with 256-bit (32-byte) keys.

Why do many modern TLS and SSH deployments choose Ed25519 or P-256 over RSA-3072 when both provide ~128-bit classical security?

RSA-3072 requires 3072-bit keys and heavy modular exponentiation during signing or decryption, whereas Ed25519 and P-256 reach ~128-bit classical security with 256-bit keys, smaller certificates and signatures, and much faster signing and key generation.

RSA-3072 uses a modulus N = pq of 3072 bits (two ~1536-bit primes). Because the General Number Field Sieve (GNFS) factors integers in sub-exponential time, security scales sub-linearly with key length: increasing from 2048 to 3072 bits raises classical security from ~112 to ~128 bits while roughly tripling private-key CRT modular exponentiation cost (~O(k³)). Like all RSA key sizes, RSA-3072 offers no protection against a sufficiently large fault-tolerant quantum computer running Shor’s algorithm, which factors N in polynomial time.

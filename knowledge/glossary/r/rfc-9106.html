RFC 9106 (Argon2)

The IETF specification for Argon2, a modern memory-hard function for hashing passwords and deriving keys from passphrases.

Websites and encrypted disks should never store your password as plain text; instead, they scramble it into a one-way fingerprint. Old scrambling methods are easy for attackers with fast graphics cards to guess millions of times per second. RFC 9106 defines Argon2, a modern standard that forces each guess to use a chunk of memory as well as processing time, making mass password guessing slow and expensive.

When configuring disk encryption (such as LUKS2) or application authentication on Linux, Argon2id is typically recommended over older algorithms like PBKDF2. Because Argon2id requires configurable RAM in addition to CPU iterations, attackers cannot cheaply parallelize guesses on GPUs or custom ASICs. Tuning its memory cost too high on a low-RAM machine, however, can cause out-of-memory failures when unlocking a disk at boot.

Why does Argon2id resist GPU password-cracking attacks much better than SHA-256 or PBKDF2?

GPUs have thousands of fast arithmetic cores but limited per-core memory bandwidth; forcing each password guess to fill and read megabytes of RAM makes GPU parallelization prohibitively expensive.

IETF RFC 9106 (2021) specifies three variants: Argon2d (data-dependent memory indexing, maximizing resistance to time-memory trade-off attacks but vulnerable to cache-timing side channels), Argon2i (data-independent indexing, resisting side channels at slightly lower TMTO resistance), and Argon2id (hybrid: data-independent for the first half of the first pass, then data-dependent). Parameters include memory cost m (in KiB), time cost t (passes), parallelism p (lanes/threads), salt, and tag length. RFC 9106 recommends Argon2id as the default for general password hashing and key derivation, balancing side-channel safety with GPU/ASIC resistance.

Router

A router is a networking device that connects separate networks and forwards data packets between them toward their destination.

Think of a router like a postal sorting office. Devices on your home Wi-Fi are like houses on one street, while websites live in distant cities. When your computer sends data, the router reads the destination address on each packet and sends it along the best next road—keeping local traffic inside your network or passing external requests out to your internet provider.

Unlike a network switch, which forwards frames within a single local network using MAC addresses, a router operates at the IP layer and connects different subnets. On Linux, you can inspect routing decisions with ip route, and any Linux host can act as a router by enabling IP forwarding (net.ipv4.ip_forward=1). At each hop, a router decrements the packet’s time-to-live (TTL) by 1 and rewrites the link-layer (Ethernet) header for the next hop while preserving the source and destination IP addresses (unless NAT is applied).

Why does a router rewrite a packet’s Ethernet MAC addresses at every hop while leaving the destination IP address unchanged?

MAC addresses only identify devices on the immediate local link (one hop), whereas IP addresses identify the end-to-end sender and receiver across the full path. Each router strips the incoming frame header and wraps the IP packet in a new frame addressed to the next hop’s MAC address.

A modern router separates its control plane—which runs routing protocols (OSPF, IS-IS, BGP) or static rules to populate the Routing Information Base (RIB)—from its forwarding plane, which compiles longest-prefix-match routes into a hardware- or kernel-optimized Forwarding Information Base (FIB) paired with an adjacency table (ARP/NDP next-hop L2 rewrites). Operational edge cases include asymmetric routing, ICMP Time Exceeded generation when TTL reaches zero, Path MTU Discovery blackholes when ICMP Fragmentation Needed is filtered, and microburst queue drops under ECMP hash polarization.

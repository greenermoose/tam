Retirement

Removing a temporary software patch and its local packaging once the official release includes the fix.

Sometimes you have to apply a temporary fix to a program while waiting for the original developers to release an official update. Once that official update arrives with the real fix, you no longer need your temporary workaround. Retirement is the cleanup step that removes the temporary fix so your system goes back to using the standard version cleanly.

Carrying a local patch only works as long as it is needed; leaving it around after upstream ships the fix can pin an older version or mask future security updates. During retirement, the local repository files, any guard hook that prevented accidental overwrites, and the tracking status files are removed so normal package updates resume from upstream.

Why is it important to retire a temporary patch once upstream releases the fix?

Keeping a local patched package active after upstream includes the fix can block newer upstream updates or reintroduce older bugs, because the local override continues taking precedence.

Retirement is the automated teardown of a carried patch’s local build artifacts, repository entry, guard hook, and tracking status once version comparison (vercmp) confirms that the upstream package version meets or exceeds the fixed release. Removing the local repo entry and guard hook atomically avoids a window where an unpatched or stale local build shadows upstream, while preserving clean upgrade ordering in the package manager’s dependency and version resolution.

Guide / Glossary A–Z / Terms beginning with R / Register

A register is a tiny, ultra-fast storage location built directly inside a processor to hold data the CPU is actively working on.

If system memory (RAM) is like a filing cabinet across the room and the hard drive is a warehouse down the street, registers are the few sticky notes right in your hands. A CPU can only do math on values sitting in its registers, so it constantly pulls numbers from RAM into registers, calculates a result, and writes it back out.

Registers sit at the very top of the memory hierarchy—accessing one takes less than a single clock cycle, compared to dozens or hundreds of cycles for RAM. On x86-64 Linux, general-purpose registers like rax, rdi, and rsi pass function arguments and return values, while special registers like rip (instruction pointer) and rsp (stack pointer) track where the program is executing.

Why can’t a CPU just have gigabytes of registers instead of needing RAM?

Registers use fast, multi-ported SRAM flip-flops wired directly into the CPU’s execution units and must be named directly in short machine instructions. Making the register file huge would slow down access times, bloat instruction encodings, and consume massive chip area and power.

Architectural registers (16 64-bit GPRs in x86-64, 31 in AArch64) are the ISA-visible names defined by the ABI (e.g., System V AMD64 ABI: rdi, rsi, rdx, rcx, r8, r9 for integer arguments; rax for return values and syscall numbers). Internally, out-of-order superscalar CPUs map these onto a larger Physical Register File (PRF) via register renaming (RAT) to eliminate false Write-After-Read and Write-After-Write hazards.

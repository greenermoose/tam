XNU (X is Not Unix)

The open-source hybrid kernel powering macOS, iOS, iPadOS, watchOS, and tvOS.

A kernel is the core traffic controller of an operating system, managing memory, hardware, and running programs. Apple’s XNU kernel is called a “hybrid” because instead of being built from one single blueprint, it combines pieces from two different designs—a message-passing core and a traditional Unix layer—into one fast engine that runs Macs and iPhones.

Unlike the monolithic Linux kernel, XNU pairs a Mach microkernel core (handling threads, virtual memory, and inter-process communication) with a FreeBSD-derived layer (providing POSIX system calls, VFS, and the network stack) inside the same kernel address space. Running both in ring 0 avoids the heavy context-switch overhead of pure microkernels while still exposing Mach ports and BSD sockets side by side.

Why does XNU run Mach and BSD components in the same kernel address space instead of as separate user-space servers?

In a pure microkernel, every file read or network call requires passing messages across user/kernel boundaries, which adds latency. Placing Mach, BSD, and drivers in one address space lets them call each other directly for speed while keeping modular internal interfaces.

XNU integrates a modified Mach 3.0 core (tasks, threads, Mach ports, IPC, and VM objects/pmap), a BSD subsystem (POSIX syscalls, vnode/VFS, mbuf networking, and MAC framework hooks for Sandbox/AMFI), and I/O Kit—an object-oriented C++ driver framework with matching/probing registries and DriverKit user-space extensions. The kernel exposes dual syscall tables (negative numbers for Mach traps, positive for BSD syscalls) and uses Libsystem in user space as the unified ABI boundary, as direct raw syscall numbers are not guaranteed stable across macOS releases.

Guide / Glossary A–Z / Terms beginning with X / XSS (Cross-site scripting)

XSS is a security flaw in which text from an untrusted source is treated as page code instead of ordinary words.

If a site shows a comment and the comment contains hidden instructions, an XSS flaw can make the browser follow those instructions as if the site wrote them.

Escaping text where it is inserted into the page, and using textContent rather than innerHTML, keeps input as words. Frameworks escape by default but not in every context, such as a URL or an attribute.

Why is escaping output better than banning the word script in input?

Escaping works at the point where text becomes markup and covers every tag and attribute form. A word ban misses alternate tags, event attributes and encodings, and it damages harmless input.

XSS is classified as stored, reflected or DOM-based depending on where the payload waits. A content security policy limits which scripts may run and where they may send data. Sanitization is needed only when a product truly requires rich markup, and it must be context-aware.

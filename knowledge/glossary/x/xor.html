XOR (Exclusive OR)

A fundamental logic operation that outputs 1 (true) when its two inputs differ and 0 (false) when they match.

Think of XOR as an “either-or, not both” rule, like a hallway light controlled by two switches: flipping either switch changes whether the light is on or off, and the light is only on when the two switches are in opposite positions. Computers use this simple rule everywhere—to add numbers, spot flipped bits, and scramble secret data.

Because XOR is self-inverting—applying the same value twice cancels out ((A ^ B) ^ B = A)—it shows up in RAID 5 parity drives (rebuilding a missing disk by XORing the survivors), stream ciphers (mixing plaintext with a keystream), and bitwise toggling in C or shell scripts. Unlike regular OR, XOR never loses information about either input once the other is known.

In RAID 5, how can a controller reconstruct a failed drive’s data using XOR?

The parity block stores the XOR of all data blocks in the stripe. Because XOR is reversible and associative, XORing the remaining healthy data blocks with the parity block cancels out every surviving drive and leaves behind the exact bits of the missing drive.

XOR is addition modulo 2 in GF(2) (A ⊕ B), forming an associative, commutative group where every element is its own inverse. In digital hardware it implements half-adder sum bits, carry-save adders, and linear-feedback shift registers (LFSRs); in error detection/correction it underpins CRC polynomial division over GF(2)[x] and Hamming/LDPC parity-check matrices. In cryptography, XORing a keystream preserves uniformity only if the pad is never reused: a two-time pad leaks P1 ⊕ P2 = C1 ⊕ C2, enabling crib-dragging attacks.

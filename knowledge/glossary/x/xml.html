Guide / Glossary A–Z / Terms beginning with X / XML (eXtensible Markup Language)

A structured, tag-based text format for representing hierarchical data, used on Linux by Fontconfig, SVG graphics, and D-Bus introspection.

XML looks a lot like HTML: it wraps pieces of information in matching opening and closing tags such as <name>...</name> so both humans and programs can read the structure. Unlike HTML, which has fixed tags for web pages, XML lets each program define its own tags—making it a common way to store configuration files, vector drawings, and structured messages.

On a Linux desktop, you encounter XML in Fontconfig rules (/etc/fonts/fonts.conf or /home/alex/.config/fontconfig/fonts.conf), scalable .svg icons, and D-Bus service introspection. Unlike JSON or TOML, XML supports attributes on tags, namespaces, and strict schemas, and you can validate syntax errors—such as an unclosed tag—using xmllint --noout file.xml.

Why does a single missing closing tag break an entire XML configuration file, unlike some forgiving HTML parsers?

XML requires documents to be strictly well-formed: every opening tag must match a closing tag and nest cleanly. Parsers are required by the specification to reject malformed input with a fatal error rather than guessing what the author meant, preventing silent misconfigurations.

Defined by the W3C XML 1.0/1.1 specification, XML represents an ordered tree of elements, attributes, text nodes, processing instructions, and comments, optionally constrained by DTD, XSD, or RELAX NG schemas and namespaces (xmlns). Parsers follow either tree-based DOM/XPath models or streaming SAX/StAX APIs. Security-sensitive deployments must disable external entity resolution (DOCTYPE / XXE) to prevent arbitrary file disclosure or SSRF, and guard against billion-laughs entity expansion DoS attacks.

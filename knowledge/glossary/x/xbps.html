Guide / Glossary A–Z / Terms beginning with X / XBPS (X Binary Package System)

The fast, independent binary package manager created for Void Linux.

A package manager is like an app store for your operating system that downloads, installs, updates, and removes programs cleanly. XBPS is the package manager built specifically for Void Linux, designed to be quick and lightweight while keeping track of which files and supporting libraries each program needs.

Unlike apt or dnf, XBPS splits its work across focused tools: xbps-install installs and upgrades packages, xbps-query inspects local or remote package metadata, and xbps-remove uninstalls packages and unused dependencies. Because Void Linux is a rolling-release distribution, you update the whole system with xbps-install -Su, and you should avoid partial upgrades where a single package is updated against an older library set.

Why is it risky to run xbps-install pkgname on a rolling-release system without syncing and upgrading first?

Installing a new package against an outdated local system can pull in newer shared libraries that break older installed binaries—a partial upgrade. Running xbps-install -Su first keeps all packages and shared libraries aligned with the repository’s current ABI.

Written in C with minimal dependencies (libarchive, zlib, OpenSSL/LibreSSL), XBPS tracks packages via plist metadata (prop.plist, files.plist) stored under /var/db/xbps and verifies signed repository indexes and .xbps tarballs using RSA/Ed25519 keys. Transactions unpack into staging before atomic file replacement and trigger virtual package/alternatives resolution and INSTALL/REMOVE hooks. On the build side, xbps-src (from void-packages) builds binary packages in isolated chroot/namespace environments with cross-compilation support across glibc and musl targets.

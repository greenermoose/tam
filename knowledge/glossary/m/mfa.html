Guide / Glossary A–Z / Terms beginning with M / MFA (Multi-Factor Authentication)

Multi-Factor Authentication (MFA) is a login security method that requires two or more independent proofs of identity before granting access.

A password alone is like a single front-door key: if someone steals or guesses it, they can walk right in. MFA adds a second lock of a different kind—such as tapping a physical security key or approving a prompt on your phone—so a stolen password by itself is not enough.

MFA factors fall into three categories: something you know (password or PIN), something you have (hardware security key or authenticator app), and something you are (fingerprint or face). Asking for two passwords is not true MFA because both are knowledge factors. In practice, hardware FIDO2 keys are much stronger than SMS text codes, which can be intercepted via SIM swapping or entered into fake phishing pages.

Why is a password plus a security question not considered true MFA?

Both a password and a security question are “something you know” (knowledge factors). True MFA requires at least two distinct factor categories—such as a password (knowledge) paired with a hardware key (possession).

Under NIST SP 800-63B, authenticator assurance distinguishes replayable OTPs (TOTP/HOTP, RFC 6238/4226, which remain vulnerable to real-time adversary-in-the-middle phishing proxies) from verifier-impersonation-resistant protocols. FIDO2/WebAuthn (CTAP2 + WebAuthn) binds an asymmetric keypair to the TLS origin (rpId) and signs a server challenge inside a hardware element, preventing credential relay across lookalike domains; on Linux, pam_u2f extends this to local PAM login and privilege elevation.

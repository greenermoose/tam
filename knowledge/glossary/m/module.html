Module

A module is a file with a clear interface: it exports named values and imports what it needs from other modules.

Modules are like labelled drawers in a workshop. Each drawer holds one kind of tool and has a label telling you what is inside, so you do not need to open every drawer to find a hammer.

Standard ES modules use export and import. A .mjs file selects module mode in Node, or package.json can set type to module. Imports are resolved from file paths or package names.

Why do bundlers prefer static import over conditional require?

A static import is visible before code runs, so a bundler can build the full dependency graph and decide which exports are reachable. A conditional require depends on runtime values and is harder to analyze.

ES modules are statically analyzable, which lets bundlers build a graph and remove unused exports. CommonJS uses require() at runtime. Circular imports work but can expose partially initialized bindings; module scope is lexical and strict.

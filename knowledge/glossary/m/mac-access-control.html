Mandatory Access Control (MAC)

Mandatory Access Control (MAC) is a system-wide security model enforced by the operating system kernel that even file owners and administrators cannot override with normal permissions.

On most computers, if you create a file, you decide who can read or share it—just like putting a lock on your own desk drawer. Mandatory Access Control works more like a high-security building’s vault rules: even if you wrote a document yourself, the building’s rules forbid anyone from carrying it out of the vault room. Because the operating system enforces those rules centrally, a single hacked program cannot simply change file permissions to escape its cage.

Standard Linux permissions (chmod/chown) are Discretionary Access Control (DAC): a user who owns a file can grant read access to anyone. MAC layers a second check underneath via Linux Security Modules (LSM) such as SELinux or AppArmor. Even if a web server process runs with permission to read a file under DAC, an SELinux or AppArmor policy can deny the open syscall if that process type or profile is not allowed to touch that file’s label or path.

If a file has mode 0644 owned by root, why can SELinux still block a compromised daemon running as a service user from reading it?

Linux checks both DAC and MAC hooks before allowing access, and both must succeed. Even though 0644 grants read permission to all users under DAC, SELinux evaluates the daemon’s security context against the file’s label and denies the syscall if the policy lacks an explicit allow rule.

In formal security models, MAC enforces centralized, non-discretionary policy over security labels where subjects cannot alter policy or propagate rights—classically modeled by Bell–LaPadula (no read up, no write down for confidentiality), Biba (integrity), and Type Enforcement (TE). In Linux, LSM hooks (e.g., security_inode_permission, security_bprm_check) run after DAC checks in the VFS and socket layers; SELinux binds labels via extended attributes (security.selinux) while AppArmor mediates by path-based profiles. Misconfigured labels (e.g., files moved with mv retaining source context) or overly permissive booleans are common failure modes in production deployments.

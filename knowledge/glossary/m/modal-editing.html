Modal editing

Modal editing is an editing design in which the same keys mean different things depending on the editor's current mode.

In most programs, pressing d types the letter d. In a modal editor, d means “delete” until you deliberately switch to a mode where typing inserts text. vi works this way. In command mode its letters are instructions; in insert mode they are ordinary text. Pressing Escape leaves insert mode and returns you to commands. The benefit is that short key sequences become a compact language for changing text. The cost is that a beginner can type a command while expecting letters, or type letters while expecting a command, and see something unexpected.

vi's two main modes are command mode, where keystrokes are editing commands, and insert mode, where they become file text. A few more modes exist: the colon command line, visual selection, and replace mode. Vim shows -- INSERT -- at the bottom of the screen, but classic vi gives no indicator, so the Escape key is the habit that keeps you oriented. Modal editing is a contrast with modeless editing, the design used by GNU Emacs and by most graphical editors. In a modeless editor, typing inserts text and commands use modifier keys or have names, so there is no mode to enter or leave. Other modal editors include Kakoune and Helix, which follow vi's idea but change the order of operations. Modal input is not unique to editors either: games and drawing programs often use modes to give one key several meanings.

You open vi and press i, then type a sentence. Why does pressing Escape matter before saving?

While you are in insert mode, : is just a character, so :wq would be typed into the file. Escape returns you to command mode, where : starts the ex command line and :wq writes and quits.

Modal editing is a finite-state design layered on a command grammar. In vi, the normal mode parses an optional count, an operator, another optional count, and a motion, as in d2w; a doubled operator applies to whole lines, as in dd. Vim and Neovim extend this with text objects (ci", yap), operator-pending state, visual and blockwise visual modes, a command-line mode, replace mode, and a terminal-job mode. The design gives terse composability but introduces mode errors: a command typed in the wrong mode does the wrong thing, and a text sequence typed in command mode can trigger destructive commands. Vim's showmode and mode indicators reduce this risk without removing it. POSIX vi describes only open and visual modes and refers to ex for the command language, so the exact mode set is an implementation matter. Emacs is the usual modeless counterexample: every action is a named command reached by a key chord, so the same key means one thing regardless of an insert state.

Mnemonic

A mnemonic is a short, human-readable name—such as add, mov, or jmp—used in assembly language to represent a machine instruction.

Processors actually execute raw binary numbers like 10111000, which are nearly impossible for humans to read or remember. A mnemonic is a short nickname—like mov for “move” or add for “add”—so programmers can read and write low-level instructions as words instead of memorizing strings of ones and zeros.

When you inspect a compiled Linux binary with objdump -d, the disassembler turns raw machine bytes back into mnemonics so you can follow what the program does. Notice that the same operation can look different depending on syntax: Intel syntax writes mov eax, 1 (destination first), whereas AT&T syntax used by GNU as writes movl $1, %eax (source first, with a size suffix l).

Why can a single mnemonic like mov correspond to many different binary opcodes?

The exact machine opcode depends on the operand types and sizes—moving a constant into a register, reading from memory, or moving 8-bit versus 64-bit values each use different binary encodings even though they share the mov mnemonic.

An assembler resolves a mnemonic and its operand addressing modes into a concrete opcode, ModR/M or SIB bytes (on x86), and immediate or displacement fields. Mnemonics are heavily overloaded across operand widths and ISA extensions, and assemblers also define pseudo-instructions (such as RISC-V li or nop) that expand into canonical encodings. AT&T size suffixes (b/w/l/q) disambiguate operand width when memory operands lack an explicit register.

Mode (permission)

A permission mode is a set of access rules attached to a Linux file or directory that controls who can read, modify, or execute it.

Every file or folder on Linux has a small three-part lock: one rule for the owner, one for a shared group, and one for everyone else. Each rule says whether that person can look inside (read), make changes (write), or run it as a program (execute).

Running ls -l shows modes like -rwxr-xr-- (octal 0754) for user, group, and others, and chmod changes them. Crucially, x (execute) means something different on directories than on files: on a file it lets you run it as a program, whereas on a directory it lets you traverse (cd into) it and access files inside.

What happens if a directory has read (r) permission but lacks execute (x) permission?

You can list the filenames inside the directory, but you cannot cd into it or open any of the files inside it, because directory x controls traversal and metadata lookup.

In POSIX, permission bits occupy the low 12 bits of st_mode in struct stat (separate from the upper 4-bit S_IFMT file-type mask): 9 rwx bits (0777) plus setuid (04000), setgid (02000, controlling group inheritance on directories), and the sticky bit (01000, restricting unlink/rename in shared directories like /tmp). Effective access also depends on umask at creation, POSIX ACLs, mount flags (noexec, ro, nosuid), Linux capabilities, and LSM policies (SELinux/AppArmor).

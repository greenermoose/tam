Mount

The action of attaching a storage device or virtual filesystem to a directory so the operating system can read and write its files.

Plugging in a USB drive or opening a disk image does not automatically make its files appear in your folders—the system first has to connect that storage to a spot in your folder tree. Mounting is that connection step, and unmounting is safely disconnecting it before you unplug the drive so nothing gets cut off mid-save.

In Linux, you attach filesystems either manually with the mount command, automatically at boot via /etc/fstab or systemd mount units, or on demand through desktop helpers like udisks2. Mounting applies options such as ro (read-only), noexec, or nosuid, and you can inspect active mounts with findmnt or mount; attempting to umount a busy filesystem fails until open files and working directories inside it are closed.

Why does running umount sometimes fail with “target is busy”?

Because at least one process still has an open file descriptor or its current working directory inside that mounted filesystem, and unmounting while active would break those references.

Under the hood, the mount(2) syscall (and the newer split API fsopen/fsconfig/fsmount/move_mount) instantiates or reuses a superblock and attaches a vfsmount to a target path inside the calling process’s mount namespace. Options split into superblock-level flags (shared across bind mounts of the same filesystem) and per-mount flags (MS_RDONLY, MS_NOSUID, MS_NODEV, MS_NOEXEC); lazy unmounting (umount -l / MNT_DETACH) detaches the mount from the namespace immediately while deferring superblock teardown until the last open reference closes.

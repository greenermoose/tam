Guide / Glossary A–Z / Terms beginning with M / MMU (Memory Management Unit)

The Memory Management Unit (MMU) is the processor hardware that translates virtual memory addresses used by programs into physical RAM addresses and enforces access permissions.

Every program wants to act as if it has a clean, private desk of memory all to itself, even though dozens of programs share the same physical RAM chips. The MMU works like a fast postal sorter inside the CPU: it translates each program’s private “virtual” address into a real slot in RAM and blocks one program from peeking into another’s memory.

Because of the MMU, two Linux processes can both use the exact same virtual address (such as 0x400000) without colliding—each process has its own page table mapping that virtual address to different physical frames. When a program touches an unmapped address or writes to read-only memory, the MMU triggers a page fault; the kernel either loads the page or terminates the process with SIGSEGV.

What happens when a Linux process writes to a memory address marked read-only in its page tables?

The MMU blocks the write and raises a hardware page-fault exception into the kernel. Unless the kernel intentionally handles it (such as for copy-on-write), the kernel sends SIGSEGV to the process, causing a segmentation fault.

Modern x86-64 and ARM64 MMUs implement multi-level radix page tables (4-level 48-bit or 5-level 57-bit virtual addressing on x86-64; 4 KiB base pages plus 2 MiB / 1 GiB hugepages) traversed by a hardware page-table walker on Translation Lookaside Buffer (TLB) misses. Page table entries (PTEs) encode physical frame numbers alongside R/W, U/S, NX/XD, Accessed, and Dirty bits. Context switches updating CR3 (or TTBR0_EL1) use PCID/ASID tags to preserve address-space isolation without full TLB flushes.

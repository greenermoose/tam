Guide / Glossary A–Z / Terms beginning with M / MINIX

MINIX is an educational Unix-like operating system created by Andrew Tanenbaum that inspired Linux and influenced modern microkernel design.

Most operating systems pack nearly everything—file access, networking, and device drivers—into one giant core program, so a bug in one part can freeze the whole computer. MINIX was built as a small teaching system where those parts run as separate mini-programs instead; Linus Torvalds studied MINIX while writing the first version of Linux.

Whereas Linux uses a monolithic kernel (running drivers inside kernel space for speed), MINIX 3 uses a microkernel: only scheduling, inter-process communication, and basic interrupts stay in kernel mode, while filesystems and device drivers run as isolated userspace servers. If a driver crashes in MINIX 3, a supervisor process can restart that single component without rebooting.

How does a microkernel like MINIX 3 differ from the Linux kernel when a device driver crashes?

In Linux’s monolithic kernel, drivers run in privileged kernel space, so a serious driver bug can panic the entire OS. In MINIX 3, drivers run as isolated userspace servers, allowing a supervisor to restart the crashed driver without bringing down the system.

MINIX 1 (1987) accompanied Tanenbaum’s Operating Systems: Design and Implementation and sparked the 1992 Tanenbaum–Torvalds debate over microkernel versus monolithic architecture. MINIX 3 (2005) shifted toward self-healing reliability: a ~6,000-line kernel enforces least privilege via capability-based IPC and memory grants, while a userspace Reincarnation Server (rs) monitors heartbeats and restarts faulted drivers. The primary trade-off is IPC and context-switch overhead compared to monolithic kernels.

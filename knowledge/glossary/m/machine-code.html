Guide / Glossary A–Z / Terms beginning with M / Machine code

Machine code is the binary instructions a processor can execute directly.

A processor does not actually understand English words like print or if—at the hardware level, it only responds to patterns of 1s and 0s. Machine code is that raw stream of binary instructions. Programs written in human-friendly languages such as C or Python must be translated (or interpreted) into machine code before the CPU can carry them out, while assembly language gives human-readable names to those exact binary steps.

Machine code consists of opcodes (what operation to run) and operands (which registers, constants, or memory addresses to use), formatted for one specific instruction set architecture such as x86-64 or ARM64. An assembler translates assembly mnemonics one-to-one into those bytes, whereas a compiler optimizes and rearranges higher-level code before emitting them. On Linux, objdump -d lets you inspect a binary’s raw hex bytes side-by-side with their disassembled mnemonics. See Assembly language programming and machine code.

Why can’t a compiled x86-64 binary run directly on an ARM64 processor without translation or emulation?

The same binary byte patterns mean completely different instructions—or invalid opcodes—to different CPU architectures, and the register layouts and calling conventions differ too. Each ISA defines its own machine-code encoding.

Encoded instruction bytes for a specific ISA and execution mode, fetched and decoded by the processor pipeline (fixed 32-bit words on AArch64 vs. variable 1–15-byte instructions with prefixes, ModR/M, and SIB bytes on x86-64). Instruction encoding, alignment, and register usage are governed by the platform ABI and microarchitecture; the same source code yields different machine code across target triples, CPU feature flags (such as AVX2), and optimization levels.

MAC - Message Authentication Code

A MAC (Message Authentication Code) is a short cryptographic tag created using a shared secret key to prove a message is authentic and has not been altered.

Think of a MAC as a tamper-evident wax seal stamped with a signet ring that only the sender and receiver possess. If someone intercepts a message in transit and changes even a single character, they cannot produce the matching seal without the secret ring. When the receiver checks the message with their copy of the key and the seal does not match, they know right away that the message was forged or corrupted.

A plain cryptographic hash like SHA-256 detects accidental corruption, but an attacker who modifies a message can simply recompute a new SHA-256 hash. Because a MAC mixes a secret key into the computation, only someone holding that key can generate or verify a valid tag. In practice, systems use algorithms like HMAC-SHA256 (often for API tokens and webhook signatures) or Poly1305/GMAC inside authenticated encryption ciphersuites, and compare tags in constant time to avoid leaking secrets via timing.

Why isn’t a plain SHA-256 checksum enough to protect a message against an active attacker?

SHA-256 uses no secret key, so anyone can compute it. An attacker intercepting the message can alter the contents, compute a fresh SHA-256 hash for the tampered data, and replace the original hash—leaving the receiver unaware unless a keyed MAC or digital signature is used.

Formally, a MAC is a tuple (Gen, Tag, Verify) achieving existential unforgeability under chosen-message attack (EUF-CMA): an adversary with a tagging oracle cannot forge a valid tag for any fresh message. Constructions fall into hash-based (HMAC, RFC 2104, immune to length-extension attacks via nested key padding), block-cipher-based (CMAC/AES-CMAC), and universal-hash Wegman–Carter MACs (GMAC over GF(2^128), Poly1305 modulo 2^130 − 5). Tag verification must use constant-time comparison (e.g., CRYPTO_memcmp) and never reuse a one-time nonce-derived key (catastrophic for GMAC/Poly1305, where nonce reuse leaks the authentication key).

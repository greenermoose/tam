MD5 (Message Digest 5)

MD5 (Message Digest 5) is an obsolete 128-bit cryptographic hash function that produces a 32-character hexadecimal fingerprint for any input.

A hash acts like a digital wax seal for a file: changing even one letter inside the file normally produces a completely different fingerprint. MD5 was widely used for this in the 1990s, but researchers found ways to craft two different files with the exact same MD5 fingerprint, so it can no longer be trusted for security.

You will still see md5sum on Linux for quick, non-adversarial checks—such as verifying a local file copy was not truncated—or when reading legacy checksum lists. Never use MD5 for passwords, digital signatures, or verifying downloads from untrusted networks; use SHA-256 or BLAKE3 for integrity and Argon2id or bcrypt for passwords.

If MD5 is broken for security, why does md5sum still exist on Linux systems?

MD5 is fast and still catches accidental corruption (such as a bad disk read or interrupted copy) when no attacker is involved, and it remains needed for legacy checksum files. It is unsafe whenever an adversary might deliberately craft a matching hash.

Defined in RFC 1321 (Rivest, 1992), MD5 is a Merkle–Damgård construction processing 512-bit blocks through 64 steps (4 rounds of 16 operations) over four 32-bit state words. Although 128 bits implies 264 generic collision resistance, differential cryptanalysis (Wang et al., 2004) generates identical-prefix collisions in seconds, and chosen-prefix collisions (Stevens et al., 2007/2009) enabled forging rogue X.509 CA certificates. Like other Merkle–Damgård hashes, naive MD5(secret || message) MACs are also vulnerable to length-extension attacks.

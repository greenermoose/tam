MESI (Modified, Exclusive, Shared, Invalid)

MESI (Modified, Exclusive, Shared, Invalid) is a cache-coherence protocol that keeps private per-core CPU caches consistent with each other and with main memory.

Modern processors have multiple cores, each with its own small, fast scratchpad (cache) so it does not have to fetch from main memory every time. If one core updates a number on its scratchpad, another core’s copy becomes outdated. MESI is the set of traffic rules—labeling each piece of data as modified, exclusive, shared, or invalid—so no core reads stale data.

Each 64-byte cache line in L1/L2 cache carries one of the four MESI states. Before a core can write to a Shared line, it must invalidate copies held by other cores. In multithreaded code, this causes “false sharing”: if two threads on different cores update unrelated variables that happen to sit in the same 64-byte cache line, the cores repeatedly invalidate each other’s caches and performance drops.

Why can two threads updating completely separate variables still slow each other down under MESI?

MESI tracks coherence per 64-byte cache line, not per variable. If both variables share a cache line, every write by one core invalidates the other core’s copy (false sharing), forcing repeated cache-line transfers.

Over a snooping or directory interconnect, MESI enforces the Single-Writer, Multiple-Reader (SWMR) invariant: Modified (dirty, sole copy), Exclusive (clean, sole copy—allowing silent upgrade to M on write without a bus transaction), Shared (clean, potentially replicated), and Invalid (unusable). Write-invalidate transitions issue Read-For-Ownership (RFO) requests. Production CPUs extend MESI: AMD’s MOESI adds Owned so dirty lines can be shared without immediate DRAM writeback, while Intel’s MESIF adds Forward to pick one responder among Shared copies. Coherence serializes single-address visibility, not cross-address ordering; store buffers and invalidation queues still require memory barriers.

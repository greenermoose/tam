Guide / Glossary A–Z / Terms beginning with M / Make

Make is a build automation tool that turns source files into finished programs or documents by running only the steps whose inputs have changed.

Compiling a large project from scratch after fixing a single typo wastes time. Make acts like a smart kitchen prep list: if an ingredient was already prepared and nothing about it changed, Make skips that step and only rebuilds the parts that depend on what you edited.

Make reads a Makefile containing rules written as target: prerequisites followed by tab-indented shell commands (recipes). It compares file modification timestamps to skip up-to-date targets. Two common pitfalls in everyday use are indenting recipes with spaces instead of a literal tab character, and forgetting to mark action-only targets like clean or all as .PHONY.

Why should a target like clean be declared with .PHONY?

Make checks whether a file with the target’s name exists and is newer than its prerequisites. If a file named clean exists in the directory and has no prerequisites, Make treats it as up to date and refuses to run the cleanup commands unless .PHONY: clean marks it as an action rather than a file.

GNU Make constructs a directed acyclic dependency graph (DAG), supports two variable-expansion flavors (= deferred/recursive vs. := immediate/simple), and provides pattern rules (%.o: %.c) with automatic variables ($@, $<, $^). Common failure modes include missing header dependencies (mitigated by compiler-generated -MMD -MP depfiles), parallel race conditions under -j when rules share undeclared outputs or omit order-only prerequisites (|), and timestamp skew on network filesystems. Unlike Ninja, Bazel, or Nix, Make tracks modification times rather than content hashes.

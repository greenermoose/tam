Monospace

A typeface in which every character occupies the exact same horizontal width.

In everyday books and websites, a narrow letter like “i” takes up much less space than a wide letter like “w”. A monospace font works like a classic typewriter or graph paper: every letter, number, and punctuation mark gets an identical box. That makes columns of numbers, code indentation, and terminal tables line up cleanly down the page.

Unlike proportional fonts used for prose, monospace fonts give every glyph the same advance width, which is why terminal emulators, code editors, and tools like ls -l or ps rely on them to align columns without tab stops. Many programming monospace fonts also add clear visual distinctions between easily confused characters—such as 0 vs O and 1 vs l vs I—and optionally include coding ligatures that render multi-character operators like != or => as a single combined shape while keeping the underlying character count and column width intact.

Why does a table of numbers printed in a terminal misalign if you paste it into a word processor using a proportional font?

Because proportional fonts give digits, spaces, and punctuation different widths, so the same number of space characters no longer adds up to the same horizontal offset on each line.

In OpenType/TrueType metrics, a monospace font sets uniform hmtx advance widths across its ASCII/core glyphs and typically flags isFixedPitch in the post table and panose proportion 9 in OS/2, allowing renderers and terminal grids to assume cell-locked placement. Real-world edge cases arise with CJK ideographs (often double-width, occupying two terminal cells per wcwidth()), combining diacritics (zero advance width), emoji sequences, and fallback fonts whose cell height or baseline differs from the primary font; terminal emulators must either clip, scale, or allow cell overflow when fallback glyphs violate the single-cell advance assumption.

Mount point

The existing directory in a filesystem tree where another filesystem is attached so its contents become accessible.

Linux puts all your files into one big folder tree starting at / instead of giving every drive a letter like C: or D:. When you plug in a USB stick or add a second hard drive, the system picks an empty folder—such as /media/alex/USB—and attaches the drive there. That chosen folder is the mount point: opening it shows the files on the drive.

A mount point must already exist as a directory before a filesystem is attached to it. Once mounted, the attached filesystem’s root replaces whatever was inside that directory; any files that happened to live in the underlying directory beforehand are not deleted, just hidden until the filesystem is unmounted. Common conventions place temporary removable media under /run/media/ or /media/ and administrator-configured mounts under /mnt/ or dedicated paths like /home or /var.

What happens to files that were already inside a directory if you mount another filesystem onto that same directory?

They remain on the underlying disk but become temporarily inaccessible (hidden) until the newly mounted filesystem is unmounted.

In the Linux VFS, a mount point is a dentry/inode pair within a specific mount namespace where a struct mount is grafted onto a parent mount, overriding path-walk resolution at that dentry while preserving the underlying directory’s inode underneath. Mount points support stacked overmounts (each new mount shadows the previous one at that path), bind mounts (attaching a subtree rather than a whole block device), and per-mount propagation types (shared, slave, private, unbindable), which govern whether sub-mounts inside a directory replicate across namespaces such as containers.

modifyOtherKeys

A terminal setting that lets applications distinguish key combinations that older terminal protocols send as identical bytes.

Normally, pressing certain key combinations—like Ctrl+I and Tab, or Ctrl+Shift+A and Ctrl+A—sends the exact same signal to a terminal program, so the program cannot tell which one you actually pressed. Turning on modifyOtherKeys acts like giving each key combination its own distinct name tag, allowing modern editors and shells to bind shortcuts that used to collide.

In traditional terminal input, control characters map to a narrow 7-bit range, so Ctrl+I and Tab both transmit byte 0x09, and Ctrl+M collides with Enter (0x0D). When an editor like Vim or Neovim enables modifyOtherKeys in xterm or a compatible terminal, modified keys are reported as CSI sequences of the form CSI 27 ; modifier ; code ~, keeping Ctrl+Shift+Letter, Ctrl+Enter, and Ctrl+I distinct from plain control bytes.

Why can’t a terminal application tell Ctrl+I apart from Tab without modifyOtherKeys or a newer keyboard protocol?

Because legacy ASCII control encoding maps Ctrl+letter to bytes 0x01–0x1A, which places Ctrl+I on 0x09—the exact same byte that Tab sends—so the application receives identical input unless an extended encoding like modifyOtherKeys is active.

Introduced in xterm via CSI > 4 ; level m (and disabled with CSI > 4 ; 0 m or CSI > 4 m), modifyOtherKeys has two active modes: level 1 encodes modified keys that lack a standard modified CSI/ASCII representation (such as Ctrl+Shift+A or Shift+Enter) while leaving unambiguous keys alone, whereas level 2 encodes almost all modified keys—including Ctrl+I or Ctrl+M—as ESC [ 27 ; modifier ; keycode ~ (where modifier follows the xterm 1-based bitmask: 2=Shift, 3=Alt, 5=Ctrl, and keycode is the Unicode/ASCII code point). Edge cases include nested multiplexers like tmux (requiring extended-keys forwarding) and applications that expect raw C0 bytes for legacy bindings; newer terminals increasingly prefer the Kitty keyboard protocol (CSI u) for full press/repeat/release event reporting and layout-independent keycodes.

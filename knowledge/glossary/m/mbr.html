Guide / Glossary A–Z / Terms beginning with M / MBR (Master Boot Record)

The Master Boot Record (MBR) is the legacy partitioning and boot-sector format stored at the very beginning of a storage disk.

Before an operating system can read files on a drive, it needs a table of contents showing where each section (partition) starts and ends. MBR is an older 1980s-era table of contents stored on the very first block of the disk, alongside a tiny starter program that helps the computer begin booting.

On Linux, tools like fdisk and lsblk show MBR disks with a dos label. MBR supports at most four primary partitions and cannot address disks larger than 2 TiB with standard 512-byte sectors. To create more than four partitions, one primary slot must become an extended partition containing logical partitions. Modern UEFI systems use GPT instead, which removes these limits and keeps a backup header.

Why does an MBR disk need an “extended” partition if you want five partitions?

The MBR partition table has room for only four 16-byte entries. To work around that limit, one primary entry is marked as an extended partition container that links to a chain of Extended Boot Records (EBRs) inside it for logical partitions.

Stored at LBA 0 (512 bytes), an MBR comprises 446 bytes of stage-1 bootstrap code, four 16-byte partition entries starting at offset 0x1BE, and the 0x55AA boot signature at 0x1FE. Each entry encodes a bootable flag (0x80), start/end CHS tuples, a partition type byte (e.g., 0x83 Linux, 0x82 swap, 0xEE protective GPT), and 32-bit LBA start and sector-count fields—capping capacity at 232 × 512 bytes (2 TiB). MBR lacks checksums or backup headers, so corrupting LBA 0 destroys the layout; GPT disks place a protective 0xEE MBR at LBA 0 to stop legacy tools from overwriting GPT metadata.

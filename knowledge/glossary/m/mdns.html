mDNS (Multicast DNS)

A way of resolving names on the local network by asking every device on the link, instead of asking a configured DNS server.

Ordinary DNS sends a question to a known server. Multicast DNS sends the question to everyone on the local network and lets the device that owns the name answer. This is why a device ending in .local can be found without anyone setting up a name server. It is the name-resolving part of Zeroconf, used by Avahi and Bonjour.

mDNS uses UDP port 5353 and the link-local multicast groups 224.0.0.251 and FF02::FB. A device that wants a name sends a multicast query; the owner multicasts a response with a short random delay to reduce collisions. On Linux, avahi-resolve -4 -n printer.local resolves a .local name, and a Name Service Switch module such as nss-mdns lets ordinary applications resolve them too. Multicast does not cross a router by default, so discovery stays on the local network.

Why does a .local name fail when sent to a global DNS server?

.local is reserved for link-local names and is not delegated in the global DNS hierarchy. The answer lives with a device on the local link, which an upstream DNS server cannot know.

mDNS reuses the DNS wire format with no configured server. Queries use IP TTL 255; responders delay replies by a random 20 to 120 milliseconds. A host claiming a unique name probes with tentative records, then announces with unsolicited responses; a withdrawal is a record with a TTL of zero, called a goodbye packet. Unique records carry a cache-flush bit so receivers drop older copies, while shared records do not. Negative answers use NSEC records to prove a name or type is absent, and known-suppression avoids repeating an answer recently heard from another host. Normal operation is defined in RFC 6762; DNS-SD builds service discovery on top.

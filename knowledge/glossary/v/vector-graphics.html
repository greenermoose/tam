Guide / Glossary A–Z / Terms beginning with V / Vector graphics

Vector graphics describe images as mathematical shapes, lines, and curves rather than a fixed grid of colored dots (pixels).

Think of the difference between a mosaic made of square tiles and a recipe for drawing a circle. If you zoom way in on a mosaic (a photo or pixel image), you start seeing blocky squares. A vector graphic is like the recipe: it says “draw a blue circle of this size with a black outline,” so whether you display it on a tiny watch screen or print it on a billboard, the computer redraws the curves fresh and razor-sharp.

Common vector formats include SVG for the web and desktop icons, PDF/PostScript for documents, and TrueType/OpenType outlines for fonts. On Linux, desktop themes and apps rely heavily on SVG icons because one file scales cleanly across 100% and 200% HiDPI displays without shipping separate PNGs for every size. By contrast, photographs and detailed textures are poor fits for vectors and belong in raster formats (PNG, JPEG, WebP) because describing millions of subtle color variations as shapes would be huge and slow to render.

Why do UI icons and logos usually use SVG instead of PNG, whereas camera photos stay raster?

Icons and logos consist of clean geometric shapes that scale infinitely in SVG without blurring, while camera photos have millions of irregular pixel-level color variations that cannot be compactly represented as geometric paths.

Vector graphics represent 2D scenes as resolution-independent primitives—straight segments, quadratic and cubic Bézier curves, affine/projective transforms, stroke widths, miter/cap rules, and fill rules (non-zero winding vs. even-odd)—which are only rasterized into framebuffers at display or print time. Modern renderers (Cairo, Skia, Direct2D, GPU path shaders) tessellate curves or evaluate signed-distance fields (SDFs) and apply anti-aliasing (coverage sampling, MSAA, or subpixel LCD filtering) to prevent aliasing along diagonal edges. Security and performance edge cases include SVG’s XML/DOM surface (XXE, embedded scripts in browsers vs. static <img> sandboxing) and pathological path complexity (tens of thousands of overlapping translucent paths causing CPU/GPU fill-rate stalls).

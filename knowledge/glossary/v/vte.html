Guide / Glossary A–Z / Terms beginning with V / VTE (Virtual Terminal Emulator library)

VTE is a GTK widget library that provides the terminal screen and input handling inside GNOME Terminal and several other Linux terminal emulators.

VTE is a shared building block for terminal apps. Instead of every terminal program writing its own code to draw letters, handle colors, and scroll text, many GTK-based Linux terminals plug in VTE to do that work in one consistent way.

In practice, VTE sits between the graphical window and the shell running inside it. Used by GNOME Terminal, Tilix, and Xfce Terminal, it opens a pseudoterminal (PTY), interprets terminal control sequences for cursor movement and colors, and draws the text grid using GTK. This contrasts with standalone terminal emulators such as foot, Alacritty, or Kitty, which implement their own terminal engines and rendering pipelines rather than sharing VTE.

Why do GNOME Terminal and Xfce Terminal often share the same text-rendering or escape-sequence quirks?

Because both embed the same libvte library to parse terminal sequences and draw the terminal grid, so a bug or feature in VTE affects every emulator built on it at once.

libvte provides the VteTerminal GTK widget and VtePty abstraction, managing Unix98 pseudoterminal allocation (openpty/posix_openpt), non-blocking I/O over the PTY master, and a stateful ECMA-48/xterm control-sequence parser (CSI, OSC, SGR attributes, and alternate screen buffers). Text layout and glyph rendering run through Pango and Cairo (or GTK4 snapshot nodes), backed by a ring-buffered scrollback history that can optionally spill to encrypted temporary files. Sharing VTE centralizes security fixes and accessibility (ATK/AT-SPI) support, at the cost of coupling emulators to GTK’s event loop and CPU-heavy text shaping compared to GPU-first rasterizers.

Guide / Glossary A–Z / Terms beginning with V / VMX (Virtual Machine Extensions)

VMX (Virtual Machine Extensions) is Intel’s hardware virtualization feature set—marketed as VT-x—that lets a processor run virtual machines efficiently.

Running a virtual machine purely in software is slow because the host computer has to double-check every sensitive instruction the guest operating system tries to run. VMX is extra circuitry built directly into Intel processors so the CPU itself can safely run a guest operating system at near-native speed. If you ever see a BIOS setting called “Intel Virtualization Technology,” turning it on enables VMX.

On Linux, you can check whether the CPU supports and exposes VMX by running grep vmx /proc/cpuinfo (AMD’s equivalent flag is svm). The kernel’s kvm_intel module requires VMX to accelerate QEMU/KVM guests; if VMX is disabled in UEFI/BIOS firmware—often controlled by IA32_FEATURE_CONTROL—KVM refuses to load and virtualization tools fall back to slow software emulation.

If your Intel CPU supports VT-x, why might /proc/cpuinfo still not show the vmx flag or why might KVM fail to start?

UEFI/BIOS firmware can disable VMX and lock the IA32_FEATURE_CONTROL MSR before the OS boots, hiding or blocking the feature until you enable virtualization in firmware settings and cold-boot. Running inside a nested VM without nested virtualization enabled on the outer hypervisor also hides vmx.

Intel VMX introduces two operating modes—VMX root (for the hypervisor) and VMX non-root (for the guest)—entered via VMXON and controlled through a 4 KiB Virtual Machine Control Structure (VMCS) managed by VMPTRLD, VMREAD, VMWRITE, VMLAUNCH, and VMRESUME. Guest traps trigger VM-exits that save guest state and load host state automatically. Extended Page Tables (EPT) add a second-level page walk so guest OS page-table writes do not require shadow-page-table VM-exits, while VPIDs (Virtual Processor IDs) tag TLB entries across transitions to avoid full TLB flushes.

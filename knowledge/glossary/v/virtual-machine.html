Virtual machine

A virtual machine is a software-defined computer that runs inside another physical computer, with its own simulated hardware and operating system.

Imagine running a second computer inside a window on your main computer. A virtual machine (VM) acts like a separate PC: it has its own pretend processor, memory, hard drive, and network card, and you can install a completely different operating system inside it. Because it lives inside software, you can pause it, back it up as a single file, or erase it without harming your real computer.

On Linux, virtual machines are commonly run with KVM/QEMU, VirtualBox, or libvirt. Unlike containers—which share the host’s Linux kernel and isolate processes using namespaces and cgroups—a VM boots its own kernel on virtualized CPUs, memory, and devices provided by a hypervisor. That makes VMs heavier on RAM and startup time, but lets you run Windows, BSD, or a different Linux kernel safely alongside your host.

Why can a container start in milliseconds while a virtual machine usually takes seconds?

A container is just a group of isolated processes running directly on the already-booted host kernel. A virtual machine must initialize virtualized firmware (such as OVMF/UEFI), load its own guest kernel, probe virtual devices, and start its own init system before user programs can run.

A virtual machine is an isolated guest execution environment managed by a Type-1 or Type-2 hypervisor. Using hardware virtualization extensions (Intel VT-x/VMX or AMD-V/SVM), the hypervisor executes unprivileged guest code natively on physical cores while trapping sensitive instructions, MSR accesses, and I/O into the VMM via VM-exits. Guest physical addresses are translated to host physical addresses through two-dimensional paging (Intel EPT or AMD RVI), and high-throughput I/O typically uses paravirtualized virtio ring buffers (virtqueue) or VFIO PCI passthrough with IOMMU isolation instead of emulating legacy hardware registers.

Virtual console

A virtual console is a full-screen, text-based screen provided directly by the operating system outside the graphical desktop.

Think of your computer as having several separate screens behind the scenes, even when you only have one monitor. Most of the time you look at the graphical desktop, with windows and a mouse pointer. A virtual console is one of the plain text screens waiting behind it. If the desktop freezes or fails to start, switching to a virtual console often lets you log in with just a keyboard and fix the problem.

On Linux, you typically switch between virtual consoles with Ctrl+Alt+F1 through Ctrl+Alt+F6 (or chvt). Each virtual console corresponds to a kernel device such as /dev/tty2 and usually runs a getty login prompt, whereas a terminal window inside your desktop opens a pseudo-terminal such as /dev/pts/0. Because a virtual console does not depend on X11 or Wayland, it remains a key boundary for troubleshooting display-manager or compositor crashes.

If your desktop compositor freezes, why can switching to /dev/tty3 still work—and when will it fail?

Switching VTs is handled by the kernel and display driver rather than the frozen Wayland or X11 compositor, so the kernel can hand the screen and keyboard to a separate getty session. However, if the GPU driver has wedged the display hardware or the kernel input subsystem is hung, the VT switch itself will not render or respond.

In the Linux kernel, virtual consoles are implemented by the VT subsystem (drivers/tty/vt/) backed by fbcon over a DRM/KMS framebuffer. Console switching, keyboard event delivery, framebuffer rendering, kernel responsiveness, and userspace agetty/PAM authentication are independent dependencies: a VT_ACTIVATE ioctl or chvt request only succeeds if the active graphical session releases DRM master (or the kernel forces a switch) and the display driver can modeset cleanly. Because /dev/pts/* pseudo-terminals are multiplexed over PTY master/slave pairs inside user sessions, they disappear if the compositor or session manager dies, unlike kernel-owned /dev/ttyN devices.

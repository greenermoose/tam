VT (Virtual Terminal / Virtual Console)

VT refers to a virtual terminal—either a Linux kernel text console (/dev/tty1–/dev/ttyN) or, historically, a Digital Equipment Corporation Video Terminal.

On Linux, a VT (virtual terminal) is one of several built-in, full-screen text screens you can switch to by pressing keys like Ctrl+Alt+F3. Each one works like a separate keyboard-and-screen session—handy if your desktop freezes or you want to log in without graphics. Historically, the letters VT also came from classic 1970s and 1980s “Video Terminal” hardware made by DEC.

In Linux, the kernel provides virtual consoles numbered /dev/tty1 through /dev/tty63 (commonly 1–6 have login prompts, and one holds the graphical session). In everyday terminal emulators inside your desktop, you are using a pseudo-terminal (/dev/pts/*) rather than a kernel VT, though both understand VT-inspired escape sequences. When a display manager fails, switching to another VT lets you inspect logs or restart services.

Why does running tty inside a desktop terminal window print /dev/pts/0 instead of /dev/tty1?

A desktop terminal emulator runs as a normal graphical program and asks the kernel for a pseudo-terminal pair (/dev/pts/*) so it can draw text in a window. Kernel virtual terminals (/dev/tty1–/dev/tty63) own the physical console outside the windowing system.

The Linux kernel VT subsystem (drivers/tty/vt/) binds the input layer (keyboard.c/evdev) and a console driver (typically fbcon over DRM/KMS) to /dev/ttyN line disciplines. Userspace session managers and display servers coordinate VT ownership via ioctl calls (VT_ACTIVATE, VT_WAITACTIVE, VT_SETMODE with VT_PROCESS) and KDSKBMODE/KDSETMODE (KD_TEXT vs. KD_GRAPHICS), releasing or acquiring DRM master during switches. Because the kernel VT lacks full Unicode shaping, GPU acceleration, and scrollback-security isolation, modern Linux setups sometimes minimize its role in favor of userspace KMS consoles or serial/SSH recovery.

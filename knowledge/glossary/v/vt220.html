VT220 (DEC Video Terminal)

The VT220 was a 1983 DEC hardware terminal that introduced 8-bit control codes and the numeric function-key escape sequences still used by modern terminals.

When you press a function key like F5 or Page Up in a Linux terminal, the terminal does not send a simple letter—it sends a short invisible code so programs know which special key you pressed. Those codes (such as ESC [ 1 5 ~ for F5) were popularized by the 1983 DEC VT220 terminal. Decades later, Linux terminal apps still recognize VT220-style key codes.

The VT220 introduced the LK201 keyboard layout and standardized CSI <number> ~ sequences for F5 through F20 and editing keys (Insert, Delete, Home, End, Page Up, Page Down). Notice a classic quirk: the numbering skips 16 and 22 (F5 is 15~, F6 is 17~, F10 is 21~, F11 is 23~) because of historical breaks on the LK201 keyboard. When SSHing into older systems or configuring TERM=vt220, knowing this convention explains why mismatched terminfo entries cause function keys to print stray tildes (~).

Why does pressing F5 or Delete in a misconfigured terminal sometimes print ~ or 5~ instead of running the key action?

The terminal sends a VT220-style sequence like ESC [ 1 5 ~, but if the remote shell or application’s TERM/terminfo entry expects a different prefix length or doesn’t recognize that sequence, it consumes only the start and prints the trailing characters literally.

The DEC VT220 (1983) extended the VT100/VT102 architecture from 7-bit ASCII to 8-bit environments, introducing the DEC Multinational Character Set (MCS), 8-bit C1 control characters (0x80–0x9F, such as 0x9B as single-byte CSI when S8C1T is active), and Dynamically Redefinable Character Sets (DRCS) for soft fonts. Its LK201 keyboard defined the CSI n ~ encoding (11~–15~, 17~–21~, 23~–24~ for function keys, and 1~–6~ for editing keys), though modern terminfo entries often retain VT100 SS3 P–S (ESC O P..S) for F1–F4 alongside VT220 tilde sequences for F5–F12.

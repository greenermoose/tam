Variable

A variable is a named label in a program, script, or shell that holds a value you can read and often change.

Think of a variable like a labeled jar on a kitchen shelf. The label on the outside (such as username or count) stays the same, while what you put inside can be swapped out as your work goes on. Instead of retyping a long folder path or number ten times, you store it under a short name and refer to that name whenever you need it.

How a variable behaves depends on the language and scope. In POSIX/Bash shells, variables store strings, are assigned without spaces around = (name="alex"), and are read with $name; only exported variables pass into child processes as environment variables. By contrast, languages like Python bind names to typed objects dynamically, while C and Rust associate variables with specific data types and memory lifetimes. Notice also that in shell scripts, unquoted $var undergoes word splitting and glob expansion, which is a frequent source of bugs when filenames contain spaces.

Why does setting FOO=bar in your terminal not make FOO visible inside a Python script you launch next?

Without export FOO, a shell variable stays local to the current shell process and is not copied into the environment block passed to child processes.

At the compiler and runtime level, a variable is an identifier bound to a storage location (register, stack frame slot, static/BSS address, or heap reference) with defined scope, storage duration, type, and aliasing rules. Optimizing compilers rely on strict aliasing and SSA (Static Single Assignment) form to keep variables in registers and eliminate redundant loads—meaning data races or type-punning in C/C++ cause undefined behavior unless mediated by atomics, volatile (for MMIO, not thread sync), or memcpy. In shell execution, parameter expansion follows strict order-of-operations (brace, tilde, parameter/variable, command, arithmetic, word splitting, pathname expansion), making unquoted expansions an injection vector.

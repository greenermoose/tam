VFIO (Virtual Function I/O)

VFIO (Virtual Function I/O) is a Linux kernel framework that safely gives a virtual machine or userspace program direct access to a physical PCIe device, such as a GPU or network card.

Normally, a virtual machine shares your computer’s hardware through software simulation, which is slower than real hardware—especially for 3D graphics or high-speed networking. VFIO acts like a secure handoff: it temporarily disconnects a physical card (like a second graphics card) from the host system and hands it straight to a virtual machine, while using hardware guardrails so the guest OS cannot peek at the host’s memory.

VFIO is the foundation of Linux GPU passthrough with QEMU/KVM. First, you enable the hardware IOMMU in firmware and kernel parameters (intel_iommu=on or amd_iommu=on), then bind the target PCIe device to the vfio-pci kernel driver instead of its normal driver (such as amdgpu or nvidia). Because the IOMMU isolates memory at the hardware-group level, all devices sharing the same IOMMU group must be passed through together. You can inspect groups under /sys/kernel/iommu_groups/ and pass the device to QEMU with -device vfio-pci,host=....

Why might passing through just a GPU fail if a USB controller or audio device is in the same IOMMU group?

The IOMMU enforces DMA isolation per group rather than per individual PCIe function, so VFIO requires every device in that IOMMU group to be bound to vfio-pci (or a safe stub) before a VM can claim any of them.

VFIO exposes IOMMU-protected device access to userspace via /dev/vfio/vfio (container) and /dev/vfio/<group> (and newer cdev/iommufd APIs), allowing QEMU, DPDK, or SPDK to mmap PCIe BARs, map guest RAM into the IOMMU page tables (pinning pages for DMA), and wire MSI/MSI-X interrupts to eventfds for KVM IRQFD injection without host-kernel driver involvement. Operational edge cases include PCIe ACS (Access Control Services) missing on consumer chipsets—merging unrelated slots into one IOMMU group—GPU reset bugs (AMD Navi/Vega FLR failures requiring vendor-reset or host reboot), Resizable BAR sizing vs. MMIO aperture limits, and pinned guest memory preventing host swapping or transparent hugepage reclamation.

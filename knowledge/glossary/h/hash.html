Hash

A fixed-size value—often called a digest or fingerprint—computed from any amount of input data.

A hash is like a compact digital fingerprint for a file or piece of text. Whether a file is ten words long or a whole movie, running it through a hash produces a short code of the same length. If even one letter or pixel changes, the fingerprint changes completely—which makes hashes great for checking whether a download arrived intact.

Not all hashes serve the same purpose. Non-cryptographic hashes (such as SipHash or xxHash) are built for speed in hash tables, caches, and checksums, whereas cryptographic hashes (such as SHA-256 or BLAKE2b) are designed so you cannot practically forge an input that matches a given digest. On Linux, you routinely verify downloads or ISO images with sha256sum, and tools like Git identify every commit and file blob by its hash. Because any hash maps an infinite set of inputs to a finite output size, collisions are mathematically possible—so security depends on choosing an algorithm where finding one is infeasible (avoiding broken ones like MD5 and SHA-1).

Why can you verify a 4 GB Linux ISO download by comparing a single 64-character SHA-256 string?

SHA-256 has the avalanche property and collision resistance: changing even a single bit in the 4 GB file scrambles the output unpredictably, and finding a different file with the same digest is computationally infeasible.

A cryptographic hash function H: {0,1}* -> {0,1}^n must satisfy three formal properties: preimage resistance (given y, finding x with H(x)=y costs ~2^n), second-preimage resistance (given x1, finding x2 != x1 with H(x1)=H(x2) costs ~2^n), and collision resistance (finding any pair x1 != x2 with H(x1)=H(x2) costs ~2^(n/2) due to the birthday bound). Common failure modes include using raw hashes for password storage (too fast—use memory-hard KDFs like Argon2id instead), using unkeyed hashes for message authentication (vulnerable to length-extension in Merkle–Damgård designs—use HMAC or BLAKE2/SHA-3), and using non-randomized hash tables on untrusted input (vulnerable to HashDoS collisions unless keyed with e.g. SipHash-2-4).

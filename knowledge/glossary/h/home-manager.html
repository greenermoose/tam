Home Manager

Home Manager is a Nix tool that builds a user’s configuration and programs into a versioned generation you can switch to or roll back (historical on Tamlinux, which has retired Nix and Home Manager).

Instead of installing apps one by one and tweaking scattered settings by hand, Home Manager uses a single written recipe to build a complete snapshot (called a “generation”) of your personal programs and preferences. Tamlinux delivers much of the workstation through Home Manager generations. If an update causes trouble, you can switch back to an earlier snapshot, though files you edited manually outside the recipe are not automatically undone.

Home Manager manages per-user profiles as immutable Nix store closures: switching generations atomically updates symlinks in ~/.nix-profile and managed dotfiles in ~ without altering previous generations. Unlike NixOS system generations (which manage the kernel, system services, and /etc), Home Manager scopes strictly to one user account. Tamlinux deployment ties product assemblies to these generations; always identify the generation and assembly evidence before a rollback.

Why doesn’t rolling back a Home Manager generation revert a file you edited by hand outside Home Manager?

Rolling back only repoints symlinks to an earlier immutable Nix store closure. Files that Home Manager does not manage remain plain mutable files in your home directory, so generation switches leave them untouched.

Home Manager evaluates a NixOS-style module system (lib.evalModules) targeting user space, producing an activation derivation with home-path (a buildEnv package union) and an activate script that updates home-files linkfarms, reloads user units via systemctl --user, and advances the profile GC root under ~/.local/state/nix/profiles/home-manager. Common failure modes include activation collisions when an application expects to rewrite a read-only Nix store symlink in place (requiring force = true or out-of-store links), imperative activation-script side effects (such as dconf writes) that do not automatically revert on rollback, and nixpkgs/Tamlinux assembly drift causing ABI or graphics-driver mismatches in user-installed binaries.

Hexadecimal

Hexadecimal is a base-16 number system that uses sixteen symbols—0 through 9 and A through F—to represent values compactly.

Computers think in long strings of 1s and 0s (binary), which are hard for humans to read without making mistakes. Hexadecimal groups four 1s and 0s into a single digit from 0 to 9 or A to F, turning a long, messy binary number into a short, readable code—like the #FF8800 codes used for web colors.

Because 16 is 2⁴, one hexadecimal digit maps cleanly to 4 bits (a nibble), and two hex digits represent 1 byte (00 to FF, or 0 to 255). On Linux, you see hex everywhere: memory addresses in crash logs (0x7fff...), MAC addresses, file permissions/bitmasks, and byte dumps from tools like hexdump -C or xxd.

Why do programmers and Linux tools prefer hexadecimal over decimal for inspecting raw bytes and memory addresses?

Because each hex digit corresponds to exactly four binary bits, two hex digits always align cleanly with one 8-bit byte—whereas decimal boundaries (powers of 10) do not align with powers of 2.

In base-16 positional notation, each digit represents 4 bits (a nibble), making bitmasking, bitwise shifts, and byte-endianness inspection immediate without base conversion. C, Rust, Python, and shell tools prefix hex literals with 0x (for example, 0xdeadbeef), while network and hardware identifiers use colon-separated octets (MAC, IPv6). When reading little-endian memory dumps on x86_64 or AArch64, multi-byte integers appear byte-reversed in sequential hex dumps (for instance, 0x12345678 stored as 78 56 34 12).

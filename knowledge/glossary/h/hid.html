HID (Human Interface Device)

HID (Human Interface Device) is a standardized protocol used over USB and Bluetooth for input and interaction hardware such as keyboards, mice, touchpads, game controllers, and FIDO2 security keys.

HID is the common language that lets you plug in almost any keyboard, mouse, or security key and have it work right away without hunting for extra drivers. Instead of every brand inventing its own secret format, devices use HID to describe what buttons, axes, or keys they have so your computer understands them automatically.

On Linux, the kernel’s hid-generic (or vendor-specific HID drivers) parses a device’s report descriptor and turns key presses and pointer motion into standard evdev events under /dev/input/event*. Devices that need bidirectional raw packets—like FIDO2/U2F security keys or RGB/firmware configurators—also expose /dev/hidraw* nodes, which require matching udev rules for non-root user access.

Why do browsers and FIDO2 tools access a USB security key via /dev/hidraw* instead of /dev/input/event*?

FIDO2/CTAP2 exchanges structured request-and-response packets directly with the token rather than sending keystrokes or pointer movements, so applications need raw HID packet access through /dev/hidraw* rather than translated evdev input events.

Defined by the USB-IF HID specification and adapted over Bluetooth (HOGP over GATT), an HID device publishes a compact binary Report Descriptor defining Usage Pages, Usages, and Input/Output/Feature report layouts. In Linux, transport drivers (usbhid, i2c-hid, uhid, hidp) feed the core HID layer, which binds either hid-input (mapping usages to evdev codes) or device-specific quirk drivers, while hidraw passes unparsed reports to user space. Permissions on /dev/hidraw* are typically granted per-session via udev uaccess tags.

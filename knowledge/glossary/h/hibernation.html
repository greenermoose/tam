Hibernation

Hibernation is a power-saving state that copies everything in active memory (RAM) to persistent storage and turns the computer completely off, allowing you to resume your exact session later.

Normal sleep keeps your open apps alive using a trickle of battery power, so if the battery dies, your unsaved work is lost. Hibernation is like taking a photograph of your entire desk, packing it into a drawer, and turning off the lights—your computer uses zero power while off, and when you turn it back on, all your windows and tabs reappear right where you left them.

Unlike suspend-to-RAM, hibernation (ACPI S4 / suspend-to-disk) requires a swap partition or swap file at least as large as the active memory image, plus a kernel boot parameter such as resume= (and resume_offset= for a swap file) so the initramfs knows where to reload the image. On systems with Secure Boot enabled, Linux kernel lockdown blocks unauthenticated hibernation images unless signed or disabled.

Why does Linux hibernation require a swap partition or swap file even on a machine with plenty of RAM?

Because RAM loses its contents when power is cut in S4; the kernel must write the entire memory snapshot to non-volatile swap space before powering off so the next boot can restore it.

In Linux swsusp, transitioning to ACPI S4 freezes user-space and kernel threads, quiesces devices, allocates and compresses pages (typically LZO or zstd) into an image written to the designated swap device, and powers down the platform. On resume, the bootloader starts a fresh kernel and initramfs; once the resume= device is parsed, the restore kernel reads the image header, atomically swaps the saved page frames back into physical RAM, and jumps to the saved CPU context—which is why mounting or modifying any filesystem between hibernate and resume causes severe corruption, and why kernel lockdown rejects unsigned images under UEFI Secure Boot.

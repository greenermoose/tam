HRU (Harrison-Ruzzo-Ullman model)

The HRU (Harrison–Ruzzo–Ullman) model is a classic formal access-control model proving that general safety verification is undecidable.

Imagine a giant permission chart listing which users can read or edit which files, along with rules for creating new files and sharing access. You might hope to run an automated checker that guarantees “nobody outside accounting can ever reach the payroll file.” The HRU model proved that once a permission system is flexible enough to create new items and grant rights in combination, no universal checker can answer that question for every possible rulebook.

HRU models protection state as an access matrix (rows for subjects, columns for objects, cells for rights) updated by conditional commands built from primitive operations (enter, delete, create, destroy). This explains why real systems such as SELinux or capability-based kernels constrain how permissions propagate: unrestricted dynamic policy rules make static safety checking equivalent to the halting problem.

What restriction makes safety decidable in the HRU model?

Restricting commands to be mono-operational (each command performs only a single primitive operation, without chaining creations and right grants) makes safety decidable, though it is too restrictive for many real-world policies.

Formalized by Harrison, Ruzzo, and Ullman (1976), a protection system (R, C) defines finite rights R and commands C guarded by matrix predicates that execute sequences of six primitives (enter r into (s,o), delete r from (s,o), create subject/object, destroy subject/object). Safety asks whether an initial matrix Q_0 can ever leak right r into a cell not initially holding it. By encoding a Turing machine’s tape and transitions as subjects, objects, and multi-primitive commands, HRU reduces safety to the halting problem (undecidable in general; PSPACE-complete if create is omitted). Later models such as Take–Grant and the Typed Access Matrix (TAM) recover decidable or linear-time verification through structural constraints.

Guide / Glossary A–Z / Terms beginning with H / Home directory

A home directory is the personal folder assigned to a user account for storing documents, downloads, and per-user settings.

Think of your home directory as your own private desk on a shared computer: it holds your documents, downloads, and app preferences, separate from other people’s files and from core system folders. When you open a file manager or terminal, you start there, and other regular users cannot peek inside or change what you keep there.

On Linux, regular user home directories typically live under /home/alex (while root uses /root), and the shell shortcut ~ or $HOME expands to that path. Hidden dotfiles (names starting with .) and ~/.config store personal preferences without affecting other accounts or needing administrator privileges.

If you edit a setting inside ~/.config, does it affect other users on the same machine?

No. Because each account has its own home directory (for example, /home/alex), changes under ~ apply only to that user. System-wide defaults live under /etc and require elevated privileges to modify.

The authoritative home path is field 6 (pw_dir) of the user’s /etc/passwd or NSS getpwnam entry, exported into HOME at login. Modern Linux desktop software follows the XDG Base Directory Specification (XDG_CONFIG_HOME defaulting to ~/.config, XDG_DATA_HOME to ~/.local/share, XDG_STATE_HOME to ~/.local/state, and XDG_CACHE_HOME to ~/.cache) to separate config, state, and regenerable cache. Operational edge cases include sudo vs. su - preserving or resetting HOME, directory permissions (0700 vs. 0755) on multi-user hosts, and systemd-homed or encrypted home mounts where pw_dir is mounted only after PAM authentication.

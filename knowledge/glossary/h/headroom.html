Headroom

Headroom is the extra capacity—such as free disk space, unused memory, or spare network bandwidth—kept in reserve below a system’s maximum limit.

Think of headroom like keeping a few inches of empty space at the top of a backpack or a little extra gas in your tank. If a disk or memory fills all the way to 100%, a computer slows down or crashes when a program needs even a tiny bit more room. Leaving headroom keeps everyday tasks running smoothly.

In Linux, running out of disk headroom prevents logs, package updates, or login sessions from writing temporary files; similarly, running without memory headroom forces heavy swapping or triggers the OOM killer. Filesystems like ext4 even reserve a small percentage (by default 5% for root) so an ordinary user filling the disk does not lock out system recovery.

Why does Linux ext4 reserve a portion of disk space (often 5%) for the root user by default?

It preserves disk headroom so critical system daemons, root login, and recovery tools can still write temporary files and logs—and reduces file fragmentation—even if a regular user fills the rest of the filesystem.

Headroom acts as an operational buffer against non-linear performance cliffs and allocation failures: copy-on-write filesystems (Btrfs, ZFS) suffer severe metadata fragmentation and sluggish block-group allocation above ~80–85% occupancy; SSDs require over-provisioning and free erase blocks for garbage collection and wear leveling; and Linux memory management relies on vm.min_free_kbytes watermarks so atomic/IRQ allocations succeed without blocking on direct reclaim. Capacity planning sizes headroom for peak bursts, atomic updates, and snapshot retention rather than steady-state averages.

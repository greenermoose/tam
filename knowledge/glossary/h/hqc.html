HQC (Hamming Quasi-Cyclic)

HQC (Hamming Quasi-Cyclic) is a code-based post-quantum key encapsulation mechanism selected by NIST as a backup to ML-KEM.

Modern encryption relies on math puzzles that are easy to lock but hard to unlock without a secret key. Most new quantum-safe tools use geometry puzzles called “lattices.” HQC uses a completely different family of puzzles based on error-correcting codes—the same kind of math that fixes scratches on discs or static on radio signals—giving security teams an independent backup if lattice math is ever broken.

Selected by NIST in 2025 after PQC Round 4, HQC provides a code-based KEM alongside the lattice-based ML-KEM (FIPS 203). In practice, HQC has larger public keys and ciphertexts (a few kilobytes compared to roughly 1 KB for ML-KEM) and slightly higher CPU cost, so ML-KEM stays the everyday default for TLS and SSH while HQC provides mathematical diversity.

Why did NIST select HQC when ML-KEM was already standardized?

Algorithm diversity. ML-KEM relies on Module-LWE lattice assumptions; if a mathematical or quantum attack ever breaks lattices, an independent code-based KEM like HQC provides a ready fallback without sharing the same assumption.

HQC’s security reduces to the Quasi-Cyclic Syndrome Decoding (QCSD) problem over the binary polynomial ring F_2[X]/(X^n - 1) for prime n. Unlike Classic McEliece (which hides a Goppa code’s structure at the cost of 260+ KB public keys), HQC uses a public random quasi-cyclic code (1, h) paired with an explicit concatenated Reed–Muller and Reed–Solomon (RMRS) error-correcting code to decode low-weight noise e + r_2 * y - r_1 * x. It achieves IND-CCA2 security via the Fujisaki–Okamoto transform, requiring a bounded decryption failure rate (< 2^-128) and constant-time RMRS decoding to prevent timing side-channels.

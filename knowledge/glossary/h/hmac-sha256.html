HMAC-SHA256

HMAC-SHA256 is a widely used keyed message authentication code that combines a secret key with the SHA-256 hash function to prove a message is authentic and untampered.

Like a tamper-evident seal made with a secret recipe, HMAC-SHA256 lets two parties who share a secret key verify that a message really came from the other person and was not changed on the way. Anyone without the secret key cannot forge a matching tag, making it a workhorse for logins, API requests, and secure connections.

HMAC-SHA256 is the default workhorse behind webhook signatures, JWTs (HS256), key derivation (HKDF-SHA256), and SSH/TLS integrity checks when AEAD is not used. When verifying an HMAC-SHA256 tag in code, always use a constant-time comparison function (such as hmac.compare_digest in Python) rather than == so attackers cannot leak bytes via timing side channels.

Why must applications compare HMAC-SHA256 tags with a constant-time function instead of a normal string equality check?

A standard equality check stops at the first mismatched byte, creating tiny timing differences that an attacker can measure over many requests to guess a valid tag byte by byte.

Defined in RFC 2104 and RFC 4868, HMAC-SHA256 evaluates SHA256((K' XOR opad) || SHA256((K' XOR ipad) || m)) with a 64-byte block size (keys longer than 64 bytes are hashed first; shorter keys are zero-padded) and yields a 256-bit (32-byte) tag, optionally truncated to 128 bits in protocols like IPsec. It provides 256-bit preimage and ~128-bit/256-bit MAC forgery resistance under standard PRF assumptions, and serves as both the extract and expand primitive in HKDF (RFC 5869) and the PRF in TLS 1.2 and PBKDF2-HMAC-SHA256.

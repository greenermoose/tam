HT (Horizontal Tab, 0x09)

HT (Horizontal Tab, byte 0x09) is the ASCII control character produced by the Tab key or Ctrl+I that advances the cursor to the next tab stop.

On an old typewriter, pressing Tab jumped the carriage forward to preset column stops so you could line up tables or indent paragraphs without tapping Space over and over. In text files and terminals today, the Tab key inserts this single invisible character instead of multiple spaces, and the program showing the text decides how wide that jump looks.

Part of the C0 control codes (0x00–0x1F), HT (0x09) is written \t in C, Python, and shell strings. Because Ctrl+I transmits the exact same byte in traditional terminal input, terminal programs cannot tell Tab and Ctrl+I apart without an extended keyboard protocol. File formats also treat HT differently: Makefiles require a literal tab before recipe commands, whereas YAML forbids tabs for indentation.

Why does pressing Ctrl+I in a terminal often trigger tab completion just like the Tab key?

In classic ASCII terminal encoding, I is the 9th letter after @ (0x49 - 0x40 = 0x09), so Ctrl+I sends the exact same byte (0x09, HT) as the Tab key.

ECMA-48 / ANSI X3.64 defines HT (0x09) as advancing the active presentation position to the next forward tabulation stop (defaulting to every 8 columns, (col + 8) & ~7, though terminfo hts/tbc sequences ESC H and ESC [ 3 g configure custom stops). On Linux PTYs with termios OPOST output processing, TABDLY (XTABS/TAB3) expands 0x09 into spaces in the kernel line discipline before the terminal emulator sees it. Modern terminals supporting the Kitty keyboard protocol or CSI u can disambiguate Ctrl+I from Tab via CSI sequences, whereas legacy termios raw input collapses both to 0x09.

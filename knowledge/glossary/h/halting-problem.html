Guide / Glossary A–Z / Terms beginning with H / Halting problem

The provably unsolvable problem of deciding, for any arbitrary program and input, whether it will eventually stop or run forever.

Imagine trying to build a universal “freeze detector” tool that can inspect any program before you run it and tell you with 100% certainty whether it will finish its work or get stuck in an endless loop. In 1936, mathematician Alan Turing proved that no such universal checker can ever exist. No matter how clever the checker is, you can always construct a tricky program that asks the checker what it will do and then deliberately does the opposite—forcing the checker to be wrong.

Because the halting problem is undecidable, compilers, linters, and security scanners cannot automatically prove every property of arbitrary code without either missing some bugs or rejecting some safe programs. Systems that need a strict guarantee of termination therefore restrict what programs are allowed to express: for example, the Linux kernel’s eBPF verifier rejects arbitrary unbounded loops so every loaded program is guaranteed to finish, and access-control models like HRU show that unrestricted policy rules make safety verification impossible in general.

Why can the Linux kernel’s eBPF verifier guarantee that an eBPF program will terminate, even though the halting problem is unsolvable in general?

The halting problem applies to arbitrary general-purpose (Turing-complete) programs. The eBPF verifier avoids it by restricting programs to bounded loops and acyclic control flow, rejecting any program whose termination it cannot statically prove.

Proved undecidable by Alan Turing in 1936 using diagonalization, the halting problem asks whether a universal decider H(M, w) exists that returns true iff Turing machine M halts on input w. Assuming H exists allows constructing a machine D(M) that loops forever if H(M, M) is true and halts otherwise; evaluating D(D) yields a contradiction. The halting language is recursively enumerable (semi-decidable by simulation) but not decidable, and its complement is not recursively enumerable. By Rice’s theorem, every non-trivial semantic property of a program’s input-output behavior is likewise undecidable, which is why static analyzers must trade soundness against completeness and why formal security models such as HRU prove general safety undecidable via reduction from halting.

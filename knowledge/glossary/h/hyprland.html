Hyprland

Hyprland is the tiling Wayland compositor Tamlinux uses today for its graphical desktop.

Instead of letting windows pile up and overlap like loose papers on a desk, Hyprland automatically arranges them side by side in neat tiles so you can see and reach them with keyboard shortcuts (such as the Meta key). It draws the screen and passes your clicks and keystrokes to apps. Tamlinux packages Hyprland with its own binding files, while Sway is a planned future target.

Hyprland is an independent Wayland compositor—combining window management and screen compositing in a single process rather than using X11’s separate window manager—with its own configuration language and plugin ABI. Legacy X11 apps run through XWayland. In Tamlinux, keybindings and layout rules live under the product session tree, so you should check those packaged files rather than relying on stock upstream Hyprland defaults or another distribution’s chords.

Why might an upstream Hyprland shortcut guide not work on Tamlinux?

Because Tamlinux ships product-specific binding files in its session tree that override upstream defaults; checking the packaged Tamlinux configuration shows the actual active shortcuts.

The current Tamlinux Wayland compositor; configuration and bindings are product-specific overlays on upstream Hyprland. Built around Wayland core protocols plus xdg-shell, wlr-layer-shell, and custom hyprland-* extensions, it exposes runtime state and event streams over Unix sockets (.socket.sock and .socket2.sock in $XDG_RUNTIME_DIR/hypr/<instance>) for hyprctl automation. Operational trade-offs include a volatile C++ plugin ABI tied closely to upstream releases, fractional-scaling blurriness in XWayland clients, and single-process blast radius where a compositor crash terminates all client Wayland surfaces.

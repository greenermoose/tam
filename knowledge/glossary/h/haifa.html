Guide / Glossary A–Z / Terms beginning with H / HAIFA (HAsh Iterative FrAmework)

A structural design pattern for cryptographic hash functions that mixes a salt and a running bit counter into every step to prevent length-extension and multi-target attacks.

When building a digital “fingerprint” tool (a cryptographic hash), engineers need a recipe for processing long messages piece by piece. Older recipes had clever shortcuts that attackers could sometimes exploit—for example, tacking extra data onto the end of a message without knowing the secret inside it. HAIFA is a newer, sturdier recipe that stamps each step with how much data has been seen so far and a random-looking tag, closing those shortcuts.

Older hash functions such as MD5, SHA-1, and SHA-2 use the Merkle–Damgård construction, where knowing H(secret || message) allows an attacker to compute H(secret || message || padding || extra) without knowing the secret—a flaw known as a length-extension attack. HAIFA (HAsh Iterative FrAmework), used most famously by BLAKE and BLAKE2 (and carried forward in simplified form in BLAKE3), prevents this by feeding a message-length counter and an optional salt into every compression block, and by distinguishing the final block.

Why can you safely compute a keyed MAC with BLAKE2 directly, whereas SHA-256 requires a wrapper like HMAC?

SHA-256’s Merkle–Damgård structure is vulnerable to length-extension attacks if used as H(key || message). HAIFA-based designs like BLAKE2 include block counters and finalization flags (plus dedicated keying parameters), so appending data cannot extend a valid digest.

Proposed by Eli Biham and Orr Dunkelman (2006), HAIFA generalizes Merkle–Damgård by defining the chaining iteration as h_i = C(h_{i-1}, M_i, #bits, salt), where #bits is the cumulative number of message bits processed through block i (set to 0 in padding-only final blocks, or flagged separately) and salt is a fixed-length domain/instance parameter. Including #bits defeats Kelsey–Kohno herding and Joux multicollision second-preimage extensions, while domain-separating the final compression and using a salt mitigates precomputed rainbow-table and multi-target attacks. Note that while SHA-3 (Keccak sponge) avoids Merkle–Damgård via capacity separation, BLAKE2’s HAIFA compression achieves similar structural resistance with high software throughput on 64-bit SIMD architectures.

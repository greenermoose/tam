IBRS (Indirect Branch Restricted Speculation)

A CPU hardware mitigation that restricts speculative indirect-branch prediction across privilege levels.

To run faster, modern processors guess where a program’s code will jump next before checking for sure. Without extra protection, an ordinary app could train that guessing system to trick the operating system core into briefly touching secret data. IBRS is a hardware lock that stops lower-privilege apps from steering the processor’s guesses inside the OS core.

IBRS mitigates Spectre v2 (branch target injection) alongside or instead of software Retpoline. On Linux, you can check which mitigation is active in /sys/devices/system/cpu/vulnerabilities/spectre_v2. Legacy IBRS required writing a CPU control register on every entry to the kernel, adding noticeable syscall overhead; newer CPUs support Enhanced IBRS (eIBRS), which is enabled once at boot and enforces isolation in hardware with much lower performance cost.

Why is Enhanced IBRS (eIBRS) preferred over original IBRS on newer processors?

Original IBRS forced the kernel to write a model-specific register on every privilege transition to flush or restrict branch predictions, slowing down system calls. eIBRS enforces the isolation continuously in hardware after a single boot-time enable.

On x86, IBRS is controlled via MSR_IA32_SPEC_CTRL (0x48) bit 0, enumerated by CPUID.(EAX=7,ECX=0):EDX[26], while eIBRS support is advertised in IA32_ARCH_CAPABILITIES[1] (IBRS_ALL) or AMD AUTOIBRS. Legacy IBRS prevents Branch Target Buffer (BTB) entries trained before the MSR write from controlling indirect-branch speculation afterward, but imposes heavy WRMSR latency on syscall and VM-exit boundaries. eIBRS tags predictor entries with privilege/mode context so user or guest predictions cannot steer kernel or host speculation. Remaining edge cases such as Branch History Injection (BHI) require complementary controls (BHI_DIS_S or software clearing sequences) because BHB state still crosses privilege boundaries on some microarchitectures.

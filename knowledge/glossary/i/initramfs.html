Initramfs (initial RAM filesystem)

A small, temporary in-memory filesystem loaded during early boot so the kernel can prepare storage and mount the real root filesystem.

Think of an initramfs as a compact travel toolkit the computer unpacks into memory right as it wakes up. Before the main drive is unlocked and ready, the computer uses the tools inside that toolkit—like a key prompt for an encrypted disk or a driver for a storage card—to open the main system and hand off control.

The bootloader loads both the Linux kernel and the initramfs image into RAM before starting the kernel. On systems using full-disk encryption (LUKS), LVM, RAID, or network root filesystems, the initramfs provides the user-space utilities and kernel modules needed to prompt for a passphrase, assemble volumes, and mount the real root filesystem.

Why can’t the Linux kernel always mount the root filesystem directly without an initramfs?

Because the root filesystem may sit on an encrypted LUKS volume, LVM/RAID array, or storage device whose unlock utilities or modular drivers are not compiled directly into the kernel binary.

An initramfs is a (usually compressed) newc-format cpio archive—optionally prefixed with uncompressed CPU microcode—that the kernel unpacks into an internal rootfs (a tmpfs/ramfs instance) and executes /init as early PID 1. Unlike the legacy block-device initrd (which relied on a ramdisk driver and pivot_root), initramfs transitions via switch_root, deleting the temporary rootfs contents to reclaim RAM before execing the real /sbin/init.

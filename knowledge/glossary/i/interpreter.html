Interpreter

A program that reads and executes source code or an intermediate representation directly, without requiring a separate ahead-of-time native binary.

Think of a live translator at a speech compared to someone translating a whole book in advance. A compiler translates an entire program into machine language ahead of time so it runs later; an interpreter reads each part of the program on the spot and carries out the steps right away, making quick edits and testing much easier.

Shell scripts (bash), python3, perl, and awk all rely on interpreters. On Linux, when you run an executable script beginning with a shebang line such as #!/usr/bin/env python3, the kernel launches that interpreter and passes your script file to it. Interpreters trade some raw execution speed for portability and interactive debugging.

What does the Linux kernel do when you execute a script that starts with #!/bin/sh?

It reads the shebang line and executes /bin/sh with the script’s path as an argument, letting the shell interpreter parse and run the file.

Production interpreters rarely evaluate raw source text repeatedly; instead they parse source into an AST and compile it to stack- or register-based bytecode executed by a VM dispatch loop (using switch dispatch, threaded code, or computed goto to improve branch-predictor locality). High-performance runtimes pair an interpreter with a tracing or method-based JIT compiler and inline caches to eliminate dynamic-typing and dispatch overhead on hot paths, trading memory footprint for throughput.

Guide / Glossary A–Z / Terms beginning with I / Interrupt

An interrupt is a signal that makes the CPU pause its current work so the kernel can handle an event.

Interrupts are like a doorbell. A device such as a keyboard or network card rings when something needs attention. The kernel answers briefly, then the program that was running carries on from where it stopped. You can read the count of interrupts on a Linux system in /proc/interrupts.

Hardware interrupts come from devices through an IRQ, from timers, and from signals sent between CPU cores. A system call or an exception also enters the kernel, but it is caused by the running program itself rather than by an outside event. The kernel saves the state of the interrupted task, runs a short handler, then returns to that task or switches to another one.

Linux runs a hardirq top half in interrupt context, where sleeping is forbidden, and defers longer work to softirqs, tasklets or threaded handlers. Message-signaled interrupts (MSI/MSI-X) replace shared legacy lines on modern PCIe devices. An interrupt may set the need-reschedule flag, so returning from it can lead to a context switch rather than a direct return to the previous task.

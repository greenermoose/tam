Instruction

A single, elementary operation—such as adding two numbers or reading a value from memory—that a processor can decode and execute.

Think of a processor as a chef following a recipe written in tiny steps: “pick up bowl”, “pour one cup”, “stir”. Each tiny step is an instruction. Programs written by humans are translated into millions of these basic steps so the hardware can carry them out one after another at billions of steps per second.

Machine instructions belong to a processor’s instruction set architecture (ISA), such as x86-64 or ARM64, which is why a binary compiled for one CPU family cannot run natively on another. You can inspect the machine instructions inside a compiled Linux program with objdump -d. On x86-64, instruction lengths vary from 1 to 15 bytes, whereas ARM64 uses fixed 32-bit instructions.

Why can’t a binary compiled for an x86-64 laptop run natively on an ARM64 phone?

Because the two processors implement different instruction set architectures (ISAs), meaning their binary opcodes, register layouts, and instruction encodings are incompatible.

An ISA-defined instruction encoding specifies an opcode, register or immediate operand specifiers, addressing modes, and optional prefixes (such as x86 REX/VEX/EVEX). In out-of-order superscalar CPUs, architectural instructions are fetched, decoded—often cracked into internal micro-operations (uops)—renamed to physical registers to eliminate WAR/WAW hazards, dispatched to execution ports, and retired in program order via the reorder buffer (ROB) to preserve precise exceptions.

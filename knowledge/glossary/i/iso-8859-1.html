ISO 8859-1 (Latin-1)

An 8-bit, single-byte character encoding for Western European languages, also known as Latin-1.

Before UTF-8 became the universal way to store text, computers used smaller regional tables that fit every letter into a single byte (256 slots). ISO 8859-1 was the standard table for Western European languages: the first half held plain English letters and digits, and the second half added accented characters like é, ñ, and ü plus symbols like £ and ©. Today it still turns up in older files, emails, and web pages—and when a modern UTF-8 program reads it without converting, accented letters turn into garbled symbols.

Latin-1 keeps standard 7-bit ASCII in bytes 0x00–0x7F and places Western European letters and punctuation in 0xA0–0xFF, leaving 0x80–0x9F unassigned in ISO 8859-1 itself (reserved for C1 control codes in ISO/IEC 6429, whereas Windows-1252 fills 0x80–0x9F with printable characters like € and curly quotes). On Linux, you can convert legacy Latin-1 files to UTF-8 with iconv -f ISO-8859-1 -t UTF-8 old.txt > new.txt, and HTML5 browsers treat iso-8859-1 labels as Windows-1252 in practice.

Why does opening an ISO 8859-1 file containing the word café in a strict UTF-8 viewer fail or show a replacement character?

In ISO 8859-1, é is the single byte 0xE9. In UTF-8, 0xE9 is the leading byte of a 3-byte sequence; followed by a newline or ASCII character, it is an invalid UTF-8 byte sequence rather than é (0xC3 0xA9).

ISO/IEC 8859-1:1998 defines an 8-bit single-byte coded character set whose graphic characters 0x20–0x7E and 0xA0–0xFF map 1:1 to Unicode code points U+0020–U+007E and U+00A0–U+00FF (the Latin-1 Supplement block), while 0x00–0x1F (C0) and 0x80–0x9F (C1) are control-code ranges defined outside 8859-1 by ISO/IEC 6429. Because UTF-8 encodes non-ASCII code points using bytes 0x80–0xF4—including continuation bytes 0x80–0xBF—raw 8-bit C1 controls such as 0x9B (8-bit CSI) collide with UTF-8 multi-byte sequences; consequently, UTF-8 terminals require 7-bit ESC [ (0x1B 0x5B) instead of bare 0x9B and reject invalid C1 or Latin-1 bytes as malformed UTF-8.

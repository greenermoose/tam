Guide / Glossary A–Z / Terms beginning with I / IMC (Integrated Memory Controller)

Circuitry built directly into a modern processor that manages reading from and writing to the computer’s main memory (RAM).

Think of RAM as a busy warehouse of shelves and the processor as a factory floor. The IMC is the dispatcher sitting right inside the factory, fetching materials and storing finished parts without sending messengers down the road to another chip. That direct connection makes the whole computer feel snappier and avoids traffic jams when several programs need data at once.

Moving the memory controller from a separate motherboard chip (the old northbridge) onto the CPU die dramatically reduced memory latency and tied supported RAM types (such as DDR4 or DDR5) and channel counts directly to the processor model. On Linux, you can inspect memory layout with dmidecode -t memory, and populating multiple channels matters because the IMC stripes requests across them for higher bandwidth.

Why does installing two matching RAM sticks in separate channels usually outperform one stick of the same total capacity?

Because the IMC can interleave reads and writes across both memory channels in parallel, roughly doubling peak memory bandwidth compared to using a single channel.

An on-die IMC implements out-of-order DRAM command scheduling (typically FR-FCFS to exploit open row buffers), refresh management (tREFI/tRFC), power-down states, and physical-layer (PHY) link training across DDR4/DDR5 command, address, and data buses. In multi-socket or chiplet NUMA topologies, each socket or I/O die hosts its own IMC(s), so remote accesses incur cross-interconnect latency; ECC-capable IMCs also perform inline SECDED syndrome checking and background patrol scrubbing, reporting faults via EDAC and MCE.

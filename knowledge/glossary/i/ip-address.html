IP address

A numeric address that identifies a network interface so packets can be routed to and from it.

An IP address is like a street address for a device on a network. Just as a postal carrier needs a destination address to deliver a letter and a return address to send a reply, your computer and the servers you visit use IP addresses so data packets know where to go and where to come back. Without an IP address, a device can sit on a Wi-Fi or wired connection, yet no internet traffic can reach it.

On Linux, IP addresses are assigned to network interfaces (visible with ip addr), not to the machine as a whole—a laptop with both Ethernet and Wi-Fi can hold separate addresses simultaneously, alongside 127.0.0.1 (::1 in IPv6) on the loopback interface lo. Two versions coexist: IPv4 (192.0.2.10) and IPv6 (2001:db8::1), configured statically or automatically via DHCP or SLAAC. An address alone is not enough for routing; it is paired with a subnet mask or CIDR prefix length (such as /24) that tells the kernel which peers are on the local link versus reachable through a default gateway.

If two computers have IP addresses 192.168.1.10/24 and 192.168.2.10/24 on the same switch, why can they not reach each other directly without a router?

The /24 prefix means only the first 24 bits define the local subnet. Because 192.168.1 and 192.168.2 differ in the third octet, each host treats the other as remote and sends packets to its default gateway rather than resolving the peer directly with ARP.

An IP address is a Layer 3 locator (32-bit for IPv4 per RFC 791; 128-bit for IPv6 per RFC 8200) whose semantics depend on prefix length and scope. In IPv6, a single interface routinely binds multiple addresses with distinct lifetimes and scopes: a link-local fe80::/10 address (requiring a zone index such as %eth0 for sockets), one or more SLAAC global unicast addresses, and RFC 4941 privacy/temporary addresses for outbound connections while keeping stable addresses for inbound services. Linux implements the weak host model by default for IPv4 (tunable via net.ipv4.conf.*.arp_ignore and rp_filter), allowing packets for an address on one interface to arrive on another unless strict source validation or policy routing (ip rule) is configured.

Guide / Glossary A–Z / Terms beginning with I / IPC (Inter-Process Communication)

Mechanisms that let separate operating-system processes exchange data and coordinate work.

Each running program on a computer lives in its own protected bubble of memory so one crashing app cannot scramble another app’s data. IPC is the set of controlled doorways that the operating system provides so programs can still talk to each other safely—for example, when a web browser asks a helper process to render a tab, or when one command-line tool passes its output directly to another.

Linux provides several IPC mechanisms with different trade-offs. Anonymous pipes (|) and FIFOs stream bytes between commands, Unix domain sockets (AF_UNIX) support bidirectional messaging and file-descriptor passing (used by D-Bus, Wayland, and systemd), shared memory (shm_open or memfd_create) avoids copying large buffers like video frames, and signals (SIGTERM, SIGUSR1) deliver lightweight notifications. Because processes do not share address spaces by default, you can inspect active IPC endpoints on a running system with tools like ss -x (Unix sockets) and ipcs (SysV IPC).

Why does a Wayland compositor use shared memory (memfd_create) plus a Unix socket instead of sending every pixel over the socket?

Copying multi-megabyte framebuffers through kernel socket buffers 60 or more times per second wastes CPU and memory bandwidth. Passing a shared-memory file descriptor once over AF_UNIX (SCM_RIGHTS) lets the client and compositor map the same physical pages, using the socket only for small damage and synchronization messages.

POSIX and Linux IPC span kernel-buffered channels (pipes, POSIX/SysV message queues, AF_UNIX sockets), zero-copy shared memory (mmap over tmpfs/memfd_create or shmget), and synchronization primitives (futex, POSIX semaphores, eventfd). Security and isolation boundaries apply differently to each: AF_UNIX supports SO_PEERCRED (uid/gid/pid) and SCM_RIGHTS capability transfer, whereas SysV IPC keys live in a global namespace unless isolated via CLONE_NEWIPC (IPC namespaces). Failure modes include deadlocks on full pipe buffers (PIPE_BUF atomicity guarantees apply only to writes ≤ 4096 bytes on Linux), SIGPIPE termination when readers close early, and leaked /dev/shm or SysV segments after SIGKILL.

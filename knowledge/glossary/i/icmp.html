ICMP - Internet Control Message Protocol

A network-layer protocol used by devices and routers to send control, diagnostic, and error messages.

ICMP is the network’s postal status system rather than a way to carry web pages or files. When a packet cannot be delivered, takes too many hops, or when you run a quick “are you there?” check with ping, routers and computers use ICMP to send back short error or status notes.

Internet Control Message Protocol carries diagnostic and error messages for IP, including Echo Request/Reply (used by ping), Destination Unreachable, and Time Exceeded (used by traceroute). It also powers Path MTU Discovery: when a router cannot forward an oversized packet without fragmenting it, an ICMP error tells the sender to shrink its packet size. Blocking all ICMP indiscriminately in a firewall can break large transfers even though basic connections appear to open.

Why can dropping all ICMP packets in a firewall cause large downloads to stall?

Path MTU Discovery relies on ICMP “Fragmentation Needed” (IPv4) or “Packet Too Big” (IPv6) messages to learn the smallest link size along a route; if those errors are blocked, the sender keeps transmitting oversized packets that get silently dropped.

Encapsulated directly in IP (protocol 1 for IPv4, RFC 792; Next Header 58 for ICMPv6, RFC 4443), ICMP headers carry Type, Code, and a 16-bit one’s-complement checksum (ICMPv6 covers an IPv6 pseudo-header). Unlike IPv4, IPv6 makes ICMPv6 mandatory for core link operations: Neighbor Discovery Protocol (NDP: RS/RA/NS/NA) replaces ARP, and MLD handles multicast membership. Operational and security considerations include strict error-rate limiting (RFC 4443 §2.4) to prevent amplification or CPU exhaustion, and Linux’s net.ipv4.ping_group_range sysctl, which permits unprivileged SOCK_DGRAM IPPROTO_ICMP sockets without requiring CAP_NET_RAW.

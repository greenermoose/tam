ISA - Instruction Set Architecture

The formal specification of instructions, data types, and hardware features that a processor understands.

An ISA is the shared language between software and a CPU. Just as a recipe written in English only works for someone who reads English, a program compiled for one ISA—such as x86-64 on most PCs or ARM64 on phones—can only run directly on a processor built for that same ISA. Two different chips can be designed differently inside, yet run the exact same programs as long as they implement the same ISA.

In Linux, you see the ISA in package and kernel architecture names such as x86_64 (amd64), aarch64 (arm64), and riscv64. Crucially, the ISA is separate from the microarchitecture: Intel and AMD both implement the x86-64 ISA, so the same compiled Linux binary runs on both, even though their internal pipelines, caches, and branch predictors differ. When software must run across ISAs (for example, running an aarch64 container on an x86_64 host), tools like qemu-user translate instructions in software at a performance cost.

Why can the same compiled x86_64 binary run on both an AMD Ryzen CPU and an Intel Core CPU without recompiling?

Both processors implement the same x86-64 instruction set architecture—the same opcodes, registers, and programmer-visible behavior. Their internal hardware designs (microarchitectures) differ, but the ISA contract guarantees binary compatibility.

An ISA defines the hardware-software interface: instruction encodings, architectural register files, addressing modes, privilege rings or exception levels (e.g., x86 Ring 0–3, ARM EL0–EL3, RISC-V M/S/U modes), virtual-memory page-table formats, and the memory consistency model (e.g., x86-TSO versus ARMv8 and RISC-V weak ordering requiring explicit barriers). On Linux, user-space ABIs (like the System V AMD64 ABI) layer calling conventions and syscall boundaries atop the ISA, while optional ISA extensions (AVX-512, SVE, RISC-V Vector) are discovered at runtime via CPUID, AT_HWCAP, or riscv_hwprobe so binaries can dispatch optimized paths without breaking baseline compatibility.

Guide / Glossary A–Z / Terms beginning with I / IOMMU (Input-Output Memory Management Unit)

A hardware unit that translates and restricts memory addresses used by peripheral devices during Direct Memory Access (DMA), isolating devices from arbitrary system RAM.

Fast add-on hardware like graphics cards, network cards, or Thunderbolt docks can write straight into your computer’s memory without asking the processor every time. Without an IOMMU, a buggy or malicious plugged-in device could read passwords or overwrite anything in RAM. The IOMMU acts like a security guard at the memory door, giving each device its own private mailbox and blocking it from touching anything else.

Intel calls this hardware VT-d, AMD calls it AMD-Vi, and ARM systems call it SMMU. Enabling the IOMMU in firmware and Linux defends against physical DMA attacks over Thunderbolt or PCIe and is required for VFIO GPU passthrough into virtual machines. You can inspect which devices share isolation boundaries under /sys/kernel/iommu_groups/.

Why does VFIO device passthrough to a virtual machine require an IOMMU?

Because the IOMMU translates the guest VM’s memory addresses into host physical addresses and confines the passed-through device so it cannot DMA into the host kernel or other VMs.

An IOMMU walks multi-level I/O page tables (indexed by PCIe Requester ID) to translate I/O Virtual Addresses (IOVAs) to host physical addresses, caching entries in an IOTLB and enforcing per-device read/write permissions alongside interrupt remapping for MSI/MSI-X writes. In Linux, devices sharing non-isolated downstream ports fall into the same IOMMU group—the minimum granularity for VFIO ownership—and strict unmap mode (iommu.strict=1) trades throughput for immediate IOTLB invalidation to close transient stale-mapping windows.

Guide / Glossary A–Z / Terms beginning with I / Interoperability

Interoperability is the ability of different programs, devices or services to work together. It is stronger than "they can exchange bytes": the systems must agree on meaning well enough that the result still makes sense.

Two messaging apps are interoperable when a person on one can talk to a person on the other without either of them changing apps. A shared format or service makes that possible. If only one side understands the messages, the systems are connected but not interoperable.

Open specifications reduce the guesses each implementation must make. The IETF (Internet Engineering Task Force) develops internet protocols through review and running code; the W3C (World Wide Web Consortium) uses shared web tests to check browser agreement. In messaging, RCS (Rich Communication Services) depends on carriers and clients following the same GSMA Universal Profile, so capability discovery and fallbacks behave in the same way on both sides.

Interoperability can conflict with privacy promises. A common transport may work across services while forcing a lowest-common-denominator security mode, or a relay may keep metadata that a closed service would not expose. The useful question is therefore not only "can they talk?" but "what guarantees survive the exchange?" Standards documents define the expected behaviour; measurement against real implementations shows whether it holds.

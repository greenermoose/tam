Guide / Glossary A–Z / Terms beginning with I / Inode

A filesystem data structure that stores a file’s metadata and where its contents live on disk, separate from its filename.

Think of a directory as a label on a folder and an inode as the hidden catalog card it points to. The folder only holds the file’s name; the catalog card records who owns the file, who can read or edit it, how big it is, and where its data sits on the drive. Because the name and the card are separate, two names can point to the exact same file.

In Linux filesystems like ext4 and XFS, directories map filenames to inode numbers (viewable with ls -i, while stat shows the full inode metadata). Creating a hard link (ln a b) gives two filenames the same inode number, and deleting a file only frees its blocks once its link count drops to zero and no process holds it open. A disk with millions of tiny files can also run out of inodes (df -i) even when free gigabytes remain.

If you delete a huge log file while a program still has it open, why doesn’t free disk space return immediately?

Because removing the directory entry only drops the link count to zero; the kernel keeps the inode and its data blocks allocated until the last open file descriptor is closed.

An on-disk inode (for example, 256 bytes by default in ext4) stores i_mode, i_uid/i_gid, i_size, i_links_count, nanosecond timestamps, flags, extended attributes, and block or extent-tree mappings (ext4_extent_header). In the Linux VFS, struct inode is cached alongside struct dentry; unlinking decrements i_nlink, while evict_inode() runs only when both i_nlink == 0 and reference count i_count == 0. Copy-on-write filesystems like Btrfs allocate inodes dynamically in B-trees rather than fixed tables.

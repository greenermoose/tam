ISO/IEC 9899 (C standard)

The international standard series that defines the C programming language and its standard library.

C is one of the foundational languages used to build operating systems, drivers, and system utilities. ISO/IEC 9899 is the official rulebook that spells out exactly how C works—what keywords exist, how numbers and text behave, and what built-in functions every C system must provide—so a C program written carefully can be compiled on many different computers without rewriting it from scratch.

Published in major editions—C90, C99, C11, C17, and C23—ISO/IEC 9899 lets you tell compilers like gcc or clang which ruleset to enforce using flags such as -std=c11 or -std=c23. The standard distinguishes between hosted environments (a full OS with stdio.h, malloc, and main) and freestanding environments (kernels or firmware with only minimal headers like stdint.h and stddef.h). In practice, Linux programs often mix standard C with POSIX APIs (like fork or open, enabled via _POSIX_C_SOURCE) or GNU extensions (-std=gnu11 versus strict -std=c11).

What changes when you compile a C file with -std=c11 instead of -std=gnu11?

-std=c11 enforces strict ISO/IEC 9899:2011 conformance and disables non-standard GNU extensions and POSIX feature macros by default, whereas -std=gnu11 enables GNU extensions alongside C11.

Developed by ISO/IEC JTC 1/SC 22/WG 14, ISO/IEC 9899 defines an abstract machine whose observable behavior is governed by sequenced-before relations, strict aliasing (effective type) rules, and a formal multi-threaded memory model introduced in C11 (<stdatomic.h>, <threads.h>). The standard partitions non-portable constructs into implementation-defined behavior (documented by the compiler and ABI, such as sizeof(long)), unspecified behavior (such as argument evaluation order), and undefined behavior (UB, such as signed integer overflow or out-of-bounds dereference), which optimizing compilers exploit as unreachable states. Tamlinux targets ISO/IEC 9899:2011 (C11) for core native tools.

JWT (JSON Web Token)

A JWT (JSON Web Token) is a compact, URL-safe token format used to pass verified identity and permission claims between services.

Think of a JWT like a stamped concert wristband: after you show your ID at the entrance once, the wristband tells every gate inside who you are and when your pass expires without making you log in again. Because it is short and text-based, websites and apps can easily send it along with every request.

Used heavily in OpenID Connect (OIDC) and web APIs, a JWT carries JSON “claims”—such as sub (subject), iss (issuer), and exp (expiration time)—usually wrapped in a JWS signature. Because a JWT is self-contained, a backend server can verify it locally without querying a central session database on every request. The trade-off is that a valid, unexpired JWT cannot easily be revoked before exp unless the server maintains a revocation list.

Why do APIs typically keep JWT access-token lifetimes short (minutes rather than months)?

Because JWTs are stateless and self-contained; if a token is stolen, it remains valid until its exp timestamp unless the server adds stateful revocation checks.

Defined in IETF RFC 7519, a JWT is a JSON Claims Set serialized inside either a JWS (signed) or JWE (encrypted) container, with registered claims (iss, sub, aud, exp, nbf, iat, jti) and extensible public/private claims. Secure verification requires validating the cryptographic signature against an expected key and algorithm first, then enforcing iss, aud, and exp/nbf (allowing bounded clock skew), and distinguishing ID tokens from OAuth 2.0 access tokens (RFC 9068) to prevent cross-audience token substitution.

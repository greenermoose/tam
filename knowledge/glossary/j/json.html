JSON (JavaScript Object Notation)

JSON (JavaScript Object Notation) is a lightweight, text-based data format that represents structured information as key-value pairs and lists.

Think of JSON like a neatly labeled set of folders and checklists written in plain text: curly braces hold named settings (like "name": "alex"), and square brackets hold ordered lists. Because both people and programs can read it without special tools, it is one of the most common ways apps save preferences and share information over the web.

On Linux, JSON appears in configuration files, web APIs, and CLI tool output—for example, tam’s index.json, Waybar and Hyprland IPC output (hyprctl -j), and LUKS2 disk encryption headers. Tools like jq let you filter and transform JSON right in the terminal. Unlike YAML or TOML, JSON does not allow comments or trailing commas, so a single stray comma will make a parser reject the file.

Why do many Linux CLI tools offer a --json or -j flag alongside human-readable tables?

Because human-readable tables change column widths and wording across versions, whereas JSON provides a stable, typed structure that scripts and jq can parse reliably without brittle text splitting.

Specified by RFC 8259 (and ECMA-404), JSON defines six value types—object, array, string, number, boolean, and null—encoded in UTF-8 without a BOM. Its simplicity hides common interoperability traps: RFC 8259 specifies no integer/float distinction or precision limit, so 64-bit integers (such as 64-bit IDs) silently lose precision in IEEE 754 double-precision parsers (e.g., JavaScript Number); duplicate object keys are discouraged rather than forbidden, allowing parser-differential attacks; and strict parsers reject NaN, Infinity, and unescaped control characters.

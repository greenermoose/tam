Sudo (superuser do)

sudo (“superuser do”) is a command that lets an authorized user run a single command with another user’s—usually root’s—permissions.

On Linux, your everyday user account is kept away from system-wide settings so a mistake cannot accidentally break the whole machine. Instead of logging in full-time as the all-powerful administrator (root), sudo acts like borrowing the master key for one specific door: you type your own password, run the one administrative task you need, and immediately go back to normal permissions.

When you run sudo <command>, it checks the rules in /etc/sudoers (and /etc/sudoers.d/), asks for your password—not root’s—and logs the action. By default it caches your authentication for a few minutes so you do not have to retype your password on every command. To edit sudoers safely, use visudo, which validates syntax before saving so you do not lock yourself out.

Why does sudo echo "x" > /etc/example still fail with “Permission denied”?

Because the shell sets up the output redirection (> /etc/example) before running sudo, so the redirection runs with your normal user permissions. Only echo runs as root; use echo "x" | sudo tee /etc/example instead.

sudo is a setuid-root policy engine that parses sudoers(5) rules, authenticates via PAM, and drops or switches credentials (setresuid/setresgid, supplementary groups) before execve(). For safety, env_reset strips most caller environment variables and replaces PATH with secure_path, preventing library-injection attacks via LD_PRELOAD or tampered PATH binaries. Authentication timestamps are scoped by tty/ppid (modern sudo stores per-session records in /run/sudo/ts/) and can be invalidated early with sudo -k. Fine-grained sudoers entries must beware of “escape” commands (editors, pagers, or find -exec) that spawn shells as root unless restricted with NOEXEC.

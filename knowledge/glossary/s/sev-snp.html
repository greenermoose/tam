SEV-SNP (Secure Encrypted Virtualization - Secure Nested Paging)

SEV-SNP (Secure Encrypted Virtualization – Secure Nested Paging) is an AMD CPU security feature that encrypts a virtual machine’s memory and prevents the host hypervisor from tampering with it.

Normally, the company or server hosting a virtual machine can peek into everything that virtual machine is doing in memory, much like a landlord with a master key to your apartment. SEV-SNP gives each virtual machine its own hardware-enforced lock and encryption key inside the CPU chip itself, so even the server’s administrator or a compromised host operating system cannot read or alter the guest’s private memory.

Earlier AMD SEV encrypted guest RAM against passive reads, but a malicious hypervisor could still remap or replay memory pages behind the guest’s back. SEV-SNP closes that gap by adding hardware memory-integrity protection and remote attestation—allowing a tenant (such as a cloud customer) to cryptographically verify that their Linux VM booted unmodified on genuine AMD hardware before releasing secrets to it. On Linux, support requires both host KVM/PSP firmware enablement and an SNP-aware guest kernel (visible via /dev/sev-guest).

What threat does the “SNP” (Secure Nested Paging) part of SEV-SNP defend against that basic memory encryption alone misses?

Basic encryption hides memory contents from reads, but a hypervisor controls page tables and could still remap, alias, or replay encrypted pages. SNP enforces hardware page-ownership checks so the hypervisor cannot corrupt or remap guest memory unnoticed.

SEV-SNP assigns each guest a hardware Address Space Identifier (ASID) bound to an AES-128-XEX memory-encryption key generated inside the AMD Platform Security Processor (PSP), never readable by host x86 software. Integrity is enforced via the Reverse Map Table (RMP), a host-allocated but CPU-checked structure mapping every physical page to an owning ASID, guest physical address (GPA), and immutable/validated state; unauthorized hypervisor writes or GPA remapping trigger an RMP #PF fault. Guest boot measurements (LAUNCH_FINISH) are signed by the PSP’s Versioned Chip Endorsement Key (VCEK) into an attestation report, while guest–host communication is restricted to explicit shared pages (C-bit = 0) and GHCB/VMGEXIT protocols.

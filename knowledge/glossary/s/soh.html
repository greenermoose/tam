SOH (Start of Heading, 0x01)

An ASCII control character (hex 0x01, commonly typed as Ctrl+A) originally designed to mark the start of a message header in telecommunications.

Before modern screens existed, teletypes sent streams of plain bytes over wires. Byte 0x01 (SOH) acted like a “header starts here” tag so the receiving machine knew routing info was coming before the actual message text. On modern computers, pressing Ctrl+A still sends that exact 0x01 byte—which is why terminal programs often use Ctrl+A as a shortcut.

Part of the C0 control codes (0x00–0x1F), SOH is generated by terminals when you hold Ctrl with A (0x41 minus 0x40 = 0x01). In Linux shells using GNU Readline (like Bash), Ctrl+A jumps the cursor to the beginning of the line, while terminal multiplexers like GNU Screen use Ctrl+A as their command prefix—creating a classic shortcut conflict when running Bash inside Screen.

Why does pressing Ctrl+A inside GNU Screen not immediately jump to the start of your Bash prompt?

Both Screen and Bash’s Readline bind byte 0x01 (SOH). Screen intercepts Ctrl+A first as its command prefix; you have to press Ctrl+A followed by a to forward a literal 0x01 byte to Readline.

Defined in ASCII/ISO 646 as 0x01 (binary 00000001), SOH originally framed the routing or sequence header preceding STX (0x02, Start of Text) in synchronous and asynchronous link protocols such as BISYNC and XMODEM (whose 128-byte packet begins with 0x01, block number, and one’s-complement block number). In POSIX termios canonical or raw modes, 0x01 passes through unmodified unless IEXTEN or Readline keymaps (\C-a: beginning-of-line) intercept it; in JSON or XML, unescaped 0x01 is invalid control data.

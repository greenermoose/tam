Guide / Glossary A–Z / Terms beginning with S / SUB (Substitute, 0x1A)

SUB (Substitute) is the ASCII control character with byte value 0x1A, commonly generated by pressing Ctrl+Z.

When you press Ctrl+Z in a Linux terminal to pause a running program and get your prompt back, your keyboard is sending the single control byte 0x1A, historically called Substitute. Long ago it stood in for garbled characters on noisy lines; on Linux today, it acts like a “pause button” that lets you suspend a foreground task and resume it later.

SUB is part of the C0 control codes, mapping 'Z' (0x5A) with Ctrl to 0x1A. When a terminal is in normal line-discipline mode, typing Ctrl+Z tells the kernel to pause the foreground job with SIGTSTP so you can run other commands or bring it back with fg or bg. Historically, DOS and CP/M also used 0x1A as an end-of-file marker in text files, which is why old Windows text files sometimes show a stray ^Z.

Why does pressing Ctrl+Z inside a full-screen editor like Vim sometimes fail to suspend it, or behave differently?

Full-screen programs put the terminal into raw mode (disabling ISIG), so the kernel does not automatically turn 0x1A into SIGTSTP. Instead, the program reads the byte itself and decides whether to handle it as a command or manually suspend.

ASCII 0x1A (SUB, ^Z) is defined in ECMA-48 as a replacement character for invalid/erroneous data and also acts as an immediate abort for in-progress ESC or CSI control sequences in VT-compatible terminal emulators (returning the parser to ground state without executing the partial sequence). On POSIX systems, 0x1A is the default c_cc[VSUSP] byte in struct termios: when ISIG is set in c_lflag, the tty line discipline intercepts 0x1A and delivers SIGTSTP to the foreground process group (tcgetpgrp()) instead of queuing the byte for read(). Programs in raw mode (cfmakeraw()) clear ISIG, receiving literal 0x1A unless they handle keybindings or raise SIGTSTP themselves.

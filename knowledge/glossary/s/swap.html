Swap

Swap is disk or compressed-memory space that the operating system uses as overflow backing storage when physical RAM is under pressure or when inactive memory pages can be moved aside.

Think of RAM as your workbench and disk storage as a filing cabinet. Everything you are actively working on stays on the workbench because it is fast to reach. When the workbench gets crowded, swap lets the computer tuck away tools and papers you have not touched in a while into the filing cabinet so active work still has room—though fetching them back takes noticeably longer.

In Linux, swap can live in a dedicated partition, a swap file, or an in-RAM compressed block device (zram). You can inspect active swap areas with swapon --show or free -h. Swap does not only prevent sudden out-of-memory crashes; it also lets the kernel push cold anonymous pages (like idle background app memory) out of RAM so more RAM can serve as a fast page cache for files. However, heavy “thrashing”—constantly moving active pages between RAM and a slow disk—makes the system feel frozen.

Why might a Linux system with plenty of free RAM still show a small amount of swap used?

The kernel’s memory reclaim balances anonymous pages against the file page cache. If a background process allocates memory and never touches it again, swapping those cold pages out frees RAM for frequently read files, improving overall disk responsiveness.

Swap provides backing store specifically for anonymous pages (heap, stack, MAP_ANONYMOUS mappings, tmpfs pages) that lack a filesystem file backing them, whereas clean file-backed pages can simply be dropped and faulted back from their inode. The kernel manages swap slots via swap_info_struct extents, tracking per-slot reference counts in swap_map and encoding swapped-out PTEs with swap type and offset; reclaim aggressiveness is tuned via vm.swappiness (or cgroup v2 memory.swap.max and memory.high), while zswap intercepts swap-out I/O in a compressed RAM pool before hitting disk. Edge cases include hibernation (suspend-to-disk), which requires swap space sized for the active memory image, and copy-on-write filesystems like Btrfs where swap files require nocow and no snapshots on the subvolume to keep physical block offsets stable.

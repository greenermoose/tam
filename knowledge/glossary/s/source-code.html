Source code

The human-readable text written by programmers to define how a software program works.

Think of source code like a written recipe in English, while the finished program is the baked cake—or the kitchen instructions translated into fast machine steps. Humans can read, edit, and fix source code, whereas the computer’s processor only understands raw binary numbers.

Source code is stored in plain text files (such as .c, .py, or .sh) and follows the syntax of a programming language. Depending on the language, it is either compiled ahead of time into native machine code (gcc, rustc), compiled to bytecode for a virtual machine (Java, WebAssembly), or executed by an interpreter (python3, bash). In Linux distributions, source packages allow users and maintainers to inspect behavior, apply security patches, and rebuild binaries for different CPU architectures.

Why can’t you usually run a C source file directly the way you run a Python script?

Python uses an interpreter that reads .py source code (or cached bytecode) at runtime, whereas C has no standard runtime interpreter and must first be compiled and linked into native machine-code instructions for your CPU and OS.

Source code represents the canonical, architecture-independent (or conditionally #ifdef-guarded) AST and semantic specification of a program before lowering through a compiler’s front-end, IR optimization passes, and back-end code generation. Its fidelity for reproducible builds and debugging depends on deterministic toolchains, DWARF debuginfo (-g) mapping machine addresses back to source lines, and license compliance (such as GPL “corresponding source” obligations including build scripts).

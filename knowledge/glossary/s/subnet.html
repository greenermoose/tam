Subnet

A subnet is a smaller, logically grouped range of IP addresses carved out of a larger network.

Think of a large office building with thousands of rooms. Instead of putting every room on one giant hallway, you divide the building into floors and wings so mail and visitors only go where they belong. A subnet does the same thing for IP addresses: it groups nearby devices—like everything on your home Wi-Fi—into one neighborhood so they can talk directly to each other without bothering the rest of the internet.

Subnets are written using an IP address and a prefix length, such as 192.168.1.0/24 (meaning the first 24 bits identify the network and the remaining 8 bits identify hosts). Your computer compares a destination IP against its own subnet mask: if the network prefix matches, it sends packets directly on the local link; if not, it hands the packet to the default gateway (router).

In IPv4, why does a /24 subnet (256 addresses) only give you 254 usable host addresses?

The very first address in the range (all host bits 0, e.g. 192.168.1.0) is reserved as the network identifier, and the very last address (all host bits 1, e.g. 192.168.1.255) is reserved as the broadcast address.

Under CIDR (RFC 4632), a subnet is defined by an address prefix and bitmask length /n, replacing legacy classful boundaries. Forwarding tables perform longest-prefix match (LPM) across overlapping routes; on-link determination in Linux (ip route) creates a connected route with scope link, triggering ARP (IPv4) or NDP (IPv6, RFC 4861) rather than next-hop gateway resolution. Edge cases include /31 point-to-point IPv4 links (RFC 3021, where both addresses are usable without a broadcast address), /32 (or IPv6 /128) host routes, and IPv6’s standard /64 LAN prefix required for SLAAC. Overlapping subnets across interfaces or VPN tunnels frequently cause asymmetric routing or blackholed traffic unless resolved via policy routing (ip rule).

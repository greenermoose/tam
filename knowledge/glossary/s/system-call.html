System call

A system call (or syscall) is the controlled doorway an ordinary program uses to ask the operating system kernel to perform privileged work on its behalf.

Applications run in a restricted sandbox called user space so a buggy or untrusted program cannot directly overwrite your disk, read another app’s memory, or hijack the network card. Whenever a program needs to open a file, draw to the screen, or connect to the internet, it has to hand a polite request through a guarded gate to the kernel, which checks permissions and does the real work safely.

In Linux, programs rarely invoke raw system calls by hand; instead, standard C library (glibc or musl) functions like fopen() or malloc() wrap lower-level syscalls such as openat, read, write, mmap, and brk. You can watch a program’s syscalls in real time with strace—for example, strace -e trace=file ls shows every path ls asks the kernel to open or inspect, making strace invaluable when debugging missing libraries or permission errors (EACCES, ENOENT).

Why does calling printf() ten times in a loop often produce only one write system call in strace?

Crossing into the kernel for every small print is expensive, so the C library buffers output in user-space memory and flushes it with a single write syscall when the buffer fills or sees a newline.

On x86-64 Linux, user space enters kernel mode via the syscall instruction (passing the syscall number in rax and up to six arguments in rdi, rsi, rdx, r10, r8, r9, returning the result or -errno in rax), transitioning from ring 3 to ring 0 at MSR_LSTAR (entry_SYSCALL_64) without an IDT software interrupt; legacy 32-bit int 0x80 and sysenter remain for compat ABIs. A few read-only high-frequency calls (clock_gettime, gettimeofday, getcpu) are mapped into user space via the vDSO so they execute without a privilege-level switch. Because speculative-execution mitigations (KPTI, retbleed, SRSO) add entry/exit overhead to ring transitions, high-throughput workloads increasingly batch syscalls through shared ring buffers like io_uring or filter them with seccomp-bpf at syscall entry.

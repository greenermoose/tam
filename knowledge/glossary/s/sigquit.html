SIGQUIT (Quit signal)

SIGQUIT (signal 3) is a terminal signal sent by Ctrl+\ that asks a process to stop and, by default, save a core dump for debugging.

If Ctrl+C (SIGINT) is a polite tap to stop, Ctrl+\ (SIGQUIT) is hitting the emergency stop button that also takes a snapshot of what the program was doing. Developers use it when a program is misbehaving and they want a record of its state to investigate later.

Part of Unix signals, SIGQUIT (3) is triggered by Ctrl+\ when a program ignores Ctrl+C or when you want a crash dump. Unlike SIGKILL, SIGQUIT can be caught—for example, the JVM catches SIGQUIT to print a full thread dump to standard output without exiting.

When you press Ctrl+\ on a hung program, why might no core file appear in your current directory?

Modern Linux distributions often set RLIMIT_CORE to 0 by default or pipe core dumps to systemd-coredump (inspectable with coredumpctl) rather than writing a core file in the working directory.

POSIX signal 3 (SIGQUIT), generated by the N_TTY line discipline when the VQUIT character (default 0x1C, Ctrl+\) is received with ISIG set. Its default disposition is Core (terminate and produce a core dump), subject to RLIMIT_CORE, /proc/sys/kernel/core_pattern (commonly piped to systemd-coredump), PR_SET_DUMPABLE, and setuid restrictions. Because it is catchable, runtimes and servers sometimes repurpose SIGQUIT for diagnostics (thread dumps in Java, stack traces in Go when not ignored).

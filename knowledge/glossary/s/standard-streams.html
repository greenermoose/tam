Guide / Glossary A–Z / Terms beginning with S / Standard streams

The three default input and output channels (stdin, stdout, and stderr) automatically given to a program when it starts.

Think of a command-line program like a small workshop with three pipes attached: one pipe brings raw materials in (standard input), one sends finished work out (standard output), and a separate pipe sends warning notes (standard error). Because warnings have their own pipe, you can save the finished output to a file while still seeing error messages on your screen.

In Linux shells, stdin is file descriptor 0, stdout is 1, and stderr is 2. By default all three connect to your terminal, but redirection and pipes rewire them independently—for example, grep foo log.txt > matches.txt 2> errors.log sends normal output to one file and errors to another, while cmd1 | cmd2 connects cmd1’s stdout (1) to cmd2’s stdin (0), leaving stderr on the terminal.

Why doesn’t ls /nonexistent | wc -l count the error message as a line?

A pipe (|) connects the left command’s standard output (1) to the right command’s standard input (0). Error messages go to standard error (2), so they appear on the terminal instead of entering the pipe.

POSIX specifies STDIN_FILENO (0), STDOUT_FILENO (1), and STDERR_FILENO (2) as conventional open file descriptors inherited across fork() and execve() (unless marked FD_CLOEXEC). Shells implement redirections via open(), pipe(), and dup2() in the child before execve(). Crucially, C stdio buffering differs by stream and target: stdout is line-buffered when isatty(1) is true and block-buffered when redirected to a file or pipe, whereas stderr is unbuffered by default so diagnostics appear immediately even on crashes.

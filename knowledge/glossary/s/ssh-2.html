Guide / Glossary A–Z / Terms beginning with S / SSH-2 (Secure Shell version 2)

The modern, standardized version of the Secure Shell protocol (RFC 4251–4254) used for encrypted remote logins, command execution, and file transfers.

Just like web browsers moved from old, insecure ways of connecting to modern HTTPS, remote terminal access moved from an older version (SSH-1) to SSH-2. Today, whenever you use ssh to log in to a server or push code, you are using SSH-2 under the hood.

SSH-2 cleanly splits the protocol into three layers: transport (key exchange, server authentication, encryption), user authentication (public keys, passwords, keyboard-interactive), and connection (multiplexed channels for shells, SFTP, and port forwarding). OpenSSH dropped SSH-1 support years ago, so modern ssh clients and sshd servers speak SSH-2 exclusively.

What is the practical benefit of SSH-2 multiplexing channels inside one connection?

After a single key exchange and login, one TCP connection can carry an interactive shell, SFTP transfers, and forwarded ports simultaneously without re-authenticating or opening separate connections.

Specified in RFC 4251–4254, SSH-2 replaced SSH-1 after the 2001 CRC-32 compensation-attack detector vulnerability (which allowed chosen-ciphertext insertion) and SSH-1’s lack of integrity protection and key re-exchange. SSH-2 separates the Binary Packet Protocol (SSH-TRANS, RFC 4253) with explicit MACs or AEAD ciphers (such as chacha20-poly1305@openssh.com and aes256-gcm@openssh.com), SSH-USERAUTH (RFC 4252), and SSH-CONNECT (RFC 4254) with per-channel flow-control windows (SSH_MSG_CHANNEL_WINDOW_ADJUST). It also supports periodic key re-exchange (SSH_MSG_KEXINIT) over long-lived sessions.

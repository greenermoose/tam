Sanitizer

A compiler instrumentation tool that inserts runtime checks into a program to detect memory errors, data races, and undefined behavior while it runs.

A sanitizer is like an automatic safety inspector built right into a program while it is being created. Instead of waiting for a hidden bug to cause a mysterious crash later, the inspector watches every step as the program runs and immediately points out the exact line where something went wrong, such as reading past the end of a list.

When compiling C or C++ with GCC or Clang, you enable sanitizers with flags like -fsanitize=address (AddressSanitizer for out-of-bounds or use-after-free bugs), -fsanitize=undefined (UBSan for signed integer overflow or null dereferences), or -fsanitize=thread (TSan for data races). Unlike Valgrind, which interprets machine code and slows programs down 10–30×, sanitizers compile checks directly into the binary so they typically run with only ~2× overhead, making them practical for automated test suites. Note that ASan and TSan cannot be combined in the same build.

Why do developers still test with AddressSanitizer even when their program compiles cleanly with -Wall -Wextra?

Compiler warnings only catch issues visible statically at compile time, whereas many memory errors—like a buffer overflow triggered by specific runtime input or a use-after-free across function calls—only manifest dynamically during execution.

Compiler sanitizers pair compile-time IR instrumentation (e.g., LLVM passes) with a linked runtime library (libasan, libtsan, libubsan). AddressSanitizer reserves virtual shadow memory (mapping 8 bytes of application memory to 1 shadow byte via a fixed offset) and surrounds stack, global, and heap allocations with poisoned redzones; every memory access checks the shadow byte before dereferencing, trapping on non-zero values. ThreadSanitizer maintains vector-clock state in shadow memory per 8-byte word to detect unsynchronized happens-before violations. Trade-offs include large virtual address space reservations (several terabytes on 64-bit Linux, breaking strict RLIMIT_AS caps), incompatibility with static linking in some configurations, and mutual exclusion between ASan, TSan, and MSan.

Guide / Glossary A–Z / Terms beginning with S / Server-side rendering (SSR)

Server-side rendering, or SSR, means a server builds the page's markup before the browser receives it.

The server prepares a finished page and sends it, rather than sending an empty frame and asking the browser to build everything. Words can appear sooner.

After the markup arrives, browser script attaches behaviour to the existing elements. That attachment step is called hydration, and it must match the markup the server sent.

Why can SSR show words earlier than a pure SPA?

The browser receives markup it can display immediately. A pure SPA first downloads and runs script, then builds the markup; both can end at the same view, but the first visible content arrives later.

SSR can stream markup as data becomes ready and cache whole responses. A hydration mismatch occurs when client and server compute different markup from the same URL. Server code must avoid browser-only globals, and serialized data must be escaped to avoid XSS.

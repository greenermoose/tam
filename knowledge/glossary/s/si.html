SI (Shift In, 0x0F)

SI (Shift In, byte 0x0F) is an ASCII control character that switches a terminal back to its standard character set.

Have you ever accidentally printed a binary file to a terminal and seen your prompt turn into gibberish box-drawing symbols? Old terminals used a pair of invisible switch codes to flip between normal letters and special line-drawing characters. Shift In (SI) is the “switch back to normal letters” signal that restores readable text.

Part of the C0 control codes, SI (0x0F, also typed as Ctrl+O in raw contexts) pairs with Shift Out (SO, 0x0E). When stray binary data printed to a terminal contains a 0x0E byte, the terminal switches to the alternate G1 graphics set and turns lowercase letters into line-drawing glyphs. Sending a 0x0F byte—for example with printf '\x0f' or running reset—restores normal ASCII text without closing your session.

Why can running cat on a binary file leave your terminal prompt displaying strange symbols even after cat finishes?

If the binary stream contained an accidental 0x0E (Shift Out) byte without a matching 0x0F (Shift In), the terminal remains latched into its alternate line-drawing character set until SI or a terminal reset restores G0.

In ISO/IEC 2022 and DEC VT100/xterm terminal emulation, SI (0x0F, Locking Shift Zero / LS0) invokes the G0 character set into the GL (0x20–0x7F) graphic region, reversing SO (0x0E, LS1) which invokes G1 (commonly configured to the DEC Special Graphics line-drawing set via ESC ) 0). Because GL state persists across commands in the terminal emulator rather than the shell, recovery requires emitting \x0f, sending RIS (ESC c), or running tput sgr0 / reset.

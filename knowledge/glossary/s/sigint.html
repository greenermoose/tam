SIGINT (Interrupt signal)

SIGINT (signal 2) is the interrupt signal sent to a foreground terminal program when you press Ctrl+C.

Think of SIGINT as tapping someone on the shoulder to say “please stop what you’re doing.” When a command is taking too long or scrolling endlessly, pressing Ctrl+C asks it to stop cleanly without pulling the plug on your whole computer.

Part of Unix signals, SIGINT (2) is catchable, so programs like text editors, compilers, or database shells can catch it to clean up temporary files, flush buffers, or prompt “really quit?” instead of exiting immediately. Unlike SIGTERM (sent by kill), SIGINT is tied to interactive terminal input; unlike SIGKILL, a stuck or custom-handling program can ignore it.

Why does pressing Ctrl+C in a Python script print a Traceback instead of killing the process silently?

Because Python installs a SIGINT handler that raises KeyboardInterrupt, allowing try/finally cleanup blocks to run before exiting rather than terminating abruptly.

POSIX signal 2 (SIGINT), generated by the kernel’s N_TTY line discipline and delivered to the terminal’s foreground process group (tcgetpgrp) when the VINTR byte (default 0x03, Ctrl+C) arrives and ISIG is enabled in termios c_lflag. Programs that put the terminal into raw mode (clearing ISIG) receive literal 0x03 bytes instead. Interactive shells typically ignore SIGINT while waiting on foreground jobs, and non-interactive background jobs launched with & in POSIX shells have SIGINT/SIGQUIT set to SIG_IGN by default; wait-and-cooperative-exit shells distinguish a child that died from SIGINT versus one that caught it and exited normally.

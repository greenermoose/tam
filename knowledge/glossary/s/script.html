Script

A program written as plain text that is read and executed by an interpreter rather than compiled into machine code beforehand.

A script is a simple list of instructions saved in a text file—like a recipe—that another program reads and follows step by step. People use scripts to automate repetitive chores, such as renaming hundreds of photos or backing up a folder with a single command.

On Linux, shell scripts (for Bash or sh) and Python scripts are everyday automation tools. To run a script directly by name like ./backup.sh, two things are needed: execute permission (chmod +x backup.sh) and a shebang line at the very top (such as #!/bin/sh or #!/usr/bin/env python3) telling the system which interpreter should run it. Contrast this with compiled C programs, which become standalone binary files.

What happens if you mark a script executable with chmod +x, but forget the #! shebang line at the top?

When the kernel’s execve call sees no #! magic bytes, it returns ENOEXEC; a shell may fall back to running the file as a shell script, which fails if the file is actually written in Python or another language.

In Linux, executing a script relies on the kernel’s binfmt_script handler inside execve(2): if the file begins with the two-byte magic #!, the kernel parses the interpreter path and at most one optional argument (truncated at BINPRM_BUF_SIZE, 256 bytes on modern kernels), then re-invokes execve with the interpreter as argv[0], the optional argument if present, and the script path. Common pitfalls include CRLF line endings (causing /bin/sh^M: bad interpreter), using #!/usr/bin/env when PATH is restricted in systemd units, and ignoring quoting/word-splitting in POSIX shell scripts.

SSH (Secure Shell)

An encrypted network protocol and command-line tool for logging into remote machines, running commands, transferring files, and forwarding network ports securely.

When you want to control another computer over the internet or a local network, sending your password and commands in plain text would let anyone on the same network read them. SSH wraps the entire conversation in a locked tunnel so only you and the remote computer can see what is typed or sent back.

Connecting with ssh alex@server opens a remote shell over TCP port 22, while scp and sftp reuse the same protocol to copy files and ssh -L forwards local ports through the encrypted tunnel. The first time you connect to a host, ssh asks you to confirm its host key fingerprint and saves it in ~/.ssh/known_hosts to detect impersonation on future connections.

Why does ssh warn you loudly if a remote server’s host key suddenly changes?

A changed host key means the server’s cryptographic identity no longer matches what is recorded in ~/.ssh/known_hosts—either the server was reinstalled, or an attacker is intercepting the connection (man-in-the-middle).

OpenSSH implements SSH-2 (RFC 4251–4254), negotiating post-quantum hybrid or elliptic-curve key exchange (such as sntrup761x25519-sha512 or curve25519-sha256), authenticating the server via host keys or OpenSSH host certificates, and deriving symmetric keys for AEAD transport encryption. Over a single authenticated transport, ssh multiplexes independent channels (ControlMaster/ControlPath), supports ProxyJump (-J) without exposing private keys to bastion hosts, and limits ssh-agent forwarding (-A) exposure risks when untrusted root users exist on intermediate hosts.

SQL injection

SQL injection is a security flaw in which input is treated as part of a database query instead of as a value.

If a form answer is pasted straight into a question for the database, a clever answer can change the question. The database then answers something the programmer never intended.

Use parameterized queries: send the SQL text and the values separately. Validate input for business rules, but do not rely on validation alone for safety.

Why does escaping quotation marks alone often fail?

Different databases and contexts use different quote and escape rules, and some injections need no quotes at all. Passing values as parameters keeps them separate from query syntax by construction.

Payloads can use UNION queries, boolean conditions or timing differences to infer data when results are not returned directly. Object-relational mappers reduce raw SQL but can still be misused with interpolated fragments. Least-privilege database accounts limit the damage.

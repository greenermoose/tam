Stack trace

A stack trace is the list of function calls that were active when an error occurred.

When a program stops with an error, it leaves a trail of where it had been. That trail is the stack trace, like breadcrumbs back to the place that started the trouble.

Read the first frame as the place the error was raised, then follow the calls below it to find who asked for that work. A source map turns generated file positions back into your original code.

Why can the top frame of a stack trace be library code rather than your own?

The error may be raised while a library checks a value your code passed. Read down the trace to the first frame in your application and inspect the arguments at that boundary.

Asynchronous traces may be split across tasks unless the runtime supports async stack tagging. Minified bundles produce short, unhelpful names; symbolication restores them. The deepest frame is not always the bug: inspect the arguments and boundary that caused it.

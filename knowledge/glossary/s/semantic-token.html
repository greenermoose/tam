Semantic token

A semantic token is a named design variable—such as surface, text-muted, or accent—that describes a role in a user interface rather than a fixed color or size.

Instead of painting every button “bright blue” directly, designers give that color a job title like “primary action.” That job title is a semantic token. When you switch from a light theme to a dark theme, you do not have to repaint every button one by one—you just update what “primary action” or “background” points to, and the entire app updates cleanly and stays readable.

Design systems usually layer semantic tokens on top of raw palette tokens (for example, color.danger aliasing red.600 in light mode and red.400 in dark mode). In CSS, GTK, or desktop themes, using semantic tokens prevents mismatched contrast when themes change, whereas hard-coding raw hex values like #ffffff breaks dark mode or high-contrast accessibility themes. Notice that two elements can share the same raw color today while using different semantic tokens (such as border.subtle vs. surface.disabled) so they can diverge later without editing components.

Why is referencing color.surface.elevated better than referencing gray.800 directly in a UI component?

gray.800 encodes a fixed appearance, which breaks if the user switches to a light or high-contrast theme. A semantic token like color.surface.elevated encodes intent, allowing each theme to map it to an appropriate accessible value.

In structured design-token architectures (such as the W3C Design Tokens Format), semantic tokens sit in a multi-tier alias graph: primitive/reference tokens hold literal values (hex, OKLCH, rem), semantic/system tokens alias primitives by functional role and state (surface.interactive.hover, on.accent), and component tokens optionally bind specific widgets to semantic roles. Resolving the graph at build time or runtime via CSS custom properties or toolkit style engines enforces WCAG contrast invariants across light, dark, and forced-colors modes. A key failure mode is semantic-token leakage—aliasing a role like text.link to unrelated elements simply because they happen to share the same hue—which destroys theme invariance when a brand or accessibility palette is updated.

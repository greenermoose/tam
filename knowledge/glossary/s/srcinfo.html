.SRCINFO

A plain-text metadata file generated from a PKGBUILD so Arch Linux package tools and the AUR can read package details without executing shell scripts.

Before installing community software, a package manager needs to know its name, version, and what other programs it requires. Instead of running an untrusted setup script just to ask those questions, .SRCINFO acts like a printed nutrition label on the outside of the box that any tool can read safely.

A PKGBUILD is a Bash script, so parsing it directly with regexes is unreliable and executing it before inspection is a security risk. Running makepkg --printsrcinfo > .SRCINFO evaluates the PKGBUILD once and writes flat key = value lines (covering pkgbase, pkgname, pkgver, depends, and architecture-specific overrides), which AUR helpers and the AUR web interface read without running code.

What happens if you edit pkgver in a PKGBUILD and push to the AUR without regenerating .SRCINFO?

The AUR web interface and AUR helpers still see the old version from .SRCINFO, or the AUR git hook rejects the push, because the repository relies on .SRCINFO rather than executing the PKGBUILD on the server.

.SRCINFO is an INI-like static projection of a PKGBUILD’s metadata, scoped by pkgbase and one or more pkgname sections for split packages. Multi-valued fields repeat the key (depends = ...) rather than using array syntax, and architecture-qualified attributes use suffixes such as depends_x86_64. Because makepkg --printsrcinfo runs in a subshell to expand variables and functions, dynamic pkgver() updates or conditional dependencies evaluated at build time are frozen at generation time, which is why AUR server-side pre-receive hooks enforce .SRCINFO presence and consistency.

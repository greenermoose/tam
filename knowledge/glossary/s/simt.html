SIMT (Single Instruction, Multiple Threads)

SIMT (Single Instruction, Multiple Threads) is the GPU execution model that runs groups of independent scalar threads together in lockstep.

Think of SIMT like a marching band where every musician plays from the same sheet music at the same beat, even though each person holds their own instrument and tracks their own spot. GPUs use this trick to run thousands of pixel or math calculations at once without needing thousands of separate control units.

While CPU SIMD packs multiple values into one vector instruction written by the programmer, SIMT lets you write code as if for a single thread, and the GPU hardware groups threads into warps (NVIDIA, 32 threads) or wavefronts (AMD, 32 or 64 threads). If threads in the same group take different if/else branches—called branch divergence—both paths execute sequentially with inactive threads masked off, cutting throughput.

What happens to GPU performance when half the threads in a warp take the if branch and the other half take the else branch?

The warp executes both branches one after the other while masking off the non-participating threads in each pass, roughly halving execution efficiency for that divergent region.

GPU execution model mapping scalar thread abstractions onto wide vector ALUs (NVIDIA warps of 32 threads; AMD RDNA/GCN wavefronts of 32/64). Each thread maintains its own register slice and logical program counter, while the warp scheduler issues one instruction per cycle across active lanes via an execution mask (predication) and a reconvergence stack. Pre-Volta NVIDIA architectures enforced lockstep reconvergence per warp, whereas Volta+ introduced Independent Thread Scheduling with per-thread PCs to allow finer-grained synchronization, still requiring explicit __syncwarp() for warp-level primitives.

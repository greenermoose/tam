SIMD (Single Instruction, Multiple Data)

SIMD (Single Instruction, Multiple Data) is a CPU execution technique that applies one instruction to several data elements packed into a wide register at the same time.

Instead of adding two numbers at a time like a single cashier scanning one item, SIMD is like a wide stamp that marks eight boxes in a single press. Modern processors use this to speed up repetitive math in video, audio, images, and encryption.

On x86_64, SIMD extensions evolved from SSE (128-bit) to AVX/AVX2 (256-bit) and AVX-512 (512-bit), while ARM uses NEON and SVE. Compilers can auto-vectorize simple loops, or programmers can use intrinsics and libraries when data has no loop-carried dependencies. Notice that widening SIMD only helps when data is contiguous and aligned enough to keep lanes full.

Why can’t a compiler automatically use SIMD to speed up every for loop?

If each iteration depends on the previous iteration’s result (a loop-carried dependency) or scatters reads and writes unpredictably in memory, the operations cannot safely run simultaneously in one vector instruction.

Flynn’s taxonomy data-parallel model executing one decoded instruction stream across fixed-width vector registers (128-bit XMM, 256-bit YMM, 512-bit ZMM on x86_64; scalable 128–2048-bit vectors on ARM SVE). Trade-offs include horizontal reduction overhead, lane-masking penalties for conditional branches, unaligned-load splits across cache lines, and frequency throttling on some Intel cores during heavy 512-bit execution. Unlike SIMT, SIMD exposes the vector width directly in the ISA (except in vector-length-agnostic ISAs like SVE and RISC-V RVV).

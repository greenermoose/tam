SIGSTOP (Stop signal)

SIGSTOP (signal 19 on x86_64 Linux) is an uncatchable signal that pauses a running process in place until SIGCONT resumes it.

SIGSTOP works like a universal pause button controlled by the operating system. It freezes a program exactly where it is—keeping its memory and open files intact—without the program being able to refuse, and you can unfreeze it later with SIGCONT.

Part of Unix signals, SIGSTOP cannot be caught, blocked, or ignored, which distinguishes it from SIGTSTP (Ctrl+Z). Programs like text editors catch SIGTSTP to restore your terminal screen before pausing, whereas kill -STOP freezes the process immediately without letting it clean up the terminal.

Why is kill -STOP risky to use on a full-screen terminal app like an editor, compared to pressing Ctrl+Z?

Because SIGSTOP cannot be caught, the editor cannot switch the terminal back out of raw or alternate-screen mode before freezing, leaving your shell prompt garbled until you resume it with kill -CONT.

POSIX stop signal (number 19 on x86_64/ARM64 Linux; architecture-dependent—for instance 17 on Alpha/SPARC and 23 on MIPS). The kernel moves all threads in the thread group into TASK_STOPPED without invoking any userspace handler, notifying the parent via SIGCHLD / waitpid(..., WUNTRACED). Execution resumes only upon delivery of SIGCONT, which clears pending stop signals (SIGSTOP, SIGTSTP, SIGTTIN, SIGTTOU). Debuggers (via ptrace) rely on a related mechanism (__TASK_TRACED) to inspect stopped threads.

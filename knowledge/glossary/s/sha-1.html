SHA-1

SHA-1 (Secure Hash Algorithm 1) is an older 160-bit cryptographic hash function that produces a 40-character hexadecimal fingerprint, now deprecated for security use because collision attacks against it are practical.

A hash function works like a digital blender that turns any file—whether a one-word note or a huge movie—into a fixed-length 40-character fingerprint. For years, SHA-1 was the standard way to verify that a downloaded file had not been altered. Researchers eventually figured out how to craft two different files that produce the exact same SHA-1 fingerprint, so modern security systems have moved on to stronger algorithms like SHA-256.

Part of the SHA algorithms family, SHA-1 is rejected by modern web browsers, TLS certificates, and OpenSSH (ssh-rsa using SHA-1 is disabled by default in modern OpenSSH). However, you still see SHA-1 in non-adversarial contexts—most notably as Git’s traditional 40-hex-digit object IDs—and in legacy sha1sum checksums. Note the distinction: a broken hash is unsafe for digital signatures and untrusted-input integrity, even if it still works for detecting accidental bit flips or identifying internal objects.

Why is SHA-1 unsafe for TLS certificates and code signing even though Git has long used 40-character SHA-1 hashes?

TLS and code signing must resist an attacker deliberately crafting two different inputs with the same hash (a collision attack), which is practical against SHA-1. Git historically used SHA-1 mainly for content addressing and accidental-corruption checks, and is migrating toward SHA-256 for cryptographic integrity.

Specified in FIPS 180-4, SHA-1 uses a Merkle–Damgård construction with a 512-bit message block, 80 rounds of compression, and a 160-bit internal state—giving an ideal birthday-bound collision resistance of 280 operations. Differential cryptanalysis reduced this far below 280: the 2017 SHAttered attack produced an identical-prefix PDF collision in ~263.1 SHA-1 evaluations, and chosen-prefix collisions were demonstrated in 2020 at ~263.4 complexity, enabling forged PGP/X.509 signatures. While second-preimage resistance remains near 2160 and HMAC-SHA1 is not directly broken by collision attacks (depending only on compression-function PRF assumptions), NIST disallowed SHA-1 for digital signatures after 2013 and scheduled complete deprecation by 2030.

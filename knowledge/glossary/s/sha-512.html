Guide / Glossary A–Z / Terms beginning with S / SHA-512

SHA-512 is a cryptographic hash function in the SHA-2 family that produces a 512-bit digital fingerprint for any input.

Like SHA-256, SHA-512 turns any file or message into a fixed-size fingerprint. The result is 128 hexadecimal characters long. If the input changes by even one bit, the SHA-512 value changes completely. People use it to check downloads, verify data integrity, and identify content reliably.

SHA-512 is part of the SHA algorithms family. On Linux, sha512sum computes it. It gives a larger digest than SHA-256, which can be useful when a protocol or standard calls for 256-bit collision resistance with a wider margin or when 64-bit platforms benefit from its 64-bit word design. It is still a fast one-way hash, so it is not a password-hashing function by itself; use a slow password hash such as Argon2id for passwords.

Is SHA-512 "more secure" than SHA-256 for every use?

It has a larger digest and higher theoretical security margins, but SHA-256 is already secure for most uses. The right choice depends on protocol requirements, performance, and interoperability, not just digest size.

Defined in FIPS 180-4, SHA-512 processes 1024-bit blocks with 80 rounds over eight 64-bit state words, producing a 512-bit digest. It targets 256-bit collision resistance and 512-bit preimage/second-preimage resistance. SHA-384 is the same compression function with different initial values and a truncated output. Like other Merkle-Damgård hashes, raw SHA512(k || m) is vulnerable to length extension; use HMAC-SHA-512 or a SHA-3/Keyed-SHAKE construction when message authentication is needed. On 64-bit CPUs, SHA-512 can be competitive with or faster than SHA-256 despite the larger digest.

SGR (Select Graphic Rendition)

SGR (Select Graphic Rendition) is the terminal escape sequence standard used to change text colors, weight, underlines, and other visual attributes.

When a terminal command prints green “OK” text, bold headings, or red error messages, it is not sending graphics—it is sending invisible text codes right before the words. SGR is the code system that tells the terminal, “switch to red bold text now,” and then, “go back to normal text,” so the rest of your screen does not stay red.

An SGR sequence begins with the Control Sequence Introducer (ESC [, written in shell scripts as \e[ or \033[), followed by semicolon-separated numeric parameters and ending with m—for example, \e[1;31m for bold red and \e[0m to reset all attributes. Well-behaved CLI tools check whether standard output is a TTY (isatty()) or honor NO_COLOR before emitting SGR codes so piped output to files or grep is not polluted with raw escape bytes; less -R specifically passes SGR sequences through while stripping unsafe control codes.

Why do programs often check if stdout is a terminal before printing SGR color codes?

SGR codes are inline byte sequences, not out-of-band metadata. If printed into a pipe or log file, downstream tools like grep, awk, or plain text editors see literal escape characters that can break parsing or clutter logs.

Defined in ECMA-48 §8.3.117 as CSI Ps ... m (final byte 0x6D), SGR mutates the terminal emulator’s active character-cell attribute state. Parameters cover basic 8/16 colors (30–37, 40–47, bright 90–97, 100–107), typographic modes (1 bold, 3 italic, 4 underline—with extended Kitty/mintty subparameters like 4:3 for curly underlines), and extended colors via 38;5;n / 48;5;n (256-color indexed) or 38;2;r;g;b (24-bit truecolor, with colon-delimited ISO-8613-6 38:2::r:g:b variants). Terminfo abstracts reset via sgr0, while a classic parsing pitfall is that semicolon-separated extended colors (38;2;r;g;b) are stateful across parameters, whereas colon subparameters isolate them cleanly.

Guide / Glossary A–Z / Terms beginning with S / Single-page application (SPA)

A single-page application, or SPA, loads one HTML page and then changes what the reader sees with JavaScript.

Instead of opening a new page for every click, a SPA swaps the view inside the same window. It can feel faster, much like changing channels without standing up.

A SPA uses client-side routing to choose a view from the URL and fetch data as needed. The browser history API lets Back and Forward work without a full reload.

What server rule does a SPA need for a direct link to a client-side route?

The server must return the application's shell page for unknown paths that are client routes, rather than a 404. The browser script then reads the URL and renders the right view.

SPAs move rendering, state and routing into the browser. They need fallback routes on the server, careful handling of direct links, and a strategy for search engines that do not run script. Large bundles and hydration-like state reconstruction are common performance costs.

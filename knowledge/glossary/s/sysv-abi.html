System V ABI (SVID)

The System V ABI (Application Binary Interface), alongside the older SVID (System V Interface Definition), is the standard that defines how compiled Unix and Linux programs call functions, lay out ELF binaries, and talk to libraries and the kernel.

Even if two programs are written in different languages or compiled by different tools, they still need to share system libraries and run on the same Linux system. The System V ABI is the shared rulebook that everyone agrees to follow—like agreeing which hand holds the fork and which side of the road to drive on—so compiled code from one place can cleanly call functions compiled somewhere else.

Every CPU architecture has a processor-specific supplement (psABI). On x86-64 Linux, the System V AMD64 ABI says the first six integer or pointer arguments go into registers rdi, rsi, rdx, rcx, r8, and r9 (with floating-point values in xmm0–xmm7), and return values come back in rax/rdx—contrasting with Windows x64, which uses rcx, rdx, r8, r9. It also standardizes the ELF executable format, dynamic linking via the GOT/PLT, and stack alignment before a call instruction.

Why can’t you link a Windows x64 .obj file directly into a Linux x86-64 program without an adaptation layer?

Even though both use x86-64 machine instructions, Windows x64 and Linux x86-64 follow different ABIs: they pass function arguments in different registers, preserve different callee-saved registers, and use different object formats (PE/COFF vs. ELF).

The AT&T System V gABI and x86-64 psABI specify ELF64 sections, relocations (R_X86_64_*), thread-local storage models (via %fs:0), DWARF .eh_frame stack unwinding, and strict calling conventions: rbx, rbp, and r12–r15 are callee-saved; rsp must be 16-byte aligned immediately before call, with a 128-byte “red zone” below rsp in user space (disabled with -mno-red-zone in kernel code because interrupts clobber memory below rsp). Note the distinction: SVID originally standardized source and runtime Unix APIs, whereas the System V ABI and its modern psABIs govern binary compatibility.

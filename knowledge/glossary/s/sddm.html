SDDM (Simple Desktop Display Manager)

SDDM (Simple Desktop Display Manager) is a graphical login screen program that starts a desktop session after verifying a user’s credentials.

When you turn on a Linux computer with a desktop, you first see a screen asking for your username and password. SDDM is that front door: it draws the background, user list, and password box, checks your password, and hands you off to your Tamlinux desktop session. Without a display manager like SDDM, you would see a plain text prompt and have to type commands to start the graphical desktop yourself.

SDDM (managed by sddm.service on systemd distributions) runs as a greeter before any user logs in. Unlike older display managers built around X11 alone, SDDM themes are written in Qt and QML and can launch both Wayland compositors (such as Hyprland or KDE Plasma) and X11 window managers using session desktop files in /usr/share/wayland-sessions/ or /usr/share/xsessions/. Once you enter a password, SDDM delegates verification to PAM and asks systemd-logind to register your session and grant access to graphics and input devices.

Why does SDDM still work if your desktop environment is Wayland-only?

SDDM itself only renders the login greeter and spawns the chosen session command. Because it reads Wayland session descriptors and lets systemd-logind set up seat permissions, it can launch a Wayland compositor directly without requiring an X11 session for the user.

SDDM separates a privileged root daemon (sddm) from an unprivileged greeter process (sddm-greeter or sddm-greeter-qt6 running as the sddm user). The daemon orchestrates PAM conversation stacks (/etc/pam.d/sddm), opens the logind session via D-Bus so XDG_RUNTIME_DIR and DRM/evdev device nodes are assigned to the seat, and spawns sddm-helper to drop privileges and execute the target session wrapper. A common failure mode is a broken greeter display server configuration (for example, X11 greeter fallback failing on a Wayland-only GPU driver, or missing Qt Quick/Wayland plugins), which leaves the system on a blank TTY even though sddm.service is active; switching the greeter’s DisplayServer=wayland in sddm.conf or inspecting journalctl -u sddm isolates greeter crashes from PAM or session startup failures.

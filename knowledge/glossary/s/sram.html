SRAM - Static Random-Access Memory

A fast type of computer memory that holds each bit in a small transistor circuit as long as power stays on.

Imagine a row of light switches that stay in whatever position you flip them to until the power goes out. Because the computer does not have to keep reminding each switch what state it is in, it can read and write data almost instantly, which is why processors keep their closest scratchpad memory in SRAM.

Inside a Linux system, SRAM is not what you buy as RAM sticks—those are DRAM, which stores bits in tiny capacitors that leak charge and must be refreshed thousands of times per second. SRAM needs no refresh cycle, so CPUs use it for L1, L2, and L3 caches and registers, trading much higher cost and lower density for nanosecond-scale latency.

Why isn’t main system memory (RAM) built out of SRAM if it is so much faster?

A standard SRAM cell takes six transistors per bit, whereas DRAM uses one transistor and one capacitor. Building gigabytes of main memory out of SRAM would be far larger, hotter, and vastly more expensive than DRAM.

A typical 6T CMOS SRAM cell uses two cross-coupled inverters (four transistors) forming a bistable latch plus two access transistors gated by the wordline onto differential bitlines (BL, /BL). Read stability requires sizing pull-down transistors stronger than access transistors to prevent destructive read upsets, while write-ability requires the opposite ratio. Beyond CPU caches, SRAM appears in microcontroller on-chip memory and FPGA LUTs; its static leakage power scales with cell count, making power-gating and retention-voltage scaling critical in modern SoCs.

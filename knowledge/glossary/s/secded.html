SECDED (Single-Error Correction, Double-Error Detection)

SECDED (Single-Error Correction, Double-Error Detection) is an error-correcting code scheme that automatically repairs any 1-bit memory corruption and reliably detects 2-bit corruption.

Computer memory stores data as billions of tiny electrical charges representing 0s and 1s, and occasionally a stray particle or electrical glitch flips one bit by mistake. SECDED works like a clever checksum written alongside every small chunk of data: if one bit flips, the math pinpoints which bit is wrong and flips it back automatically. If two bits flip at once, it cannot guess which two changed, but it raises an alarm so the computer does not silently use corrupted data.

In server and workstation ECC RAM, SECDED is the standard reason ECC memory modules have extra chips: each 64-bit data word is stored with 8 parity bits (72 bits total per bus width). On Linux, hardware memory controllers report corrected 1-bit events to the kernel’s EDAC (Error Detection and Correction) subsystem and MCE logs, while uncorrectable 2-bit errors trigger a fatal machine check or kernel panic to prevent silent data corruption. Notice that a rising count of corrected 1-bit errors is an early warning that a DIMM is degrading before a 2-bit error occurs.

Why does a 2-bit error in SECDED halt or alert the system instead of being corrected automatically?

SECDED only has enough parity redundancy to uniquely identify the position of a single flipped bit. Two simultaneous flips produce a syndrome that cannot distinguish a unique 2-bit pattern, so the hardware flags an uncorrectable error rather than risking a wrong correction.

SECDED extends a Hamming (71,64) single-error-correcting code (minimum Hamming distance d = 3) with one overall parity bit to form an extended Hamming (72,64) linear block code with minimum distance d = 4. The parity-check matrix H is constructed so every column is nonzero, distinct, and has odd weight (or equivalently, an even-weight overall parity row is added). Computing the 8-bit syndrome s = H · rT yields four distinct outcomes: s = 0 indicates no detected error; nonzero s with odd parity identifies a single-bit error whose column index pinpoints the bit to invert; nonzero s with even parity indicates an even-weight (typically 2-bit) uncorrectable error. Note the critical edge case: 3-bit errors have odd syndrome weight and can alias onto a 1-bit syndrome, causing miscorrection, which is why modern DDR5/HBM systems pair SECDED with on-die ECC, memory scrubbing, or multi-symbol Reed–Solomon chipkill codes.

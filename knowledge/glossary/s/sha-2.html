SHA-2

SHA-2 is a family of widely used cryptographic hash functions that turn any data into a fixed-length digital fingerprint.

Think of SHA-2 as a set of tamper-evident seals for digital files. Whether you feed it a one-word message or a full operating-system image, it produces a short, scrambled summary that changes completely if even a single bit of the input changes. You cannot reverse the summary to recover the original file, which makes it useful for checking downloads, verifying software updates, and securing web connections.

Part of SHA algorithms, SHA-2 includes variants named by their output length in bits—most commonly SHA-256 and SHA-384, along with SHA-224 and SHA-512. On Linux, commands like sha256sum and sha512sum check file integrity, while TLS certificates and package managers rely on SHA-2 instead of the broken SHA-1. SHA-256 is faster on 32-bit CPUs, whereas SHA-512 and SHA-384 often run faster on 64-bit processors because they use 64-bit arithmetic.

Why might a 64-bit server use SHA-384 or SHA-512 instead of SHA-256?

SHA-384 and SHA-512 operate natively on 64-bit words rather than 32-bit words, so on 64-bit CPUs they often achieve higher throughput per byte while also providing larger security margins.

Standardized in NIST FIPS 180-4, SHA-2 uses a Merkle–Damgård construction with a Davies–Meyer compression function: SHA-224/256 process 512-bit message blocks across 64 rounds of 32-bit word operations, while SHA-384/512 (and SHA-512/224, SHA-512/256) process 1024-bit blocks across 80 rounds of 64-bit word operations. Full-width SHA-256 and SHA-512 remain vulnerable to length-extension attacks when misused as a naive keyed MAC (H(key || message)), which is why HMAC or truncated variants (SHA-224, SHA-384, SHA-512/256) are required in protocols that depend on prefix-MAC security. Modern x86_64 (SHA-NI) and ARMv8 Cryptography Extensions accelerate SHA-256 in hardware.

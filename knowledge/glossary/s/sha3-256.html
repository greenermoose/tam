SHA3-256

SHA3-256 is the 256-bit cryptographic hash function in the NIST FIPS 202 SHA-3 family.

SHA3-256 produces a 256-bit (64-character hexadecimal) fingerprint just like SHA-256, but computes it using the newer SHA-3 sponge design. For everyday users, it serves the exact same purpose—detecting whether a file or message has been changed—while offering a backup algorithm that does not share SHA-256’s internal structure.

Part of SHA algorithms, SHA3-256 matches SHA-256’s 256-bit output size and security target, making it a drop-in replacement when a protocol or application prefers SHA-3. You can compute it on Linux with OpenSSL (openssl dgst -sha3-256 file) or Python’s hashlib.sha3_256. Note that SHA3-256 is not the same as original Ethereum Keccak-256: NIST added a two-bit padding suffix when standardizing SHA-3, so the two produce different digests for identical inputs.

If you hash the same file with SHA-256 and SHA3-256, will the digests match?

No. Both produce 256-bit (64-hex-character) outputs, but they use completely different mathematical algorithms, so their digests for any input are unrelated.

Specified in FIPS 202, SHA3-256 instantiates the Keccak sponge over Keccak-f[1600] with rate r = 1088 bits (136 bytes per block) and capacity c = 512 bits, appending the 01 domain-separation bits before pad10*1 multi-rate padding (which distinguishes it from pre-standard Keccak-256). The 512-bit capacity guarantees 128-bit collision resistance and 256-bit preimage/second-preimage resistance in the random-permutation model while preventing length-extension attacks because 1344 bits of the 1600-bit state are never squeezed out.

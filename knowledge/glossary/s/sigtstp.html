Guide / Glossary A–Z / Terms beginning with S / SIGTSTP (Terminal Stop signal)

SIGTSTP (signal 20 on x86_64 Linux) is the catchable terminal stop signal sent when you press Ctrl+Z to suspend a foreground job.

Pressing Ctrl+Z is like putting a bookmark in a book and setting it aside for a moment. SIGTSTP pauses the running program and hands you back your shell prompt so you can run other commands, then pick the paused program right back up with fg or bg.

Part of Unix signals, SIGTSTP can be caught or ignored—unlike SIGSTOP. Full-screen terminal programs such as micro, vim, or less install a SIGTSTP handler to restore normal terminal settings and clear the alternate screen before re-raising a stop, so your shell stays usable while the app is suspended.

How do you resume a program that you suspended with Ctrl+Z?

Run fg in the same shell to bring it back to the foreground, or bg to let it keep running in the background (both send SIGCONT).

POSIX terminal stop signal (20 on x86_64/ARM64 Linux; architecture-dependent). Emitted by the N_TTY line discipline to the foreground process group when VSUSP (default 0x1A, Ctrl+Z) is read and ISIG is enabled. A typical interactive handler restores saved termios attributes, resets signal disposition to SIG_DFL, and calls raise(SIGTSTP) (with SIGTSTP unblocked) so the kernel actually suspends the process; on resume via SIGCONT, a paired SIGCONT handler re-enters raw or alternate-screen mode and redraws. Background jobs attempting terminal reads or writes instead receive SIGTTIN or SIGTTOU.

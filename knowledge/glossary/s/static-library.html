Guide / Glossary A–Z / Terms beginning with S / Static library

A static library is a bundle of pre-built code that gets copied directly into a program when it is compiled and linked.

Think of building a program like assembling a cookbook. Instead of telling the reader to go buy a separate reference book every time they need a basic sauce, you print those recipes right inside the cookbook itself. A static library works the same way: the helpful code is baked directly into the final program file, so the program carries everything it needs and does not have to hunt for that library file later on someone else’s computer.

On Linux, static libraries are usually named with a .a extension (such as libfoo.a) and are created by bundling compiled .o object files with the ar tool. Unlike a shared library (.so), which stays separate on disk and is loaded at run time, a static library is folded into the executable during linking. This makes the executable larger, but avoids “missing library” errors when moving it to another system.

If a security bug is fixed in a static library, does an already-compiled program automatically get the fix?

No. Because the library’s code was copied into the executable at link time, the program still contains the old code. You must relink (or recompile) the program against the updated library to pick up the fix, unlike a shared library where updating the .so file can update all programs that load it.

A static library is an ar(1) archive of relocatable ELF object files, typically indexed with a symbol table (ranlib or ar -s, stored in the / archive member). During static resolution, ld scans archives left-to-right and extracts only the object members that satisfy currently undefined symbols—meaning argument order on the link line matters, and circular dependencies between archives require repeating libraries or wrapping them in --start-group/--end-group. Because unused object files are omitted, -ffunction-sections -fdata-sections paired with --gc-sections reduces binary bloat. On modern Linux distributions, fully static binaries (-static) with glibc are discouraged because NSS (Name Service Switch) and dlopen() still expect dynamic loading; musl is commonly used when true static linking is required.

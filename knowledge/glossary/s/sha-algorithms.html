SHA algorithms (SHA-1, SHA-2, SHA-256, SHA-3, SHA3-256, SHA384)

SHA (Secure Hash Algorithm) is a series of NIST-standardized cryptographic hash functions used to create fixed-size digital fingerprints of data.

Think of the SHA family as successive generations of digital tamper-evident seals. Each generation takes any file or message and produces a short, unique fingerprint so computers can tell whether data was altered or corrupted. Just as physical locks get stronger over time when old designs are picked, SHA-1 was retired after weaknesses were found, leaving SHA-2 and SHA-3 as the trusted standards used across websites, software downloads, and security tools.

In everyday Linux and security work, you will encounter three main SHA generations: deprecated SHA-1 (160-bit, still seen in legacy Git repositories for identification but unsafe against forgery), the ubiquitous SHA-2 family (SHA-256, SHA-384, SHA-512), and the newer sponge-based SHA-3 family (SHA3-256). Command-line tools like sha256sum and sha512sum check file integrity, while TLS and SSH negotiate specific SHA-2 or SHA-3 variants for signatures and key derivation.

Why is SHA-1 still acceptable for identifying old Git commits locally, yet forbidden for TLS certificates?

TLS certificates require collision resistance against active attackers who could forge a valid signature, and practical chosen-prefix collisions exist for SHA-1. Local object lookup without an adversarial signer is less exposed, though Git is migrating to SHA-256.

The NIST SHA suite spans three distinct constructions: SHA-1 (FIPS 180-4, 160-bit Merkle–Damgård, broken with practical chosen-prefix collisions around 2^63 operations), SHA-2 (FIPS 180-4, 32-bit/64-bit Davies–Meyer Merkle–Damgård with 112–256-bit collision resistance), and SHA-3 (FIPS 202, Keccak sponge over Keccak-f[1600] with extendable-output SHAKE128/256 and cSHAKE/KMAC derivatives in SP 800-185). Because Merkle–Damgård hashes expose their full chaining state, unkeyed SHA-256(k || m) is vulnerable to length extension, whereas SHA-3’s hidden capacity eliminates length extension and simplifies keyed MACs (KMAC) without HMAC’s double-pass wrapper.

Guide / Glossary A–Z / Terms beginning with S / Sharding

Sharding spreads rows across multiple machines so no single database holds everything.

It is sorting a huge card index into several drawers by the first letter of a surname.

The shard key decides where each row goes. A good key spreads work evenly and keeps common queries inside one shard.

Sharding changes failure and join behaviour: cross-shard joins and transactions are expensive, and a poor key creates hotspots. Resharding needs a migration plan.

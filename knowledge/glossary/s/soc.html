Guide / Glossary A–Z / Terms beginning with S / SoC (System on a Chip)

An integrated circuit that combines a computer’s processor, graphics, memory controllers, and input/output interfaces onto a single chip or package.

A traditional desktop PC separates the CPU, graphics card, and motherboard chips into distinct parts plugged into a board. An SoC packs all of those jobs onto one fingernail-sized silicon chip—like fitting a kitchen, bedroom, and living room into a studio apartment—which is why smartphones, Raspberry Pis, and modern laptops can be thin, quiet, and frugal with battery power.

Because an SoC integrates CPU cores, GPU, RAM controllers, USB/PCIe, and power management together, Linux cannot always probe hardware dynamically the way a PC uses ACPI and PCI enumeration. Instead, ARM and RISC-V SoCs typically rely on a Device Tree (.dtb loaded by the bootloader) to describe which peripherals exist at which memory addresses and interrupt lines. You can inspect a running system’s SoC info under /sys/devices/soc0/ or /proc/device-tree/.

Why do ARM SoC boards usually need a board-specific Device Tree file for Linux to boot, unlike standard x86 PCs?

Many SoC peripherals sit on internal, non-discoverable buses (like AMBA/AXI) rather than self-describing PCIe or ACPI tables. The Device Tree tells the Linux kernel the exact memory addresses, clocks, and interrupts of each integrated block.

An SoC integrates heterogeneous compute (big.LITTLE/DynamIQ CPU clusters, GPU, NPU, DSP), coherent interconnects (such as ARM AMBA CHI/ACE), unified memory controllers (LPDDR5/HBM), and DMA-capable I/O blocks on a monolithic die or chiplet package. Shared last-level cache and unified memory eliminate discrete PCIe copy overhead, while Linux’s devicetree, clk, regulator, pinctrl, and iommu subsystems coordinate clock gating, DVFS power domains, and DMA isolation across tightly coupled IP blocks.

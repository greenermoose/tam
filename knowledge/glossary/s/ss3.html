SS3 (Single Shift 3)

A two-byte terminal escape prefix (ESC O, or 0x8F in 8-bit mode) used for unparameterized function keys and application-mode cursor keys.

When you press a special key like F1 or an arrow key, your keyboard does not send a single letter—it sends a short code so the program in the terminal knows which key was pressed. SS3 is one of those short starter codes (Escape followed by O) used for a few classic keys that do not need extra numbers attached.

Most modern terminal key sequences start with CSI (ESC [) so they can carry numeric parameters like modifiers or repeat counts. SS3 (ESC O) carries no parameters—just one final byte, such as ESC O P for F1 or ESC O A for Up Arrow when the terminal is in application cursor mode (DECCKM). Switching between ESC [ A and ESC O A is a common reason raw keybindings break inside tmux, vim, or less.

Why do arrow keys sometimes send ESC O A instead of ESC [ A?

Full-screen terminal programs often enable application cursor mode (DECCKM), which tells the terminal emulator to send SS3 (ESC O) sequences for arrow keys instead of standard CSI (ESC [) sequences.

Defined in ECMA-48 as Single Shift Three (0x1B 0x4F in 7-bit environments, 0x8F C1 control in 8-bit environments), SS3 originally shifted the G3 character set for a single graphic character. DEC VT100/VT220 terminals and xterm repurposed ESC O for keypad application mode (DECKPAM), DECCKM cursor keys (A–D), and PF1–PF4 (P–S, mapped to F1–F4). Because SS3 lacks parameter bytes, modified function keys (such as Shift+F1) cannot be encoded under SS3 and fall back to CSI (ESC [ 1 ; 2 P) or kitty keyboard protocol sequences.

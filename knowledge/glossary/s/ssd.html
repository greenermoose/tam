SSD - Solid-State Drive

A non-volatile storage device that stores data on flash memory chips rather than spinning magnetic platters.

Older hard drives store files on spinning disks with a tiny moving arm, much like a record player. An SSD has no moving parts—it stores files electronically on memory chips, so your computer boots faster, opens apps almost immediately, and is much less likely to be damaged by a bump.

On Linux, SSDs typically appear as /dev/nvme0n1 (over PCIe/NVMe) or /dev/sda (over SATA). Unlike spinning disks, flash memory cannot overwrite a single page in place—it must erase whole blocks first—so the OS periodically sends TRIM (fstrim) commands to tell the drive’s controller which deleted blocks are safe to erase in the background.

Why does Linux run fstrim periodically on SSDs even though spinning hard drives do not need it?

Flash cells must be erased in large blocks before being rewritten. Without TRIM, the SSD controller does not know which deleted filesystem blocks are free, causing extra internal copying (write amplification) and slower writes.

An SSD embeds a Flash Translation Layer (FTL) in its controller to map logical block addresses (LBAs) to physical NAND pages, perform dynamic/static wear leveling, manage bad blocks, and run garbage collection. Because NAND program/erase cycles degrade oxide layers and erase blocks (often megabytes) are far larger than 4 KiB pages, unaligned or un-trimmed writes increase write amplification factor (WAF). NVMe replaces legacy AHCI’s single 32-command queue with up to 64K queues of 64K commands each, aligning with multi-core Linux blk-mq submission queues.

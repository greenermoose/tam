SVM (Secure Virtual Machine)

SVM (Secure Virtual Machine), marketed as AMD-V, is AMD’s hardware virtualization extension built into x86-64 processors so virtual machines can run guest operating systems near native speed.

Normally, one operating system expects to own the whole computer. When you run a virtual machine inside Linux, the guest system tries to do privileged tasks that could interfere with your main system. SVM adds a built-in hardware referee to AMD processors so the guest can run directly on the CPU while staying safely boxed in, making virtual machines much faster and more secure than pure software emulation.

On Linux, the KVM hypervisor loads the kvm_amd kernel module when SVM is available and enabled in firmware (BIOS/UEFI). You can check whether the CPU advertises it by running grep -E 'vmx|svm' /proc/cpuinfo (svm for AMD, contrasting with vmx for Intel VT-x). If svm is missing or kvm_amd fails to load, hardware virtualization is usually disabled in the motherboard firmware under an option such as “SVM Mode”.

What does it mean if svm appears in /proc/cpuinfo, yet kvm_amd refuses to load?

The CPU silicon supports SVM, but motherboard firmware (BIOS/UEFI) has locked virtualization off via the VM_CR.SVMDIS bit before Linux booted. Enabling SVM Mode in firmware clears that lock so KVM can activate hardware virtualization.

SVM is advertised via CPUID Fn8000_0001_ECX[2] and enabled by setting EFER.SVME (bit 12 of MSR 0xC0000080), provided VM_CR.SVMDIS (MSR 0xC0010114[4]) is clear. Unlike Intel VMX’s opaque VMCS accessed with VMREAD/VMWRITE, SVM places guest state and intercept bitmaps in a memory-resident Virtual Machine Control Block (VMCB) whose physical address is passed in RAX to VMRUN, paired with VMLOAD/VMSAVE, CLGI/STGI (global interrupt flag control), and ASIDs for TLB tagging alongside Nested Page Tables (NPT). Nested virtualization traps guest VMRUN into L0, merging L0 and L1 VMCB intercepts and nested page tables, where subtle bugs often involve GIF handling, SMM/SMI interactions, or AVIC/x2AVIC interrupt-controller virtualization mismatches.

SPN (Substitution-Permutation Network)

A block-cipher design that encrypts fixed-size chunks of data by repeating layers of byte substitution and bit scrambling.

Think of shuffling a deck of cards and also swapping every card’s suit according to a secret chart, then doing both again many times. Doing just one step would be easy to undo, so repeating both makes the original message unrecognizable without the key.

Modern ciphers such as AES use an SPN structure: each round mixes in part of the key (AddRoundKey), replaces bytes through a non-linear lookup table (SubBytes for confusion), and spreads bits across the block (ShiftRows and MixColumns for diffusion). Unlike a Feistel network, which encrypts only half the block per round, an SPN transforms the entire block in every round.

Why does an SPN alternate substitution and permutation instead of repeating only one of them?

Substitution alone hides individual values but leaves patterns across positions intact, while permutation alone only moves bits around without hiding them. Alternating both ensures that changing a single input bit rapidly affects every bit of the output.

Formally, an iterated SPN alternates key addition, parallel S-box layers (providing non-linearity and low differential/linear approximation probabilities), and an invertible linear mixing layer (often an MDS matrix, as in AES’s MixColumns, maximizing branch number). Because every layer must be invertible for decryption—unlike Feistel networks (DES) where the round function need not be bijective—SPNs require explicit inverse S-boxes and inverse linear layers, though decryption can share hardware or use equivalent inverse key schedules.

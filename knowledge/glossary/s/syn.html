SYN (Synchronous Idle, 0x16)

SYN (Synchronous Idle, ASCII 0x16, Ctrl+V) is a control character originally used to keep synchronous serial links aligned and used in Unix terminals to insert the next character literally.

Long before modern networks, two machines talking over a serial wire needed a steady heartbeat character when no real data was flowing so their clocks stayed in step—that character was SYN. On a modern Linux terminal, that same key combination (Ctrl+V) has a handy second life: it tells your shell not to treat the next key as a shortcut or command, but to type it as-is.

In the C0 control codes, SYN (0x16, decimal 22) is produced by Ctrl+V because V is the 22nd letter of the alphabet. In Linux’s terminal line discipline (termios), 0x16 is the default VLNEXT (“literal next”) character: pressing Ctrl+V followed by Enter, Tab, or Ctrl+C inserts the raw control character instead of submitting the line or sending SIGINT. Note that SYN here is an ASCII character byte, not to be confused with the TCP SYN flag used to open network connections.

When you press Ctrl+V then Ctrl+C in a terminal running cat, why doesn’t cat immediately exit?

The kernel’s canonical line discipline intercepts Ctrl+V (VLNEXT) and suppresses special processing for the very next byte. As a result, Ctrl+C (0x03) is stored as literal input data instead of generating a SIGINT signal.

Defined in ANSI X3.4 / ISO 646 as C0 code 0x16 (^V), SYN was specified for character-oriented synchronous protocols (such as IBM BISYNC) where receivers hunted for contiguous SYN octets to achieve frame and bit-clock synchronization before STX. In POSIX termios (c_cc[VLNEXT] under IEXTEN), when ICANON and IEXTEN are enabled in the N_TTY line discipline, receiving VLNEXT sets ldata->lnext = 1, bypassing ISIG, ICRNL, and erase/kill interpretation for the next single byte. In raw mode (cfmakeraw()), IEXTEN is cleared and 0x16 passes straight to userspace—which is why full-screen applications like vim implement their own Ctrl+V literal-insert handler independently of the kernel tty driver.

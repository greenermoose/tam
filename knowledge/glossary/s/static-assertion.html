Static assertion

A check evaluated by the compiler at build time that halts compilation with an error if a constant condition is false.

Instead of waiting until a program is running to notice that a critical assumption is wrong—like a bridge failing only when a truck drives over it—a static assertion checks the blueprint before anything is built. If the numbers do not add up, the compiler refuses to finish building the program and points straight to the problem.

Unlike runtime assert(), which only triggers if the running program hits that code path (and may be compiled out with -DNDEBUG), a static assertion runs unconditionally during compilation. In C and C++, systems programmers use it to verify assumptions such as sizeof(struct header) == 16 across architectures so layout bugs are caught immediately on build rather than corrupting data at runtime.

When should you use a static assertion instead of runtime assert()?

Use a static assertion whenever the condition depends only on compile-time constants—such as type sizes, struct layouts, or array bounds—so the build fails immediately on any unsupported platform.

Standardized in C11 as _Static_assert(constant-expression, string-literal) (with <assert.h> providing static_assert, and C23 making both static_assert a keyword and the message optional) and in C++11 as static_assert, the operand must be an integral constant expression evaluated during translation. When false, the compiler emits a diagnostic containing the message string and aborts translation. In pre-C11 codebases (such as older Linux kernel headers), BUILD_BUG_ON emulated this via negative-sized array or bitfield declarations, which failed less cleanly with opaque type errors.

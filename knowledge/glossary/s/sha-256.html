SHA-256

SHA-256 is a cryptographic hash function in the SHA-2 family that produces a 256-bit digital fingerprint for any input.

When you download a program or check that a file has not been altered, SHA-256 acts like a unique 64-character serial number computed from the file’s contents. If someone changes even one letter or corrupts a single byte during download, the resulting SHA-256 fingerprint looks completely different. Because two different files are astronomically unlikely to share the same fingerprint, matching the published SHA-256 value gives you confidence that you have the exact file.

Part of SHA algorithms, SHA-256 is the workhorse digest across Linux and the web: sha256sum computes it on files, Arch packages and Tamlinux build digests record it in manifests, Git supports it as a modern object hash, and TLS certificates use it for signatures. Unlike encryption, hashing is one-way—you cannot decrypt a SHA-256 digest back into the original data. Also avoid using raw SHA-256 to store user passwords; fast hashes let attackers guess billions of passwords per second, so use a slow password-hashing function like Argon2id instead.

If two files produce the same SHA-256 output in your verification script, what should you conclude?

In practice, you can conclude the files are identical. Finding two different inputs with the same 256-bit SHA-256 digest (a collision) requires roughly 2^128 operations, which is computationally infeasible.

Defined in FIPS 180-4, SHA-256 pads inputs to a multiple of 512 bits (appending a 1 bit, zeros, and a 64-bit big-endian length) and runs 64 rounds of ARX-like bitwise operations (Ch, Maj, Σ0, Σ1) over eight 32-bit state words initialized from the fractional parts of the square roots of the first eight primes. It targets 128-bit collision resistance and 256-bit second-preimage and preimage resistance. Because the entire internal state is output directly, raw SHA256(k || m) suffers from length-extension attacks; use HMAC-SHA256 for authentication, and note that hardware SHA-NI instructions can process blocks an order of magnitude faster than pure-software implementations.

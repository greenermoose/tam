Guide / Glossary A–Z / Terms beginning with S / Shebang

A shebang is the special #! line at the very top of a text script that tells the operating system which program should run it.

Text files containing instructions—like shell scripts or Python programs—cannot run by themselves because the computer needs to know which language interpreter understands them. Putting #! followed by the interpreter’s location on the first line is like writing “Open with Python” on the cover of a notebook: when you run the script directly, the system reads that first line and hands the file to the right program automatically.

In Linux scripts, you will commonly see #!/bin/sh, #!/bin/bash, or #!/usr/bin/env python3. Using /usr/bin/env searches your PATH so the script works even when python3 lives in different directories across distributions or virtual environments. Remember two practical gotchas: the script file still needs executable permission (chmod +x script.sh) to run directly as ./script.sh, and if you pass an explicit interpreter on the command line (such as bash script.sh), the shebang line is ignored as an ordinary comment.

Why does #!/usr/bin/env python3 often work better than #!/usr/bin/python3?

env looks up python3 in the user’s PATH, so it finds the active virtual environment or non-standard install path instead of hardcoding one fixed location.

During execve(2), the kernel’s binfmt_script handler inspects the first two bytes for magic 0x23 0x21 (#!), parses the interpreter path and at most one optional argument string (up to BINPRM_BUF_SIZE, 256 bytes on modern Linux), and re-invokes execution with argv rewritten to [interpreter, optional_arg, script_path, original_args...]. Because Linux passes everything after the interpreter as a single argument, flags like #!/usr/bin/env -S python3 -u require env -S to split options. Trailing \r from CRLF line endings becomes part of the interpreter path and causes misleading No such file or directory errors, and setuid bits on scripts are ignored by the kernel to prevent race conditions.

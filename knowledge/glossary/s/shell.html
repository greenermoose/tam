Shell

A shell is a program that reads the instructions you type and asks the computer to carry them out.

A shell is your text-based conversation partner with the operating system. When you open a terminal window or a text console, the shell shows a prompt, waits for you to type a command, runs the right program, and displays the result. On Tamlinux the usual interactive shell is Bash, while the Guide is a separate program you can reopen with tam hi.

Beyond launching standalone programs, a shell connects commands together with pipes (|) and redirections (>, <), expands wildcards like *.txt, and runs built-in commands such as cd and export that must alter the shell’s own state. It also manages background and foreground jobs, distinguishing interactive shells (where you type) from non-interactive shells (which execute scripts). See pipelines and jobs for hands-on usage.

Why must cd be a shell built-in rather than an external program like /usr/bin/ls?

An external program runs in a child process and can only change its own working directory; once it exits, the parent shell’s directory would be unchanged. A built-in runs inside the shell process itself so the directory change persists.

Before invoking fork/execve, a POSIX shell tokenizes input, applies quoting rules, and performs ordered expansions (brace, tilde, parameter, command substitution, arithmetic, word splitting, and pathname globbing), then sets up file-descriptor redirections (dup2) and pipeline FDs in the child. Interactive shells also manage terminal foreground process groups via tcsetpgrp and SIGTSTP/SIGCONT job control, expose exit statuses ($?, with signals encoded as 128 + signo), and behave differently across login versus non-login startup files (e.g., .bash_profile vs. .bashrc).

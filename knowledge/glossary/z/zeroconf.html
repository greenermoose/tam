Guide / Glossary A–Z / Terms beginning with Z / Zeroconf

Zero-configuration networking: a set of techniques that let devices join a network and find each other without a central configuration service.

Zeroconf is the idea behind plugging in a printer and seeing it appear, with no address to type and no server to set up. The devices announce themselves and listen for one another on the local network. Apple calls its implementation Bonjour; Linux uses the compatible Avahi. Zeroconf is the overall approach, not a single protocol.

Zeroconf combines several pieces: an address chosen without a DHCP server, a name resolved on the local link by mDNS, and services listed and resolved by DNS-SD. The pieces are independent, so a network can use DHCP for addresses and still use mDNS and DNS-SD for discovery. On Linux, avahi-browse shows what a Zeroconf device is offering.

Is Zeroconf the same as Avahi or Bonjour?

No. Zeroconf is the general approach. Avahi and Bonjour are two compatible implementations of it, on Linux and Apple systems respectively.

The IETF zeroconf working group developed the standards that make this interoperability possible. Link-local addressing uses IPv4 169.254.0.0/16 or IPv6 link-local addresses; name resolution is RFC 6762 (mDNS) and service discovery is RFC 6763 (DNS-SD). These mechanisms operate on a single link and do not require, or cross, a router. They also provide no authentication, so a device found this way should not be trusted merely because it appeared in a local list.

Event loop

An event loop is the part of a runtime that waits for work, runs one piece at a time, and then moves to the next.

Imagine one clerk at a counter. They finish the person in front before calling the next. New arrivals wait in a line rather than interrupting the current task.

In browsers, clicks, timers and network replies are tasks. Promises queue microtasks that run before the next task. In Node, the loop also coordinates filesystem and network work through libuv.

Why does a delayed promise not freeze the whole page?

The promise settles later and queues a microtask. The event loop keeps running other tasks and rendering while the delay passes, then resumes only the code waiting on that promise.

A loop iteration drains microtasks after each callback; rendering may occur between tasks in a browser. Long synchronous work starves both rendering and queued callbacks. Node's phases order timers, polls and check callbacks, but user JavaScript still runs on one thread per process.

EOF (End of File)

End of file: the condition indicating that no more data is available to read from a file, pipe, or input stream.

When a program reads a file or waits for your typing, it needs a clear way to know when the input is finished. EOF is that “nothing left to read” signal—like reaching the back cover of a book, or hanging up a phone call so the listener knows you are done speaking.

In a Linux terminal, pressing Ctrl+D on a blank line sends EOF to the running program (for example, closing an interactive Python or cat session). In a shell pipeline, EOF happens automatically when the upstream writer closes its output or exits—unlike Ctrl+C, which interrupts the process with a signal.

Is EOF a special character stored at the end of every file on disk?

No. On Linux and Unix systems, EOF is a stream condition reported by the operating system when the read position reaches the file’s byte length or when a pipe’s write end closes.

At the POSIX I/O layer, EOF is signaled by read(2) returning 0 bytes (not -1), whereas C stdio represents it with the negative macro EOF (-1) returned by fgetc(3) alongside feof(3) to distinguish end-of-stream from read errors. Note that on sockets or pipes, a peer closing its write half triggers EOF on subsequent reads, while for regular files EOF is simply reaching st_size and can be cleared if another writer appends data.

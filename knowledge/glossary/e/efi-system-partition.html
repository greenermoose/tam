EFI System Partition

The EFI System Partition (ESP) is the dedicated disk partition that stores boot loaders and startup files for UEFI firmware.

Think of the EFI System Partition as a small, tidy front hallway on your storage drive. Even if Linux stores your files in its own format elsewhere on the disk, the computer’s startup firmware always checks this shared hallway first because it knows how to read it and launch your operating system from there.

On Linux, the ESP is a FAT32-formatted partition typically mounted at /boot/efi or /efi, holding vendor subdirectories like EFI/systemd/ or EFI/BOOT/BOOTX64.EFI. Unlike /boot on ext4 or Btrfs, FAT32 has no POSIX file permissions, so /etc/fstab normally mounts it with restrictive masks such as umask=0077 to protect files like random-seed data.

Why must the EFI System Partition use FAT32 instead of ext4 or Btrfs?

Motherboard UEFI firmware includes a built-in FAT filesystem driver by specification, whereas it generally cannot read Linux-specific filesystems before a boot loader or kernel loads.

Identified on GPT disks by Partition Type GUID C12A7328-F81F-11D2-BA4B-00A0C93EC93B (and MBR type 0xEF where used), the ESP must use FAT32 on fixed media per the UEFI specification. When NVRAM BootOrder variables are missing or reset, firmware falls back to the architecture’s default removable-media path (e.g., \EFI\BOOT\BOOTX64.EFI); undersized ESPs (under ~512 MiB) can run out of space when storing multiple kernels, initramfs images, or Unified Kernel Images alongside another OS’s files.

ECMA-48 is the international standard for terminal control functions and ANSI escape sequences.

When a terminal displays colored text, bold headings, or a moving progress bar, the program sends hidden instructions mixed right into the text—like stage directions in a script telling an actor where to stand or what lighting to use. ECMA-48 is the shared rulebook for those instructions so different terminals understand them the same way.

ECMA-48 (also published as ISO/IEC 6429) defines the escape-sequence grammar—such as Control Sequence Introducer (CSI) and Select Graphic Rendition (SGR) codes—used by Linux virtual consoles and terminal emulators. In practice, you see these sequences when formatting colors or cursor movement with printf, or when viewing raw log files in less without -R.

Why do raw ^[[31m codes sometimes appear when you pipe colored command output into a file or plain viewer?

Programs emit ECMA-48 escape sequences as ordinary bytes in the text stream. A terminal emulator interprets them as color commands, whereas a plain file or viewer without escape-sequence handling prints the raw bytes literally.

Ecma International standard ECMA-48 (5th ed., 1991; ISO/IEC 6429:1992) specifies C0 (0x00–0x1F) and C1 (0x80–0x9F) control sets, 7-bit (ESC [, 0x1B 0x5B) and 8-bit (0x9B) CSI introducers, parameter bytes (0x30–0x3F), intermediate bytes (0x20–0x2F), and final bytes (0x40–0x7E). In UTF-8 terminals, raw 8-bit C1 bytes collide with multi-byte continuation bytes, so 7-bit ESC [ sequences are required; vendor extensions (such as DEC private modes) use parameter-range prefixes like ? or > outside core ECMA-48.

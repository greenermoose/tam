EUF-CMA (Existential Unforgeability under Chosen-Message Attack)

EUF-CMA (Existential Unforgeability under Chosen-Message Attack) is the standard security definition for digital signatures and message authentication codes (MACs).

Imagine a notary who will sign any document you hand them. EUF-CMA means that even if a forger watches the notary sign hundreds of documents the forger picked out, they still cannot create a valid signature for even one new document the notary never signed.

Modern schemes such as Ed25519, RSA-PSS, ECDSA, and post-quantum ML-DSA are designed to satisfy EUF-CMA so attackers observing signed software packages, TLS handshakes, or API tokens cannot forge a signature on a different message. Note the contrast with strong unforgeability (SUF-CMA): EUF-CMA forbids forging a signature for any new message, whereas SUF-CMA also forbids producing a second valid signature for a message that was already signed.

Why does the EUF-CMA security model let the attacker choose which messages get signed?

In real systems, attackers can often influence what a server or signer signs—for example, by submitting login requests, certificates, or commits. Proving a scheme secure against an attacker who picks the training examples guarantees security against weaker, passive eavesdroppers too.

In the EUF-CMA game, a challenger generates (pk, sk) and gives pk to a PPT adversary A with access to a signing oracle Sign(sk, ·). After querying messages m_1, …, m_q and receiving σ_i, A wins by outputting (m*, σ*) where Verify(pk, m*, σ*) = 1 and m* ∉ {m_1, …, m_q}; security requires this win probability to be negligible. Key nuances: EUF-CMA permits signature malleability (such as ECDSA (r, −s mod n)) unless strengthened to SUF-CMA; nonce reuse in randomized ECDSA breaks EUF-CMA completely via private-key recovery, motivating hedged/deterministic signing (RFC 6979, Ed25519).

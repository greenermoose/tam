ETB (End of Transmission Block, 0x17)

ASCII control character 0x17 (End of Transmission Block), originally used to mark the end of a data block and mapped in Linux terminals to Ctrl+W for deleting the previous word.

When you type in a terminal, some key combinations send invisible control signals instead of letters. Pressing Ctrl+W sends the ETB signal, which acts like a quick “delete last word” button so you do not have to tap Backspace repeatedly.

Part of the C0 control codes, ETB (0x17) is bound by default to VWERASE in the Linux kernel terminal line discipline, erasing back to the previous whitespace. Contrast this with Ctrl+U (VKILL, which erases the whole line) and Backspace (which erases one character). Full-screen programs like vim or less run in raw mode, so they receive 0x17 directly rather than letting the kernel edit the line.

Why does Ctrl+W erase a word at a shell prompt, while inside an editor like Vim it can trigger a window command instead?

At a shell prompt (canonical mode), the kernel line discipline intercepts 0x17 (VWERASE) and deletes the previous word before the shell sees it. In raw mode, the editor disables line-discipline editing so 0x17 is delivered unchanged to the application.

ASCII 0x17 (decimal 23, ^W, binary 00010111). Defined in ANSI X3.4 / ISO/IEC 646 to delimit intermediate blocks in block-oriented serial protocols (unlike ETX 0x03 for end of text or EOT 0x04 for end of transmission). In Linux termios, c_cc[VWERASE] defaults to 0x17 (\027) and takes effect only when both ICANON and IEXTEN are set in c_lflag. Standard Linux n_tty treats whitespace as the word boundary, whereas BSD-style ALTWERASE stops at non-alphanumeric characters.

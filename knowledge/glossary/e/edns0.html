EDNS0 (Extension Mechanisms for DNS 0)

An extension mechanism that lets modern DNS messages carry extra capabilities and larger payloads.

Original DNS messages were small and had limited room for new features. EDNS0 is a way for DNS clients and servers to say "I support newer DNS features." It helps DNS carry larger replies and extra flags without changing the basic DNS message format in an incompatible way.

EDNS0 (often written EDNS(0)) adds an OPT pseudo-record in the DNS additional section. It is not a normal DNS record; it carries metadata such as the sender's UDP payload size and extended flags. DNSSEC uses the EDNS0 DO (DNSSEC OK) bit to request DNSSEC records. With EDNS0, DNS over UDP can use payloads larger than the old 512-byte limit, though large packets may still be fragmented or fall back to TCP.

Why does EDNS0 matter for DNSSEC?

DNSSEC replies include extra records such as signatures, making them larger. EDNS0 lets the client advertise support for larger UDP payloads and set the DO bit to ask for DNSSEC data.

EDNS0 is specified by RFC 6891. The OPT RR encodes extended RCODE bits, UDP payload size, version, flags, and option codes (RDATA options such as NSID, COOKIE, ECS, or padding). Because OPT is hop-by-hop metadata, intermediaries must handle it carefully; broken middleboxes have historically caused EDNS/DNSSEC interoperability problems, leading to fallback behavior in resolvers. EDNS0 is also the transport for modern DNS extensions, but it does not itself provide confidentiality or authentication.

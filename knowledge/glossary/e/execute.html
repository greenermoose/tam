Guide / Glossary A–Z / Terms beginning with E / Execute

To carry out a CPU instruction or run a program.

Think of a recipe card: reading the steps is preparation, while actually turning on the stove and mixing ingredients is executing. In a computer, executing means the processor is actively doing the work—adding numbers, saving a value, or moving to the next step.

Inside the CPU, execution follows fetch and decode: the processor takes a decoded instruction and applies it to registers, memory, or devices. In broader Linux usage, “execute” also describes starting a program via execve or granting the x permission bit—which on a file allows running it, and on a directory allows traversing into it.

What is the difference between decoding an instruction and executing it?

Decoding determines what the instruction bits mean and which registers or addresses they use, whereas executing actually performs the operation—computing a result, accessing memory, or updating the program counter.

Microarchitecturally, the Execute (EX) stage dispatches decoded micro-ops to functional units—ALUs, vector/FPUs, branch units, and address-generation units (AGUs)—producing results and updating condition flags. In out-of-order superscalar cores, execution decouples from program order via reservation stations and a reorder buffer (ROB): operations fire as soon as source operands are ready, with memory instructions split across AGUs and store/load queues and results committed in-order only after branch and exception checks clear.

ECB (Electronic Codebook)

The simplest block-cipher mode of operation, which encrypts each fixed-size block independently with the same key and therefore leaks patterns in repeated data.

Imagine replacing every letter in a message with a fixed symbol, like a newspaper puzzle. Even if you cannot read the symbols, any repeated word or picture still shows the exact same shape—so an outsider can spot patterns right through the disguise, which makes ECB unsafe for real data.

Because ECB uses no initialization vector (IV) or chaining between blocks, identical 16-byte AES input blocks always produce identical output blocks—encrypting a bitmap image in ECB famously leaves its silhouette visible. In practice, always choose an authenticated mode such as AES-GCM or ChaCha20-Poly1305 instead.

Why is ECB unsafe even if you use a strong 256-bit AES key?

AES-256 only scrambles each isolated 16-byte block; without an IV or chaining, identical plaintext blocks still produce identical ciphertext blocks, leaking data structure and letting attackers reorder or replay blocks.

Defined as deterministic block encryption C_i = E_K(P_i), ECB fails IND-CPA security for any message longer than one block or repeated across messages (P_i = P_j iff C_i = C_j). It also provides no integrity protection, permitting silent block reordering, splicing, and truncation. Its only legitimate role is encrypting a single uniformly random block (for example, inside key-wrapping or higher-level constructions), never arbitrary multi-block plaintext.

Executable

A file that the operating system can run as a program.

Not every file on your computer can be run—photos, notes, and music files just hold data. An executable is a file that holds instructions the system can carry out and is marked as allowed to run, like an app you launch or a command you type in a terminal.

On Linux, a file does not need a .exe extension to be executable; it needs execute permission (x, granted with chmod +x) and a recognized format—either compiled machine code or a text script beginning with a shebang line such as #!/usr/bin/env bash. You can still run a non-executable script by passing it to an interpreter (bash script.sh), whereas running ./script.sh requires the x bit.

Why does Linux sometimes refuse to run a freshly downloaded script with “Permission denied” even though its contents are valid?

Downloaded files normally lack the execute permission bit (x). Until you add it with chmod +x—or pass the file to an interpreter like sh—the kernel will not run it directly.

In Linux execve(2), the kernel dispatches executables through registered binfmt_* handlers: binfmt_elf maps PT_LOAD segments, populates the initial stack and auxiliary vector (AT_ENTRY, AT_PHDR), and transfers control to PT_INTERP (ld-linux.so) for dynamically linked binaries; binfmt_script parses #! headers (up to BINPRM_BUF_SIZE) to invoke the specified interpreter; and binfmt_misc routes magic bytes or extensions to user-space runners. Mount-level noexec flags and MAC policies override file mode bits, and Linux ignores setuid/setgid bits on #! scripts.

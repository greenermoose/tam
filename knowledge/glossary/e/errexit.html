Errexit

A POSIX shell option (enabled with set -e) that makes a script exit immediately when a command fails with a nonzero exit status.

Normally, if one step in a shell script fails, the script keeps marching forward and runs the next lines anyway—which can turn a small mistake into a bigger mess. Turning on errexit acts like an emergency stop: as soon as a command fails unexpectedly, the script halts right there.

You enable it with set -e (or set -o errexit) at the top of a script. However, errexit deliberately does not exit when a failing command is part of an if condition, a while/until test, a ! negation, or the left-hand side of && or ||—because those constructs check failure on purpose.

Why doesn’t set -e abort a script when grep -q pattern file returns 1 inside if grep -q pattern file; then ...?

POSIX disables errexit while evaluating the condition of an if statement so scripts can test commands that legitimately return nonzero statuses without aborting.

POSIX errexit has subtle suppression and scope rules: in a pipeline without pipefail, only the last command’s exit status triggers exit; inside compound commands tested by if, &&, or ||, suppression propagates dynamically into called shell functions, often surprising authors. Moreover, command substitutions in assignments (x=$(failing_cmd)) trigger errexit, whereas local x=$(failing_cmd) in Bash masks the failure because local itself succeeds and returns 0.

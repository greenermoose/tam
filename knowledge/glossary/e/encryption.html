Encryption

The process of scrambling readable data into an unreadable form so that only someone with the right key can decode it.

Encryption works like locking a message inside a strongbox before sending it or storing it on a laptop. Anyone who intercepts the box—or steals the laptop—can see that something is there, but without the matching key they see only meaningless scrambled data.

In everyday Linux use, encryption protects both data at rest (such as LUKS full-disk encryption) and data in transit (such as TLS for HTTPS and SSH for remote shells). Symmetric encryption uses one shared key for speed, while asymmetric (public-key) encryption uses a public/private key pair to exchange keys or verify identity without sharing secrets beforehand.

If encryption keeps data confidential, why do modern protocols also need authentication or integrity checks?

Plain encryption hides the content, but without integrity protection an attacker could flip bits in transit and corrupt or alter the decrypted message undetected.

Modern encryption relies on AEAD (Authenticated Encryption with Associated Data) constructions such as AES-GCM or ChaCha20-Poly1305, which bind confidentiality to a cryptographic MAC tag to defeat chosen-ciphertext and padding-oracle attacks. Security depends critically on non-repeating nonces/IVs, proper key derivation (e.g., Argon2id for passphrases, HKDF for session keys), and side-channel-resistant constant-time implementations.

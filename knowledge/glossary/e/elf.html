ELF (Executable and Linkable Format)

ELF (Executable and Linkable Format) is the standard binary file format on Linux for executables, shared libraries (.so), relocatable object files, and core dumps.

ELF is the standard “shipping container” Linux uses for compiled programs. Whether a file is a runnable app or a shared library of helper code, packing it in ELF format lets Linux check which processor it was built for and place each piece of code and data into memory before running it.

Compiler object files (.o), executables, and shared libraries (.so) are all ELF files; you can inspect their architecture, dynamic dependencies, and sections with file, readelf -h, objdump -d, and ldd. Dynamically linked binaries point to a runtime loader such as /lib64/ld-linux-x86-64.so.2, whereas statically linked binaries embed all needed code directly.

What happens if you try to run an ELF binary compiled for ARM64 on an x86-64 Linux PC (without emulation)?

The kernel reads the ELF header’s machine field, sees it does not match the host CPU architecture, and refuses to execute it with an “Exec format error.”

Defined by the System V ABI, an ELF file begins with a 16-byte e_ident (magic 0x7F 'E' 'L' 'F', 32/64-bit class, endianness, ABI) and exposes two complementary views: Program Headers (PT_LOAD, PT_INTERP, PT_DYNAMIC, PT_GNU_STACK, PT_GNU_RELRO) consumed by the kernel binfmt_elf loader and ld.so, and Section Headers (.text, .rodata, .data, .bss, .plt, .got) used by linkers and debuggers (and strippable at runtime). Modern hardening builds position-independent executables (ET_DYN) for ASLR and pair BIND_NOW with full RELRO to make the GOT read-only after relocation.

Endianness

Endianness says which byte of a multi-byte number comes first in memory or in a file.

Memory is numbered one byte at a time. A number wider than one byte must be split across several addresses. Little-endian puts the smallest part first; big-endian puts the largest part first. Both can store the same number.

The 32-bit value 0x12345678 is stored as 78 56 34 12 in little-endian order and 12 34 56 78 in big-endian order. Most desktop and server processors use little-endian order. Network protocols have traditionally used big-endian order, called network byte order, so data must be converted when it crosses that boundary. Byte order does not affect the order of bits inside one byte.

A file contains 78 56 34 12. What could the 32-bit value be?

It is 0x12345678 if written little-endian and 0x78563412 if written big-endian. The bytes alone cannot decide; the file format must state the order.

Endianness applies whenever data leaves the processor: file formats, network packets, device registers and debug buffers. Conversion routines such as htons and ntohl handle 16- and 32-bit network order. Mixed-endian formats exist in older architectures. A field smaller than a byte, a text string or a sequence of unrelated bytes has no endianness, even though it may sit inside a wider word. Use explicit fixed-width unsigned types and byte-array views when inspecting raw data; relying on host layout makes formats non-portable.

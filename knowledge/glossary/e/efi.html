Guide / Glossary A–Z / Terms beginning with E / EFI (Extensible Firmware Interface)

EFI (Extensible Firmware Interface) is the programmable firmware interface specification that replaced the legacy PC BIOS.

EFI is the modern startup manager built into your computer’s motherboard. Old BIOS firmware could only run tiny, rigid startup instructions from the very beginning of a disk; EFI works more like a mini-operating system that can read files, check hardware, and launch your main operating system cleanly.

Now standardized as UEFI, EFI provides Boot Services (loading .efi boot loaders from an EFI System Partition) and Runtime Services (managing NVRAM boot entries and system resets). On Linux, you can inspect firmware variables under /sys/firmware/efi/efivars and update boot order with efibootmgr—a sharp contrast to legacy BIOS, which relied on a 512-byte MBR boot sector in 16-bit real mode.

What changes when the Linux kernel calls ExitBootServices() during startup?

Firmware shuts down its Boot Services and releases boot-time memory to the kernel; afterward, only EFI Runtime Services (such as NVRAM variable access and reboot) remain available.

EFI/UEFI exposes an EFI_SYSTEM_TABLE of Handles and GUID-identified Protocols and executes PE32+ (PE/COFF) images marked with subsystem EFI_IMAGE_SUBSYSTEM_EFI_APPLICATION. The kernel’s CONFIG_EFI_STUB lets Linux itself act as an EFI executable, validating the memory map key at ExitBootServices() and accessing NVRAM variables tagged with NON_VOLATILE, BOOTSERVICE_ACCESS, and RUNTIME_ACCESS attributes.

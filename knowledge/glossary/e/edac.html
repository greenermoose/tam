EDAC (Error Detection and Correction)

EDAC (Error Detection and Correction) is the Linux kernel subsystem that monitors, logs, and reports hardware memory (ECC) and bus errors.

Electrical noise or stray radiation can occasionally flip a 0 to a 1 in computer memory. Server and workstation ECC memory can spot and fix small flips automatically, and EDAC is the Linux system that keeps a log of those fixes—warning you if a memory stick is starting to wear out before it causes a crash.

On systems with ECC RAM and a supported driver, Linux exposes per-controller counters under /sys/devices/system/edac/mc/, separating corrected errors (ce_count) from uncorrected errors (ue_count). Corrected errors let the system keep running, while uncorrected errors indicate corrupted data that may trigger a kernel panic or machine check.

If ECC memory fixes corrected errors automatically, why does EDAC still count and log them?

A rising corrected-error rate is an early warning sign of a failing DIMM or bad slot; replacing the module early prevents an eventual multi-bit uncorrected error that ECC cannot repair.

The drivers/edac/ framework tracks SECDED (Single Error Correction, Double Error Detection) and Chipkill/SDDC events from integrated memory controllers, hardware scrubbers, or firmware-first ACPI APEI/GHES (ghes_edac) CPER records. Note that when firmware claims Machine Check Exceptions via APEI, native IMC EDAC drivers may be blocked or suppressed to avoid duplicate reporting, and user-space daemons such as rasdaemon map mc/csrow/channel counters back to physical DIMM silk-screen labels.

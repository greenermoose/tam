Environment variable

A named text value stored in a process’s environment and passed down from parent processes to their children.

Think of environment variables as sticky notes attached to a running program when it starts. Notes like HOME (where your personal folder is) or LANG (which language to use) let every program you launch pick up your basic preferences automatically without asking each time.

In a shell, variables set with export NAME=value become part of the environment inherited by commands you run, whereas plain shell variables stay local to that shell. Because inheritance flows strictly downward from parent to child, a child script cannot change an environment variable in its parent shell.

Why can’t a script you run normally change your current shell’s PATH?

A script runs in a child process that receives a copy of the parent’s environment; modifying that copy affects only the child and its own descendants, unless you source the script in the current shell.

At the POSIX/Linux ABI level, the environment is an array of NUL-terminated NAME=VALUE strings passed via execve(2) (envp), mapped onto the initial user stack above argv and exposed in C via extern char **environ and getenv(3). In multi-threaded programs, setenv(3)/putenv(3) are not thread-safe against concurrent getenv(3) calls, and environ shares the per-process ARG_MAX limit with command-line arguments.

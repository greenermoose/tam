Unicode

The universal text standard that assigns a unique number to every written character, symbol, and emoji across the world’s writing systems.

Early computers only agreed on numbers for English letters and a few punctuation marks, so opening a document written in another language often turned text into garbled symbols. Unicode solves this by giving every character—from Latin and Cyrillic letters to Japanese kanji, math symbols, and emoji—its own permanent ID number. Because every device uses the same master catalog, text looks the same whether it is read on a phone, a web browser, or a Linux terminal.

Unicode separates two ideas that are easy to confuse: a code point (an abstract number written like U+0041 for A or U+1F427 for 🐧) and a character encoding (how that number is stored as bytes, most commonly UTF-8 on Linux and the web). A single visible character—called a grapheme cluster—can also be built from multiple code points, such as a base letter plus a combining accent or an emoji modified by a skin-tone code point.

Why does counting characters or moving a cursor over é sometimes treat it as two units instead of one?

Because é can be represented either as one precomposed code point (U+00E9) or as e (U+0065) followed by a combining acute accent (U+0301). Naive code-point counting treats the second form as two characters even though a reader sees one glyph.

Maintained by the Unicode Consortium and synchronized with ISO/IEC 10646, Unicode defines 1,114,112 code points (U+0000–U+10FFFF) organized into 17 planes (Plane 0 BMP plus 16 supplementary planes), excluding the surrogate range 0xD800–0xDFFF reserved for UTF-16. Beyond code-point assignment, the standard specifies normalization forms (NFC, NFD, NFKC, NFKD) for canonical and compatibility equivalence, the Bidirectional Algorithm (UBA) for mixed RTL/LTR scripts, and UAX #29 grapheme cluster segmentation. Filesystems and protocols vary in handling: Linux VFS treats pathnames as opaque byte sequences (typically UTF-8 without normalization), whereas macOS HFS+/APFS have different normalization behaviors that can cause cross-platform filename collisions.

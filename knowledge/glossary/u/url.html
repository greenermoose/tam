URL (Uniform Resource Locator)

A standardized address—such as https://example.com/guide—that specifies both where a resource lives and how to retrieve it.

A URL is the street address of a web page, file, or other resource. Just as a postal address tells a carrier the country, city, and house number, a URL tells your browser or app which protocol to use (like https://), which server to contact, and which specific page or file to open.

A URL has distinct parts: a scheme (https, file, ssh), an authority (optional user, host, and port like example.com:8443), a path (/docs/index.html), an optional query (?q=linux), and a client-side fragment (#section). Characters with special meaning—like spaces or &—must be percent-encoded (such as %20) so tools like curl and web servers do not misread them.

Why is the #section fragment at the end of a URL not sent to the web server in an HTTP request?

By specification, fragments are resolved locally by the client (such as scrolling a browser to a heading ID). Stripping the fragment before sending the HTTP request path avoids leaking client-side navigation state and keeps server caching uniform.

Formalized in RFC 3986 (syntax) and the WHATWG URL Standard (browser parsing and IDNA Punycode host encoding), a URL is a locator subset of URI. Subtle parser differentials between RFC 3986 and WHATWG—such as handling of backslashes, multiple slashes, IPv4-mapped addresses, or userinfo (user:pass@)—are a frequent source of SSRF and open-redirect vulnerabilities when a validator and a fetcher use different URL parsers. Note also that query strings follow application/x-www-form-urlencoded rules (+ as space) in HTML forms rather than strict RFC 3986 percent-encoding.

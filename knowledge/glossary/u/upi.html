UPI (Ultra Path Interconnect)

Intel’s high-speed processor-to-processor interconnect used in multi-socket servers to let separate CPUs share memory coherently.

Large server motherboards sometimes hold two or four physical processor chips instead of one. If a program running on CPU 1 needs data stored in memory wired to CPU 2, the two chips need a fast private bridge to talk and keep their caches in sync. UPI is that bridge on modern Intel servers, replacing the older QPI link.

In multi-socket Xeon systems, each CPU socket has its own local DRAM channels, creating a Non-Uniform Memory Access (NUMA) topology; UPI connects the sockets so any core can address any memory, at slightly higher latency across the link. On Linux, you can inspect the resulting NUMA nodes and cross-socket distances with numactl --hardware or lscpu. Analogous to AMD’s Infinity Fabric across sockets, UPI bandwidth matters for database and virtualization workloads that span sockets.

Why does pinning a memory-intensive workload to one NUMA node often improve performance on a dual-socket UPI server?

Accessing DRAM attached to the remote socket must traverse the UPI interconnect, adding latency and consuming UPI bandwidth. Keeping threads and their memory allocations on the same socket avoids cross-UPI traffic.

Introduced with Skylake-SP Xeon Scalable processors to succeed QPI, Intel UPI is a point-to-point, directory-assisted cache-coherent interconnect operating at 10.4 GT/s through 16–20+ GT/s on newer generations over 20 data lanes per link direction, typically with 2 to 6 UPI links per socket. UPI uses flit-based packet framing and snoop/directory-based MESIF-family coherence protocols; on 4- and 8-socket topologies, partial-mesh routing introduces multi-hop latency penalties (exposed in the ACPI SLIT table) and makes UPI link saturation a primary bottleneck when uncore traffic is poorly localized.

Userspace

Userspace (or user space) is the part of an operating system where ordinary applications, shells, and libraries run, outside the privileged OS kernel.

Think of your computer like a restaurant: the kernel is the kitchen where dangerous equipment, sharp knives, and food safety are strictly controlled, while userspace is the dining room where guests sit. Every app you open—your web browser, text editor, or music player—runs in userspace. If an app crashes, it is like a guest spilling a drink: annoying, but the kitchen keeps running and other tables are unaffected.

In Linux, every regular process—from bash and systemd services to graphical apps—runs in userspace without direct access to hardware registers or other processes’ memory. When a program needs to read a file, open a network socket, or allocate memory, it asks the kernel through system calls (often wrapped by C libraries like glibc). You can watch those boundary crossings in action using strace on any command. If a userspace process crashes with a segmentation fault, only that process terminates; by contrast, a bug inside the kernel triggers a kernel panic and halts the whole machine.

Why can’t a normal userspace program read another user’s process memory or write straight to a disk sector?

The CPU and memory management unit enforce hardware isolation between unprivileged userspace and the privileged kernel, so every cross-process or hardware access must pass through kernel system calls that check permissions first.

Userspace executes at unprivileged CPU privilege levels (x86-64 Ring 3; ARM64 EL0) with per-process virtual address spaces enforced by the MMU and page tables, isolating processes from each other and from kernel-space mappings (Ring 0 / EL1). Crossing into the kernel occurs via synchronous traps (syscall/svc), hardware interrupts, or page faults, incurring context/TLB overhead—mitigated on Linux by KPTI/PCID and vDSO (mapping read-only kernel data like clock_gettime() directly into userspace to avoid trap latency). Trade-offs center on safety versus overhead: moving drivers or filesystems into userspace (FUSE, VFIO, DPDK, io_uring) improves fault isolation and debuggability at the cost of IPC/copying or polling CPU usage.

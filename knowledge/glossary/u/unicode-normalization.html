Guide / Glossary A–Z / Terms beginning with U / Unicode normalization

Unicode normalization rewrites text so sequences with the same visible meaning get the same code-point form.

The same accented letter can be stored as one code point or as a letter plus a separate accent. Both look identical, but a computer comparing them byte by byte sees two different strings. Normalization picks one agreed form so text compares and searches consistently.

Unicode defines four forms: NFC and NFD use canonical equivalence, while NFKC and NFKD also apply compatibility conversions that can change characters, for example turning a ligature into two letters. NFC composes base characters with combining marks; NFD decomposes them. Search, filenames and identifiers should choose a form deliberately and document it.

Canonical ordering reorders combining marks by canonical combining class before composition, so different input orders produce the same form. Composition exclusions and singleton decompositions prevent round-trip ambiguity, and Hangul composition is algorithmic rather than table-driven. Normalization applies to code points, not to database normalization of tables, and Linux filesystems generally store pathname bytes without normalizing them.

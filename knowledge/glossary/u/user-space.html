User space

User space is the unprivileged part of an operating system where ordinary programs run, separate from the protected kernel space.

Think of user space as the public rooms of a building and kernel space as the locked control room. Your web browser, editor, terminal, and games run in user space. They can do useful work, but they cannot directly control hardware or other programs' memory. If a user-space program crashes, it usually affects only that program, not the whole computer.

In Linux, processes such as shells, desktop apps, and services run in user space with limited privileges. When they need to read a file, send network data, or create a process, they make system calls into the kernel. This boundary makes user-space programming safer and easier to debug than kernel-space programming: tools like debuggers, sanitizers, and normal process isolation work in user space, while kernel bugs can panic or destabilize the whole system. The term userspace is often used for the same idea.

Why do ordinary programs run in user space instead of kernel space?

User space limits what a program can do directly, so the kernel can enforce permissions, isolate processes, and protect hardware; this prevents most application bugs from taking down the whole system.

User-space code executes at unprivileged CPU privilege levels (for example, x86-64 Ring 3 or ARM64 EL0) in per-process virtual address spaces managed by the kernel and MMU. Transitions to kernel space occur through system calls, page faults, and interrupts. User-space programming trades direct hardware access for isolation and portability; mechanisms such as FUSE, BPF, and io_uring move selected functionality across the boundary with different safety and performance costs.

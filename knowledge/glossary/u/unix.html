Unix

An influential 1970s operating system created at Bell Labs whose design of files, pipes, and small composable tools shaped Linux, BSD, and macOS.

Long before modern desktops and smartphones, researchers at Bell Labs built an operating system called Unix around a simple idea: keep tools small, let them pass text to each other like water through pipes, and treat almost everything—documents, folders, and even hardware devices—as a file. Even though Linux was written from scratch later on, it copied those same building blocks so people and programs could feel at home on both.

Modern systems such as Linux, FreeBSD, and macOS are “Unix-like” because they follow POSIX and Single UNIX Specification conventions inherited from Unix: hierarchical directories rooted at /, standard input/output/error streams, shell pipelines (|), and user/group file permissions. Notice that Linux is a clean-room kernel and is not trademark-certified as “UNIX,” whereas macOS is BSD-derived and POSIX-certified.

Why can a shell pipeline written on Linux often run almost unchanged on BSD or macOS?

Because all three implement the POSIX user-space model inherited from Unix—standard utilities, text streams, exit codes, and filesystem paths behave consistently across Unix-like systems.

Developed by Ken Thompson and Dennis Ritchie at AT&T Bell Labs and rewritten in C (Version 4, 1973) for portability across architectures, Unix established the process and VFS abstractions still central to modern kernels: fork(2)/execve(2) process creation, file-descriptor tables shared across pipe(2), TTY line disciplines, and unified byte-stream I/O (open/read/write/close). The split between AT&T System V and UC Berkeley’s BSD drove the POSIX (IEEE Std 1003) standardization effort, though modern Linux diverges in areas such as clone(2), procfs/sysfs, and netlink sockets where “everything is a file” no longer holds strictly.

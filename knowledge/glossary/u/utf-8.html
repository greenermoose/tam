Guide / Glossary A–Z / Terms beginning with U / UTF-8 (Unicode Transformation Format, 8-bit)

UTF-8 (Unicode Transformation Format, 8-bit) is the standard way computers store and exchange Unicode text as bytes.

Computers store numbers, not letters. Early systems used a small table called ASCII that covered English letters and basic punctuation, which broke as soon as someone typed accented letters, Chinese characters or emoji. UTF-8 gives every character a byte pattern while keeping plain English text identical to ASCII.

UTF-8 is a variable-width encoding: a code point takes one to four bytes. Plain ASCII takes one byte with the same values as before, accented Latin usually takes two, CJK characters three and emoji four. On Linux it is the default locale encoding, used in filenames, terminals and configuration files; garbled text appears when software decodes those bytes with the wrong encoding.

Why does counting bytes in a UTF-8 string not always match the number of visible characters?

Non-ASCII characters use two to four bytes, and some visible glyphs combine several code points.

UTF-8 encodes Unicode scalar values into one to four bytes using self-synchronizing prefix bits: 0xxxxxxx, 110xxxxx, 1110xxxx and 11110xxx followed by 10xxxxxx continuation bytes. Decoders can resynchronize mid-stream, and byte-wise comparison preserves code-point order. Overlong encodings must be rejected for security, unpaired surrogates are invalid in strict UTF-8, and a leading byte-order mark can break script shebangs.

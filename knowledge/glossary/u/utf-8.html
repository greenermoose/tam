Guide / Glossary A–Z / Terms beginning with U / UTF-8 (Unicode Transformation Format, 8-bit)

UTF-8 (Unicode Transformation Format, 8-bit) is the standard way computers store and exchange Unicode text as sequences of bytes.

Computers only store numbers, not letters. Early systems used a small table called ASCII that only covered English letters, numbers, and basic punctuation, which broke whenever someone typed accented letters, Chinese characters, or emoji. UTF-8 solves this by giving every character in the world’s writing systems a byte pattern while keeping plain English files identical to old ASCII—so both old and new software can read basic text without garbled symbols.

UTF-8 is a variable-width encoding: every Unicode code point takes 1 to 4 bytes. Plain ASCII characters (U+0000 to U+007F) take 1 byte with the exact same byte values as ASCII, accented Latin characters usually take 2 bytes, CJK characters take 3 bytes, and emoji take 4 bytes. On Linux, UTF-8 is the default locale encoding (LANG=en_US.UTF-8), used in filenames, terminals, and config files. You can inspect raw UTF-8 bytes with xxd or convert legacy files (like ISO-8859-1 or Windows-1252) with iconv—garbled text (“mojibake”) happens when software decodes UTF-8 bytes using the wrong encoding.

Why does counting bytes in a UTF-8 string not always match the number of visible characters?

Non-ASCII characters use 2 to 4 bytes each, and some visible glyphs combine multiple code points (such as a base letter plus an accent or an emoji with a skin-tone modifier), so byte length is often larger than character or grapheme count.

UTF-8 encodes Unicode scalar values (U+0000–U+10FFFF, excluding UTF-16 surrogates 0xD800–0xDFFF) into 1–4 bytes using self-synchronizing prefix bits: 0xxxxxxx (1-byte ASCII), 110xxxxx (2-byte), 1110xxxx (3-byte), 11110xxx (4-byte), followed by 10xxxxxx continuation bytes. Because continuation bytes always start with 10 and never appear as leading bytes or ASCII, a decoder can resynchronize mid-stream and byte-wise strcmp preserves code-point order without NUL bytes inside multi-byte sequences. Key failure modes and edge cases include overlong encodings (security vulnerabilities where / is encoded in 2 bytes to bypass path checks; decoders must reject them), unpaired surrogates (invalid in strict UTF-8, vs. WTF-8/CESU-8), and a leading BOM (EF BB BF) breaking shebangs (#!) or shell scripts.

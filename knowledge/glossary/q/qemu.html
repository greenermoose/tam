Guide / Glossary A–Z / Terms beginning with Q / QEMU (Quick Emulator)

QEMU (Quick Emulator) is an open-source machine emulator and virtualizer that lets you run full operating systems or individual programs inside virtual hardware on Linux and other hosts.

QEMU lets you run a “computer inside your computer.” You can use it to boot another operating system—like testing a Linux distribution or running Windows—in a window without erasing your real hard drive, or even to pretend your laptop is a completely different kind of chip, such as a Raspberry Pi’s ARM processor.

QEMU works in two main modes: when the guest matches your host CPU (e.g., x86_64 on x86_64), pairing QEMU with Linux’s KVM (-enable-kvm) runs guest instructions directly on the physical CPU at near-native speed; when architectures differ (e.g., running ARM64 or RISC-V guests on x86_64), QEMU’s TCG (Tiny Code Generator) translates instructions in software, which is much slower. Tools like virt-manager and libvirt manage QEMU VMs under the hood.

Check: you launch an x86_64 VM with qemu-system-x86_64 and it feels sluggish until you add -enable-kvm. Why?

Without -enable-kvm, QEMU defaults to software CPU emulation (TCG), translating every guest instruction in userspace instead of letting the kernel’s KVM module execute guest code directly on your hardware virtualization extensions.

In KVM-accelerated mode, QEMU acts as the userspace VMM: it allocates guest physical memory, runs vCPU threads calling ioctl(KVM_RUN), and emulates platform devices (PCIe, APIC, USB, or paravirtualized virtio-blk/virtio-net/virtio-gpu rings) upon VM exits. In TCG mode, it performs dynamic binary translation from guest basic blocks to host native code (supporting both full-system qemu-system-* and Linux syscall-forwarding user-mode qemu-<arch> via binfmt_misc). Storage typically uses qcow2 images (copy-on-write, snapshots, backing files), and live migration or automation is driven over the JSON-based QMP (QEMU Machine Protocol) socket.

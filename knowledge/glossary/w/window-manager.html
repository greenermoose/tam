Window manager

A window manager is the desktop software that controls where application windows appear on screen, how they are sized, and which window receives your keyboard and mouse input.

If open apps are papers on a desk, the window manager is the organizer that decides whether they overlap in piles or sit neatly side by side, and lets you move, resize, focus, or close them.

Linux window managers generally follow either a floating/stacking model (windows overlap freely with titlebars and drag handles, as in GNOME or Xfce) or a tiling model (windows automatically divide the screen without overlapping, driven largely by shortcuts such as Meta + arrow keys, as in Sway or i3). Knowing which model you use explains why windows either stack or snap into grids on launch.

What is the main difference between a floating window manager and a tiling window manager?

A floating window manager lets windows overlap at arbitrary positions, while a tiling window manager automatically arranges windows into non-overlapping regions to fill the screen.

Architecture differs sharply between X11 and Wayland. On X11, a window manager (such as i3 or Openbox) is a separate X client that selects SubstructureRedirectMask on the root window to intercept MapRequest and ConfigureRequest events, reparents frames for decorations, and coordinates via ICCCM/EWMH—separate from an optional compositor (picom). On Wayland, window management, display serving, and compositing are unified in one process (such as Sway, Mutter, or KWin) that owns DRM/KMS outputs, enforces xdg-shell surface lifecycle and focus policies, and composites client buffers directly.

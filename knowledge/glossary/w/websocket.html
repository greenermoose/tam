WebSocket

WebSocket is a web protocol that keeps one connection open so a browser and a server can both send messages at any time.

Ordinary web requests are like sending letters one at a time. A WebSocket is a phone call: once it is open, either side can speak without hanging up.

A client opens ws:// or wss:// and listens for message events. Applications add reconnects and heartbeat messages so a dropped connection is noticed.

Why is WebSocket useful for a chat page but not for a static article?

Chat needs the server to push new messages at unpredictable times. A static article is a single cacheable HTTP reply, where ordinary HTTP is simpler and works better with caches.

A WebSocket starts as an HTTP upgrade request, then carries framed messages over TCP with wss adding TLS. Proxies and load balancers may close idle connections, so keepalives and reconnect backoff are required. It does not replace HTTP for ordinary cacheable reads.

Guide / Glossary A–Z / Terms beginning with W / WAW (Write-After-Write hazard)

A WAW (Write-After-Write) hazard is a CPU pipeline conflict that occurs when two instructions write to the same register and could finish out of order.

Imagine two people updating the same box on a whiteboard: the first writes a slow calculation, and the second writes a newer number right after. If the second person finishes first and the first person writes later, the old number ends up in the box. Modern CPUs prevent this mix-up by giving each write its own temporary scratchpad.

WAW is a false (name) dependency: the second instruction does not actually need the result of the first, they just happen to name the same architectural register. Out-of-order CPUs eliminate both WAW and WAR (Write-After-Read) hazards through hardware register renaming, mapping a small set of ISA register names onto a much larger pool of internal physical registers.

Why is a WAW hazard called a “false” dependency compared to a Read-After-Write (RAW) hazard?

In a WAW hazard, no data flows from the first write to the second—the conflict exists only because both instructions reuse the same register name, so renaming the destination removes it.

Formally, an output dependence exists when instruction I2 writes architectural register R after I1 in program order without I2 reading I1’s value; executing I2’s writeback before I1’s would leave R with stale state. Out-of-order cores using Tomasulo’s algorithm or a Reorder Buffer (ROB) with a Physical Register File (PRF) resolve WAW dynamically in the rename stage: the Register Alias Table (RAT) assigns each destination write a fresh physical register tag, while in-order retirement updates the committed architectural map and frees the overwritten physical register—preserving both parallel execution and precise exception recovery.

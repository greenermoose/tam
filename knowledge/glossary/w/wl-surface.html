Guide / Glossary A–Z / Terms beginning with W / wl_surface

A wl_surface is the Wayland object that represents an application's drawable area.

An application paints a picture into memory and attaches it to its surface. When it commits the surface, the compositor knows the picture is ready to place on screen.

A surface by itself is just a rectangle for pixels. A role such as xdg-shell makes it an ordinary window or popup. Buffers may come from shared memory or GPU memory through DMA-BUF.

Surface state is double-buffered: attached buffers, damage, transforms, scale and opaque region are pending until a commit. The compositor applies that state atomically at frame presentation and sends release events when a buffer is no longer in use. Protocol extensions add subsurfaces, viewports and frame callbacks.

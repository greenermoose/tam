Wayland

Wayland is the modern display protocol that Linux desktops use to let applications draw windows and receive input through a compositor.

Wayland is a set of rules that lets each app draw its own window (called a surface) and hand it to a central coordinator called a compositor. The compositor arranges those windows on your screen and sends keyboard and mouse actions to the right app. Tamlinux uses Wayland through its compositor.

Wayland replaces the older X11 model on most modern Linux desktops. In X11, a separate display server sat between apps and a window manager, and any app could observe global keystrokes or screen contents; under Wayland, the compositor is the display server and isolates each client’s buffers and input. When troubleshooting, you often separate client bugs from compositor extensions for screenshots, panels, or input methods.

Why can’t a regular Wayland app capture the whole screen or read keystrokes meant for another window on its own?

Wayland isolates clients so the compositor controls all surfaces and input routing; global screen capture or shortcuts require explicit compositor-mediated protocols or portals.

Wayland is an asynchronous, object-oriented wire protocol over a Unix domain socket (WAYLAND_DISPLAY) in which a compositor owns DRM/KMS outputs and mediates client surfaces and input seats; Tamlinux sessions use Wayland compositors. Clients allocate shared-memory (wl_shm) or GPU-backed (linux-dmabuf) buffers and apply atomic surface state via wl_surface.commit, while window roles rely on xdg-shell. Extended desktop features—such as layer-shell panels, screencopy, and zwp_text_input—are negotiated as optional protocol globals, with XWayland bridging legacy X11 clients.

Word splitting

Word splitting is the shell step that divides the result of an unquoted expansion into separate words, called fields.

When you write a name in a shell command, spaces usually separate one word from the next. If the name is stored in a variable, the shell first replaces the variable with its value and then looks again for spaces. That second look is word splitting. It is why a file called My notes.txt can turn into two words unless you put quotes around the value. The characters that count as separators come from IFS.

With a POSIX shell, writing $name unquoted lets splitting happen; writing "$name" keeps the whole value as one field. The same rule applies to the result of command substitution and arithmetic expansion. Splitting happens after those expansions and before the shell looks for filename patterns, so an unquoted * in a variable can also match files. Read IFS and splitting for a worked example and the expansion order for why the order matters.

A variable holds two names separated by a space. Why does an unquoted expansion sometimes become two arguments?

The space is a separator from IFS. After the variable is replaced by its value, the splitting step divides the value at that space, so the command receives two arguments instead of one.

Field splitting is applied only to parts of a field that came from an unquoted parameter expansion, command substitution or arithmetic expansion. Literal characters from the original word stay attached to the candidate field. Sequences of IFS white space delimit a field and are discarded; a non-whitespace IFS character delimits a field even when the candidate is empty, which is how empty fields arise. If the whole input is empty or consists only of IFS white space, the result is zero fields. When IFS is null, no splitting occurs but an entirely empty expanded field is removed. The special parameters @ and * have their own rules. See POSIX Shell Command Language section 2.6.5 and Bash manual.

Wildcard

A wildcard is a special placeholder character in a pattern that matches one or more unspecified characters, most commonly used to select groups of files or filter text.

Think of a wildcard like a blank tile in a word game that can stand in for any letters. Typing *.txt is a shortcut for saying “every file whose name ends with .txt” without having to type each filename yourself.

In Linux shells such as Bash and Zsh, wildcards (*, ?, [a-z]) are glob patterns that the shell expands into matching filenames before the command runs. That is why you quote patterns passed to find -name '*.log' or grep: otherwise the shell expands them in the current directory first, and regular expressions use * as a repetition quantifier rather than a standalone filename wildcard.

Why should you quote *.log in find . -name '*.log'?

Without quotes, the shell expands *.log against files in the current directory before find starts, which either searches for the wrong literal names or fails if multiple files match.

POSIX shell globbing (fnmatch) defines * (zero or more non-/ characters), ? (one character), and bracket expressions ([!...]), excluding leading dots unless matched explicitly or via dotglob—distinct from regex syntax where * quantifies the preceding atom. Edge cases include unmatched-glob behavior (passed literally in POSIX sh/Bash unless nullglob or failglob is set, whereas Zsh errors by default) and filenames starting with - being parsed as command flags after expansion unless prefixed with ./* or --.

ARM - Advanced RISC Machines

A family of energy-efficient processor designs (originally Acorn RISC Machines, now stylized Arm) widely used in phones, tablets, single-board computers, and servers.

Most desktop PCs use Intel or AMD chips built for maximum speed when plugged into a wall outlet. Arm chips are designed from the ground up to sip battery power while staying cool, which is why they power almost every smartphone, many tablets, and tiny Linux computers like the Raspberry Pi.

On Linux, “ARM” spans two distinct worlds: older 32-bit chips (often labeled armhf or armv7l in package managers and uname -m) and modern 64-bit chips (arm64 / aarch64). Unlike x86 PCs where one generic kernel image boots almost any motherboard, many Arm boards need a hardware-specific Device Tree Blob (.dtb) so the Linux kernel knows which pins, buses, and peripherals exist on that board.

Why can’t you usually run an amd64 Linux binary directly on a Raspberry Pi without an emulator?

A Raspberry Pi uses an Arm processor whose machine-code instruction set is completely different from x86-64 (amd64), so the CPU cannot decode x86-64 instructions natively.

Arm is a load/store RISC architecture licensed by Arm Ltd as IP cores (Cortex-A/R/M) or architectural licenses (such as Apple Silicon, Ampere, and AWS Graviton), segmented into A-profile (application OS with MMU), R-profile (real-time), and M-profile (microcontrollers). Key traits include a weakly ordered memory model (requiring explicit DMB/DSB/ISB barriers for lock-free concurrency, unlike x86’s stronger TSO), privileged Exception Levels (EL0 user space, EL1 kernel, EL2 hypervisor, EL3 secure monitor/TrustZone), and optional vector extensions (NEON, SVE/SVE2). Created in 1983 as the Acorn RISC Machine and renamed Advanced RISC Machines in 1990, the architecture transitioned from 32-bit AArch32 (ARMv7) to 64-bit AArch64 in ARMv8-A.

Guide / Glossary A–Z / Terms beginning with A / ANV (Intel Vulkan Mesa Driver)

The open-source Mesa graphics driver that implements the Vulkan API for Intel GPUs on Linux.

A graphics driver is the translator between a game or 3D app and your graphics hardware. On Linux, Intel graphics chips use a free, built-in driver package called Mesa. ANV is the specific part of Mesa that translates modern Vulkan graphics commands so an Intel chip can draw them on screen.

Mesa splits Intel’s userspace drivers by API: Iris handles OpenGL, while ANV handles Vulkan. Both sit in userspace and communicate with the Linux kernel’s i915 or newer xe DRM driver. You can verify ANV is active by running vulkaninfo --summary and checking that driverName reports ANV (or Intel open-source Mesa driver) rather than llvmpipe (CPU software rendering).

If a Vulkan app falls back to llvmpipe instead of ANV on an Intel laptop, what is happening?

llvmpipe is Mesa’s CPU software rasterizer; falling back to it means the app could not use the Intel GPU via ANV—for example because the Vulkan ICD JSON is missing, permissions on /dev/dri/renderD* failed, or the GPU generation is unsupported.

ANV is a Vulkan Installable Client Driver (ICD) registered via /usr/share/vulkan/icd.d/intel_icd.*.json targeting Intel Gen7+ (Ivy Bridge) through Arc/Xe2 architectures, lowering SPIR-V through Mesa’s NIR IR and the Intel backend compiler (brw/elk) to EU ISA shaders. In userspace, ANV records GPU command buffers, manages descriptor heaps and pipeline state objects, and submits work to kernel DRM via i915 (DRM_IOCTL_I915_GEM_EXECBUFFER2) or xe (DRM_IOCTL_XE_EXEC with vm_bind explicit virtual memory management and syncobj fences). Because Vulkan shifts synchronization and memory allocation to the application, ANV avoids OpenGL’s implicit global state and hazard-tracking overhead.

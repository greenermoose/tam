ARP (Address Resolution Protocol)

The protocol that finds the hardware address belonging to an IPv4 neighbor on the same network.

An IP address is a number used by the network layer, but an Ethernet frame needs a hardware address to reach the next device on the cable. ARP asks the local network "who has this IP address?" and the owner replies with its hardware address. The answer is kept briefly in a neighbor table so the question does not have to be asked for every packet.

On Linux, ip neigh show displays the neighbor table. An entry such as 192.168.1.1 lladdr 10:0c:6b:20:34:e6 REACHABLE records the learned hardware address and its state. INCOMPLETE means no reply arrived. Only addresses on the local link need ARP; a remote address is reached through the gateway's hardware address.

Why does ARP not find the hardware address of a web server across the internet?

ARP works only on a shared link. Frames to a remote server are addressed to the local gateway, which forwards the packet onward; the server's hardware address is never needed by the sender.

ARP requests are broadcast at the link layer and answered with a unicast ARP reply; the result populates the kernel's neighbour cache, keyed by destination address and output interface. IPv6 replaces ARP with ICMPv6 Neighbor Solicitation and Advertisement under NDP, which also performs duplicate address detection. Gratuitous ARP announcements can update neighbors after a failover, but ARP has no authentication, so an attacker on the link can spoof replies and redirect traffic. Static neighbor entries and dynamic ARP inspection are common defenses.

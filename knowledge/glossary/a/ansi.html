ANSI (American National Standards Institute)

The US standards body (American National Standards Institute) whose early terminal and character standards gave us the “ANSI” names still used in Linux today.

When people say “ANSI” on Linux, they usually mean the hidden text codes that make terminal output colorful or move the cursor around—like green status messages or progress bars that update in place. ANSI is actually the standards group that helped standardize those codes decades ago so different brands of screens and computers could understand the same formatting.

In everyday shell work, you encounter ANSI escape sequences when tools like ls --color, grep --color, or git diff wrap text in ESC [ codes (written \033[ or \e[ in scripts) to set colors or clear lines. Piping colored output into a file or text filter can leave raw escape bytes in the stream, which is why well-behaved CLI tools check isatty() and disable color unless --color=always is passed, or rely on less -R to render colors safely.

Why does piping ls --color=always into grep sometimes fail to match filenames as expected?

With --color=always, ls wraps filenames in invisible ANSI escape sequences such as \e[01;34m, so the raw byte stream contains extra characters around the name unless colors are disabled for non-terminal output.

ANSI coordinates US standards rather than owning terminal protocols today: ANSI X3.4 standardized ASCII (7-bit coded character set), while ANSI X3.64 (1979) adopted ECMA-48 control sequences for video terminals before being withdrawn in 1997 in favor of ECMA-48 / ISO/IEC 6429. Control Sequence Introducer (CSI) sequences begin with 0x1B 0x5B (ESC [) in 7-bit mode or C1 0x9B in 8-bit mode, followed by parameter bytes (0x30–0x3F), intermediate bytes (0x20–0x2F), and a final byte (0x40–0x7E), such as SGR (m) for attributes and 24-bit truecolor (38;2;R;G;B). ANSI X3.159-1989 also standardized C89 (“ANSI C”), later ratified as ISO/IEC 9899:1990.

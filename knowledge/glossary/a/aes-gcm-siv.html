Guide / Glossary A–Z / Terms beginning with A / AES-GCM-SIV

A nonce-misuse-resistant authenticated encryption mode based on AES and GCM-style building blocks.

Many encryption modes become dangerous if the same nonce is accidentally reused with the same key. AES-GCM-SIV is designed to fail more safely in that situation. It still encrypts and checks for tampering, but it reduces the chance that one nonce mistake exposes plaintext or lets attackers forge messages.

AES-GCM-SIV is an AEAD mode specified in RFC 8452. It derives a synthetic IV from the nonce, additional authenticated data, and plaintext before encrypting. That means if a nonce is reused, the result is less catastrophic than in AES-GCM, where nonce reuse can leak the GHASH key and break authenticity. It is not a free pass to ignore nonce discipline: repeated nonce and plaintext pairs still leak equality, and keys must still be managed carefully.

How is AES-GCM-SIV different from AES-GCM?

AES-GCM is very fast but fragile on nonce reuse. AES-GCM-SIV adds synthetic-IV derivation so accidental nonce reuse is much less damaging, while keeping authenticated encryption and good performance.

RFC 8452 defines AES-GCM-SIV as a nonce-misuse-resistant AEAD using POLYVAL (a GF(2^128) universal hash related to GHASH) and AES-CTR with a synthetic tag-derived IV. The construction provides IND-CPA and INT-CTXT security under the usual assumptions when nonces are unique, and degrades more gracefully than AES-GCM under nonce reuse: it preserves confidentiality except for revealing equality of (nonce, AAD, plaintext) tuples and avoids the universal forgery break caused by GCM's GHASH subkey recovery. It remains sensitive to key misuse and is not a substitute for proper nonce generation in high-volume systems.

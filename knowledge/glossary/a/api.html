Guide / Glossary A–Z / Terms beginning with A / API - Application Programming Interface

A defined contract of functions, data structures, and rules that lets one piece of software talk to another.

Think of an API like a restaurant menu. You do not need to walk into the kitchen and know how the stove works; you just order from the list of dishes using the exact names on the menu, and the kitchen hands back your food. In the same way, an API lets one program ask another program or the operating system to do a job without knowing its inner code.

On Linux, you encounter APIs at several layers: C programs call the POSIX/libc API (functions like open() and read()), GUI apps call toolkit APIs (GTK or Qt), and web clients call HTTP/REST APIs. A crucial distinction during library upgrades is that source-level compatibility (the API—function names and argument types) can remain intact even when binary compatibility breaks, requiring programs to be recompiled against the new headers.

Why might a compiled program fail to run after a shared library upgrade even though the library’s source code API did not change?

The binary layout (ABI)—such as struct field offsets, enum sizes, or symbol versions—can change without altering the source-level API, breaking already-compiled binaries until they are rebuilt.

An API defines a source-level syntactic and semantic contract—function signatures, type definitions, error conventions, ownership/lifetime invariants, and thread-safety guarantees—whereas an ABI (Application Binary Interface) fixes the compiled machine-level representation (calling conventions, struct padding/alignment, vtable layout, name mangling, and ELF symbol versioning). In Linux user space, libraries like glibc maintain backward ABI compatibility across releases via .symver versioned symbols so older binaries bind to legacy entry points while new compilations link against updated ones. By contrast, the Linux kernel guarantees a stable user-space syscall ABI (uapi) while intentionally offering no stable internal kernel module API or ABI across releases.

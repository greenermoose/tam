Guide / Glossary A–Z / Terms beginning with A / Avahi

The Linux daemon and tools that publish and discover services on a local network without a central server.

Avahi is the program that lets a Linux computer call out what it offers and listen for what other devices offer. A print dialog can show a nearby printer because the printer announced itself and Avahi received the announcement. It works with Bonjour, the Apple name for the same idea, so devices from different makers can find each other.

Avahi runs as avahi-daemon and is used through commands such as avahi-browse, avahi-resolve and avahi-publish. Browse a service type with avahi-browse _ipp._tcp -t -r -p; the + lines announce found instances and the = lines give host, address and port. Static services can be published from XML files under /etc/avahi/services/. A firewall must allow UDP 5353 for discovery to work across the local network.

Why can a service appear twice, once on a physical interface and once on loopback?

Avahi listens on several interfaces. It receives its own announcement both on the wired interface and through lo, so a parsable browse shows two records with different source addresses.

Avahi implements mDNS and DNS-SD. The daemon owns the multicast socket on UDP 5353, performs conflict resolution for unique records, and exposes browsing and publishing over D-Bus. avahi-daemon.conf controls host-name, domain-name, use-ipv4, use-ipv6, allow-interfaces, deny-interfaces, enable-dbus, the publish-* switches and enable-wide-area. Host name resolution is a separate matter: applications reach .local names through a Name Service Switch module such as nss-mdns, not through the daemon directly. mDNS has no authentication, so it must not be treated as a security boundary.

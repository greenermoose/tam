Argument

A value or piece of information—such as a filename, number, or text string—passed to a command or function so it knows what to act on.

When you tell someone “open the door,” “the door” is the thing you want them to act on. In the same way, when you type a command in a terminal, the command is the action and the argument is the target—like giving ls a folder name so it knows which folder to list.

In a shell command like cp report.txt backup/, cp is the command, while report.txt and backup/ are its two positional arguments. Flags such as -r or --verbose are options that modify behavior, though at the OS level they are passed as argument strings too. Watch out for spaces: cat my notes.txt passes two arguments (my and notes.txt), whereas cat "my notes.txt" passes one argument containing a space.

Why does rm my file.txt fail or delete the wrong files compared to rm "my file.txt"?

Without quotes, the shell splits on whitespace and passes two separate arguments (my and file.txt) to rm; quotes keep the filename together as a single argument.

When a Unix shell executes a command, it performs expansion and word splitting according to IFS (respecting single quotes, double quotes, and backslash escapes) and invokes execve(pathname, argv, envp) with a NULL-terminated array of C strings (argv[0..argc-1]), where argc is the argument count and argv[0] is conventionally the program name. Kernel limits on combined argv and envp size are exposed via ARG_MAX (raising E2BIG when exceeded). Filenames beginning with - can be misinterpreted as options by getopt unless separated with -- (end-of-options marker) or prefixed with ./.

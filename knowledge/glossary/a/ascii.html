ASCII - American Standard Code for Information Interchange

A foundational seven-bit character encoding that assigns numbers 0 through 127 to basic English letters, digits, punctuation, and control codes.

Computers only store numbers, not letters. ASCII is like a shared numbered chart where everyone agrees that 65 means “A”, 97 means “a”, and 32 means a space. Even though modern computers support thousands of international characters and emojis, they still keep ASCII’s original numbering at the start so older text files and programs continue to work.

In Linux terminals and configuration files, plain ASCII (bytes 0x00–0x7F) is valid UTF-8 byte-for-byte, which is why tools like grep, shell scripts, and C programs handle English text seamlessly. Control codes (0x00–0x1F and 0x7F) don’t print symbols; instead, they trigger actions such as newline (0x0A), carriage return (0x0D), or interrupt (Ctrl+C, 0x03).

Why does a pure ASCII file automatically work when a Linux program expects UTF-8?

UTF-8 was designed so that code points 0–127 encode as identical single bytes (with the high bit set to 0), making every valid ASCII byte stream valid UTF-8 without conversion.

Standardized as ANSI X3.4 (and ISO/IEC 646 IRV), 7-bit ASCII reserves 0x00–0x1F and 0x7F for C0 control characters and 0x20–0x7E for printable glyphs. Historically, the unused eighth bit was co-opted for parity checking or incompatible 8-bit code pages (e.g., ISO-8859-1, CP437), causing mojibake across systems. UTF-8 resolves this by preserving 0x00–0x7F as self-synchronizing 1-byte sequences while using high-bit-set lead/continuation bytes (0x80–0xF4) for U+0080–U+10FFFF; note that raw 8-bit legacy files containing bytes >= 0x80 are not ASCII and will fail strict UTF-8 validation.

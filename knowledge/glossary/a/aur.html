AUR (Arch User Repository)

A community-maintained repository of PKGBUILD build scripts for installing extra software not included in Arch Linux’s official repositories.

Arch Linux keeps its main software catalog lean, so many niche or third-party apps aren’t in the official store. The AUR is a community bulletin board where users share step-by-step build recipes so others can compile and package those extra programs on their own computer.

Unlike official Arch packages (which are pre-built and signed by trusted maintainers), AUR entries are user-submitted PKGBUILD scripts built locally with makepkg and installed with pacman -U. Because anyone can upload a PKGBUILD, you should always read the script before building—even when using an AUR helper like yay or paru—to verify where it downloads sources and what commands it runs.

Why is installing from the AUR riskier than installing from Arch’s official repositories?

Official packages are pre-built and cryptographically signed by Arch maintainers, whereas AUR PKGBUILDs are unreviewed community scripts that execute on your machine during makepkg.

Each AUR package is a Git repository containing a PKGBUILD and generated .SRCINFO metadata (consumed by AUR RPC APIs and helpers without executing Bash). Running makepkg sources the PKGBUILD in a subshell—executing prepare(), build(), check(), and package()—meaning malicious or broken scripts run arbitrary code under the invoking user before pacman ever touches /usr. Additionally, because AUR packages are not rebuilt automatically on official library soname bumps, pacman -Syu can leave AUR binaries broken until rebuilt against the new shared libraries.

Guide / Glossary A–Z / Terms beginning with A / AddressSanitizer (ASan)

A fast compiler-based tool that instruments C, C++, and other native programs to detect memory-safety bugs at runtime.

Programs written in languages like C manage computer memory manually, and a tiny mistake—such as reading past the end of a list or using data after it has been deleted—can cause silent corruption or crashes. AddressSanitizer acts like a strict safety inspector built into the program during testing: the instant the code touches memory it should not, it halts the program and points to the exact line where the mistake happened.

Compiled into binaries with -fsanitize=address in GCC or Clang, AddressSanitizer (ASan) catches out-of-bounds reads and writes on the stack, heap, and globals, as well as use-after-free and double-free bugs, typically with around 2× CPU overhead and higher RAM usage. Notice that ASan is a testing and debugging tool rather than a production hardening flag: it aborts on the first detected error with a detailed stack trace showing where the memory was allocated, freed, and illegally accessed.

If a C program has a 1-byte buffer overflow on a heap array, why might it seem to run fine normally yet crash immediately under AddressSanitizer?

Without ASan, a 1-byte overflow often lands in allocator padding or an adjacent unused byte without triggering a hardware page fault. ASan surrounds every allocation with poisoned redzones, so even a 1-byte overshoot hits a poisoned shadow byte and is caught immediately.

ASan reserves a contiguous shadow memory region (1 byte of shadow per 8 bytes of application virtual memory, computed via (addr >> 3) + Offset) and inserts inline instrumentation before every memory load or store to check whether the corresponding shadow byte is zero (all 8 bytes addressable) or non-zero (partially addressable 1..7 or poisoned negative sentinel). Heap, stack, and global objects are padded with redzones, and freed heap chunks are held in a FIFO quarantine to catch temporal use-after-free bugs; note that ASan cannot detect uninitialized reads (MemorySanitizer’s domain) and can miss intra-object struct overflows or pointer-arithmetic jumps that skip entirely over a redzone.

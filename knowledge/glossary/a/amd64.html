AMD64 (Advanced Micro Devices 64-bit)

The 64-bit extension of the x86 processor architecture used by most modern desktop and laptop PCs.

Think of a processor as a desk where a computer does its work. Older 32-bit chips had a small desk and could only keep track of about 4 gigabytes of memory at once. AMD64 widened the desk to 64 bits, letting your computer use much more memory and handle bigger numbers in a single step while still running older 32-bit programs.

In Linux, you will see this architecture named either amd64 (Debian, Ubuntu, kernel packages) or x86_64 (GCC triples, uname -m, Fedora/Arch). Despite the name “AMD64”, Intel adopted the same design under the name Intel 64, so both AMD and Intel PCs run the same 64-bit Linux binaries. Running file /bin/ls shows an ELF 64-bit LSB executable for x86-64.

Why does an Intel laptop still install packages labeled amd64?

AMD designed the 64-bit extension to x86 first, and Intel later implemented the compatible instruction set. Linux distributions kept amd64 (or x86_64) as the shared architecture name for both vendors’ 64-bit x86 chips.

AMD64 introduces 64-bit long mode (64-bit mode plus 32-bit compatibility mode under a 64-bit kernel), expands the general-purpose register file from 8 to 16 64-bit registers (RAX–R15), and adds RIP-relative addressing for position-independent code. Virtual addresses are 48-bit (or 57-bit with 5-level paging) canonical addresses sign-extended to 64 bits; non-canonical accesses raise #GP. The System V AMD64 ABI passes the first six integer arguments in RDI, RSI, RDX, RCX, R8, and R9, mandates 16-byte stack alignment before call, and defines a 128-byte red zone below RSP in user space (disabled with -mno-red-zone in kernel code).

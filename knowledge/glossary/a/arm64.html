ARM64 (AArch64)

The 64-bit version of the Arm processor architecture (officially called AArch64), used in modern smartphones, Apple Silicon Macs, and energy-efficient cloud servers.

Just as PCs moved from 32-bit to 64-bit chips so they could use more memory and run faster, Arm chips made the same leap with ARM64. Today, almost every modern phone, newer Raspberry Pi, and Arm-based server runs in 64-bit ARM64 mode.

In Linux, you will see this architecture called arm64 (Debian/Ubuntu, Linux kernel arch/arm64) or aarch64 (GCC triples, uname -m, Fedora/Arch)—both refer to the same 64-bit instruction set. While Tamlinux currently targets x86_64 (AMD64), Linux and C11 codebases keep ARM64 portability in mind, since assumptions that hold on x86 (such as strict memory ordering or char being signed by default) can expose hidden bugs on ARM64.

On Linux, what is the difference between arm64 and aarch64?

They refer to the exact same 64-bit Arm architecture: aarch64 is Arm’s official execution-state name used by toolchains and uname -m, while arm64 is the package and kernel directory name used by Debian/Ubuntu and Linux.

ARM64 corresponds to the AArch64 execution state introduced in ARMv8-A (and extended in ARMv9-A), featuring 31 general-purpose 64-bit registers (X0–X30, with X30 as the link register), a dedicated zero register (XZR/WZR), separate stack pointers per exception level (SP_EL0–SP_EL3), and fixed-width 32-bit instruction encoding. The AAPCS64 ABI passes up to eight integer arguments in X0–X7 and eight SIMD/FP arguments in V0–V7. Notable portability differences from x86-64 include unsigned char by default in C, weakly ordered memory requiring acquire/release (LDAR/STLR) or LSE atomics for synchronization, selectable 4 KB / 16 KB / 64 KB page sizes, and hardware features such as Pointer Authentication (PAC) and Memory Tagging Extension (MTE).

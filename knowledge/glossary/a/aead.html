Guide / Glossary A–Z / Terms beginning with A / AEAD - Authenticated Encryption with Associated Data

A family of symmetric encryption algorithms that simultaneously hides a message’s contents and guarantees that neither the ciphertext nor unencrypted header data has been tampered with.

Older encryption methods only scrambled the message, leaving it surprisingly easy for an attacker to flip bits or alter the message without being noticed—unless the programmer carefully bolted on a separate tamper-check seal. AEAD combines both jobs into one lock-and-seal package: it keeps the message secret and attaches a tamper-proof tag so any modification to the message or its outer label is caught before the data is trusted.

Modern protocols such as TLS 1.3, WireGuard, and SSH standardize on AEAD ciphers—most commonly AES-GCM and ChaCha20-Poly1305—because combining confidentiality and integrity in one API prevents classic encrypt-then-MAC vs. MAC-then-encrypt implementation mistakes. Every AEAD encryption call takes four inputs (key, unique nonce, plaintext, and optional unencrypted associated data) and outputs ciphertext plus an authentication tag; if tag verification fails on decryption, the library must discard the output and return an error rather than exposing partial plaintext.

Why should an application never reuse the same nonce with the same key in an AEAD cipher like AES-GCM or ChaCha20-Poly1305?

Both AES-GCM and ChaCha20-Poly1305 generate a keystream from the key and nonce; reusing a nonce XORs two plaintexts together under the same keystream (leaking their difference) and in GCM also leaks the GHASH authentication key, enabling attackers to forge tags.

Formally, an AEAD scheme must satisfy both IND-CPA (indistinguishability under chosen-plaintext attack) and INT-CTXT (ciphertext integrity), together implying IND-CCA3 / authenticated encryption security over (K, N, A, P) → (C, T). Nonce-misuse sensitivity varies by construction: AES-GCM (CTR + GHASH over GF(2^128)) and ChaCha20-Poly1305 catastrophically lose both confidentiality and authenticity on a single nonce repeat, motivating nonce-misuse-resistant schemes like AES-GCM-SIV (RFC 8452, which derives a synthetic IV via POLYVAL over AAD and plaintext) or XChaCha20-Poly1305 (192-bit extended nonce suitable for random generation).

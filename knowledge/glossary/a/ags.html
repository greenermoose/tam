AGS (Aylur's GTK Shell)

Aylur’s GTK Shell: a JavaScript and TypeScript widget framework over GTK3/GTK4 for building custom Wayland desktop shells.

Minimal Wayland window managers only arrange your application windows—they don’t come with a top bar, clock, volume slider, or notification popups. AGS is a toolkit that lets you build those desktop pieces yourself using JavaScript or TypeScript on top of GTK, so you can design your own taskbar, control center, or launcher.

Tamlinux chose Quickshell (QML/Qt6) over AGS/EWW for its desktop bar and plugin system. Compared with Waybar (static JSON/CSS bar) or EWW (Yuck markup driven by shell scripts), AGS exposes reactive TypeScript/JS components with built-in system services for audio, notifications, and media—making complex widgets easier to script, though major releases (v1 to v2/Astal) have involved breaking API changes.

How does AGS differ from a standalone status bar like Waybar?

Waybar provides a fixed set of built-in bar modules configured with JSON and CSS. AGS is a programmable widget framework: you write TypeScript or JavaScript against GTK and system services to build arbitrary bars, control panels, notification popups, and launchers.

AGS v2+ is built on Astal (a Vala/C library suite providing GObject-introspected bindings for wlr-layer-shell, D-Bus StatusNotifierItem, PipeWire/PulseAudio, MPRIS, NetworkManager, and UPower) hosted inside GJS (SpiderMonkey) with JSX/TSX reactive bindings to GTK3 or GTK4. Key trade-offs include GJS/GTK memory footprint compared to native C/Rust bars, single-threaded JS event-loop stalls if synchronous I/O is used, and compositor support requirements for zwlr_layer_shell_v1 (e.g., Hyprland, Sway, Niri).

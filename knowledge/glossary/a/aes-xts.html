AES-XTS (XEX-based Tweaked-Codebook with Ciphertext Stealing)

A disk-encryption block mode that tweaks each 16-byte block by its sector and block position without expanding sector size.

A hard drive or SSD is split into fixed-size sectors, like numbered lockers, and your computer needs to read or overwrite any single locker without touching the rest of the drive or making the data bigger. AES-XTS is designed for this job: it mixes each sector’s number into the encryption so identical files stored in different places still look completely different, while keeping every sector the exact same size.

Part of AES variants, AES-XTS is the default cipher mode for dm-crypt and LUKS2 full-disk encryption (often shown as aes-xts-plain64 in cryptsetup status). Unlike network modes such as AES-GCM, XTS provides confidentiality only and has no built-in integrity tag; detecting tampered disk blocks requires pairing dm-crypt with dm-integrity or a checksumming filesystem.

Why doesn’t AES-XTS add an authentication tag to detect tampered disk sectors?

Block devices expect 512-byte or 4096-byte sectors to map 1:1 to physical storage blocks. Adding a MAC tag to every sector would expand it or require separate metadata storage, breaking standard sector geometry. XTS preserves exact sector size and leaves integrity to upper layers or dm-integrity.

Defined in IEEE P1619 / NIST SP 800-38E, XTS-AES splits the key into K1 (data) and K2 (tweak). For sector index i and 16-byte block index j, it computes T = AES_K2(i) × α^j in GF(2^128) and outputs C = AES_K1(P ⊕ T) ⊕ T, using ciphertext stealing when a sector is not a 16-byte multiple. Trade-offs: a 1-bit ciphertext modification randomizes the entire 16-byte block rather than failing decryption, and an attacker who can observe multiple snapshots of the same sector over time can detect when a 16-byte block reverts to an earlier value.

AES-NI (AES New Instructions)

An x86_64 CPU instruction-set extension that accelerates AES encryption and decryption in hardware at constant time.

Normally, a processor has to run many small math steps and memory lookups to scramble data with AES, which takes extra time and power. AES-NI builds those scrambling steps directly into the processor’s silicon, like having a dedicated hardware calculator for locks instead of doing the math by hand. That makes encrypted disks, VPNs, and HTTPS websites much faster while keeping CPU usage low.

Part of AES variants, AES-NI executes AES rounds in dedicated CPU registers rather than software lookup tables. On Linux, you can check /proc/cpuinfo or lscpu for the aes flag (and pclmulqdq for fast GCM authentication); the kernel’s aesni_intel module automatically accelerates dm-crypt/LUKS, WireGuard, IPsec, and OpenSSL when present.

Why is AES-NI safer against side-channel attacks than a standard software lookup-table implementation?

Fast software AES often uses precomputed T-tables in memory. Because secret key bytes determine which table entries are read, another process sharing the CPU cache can measure cache-hit timing to infer key bits. AES-NI runs rounds inside CPU registers with no data-dependent memory lookups, keeping execution time constant.

Introduced on Intel Westmere and AMD Bulldozer, AES-NI adds six x86_64 instructions (AESENC, AESENCLAST, AESDEC, AESDECLAST, AESKEYGENASSIST, AESIMC) operating on 128-bit XMM registers, typically paired with PCLMULQDQ for carry-less multiplication in GF(2^128) (GHASH in AES-GCM). Newer VAES and VPCLMULQDQ extensions vectorize multiple independent blocks across AVX2/AVX-512 lanes—maximizing throughput for CTR, XTS, and GCM, whereas serial modes like CBC encryption remain latency-bound. On ARM64, the equivalent is the Armv8 Cryptography Extension (aes/pmull).

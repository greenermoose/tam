Guide / Glossary A–Z / Terms beginning with A / AMD-V (AMD Virtualization)

AMD Virtualization (also known as SVM, Secure Virtual Machine): hardware virtualization extensions in AMD x86_64 processors.

Without hardware help, running a virtual machine inside your computer forces software to translate or fake sensitive processor steps, which makes the virtual computer slow. AMD-V adds a built-in “guest mode” to AMD processors so a virtual machine’s operating system can run most of its code directly on the real CPU while staying safely isolated from your main system.

On Linux, AMD-V appears as the svm flag in /proc/cpuinfo and lscpu (the AMD counterpart to Intel’s vmx flag for VT-x). The kvm_amd kernel module uses it to provide hardware-assisted acceleration for QEMU and libvirt via /dev/kvm, though many motherboards ship with SVM disabled in UEFI/BIOS firmware until you turn it on.

Why might KVM report no hardware acceleration on an AMD PC even though the CPU supports AMD-V?

Many motherboards disable SVM (AMD-V) in UEFI/BIOS firmware by default. Until SVM is enabled in firmware settings, the Linux kvm_amd kernel module cannot initialize hardware virtualization.

AMD64 Secure Virtual Machine (SVM) adds Guest/Host execution transitions via VMRUN and VMEXIT backed by a 4 KiB Virtual Machine Control Block (VMCB) holding guest register state and intercept bitmaps. Rapid Virtualization Indexing (RVI, also called Nested Page Tables / NPT) provides hardware second-level translation from Guest Physical Addresses (GPA) to Host Physical Addresses (HPA), eliminating the high VMEXIT overhead of software shadow page tables at the cost of a 2D page-table walk on TLB misses. Related extensions include AVIC for virtualized interrupt delivery and SEV/SEV-SNP for encrypted guest memory.

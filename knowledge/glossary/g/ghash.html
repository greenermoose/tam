GHASH

The polynomial authentication function inside AES-GCM that produces a tag to verify encrypted data has not been tampered with.

When you send an encrypted message, you also want a tamper-evident seal so the receiver knows nobody altered it in transit. GHASH is the fast mathematical seal-maker used inside AES-GCM: it mixes the encrypted data and any unencrypted headers into a short check value that breaks if even a single bit is flipped.

GHASH processes both Additional Authenticated Data (AAD)—like packet headers that must remain readable—and the ciphertext, outputting a 128-bit authentication tag. On modern x86 and ARM CPUs, dedicated carryless-multiplication instructions (such as PCLMULQDQ or PMULL) accelerate GHASH so authentication keeps pace with hardware AES encryption. Unlike a standalone hash like SHA-256, GHASH is keyed and not collision-resistant on its own; it must only be used with a unique per-message counter block.

What happens if the same AES-GCM key and nonce are accidentally reused for two different messages?

Not only does keystream reuse expose the XOR of both plaintexts, but because GHASH evaluates a polynomial over GF(2^128) using a fixed secret hash subkey H, two messages under the same nonce yield equations that let an attacker recover H and forge arbitrary tags.

Specified in NIST SP 800-38D, GHASH evaluates a polynomial over GF(2^128) using Horner’s rule: Y_i = (Y_{i-1} ^ X_i) * H, where H = AES_K(0^128) is the hash subkey and input blocks X_i consist of zero-padded AAD, zero-padded ciphertext, and a 64-bit length block len(A) || len(C). The final tag masks GHASH_H(A, C) with AES_K(J_0). Because GHASH is an epsilon-almost-XOR-universal hash rather than a cryptographic PRF, reusing a nonce cancels the AES_K(J_0) mask across two ciphertexts, reducing tag differences to a low-degree polynomial in H whose roots can be factored directly ("Forbidden Attack").

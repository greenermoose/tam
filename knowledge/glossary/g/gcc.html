GCC (GNU Compiler Collection)

GCC (GNU Compiler Collection) is the standard open-source compiler suite used on Linux to turn source code into executable programs.

People write software in human-readable languages like C or C++, but a computer’s processor only understands raw binary machine instructions. GCC is the translator that reads source code files, checks them for mistakes, and turns them into a runnable program or library. Almost every core piece of a Linux system—from the kernel itself to everyday command-line tools—can be built with GCC.

On Linux, invoking gcc main.c -o app runs preprocessing, compilation, assembly, and linking in one step, while flags like -Wall -Wextra catch common bugs early and -O2 enables standard optimizations. Tamlinux compiles C11 components with GCC (or Clang) using strict warnings and optional AddressSanitizer (-fsanitize=address) during testing to catch out-of-bounds memory access. Compared with Clang, GCC often serves as the default system compiler for building the Linux kernel and glibc.

What is the difference between compiling with -O0 and -O2 -g when debugging a C program?

-O0 disables optimizations so every line maps straightforwardly in a debugger, while -O2 -g optimizes for speed and keeps DWARF debug symbols, though some variables may be inlined or optimized out.

GCC’s multi-frontend, multi-target architecture translates C (including C11/C23), C++, Ada, Go, and Fortran into language-independent GIMPLE and SSA intermediate representations for target-independent passes before lowering to RTL and machine assembly. Practical build flags balance diagnostics and hardening: -Wall -Wextra -Werror, -D_FORTIFY_SOURCE=2, stack protectors (-fstack-protector-strong), and sanitizers (-fsanitize=address,undefined). Edge cases include strict-aliasing optimizations (-fstrict-aliasing) turning type-punning UB into miscompilation, and LTO (-flto) deferring cross-translation-unit codegen to link time.

Guide / Glossary A–Z / Terms beginning with G / GEM (Graphics Execution Manager)

A Linux DRM kernel API for managing GPU memory objects.

Graphics programs need places in memory to store images, textures, and command buffers for the GPU. GEM is the Linux kernel system that helps graphics drivers create and manage those memory objects safely. It gives applications and the display system a common way to work with GPU buffers.

GEM manages buffer objects (GEM objects) used by DRM drivers. It provides handles for user space, supports memory mapping, and works with dma-buf for sharing buffers between devices or processes. Some drivers use GEM with simple memory placement, while discrete GPU drivers often use TTM underneath for moving buffers between VRAM and system RAM. When you hear "GEM/TTM" in Linux graphics, it usually refers to this memory-management layer.

Why is buffer sharing important in a Wayland desktop?

The compositor, application, and GPU may all need access to the same rendered image. Sharing a buffer object avoids copying pixels between processes and keeps rendering efficient.

GEM was introduced to unify DRM buffer management (originally in Intel's i915 stack) around named buffer objects, dumb buffers for simple KMS clients, and PRIME/dma-buf export-import for cross-device sharing. GEM itself is an API/framework; drivers provide memory backends. TTM offers a richer placement/eviction model for discrete GPUs with multiple memory domains, while GEM shmem/CMA helpers suit unified-memory or simpler devices. Correctness depends on explicit synchronization (dma_fence), cache/domain handling, and modifier-aware buffer layout when buffers are scanned out or shared across drivers.

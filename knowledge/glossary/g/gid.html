Guide / Glossary A–Z / Terms beginning with G / GID - Group Identifier

A numeric identifier that the operating system uses to represent a user group for file ownership and access control.

Just as people have names while computers prefer ID numbers, Linux gives every user group a number called a GID. When you share a folder with a "developers" or "audio" group, the system actually checks that number behind the scenes to decide who is allowed to read, write, or run those files.

Every process has a primary GID and a list of supplementary GIDs, while every file stores a single owning GID in its metadata. You can inspect your active group numbers with the id command, and map numbers to names via /etc/group or NSS services. Notice that if you add your account to a new group, already-running shells do not pick up the new GID until you start a new login session or run newgrp.

Why does adding your user to a new group (such as video or libvirt) not grant access in your currently open terminal?

A process inherits its primary and supplementary GIDs from its parent at login or session start. Updating /etc/group does not mutate the credentials of already-running processes; a fresh login or newgrp is required to reload the group list.

In the Linux kernel, group credentials live in struct cred as gid (real), egid (effective), sgid (saved set-GID), fsgid (filesystem GID used for VFS permission checks), and a sorted group_info array of supplementary GIDs (up to NGROUPS_MAX = 65536). Inode mode bits (S_IRWXG) are evaluated against fsgid and group_info when the process’s fsuid does not match the file’s UID. Across user namespaces, GIDs are translated through /proc/<pid>/gid_map between inner namespace IDs and host kgid_t values; unprivileged containers cannot call setgroups(2) unless setgroups is explicitly enabled after mapping.

Glyph

The specific visual shape drawn for a character, symbol, or combination of characters in a font.

A letter like "a" is an idea, while a glyph is the actual picture of that "a" drawn on your screen. Different fonts draw the same letter with different glyphs—some with curly tails, some straight—and sometimes two letters like "f" and "i" are merged into a single combined glyph so they look neater together.

Characters (Unicode code points) and glyphs are not always one-to-one: one character can map to different glyphs depending on style (bold, italic, small caps), while ligatures or complex scripts (such as Arabic or Devanagari) combine multiple code points into one glyph or reorder them visually. When an application lacks a glyph for a code point, font fallback searches other installed fonts—or renders a placeholder box ("tofu") if none is found.

Why can copying text from a PDF or terminal still give you the two letters f and i even when they were drawn on screen as a single joined ligature?

The underlying text stream stores the Unicode characters U+0066 and U+0069, while the font’s shaping engine substituted a single combined glyph only for visual rendering.

In OpenType/TrueType fonts, a glyph is an outline (quadratic Bezier in glyf or cubic Bezier in CFF/CFF2) or bitmap/color layer (COLR/CBDT) addressed by an integer Glyph ID (GID). Text shaping engines such as HarfBuzz first map Unicode code points to nominal GIDs via the font’s cmap table, then apply OpenType GSUB (substitution—ligatures, contextual alternates) and GPOS (positioning—kerning, mark attachment) lookups before handing positioned GIDs to a rasterizer (like FreeType) for hinting and subpixel or grayscale anti-aliasing.

Guide / Glossary A–Z / Terms beginning with G / GPGPU (General-Purpose Computing on GPUs)

Using a graphics processing unit (GPU) to run non-graphics parallel computations such as AI inference, scientific simulations, and cryptography.

A CPU has a few very fast, clever cores that handle complicated tasks one after another, while a graphics card has thousands of smaller cores built to color millions of pixels at once. GPGPU puts those thousands of graphics cores to work on everyday math-heavy jobs—like running local AI models or rendering physics—much faster than a CPU alone could.

Modern Linux systems access GPU compute through APIs such as Vulkan Compute, OpenCL, ROCm (AMD), and CUDA (NVIDIA). GPGPU shines when the same operation runs independently across huge arrays of data (matrix multiplication, image filtering, hashing), but it performs poorly on branch-heavy, sequential code or tiny datasets where copying data across the PCIe bus to VRAM takes longer than the calculation itself.

Why can offloading a small, fast calculation to a GPU actually make a program slower than running it on the CPU?

Data and command buffers must be transferred over PCIe (on discrete GPUs) and kernels scheduled onto the device. For small workloads, that launch and memory-copy overhead outweighs the GPU’s parallel compute speedup.

GPGPU architectures execute compute kernels/shaders on SIMT (Single Instruction, Multiple Threads) hardware—warps on NVIDIA (32 threads) or wavefronts on AMD (32 or 64 threads)—trading large CPU-style branch predictors and deep out-of-order caches for high ALU density, wide VRAM buses (GDDR6/HBM), and hardware thread-context switching to hide memory latency. Performance depends on coalesced global memory accesses, minimizing warp divergence across conditional branches, and fitting working sets into shared/LDS memory; on Linux, compute queues are exposed through DRM/KFD kernel drivers (amdgpu, nvidia, xe/i915) rather than graphics-only pipelines.

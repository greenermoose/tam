Guide / Glossary A–Z / Terms beginning with G / Generation

A generation is a numbered, immutable snapshot of managed software and configuration that you can switch between.

Think of a generation like a saved loadout for your system’s apps and settings. When you update or change configuration, a new generation is created alongside the old one rather than overwriting it. If an update breaks something, you can switch back to an earlier generation—though your personal documents and files in your home folder are not part of that loadout and stay as they are.

In Nix and Home Manager, each generation is a symlink pointing to a built store path containing packages, wrapper scripts, and declarative dotfiles. Switching generations atomically updates the active symlink without rebuilding, making rollbacks fast as long as older generations haven’t been garbage-collected. However, generations only cover declaratively managed state: mutable user data, native distribution packages, and bootloader entries live outside them and require separate recovery mechanisms such as filesystem snapshots.

If you roll back to an earlier Home Manager generation, why do recently edited documents or browser profiles remain unchanged?

Generations only track declaratively built store outputs and the symlinks pointing to them. Mutable state—such as documents, databases, and application caches—is not stored in the Nix store, so rolling back a generation leaves those files untouched.

A generation is a versioned profile link (for example, profile-42-link) referencing a complete closure of immutable /nix/store derivations; activation scripts reconcile environment variables, systemd user units, and managed symlinks against that closure. Generation identity alone is insufficient to establish a Tamlinux candidate: the recorded assembly, component revisions, retained outputs, and matching generation tie software return to a known selection, while mutable and native recovery stay explicit. Deleting old generations removes GC roots, allowing nix-collect-garbage to reclaim unreferenced store paths and permanently severing the ability to roll back to them.

Guide / Glossary A–Z / Terms beginning with G / Glob

A filename pattern using wildcard characters (like * or ?) that expands into matching file paths.

Instead of typing out twenty file names one by one, a glob lets you use a shorthand pattern—like *.txt for "every file ending in .txt"—and the command shell automatically finds and fills in all the matching names for you.

In Linux shells like Bash or Zsh, globbing happens before the command itself runs: * matches any string (except a leading dot on hidden files), ? matches a single character, and [abc] matches one character from a set. Globs are not regular expressions—for instance, * in a glob means "any characters", whereas in regex it means "zero or more of the preceding token". If a pattern matches no files, Bash leaves the literal pattern string intact unless options like nullglob or failglob are set.

Why does running rm *.log in a directory with no .log files print an error about a literal file named *.log in default Bash?

By default, when a glob matches zero filenames, Bash passes the unexpanded pattern string *.log as a literal argument to rm. Enabling shopt -s nullglob or failglob changes that fallback behavior.

POSIX pathname expansion (and C library glob(3) / fnmatch(3)) splits patterns on /, reads directory entries via getdents64(2), and sorts matches according to LC_COLLATE—which can cause range expressions like [a-z] to match uppercase letters in locale-aware collations unless LC_ALL=C or POSIX classes like [[:lower:]] are used. Extensions such as Bash’s globstar (**) and extglob (+(...), !(...)) expand expressiveness, though shells still impose ARG_MAX limits when huge expansions are passed to execve(2).

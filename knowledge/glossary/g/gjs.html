GJS (GNOME JavaScript)

A JavaScript runtime that lets developers write GNOME desktop applications and shell extensions using native GTK and system libraries.

Web browsers use JavaScript to make websites interactive, and GJS brings that same language to the Linux desktop. It acts as a bridge so developers can build desktop apps, panels, and GNOME extensions in JavaScript while still using the native buttons, windows, and system features provided by GNOME.

Under the hood, GJS embeds Mozilla’s SpiderMonkey JavaScript engine and connects it to C libraries through GObject Introspection (GI). This is how GNOME Shell extensions and tools like AGS (Aylur’s GTK Shell) control windows, notifications, and GTK widgets without compiling C code. Note that GJS runs outside a browser: there is no DOM or window object, and APIs come from GI modules such as gi://Gtk or gi://Gio.

Why can’t you run standard browser JavaScript code that uses document.getElementById directly inside GJS?

GJS embeds SpiderMonkey for the JavaScript language itself, not a web browser engine. Instead of a web DOM, it exposes native GNOME and GTK libraries via GObject Introspection.

GJS bridges SpiderMonkey’s garbage-collected JS heap with GObject’s reference-counted C object model via libgirepository typelibs (.typelib) at runtime. Marshaling converts JS primitives, arrays, and callbacks into C types and GClosures according to GI annotations (such as transfer full, transfer none, or nullable). A classic failure mode in GJS extensions is a reference-cycle or toggle-ref leak between SpiderMonkey GC and GObject refcounts—for example, holding JS closures in C signal handlers without disconnecting them on disable(). Modern GJS targets ES modules (import Gtk from 'gi://Gtk?version=4.0') and integrates with GLib’s GMainLoop for async I/O and Promises.

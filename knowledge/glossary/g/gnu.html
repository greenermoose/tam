Guide / Glossary A–Z / Terms beginning with G / GNU - GNU's Not Unix

A free-software project and Unix-like operating system effort that created many of the core tools and libraries used on Linux systems.

Linux by itself is mainly the kernel—the core traffic controller talking to your hardware. Most of the everyday commands, compilers, and text tools people associate with a Linux system (like Bash, GCC, and core file utilities) actually come from the GNU project, which set out to build a completely free Unix-style operating system.

Founded by Richard Stallman in 1983, the GNU project produced essential userland components—including GCC, GDB, Bash, GNU Coreutils, and glibc (the GNU C Library)—alongside the GNU General Public License (GPL), which requires derivative works distributed to others to remain free software. Contrasting GNU userland with alternatives like BusyBox or musl libc (used in Alpine Linux) shows why Linux systems can share the same kernel yet differ in command flags and C library behavior.

Why do some minimal Linux containers behave differently when running scripts that rely on GNU-specific flags like sed -i or grep -P?

Minimal containers often replace GNU Coreutils, grep, and sed with BusyBox or BSD-style utilities, which implement POSIX basics but omit GNU extensions. The Linux kernel is the same, but the userland tools differ.

GNU (a recursive acronym for "GNU’s Not Unix") supplies the standard toolchain and runtime foundation for most desktop and server Linux distributions: Binutils, GCC, glibc (implementing POSIX, Linux syscall wrappers, NSS, and ELF dynamic linking via ld-linux), and Autotools. While GNU’s own microkernel effort (GNU Hurd) remains niche, combining GNU userland with the Linux kernel created the GNU/Linux ecosystem, governed legally by copyleft licenses (GPLv2/v3, LGPL for libraries like glibc) that distinguish linking obligations from permissive BSD/MIT licensing.

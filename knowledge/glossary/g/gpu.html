GPU - Graphics Processing Unit

A specialized processor designed to perform thousands of simple calculations at the same time—originally for drawing graphics on a screen, and now also for video, 3D rendering, and parallel computing.

If the main processor (CPU) is like one very fast chef who can follow complex recipes step by step, a GPU is like a kitchen full of hundreds of helpers each doing the same simple task—like chopping a million carrots—all at once. Because drawing a screen means coloring millions of tiny dots every fraction of a second, handing that repetitive work to the GPU keeps animations, video, and windows smooth without bogging down the rest of the computer.

Unlike a CPU with a few complex cores optimized for low-latency branching and sequential logic, a GPU packs thousands of smaller arithmetic units optimized for high-throughput parallel math. In Linux, you see GPUs used both for desktop compositing and gaming (via Vulkan or OpenGL) and for headless workloads like video transcoding or machine learning. Integrated GPUs share system RAM with the CPU, whereas discrete GPUs have their own dedicated high-speed video memory and sit on PCIe.

Why is a GPU faster than a CPU at applying a filter to a 4K image, even though each GPU core is slower than a CPU core?

An image filter runs the same calculation independently on millions of pixels. The GPU processes thousands of pixels simultaneously across its parallel cores, whereas a CPU can only process a handful at a time—so total throughput is much higher on the GPU.

Modern GPUs execute SIMT (Single Instruction, Multiple Threads) warps or wavefronts across streaming multiprocessors, hiding high memory latency through massive thread oversubscription and fast register-file context switching rather than large L1/L2 caches. They are paired with wide-bus, high-bandwidth memory (GDDR6/HBM) and dedicated fixed-function blocks for rasterization, texture sampling, and hardware video encode/decode. On Linux, the kernel’s Direct Rendering Manager and Kernel Mode Setting (DRM/KMS) subsystems manage command submission, memory objects (GEM/TTM, DMA-BUF zero-copy sharing), and display scanout, while user-space Mesa or vendor drivers translate Vulkan, OpenGL, and compute kernels (HIP/CUDA/OpenCL) into hardware command buffers.

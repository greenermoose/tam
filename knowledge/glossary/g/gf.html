GF (Galois Field / Finite Field)

A finite mathematical field—a closed set of numbers with well-defined addition, subtraction, multiplication, and division—used heavily in cryptography and error-correcting codes.

Ordinary numbers go on forever, which is awkward for computers that work with fixed-size chunks of bits. A Galois Field is a small, self-contained number system where every calculation wraps around and stays inside the exact same fixed set of values. That predictability makes it ideal for scrambling data in encryption and spotting or fixing transmission errors.

In computing, the most common finite fields are binary extension fields written GF(2^n), where each element fits neatly into an n-bit word. For example, AES uses GF(2^8) (single bytes) for its S-box and MixColumns steps, while AES-GCM authentication and XTS disk-encryption tweaks operate in GF(2^128) (128-bit blocks). Because addition in GF(2^n) is just bitwise XOR, hardware can perform it in a single cycle without carry propagation.

Why is addition in GF(2^n) equivalent to bitwise XOR rather than ordinary integer addition?

In a binary extension field of characteristic 2, each bit position is an independent coefficient modulo 2. Adding coefficients modulo 2 produces 0 + 0 = 0, 1 + 0 = 1, and 1 + 1 = 0 with no carry—which is identical to XOR.

A finite field GF(p^n) exists if and only if its order is a prime power, and is unique up to isomorphism. Elements of GF(2^n) are represented as polynomials of degree less than n over GF(2); multiplication is polynomial multiplication modulo an irreducible degree-n polynomial (such as x^8 + x^4 + x^3 + x + 1 in AES, or x^128 + x^7 + x^2 + x + 1 in GCM). Every nonzero element has a unique multiplicative inverse (computed via the extended Euclidean algorithm or Fermat’s Little Theorem a^(2^n - 2)), which prevents zero-divisor weaknesses and guarantees bijective diffusion layers—provided lookup-table implementations avoid cache-timing side channels.

Guide / Security / Protect your computer / Fingerprints and FIDO2 security keys

Fingerprint sensors and FIDO2 keys can replace typed passwords at authorization prompts, using a local match or a hardware-backed key held by the token.

Unlocking prompts with a touch

Typing a long password many times a day can feel slow. If your laptop has a fingerprint reader, or if you carry a USB security key (FIDO2), Tamlinux can let you tap that hardware to approve permission prompts.

Why it matters

Hardware verification confirms you are physically sitting at the computer without encouraging you to choose an easy-to-guess password.

How to think about it

Fingerprints and security keys act as convenient backup keys on the same door: if your sensor is unreachable—for example when a laptop is docked with its lid closed—Tamlinux automatically falls back to asking for your password.

New words

Fingerprint authentication
Verifying your identity by scanning a registered fingerprint through fprintd.
FIDO2
A hardware token standard where tapping a physical USB or NFC key signs an authentication challenge.
PAM
Pluggable Authentication Modules, the Linux layer that decides whether a password, fingerprint, or token satisfies a prompt.

FIDO2/CTAP2 cryptography, PAM composition, and biometric limits

Reference

FIDO2 combines WebAuthn (for browsers) with CTAP2 (Client to Authenticator Protocol 2 over USB HID, NFC, or BLE). Each Relying Party receives a distinct ECDSA P-256 or Ed25519 key pair bound to its Relying Party ID (RP ID), preventing cross-site tracking and phishing.

How it works

pam_u2f issues a 32-byte random challenge over libfido2; the hardware token signs SHA-256(rpId) || flags || signCount || challenge inside its secure element only after physical user presence (UP) and optional user verification (UV/PIN). For biometrics, pam_fprintd communicates over D-Bus with fprintd, which matches sensor templates locally—though unlike FIDO2, a biometric match alone does not produce a cryptographic signature over a remote challenge.

Edge cases

Match-on-host vs. match-on-chip fingerprint readers
On match-on-host sensors, raw image frames cross USB to user-space drivers (libfprint), whereas match-on-chip sensors verify templates inside the sensor ASIC and return a signed verdict.
PAM short-circuiting
Placing sufficient before pam_unix lets a physical token pass auth while preserving password fallback; pam_succeed_if or clamshell gates prevent closed-lid fprintd timeouts.
Research frontier: How can post-quantum signatures fit within CTAP2 hardware token memory and latency budgets?

ML-DSA signatures (2.4–4.6 KB) exceed legacy 64-byte ECDSA USB HID frames and constrained smart-card RAM, driving work on stateful/stateless hash-based or compact lattice signatures on next-generation authenticators.

Guide / Security / User accounts and groups

Linux accounts give each person a separate identity, home folder and group memberships, so private files stay separate while shared access can be granted deliberately.

Who is using the computer?

Each person using a computer can have their own account with a separate name, password, and home folder under /home/. One account cannot open another person's private files by default.

Why it matters

Separate accounts keep personal documents, browser profiles, and preferences isolated while letting everyone share the installed operating system cleanly.

How to think about it

Your username is your nametag; your UID number is the numeric badge Linux checks underneath; and groups are shared clubs (such as audio or printer access) that grant specific device or admin rights.

New words

UID
The numeric user identifier Linux attaches to your account and every file you create.
GID
The primary numeric group identifier for your account.
Home directory
Your personal folder (usually /home/<username>) for documents and user configuration.

Check yourself

Why might a new group not take effect in an open terminal?

Group membership is assigned at login, so a fresh login session is needed.

Account records and safe change boundaries

Linux stores local accounts in the account database and attaches a numeric UID and primary GID to each one. Files record an owner UID and group GID; permissions are checked against those numbers, not the printed name. The home directory is a convention backed by the account record, not a special kind of filesystem.

Changing accounts

Creating an unprivileged account with its own home uses useradd -m <name> followed by passwd <name>. Adding supplementary access uses usermod -aG <group> <name>. The -a matters: usermod -G without it replaces the whole supplementary group list. Record id -Gn <user> before any change so the previous membership can be restored.

Session boundaries

Group memberships are assigned at login. A running process keeps the group list it started with, so a newly added group may not appear until the user opens a fresh login session. Groups such as wheel and docker are effectively administrator-level; grant them only with a recorded authorization and rollback decision.
